# Video idea strategist dashboard

## Steps
1. **Mechanical pattern pass:** run `python video-ideation/strategist/extract_patterns.py --json > report.json`. Rerun `outlier-tracking`'s refresh-outliers skill first if the data is more than a week stale.
2. **Creative synthesis:** read `report.json`, write/update `video-ideation/strategist/ideas.json` by hand (this is a judgment call, not scriptable), 2-4 ideas per category (bar, monkey-app-video-chat, street-daytime-pov, explainer, general), each with title, thumbnail scenario description, source outlier citation, and a one-line why. State each category's real entry count so thin categories aren't presented as equally proven, see `feedback_wider_lookback_for_thin_niches`.
3. **Thumbnail mockups, manual via SuperGrok (default, no API cost):** the user has a SuperGrok subscription with unlimited images in the consumer app (grok.com/imagine), that covers this at no marginal cost, unlike either OpenAI's or xAI's per-image developer API billing. For each idea to mock up, write a ready-to-paste prompt from its `thumbnail_scenario` field (scene description + this channel's documented style: medium/wide framing, natural lighting, minimal/no caption text, no dance-request framing) and hand it to the user with these steps: open grok.com/imagine, upload `thumbnail-creation/reference/self/P1030611.JPG` as a reference image, paste the prompt, generate, download the result and place it at `thumbnail-creation/output/strategist/<slug>.png` (or hand the file back for placement). Since this is manual and prompt-driven (not a pixel mask), always ask the user to visually confirm the result actually looks like them before moving on, a prompt-based reference composition is less exact than the mask-based approach below.
   - **Scripted fallback (only if the user explicitly wants automation and accepts real API spend):** `python thumbnail-creation/generate_concept_mockup.py --reference <self-ref-photo> --scenario "<from ideas.json>" --out output/strategist/<slug>.png`, uses OpenAI's gpt-image-1 masked edit (pixel-exact identity preservation, proven in this repo), needs its own OpenAI API billing, confirm cost/scope with the user first.
4. **QA + critic:** run `python qa/run_checks.py --level full thumbnail-creation/output/strategist/` (thumbnail-specs gate), then run the `critic` subagent on the finished mockups before showing the user, same as any other thumbnail.
5. **Publish the dashboard:** build a single HTML page (via the Artifact tool, load `artifact-design` first) showing each category's ranked ideas with its mockup thumbnail, source citation, and why. Publish the mockup PNGs as the artifact's supporting `files`. On a refresh, update the same artifact URL (read it first) rather than creating a new one.
6. **Report:** the artifact link, plus which ideas are ready to promote into a full `ideation_<name>.md` concept doc via the `new-video` skill.

## Gotchas (keep this list updated)
- **A woman is the thumbnail's main draw, not the creator solo.** Every thumbnail scenario/prompt, manual or scripted, needs a woman as the clear focal subject. `generate_concept_mockup.py` does this by default (`--no-woman` is the deliberate exception, e.g. a tier-list board graphic). When writing manual SuperGrok prompts, always state this explicitly in the prompt text, don't rely on it being implied. `ideas.json`'s `thumbnail_scenario` fields should already say so, since that's also what the MCP connector serves to Grok, see `get_style_rules` below.
- **Never generate a mockup from scratch identity**, always mask-protect a real reference photo of the creator (`generate_concept_mockup.py` already refuses if no face is detected in the reference). This channel is on-camera, not faceless, a synthetic face is not acceptable.
- **Grok connector parity:** the MCP server's `get_style_rules` tool (see `outlier-tracking/mcp-server/claude.md`) is the source of truth for standing content rules Grok needs when it's the one reasoning about ideas/prompts via the connector, since Grok can't see this repo's local memory files. Whenever a standing rule here changes (this file, or a memory feedback entry that affects idea/thumbnail output), update `get_style_rules`' returned text too, and push, so both sides of the connector agree.
- **Spending money:** SuperGrok's $30/month consumer subscription does NOT include xAI API credits, API access is a separate console.x.ai account with its own billing, this is a common mix-up. Default to the manual SuperGrok-app path (no marginal cost) over either provider's paid API. If the scripted OpenAI fallback is used, confirm scope (which/how many ideas) first, don't generate mockups for every idea in `ideas.json` by default.
- **Grok's edit API is prompt-based, not mask-based:** no pixel-exact identity protection like OpenAI's masked edit. Fine for the manual SuperGrok-app path since the user visually checks each result, but don't build an unattended/scripted Grok path without that same human check.
- **No dance-request angle** in titles or thumbnails, and no fabricated dialogue in any title/rationale text (standing channel rules).
- **Category coverage is uneven:** monkey-app-video-chat has the largest real data volume but its top-scoring raw titles lean drama/persona/meme-heavy, which conflicts with this channel's cool/smooth/mature brand vibe, adapt the underlying mechanic, don't copy the aesthetic.
