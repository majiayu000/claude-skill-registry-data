# CHE_email-marketing

## Вход и маршрутизация

Темы/URL, цель, аудитория, подтверждённый отправитель и профиль бренда: голос,
название, сайт, цветовые токены, шрифт, подпись, допустимый CTA. Отсутствующие
критичные поля запросить одним блоком; до этого допустим контентный черновик,
не «готовое брендированное письмо». Не присваивать авторство письма методологу.
Поиск недельных материалов → `che-email-digest-topic-planner`; аудит →
`che-audit-unisender-email`; полный цикл → `che-unisender-email-pipeline`.

## Процесс

1. Прочитать [редакционные и HTML-правила](references/email-production.md).
2. Разобрать каждый URL/изображение/роль; открыть источники до письма. Недоступный
   материал раскрывать только по предоставленным сведениям, без догадок по slug.
3. Выбрать одну редакционную ось, порядок материалов и практический вывод.
4. Написать тему до 50 символов, дополняющий прехедер 70–110; вступление,
   экспертные карточки и естественный CTA из входа.
5. Заполнить [универсальный шаблон](assets/email-template.html) параметрами
   профиля; повторить карточки, удалить неиспользуемые блоки/изображения.
6. Проверить факты/URL, полный HTML, alt, скрытый preheader, таблицы/inline styles,
   мобильную ширину, отсутствие заглушек/кода/неподтверждённых обещаний.

## Результат

Тема → прехедер → полный HTML без сокращений → файл, если среда поддерживает.
Отмечать недоступные источники перед результатом кратко. Не отправлять письмо,
не создавать записи/кампании. Изображения только заданные/разрешённые пользователем.

## Среда и ресурсы

Ссылки ниже разрешаются относительно установленной папки навыка. Не предполагать
текущую рабочую папку, конкретную ОС или название MCP-сервера. Профиль бизнеса и
живые данные хранить в рабочем проекте, отдельно от пакета. Файлы и выполнение
скриптов возможны только при наличии соответствующих инструментов; иначе вернуть
инструкционный результат и явно отметить, что выполнение не проверено.
