# 机器人能力技术地图

## Purpose

帮助产品经理看懂“一个机器人能力如何实现”，并把业务目标追溯到系统能力、技术模块、候选路线和验证证据。输出不替研发团队做无依据的技术选型。

## Input

可提供场景、任务流程、机器人形态、已有技术栈、架构图、研发阶段或某项能力问题。若只有一句目标，先生成粗粒度地图，并标注需要算法、硬件和系统负责人确认的部分。

示例：`使用 robotics-capability-technical-map，解释人形机器人完成货架拣选的技术实现路径。`

## Key Concepts

- **四层追溯**：业务结果 -> 可观察行为 -> 系统能力 -> 技术实现。
- **端到端闭环**：传感 -> 状态估计/世界表示 -> 决策规划 -> 执行控制 -> 结果确认 -> 数据回流。
- **指标三元组**：指标值 + 测试条件 + 统计口径，三者缺一不可。
- **主路径与降级路径**：正常能力之外，必须说明失效检测、限制运行、人工接管和恢复。
- **成熟度不等于演示效果**：区分单次演示、实验室重复、受控试点、连续现场和规模化部署。

## Application

### 1. 写出任务链

用动词描述每个步骤，例如“接收任务、找到目标、接近、抓取、搬运、放置、确认、异常恢复”。为每步写成功状态和不可接受失败。

### 2. 建立能力树

从任务映射到下列能力域：

1. 任务编排与人机交互
2. 环境与对象感知
3. 定位、状态估计与标定
4. 世界表示与语义理解
5. 任务、路径和运动规划
6. 底盘移动或足式运动
7. 机械臂、末端和灵巧操作
8. 低层控制与执行器
9. 安全监控与异常恢复
10. 算力、通信、电源与热管理
11. 数据、仿真、训练、部署和车队运维

按需读取 [技术域地图](references/technical-domain-map.md)，不要加载与当前任务无关的细节。

### 3. 为能力绑定技术路线

每个能力列出1-3条候选路线及选择条件，不把热门技术设为默认答案。例如定位可比较激光、视觉、GNSS、UWB或融合；策略可比较规则/状态机、优化方法、模仿学习、强化学习或视觉语言动作模型。

### 4. 建立追溯矩阵

| 任务步骤 | 可观察行为 | 能力 | 候选技术路线 | 输入/输出接口 | 指标与条件 | 证据 | 成熟度 |
|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  |

技术路线必须回答：为什么适合ODD、训练/标定/算力需求、失效模式、可替代方案、集成依赖和量产约束。

### 5. 标注成熟度和关键依赖

采用五级产品成熟度：

- **M1 原理可行**：单模块或单次演示。
- **M2 实验室可重复**：条件受控，重复测试通过。
- **M3 任务闭环**：端到端完成，能发现和恢复部分异常。
- **M4 现场试点**：目标ODD连续运行，有干预和故障数据。
- **M5 规模部署**：跨设备/点位稳定，支持运维、升级和成本目标。

成熟度按最弱关键依赖判断，不取模块平均值。

### 6. 生成研发顺序

先验证高风险依赖和闭环能力，再优化局部指标。推荐顺序：场景数据 -> 子能力探针 -> 最小闭环 -> 异常恢复 -> 现场连续运行 -> 泛化与降本 -> 规模运维。

### 7. 输出产品经理版技术路径

交付：一张能力树、一张追溯矩阵、关键技术决策、接口依赖、成熟度热图、最高风险假设、验证顺序和需要专业负责人确认的问题。

## Examples

### 轮式搬运

“自主搬运”需拆成地图/定位、动态避障、任务调度、到站对接、载荷检测、低电回充和失联恢复。产品指标应落到目标地面和人流条件下的成功率、干预率、周期和停机时间。

### 人形拣选

“看到就能拿”需拆成对象检测与位姿、可达性判断、抓取规划、全身平衡、力控、放置确认和失败重试。VLM/VLA可以是候选上层策略，但安全约束、低层控制和执行器能力仍需独立定义。

## Common Pitfalls

- **技术清单没有任务链**：模块齐全但无法闭环。修正：从任务步骤反向追溯。
- **指标只有峰值**：峰值速度掩盖连续稳定性。修正：加入成功率、干预率、时长和恢复。
- **把模型能力当系统能力**：忽略传感、控制和接口。修正：完整描述输入到执行反馈。
- **成熟度平均化**：一个成熟模块掩盖关键短板。修正：按关键路径最弱环节定级。
