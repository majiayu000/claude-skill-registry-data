# 每周复盘 / Weekly Study Review

把过去一周的实际执行情况读出来，对着事实做复盘，并把下周的调整落进日程。

复盘最常见的两种失败：变成自我安慰（"这周整体还不错"），或变成自我批判（"我又拖延了"）。
两种都没有产出。**这个 skill 的唯一判据是：下周会因此做什么不一样的事。**
说不出这一条，这次复盘就是白做的，要如实说，而不是凑一段总结。

## 何时使用 / When to use

- 学生主动要求复盘，或一周结束时想理一理
- 计划连续落后，需要搞清楚是计划不合理还是执行出了问题
- 学生说"最近很忙但好像什么都没推进"

**不适用于** / Not for：

- 排新计划 —— 那是 `deadline-to-study-plan`
- 深挖一段经历的意义（STAR 反思）—— 那是 `reflection-interviewer`。
  复盘看的是这一周的执行，反思看的是一段经历里的人。

## 需要的输入 / Inputs

| 输入 | 必填 | 说明 |
|---|---|---|
| 本周事项 | 是 | 含已完成的。要看计划了什么、完成了什么、什么还挂着 |
| 上一次复盘 | 否 | 有则对照：上次说要调的那件事，这周做到了吗 |
| 卡在哪的原因 | 是 | 数据只说了"做没做完"，说不了"为什么"。用 `ask_user` 给选项问，别让他写作文 |

读事项时**必须带上已完成的**（`includeDone`），否则看到的只有没做完的部分，
复盘会变成一份罪状清单。

## 流程 / Process

1. **拉事实**：取回本周的事项（含已完成）与上一次的复盘文档。
2. **直接写出对账那一段**：计划了 N 件，完成 M 件，拖了哪几件、拖了多久。
   这一段只陈述、不评价，也不需要问任何人就能写完——先写出来给他看。
3. **同一轮把原因问掉**：调 `ask_user`，针对拖住的那 1–2 件各出一问，**给选项**：

   > 「周三那份物理错题整理没动，最接近的是哪个？」
   > 没时间 / 不知道从哪下手 / 被临时的事挤掉了 / 其实做了但没标记

   选项本身就是归因框架，比"你觉得为什么没完成"好答得多，也更容易归到下一步的三类里。
   两件以上一起问，不要一周问一件。
4. **归类**：把原因归到三类之一，这一步决定下周该改什么：
   - **计划问题**：任务本身太大、时间估错了 → 改计划的拆法
   - **执行问题**：时间有但没做 → 改触发条件（放在什么之后做、在哪做）
   - **外部问题**：临时的事挤掉了 → 不用改，但下次留缓冲
5. **产出**（不要问"要不要保存"，直接出卡）：
   - `propose_artifact` 存一份 `kind: review` 的周复盘文档
   - `propose_events` 提案下周的**调整动作**（不是整周计划，只有因复盘而改变的那几件）

## 输出格式 / Output

存进 artifact 的正文：

```markdown
## 这一周
计划 <N> 件，完成 <M> 件。完成：<列表>。未完成：<列表，附拖了几天>

## 卡在哪
- <具体那件事> —— <学生自己选的/说的原因>（归类：计划 / 执行 / 外部）

## 下周改什么
- <一到两条具体动作，写清楚跟这周的做法有什么不同>

## 上次说要改的
- <上次的动作> —— 做到了 / 没做到，为什么
```

**「下周改什么」最多两条。** 一次改五个习惯等于一个也没改。

## 没有这些工具时（降级） / Without these tools (degraded mode)

上面的流程按 nestudy 的工具写。在 Claude Code 或其他没有这些工具的环境里，流程、输出格式和边界都不变，
只把工具换成下表的做法，并在回复开头写明「降级：没有 nestudy 工具，本周事项来自你贴的清单」。

| 工具 | 没有时怎么做 |
|---|---|
| `get_events` | 请学生贴出这一周的事项，**连已完成的一起**（每件：日期、事情、做完没有）。对账只按他贴的写，并注明来源是他的清单，不是事项数据 |
| `get_artifacts` | 请他贴上一次复盘里"下周改什么"那几条；拿不到就略过「上次说要改的」那一段，不编 |
| `ask_user` | 在对话里直接问：拖住的那几件一次问完、每问给选项，然后停下等他回答 |
| `propose_artifact` | 定稿的复盘按上面的输出格式写成一张 Markdown 卡片，请学生自己保存；不说"已存档" |
| `propose_events` | 下周的调整动作另写一张卡片（日期、动作），请他自己存进日历 |

## 边界 / Boundaries

- **不替学生编原因**：数据只能看出"没完成"，看不出"为什么"。
  他跳过了那一问就写"原因未明"，不要从选项里挑一个替他填。
- **不做情绪评价**：不写"你太拖延了"，也不写"你已经很棒了"。复盘不是打分。
- **不把复盘写成励志文**：这份文档日后是文书素材，里面得有真实的困难与具体的应对，不是漂亮话。
- **不代替学生反思**：正文里学生自述的部分用**他自己的话**，不要润色成更好听的版本。
- **没有可改的就说没有**：这一周执行得好，就直接说"这周没什么要调的，按原样继续"，
  不要为了让复盘看起来有价值而硬找问题。

## Token 控制 / Token discipline

- 事项一次读齐（`withinDays` 覆盖过去一周即可，记得 `includeDone: true`）
- 上次复盘只取最近一条，按摘要读；需要细节再取全文
- 复盘正文控制在一屏内；对账那段用数字，不要逐条抄事项标题
- 原因一次问完。运行时对连续追问有硬上限，一周问一件会把额度耗在半路上
