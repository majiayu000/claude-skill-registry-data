# 路线图规划Skill

## 适用场景
产品方向明确后,需要把愿景拆成可执行的阶段计划(通常 3-12 个月),对齐各版本目标、关键里程碑与资源投入。

## 执行步骤
1. 明确愿景与北极星指标:路线图起点是「要达成什么」,量化 3-6-12 个月的目标状态。
2. 划分阶段主题:每个阶段一个主题(如"冷启动获客"/"商业化变现"/"规模化降本"),主题必须回应业务目标。
3. 定义里程碑:每阶段 2-4 个里程碑,写「时间点 + 可验证标志」(如"Q2 末:日活 1 万,转化率 5%")。
4. 映射需求:把已排序的需求池(承接优先级排序结果)映射到各阶段,标注关键依赖与前置条件。
5. 标注假设与风险:路线图基于假设(市场假设/技术假设),逐条列出并写验证方式与失效预案。
6. 滚动更新机制:定义评审节奏(月度/季度)与修订触发条件(指标大幅偏离/战略调整)。

## 规范要点
- 主题与版本规划的映射:路线图管「阶段与主题」,版本规划管「迭代与功能」,两个文档必须互相引用,禁止两层各写一套冲突内容。
- 里程碑可验证:写可测量的标志,禁止"完成平台化改造"这类不可判定表述,要写"单租户 → 多租户切换上线,服务 10 个客户"。
- 假设显式化:每个假设必须有验证方式(上线数据/小范围试点)与失效后的备选路径。
- 远期粗近期细:3 个月内到版本粒度,3 个月外到主题粒度,禁止远期也假装精确。
- 资源约束写进路线图:每个阶段标注所需研发产能与关键岗位,资源不足时写明取舍。

## 输出模板
```
# [产品名] 产品路线图
1. 愿景与北极星指标(3/6/12 个月目标状态)
2. 阶段主题与里程碑时间轴
3. 需求映射表(阶段/里程碑/需求/依赖/前置条件)
4. 关键假设清单(假设/验证方式/失效预案)
5. 资源与约束
6. 评审节奏与修订触发条件
```

## 自检清单
- [ ] 阶段主题回应业务目标,无孤立功能堆砌
- [ ] 每个里程碑有可验证标志
- [ ] 需求映射承接优先级排序结果
- [ ] 假设清单含验证方式与失效预案
- [ ] 与版本规划文档互相引用不冲突
- [ ] 远期粗近期细,粒度分层合理
