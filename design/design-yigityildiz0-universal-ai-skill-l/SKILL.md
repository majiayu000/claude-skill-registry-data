# Design Router

Coordinate the design family without duplicating specialist instructions.

## Route by deliverable

| Need | Primary skill |
|---|---|
| Brand strategy, voice, identity governance | brand |
| Tokens, components, themes, state architecture | design-system |
| Product direction, UX evidence, stack guidance | ui-ux-pro-max |
| Tailwind, component styling, responsive implementation | ui-styling |
| Campaign banner, cover, ad, hero image | banner-design |
| Pitch deck or HTML presentation | slides |

For logos, icons, illustration, or photography, use the active host's native design or image-generation capability and the brand/design-system constraints. Do not require a fixed provider or model.

## Mixed-deliverable workflow

1. Define the shared brief: audience, objective, message, brand, platforms, required assets, deadlines, and acceptance criteria.
2. Establish dependencies. Brand decisions precede token and asset decisions; tokens precede UI and presentation implementation.
3. Invoke only the specialist skills required for the deliverables.
4. Keep one owner for shared tokens, copy, logos, and source assets.
5. Reconcile specialist outputs into one visual language.
6. Validate consistency, accessibility, responsiveness, production dimensions, and export completeness.

## Deliverable map

Before production, list each artifact with:

- owner or specialist workflow;
- source inputs;
- dimensions or platform;
- file format;
- dependencies;
- validation method;
- approval status.

## Guardrails

- Do not activate every design skill for a narrow request.
- Do not let independent workstreams invent different brand tokens.
- Do not mix unrelated visual directions to appear more creative.
- Do not assume an image or browser tool is available; use the host's exposed capabilities and provide a fallback specification.
- Do not include provider/model names unless selected by the user.
