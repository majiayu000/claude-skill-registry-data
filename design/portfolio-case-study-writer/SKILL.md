# 作品集案例分析写作器

## 何时使用此技能

当用户：
- 想创建作品集案例分析
- 需要把简历要点扩展成详细的项目复盘
- 正在搭建作品集网站
- 想深入展示项目工作
- 提到："case study"、"作品集"、"项目复盘"、"工作样例"、"作品集作品"

## 核心能力

- 把简历经历条目转化为详尽的案例分析
- 按最大冲击力结构化案例
- 构建有说服力的项目叙事
- 在技术细节与业务背景之间取得平衡
- 适配作品集网站的格式
- 根据受众调整深度

## 案例分析的意义

**为什么案例分析很重要：**
- 简历只展示你做了什么；案例分析展示你怎么做、为什么这么做
- 展示思考过程，而不只是结果
- 让你有更深入的技能展示空间
- 让你在众多候选人中脱颖而出
- 很多 PM、UX 和创意类岗位都要求提供

## 案例分析的结构

### 标准结构

```
1. 概述（项目摘要）
2. 问题（需要解决什么）
3. 过程（你的思路与方法）
4. 方案（你产出了什么/交付了什么）
5. 结果（带来的影响）
6. 反思（有哪些会做得不一样）
```

### 阅读时长
- **快速阅读：** 3-5 分钟（作品集必备版本）
- **深度阅读：** 10-15 分钟（给感兴趣的读者）

## 分章节写作指南

### 1. 概述部分

**目的：** 抓住读者，交代背景

**包含：**
- 项目名称与所在公司
- 你的角色
- 时间线
- 团队规模
- 一句话概括成果影响

**示例：**
```
# 重构结账流程

**公司：** 电商科技公司
**角色：** 首席产品设计师
**时间线：** 6 周
**团队：** 2 名设计师、3 名工程师、1 名 PM

**摘要：** 通过简化为 3 步结账流程，将购物车放弃率降低 35%，挽回 1400 万元人民币收入。
```

### 2. 问题部分

**目的：** 说清这份工作为什么重要

**包含：**
- 业务背景
- 用户痛点
- 关键指标或目标
- 约束条件

**示例：**
```
## 问题

公司当时的购物车放弃率高达 68%——明显高于行业平均的 55%。退出调研和用户研究揭示了若干问题：

- **步骤太多：** 我们的结账流程有 7 个页面
- **强制注册：** 用户购买前必须先注册账号
- **费用不透明：** 运费要到最后一步才显示
- **移动端不顺：** 表单没有针对移动端优化

**目标：** 3 个月内将购物车放弃率降到 50% 以下。

**约束条件：**
- 不改动现有的支付集成
- 必须保持 PCI 合规
- 距离购物旺季只有 6 周
```

### 3. 过程部分

**目的：** 展示你的思考和方法论

**包含：**
- 开展过的研究
- 涉及的干系人
- 提出的假设
- 考虑过的备选方案
- 做出的决策（及原因）

**示例：**
```
## 过程

### 研究
我首先深入理解问题：
- 分析 Mixpanel 漏斗数据中的流失点
- 对近期流失用户做了 10 场用户访谈
- 查看热力图和会话回放
- 与 5 家竞品的结账流程做对标分析

**关键洞察：** 73% 的流失发生在账号注册页。用户想的是购买，不是"发展一段关系"。

### 创意发散
我探索了几种方案：
1. 仅游客结账（最简单）
2. 社交账号登录（摩擦更低）
3. 渐进式信息收集（分阶段采集信息）
4. 单页结账（类似亚马逊）

综合可行性、时间和影响权衡后，我们选择了混合方案……

### 关键决策
- **优先游客结账：** 注册改为可选，且放在下单之后
- **价格透明：** 第一屏就显示运费
- **移动端优先设计：** 先为移动端设计，再适配桌面端
- **进度指示：** 添加清晰的"第 1 步，共 3 步"提示
```

### 4. 方案部分

**目的：** 展示你真正做出了什么

**包含：**
- 视觉物料（原型图、截图、示意图）
- 关键功能/改动
- 技术实现（如相关）
- 如何解决了上述问题

**示例：**
```
## 方案

### 全新的结账流程

**改前：** 7 个页面，强制注册
**改后：** 3 个页面，游客结账可选

[图片：改前/改后对比]

### 关键改动

**1. 价格透明组件**
[图片：价格组件设计稿]
一开始就展示商品总价、运费和税费。不留意外。

**2. 游客结账选项**
[图片：游客结账页]
注册改为可选，并清晰传达注册账号的价值。

**3. 智能表单设计**
[图片：表单设计]
- 移动端采用单列布局
- 手机号/银行卡号自动格式化
- 集成地址自动补全
- 清晰的报错提示

**4. 信任要素**
在整个流程中加入安全标识、无理由退款承诺和客服联系方式。
```

### 5. 结果部分

**目的：** 用数据证明影响

**包含：**
- 量化结果（附时间范围）
- 与目标的对比
- 受影响的次要指标
- 对业务的影响

**示例：**
```
## 结果

### 核心指标（上线后 90 天）

| 指标 | 改前 | 改后 | 变化 |
|--------|--------|-------|--------|
| 购物车放弃率 | 68% | 44% | -35% |
| 结账完成率 | 32% | 56% | +75% |
| 移动端转化率 | 18% | 41% | +128% |
| 客单价（每位访客） | ¥17 | ¥27 | +60% |

### 业务影响
- **首个季度新增收入 1400 万元**
- **移动端订单量增长 15%**
- **关于结账问题的客服工单减少 45%**

### 次要影响
- 事后注册的账号数反而增长 20%（下单后引导注册）
- 平均客单价保持稳定
- 复购率有所提升
```

### 6. 反思部分

**目的：** 展现成长型思维与自我认知

**包含：**
- 做得好的地方
- 有哪些会做得不一样
- 意料之外的挑战
- 获得的技能

**示例：**
```
## 反思

### 做得好的地方
- **前期的用户研究** 让我们避免做出错误方案
- **跨职能对齐会** 让每个人都信息同步
- **带着埋点上线** 让我们能立即衡量影响

### 有哪些会做得不一样
- **更多 A/B 测试：** 我们一次性上线了全部改版。更稳妥的做法是逐项测试，弄清各改动分别贡献了什么。
- **更早聚焦移动端：** 我们先设计桌面端再适配。移动端优先会更高效。
- **干系人教育：** 花了太多时间说服管理层。下次会更早启动干系人对齐。

### 获得的技能
- 高级 Figma 原型设计
- 使用 A/B 测试框架
- 向高管汇报数据驱动的设计决策
```

## 按岗位划分的案例分析类型

### 产品经理（PM）案例分析
**聚焦：**
- 战略与优先级取舍
- 干系人管理
- 指标与成果
- 技术权衡

### UX/产品设计师案例分析
**聚焦：**
- 用户研究
- 设计流程
- 视觉物料
- 可用性改进

### 软件工程师案例分析
**聚焦：**
- 技术架构
- 解决问题的思路
- 系统设计
- 代码质量/性能

### 市场营销案例分析
**聚焦：**
- 策略与人群定向
- 创意执行
- 渠道表现
- ROI 与归因

## 视觉元素

### 必备视觉物料
- 改前/改后对比
- 关键页面或交付物
- 流程示意图
- 结果图表

### 加分视觉物料
- 用户旅程图
- 线框图演进过程
- 研究产出物
- 团队照片

### 视觉技巧
- 保持图片尺寸一致
- 为每张图配上说明文字
- 如有需要，对敏感数据做模糊处理
- 确保图片尺寸对移动端友好

- ✅ 问题陈述清晰

- ✅ 你本人的具体贡献一目了然
- ✅ 结果已量化
- ✅ 附有视觉物料
- ✅ 对挑战与教训坦诚相告

- ✅ 已校对并润色
