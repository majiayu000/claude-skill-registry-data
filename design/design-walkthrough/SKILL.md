# 设计走查Skill

## 适用场景
线框或 Figma 设计稿完成后、进入开发前,逐项核对设计稿是否完整、准确实现了 PRD 与交互方案,提前暴露偏差避免返工。

## 执行步骤
1. 建立对照基线:以 PRD 功能清单 + AC 为基准,列「功能 → 页面 → 设计帧」映射表。
2. 功能覆盖走查:逐功能确认有对应页面帧,无遗漏功能、无 PRD 之外的多余设计(多余设计同样要上报)。
3. 文案走查:按钮、提示语、表头、错误文案与 PRD 逐字比对,不一致逐条记录。
4. 规则与状态走查:业务规则(权限、限额、必填)、状态流转、五态(默认/空/加载/错误/权限)在设计稿中是否可表达、可找到对应帧。
5. 交互走查:每个可交互元素的点击去向、弹窗、跳转是否符合交互流程定义。
6. 输出问题清单:问题按严重级别分级(阻塞:功能缺失/规则冲突;一般:文案偏差/状态缺帧),附帧位置(nodeId/页面名)与修改建议。

## 规范要点
- 走查结论只对照 PRD 说事实:写「PRD 要求 X,设计稿为 Y」,不写主观审美评价(配色、间距等视觉问题另走视觉评审)。
- 问题必须可定位:每条问题带页面名 + 帧位置 + 截图证据,禁止"整体感觉不对"这类不可执行描述。
- 阻塞级问题标准:功能缺失、字段缺失、规则与 PRD 冲突、影响主流程的状态缺失;其余归一般级。
- 走查通过门槛:阻塞级问题清零、一般级问题全部有处理结论(修复/挂起有负责人),才能进入开发。

## 输出模板
```
# [版本/功能] 设计走查报告
1. 走查范围与基线(PRD 版本号/设计稿链接)
2. 对照映射表(功能 → 页面 → 帧)
3. 问题清单(编号/级别/页面位置/PRD 依据/设计现状/修改建议)
4. 结论(通过 / 有条件通过 / 不通过+整改要求)
```

## 自检清单
- [ ] 映射表覆盖 PRD 全部功能条目
- [ ] 文案逐字比对完成
- [ ] 五态与业务规则均有对应帧
- [ ] 每条问题可定位(页面+帧+证据)
- [ ] 问题已分级且阻塞级有明确整改要求
