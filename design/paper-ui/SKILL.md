# Paper UI · briffy 的视觉标准

**范围：只适用于 briffy 这个仓库。** 这不是通用设计规范——其它项目不要套用，也不要抄进 ~/.claude 的全局配置。

**一句话：窗口是一张暖灰的底纸，每条记录是一张躺在上面的白便签。**
界面本身（导航、按钮、筛选、输入框）是**印在**底纸上的字，永远不浮起来；只有记录是真实物件，
它才有影子、才会被抬起、才会被拿走。

唯一来源是 [assets/paper/tokens.css](../../../assets/paper/tokens.css)，每个 renderer 页面在自己的 css 之前 link 它
（扩展带一份拷贝在 `extension/paper/`）。两张样张：`node dev/preview/serve.js` 后
[/lang](http://localhost:5173/lang)（版面与字）和 [/system](http://localhost:5173/system)（层 / 墨 / 空）。

抄谁：**Steidl**（德国摄影书出版社）。它的网站不是"像纸"，它就是一张纸，东西放在上面——
一种字体、一个字号梯度、零彩色、纯文字导航、零线条零方框、图片自己带影子。

## 硬约束（违反即错）

- **全直角。** `border-radius` 全仓为 0，包括圆点、药丸、滚动条、头像框。
- **没有边框、没有分隔线、没有底纹。** 分组只靠留白。仅剩的一条线是输入框底下那道发丝线（`--hair`）。
- **只有真实物件有影子。** 记录、详情窗、书架、气泡、小猫。按钮、导航、筛选、输入框永远层 0——
  按钮一旦浮起来，"便签是真实的纸"就不成立了。
- **影子是软的，光在上方**，向下落。硬偏移影 + 深色描边是海报 / neo-brutalism，不是纸。
- **一种字体。** 衬线和等宽都不进界面（`--mono` 只给日志和代码）。
- **一屏一个彩色。** 蓝墨只给"正在发生"，印泥只给 录音 / 出错 / 删除；通常一屏一滴都不出现。
- **底纸是近白，不是中灰。** 2026-09-05 量过四个参照物：Steidl `#fff`、Teenage Engineering `#fff`、
  Cosmos 纯白、are.na `#1a1a1a` + 1px 描边——**顶级的纸感设计要么近白要么深板，没有一个停在中灰**。
  中灰（L*80 左右）是设计工具画布的颜色，读起来是水泥、是"还没做完"。
  现在 `--page #f3f1f0`（L*95），纸 `--slip #fbf9f8`（L*98）——**只差 3 L\*，边界全交给影子**，所以 `--e1..--e4` 比原来重一档。
  整扇窗用 `--ground`（一道 3 L* 的顶光渐变）：一块绝对平的色是色板，不是面，真实的桌面有光。
  `--page` 是它的平均实色，留给需要一块实色的地方。
  **连带的坑**：底纸近白之后，"打穿的孔透出底纸"这件事本身看不见了（只差 3 L*）——孔要靠**它自己的内影**。
- **灰阶不带色相。** 灰阶只带一丝暖（彩度 3，肉眼分不出，但不是水泥），不偏黄也不偏蓝——
  截图里的真实颜色不该被底色拖偏，几种淡色混在一屏也只会浑。暗色是同一个色相坐标，只是明暗相反。
  **五种纸各有各的颜色**（2026-09-09 用户定的「颜色区分明显一下」，推翻了原来「只有随手记是黄的」）：
  牛皮 `--p-voice #f6efe3` · 相纸 `--p-shot #fdfcfb` · 便利贴 `--p-note #fbf6dc` ·
  索引卡 `--p-mark #edf2f5` · 复写纸 `--p-clip #f1eeea`。
  **全部留在 L\* 93–98、彩度 ≤ 8**：再往下就不是纸了，是彩色卡片，而且会把嵌在纸里的截图缩略图
  的真实颜色拖偏。原来那条的理由（「五种淡色混在一屏只会浑」）靠这个上限守住。
  蓝墨是钢笔水的 `#2f4f7a`，不是屏幕蓝。
- **没有纹理。** 纸的真实感来自颜色、影子和排版，不是噪点图。（第二版加过纸纹，被否。）
- 图标线条 `stroke-linecap: square; stroke-linejoin: miter`。
- 字体随应用打包，不联网取字。

## 四把梯子（没有第五种）

### 层 · 离纸面多远

| 层 | 是什么 | token |
| --- | --- | --- |
| 0 | 底纸 + 一切印刷元素（导航、按钮、筛选、输入框） | 无影，永不动 |
| 1 | 一条记录躺着 | `--e1` |
| 2 | 鼠标经过 | `--e2` + `translateY(-2px)` |
| 3 | 拖拽中 | `--e3` + `translateY(-4px)` + 偏 1.5°（两处允许旋转之一，另一处见剪贴板碎片） |
| 4 | 详情窗 | `--e4` + 底纸压暗（`--scrim`） |

**选中不是层级**：选中是荧光笔（`--marker`）划过，纸没有动。做成抬起会和"经过"撞车，
一屏选了六条时会浮起一片。**处理中**同理，只换一行墨色。

浮在**别人桌面**上的两样（书架、小猫）都**不带影子**——那圈阴影只会把它们和屏幕割开。

**影子的大小跟着物件走，不跟着层级走。** 托盘（搜索、关闭、底下那三只、批量条、详情卡片上的动作、
看图窗那一排）用 `--e-tray`，不用 `--e1`/`--e2`：一只 30px 的小方块套上给 200px 便签调的影子，
那道 26px 的模糊比托盘本身还宽，看着就是一团脏。（2026-09-07，用户原话「托盘的阴影太重了」。）
`--e-tray` 是 10px 的模糊、8% 的浓度——在只差 3 L* 的底纸上仍然读得出是一件东西，但不糊。
顺带纠一个旧错：托盘一直写的是 `--e2`，而 `--e2` 是「鼠标经过」那一档——托盘从不 hover，
它本来就该在「躺着」这一档以下。

### 墨 · 写得多黑

**三级墨的步长要匀，铅笔要够到 WCAG AA 4.5:1。** 2026-09-05 审计发现旧的阶梯是 98→59→45→9（步长 39/14/36）：
两个淡墨挤在一起、都离黑很远，"三级"实际只有两级；而铅笔只有 3.1:1，低于 AA。
现在亮色 98 / 48 / 34 / 20（步长 14/14，铅笔 4.6:1），暗色 20 / 62 / 75 / 92（铅笔 4.5:1）。
**墨是 L\*20 不是纯黑**——印刷黑，正好落在 Steidl 的 `#333` 那一档；纯黑（16.7:1）是屏幕黑。

`--ink` 日期/标题/正文/当前页 · `--ink-2` 摘要/工具/说明 · `--ink-3` 时间/来源/标签/未选中导航/placeholder ·
`--hair` 唯一的线 · `--marker` 选中 · `--accent` 正在发生 · `--stamp` 录音·出错·删除。
`--tone` / `--tone-2` 是"印在纸上、能按的地方"（按钮底）。

### 空 · 唯一的分隔手段

`--a1` 4 同一行字之间 · `--a2` 8 正文与元数据 · `--a3` 14 便签内边距 ·
`--a4` 26 便签之间 / 侧栏两组之间 / **一天和下一天之间** · `--a5` 54 一屏之内最大的一口气 · `--pad` 40 页边。

**一天和下一天之间原来是 `--a5`（54）**，那是**日期抬头还不显示**时定的：那块空白当时是唯一说
「换天了」的东西。现在每条带子自己写着日期（`.jg-hour`），空块就只剩「多空一手」这一件事，
而 54 再加上带子自己的 `--a2`，一天结束的地方会空出 62px 的白——比一条记录还高
（2026-09-07 用户原话「这里间距怎么那么大」）。现在 `.jg-day` / `.lv-day` 都是 `--a4`：
带子之间 8，天和天之间 34，还是四倍多，读得出来，但不是个洞。

### 字 · 六级，一种字体

`--fs-day` 21/600 日期（全页最大，产品的主语是"一天"）· `--fs-title` 13/600 · `--fs-body` 13/400 ·
`--fs-nav` 13 · `--fs-act` 12 工具与筛选（**比导航小一档：动作不是地点**）· `--fs-meta` 11 · `--fs-brand` 12（品牌最弱，它永远不变）。

**排版规矩**：拉丁在前中文在后；中文正文 13/1.6，≤14px 最粗 600，永远无斜体，字距 ≥ 0；
汉字与拉丁之间交给 `text-autospace: normal`，不手打空格；全角标点 `text-spacing-trim`；`line-break: strict`；
日期是一个词（抬头 `text-autospace: no-autospace`）；数字半角 + `tabular-nums`；`<html lang>` 跟第一语言（`zh-Hans`）。

## 版面（H5：顶栏一条，右边一条轴，中间全是素材，托盘浮着）

**版面的目标是把面积全让给素材。** 窗口只有两行：顶栏、内容；托盘不占行，浮在内容上面。

**顶栏那一行不是一整条托盘，但里面可以站托盘。**（2026-09-07 改。原先的规矩是"托盘只属于底部，
顶部只有纸上的字"，理由是把整条顶栏做成白板会和底部对不上、"筛选"会被误读成"切视图"——
那个理由现在仍然成立，**筛选那一行永远是纸上的字**。改掉的是另一半：
两件**能按、能往里打字的东西**——搜索和关闭——做成托盘之后才认得出来。
用户原话：「搜索框看不出来是搜索框」。）
所以顶栏第一行的读法是：**两只托盘立在两头，中间「怎么看」是印在纸上的字**；第二行整行都是字。

**顶栏**（第一行住在 `.winbar` 里，第二行是 `.top`，都从页边那条线起）：
第一行 搜索托盘（`.search`，320px）· 右端「怎么看」· 最右一只关闭托盘；第二行 筛选（见下）。
**「怎么看」用图标不用词**：网格＝四格、列表＝三横杠、选择＝方框打勾——它们是三件不同的事，
并排三个词会被读成一组同类。
**第一行里没有日期了**（2026-09-09）：那儿曾经有个叫「全部日期」的 `<select>`，它和筛选
是同一件事（把这一屏变短），却待在另一行、长着另一副样子，而且一天一格，翻到第三十天才找得到
「上周」。它现在是筛选那一行最前面的一排词。
**字号只有两种**：搜索 13（要往里打字），其余 12；第一行 `align-items: baseline`。

**时间轴**（右边，`--axis` 60px）：一天一行，相对日 + 条数，**右对齐、11px**——它是索引，不是内容。
日期短到 `9/4`。点一行跳过去，滚动时自己跟着走。

**卡片区**：只有记录。**日期抬头不显示**——哪一天由右边的时间轴说。
`.jg-day` 留着当锚点和一天与一天之间的留白，它是 `height: var(--a5)` 的一块空白，
**不能再 sticky、不能有底色**——一个没有字的不透明块钉在滚动区顶上，就是一条划过去会盖住卡片的横带。
**筛选是两级的，一级就是屏幕上那五种纸。**（2026-09-09 用户定的，第六版。）

```
不限 · 今天 · 昨天 · 近 7 天        全部 · 剪贴板 · 截图 · 收藏 · 文件 · 录音
  全部 · 文字 · 图片 · 链接          ← 二级，只在选了一级之后才出现
```

| | 是什么 | 值 |
| --- | --- | --- |
| 时间 | `#fdates`，一排词 | 不限 · 今天 · 昨天 · 近 7 天 |
| **一级** | `#fbuckets`，一排词 | 全部 + 五种纸（`store.js` 的 `entryBucket`） |
| **二级** | `#fsub`，缩进一行，跟着一级换 | `store.js` 的 `entrySub` |

**一级必须和 `cardKind()` 是同一个轴。** 前五版筛的都是「格式」（文字 / 图片 / 链接），
而一张从剪贴板来的图和一张截图都算「图片」，在屏幕上却是两种完全不一样的纸——
**筛的轴和看的轴不是同一个，那五版之所以都难看，根在这儿。**
五格**互斥、全覆盖**：每条记录落在且只落在一格里，五个数加起来一定等于全库
（「文件」是兜底那一格，不留孤儿）。

**二级每一格问的问题不一样**，这是这套分法好用的地方：收藏 / 截图问「从哪儿来」（站点、应用），
文件问「是什么」（真的扩展名），录音问「哪只麦克风」，剪贴板问「是什么」（文字 / 图片 / 链接）。
**一个维度对所有东西问同一句话，就总有一半答不上来**——旧那一档「来源」最大的一格是
「未知」，144 条，占 44%。分了级就没这问题：问截图从哪儿来是有答案的，剪贴板压根不问这一句。

**二级的值是开集，只有剪贴板那一格是闭集。**（2026-09-09 用户点出来的。）
收藏的站点、截图的应用、录音的麦克风、文件的扩展名——都是「库里出现过什么就有什么」，
不能写死一张表。**文件那一格踩过这个坑**：一开始用的是 `entryFormat` 那张 11 项的固定表，
于是 `.sketch` 和 `.dmg` 一起进了「其它」——实测 11 样拖进来的东西，固定表分出 8 格
（「其它」装着三样不相干的），真扩展名分出 10 格。
剪贴板是例外，因为它**装得下的东西就那么几样**，那才是闭集该在的地方。

**二级只在选了一级之后才出现**，所以默认那一屏仍然只有一行字；**只剩一个值时整排不出现**
（一个筛不掉任何东西的词不值得占一行）。缩进 `--a4` 是唯一说得出「父子」的手段——
这套里没有线、没有框、没有底纹。

**数平时不写出来，只在选中的那个和鼠标停住的那个上出现。** 一行十几个数字读起来是一条数字带，
不是一排能按的词。**位置一直留着**（`.n` 定宽 2.1em + `opacity`，不是 `display:none`）：
鼠标扫过去整行字跟着左右跳，比十几个数字还难受。

**每个数必须等于点下去之后屏幕上的条数。** 这是这个筛选器唯一的正确性要求，而 2026-09-09
之前它是错的：「筛」和「数」是两段各自算的代码，界面上「全部」偷偷扣掉剪贴板（331 条里 262 条），
数数那一路不知道，于是行上写「文字 203」、屏上摆 19 条。修法不是给数数那一路也补上那条规矩
（那只是把同一个错误抄两遍），而是**让两条路共用同一个判据**：`store.entryMatches`。
`stats()` 收和 `listEntries()` 同一套条件，每一档**放开自己那一维、照筛别的**。
守卫在 `dev/filter-count-test.js`：每个数都真的去 `listEntries` 要一遍，一万两千个数，
外加互斥和全覆盖两条结构不变量。

**「全部」里默认不含剪贴板**（一天到晚自己往里掉，一屏九成是它就不叫「全部」了）。
这条规矩以前是写死的一句 if，现在是**设置里一个开关**（`clipboardInAll`），而且在屏幕上看得见：
「全部 69 · 剪贴板 262」两个数摆在一起，本身就说明了「全部」里没有剪贴板。
判据是 `listEntries` / `stats` 的 `hideInAll`——**它只在没选一级时生效**，
点了「剪贴板」那一格就必须看得见剪贴板，一条无条件的排除做不到这件事。

**顺序写死，不按数排**：一排词的位置每次进来都不一样，肌肉记忆就没了；数会变，位置不该跟着变。
同理，**「永远筛不窄任何东西」的词才隐藏**，判据看整个库不看眼下这一刀（库里只有六天时
「近 7 天」和「不限」是同一批）——按眼下这一刀算的话，点一下别的格子，「今天」会当场消失。

筛选仍然是**单选**：一次只看一类（2026-09-06 从多选改回来的——两个能同时按的东西会让
「现在在看什么」说不清楚）。

**这一处走了六版**：① 三个维度名一排 + 当前维度的值一排——维度名和筛选值长得一模一样，
点一下换的是「列什么」不是「筛什么」；② 同样两群并到一行——选中的值在同一行上出现了两次；
③ 类型一排词 + 右边一个「＋ 筛选」弹出面板——多一层要点开才知道里面有什么；
④ 原生 `<select>`——系统画的那个菜单和这张纸格格不入（用户原话：「别用下拉框，而是一个下拉了
大托盘类似的」）；⑤ 自己的大托盘 `.ftray` + 一排类型词 + 一个剪贴板开关——一行上并排站着
**四种长得一模一样、按起来却各不相同的东西**（单选、单选、开关、下拉），而且行上一个数都不对；
⑥ 现在这个。**②③④⑤ 的共同毛病是在长相上找答案，而问题一直在那个轴上。**

注意 ⑥ 和被否掉的 ① 不是一回事：① 上面那排是**维度名**，点一下换的是「列什么」；
这里上面那排**自己就在筛**（点「截图」当场只剩 34 条），下面那排是在它里头再收一刀。
一个是换挡，一个是父子。

**关闭键在右上角，是一只 30px 的正方托盘**（`.wtray`）——和看图窗右上角那只、详情卡片上那几只
同一件东西：`--slip` 的底、直角、`--e2` 的影子。（2026-09-07 改。原先写的是"关闭键在左上角，
macOS 的窗口控件历来在那儿"——但这扇窗自己画的那个 × 不是红绿灯，左上角一个孤零零的小图标
既不像系统控件，又和搜索框在同一行留下两条差 26px 的左边线。）
**它必须是拖拽带里的普通流内元素**：`-webkit-app-region: no-drag` 在 drag 区里挖的那个洞，
是按**未脱离文档流、未变形**的盒子算的，所以这只托盘既不能 `position: absolute/fixed`，
也不能靠 `transform` 定位——否则看得见的托盘和能点的那块洞会错开，症状是「叉叉点了没反应」。
（关闭本身也别用渲染进程的 `window.close()`：`loadFile` 出来的顶层窗口不是脚本打开的，
Chromium 会直接忽略。走 `ws:close` 到主进程。）

## 身份

**它是 briffy 这个回形针，不是宠物，更不是猫。** 界面文案里不出现「小猫 / the cat」——
桌面上那个东西就叫 briffy。（2026-09-05 用户原话：「和猫没有任何关系，就是 briffy 这个回形针」。）

- **拖拽带要给窗口边框让开 6px**（`.winbar { top: 6px; left: 6px; right: 6px }`）。
  无边框窗口靠边上那几个像素改大小，而 `-webkit-app-region: drag` 会把它们抢走——
  顶到 0 的话上边、左上、右上三处都拖不动，症状是「想改窗口大小非常困难」。
  普通内容不会挡（macOS 的 resize 边框在网页命中测试之外），**只有 drag 区会**。

## 窗口

工作区窗口是**无边框**的（`frame: false, roundedCorners: false`）：macOS 只给无边框窗口关掉圆角，
而全直角是硬约束。代价是没有红绿灯，所以自己画：顶上一条 44px 的透明拖拽带 `.winbar`
（`top: 6px` 起，`padding-top: 14px`），里面左边是搜索托盘、右边是关闭托盘。

  **尺寸只有两种**（2026-09-08 用户定的）：**正方（小）· 两个正方那么宽的长方（大）**，`tileRatio()` 只返回 1 或 2。
  之前是五种纸各自一套 s/m/l 的宽高比（0.85 到 3.4，十五个数），一屏上每张卡都是不同的形状，排出来没有节奏。
  **算的是「格」，不是宽高比。** 大卡的宽 = **两个方格 ＋ 它们之间那道缝**（`2 * cell + gap`），
  不是「方格宽的两倍」——差的正好是一个 `gap`，用宽高比 2 去摆，一张大卡总比它上下那两张小卡窄 8px，
  列就永远对不齐（2026-09-07 用户原话「大卡片的宽度应该刚好等于俩小卡片」）。
  **列数是整页固定的**（`gridPlan()`）：`cols = round((width + gap) / (target + gap))`，
  `cell = (width - (cols-1) * gap) / cols`，于是**全页每张卡同高、每张小卡同宽**。
  以前是 Flickr 那种等高行——每行自己算高度去铺满宽度，一行 4 格的行格子比一行 6 格的大三分之一，

  **一行只剩一格、下一张又是大卡时，把它收成小卡**，不留窟窿——记录是按时间排的，不能为了填满

  **没有影子**（贴在屏幕边上的一张纸，那圈阴影只会把它和屏幕割开）。
  **不吸边**（2026-09-06 取消）：放哪儿是放的人说了算，松手就停在那儿，只保证它整个还在屏幕里（`clampToDisplays`）。
- **展开列表**（shelf）：站在头像**正上方**、右边缘和头像右边缘对齐，从下往上抬 14px 滑进来。
  里面**每条是一张便签**，和工作区同一套纸（`--slip` + `--e1`、直角、五种纸各带自己那件物证），
  不是一条一行的清单——2026-09-06 改的。
  **三条让它不卡、不乱关的规矩**：
  ① **窗口的下沿正好压在头像窗口的上沿，不多一个像素**，面板和头像之间那 10px 的空隙由
  `#panel { bottom: 10px }` 让出来。把空隙留在窗口外面，指针从头像挪到面板的路上会经过
  「谁也不在」的地带，关闭计时器跑起来——症状是「鼠标还在上面它就消失」；
  **但也一个像素都不能再往下探**：这扇窗 300px 宽、右边 262px 是不透明的面板，
  只要盖到头像窗口上，那枚回形针就被压在下面看不见了（2026-09-06 两头都踩过）；
  ② **内容没变就别重画**：每次停到头像上都 `innerHTML =` 一次，十五张缩略图跟着重解码一遍，这是「卡」的大头。
  比一个签名，一样就什么都不做；
  ③ **卡片要 `flex: none`**：`.list` 是竖着的 flex，装不下的时候每个孩子默认被压扁，
  而卡片里那张 84px 的图不跟着压——于是图溢出自己那张卡，盖住下面一张（「卡片会互相遮挡」）；
  ④ **别给每条加 `transition-delay`**：十五条各错开 18ms，最后一条要等到 180ms 之后才动，整块读起来就是慢。
  整张纸一起滑进来，220ms 结束。
- **拖文件进工作区窗口** = 拖到常驻头像上：同一个 `pet:drop`，窗口上压一层 `--scrim` 说「松手就存进来」。
- **看图的窗口**（`src/renderer/viewer/`，点详情里那张图打开）：一张图自己的一扇窗，像聊天软件点开大图那样。
  **这里的底是深的**（`--vbg #1c1b1a`），是全应用唯一一处——一张暖白的纸围着一张彩色照片会一直跟照片抢眼睛，
  所有看图的东西都用深底，理由一样。纸质那套语言没丢，只是纸变成了**托盘**：每个工具是一只 34px 的
  `--slip` 正方托盘 + `--e2`，和详情窗右上角、底部那三只是同一种东西；选中＝实心。
  无边框、全直角，关闭是右上角一只 30px 的正方托盘。
  **图只能放大，不能缩小**：下限就是「铺满这个框的宽或高」（`fitZoom`），按钮、滚轮、窗口变大之后都按这个夹住。
  再往下缩只是把图丢进一片空底里，没人想看那个；缩回下限时平移也归位。
  底栏三组：**左**＝展开（右侧铺开 briffy 里所有的图）· 缩小 · 放大 · 1:1 · 旋转；
  **中**＝画框 · 画圆 · 画笔 · 马赛克 · 添加文字 · 裁剪（把当前这张换成框住的那一块，画上去的东西一并烙进去；
  原文件不动，只是眼前这一张）· 撤销；
  **右**＝一键翻译 · 复制 · 图钉（`setAlwaysOnTop(true, 'screen-saver')`，普通的 floating 压不住全屏应用）。
  粗细和颜色是从当前那个工具**正上方**升起来的一条（照 macOS 标注那条做的），只在真会用到时才出现。
  **画的东西存成一串形状，不糊到像素上**：所以能撤销、放大之后位置还对得上、导出时按原图分辨率重画一遍——
  屏幕上是缩放后的样子，复制出去的是原尺寸。坐标一律记在**图片自己的像素**里。
  马赛克是唯一要读原图的（按格子重采样）。
  **三个反复踩的坑**：① 带 `transform` 的祖先会成为 `position: fixed` 的**包含块**——
  框选那个 `.marq` 放进 `.canvasWrap` 里就永远对不上鼠标，它得待在外面；
  ② `pointerdown` 的默认行为会把焦点交给被点的元素，刚 `focus()` 的输入框当场被抢走、
  blur 立刻触发——所以选中工具时要 `preventDefault()`，焦点也放到 `setTimeout(…, 0)` 里给；
  ③ **缩放要围着图自己的中心算，不是窗口中心**：台面有内边距，展开网格之后右边还会缩进去一截，
  拿窗口中心当图的中心，缩放就跟不住鼠标。
  **它取代了详情里那个 `.lightbox`**（点图往 body 上贴一张全屏图的老做法）——加窗口的时候必须把老的删掉，
  两个都留着的话点一下会同时发生：开窗口，再贴一张 `z-index: 20` 的大图，
  它盖住整个主页又压在 `z-index: 60` 的详情窗底下，看着就是「详情卡片后面的主页变成了图片」。
  **一键翻译走的是已经识别好的文字，不是把图发出去**——
  图片从不出这台电脑那条规矩在这儿一样算数。
- **没有对话气泡**（2026-09-06 删掉）：桌面上那只自己会换表情，底下还有 REC 和三个点，
  一个漂在旁边的框既遮住它、又和书架抢地方。`setPetState` 仍然收 `message`，只写进日志。
  **代价记在这里**：只出现在气泡里的那些错误文案（麦克风被拒、截图失败、快捷键冲突）
  现在只剩下一张出错的脸，没有字。
- **emoji**：`grayscale(1)` + 75%。
- **多选**：主页的字**不给选**（`user-select: none` 打在 `.jg / .jg-tile / .lv-rows / .axis / .top / .dock` 上）——
  这里每张便签都是可点、可框、可拖的**物件**，拖的时候顺手选中一行字，拉框就变成了刷高亮。
  要读字就点开详情，那里 `user-select: text`。入口有五个，都跟系统习惯对齐：
  顶栏那个勾选图标、Cmd/Ctrl 点一张便签、空白处按下往外拖（拉框）、Cmd/Ctrl+A 全选、Cmd 点右轴上的某一天（当日多选）。
  Shift 点是连选（按 `state.entries` 的顺序取区间），Esc 或点空白退出。
  **拉框拖到上下边缘要自己接着滚**，起点钉在纸上而不是屏幕上（滚了多少，起点跟着走多少）——
  否则一屏装不下的时候只能松手、滚一段、重来一次。网格和列表用的是同一个 `startMarquee(down, scroller, itemSel)`。
  **批量条不是第四只托盘，是中间那只换了内容**：同一处、同高、同边距，左边的加号和中间的问句一起让位
  （`body.picking`）——两只托盘叠在一处就成了一堆按钮，那是「栏」，不是托盘。

## 会动的 briffy

**唯一实现：`assets/brand/briffy-anim.js`**（无依赖、无构建，node 里 `require` 得到、页面里 `<script>` 挂上就有 `window.briffyAnim`）。
样张 `/briffy`，测试 `npx electron dev/briffy-anim-test.js`。

- **两道弧永远不变形。** 半径、圆心、描边全部照抄 `briffy.svg`，代码里没有任何一条路径能改它们。
  会动的只有一张脸（两只眼、一张嘴），和整只回形针作为**一个刚体**被平移 / 歪 / 缩放（支点在脚下 318.25, 638）。
  静止那一帧和 `briffy.svg` 逐字符相同——嘴那条 `d` 就是文件里的 `M291.5 320 A27.6 27.6 0 0 0 345.5 320`。
- **弹簧，不是关键帧。** 阻尼谐振，固定 120Hz 积分（掉帧不改变观感）。每个状态只说「去哪儿」，
  中途被打断是免费的：从当前位置、当前速度改朝新目标去。截图落在录音中间、出错落在保存中间，这是常态。
- **弹簧必须会停**，这是它能存在的前提。桌面窗口透明、置顶、永不关闭，每要一帧就是一次永不停止的 alpha 合成
  （pet.css 那笔账：3 个 `infinite` = 一个核的 11.4%，静止 0.9%）。所以到了目标附近且速度耗尽，
  就精确落到目标并 `cancelAnimationFrame`——两个状态之间一帧都不画。**不要在这里加任何 `infinite`。**
- **动作靠 `kick`（速度），不是关键帧位移。** 一个阻尼弹簧以 v0 释放只能走到约 `v0/(2·ω_d)`：
  638 的画布上 kick 90 只换来 2.7 单位，在桌面 50px 上是五分之一像素。
  改 kick 之后去看 `dev/briffy-anim-test.js` 打的那张峰值表，别靠脑补。
  现在：点头 9.0° · 跳 30.2 单位 · 摇头 22.1 单位 · 吓一跳 1.10×。
- **嘴用「矢高」不用半径。** 半径过不了「平」——笑变哭要在两个 sweep 之间跳一次、经过无穷大。
  矢高有正负、平滑过零，零就是一条直线，那正是嘴从笑走到哭的中途该有的形状。
- **持续状态的差别必须是「形状」，不是「动作」。** 录音要跑几分钟，弹簧在头一秒之后就睡了，
  所以说明「在听」的东西得在什么都不动的时候还在说。第一版把录音做成「眼睛大 6%、笑小一点」，
  在实际尺寸上和待机分不出来。现在：录音＝窄而高的专注眼 + 一条直嘴；截图＝又圆又大的眼 + 一个小小的 o。
  两个状态在时间上紧挨着（录完就截），不能收敛成同一张脸。
- **六个状态**（就是 pet.js 已经在广播的那六个，没有新事件）：
  待机 · 录音 · 处理中 · 截图 · 存好了 · 出错。
- **别人的标记不做表情。** 桌面形象只有用内置那张（`petskin.isBuiltin`）时才画活的 briffy；
  从图库里挑了别的 logo，就退回成框里的一张图片。
- 用在：桌面常驻形象（`.live`，和 `<img>` 同一个盒子，所以「探头」手势推谁都一样）、
  引导页第一步和最后一步（最后那个绿方块 ✓ 换成了它点头）、扩展安装页（那只 🐱 换成了它）。
  安装页是 http 出来的，够不着 file:// 资源，所以 `install-page.js` 把这个文件读进来内联。

## 动效

三种：按钮下沉 1px；记录 hover 抬 2px；面板滑入（shelf `.22s cubic-bezier(.16,1,.3,1)`）。

**存东西是一瞬间的事，动画就该是一瞬间。**（2026-09-06）桌面那只的状态时长对着弹簧真正的时长来
（点头 1.07s、摇头 1.14s、pop 0.42s）：`capturing 260 / success 1200 / error 3000`。
原来 `capturing` 是 4000——按下快门之后那只回形针要瞪四秒钟眼睛，读起来像它在犯难。
**更要紧的是：后处理的时间不能挂在脸上。** OCR、起标题、转写都是后台的活，东西早就存下了；
以前它们会一路把脸按在「处理中」（三个点一直跳）直到队列清空，那等于把后处理算进了「存东西」这个动作里。
现在存完就是一次点头，然后回待机；只有**你确实在等**的两处还用「处理中」：
自动配置（在下模型）和长截图开始（等你滚）。
**同一个状态再来一次要重演**：连着存两样东西时主进程会发两遍同样的状态，
而 `face.set` 在状态没变时什么都不做——第二次就一点反应也没有。pet.js 里靠 `poke` 补上。
常驻窗口（pet / shelf / bubble）不跑 `infinite` 动画——pet.css 顶部那笔 CPU 账是硬约束。
