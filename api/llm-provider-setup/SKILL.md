# LLM Provider Setup

애플리케이션의 LLM 연결 설정을 완성한다. 사용자가 범위를 달리 지정하지 않았다면 OpenAI, Anthropic, Google Gemini, xAI를 대상으로 한다. 기존 지원 대상이나 연동 방식을 무단으로 제거하지 않는다. 단순 API 사용법 질문이나 설정 화면과 무관한 모델 선택은 이 워크플로우의 대상이 아니다.

자연어 호출 예시: "프로바이더 스킬로 진행해", "프로바이더스킬로 진행해", "llm-provider-setup 스킬로 LLM 연결 설정해줘". 기본 설치는 source-only이므로 현재 CLI 카탈로그의 정확한 원본 경로에서 읽는다. 네이티브 slash 메뉴 등록을 전제로 하지 않는다.

## 착수

1. 프로젝트의 설정 화면, 비밀 저장소, 서버 API, 기존 SDK·버전·호출 경로와 테스트를 먼저 확인한다. 기존 composition point를 확장하고 프로젝트 언어와 UI 관례를 따른다. 웹, 데스크톱, 로컬 앱의 신뢰 경계를 구별한다.
2. **설정을 구현하거나 변경할 때마다** 각 대상 프로바이더를 따로 검색하여 현재 공식 모델 목록·모델 조회 API·추론 옵션을 확인한다. 네 제공자를 대상으로 하면 네 곳 모두 확인한다. 현재 문서 검색 도구 또는 웹 검색을 이용하고 프로바이더 공식 문서를 근거로 삼는다. 이전 작업의 모델 목록이나 기억만으로 최신이라고 판단하지 않는다. 프로젝트 SDK 버전과 인증·생성 API 제약도 확인하고, 검색·확인하지 못한 제공자는 `NOT RUN`으로 보고한다.
3. 기본은 사용자 소유의 **각 프로바이더 API 키를 사용한 직접 연결**이다. 이미 게이트웨이를 사용하거나 사용자가 지정한 경우 그 계약을 따른다. 신규 게이트웨이, SDK 또는 UI 라이브러리를 일방적으로 강제하지 않는다.

## 설정 동작 계약

- 프로바이더별 API 키를 입력·교체·삭제하고 저장 여부를 구분해서 표시한다. 저장한 키 원문은 화면이나 읽기 API로 다시 반환하지 않으며 빈 입력이 기존 키를 지우지 않게 한다. 키는 로그, 오류, 테스트 기록, 브라우저 저장소에 노출하지 않는다. 서버형 앱은 인증·인가된 서버의 기존 비밀 관리 방식에 저장하고, 로컬 앱은 OS 비밀 저장소 등 신뢰 경계에 맞는 수단을 쓴다.
- **설정 화면을 열거나 프로바이더 또는 API 키를 변경할 때마다** 해당 제공자의 공식 모델 목록 API를 그 키·계정으로 새로 조회한다. 사용자가 다시 조회할 수 있는 새로고침도 제공한다. 웹 앱은 서버에서 조회하고 로컬 앱은 해당 환경의 신뢰 경계에 맞게 요청한다. 페이지네이션과 해당 작업에 필요한 모델 유형 필터를 처리한다. 조회 중에는 기존 목록이 있다면 갱신 중임을 표시하고, 마지막 성공 시각과 실패 여부를 구분한다. 인증이 없으면 키 입력 후 조회한다. 임의의 고정 목록이나 제3자 검색 결과를 실시간 계정 목록으로 표시하지 않는다.
- 조회한 목록에는 가능한 최신 지원 모델을 표시한다. 공식 응답이나 문서로 확인한 출시·갱신 정보를 우선 사용하고, 순서나 버전 번호만으로 최신 여부를 지어내지 않는다. 목록 응답은 실제 생성 권한이나 모델별 추론 옵션을 보장하지 않으므로 공식 계약과 연결 테스트로 별도 확인한다.
- 공식 목록 조회가 없거나 실패하면 출처와 확인 시점이 있는 보수적인 대체 목록 또는 마지막 정상 캐시를 사용하되 최신·사용 가능하다고 단정하지 않는다. 어떤 경우에도 직접 모델 ID를 입력할 수 있게 한다. `models.dev` 같은 제3자 카탈로그는 참고·보조 데이터이며 프로바이더 계정의 권한이나 공식 계약을 대신하지 않는다.
- 모델 선택 목록에 `직접 입력`을 제공한다. 목록 선택 시 정확한 API 모델 ID를 모델 입력 필드에 반영하고, 직접 입력 시 필드를 편집할 수 있게 한다. 기존에 저장한 목록 밖 ID를 불러와도 보존한다. 프로바이더 변경 시 서로 다른 공급자의 모델·추론 설정이 섞이지 않게 하고 사용자 입력을 조용히 유실하지 않는다.
- 선택한 **프로바이더 + API 경로 + 모델**에 대해 공식 문서로 확인한 추론 옵션만 표시하고 해당 API의 실제 요청 형식으로 전송한다. 제공자마다 열거형, 예산, 자동 설정 등 표현과 지원 범위가 다를 수 있다. 일률적인 low/medium/high 매핑이나 추론 미지원 단정을 하지 않는다. `기본값`은 관련 파라미터 생략을 뜻한다. 모델이나 프로바이더 변경으로 기존 설정이 유효하지 않으면 사용자에게 알리고 유효한 기본값으로 되돌린다. 직접 입력 모델의 지원 여부가 불명확하면 안전하게 기본값을 사용하고 그 이유를 표시한다.
- 설정 저장 후 실제 생성 호출에서 같은 프로바이더, 모델 ID, 추론 옵션, 키가 사용되도록 끝까지 연결한다. API 키·모델·옵션별 설정 범위는 기존 앱의 사용자/조직 권한 모델을 따른다.
- 연결 테스트는 실제 요청의 대상과 결과를 명확히 하며, 목록 조회 성공만으로 생성 호출 성공을 주장하지 않는다. 지원되는 최소 생성 요청을 사용하고 비용이 발생할 수 있음을 UI에 표시한다. 인증 실패, 모델 접근/미지원, 잘못된 추론 옵션, 할당량·속도 제한, 네트워크 실패를 가능한 범위에서 구분한다. 호출을 자동 반복하거나 임의로 다른 유료 모델로 전환하지 않는다.

## 검증

기존 테스트 도구로 설정 화면 열기·프로바이더 전환·키 변경·새로고침 때 올바른 제공자의 목록이 재조회되는지 확인한다. 응답 순서가 뒤바뀌어도 이전 제공자의 결과가 현재 선택을 덮어쓰지 않아야 한다. 모델 목록 선택→ID 반영, 직접 입력·재로드, 추론 옵션과 실제 요청 매핑, 키 유지·교체·삭제, 목록 실패와 연결 오류도 검증한다. 서버 설정 API가 있으면 권한 없는 직접 호출, 잘못된 값 거부 및 저장 상태 불변도 확인한다. 서버에서 사용자 지정 URL을 허용하는 기존 기능을 다룬다면 대상 검증과 내부 주소 접근 제한을 확인한다.

실제 프로바이더 호출은 사용 가능한 자격 증명과 환경이 있을 때 최소한으로 실행한다. 모의 테스트, 목록 조회, 실제 생성 호출을 구분해 보고하고, 자격 증명·환경이 없어 실행하지 못한 항목은 `NOT RUN`으로 표시한다. 실서비스 API 키를 테스트 로그나 산출물에 남기지 않는다.
