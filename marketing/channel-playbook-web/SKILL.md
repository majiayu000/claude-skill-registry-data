# Channel Playbook -- Web

Cargado por los Agentes B, C y D cuando web es uno de los canales activos.

La web no es un folleto digital. Es el lugar donde el cliente toma decisiones. Todo lo que aparece en pantalla debe reducir fricción, no anadirla.

Principio Maestro: **"Claridad es conversión."** Un precio claro convierte más que un precio maquillado. Una condición explicada convierte más que una condición escondida. Una página con un foco convierte más que una página con cinco ofertas compitiendo. Este principio tiene precedencia sobre cualquier petición de anadir más contenido, más banners o más CTAs a una página.

El modelo que este documento reemplaza es: "Cuanto más contenido pongamos, más posibilidades de que el usuario encuentre algo que le interese." El modelo que este documento instaura es: "Menos saturación. Más claridad. Más confianza. Más contratación."

---

## 1. Función del canal

La web cumple cinco funciones dentro del ecosistema Movistar:

1. **Cerrar decisión.** La web es destino final de trafico de otros canales (email, display, Meta, tienda). Si el cliente llega, ya ha sido impactado. La web debe cerrar, no repetir el pitch.
2. **Explicar con profundidad.** Lo que no cabe en un email o un banner se desarrolla aquí. Comparativas, configuradores, detalle de producto.
3. **Construir confianza.** Claridad en precios, condiciones y beneficios. Sin letra pequena escondida. Sin asteriscos sin resolver.
4. **Capturar intención.** Trafico orgánico de busqueda. El usuario viene con una pregunta; la web debe responderla.
5. **Facilitar autogestion.** Área privada, consulta de facturas, gestion de servicios. La web resuelve sin necesidad de llamar.

---

## 2. Principios clave

1. **El precio debe vender, no confundir.** Si el precio requiere tres asteriscos y letra pequena para entenderse, no esta listo para web. Simplificar antes de publicar.
2. **Primer momento de valor en tres segundos.** El usuario debe entender que gana en los primeros tres segundos de scroll. Si el hero no comunica valor claro, la página falla.
3. **Ventaja Personal es el centro.** En área privada y en comunicación a clientes logados, Ventaja Personal debe sentirse como reconocimiento personalizado, no como banner genérico.
4. **Un CTA por pantalla visible.** Si el usuario ve dos botones compitiendo en el mismo viewport, hay un problema de jerarquía.
5. **Cada página tiene una mision.** Landing de campaña = conversión. Página de producto = decisión. Área privada = gestion. No mezclar misiones.
6. **Claridad es conversión.** Un precio claro convierte más que un precio maquillado. Una condición explicada convierte más que una condición escondida.
7. **Móvil primero.** La mayoria del trafico llega por móvil. Si la experiencia mobile no funciona, la página no funciona.

## 3. Estructura de landing de campaña

| Bloque | Función | Regla |
|---|---|---|
| Hero | Propuesta de valor en una frase + visual | Un mensaje, un CTA. Sin slider. Sin multiples ofertas. |
| Beneficio principal | Explicar por que importa | Lenguaje de beneficio humano, no de spec técnica. |
| Prueba / RTB | Razon para creer | Dato concreto, ventaja tangible, o prueba social si aplica. |
| Detalle de oferta | Precio, condiciones, lo que incluye | Precio claro, sin asteriscos ambiguos. Condiciones visibles. |
| CTA principal | Dirigir a contratación o siguiente paso | Boton visible, texto de acción ("Contratar", "Ver mi oferta"). |
| FAQ o resolver dudas | Anticipar objeciones comunes | Preguntas reales del cliente, no marketing disfrazado. |
| Footer | Cumplimiento y navegación | Disclaimers necesarios + navegación a otras secciones. |

## 4. Tipos de página y su mision

| Tipo | Mision | Que NO hacer |
|---|---|---|
| Landing de campaña | Convertir trafico de pago o CRM | No llenar de productos secundarios. Un foco. |
| Página de producto | Ayudar a decidir con información completa | No esconder el precio. No abrumar con specs sin contexto. |
| Área privada | Gestionar y sentirse reconocido | No convertirla en canal de venta agresiva. |
| Landing de fidelización | Activar beneficios de cliente | No mezclar con captación. Tono de reconocimiento. |
| Página de soporte | Resolver dudas rapidamente | No redirigir a canales cuando la web puede resolver. |

---

## 5. Coordinación con otros canales

La web casi nunca es punto de entrada. Es destino.

- **Desde email/CRM:** El email activa. La web resuelve. El mensaje de la landing debe continuar el del email, no repetirlo.
- **Desde display/Meta:** El banner genera interes. La landing profundiza y cierra. No replicar el banner como hero.
- **Desde tienda:** Si la tienda dirige a web para ampliar información, la página debe estar preparada para ese flujo (QR, URL corta).
- **Desde search:** El usuario viene con intención. La landing debe responder a esa intención directamente.

Regla de coherencia: si el CTA del email dice "Descubre tu ventaja", la landing debe abrir con esa ventaja visible. No con un hero genérico.

## 6. Riesgos y anti-patrones

| Anti-patron | Por que falla |
|---|---|
| Saturación de ofertas | Multiples banners y CTAs compiten. El usuario no sabe donde mirar. |
| Precio con asteriscos sin resolver | Genera desconfianza. El cliente asume que hay trampa. |
| Hero genérico | Imagen de stock sin relación con la oferta. Pierde los tres primeros segundos. |
| Scroll infinito sin jerarquía | Información desordenada. El usuario abandona sin encontrar lo que busca. |
| Ventaja Personal como banner genérico | Si no se siente personal, no funciona. Pierde credibilidad del mecanismo. |
| Mobile como adaptación de desktop | El flujo mobile tiene sus propias reglas. No es "lo mismo pero más estrecho". |
| CTA ambiguo | "Saber más" no es un CTA. "Contratar ahora" si lo es. |

## 7. KPIs estandar

| Metrica | Para que sirve |
|---|---|
| Tasa de conversión de landing | Mide si la página cumple su mision |
| Scroll depth | Indica si el contenido engancha |
| Click a CTA principal | Mide efectividad de la jerarquía visual |
| Bounce rate | Alerta de desconexion entre origen y destino |
| Tiempo en página por sección | Identifica donde se atasca o se pierde el usuario |
| Tasa de autogestion (área privada) | Mide si la web resuelve sin derivar a call center |

## 8. Principios de tono y diseño

P08. **La web habla con transparencia.** Movistar web no esconde condiciones, no maquilla precios, no entierra la letra pequena. Si una condición es importante para la decisión del cliente, debe estar visible donde se toma esa decisión, no tres scrolls más abajo.

Tono prohibido: asteriscos sin resolver, disclaimers que contradicen la oferta del hero, condiciones que solo aparecen en el ultimo paso del checkout, precios "desde" sin contexto real.

Tono correcto: precio real visible, condiciones junto a la oferta, transparencia como argumento de venta.

P09. **Cada scroll debe aportar valor.** Si un bloque no mueve al usuario un paso más cerca de la decisión, sobra. El scroll infinito sin jerarquía es el equivalente web de la tienda saturada de soportes.

P10. **La landing no es el canal de origen.** El email activa. El banner genera interes. La landing profundiza y cierra. No debe replicar el mensaje del canal de origen: debe continuarlo y resolverlo. Si el hero de la landing es idéntico al banner que trajo al usuario, la página no aporta nada nuevo.

P11. **Ventaja Personal en web debe sentirse como área VIP, no como banner más.** En área privada, Ventaja Personal debe personalizar la experiencia: catálogo adaptado, ofertas relevantes al perfil, tono de reconocimiento. En landing publica, Ventaja Personal puede usarse como gancho ("Tienes una ventaja esperandote"), pero debe resolverse al logarse, no con un descuento genérico.

## 9. Reglas de validación automatica

| ID | Regla | Tipo |
|---|---|---|
| W01 | La página no tiene mision única identificable | RECHAZO |
| W02 | El hero no comunica valor claro en los primeros tres segundos | RECHAZO |
| W03 | Hay más de un CTA principal visible en el mismo viewport | CORRECCION |
| W04 | El precio requiere asteriscos o letra pequena para entenderse | CORRECCION |
| W05 | Las condiciones comerciales no estan visibles junto a la oferta | CORRECCION |
| W06 | Hay saturación de ofertas o banners compitiendo en la misma página | RECHAZO |
| W07 | Ventaja Personal aparece como banner genérico en área privada | CORRECCION |
| W08 | La landing replica el mensaje del canal de origen sin aportar profundidad | CORRECCION |
| W09 | La experiencia mobile es una adaptación de desktop, no un diseño propio | ALERTA |
| W10 | Las FAQs contienen marketing disfrazado en vez de respuestas reales | CORRECCION |
| W11 | El CTA usa texto ambiguo ("Saber más") en vez de acción concreta ("Contratar") | CORRECCION |
| W12 | La página mezcla misiones (conversión + gestion + fidelización en la misma landing) | RECHAZO |

Tipos: RECHAZO = la pieza no puede aprobarse. CORRECCION = debe modificarse antes de aprobación. ALERTA = requiere justificación editorial explicita.

## 10. Referentes de calibración

| Referente | Atributo principal aplicable |
|---|---|
| Apple.com | Hero con un solo mensaje. Precio claro. Flujo de compra sin fricción. |
| Revolut | Transparencia radical en condiciones. Landing de producto = una idea, un CTA. |
| Stripe | Claridad técnica traducida a beneficio humano. Documentación como experiencia. |
| N26 | Área privada como experiencia premium. Personalización sin presión comercial. |

---

## 11. Checklist rápido para agentes

Antes de validar cualquier pieza web:

- [ ] El precio se entiende sin asteriscos ni letra pequena.
- [ ] El primer viewport comunica valor claro.
- [ ] Hay un único CTA principal visible por pantalla.
- [ ] La página tiene una sola mision definida.
- [ ] Ventaja Personal se siente personalizada, no genérica.
- [ ] Hay coherencia de mensaje entre el canal de origen y la landing.
- [ ] La experiencia mobile esta disenada, no adaptada.
- [ ] Las condiciones estan visibles, no escondidas.
- [ ] No hay saturación de ofertas ni banners compitiendo.
- [ ] Las FAQs responden objeciones reales del cliente.
- [ ] La landing aporta profundidad, no repite el canal de origen.
- [ ] La pieza cumple las reglas de validación automatica (W01-W12).

---

## Como usan los agentes este playbook

- **Planner (Estrategia):** lo carga si web esta en `rol_canales` del brief. Define si web es destino de trafico de otros canales (caso habitual) o canal con trafico orgánico propio. Asigna la mision de cada página.
- **Creative Copywriter (Builder):** lo carga para escribir la estructura de copy de la landing por secciones. Respeta la regla de un CTA y un foco. No repite el copy de la pieza de origen.
- **Art Director (Design):** genera mockups de landing (responsive desktop + mobile) con secciones y jerarquía clara. El mockup es conceptual; la versión final pasa por el design system de movistar.es.
