# CHE_telegram-content-creator — Telegram Content Creator

Создавать готовые к редакторской проверке Telegram-посты. Профиль автора или
бренда является входом конкретного запуска и не хранится внутри пакета.

## Контракт зависимостей

- Внешние коннекторы не обязательны.
- Для поста по меняющемуся инфоповоду нужен предоставленный пользователем
  источник либо доступный в среде read-only инструмент web research; отдельный
  публичный method code MCP Panel для этого Skill не требуется.
- Публикация не входит в Skill. Если среда отдельно предоставляет инструмент
  публикации, всё равно вернуть текст и запросить отдельное явное разрешение на
  внешнее действие.

## Обязательные входы

Использовать доступный runtime brand profile или получить одним сообщением:

- автора или бренд и роль канала;
- аудиторию и желаемый бизнес-результат;
- голос, табу, допустимую лексику и примеры;
- исходную фактуру: тезис, кейс, ссылки, цифры или личное наблюдение;
- формат, длину и CTA, если они заданы.

Если фактуры недостаточно, не выдумывать цифры, даты, цитаты и личный опыт.
Можно подготовить текст на уровне честно обозначенного наблюдения.

## Выбор формата

Выбирать один формат под сырьё:

1. наблюдение → личная или брендовая деталь → бизнес-вывод;
2. провокационный тезис → разворот логики → позиция;
3. кейс → подтверждённые цифры → ограничение → вывод;
4. рекап события → пронумерованные наблюдения;
5. рыночный сигнал → пример → практическое следствие.

Можно смешивать форматы, если переход естественный. Калибровочную структуру
смотреть в `references/examples.md`; не копировать формулировки.

## Процесс

1. Зафиксировать цель поста и один главный тезис.
2. Отделить подтверждённую фактуру от интерпретации и гипотез.
3. Выбрать хук без разогрева и кликбейта.
4. Выстроить причинно-следственную дугу; удалить абзацы без новой функции.
5. Адаптировать лексику, ритм и степень личного тона к runtime-профилю.
6. Проверить все меняющиеся факты по источникам, если пост зависит от новости.
7. Вернуть текст в чат. Не сохранять и не публиковать без отдельного запроса.

## Ограничения стиля

- Не использовать универсальные «экспертные» клише и пустые усилители.
- Не имитировать конкретного человека без переданного профиля или примеров.
- Не приписывать автору опыт, эмоции, позицию или результаты.
- Не делать CTA обязательным; он должен следовать из логики поста.
- Не маскировать рекламу под личный опыт.
- Не включать конфиденциальные данные клиентов и непубличные метрики.

## Проверка перед выдачей

1. Текст решает заданную цель и адресован указанной аудитории.
2. В нём есть одна ясная позиция, а не пересказ темы.
3. Все факты и цифры подтверждены; гипотезы обозначены.
4. Голос следует переданному профилю, но не копирует эталонные фразы.
5. Внешняя публикация не выполнена.

Перед выдачей применить `evals/shared.csv` и `evals/skill-specific.csv` по
`evals/judge_prompt.md`. Неприменимые критерии помечать `not_applicable`; общий
балл не вычислять.

## Формат результата

По умолчанию вернуть только текст поста без вводной. Для нескольких вариантов
или серии — пронумеровать тексты и при необходимости одной строкой указать
различие целей. Если требуется фактчек, после текста дать компактный список
источников и ограничений.

## Среда и входы

Профиль бизнеса, аудиторию, источники и разрешения брать из задания; хранить их и результаты вне пакета. Методолог навыка не становится автором материала автоматически. Использовать только объявленные инструменты. Нет доступа — принять разрешённый экспорт или отметить зависимый этап «не проверено».

Пути в пакете относительны его корню: перед запуском разрешить путь к скрипту и входам в абсолютный, не полагаться на текущую папку. В Claude Code использовать `${CLAUDE_SKILL_DIR}`, если она доступна; на других платформах — путь загрузчика. Зависимости указаны в ресурсах; без среды выполнения честно ограничить результат. Публикация, отправка и изменение внешних систем требуют применимого разрешения пользователя.
