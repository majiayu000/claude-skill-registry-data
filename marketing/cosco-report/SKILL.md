# 中远海运本地报告

## 核心原则

1. 只根据用户提供的事实、表格和可核验资料写结论。禁止补造数字、来源、指标定义或管理判断。
2. 先统一期间、单位、币种、合并范围和正负号，再计算或比较指标。
3. 把内容、样式、图片和来源写入结构化文档模型。禁止把 DOM 文本或 HTML 当成持久化事实源。
4. 使用毫米坐标和同一套页面组件生成编辑态与打印态，确保页面几何一致。
5. 保持本地优先：不得引入 CDN、运行时网络请求、遥测、登录或云上传。
6. 把来源行作为人工可核验内容。检查缺失来源，但不得自动生成来源。
7. 智能体新建特化模板一律使用 `independent`：每个文字、图表和表格直接持有自己的内容，用户打开后编辑完整 `ReportDocument 1.5`。`bound` 只用于加载、维护和回归既有旧包，不得用于新报告生成。
8. 封面与页眉页脚模板只是横竖版作者宏，应用后必须展开为可选中、可移动、可缩放和可替换的普通元素；不得输出整页截图或不可拆的新组件类型。

## 读取资源

- 涉及财务、经营、效率或风险指标时，先读 [references/指标口径.md](references/指标口径.md)。它提供默认计算规则与证据优先级，但不得覆盖用户提供的正式制度口径。
- 新建主题、页面或图表时，使用 [assets/theme-tokens.json](assets/theme-tokens.json) 作为起点。该资产是本地报告主题，不代表公司正式品牌手册；用户提供正式品牌规范时，以正式规范替换数值并保留 token 结构。
- 制作可录入数据并生成 PDF 的特化报告时，先读 [references/report-engine-workflow.md](references/report-engine-workflow.md)，再通过 `scripts/report-engine.mjs` 调用项目内核。不要绕过验证器直接拼接最终 HTML。
- 用户需要新报告需求框架时，读 [references/prompt-create-report.md](references/prompt-create-report.md)。
- 用户要修改某个特化报告时，读 [references/prompt-modify-specialized-report.md](references/prompt-modify-specialized-report.md)。
- 用户要修改所有报告共用的内核能力时，读 [references/prompt-modify-core-engine.md](references/prompt-modify-core-engine.md)。

## 工作流

### 1. 盘点输入

列出输入文件、报告期间、组织范围、目标读者、交付格式和必须保留的制度文字。区分以下内容：

- 已验证事实：原始表格、正式报告、制度文件、用户明确确认的数据。
- 合理推导：能够从已验证数据按明确公式计算的结果。
- 待确认项：期间、单位、范围、口径或来源不完整的内容。
- 禁止推断项：缺少证据的数字、因果关系、预测和归因。

材料不足但不影响结构时，用明确的待补占位符继续排版；材料不足会改变结论时，停止写结论并说明缺口。

### 2. 建立证据与口径表

为每个关键指标记录名称、期间、单位、来源、计算式和口径备注。优先使用用户提供的正式制度，其次是经批准报告，再次是原始系统导出。发现同名指标口径冲突时并列差异，不擅自选一个。

所有派生值保留计算依据。百分比变化区分“百分点”和“百分比”；负基数、零基数或范围变化时不使用普通同比公式制造误导。

### 3. 写一页设计观

在实现前，用不超过五条规则说明本报告的视觉策略：读者首先看到什么、数字层级如何建立、图片承担什么角色、颜色如何表达语义、页面如何保持节奏。避免只写“现代、专业、高级”等不可验收形容词。

母版遵循以下角色：

- 封面：只建立主题、对象、期间和机构层级；背景图必须有可读性叠色。
- 章节页：作为叙事换挡，保留明显留白，不堆业务明细。
- 标准页：用于解释、对比和结论，保持稳定版心。
- 数据页：优先保证坐标、单位、来源和标签可读。
- 尾页：承载免责声明、联系方式与密级，不新增业务结论。

优先从内核模板库选择封面和页眉页脚起点：封面至少在 `cinematic-fullbleed`、`editorial-monogram`、`institutional-rail`、`split-image-panel`、`publication-window` 中择一；内容页至少在 `minimal-rule`、`brand-rail`、`editorial-corner` 中择一。横版和竖版使用各自坐标，不把一套几何机械缩放。选中模板后仍应根据报告叙事和用户要求逐元素微调。

### 4. 组织叙事

默认按“结论摘要、关键指标、原因拆解、风险与行动、口径与来源”组织。只有在输入材料支持时才写原因与行动。每页只承担一个主要问题，标题直接表达信息，不使用空泛章节名。

图表数据必须通过结构化数组进入模型，并在用户侧以按提示词预建的单元格网格编辑；原始 TSV 只可作为内部剪贴板交换格式，不得成为常规界面。表格、图表和关键结论附近保留人工来源行。图表内不放不可验证的装饰数字。

### 5. 应用主题与版式

只存字体槽、字号档位、语义色 token 和白名单行高。不得在元素中写任意十六进制颜色、任意字号或 HTML 字符串。

文字行内标记只允许 `bold`、`accentRed`、`accentGreen`。语义红表示下降、风险或不利偏差；语义绿表示增长、改善或有利偏差。不要仅依靠颜色传达含义。

内容图片与母版图片都引用资产 ID。裁切使用原图像素坐标，不覆盖原图。文字压图时启用主题化叠色并检查对比度。

新建报告包必须使用 `authoringMode: "independent"`。独立模式不得声明 `dataSchemaVersion`、fields、derived、rules、inputSections、dataMigrations、contentTemplate、chartBinding 或 tableBinding；text/chart/table 直接保存自己的内容。智能体只生成脱敏作者初版，用户可以在特化 HTML 中增删页面和组件、直接改文字、图片、图表、表格、标签和布局。

兼容既有 `bound` 旧包时才区分绑定与静态元素。带 `contentTemplate`、`chartBinding` 或 `tableBinding` 的元素由内核持续提供事实；视觉精修只保留其位置、尺寸、层级、样式和标签设置，不保留 `content`、`runs`、`chart` 或 `table`。无绑定的既有静态元素可以保留人工内容，但不得用它复制一份需要随数据更新的事实；特化精修新增覆盖对象只允许 box/divider/image，并剥离全部事实字段。需要新增 text、chart 或 table 时应回到报告包作者基线。

bound 的事实保护必须同时存在于界面操作、覆盖生成和覆盖应用三层：绑定元素的内容只读，且不能删除或复制；即使本地覆盖文件被手工篡改，重放时也必须再次拒绝事实字段、删除标记和事实型副本。外部 page/element patch 必须按运行时字段白名单拣选，禁止把整个对象直接合并；`elementOrder` 必须验证为字符串数组。`document.meta` 也不能进入视觉覆盖。independent 不使用这些只读保护或 VisualOverrideSet，而是保存完整文档。

图表序列和分类使用稳定 ID，标签偏移分别存入 `portrait` 与 `landscape`。内容图和母版图均采用非破坏性直接裁切。工程资产与报告包资产采用同一 PNG/JPEG/WebP MIME、规范 base64 和文件签名标准；可移植工程必须包含全部图片，并限制数量、单图和总解码像素，在完整解码前读取尺寸头。导入图片必须经 Canvas 重编码剥离 EXIF/GPS、重映射资产 ID、按新旧尺寸换算裁切框并原子写入，写入和读取历史存储时都要重校验，特化资产键必须包含报告包命名空间。

### 6. 生成与检查

按以下顺序循环，直到最新渲染没有明显缺陷：

1. 生成报告工程和 PDF。
2. 把 PDF 每页渲染为 PNG，并生成 contact sheet。
3. 检查文字裁切、重叠、来源/页脚碰撞、图表标签、图片焦点、低对比和占位符。
4. 检查普通内容安全边距 12.7 mm、内容块建议间距 7.6 mm、图片不低于 150 DPI。
5. 回到文档模型修正，不从渲染 DOM 反向抽取状态。
6. 重新生成全部页面并复验。

特化报告必须先执行报告包验证和编译测试，再构建只含脱敏模板数据的单 HTML。独立模式的示例数据直接存在各组件；bound 的示例数据来自敏感字段 preview。真实数据只允许由用户在本机浏览器编辑或导入，不得写入报告包、命令日志、智能体上下文或版本库。

independent 运行时按“编译脱敏作者初版、载入报告包专属完整文档存档、渲染”的顺序执行；“恢复智能体模板”清除完整存档。bound 仍按“编译作者基线、按稳定页/元素 ID 重放视觉覆盖、渲染”的顺序执行，数据变化必须重新编译，覆盖孤儿显示 warning。不得在两种模式之间混用存档。

打印前关闭全部图表动画并同步 resize。按目标 96/150/300 DPI 生成图片打印副本，但不替换工程原始资产。

### 7. 交付

默认交付 `.report.zip` 工程与最终 PDF。ZIP 内包含 `document.json` 和 `assets/`；只有用户明确需要单文件归档时才导出 base64 JSON，并提示约 33% 的体积开销。

交付说明必须区分已通过检查、人工确认事项和未执行的压力测试。不得把未运行的 5 张大图、长历史或跨机器字体测试写成已通过。

## 质量门禁

- 文档模型版本、迁移和导出格式一致。
- 运行产物不包含外部 HTTP(S) 资源或 CSS 外链。
- 文字元素不存 HTML，页内编辑不依赖可编辑 DOM。
- 字号、字体、颜色和行高全部来自白名单或 token。
- 图片已校正方向、剥离 EXIF/GPS、去重并记录字节数。
- 工程与报告包图片均只接受 PNG/JPEG/WebP，并使用同一 MIME、规范 base64 与文件签名标准；持久化旧记录在读取前重新校验，特化资产按报告包命名空间隔离，资产流程不使用网络获取。
- 封面、章节与尾页母版图的焦点、叠色和文字可读性已检查。
- 母版图与内容图可直接裁切且不覆盖原图；横竖版图表标签偏移互不串用。
- 封面模板与页眉页脚模板的横竖版分别通过边界测试，并通过 16 页全模板真实打印矩阵；模板应用后图片、蒙版、Logo、文字、规则线和页码仍可直接编辑，页面增删或报告设置变化后机构、章节、密级和页码同步正确。
- 通用单 HTML 与特化单 HTML 都必须包含 `connect-src 'none'` CSP，且发布检查拒绝 `fetch`、XHR、WebSocket、Beacon 和 EventSource 运行时代码。
- 表格与图表有人工来源行，缺失时只告警。
- independent 通过验证器证明不存在集中字段、公式、规则和绑定；浏览器证明图 A、图 B、表格互不改写，完整文档刷新后保留。bound 数据刷新后事实仍来自内核，三层事实保护与孤儿告警继续有效。
- 最终 PDF 已逐页渲染检查，页数、纸张方向、页眉页脚和分页正确。
- 报告包至少一页；内核无固定最大页数，容量结论必须注明浏览器内存、图片体积和打印环境边界。
