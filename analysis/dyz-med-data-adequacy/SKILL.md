# 医学数据充分性把关

## 核心原则

- 把“数据是否完整”“分析是否可行”“论断是否可支持”“能否投稿”分开回答。
- 不把 GRADE 证据确定性等级等同于描述性、关联性或因果性论断。
- 样本量大不能修复错误设计、未测量混杂、时间顺序错误或系统性测量偏倚。
- 异常先作为待核实问题，不自动当作错误，也不擅自给出临床解释。
- 不根据数据量承诺具体期刊、分区、影响因子或录用概率。

## 输入

尽量获取：

- 研究问题、设计类型和计划论断；
- 数据文件、数据字典、编码说明和版本信息；
- 暴露或干预、结局、时间点、比较组和关键混杂因素；
- 主要分析、效应尺度和预设亚组；
- 已有伦理、注册或方案材料；
- 临床负责人和统计确认人。

只有汇总统计时，明确哪些检查无法完成。

## 工作流程

### 1. 建立数据地图

记录：

- 文件、工作表、行列数和更新时间；
- 分析单位、唯一标识符和重复记录规则；
- 变量名称、类型、单位、编码和值域；
- 暴露、结局、时间变量、比较组和候选混杂因素；
- 数据来源、抽取过程和可追溯版本。

敏感数据只在用户授权的本地范围内处理，不输出可识别患者信息。

### 2. 检查结构与质量

至少检查：

- 唯一标识符、重复和跨表连接；
- 缺失比例、缺失模式和异常编码；
- 不可能值、单位混用、日期顺序和随访窗口；
- 组别、结局和关键变量的分布；
- 稀疏单元、零事件、类别不平衡和极端值；
- 随访完整性、删失和竞争风险；
- 测量工具的定义、验证和组间一致性；
- 数据泄漏、重复患者或训练测试集污染风险。

需要更改原始数据时，先保留原文件并生成明确命名的新副本。

### 3. 判断分析是否可行

围绕主要问题判断：

- 主要暴露或干预是否存在且定义清楚；
- 主要结局是否可测量、时间点是否匹配；
- 比较组是否存在并具有重叠；
- 关键混杂因素是否收集；
- 样本量和事件数是否足以支撑计划模型复杂度；
- 缺失和失访是否可能改变结论；
- 数据结构是否支持纵向、聚类、生存、预测或中介分析；
- 预设分析与实际数据是否一致。

研究已完成时，优先报告可估计精度、事件数、模型容量和最小可检测效应，不计算事后观察把握度。

### 4. 确定论断上限

分别判断：

- `descriptive`：能够可靠描述样本和现象；
- `associational`：能够估计关联并合理控制已测量混杂；
- `causal_inference_candidate`：设计、时间顺序、可交换性、正值性和一致性等假设有明确依据，仍需敏感性分析；
- `predictive`：能够开发或验证预测模型，并有适当防过拟合与验证策略；
- `unsupported`：当前数据不能回答主要问题。

随机分配也不自动保证因果结论；执行偏离、失访、测量和分析问题仍需检查。观察性数据即使采用高级方法，也必须披露识别假设和未测量混杂风险。

### 5. 列出高价值补充项

对每个缺失项说明：

- 为什么影响主要问题；
- 补充后能解锁哪项分析或降低哪种不确定性；
- 是否可以合法、现实地补充；
- 获取成本和优先级。

不要把“更多变量”默认当成更好；只保留能改变决策的补充项。

### 6. 形成临床确认问题

将以下内容转成简短问题：

- 临床上不合理或方向反常的分布；
- 100% 或 0% 事件；
- 定义、单位或编码不一致；
- 关键缺失是否可从原始记录补充；
- 暴露、结局或时间窗口是否符合实际流程；
- 数据清理规则是否得到研究团队确认。

事实由临床或数据负责人确认，统计问题由合适人员复核。

### 7. 作出范围决策

使用 `templates/data-adequacy-self-check-checklist.md`，选择：

- `upgrade_pending`：补充或修正数据后重新评估；
- `accepted_ceiling`：用户接受当前分析和论断上限；
- `not_feasible`：当前数据无法回答主要问题，需要换问题或重设计。

下游工作可以在 `accepted_ceiling` 下继续，但不得超出记录的论断上限。未经确认的重大数据矛盾不得静默进入分析或稿件。

## 完成检查

- 数据来源、版本和分析单位已记录；
- 暴露、结局、比较组、时间和关键混杂因素已核对；
- 缺失、异常、重复、稀疏和随访问题已检查；
- 计划模型与样本量或事件数相匹配；
- 数据质量、分析可行性和论断上限已分开；
- 异常已转为可回答的人工确认问题；
- 范围决策及下游限制已明确；
- 没有承诺期刊、分区或录用结果。
