# 开题与研究计划

## 接住当前材料

确定研究问题、报告用途、时间跨度、模板或字数限制。沿用已给出的课题、数据和资源，只询问影响计划可行性的关键空缺。
读取用户指定的初稿、真实前期工作与约束。区分已经完成的工作和拟开展的工作。

## 构建可评审计划

1. 用现有证据说明问题为何重要、已有方法到哪里、差距尚有哪些不确定性。
2. 把总体目标拆成相互有联系的研究问题；每个问题都能对应方法与判定结果。
3. 建立“问题—假设—数据/材料—方法—评价—交付物”矩阵，暴露没有验证路径的目标。
4. 说明样本/数据来源、访问条件、对照、基线及关键分析假设。未取得的数据不能写成已经可用。
5. 依据真实截止日和依赖安排里程碑；先解决阻断后续工作的权限、设备、数据或方法问题。
6. 为主要风险写出触发条件与替代路径。替代路径应回答同一研究问题，或明确缩小范围。
7. 检查目标、方法、时间和产出是否互相匹配，删除没有资源支撑的承诺。

## 交付可使用草稿

按用户模板输出开题稿或计划，附证据矩阵、里程碑表和待核实项。
对无模板的情况采用问题背景、研究目标、方法、已有基础、计划、风险的简洁结构。
预计产出写成目标；已有成果附真实路径或来源；不编造伦理批准、合作承诺或导师确认。

## 工具与后续

- 外部文献或学校要求需要当前核验时查官方来源；无法访问则按提供版本工作并写明日期/范围。
- 没有 Word/LaTeX 排版能力时交付 Markdown 正文和结构，不能声称已经完成格式检查或编译。
- 仅需要选题比较时使用 [选题技能](../phd-ideation/SKILL.md)；具体实验设计使用 [实验技能](../phd-experiment/SKILL.md)。
- 用户只要求写计划时交付文件；只有要求同步工作台才创建待办，不能把所有里程碑标为完成。

## 工作台同步（仅在用户要求时）

先读 [本地操作约定](../phd-manager/references/local-workflow.md)，定位真实仓库与项目，沿用当前 PHD_DATA_DIR。
讨论、翻译、生成草稿或建议本身不自动修改科研状态；文件按用户要求交付，无指定位置时放在 outputs/。
要求保存时通过 CLI 读取目标和 version，保留旧备注、关联与用户给出的百分比；不直接编辑数据库。
用户事实用 user，外部材料用 import，AI 计划/评价用 ai；保留来源与实际核验范围。
多条变更使用批量预检后执行，成功回读才能报告已保存；不添加契约之外的字段。
