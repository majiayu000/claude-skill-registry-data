# 提出先選定・投稿ガイドスキル (Submission Venue Advisor)

## 目的
完成した論文を公開・提出する際、研究分野・執筆言語・公開目的（先行性確保・査読フィードバック獲得・アウトリーチ）に基づき、最適なプレプリントサーバーやオープンアクセスリポジトリを提案する。提出前の品質チェックに加え、一般的な論文公開フォームへコピーできるメタデータを **フィールド単位** で草案する。

項目インベントリの参照は [Zenodo Describe records](https://help.zenodo.org/docs/deposit/describe-records/)（CERN 運営の汎用リポジトリ。全分野・多言語・DOI 自動付与）とする。提案文は特定ベンダーの UI 用語に依存させず、他リポジトリ（OSF、機関リポジトリ等）へ写せる一般名で書く。UI のラベルが違う場合は一般名で提案し、対応するラベルを括弧で示す。

エージェントは公開ボタンを押さない。草案を書き、著者確認を待つ。

## 発動タイミング
- 論文の初稿が完成し、公開先を検討する時
- プレプリント公開（先行性の確保・査読前フィードバック）を検討する時
- 学位論文・ワーキングペーパーのリポジトリ登録時
- 公開フォーム（Zenodo 等）への入力値をフィールド単位で埋めたい時

## 主要な提出先の分類マトリクス

### 汎用（全分野対応）

| サーバー | 特徴 | 言語 | 費用 |
|---|---|---|---|
| **Zenodo** | CERN 運営。全分野・全ファイル形式対応。DOI 自動付与。GitHub 連携可 | 多言語可 | 無料 |
| **OSF (Open Science Framework)** | プロジェクト管理機能付き。データ・コードとの一体化に強い | 多言語可 | 無料 |
| **Research Square** | 学際的。査読付きプレプリント機能あり | 主に英語 | 無料 |

| 分野 | 推奨サーバー | 備考 |
|---|---|---|
| 経済学・社会科学・法学 | **SSRN** (Elsevier) | ワーキングペーパー文化が強い。政策研究との相性が良い |
| 物理学・数学・CS・統計・計量経済 | **arXiv** | 最も歴史が長く影響力大。econ カテゴリもあり |
| 生命科学 | **bioRxiv** | 生物学系の標準 |
| 医学・健康科学 | **medRxiv** | 臨床系。免責表示が必須 |
| 心理学 | **PsyArXiv** | OSF 系。日本の心理学でも利用増 |
| 社会科学全般 | **SocArXiv** | OSF 系。社会学・政治学 |
| 化学 | **ChemRxiv** | ACS 系 |
| 地球・環境科学 | **EarthArXiv** | 地球科学系 |
| 人文学 | **Humanities Commons (CORE)** | MLA 系。書評・短文も可 |

| 機関リポジトリ | 所属大学のリポジトリ（JAIRO Cloud 等） |

## 選定の判断基準

以下の順序で候補を絞り込む：

1. **分野の慣習**: 自分の分野で「読まれている」サーバーはどこか（査読者・同僚が見る場所）
2. **言語の適合**: 英語以外の論文は Zenodo / OSF / Humanities Commons が無難。SSRN・medRxiv 等は英語が前提
3. **DOI 付与**: 上記主要サーバーはすべて DOI を付与（引用可能性の担保）
4. **ライセンス選択**: CC-BY 4.0 が標準的推奨。翻案を許可したくない場合は CC-BY-ND 等
5. **将来のジャーナル投稿との両立**: 投稿予定ジャーナルのプレプリント方針を **SHERPA/RoMEO** で確認（多くの主要出版社はプレプリント公開を許容）

## 投稿前チェックリスト（品質ゲート）

投稿実行前に、以下をすべて完了させる：

- [ ] [`claim-evidence-gate`](../claim-evidence-gate/SKILL.md) の品質ゲートを PASS している
- [ ] [`citation-traceability-audit`](../citation-traceability-audit/SKILL.md) で引用の1対1対応が確認済み
- [ ] 参考文献リスト（References）が本文引用と完全に一致している
- [ ] `scripts/convert_markdown_to_pdf.py` で最終 PDF を生成し、レイアウト崩れがないか目視確認した
- [ ] アブストラクト・キーワード・著者情報（ORCID 推奨）が最新である
- [ ] ライセンス（CC-BY 等）を明記した
- [ ] 利益相反・研究倫理声明（必要な分野では IRB 承認番号）を記載した

## 複数サーバーへの展開（例: Zenodo + SSRN）

同一論文を複数のサーバーに登録することは一般に可能だが、以下に注意する：

- **バージョン管理**: 各サーバーで同一バージョン（改訂日・版数）を維持し、改訂時はすべて更新する
- **相互リンク**: 各登録ページの関連識別子欄に他方の DOI/URL を記載し、同一成果であることを明示する
- **二重投稿との区別**: プレプリントの複数登録は問題ないが、査読付きジャーナルへの同時二重投稿は倫理規定違反となる

## 公開メタデータ草案（フィールド単位）

提出先が決まったら（または著者が「フォーム入力を草案して」と指示したら）、次の順で **1 フィールドずつ** 提案する。要約段落だけを出して終わらない。

### 手順

1. 提出先を確定する（未確定なら本スキル前半で候補を出し、著者確認を待つ）。
2. SoT を読む。本文から推測で埋めない。
   - `docs/design/paper-outline.md` または `docs/<paper-id>/design/sot/paper-outline.md`（題・副題・要旨・キーワード・著者・版）
   - `docs/design/research-plan.md` または同等（読者・提出形態・やらないこと）
   - `docs/literature/literature-matrix.md`（既刊 DOI・関連成果）
   - `docs/manuscript/` の最終 PDF / HTML
   - 既存の `submission-plan.md`・著者設定（ORCID 等）があればそれ
3. 下表の各行について、提案値・根拠パス・状態を埋める。
4. `docs/design/deposit-metadata.md`（複数論文リポジトリでは `docs/<paper-id>/design/deposit-metadata.md`）に書き出す。
5. 状態が `要確認` の行だけを著者に尋ねる。`空欄` は空のまま残す。
6. 著者が承認するまで公開フォームへ転記しない。

### 状態ラベル

| ラベル | 意味 |
|---|---|
| `確定` | SoT から文言どおり転記した |
| `提案` | SoT を基に草案した（要旨の整形、キーワード順など） |
| `要確認` | 著者判断が必要（ORCID、コミュニティ、資金、公開日の解釈） |
| `空欄` | 適用なし。捏造しない |

### 禁止

- ORCID・所属機関・資金提供・コミュニティ名を推測で埋めない。SoT に無ければ `要確認` または `空欄`。
- 未発行の DOI を書かない。予約 DOI は著者がフォームで予約した値だけを使う。
- 既刊論文の DOI を、関係種別なしで「関連」とだけ書かない。関係（引用する / 版である / 補遺である 等）を付ける。
- 公開・Publish 操作を代行しない。

### フィールドインベントリ

参照は Zenodo の Describe records と Create new upload（[describe-records](https://help.zenodo.org/docs/deposit/describe-records/)、[create-new-upload](https://help.zenodo.org/docs/deposit/create-new-upload/)）。一般名で提案し、典型ラベルを括弧に書く。必須度は「引用に最低限必要な項目」と「発見可能性のための推奨」に分ける。

| # | 一般名（典型ラベル） | 必須度 | 提案の作り方 |
|---|---|---|---|
| 1 | ファイル（Files） | 必須 | 最終 PDF を第一ファイルにする。HTML / Markdown を添えるかは著者確認。公開後はファイル差し替え不可のリポジトリが多い |
| 2 | DOI（Digital Object Identifier） | 推奨 | 既存 DOI が無い初回公開は「リポジトリに発行させる / 先に予約する」。予約値を PDF に入れるかは著者確認 |
| 3 | 資源種別（Resource type） | 必須 | 査読前の独立公開は Publication → Preprint（または Working paper）。学位論文・データ・ソフトウェアは別レコードを検討 |
| 4 | 標題（Title） | 必須 | 本文言語の主標題。副題を同じ欄に連結するかはリポジトリ次第。分離できる UI なら主標題のみ |
| 5 | 追加標題（Additional titles: subtitle / translated title / alternative title） | 推奨 | 副題は subtitle。対訳標題は translated title（言語タグ付き）。SoT に対訳が無ければ `空欄` |
| 6 | 公開日（Publication date） | 必須 | 初めて公衆に出した日。今日が初公開なら当日。既に他サーバーで出していればその日。未来日やドラフト作成日で代用しない |
| 7 | 作成者（Creators） | 必須 | 引用に出る著者。姓名は姓と名を分ける。所属は SoT どおり（「なし」は空でよい）。ORCID は提供時のみ。役割は空欄（任意。作成者＝引用著者なので Author という選択肢はない。Editor 等は寄与者側） |
| 8 | 記述 / 要旨（Description: abstract） | 推奨 | outline または原稿の要旨をそのまま。HTML 可の UI でも太字・リンクの装飾は足さない。対訳要旨は追加記述にする |
| 9 | 追加記述（Additional descriptions: notes / methods / technical info） | 任意 | 版注・既刊との関係・データ欠落の注記など、要旨に入れない補足。無ければ `空欄` |
| 10 | ライセンス（Licenses and rights） | 必須 | SoT のライセンス。未指定なら CC BY 4.0 を提案し `要確認`。メタデータ自体のライセンス（Zenodo は CC0）と混同しない |
| 10b | 著作権表示（Copyright） | 推奨 | 現行 Zenodo（InvenioRDM）ではライセンスと別の自由記述欄。形式は `© {公開年} {作成者の表示名}`。権利者は作成者と一致させる。空欄可。寄与者の RightsHolder は通常不要 |
| 11 | 寄与者（Contributors） | 任意 | 引用著者にしない編集者・資金管理者など。該当者だけ。作成者と重複させない |
| 12 | キーワード / 件名（Keywords and subjects） | 推奨 | outline のキーワードを優先。統制語彙（EuroSciVoc, MeSH, GEMET 等）に合う語だけ追加し、無理に当てない |
| 13 | 言語（Language） | 推奨 | 本文の言語（ISO 639）。日英併記でも本文言語を 1 つ選ぶ。対訳は追加標題・追加記述側 |
| 14 | 版（Version） | 推奨 | outline / 原稿の版（例: `v0.1.0`）。無ければ公開日の日付版を `提案` し確認する |
| 15 | 出版者（Publisher） | 任意 | リポジトリ既定（Zenodo なら Zenodo）でよい。既刊誌の出版社を入れない（プレプリントの出版者はリポジトリ） |
| 16 | 資金情報（Funding） | 任意 | 助成番号が SoT にあるときだけ。無ければ `空欄` |
| 17 | 関連識別子 / 関連成果（Related identifiers / Related works） | 推奨 | 既刊・データ・コード・他サーバー登録。関係種別を必須にする（`cites`, `isNewVersionOf`, `isSupplementTo`, `isIdenticalTo` 等）。DOI が無い URL は最終手段 |
| 18 | コミュニティ / コレクション（Communities） | 任意 | 著者が参加済み、または参加する意思を示したコレクションだけ。推測でコミュニティを作らない・選ばない |
| 19 | 公開範囲（Visibility / Access right） | 必須 | 論文プレプリントの既定はオープン。エンバーゴは投稿先方針があるときだけ `要確認` |
| 20 | 参考文献欄（References） | 任意 | リポジトリに独立欄がある場合のみ。本文 References の複製は必須ではない。関連識別子で足りることが多い |

### 関連識別子の関係種別（よく使うもの）

| 関係 | 使うとき |
|---|---|
| `cites` | この論文が参照する既刊・データセット |
| `isNewVersionOf` / `isPreviousVersionOf` | 同一成果の改訂 |
| `isIdenticalTo` | 他サーバーに置いた同一版 |
| `isSupplementTo` / `isSupplementedBy` | 本文とデータ・付録の対 |
| `isPartOf` / `hasPart` | シリーズやコレクションの一部 |

著者の既刊シリーズがある場合、マトリクスまたは outline に DOI がある行だけを列挙する。DOI 未確認の「関連しそうな論文」は載せない。

### 成果物テンプレート

`deposit-metadata.md` は次の形にする。チャットには同じ表を出し、コピー用の値をフィールドごとにコードブロックで添える。

```markdown
# 公開メタデータ草案

- 提出先:
- 草案日:
- 状態: draft | author-approved
- 参照 SoT:

| # | フィールド | 状態 | 提案値 | 根拠 |
|---|---|---|---|---|
| 4 | 標題 | 確定 | … | `docs/.../paper-outline.md` |

## コピー用

### 標題
…
```

チャットでは先に表、次に `要確認` の質問。ファイル全文の再掲で終わらない。
