# 読了前ブリーフィングスキル (Pre-Reading Briefing)

## 目的
論文草稿を「書く」ことと「読み・検証する」ことは別の認知的負荷を伴う。執筆が高速化されても、著者自身や査読者が完成草稿を通読し、専門用語・前提・論理展開を理解するには別途の労力が必要である。本スキルは、校閲期（読了・検証フェーズ）に入る**前**に、章・節単位の「読み方ガイド」を生成し、読解スキャフォールディングを提供する。

認知スキャフォールディングの観点では、本スキルは主に **M1（ミラーリング）の読解側拡張** と **M4（ZPD プロンプティング）** に対応する：読者の現在地を反映し、次に読むべき節の前提を段階的に提示する。

## 発動タイミング
- 章または節の草稿が完成し、**著者自身が通読・検証に入る前**
- 査読者・共同研究者へ草稿を送る前の**読者向けガイド**として
- 長期間執筆が中断し、自分の草稿が「他人の文章」のようになったとき
- claim-evidence-gate 等の事後監査の前に、**人間による確認範囲**を絞りたいとき

## 前提
- 対象となる草稿ファイル（章・節）が存在すること
- 可能であれば、ドメイン概念定義（用語集）が `design/` 配下に存在すること（概念グラウンディングに利用）

## 処理手順

### Step 1: 対象範囲の確定
1. ブリーフィング対象（章・節・パラグラフ群）をユーザーと合意する。
2. 読者モデルを確認する（下記 Step 2）。

### Step 2: 読者モデルの選択
説明の深度・前提知識の扱いは、読者役割によって変える。

| 読者モデル | 想定 | 説明方針 |
| :--- | :--- | :--- |
| **著者自身（再読）** | 執筆から時間が経ち、細部を忘却 | 「なぜこの構成にしたか」「当時の意図」を再提示 |
| **初見の査読者** | 分野の専門家だが本稿の前提は未知 | 用語定義と論理構成を先に明示 |
| **初学者・実務家** | 背景知識が限られる | 前提概念を平易に説明し、専門節は「読み飛ばし可」とマーク |

読者モデルが不明な場合は、必ずユーザーに1問確認する（推測で生成しない）。

### Step 3: 節ごとのブリーフィング生成
各節について、以下の要素を**通読前に**提示する。

| 要素 | 内容 |
| :--- | :--- |
| **この節の目的** | 1文で。研究問い（RQ）との対応を示す |
| **前提となる概念・定義** | 本文中で使う専門用語3つ以内。ドメイン概念定義があれば参照を示す |
| **主要な主張（クレーム）** | この節で最も言いたいことを1〜2文で |
| **想定される反論・注意点** | 読者が疑いそうな点を1つ。カウンター議論の有無も示す |
| **読了後の確認質問** | 種類タグ付き。形式は下記「確認質問の種類」 |

分量は節あたり **5〜10行** を目安とし、詳細な要約は行わない（本文の再録ではなく、あくまで「読み方の足場」）。目的・主張欄に既にある内容を確認質問にしない。

### 確認質問の種類と役割分担（v1.1.0）

タグはエージェントが生成時に付ける。**曖昧なら TERM に倒す。** 著者の再タグは常時可だが、追加の決定として課さない。タグ運用は読者モデルが **著者自身（再読）** のときに限る。

| タグ | 何を問うか | 誰が埋めるか |
| :--- | :--- | :--- |
| **TERM** | 用語・概念の意味 | 著者。1問ずつ Capture→Mirror→Confirm |
| **VALID** | 本文記述と外部正本（版・プロトコル）の一致 | エージェントが草案。著者は採否 |
| **MAP** | 内部成果物同士の対応（表↔節、定義↔観察） | 同上 |
| **GAP** | MAP の亜種。ギャップと章・観察の対応 | 同上 |

「なぜこの文献を引いたか」等の意図質問は第4型にしない。答えが設計文書にあれば MAP、なければ TERM。

**VALID / MAP 草案の規則（P0）**

- 生成は一括してよい。**採否は2–3行／ターン。全件採用は禁止。**
- 各セルに突合根拠（表の行・節番号・引用片）を必須付記する。根拠の無い草案は出さない。
- MAP の値は **一致 / ずれ / 未対応**（表に無い・節に無い）。

**TERM の上限**: 1セッション3問。優先は著者申告の不明概念。残りは `session-research-handoff` へ退避する。全問わからない、を失敗にしない。TERM の不明は説明へ、MAP の不明は草案へ回す。

### Step 4: ブリーフィングの配置・提示
- 章冒頭に「**読了前ブリーフィング**」節として挿入するか、別ファイル（例：`docs/<paper-id>/design/reading-brief-chapterN.md`）として出力するかをユーザーに確認する。
- 本文への挿入は**校閲用の一時成果物**である旨を明記し、最終稿・投稿版からは除く運用を推奨する。

### Step 5: 読了後のフィードバック
通読後、全問回答を求めない。種類に応じて振り分ける。

- **TERM**: 著者申告の不明から最大3問。説明→Confirm。
- **VALID / MAP**: 根拠付き草案を出し、2–3行ずつ採否を取る。
- 結果（回答済／説明済／草案採用／棄却）をブリーフィングの回答欄に残す。
- 採否・不明点を次の改訂の入力とする。網羅監査は `claim-evidence-gate` に任せる（本スキルの VALID は著者向け提示）。

## 生産/理解メトリクスの分離（推奨）
本スキルを運用する際は、執筆時間（生産側）と、ブリーフィング生成＋通読＋確認質問への回答に要した時間（理解側）を**別指標として記録**することを推奨する。これにより「書けたが読めない」非対称性を定量的に観察できる。

## 成果物
- `docs/<paper-id>/design/reading-brief-chapterN.md`（別ファイル運用の場合）
- または章冒頭への一時挿入ブロック（最終稿からは除去）

## 出力例（雛形）

```markdown
## 読了前ブリーフィング：第N章 タイトル
**対象読者**: 著者自身（再読）
**推定通読時間**: 約X分

### §N.1 節タイトル
- **目的**: RQ1 に対し、〜を明らかにする
- **前提概念**: 用語A（=〜の定義）、用語B
- **主要な主張**: 〜である
- **想定反論**: 「〜では？」→ §N.2 で応答
- **確認質問** `[TERM]`: この節の結論を一言で言えますか？
```

## 他スキルとの連携
- **session-research-handoff**: 再開時のウォームアップ質問と併用すると効果的
- **claim-evidence-gate**: 本スキルの VALID は読解支援の著者向け提示。ゲートは網羅的機械監査。二重に同じ表を埋めさせない
- **scholarly-concept-modeling**: 前提概念の定義源として参照
- **academic-paper-translation**: 外国語文献の読解支援として応用可能

## 認知スキャフォールディング
本スキルの全対話において、[認知スキャフォールディング原則](../../../rules/ja/cognitive-scaffolding-rule.md)（S1〜S4）を遵守する。特に S1（ミラーリング）を読解側へ拡張し、「読者が今どこにいて、次に何を前提として必要とするか」を常に反映する。

## 免責
生成されるブリーフィングは読解支援のための二次成果物であり、論文の正しさを保証するものではない。最終的な内容確認は必ず著者が本文に対して行うこと。
