# 专业研究与咨询文稿写作

## 职责

把已有分析写成可直接进入报告或 PPT 页的文字，围绕读者关心的结论提供证据和解释，并在交付前检查准确性、结论强度与阅读负担。

也处理研究尚未开展的计划书：写清客户为什么需要研究、要作哪些决定、如何研究及最终获得什么。专业编辑既改善语言，也展开材料已有的逻辑、检查前后对应；把支持不足的推理列为待核实，不替研究者新增结论。

上游可以是研究结论、数据表、图表说明、笔记或页面草稿；可交付连续正文或逐页脚本，用户可直接使用文稿。

不负责：

- 搜索和补充资料；
- 代替专项 Skill 重新分析；
- 从零设计研究方案；可根据已有材料组织报告框架，调整段落、标题和顺序，计划书沿用已确认的研究设计；
- 制作图表或 PPT 版式；分页时可提出图表类型、数据来源与图文关系需求，具体绘制和排版交给呈现制作；
- 用模糊措辞填补数据缺口。

## 工作模式

根据请求选择最小必要模式；用户明确跳过润色时保留原稿，其他已要求的工作照常执行：

- `润色`：保持原意，改善准确性、结构和表达；
- `写作`：将已有要点组织为段落、页面、小节、章节或摘要；
- `审校`：按请求指出或修复表达含糊、论述缺项、前后矛盾及证据越界，不无关重写全文。
- `分页编排`：把已有材料或成熟正文组织成模块脚本或完整逐页文稿；可直接进入，不强制先润色全文。

用户要求根据已有资料独立新写一份文本报告、且尚无成型报告时，在写作模式读取[文本报告独立撰写](references/文本报告独立撰写.md)。该模块可独立处理简单、小型文本报告，不依赖任何研究 Skill；已有成型报告使用原有润色或审校模式，不进入此模块重新成文。

需要分页 HTML、PPT 脚本或模块／综合报告脚本时，完整读取并执行[分页编排与交付](references/分页编排与交付.md)，再全文读取对应的行业、企业、用户或综合模式参考，以及逐页格式和分页交接要求。完整脚本按模块逐项填写交付结构与页面字段，完成其质检和制作准备判断；已确认计划书直接沿用其结构。连续正文和下拉 HTML 不走分页步骤。

完整商业文稿或实质编辑先读[商业文稿成文与页面叙事](references/商业文稿成文与页面叙事.md)，明确页面用途、完整表达和前后故事；再读[专业编辑方法](references/专业编辑方法.md)，再按类型读取[计划书编辑](references/计划书编辑.md)或[研究报告编辑](references/研究报告编辑.md)。局部改句只读相关部分；[改写示例](references/改写示例.md)用于理解改写尺度，不作为固定句式。

## 执行流程

### 1. 确认任务契约

识别输入材料、目标读者、使用场景、写作单位和篇幅要求。缺少会改变结论的材料时直接说明缺口；其余情况按合理假设继续。

同时识别文稿类型和交付形态：计划书／成果报告，连续正文／分页文案。沿用已知要求。先定位必须保留的问题、结论、数字、引文、限定和交付承诺；保留分析深度，不把“去AI味”理解为缩短全文。接收研究 Skill 的成型报告时，一并读取其既定交付模板，保留必需章节及顺序、固定栏目名称、章节和验收编号（如 FA01）、图表编号，以及 Excel 工作表/单元格、图源和附件的交叉引用；编辑后逐项核对仍能定位。正文和非固定标题照常润色，用户明确要求重组时同步更新受影响的引用。

写作单位包括：

- 段落：形成结论、证据、解释和收束；
- 页面：形成说明对象的主标题、说明故事或核心判断的副标题，以及证据、分析和含义；
- 小节或章节：形成连续论点，不堆砌孤立材料；
- 摘要：只提炼正文已有的重要发现，不新增结论。

### 2. 忠实组织内容

- 保持用户材料的事实、立场和结论强度；
- 区分事实、推断、`【待核实】` 和模型知识；
- 数据写清数字、时间、范围、口径和来源；
- 来源冲突先记入底稿；影响核心结论时，正文只说明实质差异及对判断的影响，停止强推论；
- 不捏造数据、来源、案例或用户未提供的研究发现。
- 核心数字保留来源、定位、时间、地域、单位和必要口径；比例写分母，增长写基期。这些信息可以由正文、表头、图注和引用共同交代，不逐句重复。
- 核心判断的表达强度应与实际证据相称；沿用输入已有的证据等级，不要求额外评级体系。探索性发现可写明对象和依据后进入摘要，未解决的关键矛盾则写清对判断的影响。

段落可采用 PEEL：结论、证据、解释、连接。不要为了套结构强制每段同构。

### 3. 形成报告表达

商业计划书和研究报告的叙事标题与正文使用陈述句，不使用设问、反问或自问自答；固定模板栏目沿用名称；将研究问题写成明确的研究任务和判断内容。原始引文及问卷访谈工具原题保持原样，不作为报告的叙事句式。主体首次出现交代身份和业务，后续使用一致称谓；委托方、委托方的采购客户、最终使用者与研究团队分别指明，避免统称“客户”。

- 成果正文先给有依据的判断。PPT及类PPT内容页同时保留主副标题：主标题说明对象与分析角度，副标题讲清本页故事或核心判断；计划书副标题说明研究思路、拟解决的问题或方案安排，不把尚未执行的研究写成已确认结果。连续正文无需机械套用双标题；
- 数据服务论点，不复述图表标签；
- 用具体时间、范围、对象和条件替代空泛形容词；
- 页面主标题界定对象，副标题提出故事或判断，证据、分析和收尾支持其表达；
- 保持专业、自然和克制，不为“像报告”增加术语和阅读负担。

商业计划书及报告先完成有充分解释的正文，再组织页面和版式；信息卡标题也须清楚成句，正文不套短句卡片。分页文稿先写完整意思再安排版式，并按[商业文稿成文与页面叙事](references/商业文稿成文与页面叙事.md)进行单页脱离上下文阅读和整章顺读；补齐对象、核心问题及业务用途后再交给呈现制作。

成稿后读取[句子与段落编辑](references/句子与段落编辑.md)，处理空转提示、虚设反驳、拗口修饰、重复解释和对象不清。局部润色按相关条目处理；沿用已有体裁与风格要求。这是本Skill内的编辑步骤，无需再调用外部去AI味Skill。

#### 清理过度防御与解释

对每句解释做删除测试：**删掉后，结论、证据含义或读者的经营选择是否改变？**若不改变，直接删除。常见清理对象包括：

- 预先纠正正文没有提出的主张，如“这不自动意味着……”“不能据此证明所有……”。
- 自述研究操作，如“本报告未将两者平均”“具体差异放在底稿”“后续还应取得数据”。
- 重复说明已由对象、表头或“假设”交代的范围，或给清楚的分类再加“不预设只能如此”。
- 不提供新证据、机制或决策含义的段落总结、过渡和图注。

会改变结论的条件与实际风险仍须保留，优先融入判断本身。把“在15%占比假设下计算为6亿美元”写清后，通常无需再跟一句“这不是实测规模”。“获客成本上升会吃掉制作节约”解释了利润机制，应当保留。不要按否定词机械删句，也不要把有条件的判断改成确定事实。

此检查覆盖正文、摘要、标题、表格、图注及图内脚注。内部审核、Skill调用和未采用资料不默认展示给读者；不以字数要求补回这些文字。

### 4. 强制质检

每次交付前检查：

1. 核心判断是否有相称证据；
2. 是否出现无依据的全称命题或绝对断言；
3. 地域、时间、范围和数据口径是否完整；
4. 预测是否写明必要前提和时间，且未包装成已发生事实；
5. 是否把推断写成事实，或擅自强化用户原意；
6. 是否出现口号式结尾、煽动性表达或无数据支撑的形容词；
7. 是否有后半段明显缩水、重复段落或与任务无关的扩写。
8. 是否有只为预防质疑的句子，或已在数字、表头中交代却再次解释的限定。
9. 客户能否读懂具体对象、动作和结果；计划书的需求、方法、交付、周期和费用是否对应，成果报告是否解释发现的原因、差异和意义。
10. 修改后关键事实、数字、来源、有效条件和分析内容是否完整；修辞是否掩盖了尚未解决的实质矛盾。

默认避免：`毫无疑问`、`必然`、`必将`、`绝对领先`、`彻底颠覆`、`已成定局`、`爆炸式`、`井喷式`、`巨大机遇`、`万亿蓝海`、`所有企业都在`、`用户普遍认为`、`未来已来`。

证据不足时降低判断强度；仍无法成立的主张从正文删除，缺口留在底稿或交付说明。若这正是用户必须得到回答的核心问题，应简洁说明当前能判断什么、哪项缺口改变结果，不以反复声明不足代替分析。

### 5. 按请求交付

- 快速润色：给出修改稿；用户需要时再附简短改动说明；
- 写作任务：交付可直接使用的正文，并单列待核实项；
- 审校任务：优先给出修订稿，再列最重要的问题；
- 分页编排：按分页模块交付一份 Markdown 脚本，正文完整保留，制作备注与客户文案分开；说明已编排范围和影响进入呈现的具体缺项，无缺项时不列空清单；
- 保留输入原稿，修改稿另存；通过本任务复核后的润色稿在原命名规则中加“定稿”，交付清单只将该稿列为正式文本报告，后续 HTML／PPT 使用该稿。项目已有原稿保持原名与位置，不另建备份；本轮新生成的润色前稿放入 `过程稿/`，单独任务未设此目录时在文件名中加“润色前”。用户明确要求覆盖或指定文件名时按其要求执行，并在交付说明中标明哪份是定稿；不为每次修改复制一版，不默认交付内部检查清单。

## 生态衔接

- 计划书写作承接已确认的研究计划和研究框架；
- 分页HTML或PPT需要时，在本Skill内按分页模块编排逐页内容；已有合格脚本可直接交给呈现制作；
- 下拉式HTML保留连贯正文，按内容重要程度组织章节和模块，无需先转分页脚本；
- 如已安装 `hehe-report-presentation`，可由它承接图表与页面制作，生成多形态 HTML、PDF 和可编辑 PPT；未安装时直接交付文稿；
- 竞争、趋势、用户等结论分别承接对应研究 Skill 的已确认产出。

可独立处理用户提供的文稿，不要求安装其他Skill。交接沿用读者、用途、必须保留的内容与来源；制作内部备注与客户正文分开，不强制每一步额外生成文件。
