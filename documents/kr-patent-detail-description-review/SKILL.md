# kr-patent-detail-description-review — 상세 설명 ITER 10 정형 검토

## 무엇을 하는가

한국 특허 명세서의 **【발명을 실시하기 위한 구체적인 내용】**(이하 S13 실시예 본문)이 ITER 10 작성 프롬프트의 보일러플레이트 룰 + 자가 점검 11항목(W)을 따르는지 정밀 검토한다.

작성 프롬프트 전문은 `references/iter10_drafting_prompt.md`에 보존. 본 SKILL.md는 그 프롬프트를 **검토 룰셋**으로 변환한 형태.

> **C표 시퀀스(청구항 1 × 7단락) 제외**: 도면 단위 본문 구성 등 합리적 변형이 흔하여 본 스킬의 자동 점검 룰에서 제외. 필요 시 정독으로만 보강.

## 언제 사용하는가

- `kr-patent-spec-drafting`로 S13 본문 작성 직후 자체 점검
- 청구항 본문 1:1 매핑 작업 이후 단락 구조·서식 검증
- 외부 변리사 작성본 받아 S13 정형 준수 여부 확인
- `kr-patent-consistency-check` 통과 후 S13만 더 깊이 점검하고 싶을 때

## 언제 사용하지 않는가

- 명세서 전체(S1~S14) 점검: `kr-patent-consistency-check` 사용
- 청구항 자체 검토: `kr-patent-claim1-drafting` 또는 별도 청구항 점검
- 도면 부호 매핑: `kr-patent-symbol-design` / `kr-patent-drawing-mapping`

## 입력·출력

| 항목 | 내용 |
|---|---|
| **입력 (필수)** | 명세서 .docx (S13 섹션 포함) + 청구항 원문 |
| **입력 (옵션)** | 논문 PDF/텍스트 (Method·Experiment 매핑 검증용) |
| **출력** | W 자가 점검 11항목별 ✅/⚠️/❌ 표 + 위반 단락 위치·원문·수정안 + 정합 점수 (100점 만점) |

## W 자가 점검 12항목 — 핵심 검토 룰

각 항목은 자동 검출 가능한 것과 정독 필요한 것으로 구분.

### 1. S표 도입부 5단락 정형 사용 ★

**검출 방법**: S13 시작부 5단락이 S-1~S-5 정형 텍스트와 일치하는지 비교 (substring match)

| # | 시작 키워드 | 검증 |
|---|---|---|
| S-1 | "이하, 첨부된 도면을 참조하여 본 발명의 바람직한 실시예를 상세히 설명한다" | substring 매칭 |
| S-2 | "제1, 제2 등과 같이 서수를 포함하는 용어는" | substring 매칭 |
| S-3 | "어떤 구성요소가 다른 구성요소에 \"연결되어\" 있다거나" | substring 매칭 |
| S-4 | "단수의 표현은 문맥상 명백하게" | substring 매칭 |
| S-5 | "본 출원에서, \"포함한다\" 또는 \"가지다\"" | substring 매칭 |

**위반 기준**: 5개 중 누락 ≥ 1 → Priority A

### 2. 섹션 2 본 발명 개요 단락 ("본 발명은 ~") 존재

**검출 방법**: S13 도입부 직후에 "본 발명은 [핵심 목적]을 [기술적 수단]을 이용하여 ~ [발명명]에 관한 것이다." 정형 단락이 있는지

**위반 기준**: 본 발명 개요 단락 부재 → Priority A

### 3. 섹션 4 시스템 구성요소 절 "다음으로," 반복 사용

**검출 방법**: S13 안 시스템 구성요소 도입 단락에서 "다음으로," 도입어 카운트. 구성요소가 N개일 때 "다음으로," 등장 ≥ N-1 권장

**위반 기준**: 구성요소 ≥ 3개인데 "다음으로," 1회 이하 → Priority B

### 4. 종속항 모두 1:1 매핑

**검출 방법**: 청구항 2~N의 한정 시그니처가 S13 본문 어딘가에 1회 이상 등장 (`kr-patent-consistency-check` B-0과 동일)

**위반 기준**: 종속항 누락 ≥ 1 → Priority A (지원요건 흠결)

### 5. 도입어 빈도 D표 권장 범위 준수

**검출 방법**: S13 본문 전체에서 15종 도입어 카운트 → 전체 단락 수 대비 비율 계산

| 도입어 | 권장 빈도 (%) |
|---|---|
| 이하, / 이하에서는, | 1~2 |
| 본 발명은 / 본 발명에 따른 / 본 발명에서, | 5~8 |
| 일 실시예에 있어서, / 다른 실시예에 있어서, | 5~10 |
| 예를 들어, / 다른 예를 들어, / 일 예로서, | 15~25 |
| 한편, | 8~12 |
| 또한, | 8~12 |
| 이러한 [선행] | 5~10 |
| 다음으로, | 10~15 |
| 구체적으로, | 5~10 |
| 그 외 (여기에서/나아가/즉/먼저/이 경우/비록) | 합쳐서 15~30 |

**위반 기준**:
- 권장 범위 초과·미달 ≥ 5종 → Priority B
- "예를 들어," < 10% (예시 부족) → Priority B

### 6. 단락 분량 E표 권장 범위 준수

**검출 방법**: 각 단락의 어절(공백 분리 단어) 수 카운트 → 단락 유형별 권장 범위 매칭

| 단락 유형 | 권장 어절 |
|---|---|
| 도입부 정형 | 50~150 |
| 구성요소 소개 | 30~70 |
| 부연 | 30~60 |
| 예시 | 40~170 |
| 변형례 | 50~150 |
| 정리·지시 | 15~40 |
| 조건부 | 25~80 |
| 효과 | 30~80 |
| 마무리 정형 | 40~100 |

**위반 기준**:
- 200 어절 초과 단락 ≥ 5개 → Priority B (문장 4줄 초과 룰과 연동)
- 10 어절 미만 단락 ≥ 5개 → Priority C

### 7. 도면부호 V표 표기 ★

**검출 방법**:
- 시스템 구성요소: `[명사](110)`, `[명사](120)` … 100단위 십의 자리 ID
- 단계 부호: `[단계명](S110)` 등 S접두어 첫 등장
- 동일 구성요소 두 번째 등장부터 도면부호 생략 여부

**위반 기준**:
- 시스템 부호 첫 등장 누락 → Priority B
- 같은 객체에 부호 반복 부여 ≥ 5건 → Priority C

### 8. 종결 어미 K표 — "~할 수 있다" 90%+

**검출 방법**: S13 본문 모든 문장 종결 카운트 → "~할 수 있다" / "~일 수 있다" 비율 계산

| 종결 어미 | 권장 |
|---|---|
| ~할 수 있다 | 가장 빈번 |
| ~일 수 있다 | 객체 정의 |
| ~한다 / ~된다 | 단정·수동 (예외만) |
| ~로 이해되어야 한다 | 용어 정의 (도입부) |

**위반 기준**:
- "~할 수 있다" + "~일 수 있다" 합쳐 < 80% → Priority B
- "~한다" 종결 ≥ 30% → Priority B (단정형 남용)

### 9. U표 마무리 5단락 정형 ★

**검출 방법**: S13 종료부(또는 부호의 설명·청구범위 직전)에 U-1~U-5 정형 단락이 모두 있는지

| # | 시작 키워드 | 내용 |
|---|---|---|
| U-1 | "한편, 본 발명에 따른" + "프로세스에 의해 실행" | 프로그램 정형 |
| U-2 | "또한, 본 발명에서 설명한" + "프로그램(또는 어플리케이션)" | 어플리케이션 정형 |
| U-3 | "여기에서, 컴퓨터가 읽을 수 있는 매체는" + "HDD" | 매체 종류 정의 |
| U-4 | "또한, 컴퓨터가 읽을 수 있는 매체는" + "네트워크" | 무형 매체 |
| U-5 | "이와 같이, 본 발명은 상술한 실시예에 한정되지 않으며" | 외연 확보 |

**위반 기준**: 5개 중 누락 ≥ 1 → Priority A

### 10. 청구항 ↔ 본문 어휘 일관성 O표

**검출 방법**:
- 청구항 표현 "기 설정된 [N]" / "적어도 하나의 [N]" / "제1/제2 [N]" / "상기 [N]" → 본문에서도 동일 표현 유지
- 영문 병기 X(Y)는 본문 첫 등장 시 동일 병기
- 청구항에서 정의된 새 추상 명사는 본문에서 "여기에서, [신 명사]는 ~ 의미할 수 있다." 형태 정의 단락 필요

**위반 기준**:
- 청구항 표현 변형 (예: "적어도 하나의" → "하나 이상의"로 본문에서 임의 치환) → Priority B
- 청구항에 있는 영문 약어가 본문에 풀이 없음 → Priority B

### 11. 단락 결속 P표 — 자연스러움 (정독)

**검출 방법** (자동 일부 + 정독):
- 자동: 같은 객체에 다른 어휘 사용(대명사 남용) 검출
- 자동: 첫 도입어가 직전 단락과의 관계를 명시했는지 ("다음으로,"/"한편,"/"또한,"/"이러한")
- 정독: 단락 종결 → 다음 단락 도입어 연결 자연스러움

**위반 기준**:
- 도입어 없이 시작하는 단락 (절 헤더·최초 도입 외) ≥ 3개 → Priority C
- 같은 객체 다른 어휘 ≥ 5건 → Priority B

## 추가 정독 점검 (자동 검출 어려움)

### M. 효과 단락 패턴

> "따라서, 본 발명은 [효과 1]할 수 있다."
> "이를 통해, [효과 2]을 달성할 수 있다."
> "그 결과, [효과 3]의 효과가 있다."

**검출**: 섹션 6 단계별 또는 섹션 8 정리에 효과 단락이 ≥ 3개 존재하는지

### N. 부정 한정 (외연 확보)

> "다만, 이에 한정되는 것은 아니다." / "다만, 이에 한정되지 않는다." / "본 발명은 상기 예시에 한정되지 않는다."

**검출**: 예시·실시예 단락 종결에 부정 한정 등장 비율 ≥ 20%

### Q. 실시예 vs 예 구분

- "실시예" = 발명의 다른 실현 방식 (구조적 변형)
- "예" = 동일 실시예 내 구체 케이스

**검출**: "일 실시예" 도입 단락이 실제로 구조 변형을 다루는지, "예를 들어,"가 동작 예시인지 정독

### F-2. 도면 종류별 첫 단락 도입

| 도면 종류 | 도입 패턴 |
|---|---|
| 블록도 | "한편, 도 N에는 본 발명에 따른 [시스템명]의 블록도가 도시되어 있다." |
| 흐름도 | "한편, 도 N은 본 발명에 따른 [방법]의 흐름도이다." |
| 표 | "한편, 도 N은 본 발명의 일 실시예를 나타낸 표이다." |
| 그래프 | "한편, 도 N은 본 발명에 따른 [성능 측정] 결과를 나타낸 그래프이다." |

**검출**: 각 도면 도입 단락이 도면 종류에 맞는 정형 사용

## 작업 순서

### Step 1. S13 영역 추출

- 명세서 docx에서 `【발명을 실시하기 위한 구체적인 내용】` 헤더 ~ `【부호의 설명】` 또는 `【청구범위】` 직전까지의 단락 추출
- 단락별 본문 텍스트, 어절 수, 첫 도입어 분석

### Step 2. 자동 검출 (W 1~9)

W-1 (S표), W-2 (본 발명 개요), W-3 (다음으로 반복), W-4 (종속항 매핑), W-5 (도입어 빈도), W-6 (분량), W-7 (도면부호), W-8 (종결 어미), W-9 (U표)는 자동 grep·카운트로 검출.

### Step 3. 정독 점검 (W-10·11 + M·N·Q·F-2)

자동 검출 후 정독으로 어휘 일관성, 단락 결속, 효과 단락, 부정 한정, 도면 종류별 도입 정형 확인.

### Step 4. 점수 산정 + 우선순위 분류

- 100점 만점 (각 항목 가중치)
- Priority A: W-1·W-2·W-4·W-7(시스템 부호)·W-9 위반
- Priority B: W-3·W-5·W-6·W-8·W-10 위반
- Priority C: W-11 위반·부수 사항

### Step 5. 6항목 정형 보고서 출력

각 위반 사항을 다음 형식으로 보고:

```markdown
### [번호]. <항목>

**① 위치**: 단락 N (또는 N~M)
**② 근거 룰**: ITER 10 W-<번호> / <섹션 코드>
**③ 현황 (원문 인용)**:
> "..."
**④ 수정안**:
> "..."
**⑤ 부가 설명**: ...
```
