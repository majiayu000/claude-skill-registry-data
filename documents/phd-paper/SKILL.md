# 论文写作与修订

先读取 [本地操作约定](../phd-manager/references/local-workflow.md)。确定项目、论文、目标语言、稿件路径与用户要求的写作范围；从已有记录和文稿推断可确定项，缺少决定性材料时再提出具体问题。

## 写作依据

列出 `papers`、关联 `experiments` 与 `literature`。读取用户指定文稿及可用证据，形成简短的“主张—来源”对照：哪些结论已有结果支撑、哪些仍是研究假设、哪些引用尚未核验。文献只有标题时不能推断完整论文结论。

## 按任务执行

- **建立大纲**：围绕研究问题、已有工作的不足、方法、验证路径、结果、局限组织章节。区分已有贡献与计划贡献，登记真实章节名及 `todo` 状态。
- **起草段落**：沿用已确认术语和论证结构。没有证据的数据用明确的“待补实验结果”占位；不要用看似真实的数字、DOI、作者、样本量填充。将假设写成假设，避免把相关性写成因果。
- **修订现稿**：保留原意和可追踪事实，处理结构、清晰度与证据衔接；改变科学主张时解释原因。不要因语言润色扩大贡献或缩小局限。
- **处理审稿意见**：逐条区分需要解释、补分析、补实验或修改文本的事项；记录实际修改位置与证据。未完成实验不得在回复信中声称已完成。
- **投稿准备**：根据用户提供或已核验的目标期刊要求整理材料和待办。`submitted`、`accepted` 需要实际状态依据；准备好稿件不等于已投稿。

## 保存与同步

1. 原始稿件按用户要求编辑或生成新版本。无指定格式时使用 Markdown 保存到 `outputs/`；用户已有 Word/LaTeX 文件时沿用格式和现有工具，缺少相关能力则明确说明，避免伪造格式转换。
2. 在 `papers.notes` 保存简明变更说明、稿件路径与尚缺证据；适当更新 `status` 和实际完成的 `sections`，保留已有章节与关联数组。
3. 百分比只保存用户给出的人工估计，不能按生成字数自动增加。未运行的验证保留为待办。
4. 通过 CLI 写入并回读。交付稿件、关键修改与证据缺口；如果只是语言编辑而研究状态没有变化，不必强行改动阶段。

需要文献核验时读取 [phd-literature](../phd-literature/SKILL.md)，需要独立的论证审查时读取 [phd-review](../phd-review/SKILL.md)。
