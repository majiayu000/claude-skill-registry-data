# Reframe

Change the question while preserving what the user actually cares about.

1. Write the current frame in one sentence: the goal, the assumed constraint, and what counts as success. Separate user-stated constraints from assumptions you inferred.
2. Offer two or three alternative frames that change different levers, such as scope, audience, time horizon, success measure, or ownership. For each, name the assumption it relaxes and the requirement it keeps.
3. Show what each frame makes possible and what it may lose. Flag a frame that conflicts with an explicit user requirement instead of presenting it as viable.
4. State the question or observation that would decide which frame is useful. If the user asks you to choose, recommend a frame against their stated criteria.

Finish when the user can see the original question, the changed assumptions, and the practical consequence of each alternative. Do not quietly turn a reframe into a decision or an edit.

Record this output in `docs/plans/` per the [doc system](../references/doc-system.md), delegating the write to a subagent.
