# 保研套磁信制作与投递

将“了解导师—匹配经历—写信—制作附件—确认—发送—记录”作为一个受控流程。写信与真实发送是两种不同权限，不要因为用户要求写信就自动发送。

## 先判断任务模式

### 模式 A：只写草稿

输出邮件主题、正文、匹配理由和建议附件。不得发送邮件。

### 模式 B：草稿加 Word

在模式 A 基础上，生成正文-only `.docx` 并完成结构检查。不得发送邮件。

### 模式 C：准备投递

完成导师去重、官方邮箱核对、邮件和附件检查，然后把完全相同的正式邮件先发送到用户的私人确认地址。发送后停止，等待用户明确确认。

### 模式 D：正式投递

仅在当前版本的确认副本已经发送且用户明确批准后，才发送到导师官方邮箱。发送后核对邮件并更新台账。

## 最少输入

尽量从用户提供的文件和官方网页中提取：

- 申请人简历或事实清单。
- 导师姓名、学校、学院和官方主页。
- 导师官方邮箱；不得猜测。
- 申请项目和申请类型。
- 希望附上的文件。
- 私人确认邮箱，仅在需要投递时使用。
- 套磁台账，仅在需要筛选或发送时使用。

缺少导师官方邮箱时仍可写草稿，但不能进入投递流程。

## 第一步：检查导师是否重复

需要筛选或发送时读取最新套磁台账：

1. 按导师姓名、官方邮箱、学校、学院、邮件主题和发送状态去重。
2. `已发送、等待回复、已回复` 的导师不得再次作为首封对象，除非用户明确要求跟进。
3. 同一邮箱视为同一导师，即使姓名写法不同。
4. 只有方向没有具体导师时，不进入发送流程。

## 第二步：建立匹配关系

只使用可验证信息：

- 导师研究方向来自学校或实验室官方页面。
- 申请人经历来自简历、项目材料或用户确认。
- 找到 1—2 个真实连接点：研究问题、数据、方法、评估方式、系统实现或未来方向。

不要写“我对人工智能非常感兴趣”这类无法体现匹配度的通用句。

## 第三步：写邮件

推荐结构：

1. `尊敬的陈老师您好：`
2. 第一段：身份、申请场景和导师匹配点。
3. 第二段：与导师方向最相关的具体经历。
4. 第三段：希望进一步学习的内容，并询问是否接收推免或夏令营学生。
5. 简短致谢、姓名和联系方式。

保持克制、具体、礼貌。不得虚构排名、论文录用、导师评价、研究成果或邮箱。

## 第四步：制作 Word

Word 只包含套磁信正文：

- 中文字体：宋体。
- 英文和数字：Times New Roman。
- 字号：11 pt。
- 段前、段后：6 pt。
- 行距：1.5 倍。
- 无标题页、主题、附件说明、表格、页眉、页脚和页码。
- 从问候语开始，以联系方式结束。

使用：

```powershell
python "$env:USERPROFILE\.codex\skills\baoyan-taocixin-outreach\scripts\create_taocixin_docx.py" `
  --body "C:\path\letter-body.txt" `
  --out "C:\path\陈老师_套磁信_申请人.docx"
```

生成后检查 Word 中是否残留占位符、辅助说明或测试文字。

## 第五步：检查附件

首封邮件通常只需要：

- 当前简历 PDF。
- 个人作品集或简短项目材料。
- 导师定制套磁信 Word。

不要默认附上全部证书和大体积资料包。每个附件必须存在、版本正确，并与正文描述一致。

## 第六步：确认副本

需要真实发送时：

1. 从当前私有指令、私有配置或用户输入中取得确认邮箱，不在公开 Skill 中硬编码。
2. 将正式主题、正式正文和正式附件发送到确认邮箱。
3. 除收件人外，不得加入“测试、模拟、仿真”等文字。
4. 发送后读回并核对收件人、主题、正文和附件。
5. 报告发送结果，然后停止。

只接受明确确认，例如“确认无误，可以发给老师”。如果正文或附件有任何修改，必须重新发送确认副本。

## 第七步：正式发送与回写

确认后：

1. 使用同一主题、正文和附件发送到导师官方邮箱。
2. 读回已发送邮件，核对收件人和附件。
3. 报告消息 ID。
4. 将状态、导师邮箱、主题、附件、日期和消息 ID 写回台账。

## 停止条件

遇到以下情况不得正式发送：

- 导师邮箱不是官方来源。
- 导师已联系过且用户未要求跟进。
- 正文存在占位符或未经确认的事实。
- 附件缺失或版本不明。
- 没有当前版本的确认副本。
- 用户尚未明确批准。

## 默认交付

只写草稿时提供：

- 邮件主题。
- 邮件正文。
- 匹配理由。
- 推荐附件和待确认事项。

完成投递时再提供：

- 确认副本和正式邮件的核对结果。
- 正式发送消息 ID。
- 台账更新结果。
