# Goal
- Given the current Git branch, find a title and a short description to push the
  changes as a Pull Request

# Workflow

## Read Rules

- Read rules about:
  - **Coding**: `.claude/skills/coding.rules.md`
  - **Unit tests**: `.claude/skills/testing.rules.md`

## Read the Changes in the Current Git Client

- Get the changed files:
  ```bash
  git diff --name-status origin/master HEAD
  ...
  ```

- Analyze the diff against `master` (or `origin/master`):
  ```bash
  git diff master...HEAD --name-only
  # or if master is not available locally:
  git diff origin/master...HEAD --name-only
  ```

## Propose the Description of the PR
- Propose a one-line title for the PR
  - It must be Linux friendly: no `&` or non-alphanumeric chars
- Save it into `pr_title.txt`

## Propose the Description of the PR
- Write `pr_commit_msg.txt` with a short list of changes in the format
  ```
  ## <Description of the change>
  - Change1
  - Change2
  ```
  where each `<ChangeN>` is a one or two line bullet describing what changed
  related to `<Description of the change>`
- Use plaintext only, no markdown formatting
- Use nested bullets, not numbered bullets
- Wrap lines under 85 chars

## Write the Description of the PR

- Write `pr_description.md` following the template
  `.claude/templates/github_PR_description.template.md`
- Say in `pr_description.md` how it was generated, with this comment at the top:
  ```markdown
  <!-- Generated by `.claude/skills/github.find_name_for_pr/SKILL.md` -->
  ```
- Fill every section from the diff and from the plan or spec the PR closes
  - Write "N/A: <reason>" for a section that does not apply
  - Do not invent test counts or results: run the tests or ask the user
- Follow `.claude/skills/markdown.rules.md` and `.claude/skills/text.rules.md`
