# 医学稿件导出与排版

## 核心原则

1. 原始章节、数据、图片和参考文献只读；在新输出目录生成版本化文件。
2. 先核实目标期刊当前格式要求，再决定排版方案。
3. 导出只处理组装与格式，不静默修正科学事实、数字冲突或缺失引用。
4. 使用当前环境实际可用的文档工具；运行前探测能力，不引用不存在的脚本或模板。
5. 可按用户要求导出“带未解决问题的审阅版”，但必须显著标记，不能称为投稿终版。

## 所需输入

- 稿件各节或完整主稿；
- 目标期刊当前作者须知和文件模板（如有）；
- 参考文献库及引用样式；
- 表格、图片、图注、补充材料；
- 标题页与匿名审稿要求；
- 版本号、输出格式和文件命名偏好。

## 工作流

### 1. 建立导出清单

记录每个输入的稳定 artifact ID、path、version、sha256、用途和是否纳入，确认项目根目录与实际路径，
不按文件名猜身份。确认摘要、正文、参考文献、表图、补充材料、标题页和声明应当是同一文件还是分开提交。
按 R2 schema 1.1 读取相关检查的 inputs（artifact_id/version/sha256）、scope、execution_status、
applicability、domain_result、report:{path,sha256}、checked_at 与逐条验证输出 freshness。无 passport
也可使用同形独立记录，不强制安装或调用兄弟技能。

### 2. 做预检

至少核对：

- 方法、结果、摘要和表格中的 N、事件数、效应量、置信区间、P 值；
- 主要结局、组名、单位和时间点；
- 所有正文引用均有参考文献记录，所有引用标识可解析；
- 每个图表均存在、编号连续、正文有对应引用；
- 摘要和全文篇幅；
- 占位符、重复章节和重复参考文献块；
- 匿名稿中不应出现的身份信息。

发现科学或事实冲突时生成差异报告。当前 REJECT、critical/major 未验证关闭、检查 stale/unverified、
未执行、缺失或范围有限时，不能无保留标为投稿终版；已明确请求带问题审阅版的，直接按该授权继续，不重复强制
全流程审查；否则请用户确认审阅版用途。文件名、首页及 manifest 显著标注“内部审阅版／非投稿终版”及未结限制。

分开记录格式/材料完整性、科学检查结论与 freshness、外部处理授权；导出成功或材料齐全不能覆盖科学限制。
current 仅指声明的绑定可核对，校验器退出码 0 可能对应 REJECT，不是科学 PASS。只消费相关记录，不把全局
退出码当导出门禁，也不自动执行所有检查技能。问题 verified_closed 还须核对 verification_check_id 对应
current、completed、applicable 的检查及实际支持关闭的结论和 evidence:{path,sha256}，仅已回应不算关闭。
研究参与同意不代替发表同意；含可识别患者叙述/影像等时由有资质人员复核发表同意适用性与来源，未知时标待复核，
不推定伦理批准或去标识化就是发表豁免；审阅版标签不构成外传许可。

### 3. 选择可用导出路径

优先采用已核实的本地处理能力，再考虑获准的外部转换服务；已连接工具不等于本地工具，也不等于已有外传授权。
任何外部服务调用前记录：内容类别（未发表稿件、公开题录、作者身份、患者相关内容等）、处理用途、具体服务/
接收方与目的地、允许发送的文件/字段/范围和当前人类授权。只授权导出不能解释为授权上传转换。
任一项未知时外部内容发送数必须为 0，使用已确认本地工具，或降级合并 Markdown/本地操作说明。
按 R2 human_approvals 核对 state、targets 的 artifact_id/version/sha256、role、confirmed_at 及 source
（human、actor_id、statement、reference、locator），再结合当前请求人工核实权限和动作；
recorded_not_authenticated 不证明身份、合法性或有效同意。内容/用途/目的地/范围变更须重新确认。
回执记录预检时间、授权来源和范围、实际发送字段/工件绑定、目的地、发送时间、执行状态、返回文件/证据与限制；
未发送就记录未发送及降级原因，不虚构服务回执，不记录敏感正文或凭据。患者材料还需适用性与隐私专业复核，
不能仅凭操作者的一句同意外发。

按需探测本地 Pandoc、Word 或受支持工具，使用期刊提供的参考模板时保留样式。缺依赖时如实降级，
不自动安装软件、下载模板或创建外部仓库。

### 4. 组装副本

在工作副本中按目标结构合并章节，统一标题层级、图表引用和引用样式。删除重复参考文献块只作用于导出副本，
不改源文件。参考文献元数据无法核实时保留问题标记，不让模型补写。

### 5. 应用格式

按目标期刊要求设置页面、字体、行距、行号、标题页、匿名信息、表格、图注、参考文献和补充材料。三线表、
双倍行距、图像分辨率等仅在期刊确有要求时应用。

### 6. 验证成品

- 文件可正常打开；
- 章节、表格、图片和参考文献均完整；
- 中文字体、特殊符号、公式和统计符号显示正确；
- 页眉页脚、分页、行号和匿名信息符合要求；
- 没有断链、占位符或意外空页；
- 输出文件哈希、大小和版本已记录。

条件允许时在已获准路径渲染或打开成品做视觉检查；无法视觉核对时明确说明。
新增导出检查记录，分列执行状态 `not_run / blocked / failed / completed`、适用性
`applicable / not_applicable / unknown` 和格式领域结论；后两种适用性需理由，未完成时 domain_result=null，
blocked/failed 需 reason。以唯一 check ID 绑定完整实际输入、范围、日期和已落盘报告哈希，不能报告自哈希。
导出副本另登记工件 ID/版本/哈希，不把源稿 PASS 直接赋给导出件。纯排版字节改变也默认使原绑定 stale；
沿用科学判断须新建当前输入绑定记录，附内容等价性和新旧页码/定位重核依据，保留旧记录与其过期状态。

## 稳定本地路径

对于支持的 Markdown、PNG 和已核实引文输入，可按[本地 Word 接口](references/local-docx-cli.md)使用 export_docx.py。
它只生成标记清楚的审阅版 DOCX 和清单，不声称符合具体期刊、科学审核通过或支持原生修订。生成后继续执行成品视觉检查。

## 输出

默认在 `paper/submissions/` 或用户指定目录生成：

- 版本化主稿（如 `.docx`）；
- 可选 PDF 预览或其他目标格式；
- `export-check-report.md`；
- `export-discrepancies.md`（如有）；
- `deliverable-manifest.yaml`。

## 验收标准

- 源文件未被修改；
- 成品可打开，结构和资源完整；
- 动态期刊要求有来源与日期；
- 所有已知差异和降级均可见；
- 导出状态未被误报为投稿完成或科学审查通过。
