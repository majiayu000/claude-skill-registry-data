# MathRSI 原题澄清与定稿

把用户真正要求解决的问题写到另一位研究者能据此独立工作。先建立足以检索的初步问题，再消费文献调查，定稿精确原题；恢复任务时保留原规格、已有证据与尚未解决的连接。这个技能可以单独完成起步或定稿阶段，也可作为 `mathrsi-research` 的内部子流程。

本技能不选求解路线，不运行路线评审循环。后续路线设计和迭代由主流程交给独立的 `mathrsi-route-loop`。证明、构造、计算与形式化要求来自原任务，不能由规格文档自行扩大。

## 输入、两个模式和写入责任

输入首先是本轮用户原话及其指向的题面、PDF、定义或已有项目。原题所在工作区才是输出位置；MathRSI仓库是技能源码，不能把每道题的规格写回base或插件。开始前读工作区约定及已有恢复入口，工作区边界见 [WORKSPACE](../../../docs/WORKSPACE.md)。

用自然语言选择两个模式，不需要额外命令解析器：

- **preliminary／初步模式**：恢复现状，提取原对象、量词和目标，标出确实影响解题的歧义，形成可交给文献调查的初步表述。不要在搜索前假定题目全新、可解、只适合某条方法。
- **final／定稿模式**：读已有初步规格与实际 `LITERATURE.md`，核对文献对符号、进口、基线及目标含义的影响，写成可执行的正式规格。若调查尚缺足以影响目标含义的关键来源，补查那一项；不要把整轮调查从头重跑。

用户只说“明确这个问题”时，先做初步模式；已有调查足够时接着定稿。用户只要求准备问题，完成初步模式就可交付，不擅自启动长期研究。已有明确固定目标时优先恢复，不用两个模式把已经成立的规格重复审批。

被prepare或其他父流程调用时，按本次指定模式完成并返回；初步模式不自行启动survey或转入定稿。父调用者拥有“初步→调查→定稿”的调度，只执行一次调查。独立调用specify时，也只有用户明确要求接着调查，才由当前代理执行一次survey；已有同范围调查则直接消费，不另跑一遍。

沿用项目已有规格名和恢复入口；新任务默认 `FORMAL_SPEC.md`、`LITERATURE.md`、`NEXT_SESSION.md`。`FORMAL_SPEC.md` 可以从“初步，尚待文献核查”更新为正式版，不需要并行创建另一份同义spec或JSON状态机。改正式内容前保留已有有效论证和历史依据；有版本管理就使用现有历史，无需每轮额外复制整目录。

独立调用时本技能是规格文件的唯一writer。组合调用时父流程明确告诉它规格路径和已有输出归属；本技能返回应合入的正文与未决问题，由父writer写canonical文件。其他检索或反译worker只回交发现，不同时覆盖规格。不存在显式组合约定时按独立模式交付，不因磁盘恰有一份报告就吞掉输出。

## 两个模式怎样实际执行

**初步模式：** 读用户原文和题面 → 写出完整数学句子并逐句对应来源 → 分开题目与候选解法附加条件 → 给调查者问题、异名、种子和真实歧义 → 返回prepare。题目本身够清楚就交调查，不在此试证候选路线。遇到会改变对象域的歧义，保留两种解释及哪一句未确定，询问这一实质问题；其它不依赖它的准备继续。

**定稿模式：** 读初步规格和survey返回的真实结论 → 核影响原题含义的原文条件 → 修正记号、量词或引用，保留用户目标 → 写清允许的解答与验收 → 反译一次并返回caller。调查只支持条件结论时，输出“可用工具需要条件A，原题未给A，下一阶段须证明A或换路线”；不能把A补进原题后称定稿。

两次调用写同一份正式规格的不同阶段。初步产物不会因出现`FORMAL_SPEC.md`这个文件名自动成为定稿；恢复时读其中标明的模式、已消费调查和下一动作。短题的这些内容可以写在一页里。

## 1. 先恢复事实，再解释题目

先找原规格、`NEXT_SESSION.md`及任务wiki的 `query_pack.md`。摘要提供导航，再沿当前义务读相关实体与原始证明／输入；query pack有篇幅限制，缺某结论不等于结论不存在。需要读取旧计算时看实际产物与最后退出信息，不能把旧“运行中”当今日状态。只读技能、整理材料或准备新题，不恢复已暂停Goal或旧计算。

恢复时用一段话区分：本轮用户让继续哪件事；原目标是什么；已经成立的结果是什么；具体还缺哪个连接；旧材料哪些属于其他参数或其他问题。用户只问现状就据此回答；已授权继续研究则把后续动作交回主流程，不停在重写摘要。

全新任务从用户给的原始材料读题，而非从二手总结反推题目。PDF如果含候选推导，将题面与候选解法分开：题目定义仍需理解，推导中的附加条件不自动进入目标。表格中的一个数若是猜测、上界或旧纪录，要查清它在原文的标注，暂时不把它写成精确值。

可直接给工作agent的调用如下；`/clone/MathRSI`和`/tasks/problem`替换为实际路径，它们是示例位置：

```text
读取 /clone/MathRSI/base/skills/mathrsi-specify/SKILL.md 并执行初步模式。
工作区 /tasks/problem。输入是用户本轮题面及 ref/problem.pdf；
已有 FORMAL_SPEC.md、NEXT_SESSION.md 时先恢复，不重置wiki。
保留用户给定目标和允许终点，交付足以广搜的对象、量词、参数、
异名候选与实质歧义。暂不启动求解路线循环或计算任务。
```

这对Codex、Claude都有效，因为实际读取了本技能。本技能本身为宿主无关Markdown；它调用的ARIS内部动作则按下一节选择相应宿主文件，不能混用工具名。

## 2. 形成足以检索的精确初步问题

把题面反译成完整数学句子。需要写清的是对象类和全量词，而不是提前选择证明技术：对象有限还是无限，简单对象还是允许重数，参数固定还是变量，目标是存在、全称、极值、最优值、算法或分类。符号用本题自然的记号，不强制给每条句子发ID。

尤其检查这些会改变终点的区别：

- “对每个输入存在一个见证”与“给出一个对所有输入统一适用的显式算法”；后者只有原题要求才加入。
- 一个具体对象的证书，与覆盖全部对象的不可能性证明；前者可由启发式发现，后者不能由未搜到目标替代。
- 证明下界、上界或精确值。已得一侧界不自动闭合另一侧；“改进下界”也不必同时确定等号。
- 原对象与内部约化子类。正则、平衡、有限维、线性等技术条件可以出现在候选引理中，进入原命题需有原题依据。

用一两个直接相关的边界对象检查反译即可。例如目标说“至多M个约束”，不能在规格中只写“恰好M”而不解释补齐是否保真；目标是严格大于，不能改成大于等于。若存在等价表述，先写推导方向；尚未证明的“等价”写成待核转换，不作为搜索后自动可用的归约。

来源明确的术语可直接采用。影响目标的歧义，例如图是否允许重边、参数是给定实数还是整数、用户要算法还是存在性，确实不能从上下文确定时才询问；同时继续不依赖答案的来源定位。命名、目录等非阻塞事项按项目惯例处理，不为它们中断任务。

给survey的检索面可从三个相关方向提取：对象的异名与可能等价表述；当前参数或近邻参数的已有结论/反例；已知候选工具的原证明条件。例如Property B的原题可查“非二染色k元超图的最少边数”及其“边数预算内所有超图可染”的表述、相邻k的已知界、所提重染工具的假设。只有本题确有参数或候选工具时才加入相应方向；尚无方法时不为凑三项发明一个。

在 `FORMAL_SPEC.md` 写下初步命题后，给文献调查的输入应包括原文锚点、等价／异名候选、已有来源与当前未知。不要只交一个宽泛topic词。下面是**返回父调用者执行的调查委托**，不是本次初步模式当场执行的命令：

```text
读取 /clone/MathRSI/base/skills/mathrsi-survey/SKILL.md，
在 /tasks/problem 调查 FORMAL_SPEC.md 中的初步问题。
以 ref/problem.pdf 和已有 research-wiki 为种子，补外部异名、
前后引用链、勘误及反例；不把原目标换成更容易或更新颖的题。
由父调用者执行一次survey，LITERATURE.md 由指定writer写；返回实际可用进口、基线、
已找到的直接证明/反例、关键原文缺口，以及正式定稿会受影响的定义。
```

父流程已有唯一 `LITERATURE.md` writer时，委托中明确“返回待合入内容，由父流程写该文件”。初步模式在交回规格、实质歧义和这份委托后结束；prepare随后执行survey，再显式调用本技能final模式。独立specify且用户明确要求继续调查时，才执行该委托一次；调查完成回当前调用者，由它按授权安排定稿。survey内部的ARIS调用、PDF深读与wiki更新按其完整流程完成，不在specify再复制一套。

## 3. 消费调查：文献校正知识，用户决定原目标

定稿时必须实际读 `LITERATURE.md` 的结论、已用原文位置和未读来源，而非只接收“查新通过”。再读影响本题含义的原定义、定理及必要证明范围。发现“全称结果只对一个子类成立”，先核对是否文献的限制；不能反向把该限制加进用户原题以使方法适用。

调查可能得到直接证明、严格反例、只有近邻结果、或关键论文仍未取到。分别处理：

实际处理每个拟用结果时，在现有规格/文献记录中把两句话分开：“文献在A条件下证明B（版本与位置）”；“原题输入是否满足A，已有哪条证明或尚缺哪项连接”。前一句核过不等于后一句完成。定稿保留用户原量词，把首个尚缺的连接连同caller位置交回父流程写恢复页；不是把所有文献前提挪进主定理。

1. **已有定理直接推出原题**：在规格记准当前可用结论、版本及映射，把下一步改为复述／验证该推论；无需假装仍需原创搜索。用户若本来要求独立新证明，保留这一要求，已有结果提供基线而不替代交付。
2. **找到可能反例**：先确认对象、参数及被否定的确是原命题。传给后续验证的是完整对象和性质，不是一句“文献说不对”。原题允许反例作为终点时据其合同处理；原题没有给替代终点时如实报告冲突，不偷偷换成邻近真命题。
3. **只找到更强／更弱／不同对象域的结论**：保留差别。一个邻近定理不能因标题相似升级为本题进口，也不能因缺新颖性取消用户想完成的证明。
4. **关键原文未得或条件无法确认**：保留明确未决点，返回survey的定点深读动作。其他独立部分可以继续；不把“尚未确认”写成“已知错误”。

如果调用了ARIS `novelty-check`，其建议评估的是贡献与近邻工作，不是更改原目标的权限。它的PROCEED／CAUTION／ABANDON及分数不是数学真值；用户指定任务可以继续复现、证明或改进已有结果。只有用户原本交给agent选题时，才在允许范围内提出替代问题。

若原任务是“超过已知界／选择有竞争力的目标”，定稿还要说明比较的是哪种对象、哪条已核保证及来源日期；已知构造族在合法参数下的推论也参加比较，不能只对照一张表的已列实例。新来源抬高基线时，把受影响候选及新的竞争门槛交回 prepare／原 caller，让它实际调整队列；不把新门槛静默替换成用户固定的数学参数。若用户固定要构造某个对象，则继续原交付，只撤回已失效的“新纪录”措辞。DD 中 O22 构造合法但被 P33 公开机制超过，是这两种状态分开的[具体例子](../mathrsi-meta-evolve/references/evidence-and-transfer.md#4-链三基线改变的是研究价值不是图的合法性)。

## 4. 写成可供求解与验收的正式规格

规格应让后继agent不靠聊天记录知道自己须证明什么。采用定义—目标—允许终点—依赖的自然结构即可，不需填满无关栏目。对长任务通常包含以下内容：

**原题与对象。** 准确引用用户输入或题面位置，随后独立定义对象、参数、允许的退化情形与符号。只写会影响命题的约定，标准对象无需重写教科书。

**完整目标。** 用一句正式量词表达主结论，再用自然语言反译。若任务允许构造或全域排除二选一，两条终点分别写清验收；它们是足以解题的替代终点，不能各只做一半。若只有一个终点，就不擅自添加反例／算法／Lean要求。

**允许的已知结果。** 分开记录已自行证明的事实、经原文核对的文献进口、仍条件化的候选。对于进口写版本、编号／页码、完整前提和本题符号映射，并指向 `LITERATURE.md` 的详细依据。待证条件是后续研究义务，不是规格默认假设。

**什么算解决。** 自然语言证明要回到任意原始输入和主结论；构造给真实对象并证性质；若采用计算辅助，说明需要补全哪些数学覆盖与输入连接；若用户要求Lean，说明最终形式声明须保留同样对象与量词。此处不要求所有路线有限分类，不提前冻结不存在的checker接口，也不把代码退出零或模型赞同当统一完成标准。

**范围和依赖的剩余疑问。** 已有数学条件仍可作为有价值的工具，但它能否从原输入取得应另记。未解决之处写具体问题和下一读取位置，不写“继续研究”这样的空动作。

保持旧正式规格的目标不变时，只补清术语和出处即可；发现真实冲突时写明哪一句受影响及依据。若要改用户给定参数或终点，交回这一实质决定，而不是以“文献更强”为名代替用户修改任务。

## 5. 反译校对，然后交给主流程

每批澄清／反译前和结果返回后，对照原题检查这次改变是否消除了实际对象域、量词或验收歧义，并使首个未闭连接更明确。仅改术语、重写摘要或反复反译稳定规格，不算原目标推进；把方法所需条件补进原题更不能当作解除了瓶颈。

同一瓶颈连续两个实质批次没有改变下一步决策，或局部产物持续增加而关键连接、全域覆盖或端到端成本没有改善，或到达约定检查点／扩批预算时，必须返回直接caller请求[全局进展重判](../mathrsi-research/references/global-reassessment.md)，再由它交唯一研究dispatcher消费；不能自行批准沿原路线继续扩批，也不能自行启动同级stage。批次按能产生可检验信息的实质工作计，不按消息或文件计。独立调用没有父流程时，由当前执行者承担本次授权scope内的唯一调度。具体评估者和决策流程沿共享协议，不在本技能另建循环；短证明不为形式完整强制多agent。返回prepare的内容仍是稳定规格、真实歧义与首个未闭连接；重判不赋予specify选择求解路线或更换目标的权限。

最后把正式规格当作另一位研究者的唯一题面，检查自己能否从中读出原任务。重点核对刚被修改的定义、量词、严格性和允许终点；没有变化的部分复用已有核对，不启动无收益整稿审查。复杂或确有语义争议的任务可委派一次独立反译，要求它只读原题和规格，列具体不等价处；不要求每次都外呼模型。

反译通过并不证明定理成立。它只是说明下一阶段有明确目标。返回主流程的内容包括：正式规格路径；文献基线和可用进口位置；尚待证明的原题连接；首先值得处理的实际数学问题。路线选择由主流程／`mathrsi-route-loop`完成，本技能不在规格末尾用一条武断推荐锁死整个研究。

独立完成时更新 `NEXT_SESSION.md`：本次是初步还是正式、哪些定义已对齐、哪些来源仍缺、下次应读什么并执行什么。已有checkpoint保留旧已证结论与在途工作，不覆盖成空导航。组合调用把这段回交父writer，避免两个child争写checkpoint。

## 小例：同一个精确目标可有两侧义务

若用户要求证明 `R(3,3)=6`，初步规格先定义有限简单无向图的Ramsey数，并写两项共同义务：每个6顶点图都有三角形或3点独立集；存在5顶点图两者都没有。不能把“一张6点图有三角形”误作上界，也不能只证上界就宣称等号。

调查的查询可包括 `R(3,3)`、`triangle or independent triple`、`two-colouring of K6`；边着色表述到图／补图的对应需写清。定稿后上界可从任一点的三名邻点或非邻点作短证明，下界可用5圈及其补图核对。这里展示的是实际数学任务的量词拆解，不是宣称本技能已检索其历史来源或要求所有新题沿这个方法研究。

本例短到可以在一个文档内完成，无需创建大量义务文件、调用Lean或启动路线多轮评审。长题则沿同样原则，把真正影响正确性的区分写到能执行的程度。

## 不足、恢复与独立调用

材料缺题面时，从用户原话建立明确标注的初步理解并定位缺失；不能假装已读未提供PDF。文献缺关键进口时返回survey相应查询／原文定位，保留已核事实。规格歧义得到答案后只改受影响处，不重复查过的全文与证据。已暂停研究仅准备规格时，checkpoint明确“准备完成，研究未恢复”。

独立调用示例：

```text
读取本仓 mathrsi-specify/SKILL.md，执行final模式。
工作区已有 FORMAL_SPEC.md 与 LITERATURE.md；
核对原题量词和文献后的完整进口，更新正式规格及NEXT_SESSION。
用户固定的目标保持不变。本轮只定稿，不开始求解。
```

主流程调用同样的输入，最后改成“回交定稿内容，由父writer合入，随后继续路线设计”即可。模式是工作范围，不是必须等待新一轮用户输入的关卡。
