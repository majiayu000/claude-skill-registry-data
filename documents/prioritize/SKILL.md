# Prioritize

More work than capacity is the normal state. Decide what happens now, later, and never, and say why.

1. List the candidate work and the capacity available: time, people, and the attention of the decision-maker. Capacity that is not stated is assumed to be unlimited.
2. For each item, assess the value of doing it now versus later, and the cost of delay. An item whose cost of delay is low is not urgent even if it is valuable.
3. Order the work into now, later, and never. "Never" is a real answer and should be used; work that will not be done should be said, not quietly dropped.
4. State the ordering with the reason for each placement, and name the trigger that would move an item between buckets.

Prioritizing is a recommendation about ordering, not a commitment of resources. It does not authorize starting work or committing capacity.

Record this output in `docs/plans/` per the [doc system](../references/doc-system.md), delegating the write to a subagent.
