# MathRSI 证明装配

本技能把已经取得的数学结果写成从原题输入走到结论的完整证明。它是“装配验证”工作流中的装配步骤，也可由用户单独调用。输入可以是一组分散引理、带证书的有限归约，或已有较完整的稿件；输出是一份可供严格验证的完整正文，以及准确指出尚未接通之处的返回信息。

装配中允许展开已成立论证、省去重复符号、补写直接推论和真实调用，但不能为得到漂亮成稿改变原命题、偷偷把候选当进口、删去困难分支。发现需要新数学时，将那个具体义务交回 [mathrsi-prove](../mathrsi-prove/SKILL.md)。装配可以交回一份清楚的部分稿，不能用正文完整的外观代替证明完整。

**组合调用只返回原caller。** 由verify、prove、handoff或主流程调用时，完成指定scope后交回正文、状态和下一阶段建议，不自行再启动verify/prove/handoff；下一阶段由原调用方或唯一主dispatcher选择。本文“交回prove”等措辞表示需要的后继，不授予第二个调度者。内部proof-writer与必要推导照常实际执行。独立调用只完成本次授权的装配；用户明确要求持续研究时，由本agent接主调度一次再选后继，避免父子各启动同一任务。

## 一次装配的实际接棒

本次工作从“哪些结果已经可用”开始，落在“它们怎样共同推出这条原命题”。先读取源并还原调用链，再实际交给writer组织正文，最后读取成稿核前提供给与完整分流；返回的是这份正文及其连接状态。下面的入口决定第一动作，无须每次从空白起草。

| 当前输入 | 本次实际动作 | 交给调用方的结果 |
|---|---|---|
| 仅要求形式目标，或完整Lean出口已在手 | 读原目标和导出入口，确认不需另组织自然语言正文；返回caller建议verify直接Lean分支 | 原声明、实际模块/导出与已知连接或缺口；不为经过assemble先造TeX或调用writer |
| 分散的已证引理、文献进口与证书 | 读取实际证明和证据，把它们按原输入到结论排序，再调用proof-writer写现用正文 | 完整候选正文，或准确指出哪一步仍无上游供给的部分稿 |
| 已有完整现稿 | 读主命题和实际引用，确认关键连接；只修真正遗漏的说明 | 沿用的正文入口、改动和是否可交验证；不声称重复执行writer |
| 局部定理及caller | 仅组织该局部命题、必要定义、依赖和实际应用 | 可被原prove/verify消费的局部正文与条件，不升级成原题完成 |
| handoff要求重排已核章节 | 给writer现稿、允许的编辑范围和已有verification | 可读修订与实质差异；新数学断言明确交回caller建议验证 |

协调者在writer返回后亲自读文件，把每一处“由L”与L的真实前提对上。文字遗漏可以当场展开；没有证明的选择、完整分类或统一量词则成为明确blocker。不要让writer的完成标签替你做这个判断。后文分别给出调用内容、成稿消费和返回办法。

## 读取什么，在哪里写

先读任务的原规格、现有恢复记录、现用证明入口，以及本次要装配的引理和证据。

**仅形式目标无需先装配自然语言正文。** 若只验Lean见证/出口且不需要写作，读取真实声明与模块后直接返回caller，由其进入[verify的直接Lean分支](../mathrsi-verify/SKILL.md)；不把TeX、proof-writer或proof-checker加为形式验收前置。Lean模块本身尚待连接则标出实际接口，返回caller交lean-formalize；需要新数学时建议prove。若用户也要求可读证明或其正式审计，继续本技能组织该正文，Lean证据不能代替正文论证。

已有项目沿用其名称。新正文已确定要做正式proof-checker审计时，可直接选任务工作区的 `PROOF.tex`作为唯一正文，用可识别的定理/证明环境写作；不必先造Markdown再转TeX。短证明、仅Markdown交付或未确定正式审计时默认 `PROOF.md`即可。用户已有 `paper/main.tex`、`proof/main.tex` 或指定其他路径时，更新那个入口，不另外制造平行“正式版本”。任务状态留在原工作区，不写入本技能或领域插件。

本技能使用本仓完整 ARIS。Codex 读 [proof-writer](../skills-codex/proof-writer/SKILL.md)，Claude 读 [proof-writer 主线](../proof-writer/SKILL.md)。先完整读对应入口，再调用它处理明确目标。它默认写 `PROOF_PACKAGE.md`，所以**本次调用明确指定所选 `PROOF.tex`、`PROOF.md` 或现用正文路径及格式**；不让writer自行多生成一个默认版本。这是本次写作任务的明确目标，不是修改上游源码。helper 按[本仓调用约定](../../../docs/ARIS_REUSE.md)绑定本副本 `base/tools`，不回退作者机器的 ARIS 仓库或全局安装。

### 第一次进入与恢复

全新装配先确认本次声称要证明哪一个结果：原命题本身、指定子定理，还是一个阶段性条件结论。将它与允许进口、原输入的范围放在正文开头或已有规范中引用。若任务是“证明任意原对象”，一组特定实例的成功不会将入口自动改成实例命题；若任务只要显式见证，也不增加穷尽所有对象的要求。

恢复装配先读现有正文和 `NEXT_SESSION.md`，再查看上次未接通的引理是否已交回新证明或证书。旧稿已经准确表达且未变化的章节直接复用。检查实质变更所影响的引用、条件和下游结论，不重读所有历史失败，不因格式调整重跑既有数学计算。

已有领域材料按[领域调用与返回](../../../docs/DOMAIN_ROUTING.md)“装配、交付与下一次恢复”消费。读取该领域正式正文、实际检查范围与未供给前提，在本稿使用处明示条件并接真实输入；ECC混合Lean出口、极值有限/渐近界、Hamilton的带根路径或直接圈量词与Happy Ending工作稿状态各按原件保留，不能把圈延拓自动写成自由根路径或其维数提升。插件返回“通过”不能替代该段证明或文献进口。

## 1. 从原结论反向安排证明，再核正向输入能否到达

先在心中或现用义务记录中还原主证明：原结论依赖哪些定理、分支和见证，每一个条件引理需要什么，上游由哪个具体结果供给。大证明可在正文前保留简短依赖图；短证明直接写足逻辑即可。这里的用途是确定章节顺序和发现断点，不是数节点计算完成率。

整理输入时区分三件事。第一是原题给定的假设，它们可以直接出现在主定理。第二是已经证明的条件结果，装配必须在调用处说明条件如何从同一原对象得到。第三是文献进口，需要实际版本、定理或公式位置、完整参数范围和当前输入满足条件的依据。文献尚未核实的关键条件保持待核，不用“标准结果”盖住缺口。

对于计算机辅助证明，把正文中的四个动作接在一起：任意原对象为何进入被检查的域；数据或代表元如何编码这些对象；具体检查器实际证明了什么；这个事实如何推出原结论。有限目录的每项均通过不等于目录覆盖已证；两个局部最坏情况也未必可来自同一个对象。若归约合并了多个规范化，明确其可同时实施的依据或保留剩余分支。 对[有限条件计划](../mathrsi-prove/references/actual-input-coverage.md#4-有限计划明确量词允许在同一个实现中择一)，正文还须接通各分支失败条件在同一实际原输入上不能同时成立的引理，并说明被选计划如何还原该输入；仅列每项计划局部检查通过不构成覆盖。几何固定计划则保留其对全部实现统一适用的原合同，不把两类量词混用。

将每个实际用到的有限命题连到对应脚本、完整输入域、证书/结果路径和正文调用位置。只有一项时在该引理旁写清即可；多程序/多分支时用一张对照表供verify逐项消费。表格负责定位证据，正文仍证明范围覆盖及该结果如何用于原命题。

对于存在性结果，写出见证本身或其可读取的实际产物，说明如何确认它属于原对象域并满足目标性质。启发式怎样找到它可以简述，最终性质须由准确的数学或确定性核验支撑。对全称问题，样本或无反例搜索只可作为发现背景，不能填入全称连接。

此时若发现“引理 L 已证，但没有从原输入构造 L 所需的 A”，将缺口原样交回 prove：需要证明的量词、A 的具体条件、已可复用的 L、预定调用位置。不要命令 proof-writer 把 A 写成假设来让原主定理看起来闭合。

## 2. 实际调用 proof-writer，而不是让表格充当调用

把精确主命题、允许使用的已证结果、需要保留的原对象、正文目标路径与现稿一起交给对应宿主的 `proof-writer`。给实际源文件及使用位置，要求读取后组织完整论证。特别说明哪些结果已证、哪些是进口、哪些仍开，避免写作者替执行者发明状态。

例如在一个已有任务中可这样发出完整调用任务：

```text
读取本仓 base/skills/skills-codex/proof-writer/SKILL.md 并执行。
本次新稿将正式审计，唯一正文目标为工作区 PROOF.tex；
请直接使用定义、定理/引理及proof环境。已有正文则读后沿用其指定路径。
原命题见 FORMAL_SPEC.md；允许进口及原文位置见 references/IMPORTS.md。
使用 proof/selection.md、proof/coverage.md、proof/local-bound.md 的已证结论，
以及 work/exact-check/REPORT.md 实际支持的有限命题。
请从任意原输入开始，逐项满足这些引理的前提，最后回到原结论。
原题不变。若连接尚缺，返回准确 blocker 与仍成立的条件证明；
不要把缺口写成主定理新增假设。正文保留完整定义、定理/引理和证明。
```

路径是调用者任务中的实际文件，示例不代表这些文件已存在。若某一步只剩符号混乱或对象未稳定，先把具体推导交 [formula-derivation](../skills-codex/formula-derivation/SKILL.md)（Claude 用[主线](../formula-derivation/SKILL.md)），消费其稳定对象、假设与精确命题后再回 writer。只有内容需要它时才调用，不为装配每一章重复整个推导流程。

ARIS writer 返回三种有意义的结果。`PROVABLE AS STATED`的证明仍由 Root 检查它实际证明的声明及调用；`PROVABLE AFTER WEAKENING / EXTRA ASSUMPTION`必须与原题并列，不能关闭原义务；`NOT CURRENTLY JUSTIFIED`交回准确缺引理、无效推理或反例方向。其标签是作者对产物的说明，正式验证由 [mathrsi-verify](../mathrsi-verify/SKILL.md)承接。

## 3. 消费正文，关闭装配缺口而非只验文体

每批writer／推导调用前及成稿收回后，检查原输入到原结论的哪条箭头因此接通，而非只看章节是否齐全。若反复重排同一条件稿、局部引理增多却共同选取／完整分类／caller仍缺同一步，继续润色不能消除这个数学瓶颈；将严格部分与最小缺口保持在现用正文中。

同一瓶颈连续两个实质批次没有改变下一步决策，或局部产物持续增加而关键连接、全域覆盖或端到端成本没有改善，或到达约定检查点／扩批预算时，必须返回直接caller请求[全局进展重判](../mathrsi-research/references/global-reassessment.md)，再由它交唯一研究dispatcher消费；不能自行批准沿原路线继续扩批，也不能自行启动同级stage。批次按能产生可检验信息的实质工作计，不按消息或文件计。独立调用没有父流程时，由当前执行者承担本次授权scope内的唯一调度。具体评估者和决策流程沿共享协议，不在本技能另建循环；短证明不为形式完整强制多agent。装配仍不承担新路线或完整审计循环；返回的重判请求应附缺口的上下游接口，供caller决定prove或其它准确动作。

读取 writer 实际写出的文件。检查每个主要结果的对象、范围、假设和结论是否与输入一致；证明是否在所有分支结束后回到原目标。若一个分支引用另一份材料，正文要说清引用的是哪个已证结果和用法，不能把必要论证藏在一串无说明链接中。

正式稿采用定义—定理/引理—证明结构，符号在使用处可恢复，引用到实际版本和定位。把内部日志、废弃路线和模型讨论留在研究记录；成稿直接陈述最终有效证明。它可以清楚说明计算或进口的信任边界，但不用每段附免责，也不为压缩文字删掉非平凡推导。

若稿中只有文字遗漏、索引名称不同、引用位置不清或已证结论未展开，直接修正文并检查受影响处。若需要证明一个尚未成立的选择引理、重新分类完整域、证明一个新界，保留当前完整有效部分，返回 prove。装配者不以“写作修复”名义静默重开整条路线，也不直接嵌套路线改进循环。

当已经存在完整且准确的证明稿，本技能可以只读、确认当前入口，将“可交verify”的结果返回caller；不要求为了调用 writer 重写一遍。这里复用的是可检查的现成结果，而不是假装又执行了一次 writer。

遇到一个尚未核清的文献版本或前提时，只把该应用及源位置交 [mathrsi-survey](../mathrsi-survey/SKILL.md)或仓内research-lit定点补查，读取实际原文结论后回到这个连接。若当前只是符号/公式链不稳，前节的formula-derivation返回后仍由writer写入同一正文。需要对某个高风险连接独立验算时，将该局部命题和caller作为验证建议交回原调用者；不在assemble里启动完整proof-checker后又让verify重复审同一完整稿。各能力的返回必须改变这份正文中的具体步骤，不能只在报告里列出“已调用”。

## 4. 返回给验证或证明推进的内容

可进入完整验证时，返回实际正文入口、原规格、主结果、关键进口和计算证据位置，以及此次装配新增或改动的连接。仅形式目标的直接返回则给原声明、实际模块/导出及连接状态，不虚构一份正文或正式audit。把这些链接写回现有恢复记录即可，不要求另造 `ASSEMBLY_STATE.json`。没有实质未证连接才能称“完整候选证明已装配”；此语仍不等于最终验收已完成。

不能完整装配时，返回原题仍开、已经写好的严格部分、最小缺口、上下游接口和下一项 prove 行动。已有条件引理保留其准确假设，便于继续研究。若发现主定理必要前提或主要路线判断有误，由 prove 决定是否退回路线工作流；assemble 不自行改变研究目标或提高预算。

一次可消费的返回例如：

```text
正文：PROOF.md；原题：FORMAL_SPEC.md。
已装配：归约 R、局部定理 L、证书解释 C，适用范围保持原稿。
未接通：对每个原输入选出同时满足 A、B 的同一对象。
现有 L 只证明 A∧B→结论，不能单靠它关闭主定理。
交回 prove：补共同选取引理；证据及真实调用位于 PROOF.md 对应节。
```

组合调用到此返回原caller，由它消费结果继续；assemble不另发起下一阶段。独立只要求装配时交付该准确结果；独立且明确授权持续研究时，本agent转为一次主调度角色，依据结果选择verify或prove后继，不同时维持两条调度链。恢复时从该具体连接进入，正文中未变的证明和证据无需重做。

## 已解项目中的装配动作

Property B T33的24点完整caller返回后，原题仍余23点，正文就应写这个准确剩余。后来23点按真实低度点数和坏伙伴分成六支，各支给出实际 `H → PropertyB H`，再接最小反例约化，才消去点数、点对覆盖、profile和RemainingGoal等内部条件。把六份局部表并排放入一卷，或引用一个把unfinished branch当参数的conditional caller，都不能完成这次装配。具体转折见 [REAL_PROJECT_TRANSITIONS案例3、6](../../../development/workflow-redesign/REAL_PROJECT_TRANSITIONS.md)，实际最终连接见 [INTERFACE_MAP](../../../plugins/propertyb/knowledge/archive/context/propertyb33/round02/final-assembly/INTERFACE_MAP.md)。

ECC旧43/10证明的正文则必须串起完整母码分类、原目标到对应尾扩张的归约、完整合法集合以及全部pair低权见证。兼容图无边已推出所需无三行延拓时，正文直接用该必要条件回原结论，不等更强三行计算；算法发现目录的方式与后来证明目录完整的计数/互异依据分别说明。上述过程有已经完成的真实证明作锚点，不授权重跑原计算或恢复后来的45/11研究。
