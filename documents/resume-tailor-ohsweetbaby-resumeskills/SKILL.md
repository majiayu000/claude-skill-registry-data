# 简历定制器（Resume Tailor）

## 何时使用本技能

当用户想要：
- 针对某个具体招聘职位定制简历
- 调整简历以匹配岗位要求
- 创建一份投递特定岗位的定向版本
- 提到："定制简历""针对岗位改简历""目标岗位""具体职位""匹配职位描述"

请在使用 job-description-analyzer 之后使用本技能，以明确应突出什么。

## 核心能力

- 按与目标岗位的相关度重新排列经历版块
- 针对具体职位调整专业小结
- 补充职位描述中缺失的关键词
- 调整经历条目措辞以匹配岗位要求
- 在优化匹配度的同时保持真实性
- 创建多个定向简历版本

## 定制理念

**核心原则：** 你不是在撒谎或编造——而是在突出真实经历中最相关的部分。

把你全部的职业经历想象成一座成就图书馆。定制，就是挑选最符合每家雇主需求的那几本"书"。

## 定制流程

### 第 1 步：分析岗位（先使用 Job Description Analyzer）
- 识别要求的技能和关键词
- 记下这家公司的优先关注点
- 理解该岗位的核心职责

### 第 2 步：审计你的简历
对每个版块问自己：
- 这段内容是否支撑我应聘这个具体岗位？
- 针对这份工作，这句话有没有更好的表达方式？
- 它的优先级应该更高还是更低？

### 第 3 步：进行策略性调整

**专业小结：** 重写，使其呼应岗位的核心要求

**技能栏：** 重新排序，把最相关的技能放在前面，补充缺失的关键词

**工作经历：**
- 若较早的岗位与目标岗位更相关，可调整排序
- 调整条目顺序，把最相关的成果放在前面
- 将关键词自然地融入现有条目

**教育背景：** 突出相关课程、专业认证

## 逐版块定制指南

### 专业小结

这是你的"电梯演讲"——每次投递都要定制。

**通用小结（应避免）：**
```
以结果为导向的商务运营从业者，拥有 5 年经验。具备较强的分析和沟通能力。期望获得有挑战性的成长机会。
```

**针对运营经理岗位定制：**
```
拥有 5 年经验的运营经理，优化供应链流程并实现成本降低 25%。精通精益六西格玛（Lean Six Sigma）、供应商管理和跨职能团队领导。在保持质量标准的同时持续提升运营效率，有可验证的改善记录。
```

**针对项目经理岗位定制（同一个人）：**
```
拥有 5 年经验的项目经理，领导跨职能项目从概念到交付。持有 PMP 认证，精通敏捷方法论、利益相关方管理和预算管控。在超过 1000 万元的项目组合中，持续实现按时、低于预算交付。
```

### 技能栏重排序

**职位描述强调：** 数据分析、SQL、Python、利益相关方沟通

**调整前（通用顺序）：**
```
技能：Microsoft Office、沟通、项目管理、Python、SQL、数据可视化、领导力
```

**调整后（定制顺序）：**
```
技能：SQL、Python、数据分析、数据可视化、利益相关方沟通、项目管理、Microsoft Office
```

### 工作经历版块

**策略 1：调整岗位排序**

如果你最近的工作比之前的岗位相关性更低：

**调整前：**
1. 市场专员（当前岗位，但应聘的是数据类岗位）
2. 数据分析师（之前的岗位，高度相关）

**调整后：**
1. 数据分析师（标注真实日期，位置上移）
2. 市场专员（仍然保留，但退居次要）

**策略 2：调整条目顺序**

把与目标岗位最相关的条目放在最前面。

**应聘管理岗——优先放置：**
- 「领导 12 人团队……」
- 「管理 200 万元预算……」

**应聘技术岗——优先放置：**
- 「开发自动化系统……」
- 「分析 50 万+ 条数据……」

**策略 3：调整条目措辞**

融入职位描述中的关键词，同时保持真实。

**职位描述写的是：** 「利益相关方管理」
**你的条目写的是：** 「与多个团队协作」
**定制后的版本：** 「管理横跨 5 个部门的利益相关方关系，确保项目优先级达成一致」


## 常见定制场景

### 场景 1：应聘非技术公司的技术岗位

**挑战：** 他们既要技术能力，也要商业思维

**策略：**
- 以技术成果作开头
- 每条技术条目中都要体现业务影响
- 补充「面向业务利益相关方转译技术概念」类表述

### 场景 2：应聘管理岗（但你 IC 和管理都做过）

**挑战：** 展现领导力，同时不放弃技术信誉

**策略：**
- 小结：强调领导力
- 经历：以团队管理类条目开头
- 保留部分技术条目，证明你懂这项工作本身

### 场景 3：应聘创业公司（但你在大型公司工作过）

**挑战：** 展现你能在模糊环境中如鱼得水、身兼多职

**策略：**
- 突出跨职能工作
- 强调主动性与自驱力
- 展现灵活、有创造性的问题解决能力
- 弱化僵化流程和大团队协作的表述

### 场景 4：应聘大公司（但你在创业公司工作过）

**挑战：** 展现你能在结构和规模下高效工作

**策略：**
- 强调流程改进
- 突出规模化落地的工作
- 展现跨团队协作
- 补充体现规模化影响力的指标

## 关键词融入规则

### 应该做：
- 添加能真实描述你工作的关键词
- 准确时直接使用职位描述的原文措辞
- 把关键词自然地放在上下文中
- 在多个位置出现（小结、技能、经历）

### 不应该做：
- 添加你并不具备的技能
- 关键词堆砌（同一词重复 10 次）
- 制造与真实经历不符的含义
- 为关键词密度牺牲可读性

## 真实与定制的边界

**可以接受（正常的定制）：**
- 重排真实信息
- 突出相关经历
- 使用行业通用术语
- 为模糊表述补充背景说明
- 使语言风格与职位描述一致

**不可接受（撒谎）：**
- 添加你不具备的技能
- 篡改数字或指标
- 编造假经历
- 冒用你没有担任过的头衔
- 声称拥有你没有的证书

## 版本管理

### 维护一份母版简历
- 保留一份包含全部经历的完整文档
- 收录你写过的每一条经历条目
- 这是你的「唯一事实来源」

### 创建定向版本
- 文件命名清晰：「张伟_简历_产品经理_某某科技.pdf」
- 记录每个版本投给了哪家公司
- 保存定制笔记，用于面试准备

### 版本命名规范
```
[姓氏]_Resume_[目标岗位]_[公司]_[日期].pdf

示例：
- Smith_Resume_PM_Google_Jan2024.pdf
- Smith_Resume_DataAnalyst_Meta_Jan2024.pdf
- Smith_Resume_General_Master.docx（母版文件）
```

## 快速定制检查清单

在提交任何简历之前：

1. ✅ 小结中出现了岗位的确切名称/职能
2. ✅ 你的前 5 项技能与职位描述的前 5 项要求一致
3. ✅ 最相关的经历排在最前面
4. ✅ 每段工作经历的首条条目回应了岗位的核心要求
5. ✅ JD 中的关键词自然地贯穿全文
6. ✅ 正确使用了公司/行业的术语
7. ✅ 所有表述真实无误
8. ✅ 文件命名得当
9. ✅ 保持了 ATS 兼容的排版
10. ✅ 已存档，可供面试准备时参考

```markdown

**改后：** [定制版本]
**新增关键词：** [清单]

### 技能栏
**新顺序：** [重新排序后的清单]
**新增：** [新关键词]
**移除：** [如需腾出空间而有删除，列出]

### 经历改动

**[公司名称] - [职位名称]**
- 将条目 X 移至第 1 位
- 修改条目 Y：[改前 → 改后]
- 在条目 Z 中添加关键词「[措辞]」

[对每段相关的工作经历重复以上操作]

### 整体改动摘要
- 新增关键词：X 个
- 修改条目：Y 条
- 版块重排：是/否
- 预计新匹配度得分：Z%
```

## 实施注意事项

- 始终从 job description analyzer 开始
- 将定制改动记录成文档，供面试准备使用
- 持续维护母版简历作为事实来源
- 绝不为定制而牺牲 ATS 兼容性
- 定制完成后测试关键词匹配度
