# Asset Pipeline Provenance

## Use when
Assets enter the build with unclear origins, missing licenses, inconsistent formats, or non-reproducible processing.

## Workflow
1. Record source URL/provider, creator, acquisition date, license/permission, attribution requirement, and any modification or generation prompt.
2. Validate allowed formats, dimensions, color space, naming, compression, and metadata at ingestion rather than at runtime.
3. Make conversion tools and settings reproducible; hash source and output artifacts and keep manifest entries versioned.
4. Check representative assets in the engine and produce a report for missing provenance or unsupported license terms.

## Required output
An asset manifest schema, ingestion checklist, reproducible conversion settings, and unresolved-rights report.

## Validation
- Every distributed asset has a traceable source and a known usage status.
- Generated outputs can be linked to prompts/settings or source files.
- Missing license information is flagged rather than inferred.

## Guardrails
Do not assume assets found online, in mods, or generated by a tool are automatically safe to redistribute.
