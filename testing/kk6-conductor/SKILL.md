# 進行役

このセッションは進行役です。実装は作業セッションが行います。進行役は、作業セッションを始め、報告を受け入れ、統合します。ほかのスキル（poteto-mode など）が「受け取ったチャットが自分で実行する」と書いていても、このセッションではこのスキルの進め方を優先します。

計画（要件を詰めて `docs/tasks/phaseN.md` を書くこと）は、別のセッションで済んでいる前提です。

## 手順

### 1. 読む

`docs/tasks/phaseN.md`、`docs/tasks/phaseN-sessions.md`（あれば）、`docs/tasks/phaseN-check.md` を読み、どのタスクが済んでいるかを `git log` と PR で確かめる。

完了の条件：今回の範囲のタスクを、済んだものと残っているものに分けて言える。

### 2. まとまりとブリーフを用意する

`phaseN-sessions.md` がない、または今回の範囲のまとまりが載っていなければ、`docs/tasks/phase3-sessions.md` と同じ形で書く。

- まとまりの表：まとまり、タスク、内容、前提、並行、ブランチ
- 分け方の理由：並行できるまとまりは、触るファイルが重ならないことを書く。`main.rs`、`src/mocks/ipc.ts`、`tauri.conf.json`、`Cargo.toml` に触れるまとまり同士は並行にしない
- まとまりごとの開始ブリーフ（下の「開始ブリーフ」）

書いたら、表を利用者に見せて確かめてもらう。

完了の条件：今回の範囲の残りのタスクが、どれか1つのまとまりに入っている。利用者が表を承認した。

### 3. 作業セッションを始める

前提が済んだまとまりごとに、`mcp__ccd_session__start_session` でカードを出す。

- `initiation`：`offer`。利用者がカードで始めるかを選ぶ
- `context`：`fresh`。ブリーフに必要なことを全部書いてあるので、この会話は渡さない
- `use_worktree`：`true`
- `prompt`：そのまとまりの開始ブリーフ。利用者から渡すよう頼まれたブリーフは、書き換えたり縮めたりせずにそのまま渡す

並行できるまとまりは、同時にカードを出す。並行しないまとまりは、前のまとまりを統合してから出す。

カードを出したら、作業セッションの報告を待つ。待っている間に、そのまとまりのコードを自分で書き始めない。

### 4. 受け入れる

作業セッションの報告が届いたら、報告を証拠として扱わず、自分で確かめる。

- 差分を読む：`git diff main...<ブランチ>`。ブリーフの「タスク」と「守ること」に合っているか
- CI と同じコマンドを手元で流す：`npm run lint`、`npm test`、`npm run test:e2e`、Rust を変えたら `cargo fmt --check`、`cargo clippy -- -D warnings`、`cargo test`、Python を変えたら `uv run pytest` と ruff
- CLAUDE.md の「検証のスキル」に当てはまる変更なら、そのスキルを流す（Rust のコマンド・DB・ファイル操作なら `verify-kura`）
- ブリーフの「完了の条件」を1つずつ照らす

テストの出力の要約は、読み取り専用のサブエージェント（`model: sonnet`）に任せてよい。

足りないところがあれば、新しいセッションを開かず、そのまとまりの作業セッションに `SendMessage` で直しを頼み、もう一度この手順を行う。

完了の条件：完了の条件がすべて満たされ、流したコマンドがすべて通った。

### 5. 統合する

利用者に次の3つを報告し、マージの許可を待つ。

- やったこと
- 確かめた方法（コマンドと結果）
- 確かめていないこと（実アプリで自分ではできない操作は、起動の手順と確かめる操作の一覧を付ける）

許可が出たら、進行役がマージする。作業セッションはマージしない。マージしたら、`phaseN-sessions.md` の表を今の状態に直し、手順3に戻って次のまとまりのカードを出す。

## 開始ブリーフ

`mattpocock-skills:writing-for-agents` で書く。作業セッションが設計の判断をしなくて済む細かさにする。

1行目は、作業セッションを poteto-mode のやり方で進めるための指示にする。

```
Read /Users/kk6/.claude/plugins/marketplaces/cursor-plugins/pstack/skills/poteto-mode/worker.md before anything else.
```

2行目からの見出しは次の順にする。

- 背景
- 先に読むもの
- 注意すること
- タスク
- 完了の条件
- 守ること（下の「worker.md より優先すること」を含める）
- 報告（やったこと・確かめた方法・残った課題）して止まる。次のまとまりには進まない

### worker.md より優先すること

worker.md は、ブリーフがはっきり上書きした決まりだけを譲る。Kura の決まりと食い違う次の3つは、「守ること」に「worker.md より優先する」と書いて渡す。

- 未決事項（`docs/requirements.md`）に当たる判断は、自分で決めずに報告して止まる。worker.md の「質問せず、自分で選んで進める」より優先する
- PR のタイトルは `feat: <日本語の要約>（FR-xxx）` の形にし、説明は日本語の `## 変更`、`## 理由` の見出しで書く。worker.md の PR の形より優先する
- マージと main への push はしない

ほかに「守ること」に書くこと：ブランチ名、コミットに FR の ID、コードのコメントは日本語。
