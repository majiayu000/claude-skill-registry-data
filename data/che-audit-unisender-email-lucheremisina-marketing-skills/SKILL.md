# CHE_audit-unisender-email — Аудит email-рассылок UniSender

## Контракт зависимостей

- Для расчёта по готовому нормализованному JSON внешние коннекторы не нужны.
- Для live-сбора live-адаптеру требуются read-only capabilities
  `email.campaigns.read`, `email.campaign_status.read`,
  `email.campaign_stats.read` и
  `email.delivery_stats.read`.
- Не предполагать наличие link-level статистики у провайдера. Live-аудит
  имеет статус `partial`, пока карта ссылок не передана в нормализованном
  входе из другого подтверждённого источника.
- Для post-click анализа опциональны `web_analytics.report.read`,
  `web_analytics.sources.read` и `web_analytics.goals.read`. Для сверки воронки доступны
  `crm.leads.read`, `crm.pipelines.read` и
  `crm.pipeline_statuses.read`, но они не доказывают email-атрибуцию:
  полный attribution/revenue-аудит требует нормализованный вход с этой связью.
- Способ подключения и авторизации определяет платформа; Skill его не реализует.

## Маршрутизация

- Только анализ прошлых кампаний → этот skill.
- «Подготовь письмо по этим ссылкам» → `универсальный workflow подготовки письма`.
- Еженедельный поиск тем и материалов → `универсальный workflow подбора email-тем`.
- Накопительный анализ + спрос + письмо + черновик UniSender →
  `workflow подготовки и согласования email-кампании`.

## Цель

Оптимизировать не открытия сами по себе, а воронку `доставлено → уникальный клик → визит → качественный визит → заявка → продажа`. Работать read-only. Не изменять, не отправлять и не планировать рассылки без отдельного прямого запроса.

## Рабочий процесс

Собрать кампании, link map и сопоставимые окна; разделить primary/resend; нормализовать источники; проверить unique/total клики и UTM; диагностировать post-click; сверить CRM только по доказуемой атрибуции; вернуть complete/partial и приоритеты. Нет данных — не подставлять ноль.

Для этого этапа читать [процедуру](references/email-audit-procedure.md); выполнять её проверки и сохранять артефакты.

## Режим по расписанию

Для автоматизации через n8n или Scheduled Tasks:

1. Обнаруживать новую завершённую кампанию по `campaign_id`.
2. Создавать предварительный срез D+3 с меткой `provisional`.
3. Обновлять итоговый срез D+7 и включать его в baseline.
4. При необходимости создавать D+14 только для длинного цикла заявки.
5. Хранить снапшоты идемпотентно по `campaign_id + observation_window + as_of`.
6. Повторять временные ошибки коннекторов, но не публиковать неполный отчёт как полный.
7. После изменения коннектора проверять первый фактический запуск, а не только структуру workflow.

## Ограничения и безопасность

- Не помещать email, телефон или имя в UTM и URL.
- Для пользовательского связывания использовать только непрозрачный `click_id` с серверным сопоставлением и подходящим согласием.
- Отклонять URL с email, телефоном или именем в query-параметрах; не считать автоматическую проверку исчерпывающей PII-защитой.
- Не запрашивать и не раскрывать секреты; подключение источников обеспечивает платформа.
- Не смешивать lifetime-метрики с фиксированным D+7 baseline.
- Не скрывать расхождения между источниками и не выбирать удобное значение без обоснования.

## Среда и входы

Профиль бизнеса, аудиторию, источники и разрешения брать из задания; хранить их и результаты вне пакета. Методолог навыка не становится автором материала автоматически. Использовать только объявленные инструменты. Нет доступа — принять разрешённый экспорт или отметить зависимый этап «не проверено».

Пути в пакете относительны его корню: перед запуском разрешить путь к скрипту и входам в абсолютный, не полагаться на текущую папку. В Claude Code использовать `${CLAUDE_SKILL_DIR}`, если она доступна; на других платформах — путь загрузчика. Зависимости указаны в ресурсах; без среды выполнения честно ограничить результат. Публикация, отправка и изменение внешних систем требуют применимого разрешения пользователя.
