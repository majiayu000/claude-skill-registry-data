# Fullstack Project

Гайд по запуску полноценного веб-приложения (frontend + backend).

## Архитектура

| Вариант | Описание |
|---------|----------|
| Монорепо | `client/` + `server/` в одном репо (проще деплой) |
| Отдельные репо | Фронт и бэк в разных репозиториях (независимость) |
| Монолит + SSR | Next.js/Nuxt с API-роутами (быстрый старт) |

## Чек-лист запуска

### Скелет
- [ ] Определи структуру: `client/` (React+Vite), `server/` (FastAPI/Express)
- [ ] Инициализируй git, `.gitignore` (node_modules, .env, dist, __pycache__)
- [ ] README с инструкцией запуска

### Backend
- [ ] Создай API-сервер с health-эндпоинтом `/api/health`
- [ ] Env-конфигурация, CORS для dev-ориджина фронта
- [ ] Миграции БД (если нужна) — см. навык `database`

### Frontend
- [ ] Создай клиент с роутером и первой страницей
- [ ] Прокси `/api` на бэкенд (Vite proxy / CRA proxy)
- [ ] Базовый компонент + вызов API

### Связка
- [ ] Один `npm run dev`/`docker compose up` поднимает всё (см. `docker-dev`)
- [ ] Проверь, что фронт обращается к бэку (CORS/прокси настроены)
- [ ] Healthcheck фронта и бэка

### Окружения
- [ ] `.env.development`, `.env.production`
- [ ] Примеры env: `.env.example` в репо (без секретов)
- [ ] Секреты — через secret-manager на проде

## Правила
1. Начни с минимального «hello world» связки, затем наращивай.
2. Держи контракт API (типы/схемы) общим или задокументированным.
3. Один источник правды для конфигурации.
4. Проверь полный цикл: запуск → запрос → ответ → отображение.
