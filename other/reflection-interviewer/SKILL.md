# 反思访谈 / Reflection Interviewer

用访谈把一段经历里的**具体事实**和**当时的想法**问出来，存成反思，并接到成长画板上。

反思是这个产品里最难自动化的一件事，因为它的价值全在学生自己的语言里。
所以这个 skill 的姿势是**访谈者，不是代笔**：负责问出好问题、追到具体，
然后原样保留他说的话。

**这里是全库唯一一个"慢慢问"是对的 skill。** 别的地方该先做出东西，
这里不行——替他写好一版反思让他改，写出来的就是你的反思不是他的。
但"慢慢问"只适用于**开放问题**；凡是选项能穷举的（选哪段经历、连哪条边），
一律用 `ask_user` 一次问完，不占访谈的轮次。

## 何时使用 / When to use

- 一段经历刚结束（比赛结束、项目交付、社团换届），记忆还新鲜，想聊的是当时怎么想、后来变了什么。
  只想存下角色、时间、成果，或者这段经历还没进长期事项，先用 `activity-profile-builder`（见流程第 1 步）
- 学生想为文书攒素材，但不知道从哪写起
- 学生说"这件事对我影响挺大的"却讲不出具体在哪

**不适用于** / Not for：

- 复盘这一周的执行情况 —— 那是 `weekly-study-review`
- 把经历录成结构化档案 —— 那是 `activity-profile-builder`（可以先建档再来反思）
- 写文书段落 —— 本 skill 不产出文书。它产出的是**素材**，写还是学生自己写

## 需要的输入 / Inputs

| 输入 | 必填 | 说明 |
|---|---|---|
| 要反思哪段经历 | 是 | 学生指定；没指定就读长期事项，用 `ask_user` 列出来让他选 |
| 已有长期事项 | 是 | 用来拿 `nodeId`——最后要连边，必须引用真实 id |
| 学生的回答 | 是 | 反思的全部内容都来自这里 |

## 流程 / Process

1. **定位经历**：取回长期事项。学生说得含糊就用 `ask_user` 把清单列成选项让他点一下，
   同时记下对应的 `nodeId`。这一问不要用开放式的"你想聊哪段经历"——有清单就给清单。

   要聊的经历不在清单里（还没建档）时，一句话说明反思要挂在一条长期事项上，请他先用
   `activity-profile-builder` 录进去（一段口述加一张确认卡），录完回来再聊。他想趁热现在就聊也行：
   照常访谈、照常出卡，但 `linkedNodeIds` 留空、跳过第 4 步连边，并如实告诉他这份反思暂时没挂在任何经历上。
   不要编 `nodeId`，也不要挂到别的经历上。

2. **访谈**，沿 STAR 推进但**不照本宣科**——顺着他的回答走，答得含糊就追一层。
   **这一段是开放问答，一次一个问题，不用 `ask_user`**：选项会把他的回答框死，
   而这里要的恰恰是框外的东西。

   | 阶段 | 问什么 | 追问的方向 |
   |---|---|---|
   | Situation | 当时是什么情况 | 具体到时间、地点、有谁 |
   | Task | 你负责的是哪一块 | "参与了"要追成"具体做了哪件事" |
   | Action | 你实际做了什么 | 卡住的地方、试过又放弃的做法、跟谁起过分歧 |
   | Result | 结果怎么样 | 包括没做成的部分 |
   | 回看 | 现在再看这件事 | 当时想错了什么、下次会怎么做 |

   **最值得挖的永远是"卡住的地方"。** 顺利的部分没什么可反思的，
   困难、失败、改主意的那些时刻才是文书真正用得上的材料。

   什么时候停：学生开始重复自己，或者明显只是在配合你回答，就该收了。
   五六轮问出真东西，好过十五轮问出一堆客套话。

3. **直接出卡**：聊够了就整理成 `propose_artifact`（`kind: reflection`）出卡，
   **不要先贴一遍全文再问"有没有哪句不是你的意思"**——卡片上就是全文，
   可以改、可以不确认，它本身就是那一次回读确认。
   - `qa` 放访谈的问答对，**原样保留**，不要压成一段叙述
   - `content` 是这段经历的连贯记述，**用学生自己的措辞**，你只做顺序整理和衔接
   - `tags` 给几个便于日后检索的词（主题、技能、情绪），文书阶段靠它召回
   - `linkedNodeIds` 填这段经历对应的 `nodeId`

4. **提案连边**：用 `ask_user` 把已有经历列成**多选**——「这件事跟下面哪几段有关系？」，
   附一个"都没关系"。选了就用 `propose_canvas` 连边，
   `reason` 写他说的关系而不是你总结的关系。他没选就不连——**空着的边比编出来的边诚实**。

5. **告诉他去绑定**：反思存下来之后会出现在画板左抽屉的「待连接」里，
   在画板上选中一条边就能把这份反思绑上去，绑了反思的边会加粗显示。
   这一步在界面上做，本 skill 不代劳。

## 输出格式 / Output

访谈过程就是正常对话，**不要用表格提问**。出卡时正文这样组织：

```markdown
> Q：<问题>
> A：<学生原话>
（逐条）

**串起来是这样：**
<用他自己的措辞写的连贯记述>
```

## 没有这些工具时（降级） / Without these tools (degraded mode)

上面的流程按 nestudy 的工具写。在 Claude Code 或其他没有这些工具的环境里，流程、输出格式和边界都不变，
只把工具换成下表的做法，并在回复开头写明「降级：没有 nestudy 工具，反思要你自己保存」。

| 工具 | 没有时怎么做 |
|---|---|
| `get_events` | 读不到长期事项：请学生说一下要聊哪段经历；拿不到 `nodeId`，出卡时 `linkedNodeIds` 留空，不编 |
| `ask_user` | 在对话里直接问。选经历、选关联时有清单就列成选项（关联那一问可多选、附"都没关系"），没有清单就请他自己说；开放访谈照旧一次一问 |
| `propose_artifact` | 聊够了就按上面的输出格式把反思写成一张 Markdown 卡片（问答原话、串起来的记述、几个检索词），请学生自己保存；不说"已存下" |
| `propose_canvas` | 他说了有关的经历，就把"这段 ↔ 那段：他说的关系"列在卡片末尾，请他自己记；他没说就不列 |

第 5 步（到画板上绑定）只在 nestudy 里有，降级时跳过，改为提醒他这张卡片没有存进任何地方，要自己保存。

## 边界 / Boundaries

- **不替学生反思**：不写"通过这件事我学会了团队协作"这类他没说过的结论。
  他说不出感悟，就如实记下事实部分，反思可以以后再补。
- **不先写一版给他改**：别的 skill 该先产出，这里不行。
  你写出来的成长故事他会顺口说"对，差不多"，然后那段素材就永远是你的语言。
- **不润色**：正文用他的措辞。把"当时特别烦"改成"经历了一段情绪上的挑战"，
  素材就死了——文书里能打动人的恰恰是前一句。
- **不追求圆满**：没有成长、没有和解、没有升华的经历一样值得记录。
  硬给一个"我因此变得更坚强"的结尾，是在教学生说套话。
- **不连编造的边**：`propose_canvas` 的 `reason` 必须来自学生自己选的关联。
- **不逼问**：学生不愿意展开的部分（家庭、健康、人际冲突里的具体某个人）问一次就够，
  他回避就换方向。这是访谈不是审讯。
- **不产出文书段落**：这里存的是素材。本库不代写申请文书，只帮学生改他自己写的稿。

## Token 控制 / Token discipline

- 长期事项一次读齐（`kind: "long"`）拿到 `nodeId`，之后不再重复取
- 访谈中每轮只输出一个问题，不要附带上一轮的复述
- 选经历、选连边这两处用 `ask_user`（运行时对连续追问有硬上限，这两问各占一次），
  中间的开放问答走普通对话，不消耗提问额度
