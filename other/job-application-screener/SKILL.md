# Job Application Screener

> ⚠️ **This is the desensitized public edition.**
> All personal paths, real referral codes, and private profile content have been stripped
> and replaced with placeholders. Before using it, fill in your own profile, screening
> standards, and referral library — see **Setup** below.
> If you have a populated local copy, prefer that; this file is the skeleton, not a drop-in replacement.

Decide **whether to apply**. Tracking what you already applied to is
`job-application-tracker`; resume wording is `vibecoding-resume-story`.

## Setup — you need three files

| 文件 | 用途 |
|---|---|
| `profile.md` | 学历 / 经历 / 项目 / 技能 —— **简历打法的唯一依据** |
| `screening-standards.md` | 目标岗位优先级、跳过清单、城市权重、扣分项 —— **权威** |
| `referral-codes.md` | 真实内推码库 —— **找码第一站** |

🔴 **绝不能凭印象写这个人的背景。** 曾因没读档案，把「海外社媒剪辑」岗位误判成 PR/达人营销，
并批量读错岗位地点，产出一份全错的名单。写之前先读档，读完再动笔。

## Step 1: Read every screenshot

1. **一张一张读完**，读完**显式报出总数**："你发了 N 张，我逐张读完了" —— 有过漏读事故。
2. **分页与滚动重叠**会重复，去重后报实际岗位数。
3. 🔴 **筛选条件和搜索框会切片数据**（最高价值的一条）。
   - 教训一：思必驰默认视图看不到职能类岗，不提醒就漏了。
   - 教训二：用户搜「运营」没清空，页面底部写着「没有更多了~」看着像完整列表，
     实际官方 500 个岗位只看到 50 个。
   - **识别信号：岗位标题里出现黄色/浅色高亮的关键词**（搜索命中高亮）
     → 立刻判定「这是搜索/筛选结果，不是全量」，要求清空后重截。
4. 底部「没有更多了」= 完整列表；有分页控件 = 还有第 N 页没截。
5. 截图常**不含公司名和 URL**（顶部被裁）→ 用指纹反推：
   ①工作城市下拉框的城市组合 ②职能分类的特殊命名 ③岗位名+分类+城市的组合
   定位后用官网/BOSS直聘公司介绍交叉验证。
   🔴 线索不足就**直接问用户**，别硬猜——猜错公司后面全错。

## Step 2: Cross-check the job count (three numbers)

把三个数字对账，**对不上就是漏了**：

1. **页面标题的岗位总数**（如「开启新的工作（40）」）
2. **官网分类导航的计数**（如「策划类 共5个 / 运营类 共6个职位」）
3. **分页控件页数 × 每页条数**

- 正例：标题 40、4 页×10 条、我数出 40 → 可自信宣布「读全了」
- 反例：官网「运营类共 6 个职位」，截图只露出 2 个
  → **真正的机会可能就在没看到的 4 个里**，绝不能下「没有合适的运营岗」的结论

⚠️ **别把「需求人数」当「岗位数」**：高校就业网的「招聘岗位数」字段**经常填的是需求人数**
（长安写 500 实为「智能网联研发类 需求人数 500」，北汽写 1700 实为「招聘人数 1700」）。
51 个岗位 × 平均十来人 ≈ 500 人，二者不矛盾。
看到官方数字与页面数差几倍时，**先分辨它是人数还是岗位数**，别直接相除；
**以官网列表页标题 + 逐张去重数为准**。

## Step 3: Reverse-look-up the JD

**官网 SPA（北森/zhiye、Moka）直接抓只能拿到标题，抓不到正文。** 改用：

| 站点 | 命中场景 |
|---|---|
| `watchjobs.net` | JD 全文 + 优缺点分析，覆盖最全 |
| `nowcoder.com` | 内推码、员工发帖、笔试情报 |
| `campus.niuqizp.com` | 招聘批次/时间/城市汇总 |
| `o-hr.com` | 长三角岗位，含截止日期和人数 |
| 高校就业网 | 官方公告原文，最准，**常带内推码** |
| 企业自建招聘站 | 比 SPA 好抓，**JD 正文常可直接搜到** |
| `waiyupai.com` | 海外岗/小语种岗 JD 全文 |

🔑 **北森系统加 `?KeyWords=` 参数的页面会被搜索引擎收录完整 JD 正文** ——
搜 `<公司>.<域名>/jobs?KeyWords=` 或岗位名，往往直接命中带完整职责与任职资格的官方页面。

### 三道校验（搜到 JD 后必做）

**① 经验年限** —— 判断校招/社招最快的信号
- 要求「1 年以上 / 3 年以上」→ **社招岗**，明确告知
- 写「经验不限」或标「应届生校招」→ 才是该投的

**② URL 日期戳 / 发布日期** —— 判断 JD 是否过期
- 例：URL 是 `/market/**20191209**/xxx.html` → 2019 年的旧 JD，不能当现行标准
- 列表页留意每个岗位后的发布日期，差一年以上说明是混编的长期在招池

**③ 这家到底有没有这届校招** —— 🔴 **搜不到公告 ≠ 没有校招**
- 教训：我因搜不到公告就下「这批是社招池、没有 2027 届校招」的结论，
  用户随即发来该公司的「校园招聘」专页截图，当场打脸。
- **判据按可靠性排序**：
  1. **招聘官网有没有独立的「校园招聘」入口/导航项**（最可靠）
  2. 页面自身的校招标识（标签、高亮导航项、筛选器维度）
  3. 高校就业网公告（辅助，**不能作为否定证据**）

### 两条必须前置查的投递规则

**① 每家能投几个？提交后能不能改？** —— 各公司差异极大，**直接决定志愿怎么排**

| 公司 | 限制 |
|---|---|
| 米哈游 / 4399 | **1 个** |
| 库洛游戏 | 2 个，第一志愿优先 |
| 巨人网络 | 2 个，**提交后不可改** |
| 字节 / 小米 | 通常 2 个 |

→ 遇到「只能投 1 个」，**必须给出唯一推荐并说明理由**，不能让用户自己选。

**② 实习转正制 还是 直接发正职 offer？** —— 流程形态影响时间表能否接上

## Step 4: Rate and output (fixed four sections)

**匹配度三档：高 / 中 / 低**

```
一、这批图里有什么（N 张，逐张读完）
二、值得投的岗位      表格：公司 | 岗位 | 城市 | 匹配度 | 我用哪条经历去打 | 内推码
三、明确不建议投的
四、下一步动作
```

🔴 **内推码必须和岗位写在同一行/同一条里**，禁止「岗位给一堆、码另起一段罗列」。
没有公开码的，**当场写明「无公开内推码 → 走 XX 官网投递」**，并给替代路径
（公众号 / 校园大使 / 牛客·B站在职员工 / 玩家社群）。
搜不到就明说搜不到，并交代搜了哪些来源。

### Non-negotiable

- 🔴 **绝不说「没有合适的」** —— 必须列出最接近的 3-5 个，说明为什么都不合适
- 🔴 **绝不编内推码 / 公司 / 经历 / 数据** —— 不确定就写「待确认」
- 🔴 **已投过的要标出来**
- 🔴 **别吹没玩过的 IP** —— 严格区分「这家公司做过什么」（可写，公开信息）
  与「我玩过什么」（只能写真玩过的）。写了「熟悉该厂 XX」面试必被追问

### 敏感字段（补考/重修/处分/亲属）

一律 **如实填 + 最小必要**。**选「有」不致命，选「无」才是风险** ——
这类字段给入职材料核验/背调用（上市国企/大厂校招普遍要交成绩单）。
课程名按教务系统全称照抄，多门用顿号分隔，**不加解释、不卖惨**。
提醒用户去教务系统核实，别凭记忆——背调对不上比挂科本身更麻烦。

### 标准答法

- 期望薪资：必填数字填区间中位；可填文字写「按公司薪酬体系执行」
- 到岗时间：给出对应其当前实习结束时间的准确表述
- 语言水平：分数不高时国内岗**只写等级不写分数**

## Example

用户发 3 张心动公司校招列表截图 →
①「你发了 3 张，我逐张读完了」② 检查高亮/筛选器 → 无高亮 →
③ 对账：标题 40 / 4 页×10 / 我数 40 ✓ →
④ 反查 JD → 校验年限与发布日期 →
⑤ 查投递限制（心动按项目分别投）→
⑥ 四段输出，每个推荐岗位行内带内推码 + 投递入口。
