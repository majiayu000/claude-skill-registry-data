# CHE_wordstat-trend-radar — Wordstat Trend Radar

## Контракт зависимостей

- Обязательны публичные read-only methods MCP Panel
  `wordstat.regions.read`, `wordstat.top_requests.read` и
  `wordstat.dynamics.read`.
- Для сверки видимости опциональны
  `webmaster.queries.read`,
  `webmaster.query_history.read` и
  `webmaster.query_history.read`.
- Локальные Python-скрипты и SQLite используются только для вычислений и
  истории проекта; способ авторизации коннекторов определяет платформа.

Строить воспроизводимый радар спроса для одного проекта. Сначала зафиксировать границы исследования, затем собирать Wordstat. Не позволять новым формулировкам самопроизвольно менять ядро проекта.

## Обязательные артефакты

Хранить для проекта четыре файла и одну локальную историю:

1. `project-registry.json` — подтверждённые границы бизнеса.
2. `seed-manifest.json` — воспроизводимый список стартовых фраз.
3. `candidate-ledger.json` — все найденные запросы с решением и причиной.
4. `cluster-registry.json` — стабильные кластеры, алиасы, URL и история изменений.
5. `trend-history.sqlite` — наблюдения, снимки запусков и изменения сигналов; не хранить в нём ключи доступа.

Схемы и правила читать в:

- `references/project-registry.md` — обязательный реестр проекта;
- `references/clustering-policy.md` — отбор, объединение и стабильные ID;
- `references/data-contract.md` — контракты промежуточных и итоговых данных;
- `references/methodology.md` — расчёт трендов.

## 4. Применить ворота отбора

Проверять кандидата в фиксированном порядке:

1. Запрещённая тема или значение → `reject`.
2. Неразрешённая неоднозначность → `reject` или `review`.
3. Нерелевантен продукту → `reject`.
4. Ниже минимальной частотности → `watch`, если тема обязательная или уже есть товар/URL; иначе `reject`.
5. Прямой или допустимый смежный спрос → `include`.
6. Исследовательская близость → `review`, не включать автоматически.

Использовать уровни из реестра, а не свободную оценку:

- `direct` — продукт решает запрос непосредственно;
- `adjacent` — запрос ведёт к продукту через одну понятную задачу;
- `exploratory` — гипотеза без подтверждённого предложения;
- `irrelevant` — вне продукта.

Обязательная тема может пройти ниже порога только со статусом `watch`; она не становится приоритетной без материального спроса.

## 10. Выдать отчёт и аудит охвата

Начать с 3–7 сигналов, требующих решения. Для каждого показать кластер, метрики, покрытие, бизнес-связь, действие, уверенность и приоритет.

Обязательно добавить контроль качества исследования:

- число активных seed-фраз;
- число кандидатов Wordstat;
- долю `include`, `watch`, `review`, `reject`;
- причины отклонения;
- обязательные темы без спроса;
- кандидаты без назначенного кластера;
- новые, объединённые и разделённые кластеры;
- долю товаров, услуг, аудиторий и задач, покрытых seed-фразами.

Если необработанных кандидатов больше порога из реестра, не называть исследование полным.

## Ограничения

- Говорить «сигнал» или «оценка направления», а не «точный прогноз».
- Не считать черновой реестр подтверждённым.
- Не скрывать отклонённые запросы и причины.
- Не переносить выводы одного региона на другой.
- Не делать вывод о падении по одному месяцу.
- Не считать нулевые месяцы до появления запроса историей сезонности.
- Не путать рыночный спрос Wordstat с видимостью сайта.

## Среда и входы

Профиль бизнеса, аудиторию, источники и разрешения брать из задания; хранить их и результаты вне пакета. Методолог навыка не становится автором материала автоматически. Использовать только объявленные инструменты. Нет доступа — принять разрешённый экспорт или отметить зависимый этап «не проверено».

Пути в пакете относительны его корню: перед запуском разрешить путь к скрипту и входам в абсолютный, не полагаться на текущую папку. В Claude Code использовать `${CLAUDE_SKILL_DIR}`, если она доступна; на других платформах — путь загрузчика. Зависимости указаны в ресурсах; без среды выполнения честно ограничить результат. Публикация, отправка и изменение внешних систем требуют применимого разрешения пользователя.
