# 用户故事拆解Skill

## 适用场景
需求调研后,把业务诉求结构化为用户故事清单,供后续定义验收标准与 PRD 撰写。

## 执行步骤
1. 识别角色(Persona):谁在使用这个功能(区分端用户/管理员/系统)。
2. 识别动作与价值:角色要做什么,达成什么业务价值。
3. 按「As a(角色), I want(动作), So that(价值)」格式落故事。
4. 用 INVEST 原则校验质量:Independent 独立 / Negotiable 可协商 / Valuable 有价值 / Estimable 可估算 / Small 足够小 / Testable 可测试。
5. 拆分维度(故事过大时):按业务规则、按数据变体、按操作类型、按验收路径拆分。

## 规范要点
- 故事聚焦业务价值,不写技术实现(不做「用户想要一张表」这种伪故事)。
- 一个故事 = 一个角色 + 一个目标 + 一个价值,禁止「和/或」复合故事。
- 故事粒度以「一个迭代内可完成且有独立价值」为上限。
- 每个故事必须有编号(US-001 递增),便于全程追溯。

## 输出模板
```
| 编号 | 角色 | 故事(As a/I want/So that) | 优先级 | 依赖 |
|---|---|---|---|---|
| US-001 | 普通用户 | ... | P0 | - |
```

## 自检清单
- [ ] 每个故事含完整三角色要素
- [ ] 无技术实现语言
- [ ] 每个故事可独立估算与测试
- [ ] 编号唯一且连续
