# modus-sync-knowledge

这是代码任务中的自动知识维护能力，不要求用户另行调用。以本轮实际变化确定调查起点，以当前源码和场景责任确定落点，以人工所有权确定权限；最小修订约束写入量，不能缩掉判断影响所必需的调查。

1. 复核本轮实际修改与授权，不接管工作区原有或其他作者的变化。证实无长期影响且无未解决项时静默结束；需要调查或维护时完整读取[增量维护流程](../using-modus/references/authoring/incremental.md)，不以文件类别、知识缺失或未调查替代判断。
2. 有影响时按同一流程追踪主定义、实际消费者及场景差异，原位修订并验收；同时修复受影响场景内已证实的历史错漏，不扩展成无关历史清理或全域复核。
3. 既有 Module 内的事实、案例、关联和锚点自动维护。真实新增、拆并、迁移或退役沿用已有授权；尚未授权时在当前任务中合并确认，确认后继续，不要求用户另跑维护命令。人工约束与业务资料默认保护，实现变化不自动授权改写 Team Standard。
4. 能在当前任务解决的证据缺口、输入错误和写入冲突继续解决。确需用户决定、外部信息或工具恢复时，报告具体位置、已完成内容和下一动作，不把部分成功或待处理偏差归为无影响。

`explicit`、`symbol`、`path-only` 和 `anchorReviewCandidates` 只用于定位；检查器的 `noop` 表示没有写入，不证明没有语义影响。正文质量、写入保护和结束条件由共享流程定义。不构建或读取初始化 bundle，不增加执行卡、队列、持久状态或宿主专用步骤。
