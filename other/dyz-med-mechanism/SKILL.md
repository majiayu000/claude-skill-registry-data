# 医学研究逻辑与机制推理

## 目标与边界

让论断强度与研究设计、时间顺序和证据等级一致，并把缺失的机制节点转化为可验证的下一步。

- 先读取 `references/mechanism-rubric.yaml`，按其中的链条节点、MRL 层级、证据标签和失败模式工作。
- 本技能提供研究逻辑审查，不代替临床诊断、伦理审查、统计分析或领域专家判断。
- 观察到的关联不能自动升级为因果；SHAP、变量重要性和预测性能不能自动升级为生物机制。
- 不虚构通路、实验结果、效应量、文献或因果方向。
- 不存在现成领域模板时，从当前证据构建并明确标注假设，不声称加载了不存在的文件。

## 先确定任务模式

| 模式 | 适用输入 | 核心产出 |
|---|---|---|
| 问题升级 | 临床现象、数据关联、组学信号、初步问题 | 当前层级、薄弱点、升级问题和最低证据 |
| 机制链检查 | 一段机制叙述或讨论段落 | 节点、证据等级、断点和修复建议 |
| 临床到基础 | 临床问题需要实验解释 | 机制假说、模型、验证链和回归临床路径 |
| 基础到临床 | 生物学发现需要转化 | 生物标志物、靶点、分层或监测价值 |
| AI 模型解释 | 医疗预测模型结果 | 预测证据、临床过程映射和机制边界 |
| 研究再设计 | 当前设计回答不了问题 | 最小改造、理想设计和可支持的论断 |
| 因果图 | 明确暴露、结局及候选变量 | 假设图、变量角色、调整集和风险 |
| 中介分析 | 明确暴露、中介、结局和时间顺序 | 估计目标、假设、方法与敏感性分析 |

信息不足时，优先确认研究设计、时间顺序、暴露、结局、数据来源，以及用户希望支持的具体论断。

## 通用推理流程

### 1. 标定当前层级

只能选择当前证据实际支持的一层：

- `phenomenon`：现象或印象，尚无稳定关联证据；
- `association`：存在统计关联，但没有可识别的因果路径；
- `mechanism`：有中介、通路或实验性证据支持机制链；
- `translational`：机制已连接到具体临床决策、干预或产品路径，并有相应验证。

“想研究机制”不等于已达到 mechanism；“可能有临床意义”不等于已达到 translational。

### 2. 展开机制链

按顺序检查：

| 节点 | 需要回答的问题 |
|---|---|
| Clinical problem | 要解释的临床问题是什么 |
| Upstream driver | 哪个暴露、信号或因素启动链条 |
| Mediator | 中间通过什么环节传递 |
| Executor | 哪个分子、细胞或生理过程直接产生改变 |
| Phenotype | 最终可观察、可测量的结局是什么 |
| Validation path | 哪类体外、动物、人体或干预证据能验证 |
| Translational value | 会改变哪个临床决策或工作流 |

为每个节点记录“当前论断、证据来源、证据标签、缺口、所需修复”。缺失节点可以保留为空，但必须明确承认。

### 3. 给每条机制陈述贴证据标签

使用评分表中的四级标签：

- `supported`：设计和证据可直接支持；
- `plausible_inference`：有间接证据，使用“提示、可能”等谨慎措辞；
- `speculative`：仅为待验证假设，说明需要什么研究；
- `unsupported`：现有证据不足，应删除、降级或补证据后再写。

优先标记以下失败模式：

- 相关性被写成因果；
- 跳过关键中介环节；
- 生物学机制没有临床连接；
- 只复述 AI 特征重要性；
- 尚未前瞻验证却声称临床可用。

### 4. 升级问题或重设计

给出两档方案：

- 最小可行改造：在现有资源内让问题与设计匹配；
- 理想设计：若资源充分，如何获得更强证据。

对每个方案说明可以支持和不能支持的论断。若描述性研究最适合当前阶段，直接说明，不强迫因果升级。

## 专项模式

### 临床与基础双向转化

临床到基础时，输出：

- 可证伪的机制假说；
- 候选通路及替代解释；
- 合适的细胞、动物或人体样本模型；
- 阳性、阴性和关键混杂控制；
- 最低可发表证据链；
- 如何回到临床人群、结局或干预。

基础到临床时，分别评估：

- 生物标志物；
- 治疗靶点；
- 预测模型输入；
- 监测策略；
- 患者分层。

每项都要写出验证阶段、实际决策点和失败条件。

### AI 模型解释

先分开三类结论：

1. 模型在什么数据和指标上具有预测性能；
2. 哪些特征对该模型的预测有贡献；
3. 哪些病理生理解释有独立证据支持。

只有第 3 类才能进入机制论证。特征的重要性、相关性或可解释性图表不证明特征是病因、干预靶点或中介。

### 因果图

输入至少包括暴露、结局、时间顺序和候选共同原因。按以下步骤工作：

1. 标记暴露、结局、混杂因素、中介、碰撞点、竞争风险，以及可能的未测量共同原因。
2. 每条有向边都写出依据；无方向证据时，把不确定性写在图外，不把普通关联边混入 DAG。
3. 检查有向环、时间顺序和变量双重角色。
4. 枚举从暴露进入的后门路径，提出候选最小充分调整集。
5. 检查调整是否误纳中介、碰撞点或暴露后的变量。
6. 说明未测量混杂、选择偏倚、测量误差和正值性风险。
7. 让领域专家复核图；无法由当前知识判断的边标为待确认。

若使用双向边表达未测量共同原因，应明确这已是更一般的混合图表示；也可以改用显式潜变量节点保持 DAG 表达。

标准输出至少包含：

```markdown
### 因果图说明
- 暴露：
- 结局：
- 混杂因素：
- 中介：
- 碰撞点：
- 未测量共同原因：
- 候选最小调整集：
- 禁止调整变量：
- 关键假设与待确认边：
- 可识别性与敏感性风险：
```

不要把自动生成的调整集写成已验证事实。

### 中介分析方案

只有在暴露、中介、结局和时间顺序明确后才进入此模式。

1. 明确估计目标：总效应、受控直接效应、自然直接效应、自然间接效应，或其他预先定义的效应。
2. 画出暴露到中介、暴露到结局、中介到结局的路径，并标出各路径的混杂因素。
3. 检查：
   - 暴露与结局之间是否存在未控制混杂；
   - 中介与结局之间是否存在未控制混杂；
   - 是否存在受暴露影响的中介与结局共同原因；
   - 暴露与中介是否交互；
   - 时间顺序、缺失、测量误差和正值性是否合理。
4. 根据结局类型、暴露类型、研究设计、交互、非线性和多个中介选择估计方法；不要仅凭结局名称固定软件包。
5. 预先规定置信区间、敏感性分析和假设失败时的降级解释。
6. 仅当总效应和分解尺度适合时报告“中介比例”；效应异号、总效应接近零或尺度不兼容时不报告。

标准输出至少包含：

```markdown
### 中介分析规格
- 暴露：
- 中介：
- 结局与测量时点：
- 估计目标：
- 时间顺序：
- E-O、E-M、M-O 混杂控制：
- 交互与非线性：
- 拟用方法及选择理由：
- 识别假设：
- 敏感性分析：
- 可报告与不可报告的结论：
```

用户需要可执行代码时，把该规格交给统计分析技能；代码和软件包必须与实际数据结构及 estimand 匹配。

## 完成检查

- 当前机制层级已明确；
- 机制链断点已逐项指出；
- 每条关键机制论断有证据来源和标签；
- 相关性、预测性和因果性没有混写；
- 横断面或观察性设计的机制语言已降级；
- 转化价值对应具体决策，或明确说明尚未建立；
- 因果图与中介分析的识别假设和未测量风险已披露；
- 给出 1 至 3 个可执行的下一步。
