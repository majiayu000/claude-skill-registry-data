# /consumer-hunt — у выпущенной вещи должен быть список адресов

## Закон
Выпустить и не разнести = не выпустить ([[connect-rule-pipeline-ownership]] + §1.5 «сделал → объяви»).
Молчание законно только с названной причиной; «неудобно / рано / не идеально» — не причина.

## Шаг 0 — RECALL
Проверить `_outreach/tracker.json` и журнал вкладов: куда по этому артефакту уже стучались.
Второй раз в ту же дверь = спам, а спам ≠ громкость.

## Шаг 1 — собрать список адресов (0 токенов)
```
python ~/.claude/scripts/consumer_hunt.py \
  --artifact <имя-репо> \
  --topic "<тема для каталогов, напр. llm agents>" \
  --problem "<фраза боли для чужих issue>" \
  --marker "<строка кода, которую пишут те, кто решает это руками>"
```
Три двери по возрастанию цены входа:

| Дверь | Что это | Цена входа | Что несём |
|---|---|---|---|
| **каталог** | awesome-список по теме | одна строка в README | строка + раскрытие самозаявки + граница «чего НЕ доказывает» |
| **issue** | открытый чужой issue про нашу боль | комментарий по существу | как наш артефакт закрывает именно этот случай |
| **код** | репо, где задачу решают руками | PR | патч, который снимает их ручную работу |

⚠️ **Честная граница движка (замер 05.08):** каталожная дверь даёт чистый результат
(7 живых списков с первого прогона). Issue-дверь на широком запросе ШУМИТ — тащит чужие
«живые» треды не по теме. Issue-дверь без узкой формулировки боли не использовать,
выдачу глазами фильтровать всегда.

## ⭐⭐ Шаг 1-бис — ПОЛНОТА СПИСКА: первый найденный почти никогда не единственный (anton 10.09.2026, голосом)

Дословно: «найдя потребителя, мы сразу думаем: а мы правильно только одного нашли?.. Нужно всегда качественно проходиться по волту, искать ВСЕХ потребителей, хорошо подумать над этим. Найдя всех потребителей, мы всем даём наш функционал. Нельзя сделать функционал и никому его не дать».

**Правило остановки: не «нашёл», а «насытился».** Поиск закончен, когда **две оси подряд дали ноль новых имён**. До этого вердикт «потребитель найден» произносить нельзя — первый найденный это тот, кто лежал на поверхности, а не тот, кому нужнее.

**Оси перебора — проходим ВСЕ, отмечая находки по каждой:**

| ось | вопрос | инструмент |
|---|---|---|
| **свои** (ищется ПЕРВОЙ) | какой узел флота, робот, оператор или человек команды перестанет делать это руками? | `fleet_fix_audit.py`, реестр рутин |
| **волт** | какой наш скилл/рутина/пайплайн должен звать эту вещь вместо своего костыля? | grep по СИМПТОМУ (не по имени), `/ask` |
| **каталоги** | awesome-списки и реестры по теме | движок Шага 1 |
| **чужая боль** | issue и треды с ДОСЛОВНЫМ симптомом | `gh search`, реверс-поиск `/share-fix` |
| **руками** | репозитории, где ту же задачу делают вручную | `--marker` |
| **соседние экосистемы** | другие LLM-харнессы, IDE, агентные фреймворки — не только наш вендор | `gh search` по их именам |
| **другой язык** | RU / EN / CN: один симптом ищется разными словами и даёт разных людей | повтор запроса на 2-3 языках |
| **не-GitHub** | HN, Reddit, Discord, форумы, реестры MCP и скиллов | `/rep-reply`, hn_candidates |
| **будущие** | кто наткнётся потом: README, документация, поисковый след | — |

**Полнота ≠ веер.** Исчерпывающим обязан быть ПОИСК; адресация идёт по правилам двери. Найденный адрес не выбрасывается — он получает **статус и дату**: `🟢 постучались` · `⏸ глухая очередь по замеру` · `🪦 непереносимо/приватно`. Молча пропущенный адрес = нарушение; отложенный с причиной = нормальная работа.

⛔ Не ослаблены: Шаг 2 (замер очереди ДО стука) · «спам не равно громкость» (§1.5) · Tier-2 · leak-scan.

**Вердикт Шага 6 обязан нести ЧИСЛО:** «осей пройдено N/9 · адресов найдено M · насыщение да/нет». Без числа это заявка, а не работа. Канон: `reglament-vypustil-funkcional-naydi-potrebiteley-i-pridi-k-nim` §Поправка 10.09 + [[consumers-are-a-set-not-the-first-one]].

## Шаг 2 — замерить очередь ДО стука
По каждому адресу `/issue-match <repo>`. Глухая очередь = мимо, сколько бы звёзд там ни было
([[cold-pr-into-silent-queue]]: замер 7 наших PR → 0 мержей именно из-за пропуска этого шага).

## Шаг 3 — форма заявки, которая проходит
Образец, который мы САМИ приняли 05.08 от reacher-z и который стоит копировать дословно:
1. **раскрыть самозаявку** первой строкой: «Self-submission: X is maintained by the submitting author»;
2. дать **одну строку в формате списка**, не абзац рекламы;
3. написать **границу**: чего наш артефакт НЕ доказывает;
4. приложить **проверку**: лицензия, дата последнего коммита, звёзды, проверка на дубль в README;
5. **никаких превосходных степеней**.

Именно из-за пунктов 1 и 3 его PR смержили, а не потому что бенчмарк известный.

## Шаг 4 — отправка
GitHub-коммуникация (issue, комментарий, тело PR) — САМ, без «+» (§4.7).
Код в чужой репозиторий — [[github-publish-autonomous]] + leak-scan.
Юридическое подписание (CLA, DCO, передача прав) — Tier-2, руки Антона.

## Шаг 5 — записать, иначе не считается
Каждый адрес → строка в журнале вкладов с датой, дверью, текстом и исходом.
Ответ прилетит через недели, и без журнала мы его не свяжем с причиной.
Молчание адресата 14 дней = парковка, не воскрешаем.

## ⭐⭐ Шаг 5-бис — СИММЕТРИЯ: у нас тоже видно, чего нам не хватает (anton 21.09.2026, голосом)

Дословно: «по образу и подобию тех гитхабов, где просят, наш гитхаб тоже всегда оформлять так,
что мы тоже просим … подумать, чего нам не хватает, минимум 30-50».

Мы приходим в чужой трекер по ЖИВОЙ просьбе с меткой. Значит и нас найдут только по такой же:
контрибьютор ищет `label:"help wanted"` и `good first issue`, а не читает README. **Дыра,
описанная абзацем прозы, для поиска не существует.**

Закончил заход по нашему артефакту → один замер и, если пусто, один ход:

```bash
gh search issues --owner tonydzi --state open --label "help wanted" --limit 100 --json number --jq 'length'
```

- Репо, куда мы только что звали потребителей, **не имеет ни одной своей просьбы** → завести её в
  том же заходе. Источник дыры — ТОЛЬКО наши же слова: секции `What's intentionally missing` ·
  `Honest limits` · `Roadmap: next` · открытые TODO. ⛔ Выдумывать дыру ради числа: лучше 30
  честных, чем 50 пустых (§5.4 правда в цифрах).
- Каждая просьба несёт: заголовок с глаголом · зачем нам (одно честное предложение) · что считается
  done · где в коде · размер S/M/L · метки `help wanted` + `accepted`, для S ещё `good first issue`.
- Раскрытие Майкрофта первой строкой (§3.3), чёрный юмор по умолчанию — это исходящее наружу.
- Строка в `$OBSIDIAN_VAULT/_outreach/we_ask_registry.jsonl` (repo · issue · size · created · claimed_by).

⚠️ ЗАМЕР, ПОРОДИВШИЙ ПРАВИЛО (21-22.09.2026): ~50 публичных репо, 16 открытых issue, **2** с меткой
`help wanted` на весь аккаунт — при том что мы месяцами отвечали в чужих трекерах. После прохода:
**53**. Доказательство, что шаблон работает, лежало у нас же: у `verbatim-citation-gate` было три
размеченных issue, и внешний инженер забрал их с первым PR в течение часа. Одно репо сделало
правильно случайно, остальные сорок девять были невидимы.
