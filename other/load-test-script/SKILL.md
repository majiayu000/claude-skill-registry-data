# 压测脚本编写执行Skill

## 适用场景
性能压测环节,编写并执行压测脚本,安全地获取系统容量数据。

## 执行步骤
1. 确认目标与边界:压测环境、接口、预期容量、禁止破坏性场景。
2. 选工具(Locust/JMeter/wrk)并编写脚本:请求构造、参数化、断言、数据采集。
3. 渐进加压:基准(1x)→ 负载(预期 60%)→ 峰值(预期 100%)→ 稳定性(预期 60% 持续 30min)→ 瓶颈探测(逐级加压至拐点)。
4. 采集指标:吞吐、延迟分位(P50/P95/P99)、错误率、服务端资源(CPU/内存/IO/连接数)。
5. 收尾:恢复环境、清理压测数据、输出报告。

## 规范要点(安全红线)
- 生产环境压测必须持「总控 + 安全合规」审批结论,无审批不执行。
- 压测数据必须与真实数据区分,写操作压测用影子数据/影子库。
- 监控先行:压测前确认监控可用,过程中实时盯错误率,异常立即停止。
- 渐进加压,禁止一步拉满;每档保持 5-10 分钟观察。
- 压测结束必须确认环境恢复(连接、数据、资源占用)。
