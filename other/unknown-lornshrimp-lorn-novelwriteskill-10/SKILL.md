## 标题即开篇：命名与开头的同构原则（新增）

> **读者看标题的决策模式，和看开头的决策模式完全一样——只是决策窗口从 3–5 秒压缩到了 1–2 秒。**

标题和开头的底层逻辑是**同构**的：

| 维度 | 开头 | 标题 |
| --- | --- | --- |
| 核心任务 | 在 3–5 秒内抓住读者 | 在 1–2 秒内抓住读者 |
| 交易本质 | 用字换注意力 | 用更少的字换注意力 |
| **认知缺口** | 制造"不往下看就亏了"的追问 | 制造"不点开就亏了"的直觉缺失 |
| **卖点展示** | 让读者感知本书核心卖点 | 让读者一眼判定"这书和我有关" |
| **人际关系反常** | 反常的关系比物理冲突更抓人 | 标题中的人际反常感同样比"XX传奇"更有驱动力 |
| **信息差** | 读者不知道的才是钩子 | 标题露出半扇门比全打开更有效 |
| **耐心值起点** | 开篇内容消耗读者的初始耐心 | 书名决定了初始期待值——书名弱则初始耐心起点低，即使开篇写得好也难挽回 |

> **三层漏斗视角**：在"黄金书名→黄金简介→黄金一段→黄金三章"的漏斗中，书名处于最顶层。读者在 3–5 秒内通过书名决定"要不要看简介"——书名没抓住人，后续所有开篇技巧都无从施展。这就是为什么同一部作品换个书名，数据可能差 10 倍。

> **耐心值理论**（来源：作家助手·夜宵，经`网文留存模型.md`验证）：读者耐心值 = 初始期待值 − 内容消耗速度 × 时间。书名是**初始期待值**的最大决定因素——书名决定读者点开正文前的"预设好感度"。书名强则初始期待值高，读者给的时间窗口长，内容容错空间大；书名弱则初始期待值低，读者可能只看"黄金 0.1 章"就划走。**书名设计不是独立艺术，而是留存工程的第一道防线。**

**因此，本书名 Skill 的所有原则，天然向下兼容到分部标题和分卷标题，并在"章节标题"层级面临更严格的字数约束。**

> 核心原则迁移：**好标题 = 好开头的压缩版**。能用一句话写好的开头，往往也能做标题——反之，标题读起来没感觉的，打开后大概率也没感觉。

### 书名钩子：全书钩子系统第一层（新增——2026 吸收写作研究）

社区验证的**钩子五层系统**（来源：七猫社区 #32138 云天河整理，收藏 642，阅读 79297），将书名的钩子能力定义为全书钩子的第一层、**流量入口层**：

| 层级 | 定义 | 执行要点 | 本 Skill 的职责 |
| --- | --- | --- | --- |
| **① 书名钩子** | 吸引潜在读者点击 | 扫榜摸清对应题材的平台取名风格，核心看点和创新点相融合 | ✅ 本 Skill 直接产出 |
| **② 简介/标签钩子** | 引起阅读兴趣 | 背景设定+当前处境+主线目标+矛盾冲突+卖点钩子+反转结局 | 由 `通用-撰写内容简介` 产出 |
| **③ 开篇钩子** | 引发追读欲望 | 必须紧扣主题和核心看点；意外事件 + 结果符合情绪预期 | 由 `通用-强化章节开头` 承接 |
| **④ 主线钩子** | 牵动整体故事线 | 紧扣核心看点梗，有可拉扯的空间 | 由大纲设计 Skill 承接 |
| **⑤ 章节小钩子** | 每章末尾驱动追读 | 把情节讲完但不说透，章末小高潮或伏笔驱动追读 | 由 `通用-强化章末钩子` 承接 |

> **实操规则**：设计书名时，必须同步判断"这个书名在五层钩子系统中完成的是第①层的职能"——它不负责讲完卖点（那是第②层的职责），不负责开头抓人（那是第③层的职责）。书名钩子的唯一使命是：让潜在读者在榜单/搜索结果/他人推荐中，**产生"点开一看"的冲动**。

这与"三层漏斗模型"（来源：`写作技法_黄金三章与黄金一章含金量提升研究.md`、作家助手·夜宵、B站高赞帖交叉验证）完全对应：

```text
第一层：黄金书名 + 黄金简介（3–5 秒）    ← 书名钩子 + 简介钩子
    ↓ 过滤不感兴趣的读者，吸引目标读者
第二层：黄金一段 / 黄金一章（150–300 字 / 前 3 段）  ← 开篇钩子
    ↓ 在读者划走前制造认知缺口
第三层：黄金三章（6000–9000 字）      ← 主线钩子 + 章节小钩子
    ↓ 完成"压抑→蓄力→首次爽点释放"的闭环
```

**实操含义**：书名设计不只是独立创作，它是全书钩子系统的起点——书名没做对，后面的开篇钩子、主线钩子、章末钩子全部没有施展入口。扫榜阶段可以通过快速分类法判断同赛道作品的书名钩子类型（通俗直白型 vs 文艺气质型），再根据自身题材定位选择竞争策略。

> **番茄数据引用**：番茄官方数据显示，仅改写书名就能带来最高 **40% 的阅读量差异**。同一个故事，换一个名字，可能就是从扑街到爆款的区别。**书名设计不是独立艺术，而是留存工程的第一道防线——做好书名设计，是"内容之外最便宜的流量杠杆"**。（来源：知乎专栏"中国网络文学研究"《不会给小说起名？这个公式让你分分钟写出读者喜欢的爆款书名》，番茄官方数据验证。置信度：高）

## 平台标题字数限制与显示规则（新增）

> **⚠️ 重要：字数限制是技术约束，不是质量标准。** 下表各平台显示的"推荐长度"反映的是该平台 UI 的**显示截断风险线**——超过此线标题可能被截断或折行，导致核心信息丢失。但"不截断"不等于"好"。**一个刚好不截断但平淡无奇的书名，远不如一个略超截断线但钩子极强、信息密度极高的书名**——后者即使被截断，前半部分已足够产生点开冲动。截断风险通过调整核心信息前置（前 N 字传递完核心卖点）即可解决，不需要为保完整显示而牺牲信息量。**平台字数限制的合理用法是：在截断风险线内最大化信息量和点击吸引力，而非盲目追求字数短。**

标题受字数限制比开篇更严格：不同平台的标题可显示空间不同，超出限制的标题会被截断、换行或隐藏，直接损失信息传递效率。

### 章节标题字数约束

章节标题受平台目录页显示空间和读者阅读节奏的双重约束：

| 平台 | 章标题推荐长度 | 说明 |
|------|--------------|------|
| 起点中文网 | 6–15 字 | 目录页显示空间充足，但超过20字会折行 |
| 番茄小说 | 6–12 字 | 目录页+信息流双重展示，过长老读者读不顺 |
| 七猫免费小说 | 6–12 字 | 推荐流章节卡片显示空间有限 |
| 晋江文学城 | 6–15 字 | 目录页较宽松但超过15字影响列表美观 |
| 知乎盐选 | 8–20 字 | 盐选专栏目录较长标题可接受 |
| 微信读书 | 6–15 字 | 阅读器目录显示空间有限 |
| 海外平台 | 4–8 个词 | 英文标题过长影响阅读节奏 |

> **章节标题字数策略**：在推荐长度内做够信息量；超出推荐长度的标题，核心信息必须在前 N 字内完整传递。同样遵循"点击吸引力优先于字数短"原则——宁可略超推荐长度但信息密度够，也不要硬压缩到推荐长度以内却失去钩子。

## 书名定位优先原则（新增——2026 深度研究整合）

> **书名设计的首要问题不是"怎么写"，而是"写给谁看"。** 来自 B 站高赞帖的核心观点，经作家助手多位编辑交叉验证。

在动手设计书名之前，必须先回答三个定位问题（缺一不可）：

1. **读者画像**：这本书的核心读者是哪个平台、哪个年龄段、哪个题材偏好的群体？
2. **读者期待**：这群读者点开这本书时，期待看到什么？他们被书名/简介惯出来的"默认胃口"是什么？
3. **书名承诺**：这个书名在 1–2 秒内向读者传递了什么"这本书是关于什么的"信号？

### 定位正确 > 命名技巧

| 情况 | 常见错误 | 正确做法 |
| --- | --- | --- |
| **追求"好听"忽略"好认"** | 起了与平台调性脱离的抽象名 | 让读者 30 秒内归类——知道这本讲什么的、什么风格 |
| **追求"独特"忽略"可预期"** | 书名花哨但读者无法判断内容 | 书名应该是一扇窗，不是一堵墙——透出内容比遮住内容更重要 |
| **追求"热度词"忽略"匹配度"** | 堆砌当前热门词但和内容无关 | 热词必须与正文核心卖点同向，否则会造成期待落差 → 高点击低留存 |
| **追求"全包含"忽略"主轴失焦"** | 一个书名塞了题材+人设+金手指+情感线 | 只选一个最强卖点当主轴——其他卖点放在简介里展开 |

**实操规则**：在设计书名之前，先写出两句话——"这本书是写给________看的"和"他们点开这本书是为了看到________"。如果这两句话写不清楚，所有的命名技巧都是空中楼阁。

**扫榜前置**：在动手生成候选书名之前，先针对目标平台的新书榜 / 新手榜 / 畅销榜做一次快速书名分类（详见 `references/平台书名策略矩阵.md` 的"扫榜书名快速分类法"）——判断同赛道 TOP 作品的取名形态是"通俗直白型"还是"文艺气质型"、各自嵌入了什么关键词、哪些公式在本赛道上已被验证有效。扫榜不是抄袭，而是摸清当前竞争的"命名基线"，让自己做出的书名能在这个基线之上差异化。

## 何时使用

### 模式 A（独立输出）
- 为整部小说设计总书名。
- 为分部、分卷设计标题。
- 为同一作品输出多平台适配书名。
- 对已有书名方案做重审、重排、重做。
- 从大量候选里收窄出 shortlist 或决赛版。
- 为候选标题提供评分、排序依据与降级说明。

### 模式 B（嵌入式轻量——供其他 Skill 调用）
- 设计总大纲时，为各部、各卷生成一个最优卷名/部名。
- 设计分卷大纲时，为章清单中的每一章生成一个章标题。
- 生成章节控制卡时，顺手补一个章标题。

## 层级输入与产物约定（全书 / 分部 / 分卷 / 章节标题）

- 默认先确认命名层级：
	- 全书总书名（Book）
	- 分部名称（Part）
	- 分卷名称（Volume）
	- **章节名称（Chapter）—— 新增支持**
- 若用户只说"起名"，默认先反问或自行判定当前层级；无法确认时，按"先总书名，再给 1 组分部名示例，再给 1 组分卷名示例，再给 1 组章节名示例"的轻量结构输出。
- 若用户要求一次性做完整分层命名，交付必须包含：
	- 总书名候选与推荐
	- 各分部名称候选与推荐
	- 各分卷名称候选与推荐
	- **各章节名称候选与推荐（至少覆盖前 10 章或所有关键章）**
	- 分层映射关系（哪一卷属于哪一部）
- 命名应满足"上位约束下位"：**章节名不能跑出所属分卷的叙事主轴，分卷名不能跑出所属分部主轴，分部名不能跑出总书名承诺。**
- **章节标题批量设计约束**：若一次为多章设计标题，必须读取各章的章纲/控制卡，确保标题承诺的内容与该章正文一致。不得只凭卷纲批量生成空洞标题。

## 章节标题设计策略（新增）

### 章节标题 vs 书名的区别

章节标题和书名遵循**同构原则**（都是"1-2 秒抓人"），但有三个关键差异：

| 维度 | 书名 | 章节标题 |
|------|------|---------|
| 寿命 | 长期使用、覆盖全书 | 一次性、覆盖单章 |
| 孤立性 | 可孤立存在、独立传播 | 依附于上下文（上一章+下一章） |
| 剧透风险 | 不能剧透主线 | 可适当剧透本章内容——但不能剧透本卷核心悬念 |
| 字数上限 | 2–10 字（中文平台） | 6–20 字（按平台） |
| 核心使命 | 让读者买书/点开 | 让读者点开这一章继续读 |

### 章节标题的六大策略

**1. 承诺回报型**（最推荐）
在标题中预告本章的"值回票价"内容——信息释放、关系推进或情绪爆发。
```
示例："他翻开最后一页，上面写着自己的名字" → 承诺信息释放
     "会议室里，她当众拿出了那份合同" → 承诺高能场面
```

**2. 追问型**
在标题中留下一个读者迫切想知道答案的问题，驱动点开。
```
示例："那天晚上到底发生了什么？"
     "为什么是她？"
```

**3. 反常型**
在标题中制造"认知缺口"——正常逻辑下不该出现的人、事或关系。
```
示例："死者给她发了一条微信"
     "她的指纹，出现在凶器上"
     "救他的人，是当年亲手送他进监狱的警察"
```

**4. 金句型**
标题本身就是一句可截图传播的金句，读完标题就情绪到位。
```
示例："他跪下来，不是为了求她原谅"
     "三年前她签的是离婚协议，不是放弃"
```

**5. 意象型**
用场景意象带出本章情绪基调，适合情感驱动章。
```
示例："雨停了，但她的世界还在下雨"
     "空荡荡的婚床上，只剩一张纸"
```

**6. 简明推进型**
直接写清楚本章推进的事件，不做任何修饰。适合纯推进章或过渡章。
```
示例："谈判"
     "现场勘查"
     "第三份合同"
```

### 章节标题的硬规则

- **禁止剧透本卷核心悬念**：章节标题可以预告"有事情发生"，但不能提前揭示本卷最大的反转、伏笔或秘密。
- **禁止假承诺**：标题承诺了高能场面，正文必须兑现。读者会先看标题再读正文——标题和正文体验落差大 → 弃书。
- **禁止连续使用同一策略**：连续 5 章用"追问型"标题，读者会产生套路疲劳。建议按"承诺回报→反常→追问→简明→金句"的轮换模式。
- **每一章标题都应服务于追读链**：作为上章出口钩的轻度回应 + 作为本章入口的轻度钩子。标题不应孤立于上下文。
- **批量设计时逐章验证**：批量生成前 10 章标题时，逐章对标章纲/控制卡，确认标题承诺的内容确实在正文中出现。

## 默认执行顺序

1. **竞对书名分析强制前置（含字数分布分析）**：在动手设计任何书名之前，必须先做目标平台的**扫榜**——遍历新书榜/畅销榜/飙升榜等榜单，采集同题材前 10–20 本作品的书名，做结构化竞对分析。记录以下维度：
   - 公式类型（通俗直白型/文艺气质型）
   - 前置词汇模式与关键词嵌入密度
   - 情绪锚点
   - **字数分布——各书名的实际字数与在该平台的展示完整度。特别关注高人气作品中超出"推荐长度"但仍获高点击的书名，它们是破除"字越少越好"执念的最佳证据。若占比 20% 以上的热门书名超出推荐长度，说明该赛道的读者更看重信息密度和钩子强度，而非字数短。**
   - **不得跳过此步骤直接套公式填空。**
   - 若已有该题材的竞对分析报告，阅读其中的"书名策略"章节即可。
   - 若无现成报告，对目标平台的榜单做一次"5 分钟快速扫榜"——只抓前 10 本书名的公式、关键词、字数和展示完整度，形成竞对书名基线简报。
   - **扫榜+竞对分析的目的不是抄袭，而是摸清当前赛道的"命名基线"**——知道自己要竞争的书名长什么样，才能在这条基线之上做出差异化，而不是闭门造车后发出去才发现和竞对撞风格。
2. 先读取工作区中与命名直接相关的研究文档、大纲、故事面和旧方案，禁止拍脑袋起名。
3. **检查项目根目录是否存在 `Agents.md`：若存在，读取并提取其中已注册的平台列表；若不存在或未声明任何平台，则只输出不区分平台的通用书名候选，跳过所有平台适配步骤。**
4. 先确认命名层级（全书/分部/分卷/章节标题），不同层级的策略和约束不同。
5. 再提炼 3–5 个标题母核，区分世界观核、悬疑现实核、人物伦理核、灾难事件核，并判断哪些卖点适合进书名、哪些只适合留在简介。
6. 若命中分层命名任务，先建立"总书名 → 分部名 → 分卷名 → 章节名"的命名骨架，再分层生成候选：
   - 总书名优先承诺全书母核与长期阅读预期
   - 分部名优先承诺阶段主题、阶段矛盾或阶段回报
   - 分卷名优先承诺当前卷核心冲突、关键异象/事件或关系推进
   - **章节名优先承诺本章核心回报、反常或情绪高潮（新增）**
7. **只对 `Agents.md` 中已注册的平台选择不同命名主轴**，并确认各层级标题不超过对应平台的截断风险线（而非盲目追求字数短），生成真正像书名的候选。**字数约束是"截断风险"的技术基线，不是质量标准。若在截断风险线以内，更长的标题如果信息密度更高、钩子更强、更能吸引点击，优先选择更长的版本，而非刻意压缩字数。** 未在 Agents.md 中注册的平台，跳过本轮设计，不生成任何候选。
8. 若设计章节标题，逐章对标章纲/控制卡，确认标题承诺的内容在正文中存在。按"六大策略"轮换，避免连续同策略。
9. 再按统一 Rubric 评分、排序、去重、筛 shortlist，并补齐排序依据与降级理由。
10. 最后按默认交付结构输出结果，并在未被用户禁止时写入仓库文件。

## 首眼识别补充（新增）

- 书名默认还要解决 `30 秒归类`：读者第一眼至少要能判断题材方向、核心气质或最值得点开的那一层承诺。
- 若作品的核心吸引力建立在人物处境、关系张力、成长回报或身份翻转上，候选标题里至少要有一部分能让这类价值被快速识别，而不是只剩抽象好看。
- 平台适配时，优先拉开“哪种承诺放到标题最前面”，而不是只对同一母核做换词、换标点、换语序。
### 书名认知缺口检验法（新增——2026 深度研究整合）

一个好标题和一般标题的关键区别，在于它是否制造了**认知缺口**（让读者觉得"不点开就亏了"），而非仅仅设置了悬念。

| 维度 | 制造悬念的书名（弱驱动） | 制造认知缺口的书名（强驱动） |
| --- | --- | --- |
| 运作机制 | "不知道故事会怎样发展" | "不知道自己不知道——这个书名暗示了一个我完全无法预测的世界" |
| 读者感受 | 好奇但可忍耐（点不点开差别不大） | 认知失调的点迫感（不点开就会一直惦记） |
| 典型特征 | 常规卖点罗列（XX大陆、XX传奇、XX记） | 反常组合（《诡秘之主》——诡秘+主，两个词造一个全新品类感） |
| 检验标准 | 读者看标题后说"哦，XX类型的小说" | 读者看标题后说"？？这是什么，我要点开看看" |

**实操规则**：书名候选交付前，逐条做一次"认知缺口测试"——给 5 个没看过本书的人看标题，问他们"用一句话猜这本书讲了什么"。如果 5 个人给出的答案高度相似且都是对某类套路的描述，说明标题只制造了"归类感"而未制造"认知缺口"。

> **来源**：知乎·包罗万象"认知缺口"理论迁移 + B 站高赞帖"定位优先于套路"论证 —— 标题本质是书名层的认知缺口，不是简介层的卖点清单。

### 爆款书名核心公式与万能变体（新增——2026 知乎专栏吸收）

> **来源**：知乎专栏"中国网络文学研究"《不会给小说起名？这个公式让你分分钟写出读者喜欢的爆款书名》（2026-06-28），作者顾里木图的小酒馆。数据验证自番茄/起点双平台 2026 年爆款书单。证据充分性：充分；置信度：高。

在动手起名之前，除了定位原则，还需要一套**可直接套用的命名公式骨架**。以下公式和变体经番茄/起点双平台爆款数据交叉验证，是高确定性可迁移知识。

#### 核心公式：人物 + 地点 + 动作

这条公式让读者在 0.5 秒内知道：**谁、在哪儿、在干什么**。三个信息一组合，画面就有了，悬念就有了，点进来的冲动就有了。

经验证案例：

| 书名 | 人物 | 地点/处境 | 动作/结果 |
|------|------|-----------|----------|
| 《退婚当天，我靠种田系统逆袭成首富》 | 我（主角） | 退婚当天（时间节点=冲突） | 靠种田系统逆袭成首富 |
| 《重生归来，我将渣男踩在脚下》 | 我（第一人称代入） | 重生归来（类型标签） | 将渣男踩在脚下（情绪爽点一步到位） |
| 《大一实习，你跑去749收容怪物》 | 你（第二人称对话读者） | 实习（大学生日常场景） | 跑去749收容怪物（身份与行为形成巨大反差） |

> **实操规则**：每轮生成书名候选前，先拿"人物+地点+动作"骨架套一遍——如果书名不满足至少两个要素，大概率信息密度不够，读者无法在 0.5 秒内判断"这本书讲什么"。

#### 三个万能变体

**变体一：身份反差 + 动作**

把主角放在一个"不应该做这件事"的处境里，反差越大，钩子越强。适用场景：主角是个普通人，做了件不普通的事。

> 示例：《全宗都是舔狗，小师妹是真狗》——小师妹的身份配上"真狗"的行为，读者立刻想知道她到底干了什么。

**变体二：数字/极端化 + 结果承诺**

用具体数字或极端表述给读者一个明确的爽感预期。适用场景：金手指文、系统文、升级流。

> 示例：《全县每人每天给我一块钱》——"全县每人每天"是频率和范围，"给我一块钱"是核心设定。读者看到书名就能脑补出"一块钱不起眼，但全县每人一块钱就恐怖了"的爽感。
> 示例：《时停起手，邪神也得给我跪下》——极端化典型，"邪神也得跪下"这个承诺直接拉满期待值。

**变体三：互动问答 + 精准痛点**

用一个反问句戳中目标读者的真实痛点。适用场景：系统文、都市文、职场文。

> 示例：《你欠债了吗，系统要我替万人还债》——反问句让读者产生"我有没有欠债"的自我审视，房贷车贷消费贷一联想，情绪共振就来了。

#### 书名公式 + 变体 使用流程

1. 先确定本作品的**核心卖点压缩句**（一句话讲清：谁 + 在什么处境 + 要干什么 + 结果有多爽/多惨）
2. 用**核心骨架"人物+地点+动作"** 套一遍，确保三个要素中至少有两个在书名中显性呈现
3. 根据题材特征选择一个变体方向：
   - 身份反差方向 → 变体一
   - 强力金手指 / 极端数值方向 → 变体二
   - 与读者生活痛点共鸣方向 → 变体三
4. 套用变体后做一次"0.5 秒测试"——给一个不看网络小说的人看 0.5 秒，问"这本书讲了什么"。如果对方能准确说出核心卖点，公式有效；如果对方说"不知道"，公式失效，需要重构。

> **重要警告：公式不是填空题。** 把"人物+地点+动作"套上骨架、挑一个变体、填几组词进去——做完了不代表得到了一个好书名。公式只是帮你**确保信息密度及格**的工具，不是"填完就能赢"的自动化流水线。同一个骨架和变体，填不同的词、调整语序和情绪，点击率可能差 40%（番茄官方数据）。真正的书名好坏取决于词的选择、情绪的浓度、反差的强度以及与竞对书名拉开区隔的能力——这些都需要竞对分析+多版本对比+用户反馈，不是填空能解决的。

### 书名反文艺病原则（新增——2026 知乎专栏吸收）

> **来源**：同上文。证据充分性：充分；置信度：高。

**书名是筛选工具，不是文学表达。它的任务是用目标读者听得懂的话，告诉他们这本书值不值得点。**

很多新手作者对"美"有执念——"云与梦""余生安好""彼岸花开""岁月静好"。这些书名在作者的审美里是高级的，但在读者眼里只有一个意思："不知道在讲什么。"

更严重的是，系统也不知道该把它推给谁。没有关键词，算法无法打标签，推荐效率极低。

**"文艺可以，但要在'读者能看懂'的前提下文艺。"** 起点编辑反复强调的同一原则：书名不能"云里雾里"，必须突出题材和亮点。

#### 书名文艺病快速检测法

| 危险信号 | 说明 | 修正方向 |
|---------|------|---------|
| 书名去掉后不看正文就完全猜不到题材 | 文艺度过高，归类成本太高 | 加入一个题材关键词或核心设定词 |
| 书名是一句完整的抒情短句 | 太像散文标题 | 换回"人物+地点+动作"骨架 |
| 书名只有意象没有人物 | 缺乏代入入口 | 加入人称/身份词 |
| 书名读起来像古风诗词标题 | 起点编辑铁定打回 | 检查是否包含可识别的通俗词 |
| 书名读了三遍还记不住 | 太绕太抽象 | 控制在 6-10 字内，降低认知负荷 |

### 书名黄金三原则（新增——2026 知乎专栏吸收）

> **来源**：同上文《不会给小说起名？这个公式让你分分钟写出读者喜欢的爆款书名》。证据充分性：充分；置信度：高。

在核心骨架和变体之外，以下三条原则是**独立的通用检查口径**——不依赖于特定公式，任何书名候选都应逐一过检。

#### 原则一：动词前置，而不是名词堆砌

同样一个故事，换个写法点击率天差地别：

- ❌ 《修仙游戏说明书》（静态，不知道是什么东西）
- ✅ 《修仙游戏反馈？我氪金十亿！》（动态，直接看出金手指和爽感）

**动词语书名自带节奏感**，读者看到"重生归来""开局""退婚当天"这些词，手指就开始往屏幕上移了。

> **实操规则**：书名候选生成后，逐条检查"前 3 个汉字中是否包含动词或动作暗示"。如果前 3 字全是名词、修饰词或无实意词（"在一个""很久""那天""关于"），则**强制淘汰**，重新设计。

#### 原则二：前三个字必须有钩子（跨平台通用）

**所有平台的书名在推荐页/搜索结果/书架列表中都存在"显示截断"风险**——即使平台推荐长度不同，读者的阅读习惯都是"先扫前几个字再决定是否细看"。如果前三个字是"在一个""很久""那天"——读者连看都看不清你的卖点就划走了。

**强冲突前置**：前 3 个字必须抛出矛盾或悬念，无论目标平台是什么。这是注意力经济在书名层的底层规律，不受平台差异影响。

跨平台已验证的强前缀模式：
| 前置模式 | 示例 | 钩子类型 |
|---------|------|---------|
| 时停起手… | 《时停起手，邪神也得给我跪下》 | 设定+极端承诺 |
| 退婚当天… | 《退婚当天，我靠种田系统逆袭成首富》 | 时间节点+冲突 |
| 开局长生… | — | 开局设定+成长预期 |
| 重生归来… | 《重生归来，我将渣男踩在脚下》 | 类型标签+行动 |
| 大一实习… | 《大一实习，你跑去749收容怪物》 | 身份+反差 |

> **实操规则**：每个书名候选生成后，先遮住前 3 字之后的全部内容，只读前 3 字——如果仅凭前 3 字无法产生"想点开"的冲动，说明钩子位置不对或前置力不足，必须调整。

#### 原则三：在截断风险线内，优先保证信息量和钩子强度，而非追求字数短

平台字数限制只有"截断风险"这一个技术含义——超过限制标题会被截断，核心信息可能丢失。**但在截断风险线以内，更长的标题如果信息密度更高、钩子更强、更能吸引点击，就应该选更长的版本。** 不存在"越短越好"这种质量标准。

不同平台有各自的显示截断点（详见"平台标题字数限制与显示规则"表），但读者的决策逻辑是：**同一屏里，哪个标题能让我最短时间内判断"这书和我有关"并产生点开冲动，我就点哪个。** 如果一个 6 字书名需要 2 秒才能看懂在讲什么，而一个 18 字书名 0.5 秒就传递了完整卖点和钩子——18 字的就是更好的书名。

以番茄信息流为例，16–22 字是信息量与显示完整度最佳平衡的黄金长度，不是因为"这个字数短"，而是因为在这个范围内能把"人物+处境+动作"三个要素完整呈现：
- 《你欠债了吗，系统要我替万人还债》——正好 16 字，信息密度高、互动感强
- 《退婚当天，我靠种田系统逆袭成首富》——18 字，核心三要素完整

> **实操规则**：书名写到超过截断风险线时，检查核心信息是否在前 N 字内已经完整传递。如果是，可以保留；如果不是，把核心信息提前，而非删减信息量。**字数只有参考价值，没有否决权。**

### 起名自检清单（新增——2026 知乎专栏吸收）

> **来源**：同上文。证据充分性：充分；置信度：高。

在最终确定书名之前，用以下六条逐条过检**每条书名候选**。其中任一条未通过，该候选应降级或淘汰：

1. **0.5 秒归类检测**：我的书名能在 0.5 秒内让读者知道这本书讲什么吗？如果不能，太文艺了，重改。
2. **热词/关键词可识别检测**：我的书名里有读者能看懂的热词或题材关键词吗？（重生、系统、末世、总裁、闪婚……）没有的话，系统不知道推给谁。
3. **承诺匹配检测**：书名和内容匹配吗？女频虐文用甜宠书名骗进来→读者秒退+举报，首秀直接废。书名承诺必须与正文前 300 字的读者体验一致。
4. **动词检测**：我的书名有动词吗？静态书名很难吸量，动态书名自带点击冲动。
5. **安利测试**：我能用一句话跟朋友安利我的书名吗？如果一句话说不清楚这本书的核心吸引力，说明书名没写到位。
6. **点击 > 字数检测**：我的书名是否为了"短"而牺牲了信息量或吸引力？如果短了反而让读者不知道在讲什么，还不如适度拉长把核心卖点说清楚。字数限制是技术约束，不是质量标准。

> **实操集成**：本清单与 `书名评分与排序规则.md` 的 Rubric 评分互补——自检清单用于**入围筛选**（不通过直接淘汰），Rubric 用于**入围后排序**（区分候选的优劣等级）。

### 书名的 AI 搜索可见性评估维度（新增）

| 指标 | 优秀（+2） | 合格（+1） | 不合格（0） |
|------|-----------|-----------|-----------|
| 题材关键词显性度 | 书名明确包含题材/类型词 | 书名暗示但不直接包含 | 书名完全不揭示题材 |
| 语义匹配能力 | AI 在 0.1 秒内可完成题材归类 | 需结合简介判断 | 书名模糊，AI 归类困难 |
| 跨平台一致性 | 所有平台信息完全一致 | 主书名一致，副标题有差异 | 不同平台信息不一致 |
| 认知缺口可匹配性 | 书名悬念在 AI 语义检索中有高辨识度 | 有一定辨识度 | 常见词组合，AI 易混淆 |

**实操规则**：每个书名候选交付前，用 AI 搜索模拟——随机问 3 个 AI（如 DeepSeek、豆包、Kimi）"推荐一本XX题材的小说"，看你的书名是否出现在回答中（通常以"《XXX》是一部___小说"的形式）。如果 3 个 AI 都未提及，说明书名在 AI 语义检索中的可见性不足，需要优化题材关键词的显性度。

> 详细评分表见 `references/GEO标题优化规则.md` 的"AI 搜索可见性评估维度"章节。GEO 基础原理见 `../../写作研究/GEO小说项目核心参考.md`。

- 每个候选都要有排序依据；若未进入 shortlist，可补 1 句降级理由，不能只给直觉判断。

- 命中分层命名时，至少交付 1 张“分层命名表”：
   - 总书名（候选 + 头号推荐）

- **批量章标题交付时须注明各章标题采用的策略类型（承诺回报/追问/反常/金句/意象/简明推进），以确认策略轮换**

4. 各平台候选总表（"各平台"仅指 `Agents.md` 已注册的平台；含 Rubric 总分、分项、入围判断与一句话依据）
5. 每个平台头号推荐与选择理由分析
6. shortlist 与推荐结论
7. Rubric 总表与排序说明
8. 跨平台全局去重记录
9. 内部淘汰复盘（如有）
10. 自检清单与写回信息

不要只保留一张候选表；模板必须同时体现评分、取舍、推荐理由、降级理由和最终决策收窄结果。

## 默认输出口径

- **模式 A（独立输出）**：默认输出一组可比较的书名候选，并附排序依据与降级说明。多平台场景下，默认按平台分组给候选与头号推荐，但只输出在 `Agents.md` 中已注册的平台对应的分组，未注册的平台不显示。
- **模式 B（嵌入式轻量）**：只输出一个最优标题 + 一句话理由（不超过 20 字）。不生成候选表，不落盘单独文件，不跑完整 Rubric 评分。

## 硬规则

- 禁止把书名写成简介句、广告语、口号、推文标题或章节标题。
- 禁止一个标题硬塞多个卖点，导致主轴失焦。
- 禁止只靠热门词拼接，造成撞名、廉价感或误导。
- 禁止平台适配时只做换词换标点，不真正更换命名形态。
- 禁止标题承诺与正文实际卖点不匹配，也不得凭空发明材料里没有的核心设定、关系或规则。
- **禁止书名只做"题材归类"而不做"卖点承诺"**：如果读者看完书名只能在"玄幻/悬疑/言情"的大类里定位，却说不出"这本书具体有什么不一样的"，说明标题只完成了归类职能而未完成卖点展示。好书名应在归类的同时给出一个"别人没有的承诺"。
- **禁止以"短"为美、以字数论英雄**：书名的核心指标是"能吸引潜在读者点进来"，不是"短"。一个短书名如果信息密度够、钩子强、读者一看就想点，当然好；但为了短而牺牲信息量、让读者 0.5 秒内无法判断"这本书讲什么"，就是本末倒置。**字数只有参考价值，没有否决权——该长就长，能短则短，核心判据永远是点击吸引力，不是字数。** 平台字数限制是"截断风险"的技术约束，不是"越短越好"的质量标准。
- **禁止标题字数超过目标平台的截断风险线**（详见"平台标题字数限制与显示规则"表）。超出截断风险线的标题核心信息会被隐藏，等同于让读者看半句话。
- 默认要求跨平台头号推荐彼此拉开区隔，不能只是同一母核的轻微改写。
- 正式交付的候选列表默认只保留推荐标题；已被淘汰的内部草案不得混入候选表凑数。
- 分层命名任务中，禁止"层级失配"：
   - 分卷名不得写成章节小标题
   - 分部名不得退化成剧情梗概句
   - 总书名不得窄化到某一卷的局部事件
   - **章节名不得写成章内容摘要或章号别名（新增）**
- **禁止书名承诺与正文卖点脱节**：书名所承诺的核心卖点（题材、情绪回报、冲突类型），必须在正文前 300 字内让读者可感知。读者点开正文后，如果读完前三段还看不出"这和书名说的是一回事"，就会产生期待落差 → 快速流失。来源：`写作技法_黄金三章与黄金一章含金量提升研究.md`§2.2 "'展示卖点'优先于所有技巧"、作家助手·夜宵"开篇的唯一任务：展示卖点"。**自检方法**：写完开篇后回头对照书名——不开目录页，只看书名→读前 300 字，感受是否"合得上"。如果开篇换什么书名读起来都差不多，说明书名承诺未在正文落地。
- **前三章章标题递进约束（新增——2026 深度研究整合）**：黄金三章中的章节标题应遵循递进逻辑，与各章钩子职责匹配：
   - 第一章章标题：制造**认知缺口**——让读者看完标题就产生"什么意思/为什么/然后呢"的追问，不得直接揭示本章完的结局
   - 第二章章标题：暗示**局势升级或反转**——让读者感受到"问题更严重了/方向变了"，不得重复第一章的命名策略
   - 第三章章标题：预告**首次小闭环或新谜面浮现**——让读者期待第一次小高潮，同时暗示更大的谜团尚未展开
   - 三章标题不得使用同一策略；必须按"认知缺口→升级/反转→小闭环+新谜面"递进，或经论证的等效递进路径
- 分层命名任务中，禁止"体系内重名"：同一作品内分部名不可重复；分卷名需避免与其他卷名高度同构（仅换一两个字不算有效区分）。
- **跨平台全局去重（阻断级，禁止违反）**：所有平台候选合并为一个全局池，池内任意两个标题不得完全相同。m 个平台 × 每平台 n 个候选，最终交付的书名总数必须严格等于 m × n 个互不重复的书名。若发现重复，必须在输出前替换，不得以"同一标题标注不同平台"的方式保留重复项。
- **禁止为未注册平台输出书名候选（阻断级）**：任何未被 `Agents.md` 注册的平台，不得出现在交付结果中。若 `Agents.md` 不存在或未声明任何平台，则只输出不区分平台的通用书名候选，跳过所有平台适配步骤。

## 与其他 Skill / Prompt 的边界

- 本 Skill 负责全层级标题系统的设计、排序与筛选——包括书名、分部名、分卷名与章节名。
- 不负责简介撰写、封面提示词或投稿材料整体组包。
- **章节标题设计由本 Skill 承接，但批量设计章标题时必须读取各章章纲/控制卡；不得只凭卷纲批量生成空洞标题。**
