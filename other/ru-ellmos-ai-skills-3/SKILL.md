# Анализ требований к документации (Русский)

> Анализирует все документы концепций и требований, проверяет их требования на соответствие текущему коду и создает консолидированный отчет об отклонениях.

---

## Обзор и назначение

Анализирует все документы концепций и требований в папке ../docs/, проверяет их требования на соответствие текущему коду и создает консолидированный отчет об отклонениях.

---

## Соглашение об именовании

### Префикс и суффикс
Все проанализированные документы получают:
- **Префикс:** `conN_`, где N = версия анализа (1, 2, 3, ...)
- **Суффикс:** `_XX`, где XX = процент выполнения (округленный до ближайших 10)

### Порог архивации
- **>= 75% выполнено:** Документ перемещается в `../docs/_archive/`
- **< 75% выполнено:** Документ остается в `../docs/` с префиксом/суффиксом
- **Порог настраивается** (по умолчанию: 75)

---

## Процесс

### Фаза 1: Сбор документов
- Получить список всех файлов *.md и *.txt в ../docs/ (корень)
- Исключить README.txt

### Фаза 2: Извлечение требований
Для каждого документа:
- Прочитать содержимое
- Определить требования (контрольные списки, таблицы, маркеры MISSING/TODO)
- Категоризировать: Structure, Code, API, DB Schema, CLI, Feature

### Фаза 3: Проверка кода
Для каждого требования:
- Определить метод проверки (Glob, Grep, Read)
- Выполнить проверку
- Отметить как: FULFILLED, PARTIAL, MISSING

### Фаза 4: Оценка
- Подсчитать количество выполненных и открытых требований
- Рассчитать процент выполнения (%)
- Принять решение: архивировать (>= 75%) или оставить (< 75%)

### Фаза 5: Генерация результатов
- Создать REQUIREMENTS_ANALYSIS.md (сводка)
- Создать consense_diff.md (только открытые требования, по приоритету)

### Фаза 6: Версионирование
- Поиск наибольшего префикса conN_
- Новая версия = наибольшая + 1

### Фаза 7: Переименование и перемещение
- Применить новый префикс/суффикс к документам
- Архивировать или оставить

---

## Результаты

| Файл | Описание |
|------|----------|
| `conN_REQUIREMENTS_ANALYSIS.md` | Полный анализ (версия N) |
| `consense_diff_N.md` | Консолидированные открытые требования |
| `_archive/conN_*_XX.*` | Архивированные (>=75%) документы |

---

## Классификация приоритетов

| Приоритет | Критерии |
|:---------:|----------|
| P1 | Отсутствует основная функциональность, система непригодна к использованию |
| P2 | Отсутствует важная функция, возможен обходной путь |
| P3 | Желательно, улучшает UX |
| P4 | Косметические изменения, документация, качество кода |
