# 证据型深度研究

产出其他分析师可以复核的答案。优化目标是决策价值、来源质量和新增信息量，而不是链接数量。

## 界定研究问题

- 明确要支持的决策或问题、范围、司法辖区和截至日期。
- 将宽泛问题拆成 3–6 个子问题，并指出哪些关键主张会改变最终结论。
- 请求已清晰时采用合理默认值；只有缺失选项会实质改变结果时才追问。

## 工具与来源路由

使用浏览器前，先检查是否有适合该语义操作的专用连接器、本地资料、API 或 CLI。只使用真实可用的工具，不猜测接口或命令。

证据优先级：

1. **一手来源**：监管/政府记录、交易所与公司公告、标准、法院记录、原始数据集、源代码和原始研究。
2. **第一方辅助材料**：投资者关系页面、技术文档、业绩会和官方公告。
3. **方法透明的独立二手分析**。
4. **聚合站、新闻摘要、博客、论坛和社交媒体**：只作为线索或情绪证据，不作为权威底稿。

重要主张优先使用“一份一手来源 + 一份独立交叉验证”。只有单一来源时，必须标为未充分验证。

## 渐进式检索

1. 建立小型查询组合：精确术语、同义词/缩写、必要的中英文变体、时间限制词和反证查询。
2. 先扫标题、摘要、元数据和目录；去掉镜像、转载和引用同一上游材料的重复来源。
3. 只深读最可能决定结论的 3–5 个来源。证据冲突或关键缺口仍存在时再扩展。
4. 对每个有效来源记录：标题、发布者、日期、URL/文件位置、相关章节或页码、支持的主张和局限。
5. 评估缺口后调整查询。除非用户明确要求穷尽搜索，否则最多进行三轮检索细化。

当新增来源主要重复已知事实、关键主张证据充分、冲突已解决或已界定、剩余不确定性不会改变决策时停止。不得用无止境搜索掩盖信息缺口。

## 先分析，再综合

- 区分有来源的事实、计算、推断、预测和观点。
- 比较前先统一日期、单位、口径、合并/单体报表基础和修订版本。
- 执行时效门：确认最新纳入期间，并搜索此后可能推翻结论的事件。
- 主动寻找最强可信反证，说明它是否改变结论。
- 按来源层级、直接性、交叉一致性、时效性和方法透明度，将证据评为高/中/低。
- 不得把“没有找到证据”直接当成“证据证明不存在”。

## 面向决策的输出

先给结论和置信度，再给：

- 真正决定结论的少数发现；
- 紧邻每项重要主张的证据与引用；
- 矛盾、未知项和假设；
- 最有力的替代解释；
- 哪些未来证据会确认或证伪结论；
- 对重要研究附简洁来源表和方法说明。

只有重复字段比较时才用表格。仅在用户要求持久成果，或内容无法在对话中清楚呈现时，才把完整报告或证据账本保存到文件。

## 财务任务路由

- 上市公司基本面、盈利质量、治理、估值、财务取证或 IPO：使用 `stock-analysis`，本技能负责获取和交叉核验最新一手文件。
- 企业内部 FP&A、比率、DCF、预测和预算差异：使用 `financial-analyst`。
- 不混用期间、单位、币种和报表口径。每个财务数字都要有来源和期间；现价与市值必须标注时间点。

## Token 与记忆纪律

- 先取元数据和关键片段，再读全文；避免加载重复页面或整个仓库。
- 每深读一个来源，先压缩成“主张—证据—局限”，再打开下一个。
- 后续阶段携带紧凑证据账本，而不是原始浏览输出。
- 只加载当前模式需要的参考资料，不重复已经准确记录的来源内容。
- 时效性事实应带失效概念。只有用户要求或它属于稳定项目规则时才持久化：偏好进 Codex Memories，仓库规则进 `AGENTS.md`，治理知识进项目文档。
- 不把密钥、凭据、敏感财务数据或未验证主张写入记忆。

## 失败边界

访问受阻、付费墙限制、数据过期或缺少一手资料时，不宣称覆盖完整。说明缺口、对结论的可能影响，以及下一步需要的具体文件或权限。
