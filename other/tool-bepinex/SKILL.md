# BepInEx Unity/.NET 插件加载与运行框架 技能卡

## 基本信息

- **中文名称**：BepInEx Unity/.NET 插件加载与运行框架
- **来源仓库**：[BepInEx/BepInEx](https://github.com/BepInEx/BepInEx)
- **上游参考分支**：`master`
- **参考提交（使用前核对）**：`5b766a3b7f6c164d4798924a93f3acf4db769d06`
- **许可证线索**：LGPL-2.1（仓库还含运行时/第三方组件条款）；文件：`源码\LICENSE`

## 功能概览

1. 通过预加载器建立托管插件启动入口和生命周期
2. 为插件提供配置、日志、依赖加载和平台运行时适配
3. 可承载 Unity Mono/IL2CPP 项目的托管扩展，但具体后端能力取决于目标运行时

## 适用范围

- 用于 Unity 项目的插件装载、配置分发、日志接入和托管层功能宿主。

## 不能替代的边界

- 不是 IL2CPP 元数据恢复器、通用 native Hook、线程调度器或游戏服务器协议客户端；加载插件不证明目标函数可调用，也不负责闪退恢复、对局成功或反检测。

## 输入与输出合同

```text
输入：目标游戏运行时类型与版本、插件程序集/入口、配置文件、依赖清单和日志路径。
输出：预加载/插件加载日志、插件生命周期回调、配置快照和运行时错误记录。
失败：版本不兼容、依赖缺失、预加载失败、程序集异常或权限问题时必须停止插件链并保存日志。
后置：输出必须绑定项目、目标版本、平台/ABI（如适用）、时间戳和证据路径。
```

## 接入原则

1. 核对实际源码版本与说明中的参考提交后，先做最小、可撤销、可回放的接入。
2. 任何地址、线程、设备、模型、资源或协议输入都必须记录来源、版本和后置状态。
3. 工具输出是候选或观测，必须与项目专项规则、状态机和真实成功证据交叉验证。
4. 失败时保留原始错误和现场证据，不把命令退出码、识别命中或 Hook 安装当作业务成功。
5. 可与 IL2CPP 运行时桥接、Dobby/ShadowHook 组合，但边界仍由项目专项规则和版本门禁决定；不能替换底层 Hook 或函数 ABI 适配。

## 与 Codex 项目路由的边界

- `l-gameassist`：负责游戏目标、进程/设备连接和现场任务编排；本技能只提供本卡标注的工具能力，不能扩展为未登记的内存、Hook、协议或输入能力。
- `l-reverse`：负责逆向/静态或运行时证据路由；本技能的输出必须按目标版本、模块、ABI 和现场回读复核，不能把候选分析直接当作成功结论。
- `l-dev`：负责构建、依赖、配置、部署、回滚和服务维护；本技能不替代发布门禁，未完成依赖、许可证、异常恢复和回滚检查时不得发布。
