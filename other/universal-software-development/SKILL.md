# Маршрутизация разработки

Используй этот навык только для выбора процесса. После выбора одного основного исполнителя не запускай несколько конкурирующих общих циклов разработки.

## Входы и масштаб

Из запроса и проекта определи результат, режим (создание, изменение, диагностика, проверка, релиз), платформы и критерии готовности. Прочитай применимые AGENTS.md, manifests, тесты и состояние Git. Уточняй только неизвестные, которые меняют поведение, интерфейсы, данные или разрешённые действия.

Для небольшой правки достаточно локального изменения и соответствующей проверки. Для обычной функции нужен сквозной рабочий сценарий. Для миграций, конкурентности, секретов и внешних изменений заранее определи сценарии отказа и восстановления. Не вводи полный релизный процесс для одноразового скрипта.

## Выбор основного процесса

- Реализация: если доступен `codex-engineering-guardrails:code-work`, используй его как единственный общий инженерный процесс.
- Ревью и диагностика без исправлений: доступный `codex-engineering-guardrails:code-verification`.
- Боты, парсеры, фоновые задачи, автоматизация ОС: `developer-automation` добавляет предметные правила к выбранному процессу.
- Контракты API, webhook, повторная доставка: `api-integration-engineering`.
- Схемы, преобразование данных и миграции: `data-migration-engineering`.
- C++ и переносимая сборка: `cpp-cross-platform-engineering`.
- UI, Apple-платформы, документы и безопасность: используй существующий профильный навык, только когда он нужен результату.

Проверяй наличие навыка в текущей среде; названия здесь не означают, что он установлен. Не читай все перечисленные навыки заранее.

## Если профильный процесс недоступен

1. Зафиксируй наблюдаемый результат и область изменения.
2. Найди существующие соглашения и сохрани чужие изменения.
3. Для дефекта воспроизведи причину; реализуй минимальное цельное изменение.
4. Проверь требуемое поведение подходящими тестами, сборкой или воспроизводимым запуском.
5. Сообщи результат, доказательства и непроверенные части.

## Границы

Уважай уже данное разрешение пользователя; не запрашивай его повторно для той же операции. Подготовка к релизу сама по себе не разрешает публикацию. Не выводи разрешение на отправку сообщений, удаление данных, merge или изменение живых систем из технической возможности инструмента. Ограничения среды соблюдаются независимо от разрешения задачи.

Типизация Python охватывает все функции и методы. Комментарии объясняют причины решений, алгоритмы и платформенные вызовы. Секреты находятся вне кода и логов. Готовность определяется проверенным поведением; отсутствие нужной среды обозначай явно.
