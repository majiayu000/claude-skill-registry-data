# 花叔CAD

目标用户懂自己的CAD业务，不熟悉编程agent。

## 先确定交付

读项目中的原图、模板、需求和相关经验。运行`scripts/cad_io.py doctor`探测当前Python的可用后端。缺依赖、跨系统或字体不匹配时读`references/environment.md`，在用户项目建立隔离环境。

- 有原图：先读取实体、图层、文字、单位、布局和引用，保存输入哈希。只在副本修改，用户未要求的对象保留。
- 新建图：从用户需求确定单位、坐标、几何、图层、标注和交付格式。尺寸缺失且影响结果时问清楚；用户要求演示时可以列出明确假设。
- 规则清楚的批量任务：将数据作为输入，生成可复用脚本，每个变体单独保存并列出来源行。
- 从户型图片/PDF复刻，或在户型上继续布局、点位、铺装与跨楼层改图：先读`references/floorplans.md`。保留原参考、尺度依据与不确定性；视觉线稿和可用空间语义分别验收。
- 先看原生CAD命令、现有脚本或模板能否完成；已有办法合适就复用。

与用户谈尺寸、对象和结果；Python、LISP、依赖安装由agent处理。需要用户手动加载时给具体操作和成功标志。

## 选择执行路线

- 二维DXF：用`ezdxf`读写真实LINE/ARC/CIRCLE/LWPOLYLINE/TEXT/MTEXT/DIMENSION/INSERT等实体。官方接口见 https://ezdxf.readthedocs.io/ 。
- 参数化零件：用`build123d`生成实体，保留Python参数源，导出STEP；STL只作为网格副产物。阅读`references/geometry.md`。
- 机械装配（齿轮、减速器、电机关节、带轴承紧固件的回转件）或要爆炸图、剖视、运转动画、装配工程图：读`references/mechanical.md`，用`scripts/mech/`登记装配、跑验证、出网页/图/视频；`examples/planetary_reducer.py`只示范用法，新任务按需求重新设计。
- DWG或用户指定CAD原生格式：先检测原生应用、API或已有转换器。没有就如实说明支持边界，不能把DXF改扩展名交付。转换后要重新验证复杂对象与布局。
- GUI用于已有接口无法覆盖的步骤和原生应用验收，不把鼠标逐点点击作为默认绘图办法。

## 制图与修改

1. 列出具体要改的对象与边界。复用输入图中的标准；新图按角色建立图层，命名让用户能看懂。
2. 按实际几何绘制，保持1:1模型单位。DWG/DXF文件单位与数值一致；米制表格转毫米时明确转换一次。
3. 尺寸使用原生DIMENSION并渲染其显示块；尺寸值从几何取得。新建1:1毫米图时显式设置显示倍率DIMLFAC=1。改旧图先读原倍率、用户要求的显示单位和文字覆盖值，可能有合理的毫米→米倍率0.001；不要全局重置共享样式。必要调整仅针对被修改尺寸。重复符号用BLOCK/INSERT，需要编号和用途时用ATTRIB。
4. 中文文字选机器上可用的字体，缺失时报告。文字与尺寸不要压住关键几何；图框、图名、比例和单位按任务要求补齐。
5. 修改已有图时同步相关几何、尺寸和属性，保持不相关图层与对象。保存原件和可回退的输出，失败不覆盖已验收结果。

## 必须完成的验证

执行`scripts/cad_io.py inspect 输出文件 --out 检查.json`。它只报告文件结构，不替代任务验收。

- 回读落盘文件，与用户需求逐项核对：尺寸、孔径、位置、数量、长度、面积以及交付格式。尺寸分别核对真实几何、DIMLFAC和实际显示块文字；`get_measurement()`正确不能证明图面数值正确，纯文字覆盖也可能伪装尺寸。
- 改图对比前后，确认作用范围外的对象仍在；不能只改尺寸文字来假装改变几何。
- 用`scripts/cad_io.py render 输出.dxf --out 预览.png`生成预览并自己打开检查。几何正确与图面清楚分别判定。远处保留对象导致主图太小时，保留全图并用`--layers 图层名…`或`--bbox xmin ymin xmax ymax`补局部预览；交付时把可读详图设为阅读入口，不移动或删掉远处对象。
- 有目标CAD环境时重新打开文件验证，并读导入器警告、核对关键对象与属性。能打开不代表保真；出现unsupported entity、属性或编号缺失时标为兼容性未通过，保留原文件，不用炸开全部图块来冒充无损支持。没有目标CAD时注明仅通过解析/几何/预览检查，不宣称通过AutoCAD实测。
- 失败先读真实报错，按环境、文件格式、几何、文字/显示定位；同一错误两次无进展就换有依据的路线。修复前用`scripts/cad_io.py preserve 失败文件 --out 证据目录`保留有问题的CAD和预览，再修改；已经覆盖的旧文件如实记为未保留，不重造后冒充首次输出。

交付可编辑文件、必要预览、可重跑的参数源和简短修改说明。写清实际检查与未验证事项，不给没有测量依据的成功率或节省时长。

## 经验如何进化

开工按任务读取`references/experience.md`中相关条目；记录与现场冲突时以现场为准。

结束后，只回流有证据且下次能复用的新知识。保存日期、后端/版本、场景、问题、修复、验证路径和状态；证据留任务目录，经验引用它。先纠正失效结论，再加新条目。用户明确偏好与一次代选分开。

单次观察留场景经验，至少两个独立任务重现且边界清楚再升级稳定流程。能变成确定执行和检查的先改脚本并复测。改动技能前存可恢复版本，独立任务验证，退步就恢复；没有新发现不硬写经验。客户图纸和私有模板不进入公共经验。

## 版本检查

这一节让用户及时知道本 skill 有没有新版本。它只读取远程仓库的版本标签，不下载文件、不上传数据、不修改 skill 本身；唯一会写的是本目录的 `.last-update-check`，用来记住上次检查的日期。

使用本 skill 时先读 `.last-update-check`，内容是一行日期加结果，如 `2026-10-13 ok`（只有日期的旧格式按 `ok` 算）。以下情况跳过本节：内容是 `off`（用户关掉了检查）；上次 `ok` 不足 30 天；上次 `failed` 不足 7 天；本目录不是 git 克隆。

到期时运行 `git -C <本目录> ls-remote --tags --refs --sort=-v:refname origin 'v*'`：

- 成功：第一行就是最新版本，和本文件开头的 `metadata.version` 比较，然后写入 `<今天> ok`。远程更高时，先完成用户的任务，结束时告诉用户：「huashu-cad 有新版本 vX.Y.Z，更新说明见 https://github.com/alchaincyf/huashu-cad/releases ，需要时运行 `git -C <本目录> pull --ff-only`；不想再收到提醒，把 `.last-update-check` 的内容改成 `off`」。版本相同或没有标签就不用提。
- 失败（断网、沙箱不允许联网）：写入 `<今天> failed`，7 天后再试。

是否更新由用户决定，不要自动执行更新。
