# pre-mortem-technique

## When to Use

在启动高风险项目或重要决策前，需要预先识别潜在失败点以增强心理韧性和方案鲁棒性时description

## Core Logic

# 执行步骤

1.  **明确目标与假设**
    *   **输入**: 待评估的项目目标或决策方案。
    *   **操作**: 清晰陈述项目预期达成的目标，并列出支撑该方案成功的关键假设。
    *   **判断标准**: 目标陈述具体、可衡量；关键假设被完整列出，无重大遗漏。
    *   **输出**: 一份包含明确目标和关键假设的文档。

2.  **心理时间旅行至未来失败点**
    *   **输入**: 步骤1输出的目标与假设文档。
    *   **操作**: 假设一个未来时间点（例如，项目启动后6个月或1年），并**强制想象项目已彻底失败**。在脑海中生动构建失败后的场景。
    *   **判断标准**: 能够清晰、具体地描述失败后的状态和后果，产生真实的情绪感受（如沮丧、失望）。
    *   **输出**: 一个关于项目失败的生动心理场景。

3.  **逆向归因分析**
    *   **输入**: 步骤2构建的失败心理场景。
    *   **操作**: 以“这个失败是如何发生的？”为起点，进行逆向思考，列出所有可能导致这一失败结果的原因。重点关注步骤1中列出的关键假设是如何被推翻的。
    *   **判断标准**: 列出的原因覆盖内部（如执行不力、计划不周）和外部（如市场变化、竞争加剧）因素；原因具体，而非泛泛而谈。
    *   **输出**: 一份可能导致项目失败的潜在原因清单。

4.  **制定风险缓解与预案**
    *   **输入**: 步骤3输出的潜在失败原因清单。
    *   **操作**: 针对清单中的每一个主要原因，制定至少一项预防性措施（如何避免该原因发生）或一项应对性预案（如果该原因发生，如何应对）。
    *   **判断标准**: 每项措施或预案都具有可操作性；针对高风险原因制定了强力的缓解策略。
    *   **输出**: 一份与失败原因对应的风险缓解与应对计划。

5.  **整合反馈与方案调整**
    *   **输入**: 步骤4输出的风险缓解计划。
    *   **操作**: 将风险缓解计划中的关键措施整合回原始的项目方案或决策中。这可能包括调整计划、增加资源、设定新的检查点或修改目标。
    *   **判断标准**: 原始方案得到了实质性修订，以纳入从预演失败中获得的洞见。
    *   **输出**: 一个经过加固、对潜在失败更具韧性的更新版项目方案或决策。

# 输出格式要求
向用户呈现一份结构化的《事前验尸分析报告》，包含以下部分：
1.  **项目/决策目标**：[复述用户目标]
2.  **模拟失败场景**：[描述步骤2中构建的失败画面]
3.  **关键失败原因**：[列出步骤3分析出的主要原因]
4.  **风险缓解策略**：[对应每个原因，给出步骤4制定的措施]
5.  **方案调整建议**：[总结步骤5中对原方案的核心修改建议]
