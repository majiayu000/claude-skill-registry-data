# 技能侦察兵

需要选型时的默认流程：任务 → 必要澄清 → 编号推荐 → 用户选择 → 工作流与技能用法 → 确认执行。已满足的环节直接复用，不要求用户重复回答、选择或确认。

## 先判断是否需要选型

- 用户只要求查找、推荐或比较技能时，按实际范围给出候选，不扩展为产出或安装任务。
- 目标、输入和验收要求充分，通用能力或已有技能明确覆盖，且没有需要用户权衡的工具取舍时，直接完成。多段文字、多个步骤或耗时较长本身不构成启动完整流程的理由。
- 只有关键输入缺失，或技能选择会实质改变交付范围、质量要求、成本、依赖或外部影响时，才进入相应的澄清或选型环节。多个互相依赖的交付物须检查衔接；已知组合能够满足时，不为组合本身强制再选一遍。
- 缺少关键输入但无需选技能时，只问必要问题，回答后直接完成；风格等可逆细节可说明合理假设后推进。
- 用户明确要求先推荐、先看方案或先确认时，保留相应停顿；已有确认和授权覆盖当前动作时沿用，只对新增的实质变化询问。

## 三个例外

- 简单明确的任务直接完成，不强行提问、推荐技能或确认流程；用户明确要求选技能时仍按要求推荐。
- 需要选型的复杂任务走必要环节，只问关键问题。每个步骤或能力面默认推荐两到三个有实际差异的技能候选；只有一个合适时不凑数。候选总数可随复杂步骤数量增加。
- 用户明确说“你选，直接做”等时，可自主选型并跳过选择与工作流确认，在授权范围内直接执行。单说“你看着办”可决定常规细节，但不自动取消执行确认；安装及外部操作仍按实际授权处理。

## 1. 完善任务

先读上下文与可用材料，围绕交付物、使用对象、输入材料、约束等提出最多三个关键问题，给推荐选项并解释影响。等用户回答后再给正式推荐；可同时做不依赖回答的只读检查。

已有信息足够时不为流程凑问题；直接完成路径不先做技能推荐。用户说“你看着办”时采用合理假设，不追问常规细节。详见 [问询原则](references/question-gates.md)。

## 2. 检查能力与搜索

先检查当前会话技能清单、插件技能、可调用工具及用户指定的工作方式，再补查本地与项目技能目录。插件可能位于缓存或运行时目录，不能只扫描用户技能目录。

复合需求按可独立选择技能的能力面拆分；相关需求可合并搜索。已有技能能满足时直接纳入推荐，不必找外来技能。存在缺口再实时检索注册表或 GitHub；用户明确要外部候选时照其要求检索。不能用虚构名称、示例或摘要冒充已核实候选。详见 [环境与检索](references/environments.md)。

读主推技能的 SKILL.md、必要引用与依赖。比较匹配度、增量能力、成本、维护证据及中文交付能力；同领域不一刀切排除。区分描述筛选、正文检查与功能实测。详见 [候选评价](references/scoring.md)。

## 3. 编号推荐并等待选择

按步骤或能力面给一个主推与最多两个有实际差异的备选，每个技能名称前标序号。复杂步骤可组合多个互补技能，这些互补技能不能当作互斥备选。候选数量限制按步骤或能力面计算，不限制整个任务只能用三个技能。列明用途、推荐理由、来源、已安装或需安装状态、验证程度及关键限制。复合任务可说明推荐组合，序号保持唯一。

需要选择时让用户按编号选择，可多选、都不选或委托代选；已经选定或明确委托代选时跳过这一等待。不要把推荐等同于安装授权。默认用户选择后进入方案说明；若该组合的工作流、影响和验收方式已展示，用户同时明确同意按其执行，则直接执行，不再重复确认。详见 [输出方式](references/output-format.md)。

## 4. 总结工作流与技能如何使用

逐步检查复杂度：每个复杂步骤都可以推荐或复用一个或多个合适的技能；简单步骤使用通用能力即可，不为每一步强凑技能。标明技能之间的输入输出衔接、执行顺序，以及互补组合与可替换候选的区别。同一技能可服务多个步骤，无需重复安装。

根据用户选择给出可审阅的方案：每一步做什么、调用哪个技能或工具、输入是什么、输出是什么，以及最终交付物与验收方式。说明技能会实际参与哪些步骤，哪些由通用能力完成，不只罗列技能名。

如选择后细化工作流发现还需新增技能，在最终方案中补列其序号、理由与用法，让用户一并选择或确认；不能静默加入未授权的安装。执行中仅在新增技能改变已确认范围、依赖或外部影响时补充询问。

涉及安装时一并列出真实来源、目标目录、依赖、费用或账户需求和实际影响，使用户能在一次确认中决定是否安装并执行。

需要新增执行确认时询问“是否按此工作流执行？”，确认前只做需求完善、检索和必要的只读检查。直接完成路径、明确代选直做或已有确认覆盖的任务不追加这道停顿。用户只要求推荐时在推荐处结束。

## 5. 确认后执行

用户确认后，按方案完成必要安装、任务执行与验证，不逐步重复确认。用户明确说“跳过确认，直接安装并执行”等时，尊重其已有授权，不再机械停顿。若用户只要求比较、推荐或安装，按其实际范围结束，不扩展任务。

安装前检查入口脚本及调用资源、依赖和权限；不为试用运行未授权的第三方脚本。只复制目标技能及必要资源；不静默覆盖不同内容。明确更新时备份后更新。安装后检查格式与引用，不把格式通过说成实测成功，不保证会话热加载。

方案出现实质变化或新增未授权的外部发送、发布、费用、凭据使用时才补充询问。没有对口技能时说明替代方案，并在工作流确认后执行。同一任务后续沿用已确认方案，只有新增需求或用户要求时重新选技能。
