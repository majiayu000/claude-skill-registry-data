# model-first — 実装前にモデルを明示して固定する

> v0 (2026-06-23) 未検証 N=1。信頼する前に `empirical-prompt-tuning` で標準実行者に回す。
> 設計: [docs/design-model-first-and-restart.md](../../../docs/design-model-first-and-restart.md)

`$ARGUMENTS` のシステムを**実装し始める前に**、モデル（実体・不変条件・語彙）を明示して固定する。
この skill を呼んだ時点で、下の手順は standing 承認とみなしてよい（毎回の確認は不要）。

## なぜ（原則）

連鎖破綻の根は「AI が賢くない」ではなく、**相互依存するルール群を暗黙仕様のまま破綻なく維持するのが
苦手**という性質。ある状態値が別の正当値に silent に化けても気づけないのは、**その値の型・値域を
保証する不変条件が暗黙でどこにも明示されていない**から。

→ モデルを暗黙に保持せず、**artifact ＋実行可能な不変条件として外部化**する。これが機械化できる本体。
RED-first が bug の破れを先頭で loud にするのと同型で、model-first はモデルの破れを loud にする。

## いつ起動するか（自分の plan 側で判定）

- 多数の実体／ルール／状態が相互作用し、**局所の変更が全体に波及しうる**実装に着手しようとしている。
  代表: ゲーム / シミュレータ / スケジューラ / パーサ・エンコーダ / プロトコル / 多実体の状態機械。
- **除外**: 孤立した CRUD / typo / doc / 単一関数のユーティリティ / 既にモデルが明示・固定済み。

判別の勘所: 「『◯◯を作って』から実装を始めると容易に壊れるか？」が yes なら起動。

## 手順（先頭で固定する 6 段）

1. **モデル面の列挙** — 実体（ドメインのモノ）・状態変数・関与（actor）・操作を書き出す。
   「同時に交錯し合う要素」を漏れなく並べることが目的。種類が多い・変則条件が多いドメインほど、ここの抜けが後で連鎖する。
2. **不変条件の命名** — 常に成り立つべき横断制約を明文化する（例: 保存量が常に一定 ／
   ある値の型・値域が遷移で変わらない ／ 部分集合の和が全体に一致する）。
   **連鎖破綻はここが破れたときに起きる**。暗黙にせず、必ず文として書く。
3. **語彙の固定** — 1 概念 1 正式名。同義語を禁ずる（暗黙仕様 drift の根を断つ）。
4. **artifact として lock** — モデル（実体＋状態＋不変条件＋語彙）を**実装前に** doc／型／schema に書き、SSoT にする。
   置き場は対象 project 配下（例: `docs/model.md`・型定義・schema ファイル）。
   **不変条件は可能な限り実行可能な形（runtime assert／型／test）で encode** し、破れが silent でなく loud に出るようにする
   — これが状態が silent に化ける型の破綻への直接の解。
5. **先行実装の seed** — 正準実装／OSS があれば下敷きにする。発明の前に正準モデルを探す。
   外部事実が要るなら `web-research` を併用。
6. **lock 済みモデルに対して実装** — step2 の不変条件を実行ガードとして常時効かせながら生成する。
   以後の実装・修正は、この lock 済みモデルを SSoT として参照する。

## 出力（この skill の成果）

- lock した model artifact（実体・状態・不変条件・語彙）の在処を 1 行で示す。
- 不変条件のうち**実行可能な形で encode したもの**を列挙する（残りは「未 encode・暗黙のまま」と正直に明示）。

## 自己注意

- **不変条件を「列挙して満足」しない** — 可能なものは assert/型/test に落とす。文章だけの不変条件は
  silent 破綻を防げない（self-authored spec の罠の親戚）。
- モデルが既に明示・固定済みなら起動しない（冗長な再設計は過剰拡張）。
- 「完璧なモデルを最初に」ではなく「**連鎖する不変条件だけは先頭で loud に**」が眼目。
  局所で後から足せるものは後でよい。
