# decision-tool-selection — 判断・計算の道具を作る前に、問題の形から手法を選ぶ

モデルは手法の系統を知っていても、作る瞬間に問題の形を問われなければ使わない。
同じ形の問題が、道具ごとに別々の近似（比の順に取る・平均だけ・根拠の無い係数）で書かれ、正しかったかを測る物差しも無いまま残る。
この skill は、その瞬間に一覧を引き、判定の 1 行を残すためにある。厳密解を毎回作ることは求めない。

## 手順

1. 書く前に、決めたいことを対象の言葉を外して 1 行で言い直す（例: 「予算内で、グループごとに 1 つ、価値の合計を最大」）。
2. プロジェクト root の `.local/decision-catalog.md`（この環境の「道具選択の一覧」）を開く。まず概要の表を読み、合う行の節を最後まで読む。
   - 無ければ、雛形 `${CLAUDE_PLUGIN_ROOT}/skills/decision-tool-selection/catalog-template.md` から作るかを user に 1 回だけ尋ねる。作らないなら、一覧の代わりに雛形の「一覧の行の例」と自分の知識で手法を選び、3・4 へ進む。
3. 手法を決めたら、道具の README（無ければ冒頭のコメント）に次の 1 行を書く:
   「問題の形 → 一覧の行（合う行が無ければその理由）→ 手法 → 近似なら、厳密解か上界との差を測った値、または測らない理由」。
   比の順に取る・平均だけを出す・根拠の無い係数を置く、は近似として扱う。
4. 同じ所に「物差し:（答えが正しかったかを後から測る方法）」と「記録:（推奨に従った結果を書く場所）」を書く。無ければ「無し」と書く。
5. どの行にも合わなければ、一覧の「新しい手法の受け口」の条件に沿って足す。一覧の見直し日を過ぎていたら、作業は止めず、完了報告に「一覧の見直し日超過」と 1 行添える。

## 近似で足りるとき

近似で足りる場合は近似でよい。この skill が求めるのは、それを判定する 1 行を書くこと。

- 制約が 1 種類の分割（グループごとに k 個まで）で費用が全部同じ → 価値の順に取る貪欲が最適（マトロイド上の貪欲法）。
- 候補を総当たりしている → 既に厳密。
- 判断でなく測定、または user が決めた閾値 → 手法を替える対象外。
- 予算が大きく端数が効かない帯だけで使う → 貪欲との差は小さいことが多い。ただし一度差を測ってから判定する。
