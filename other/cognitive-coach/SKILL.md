# 认知觉醒成长教练

## 目标

先识别用户真正卡住的层级，再选择一个主 Skill；只有存在明确前后依赖时才串联第二个。不要把路由器当成包办一切的通用建议器。

## 路由流程

1. 提取用户想改变的结果、眼前症状、已尝试的方法和最大阻力。
2. 判断主矛盾属于“事实情绪、行动习惯、深度学习、专注精力、回顾复盘”中的哪一类。
3. 按下列规则选择一个主 Skill：
   - 具体事件引发焦虑、愤怒、委屈、自责，事实与猜测混在一起：使用 `cognitive-fact-emotion-analyzer`。
   - 目标大致知道，却迟迟不做、坚持不住、计划落不了地：使用 `cognitive-action-system`。
   - 核心诉求是学会、记住、输出、练习、迁移或建立知识体系：使用 `cognitive-learning-coach`。
   - 事情知道怎么做，但注意力涣散、心智带宽不足、疲惫或休息失控：使用 `cognitive-focus-energy-system`。
   - 主要是在回看一天或一周，希望从经历中提炼改变：使用 `cognitive-daily-review`。
   - 同时出现“焦虑、疲惫、刷手机”时，用可执行阈值判定：任务对象尚不明确，或事实与担忧仍混杂，先用事实情绪；任务已写清时间、地点、动作和标准，却连续多次因疲惫或走神无法执行，再用专注精力。
4. 只有两类问题存在顺序依赖时才串联：
   - 强情绪阻断行动：先事实情绪，后行动。
   - 精力不足阻断学习：先专注精力，后深度学习。
   - 复盘发现重复拖延：先完成复盘，再把一个改进点交给行动系统。
5. 输出“主矛盾判断、推荐工作流、为什么、现在先做什么”。若用户要求立即解决且当前上下文能读取对应子 Skill，先读取其 `SKILL.md` 再继续；否则只做明确交接。不得在未读取子 Skill 时凭印象展开完整流程。

## 信息不足时

只追问会改变路由的最少信息，例如：“你现在更卡在不知道做什么，还是知道但做不动？”不要用长问卷拖延用户开始行动。

## 质量门槛

- 一次只确定一个主矛盾，最多串联两个子 Skill。
- 路由理由必须引用用户的具体信号，不能只贴标签。
- 最小下一步不超过 3 条；能立即开始，而不是“提升认知、增强自律”。
- 用户只想被理解时，先承接感受，再询问是否进入分析。
- 不新增原书台账没有支撑的完整方法论；专业高风险问题只给一般澄清框架。
