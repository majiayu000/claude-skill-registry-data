# 交活前要有证据

属于开源包 Solo to Team · 一人成队（solo-to-team-skills）。

## 含什么

铁规一条、开口前五步、「想说什么要什么证据」对照表、该停一下的信号、常见借口、怎么跟委托方说、核对本身不能变成危险动作。

## 适合谁

- 经常代表「已经做完」向负责人／委托方汇报的助手或执行人
- 多助手协作里容易「转述别人已完成」而自己没看过成品的总控
- 文档、视频、图片、数字、链接、修电脑、放文件等日常交付（不限编程）

## 怎么用

1. 开口说任何完成义之前，走第 2 节五步；手里已有对得上当前版本的有效证据就复用，见第 1 节。
2. 对照第 3 节表格选证据；不够就报现状，不换说法暗示做完。
3. 从同仓 `../dispatch-accept-verify/` 收回来的活：先记「已收到成果」，再按本技能核，核过记「已验收」，再往下交。

## 依赖

- 能打开／播放／重算交付物的本地或约定环境即可
- 不绑死某一家助手平台；与 `../dispatch-accept-verify/` 联用效果最好

## 示例

见第 3 节对照表各行「要的证据／不够的」；与 `../dispatch-accept-verify/templates/登记行模板.md` 联用时，在「已验收」行写一句怎么核的，没过写「退回」行。完整跟做（含复用上一回核验、只补核改动部分）见包根 `examples/walkthrough-meeting-notes/`。

## 验证到哪

队内交付已按「先有证据再说做完」执行；公开包保证的是**核对步骤可照做**。能否降低返工率，见同仓 `../ops-case-notes/`「仍未证明」栏，本技能正文不下效果结论。

一句话：**先有证据，再说做完。**

## 0. 和相邻技能怎么分工

- 团队或项目里若另有「交付前要有证据」的原则条文：本技能只讲**怎么拿证据、怎么说**；冲突时以你们的原则条文为准。
- 独立审核／抽检是**别人事后复核**；本技能是干活的人**自己交出去之前**先核一遍。自己核过 ≠ 免审。
- 分清两种东西：**执行人报告**（干活的人说「好了」，附他自己的核法）和**独立核验**（收的人或指定核验人亲手看过）。前者是线索，不能当后者用。
- 动手前讲方案、记下修改意见：属方案确认类技能；那些修改记录，正是第 3 节「委托方的要求全做到了」要逐条对照的东西。
- 派出去的活有没有人收回来：见同仓 `../dispatch-accept-verify/`。

## 1. 一条铁规

没有对得上当前版本的有效证据，就不说「做好了」。

**有效证据**：你（或指定的核验人）亲手拿到的，而且它核的那个版本、范围、环境，和你现在要说的这句话对得上。

- **可以复用**：上一回已经核过、之后没改过、没出过失败、环境没换的那部分。复用时写明是哪一次核的、核的哪个版本。
- **要补核**：之后有改动、有过失败、换了环境（换电脑、换账号、换软件版本）的部分。只补核受影响的部分，不必每次从头全套再来；拿不准影响到哪，就把范围放大一点。
- **不算证据**：别人说好了的（执行人报告不能当独立核验）、核的是旧版本或别的范围的、「应该没问题」的。

跳过核对说出来的「做好了」只是猜测，猜错了委托方要白等、返工，协作里的话也就不可信了。这条规矩是习惯，不是惩罚：核过了就大方说，没核就老实说。

照字面躲开这条规矩（换个说法暗示做完了），和违反它是一回事。

## 2. 开口前的五步

1. **想清楚**：哪件事能证明我要说的这句话？
2. **拿证据**：先看手里有没有对得上当前版本、范围、环境的有效证据。有，就复用并写明出处；之后有改动或出过失败，只补核受影响的部分；没有，就亲手完整做一遍。别人的报告只当线索。
3. **看完结果**：整份看完，不只看开头几行；有几处出错就数清几处。
4. **对照**：这个结果真能撑住我要说的话吗？
   - 撑不住：照实说现在到哪一步，附上证据。
   - 撑得住：说结论，附上证据。
5. **再开口**。

**普通进度不触发全套重验。** 只说「进行到哪、下一步做什么」，照实说就行，不用为此重跑检查；一旦说「这部分做完了／好了」，那部分就要走上面五步。

## 3. 想说什么，要拿什么证据

| 想说 | 要的证据 | 不够的 |
|---|---|---|
| 文档做好了 | 用对应软件打开，或转成图片逐页看过：字、表格、页码、中文字体都正常 | 「生成成功」的提示；文件存在 |
| 视频做好了 | 从头播过，至少抽看开头、中间、结尾；分辨率、码率和源文件比过 | 导出进度到了 100% |
| 图片做好了 | 按原尺寸打开看过，过了你们的视觉自检 | 只看了缩略图 |
| 数字算对了 | 换一种办法重算一遍，总数和分项对得上 | 算过一次 |
| 链接能用 | 点开过，内容就是要的那篇；复用之前的点开记录时，写明是哪一回、对应哪一版，目标或时效变了就重新点开 | 搜索结果里看见过 |
| 电脑问题修好了 | 按原来出问题的步骤再走一遍，问题不再出现；会被自动更新、定时任务、同步改写的，写明下一次改写时间，到点再测，没测前只说「当场测通，待 X 点复测」 | 改了设置；「理论上应该好了」；当场测通就说「以后都好了」 |
| 小工具能用 | 正常用法和出错用法都实际跑过 | 代码检查通过 |
| 东西放到某处了 | 去那个位置看见了，文件名、大小、份数都对 | 复制时没报错 |
| 已放行的发送、同步成功了 | 在收件或目标那一端看得到 | 工具返回「成功」 |
| 别的助手或子任务说做完了 | 自己去看改动和成品 | 对方的报告 |
| 委托方的要求全做到了 | 重读原始要求和修改记录，逐条打勾 | 「主要部分做完了」 |

## 4. 该停一下的信号

- 想用「应该」「大概」「看起来」「差不多」。
- 还没核就想说「搞定」「完美」「没问题」。
- 想直接转述别人的「已完成」。
- 只核了一部分，想推到全部。
- 心里冒出「就这一次」「太晚了，先交了再说」。

## 5. 常见借口

| 借口 | 实际上 |
|---|---|
| 应该好了 | 去核一下 |
| 我有把握 | 有把握不等于有证据 |
| 就这一次 | 没有例外 |
| 检查工具没报错 | 没报错不等于结果对 |
| 它说成功了 | 自己去看 |
| 只查一部分就够了 | 一部分只能证明那一部分 |

## 6. 怎么跟委托方／负责人说

- 建议顺序：结果和在哪 → 为什么 → 以后怎么办。证据不用整份摆出，**一句话说清怎么核的**就行。例：「做好了，在约定文件夹里，文件名是『第3集_定稿』。我从头播了一遍，画质和原片一样。」
- 没做完照实说，不说「基本完成」。例：「8 个做好了 6 个，另外 2 个字幕还没对上，21:30 前补完。」
- 自己这边核不到的（比如只有对方手机上能看到），说清「我这边核过了什么，哪一步需要您看一眼」，不当成已完成。
- 给独立审核或写进档案时，证据写具体：打开过哪个文件、核了哪些数字、对照了哪几条要求。
- 不自责、不过度道歉。核出问题是好事，说清楚、改掉就行。

## 7. 核对本身不能变成危险动作

- 核对用只读、本地可逆的办法。不为了「试试能不能发出去」真发一条，不为测试下单，不为核对删东西。
- 核对非得碰负责人的电脑、账号，或者会让外人看到的，先按你们团队的危险动作报审流程来。
- 实在核不了：直接说「这一点我核不了，原因是……」，标「待核实」，不硬说做完了。

## 8. 什么时候用

一律在这些时候用：

- 任何表示「完成了」「正确了」「成功了」的话，包括换个说法和话里暗示。
- 交付之前、进度里要说某部分做完了之前、进入下一步之前（只报进行到哪不算）。
- 把活派出去之后，收到「做完了」的回报时（先收，再核）。
