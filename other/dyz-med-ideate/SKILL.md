# 医学研究选题与问题构建

## 目标与边界

把模糊想法推进到“可以检索、可以评估、可以讨论研究设计”的问题，不把热点清单当成选题结论。

- 若用户已有明确问题和可用数据，只补齐必要缺口后建议进入 `dyz-med-init`。
- 若用户已有稿件，转交相应写作或审稿技能。
- 本技能服务于科研设计，不提供个体诊疗建议。
- 不虚构文献、PMID、检索数量、数据可得性或发表概率。
- 将文献事实、合理推断和待验证假设明确分开。

## 工作流程

### 1. 判断起点

先识别最接近的情形；信息不足时，一次只追问会改变选题方向的关键问题。

| 情形 | 典型输入 | 推进重点 |
|---|---|---|
| 临床观察 | “临床上常见某个现象” | 明确人群、暴露、比较和结局 |
| 宽泛兴趣 | “我对某疾病感兴趣” | 从疾病领域收窄到可回答的问题 |
| 现有数据 | “手上有一个数据库” | 先核对变量、样本量、时间结构与合规性 |
| 综述意向 | “想做 Meta 或综述” | 核对原始研究数量、异质性和近期综述 |
| 导师方向 | “导师让我做某方向” | 把方向翻译成可检索、可执行的问题 |
| 学业或晋升需求 | “需要完成一篇论文” | 在时间、资源、伦理和质量之间取可行解 |
| 趋势探索 | “最近什么方向值得做” | 区分热点、空白、竞争度与本地可行性 |

至少确认：

- 目标人群或疾病范围；
- 可获得的数据、样本或实验条件；
- 时间、经费、伦理和团队能力限制；
- 预期研究类型与用途；
- 用户最在意的新颖性、可行性或临床价值。

### 2. 结构化研究问题

按问题类型选择框架，不强行套用 PICO。

- 干预或治疗：PICO 或 PICOS。
- 暴露与结局：PECO。
- 诊断研究：PIRO。
- 定性研究：PEO 或 SPIDER。
- 预测模型：目标人群、预测时点、候选变量、结局、使用场景和外部验证。

形成一句主问题，并列出：

- Population：人群、场景和关键纳排条件；
- Intervention 或 Exposure：定义、剂量、窗口或测量方法；
- Comparison：对照或参照；
- Outcome：主结局、次要结局和测量时点；
- Study design：能够回答该问题的设计。

发现一个要素不可测量时，先调整问题，不要继续包装。

### 3. FINER 可行性检查

逐项给出“通过、需补充、严重风险”及理由：

| 维度 | 核心检查 |
|---|---|
| Feasible | 样本、变量、技术、时间和经费是否足够 |
| Interesting | 是否对研究者、同行或临床决策有意义 |
| Novel | 是确认、反驳、扩展，还是新人群、新方法、新场景 |
| Ethical | 伦理审批、知情同意、隐私和风险是否可接受 |
| Relevant | 能否推进实践、政策、机制或后续研究 |

Feasible 或 Ethical 出现严重风险时，不把该方向列为首选；给出可逆的缩小方案或替代设计。

### 4. 机制层级升级

把问题标记为以下一层：

- phenomenon：只描述现象；
- association：检验变量之间的关联；
- mechanism：检验中介、通路或因果链；
- translational：连接临床决策、干预或产品路径。

若问题停留在现象或关联层，优先调用 `dyz-med-mechanism` 做问题升级。该技能不可用时，至少说明：

- 可能的上游因素、中介、执行环节和表型；
- 哪些环节已有证据，哪些只是待验证假设；
- 为什么描述性或流行病学设计在当前阶段仍然合理。

不要为了显得“高级”而强行添加未经支持的机制。

### 5. 验证文献缺口

开始检索前，先读取 `references/search-protocol.yaml`。若领域匹配，再读取
`references/search-templates/` 下的心血管、肿瘤或公共卫生模板；模板只是起点，必须按当前问题修改。

执行顺序：

1. 从结构化问题生成主题词、自由词、同义词和缩写。
2. 使用可用的 PubMed 检索与 MeSH 工具，至少执行一组可复现查询。
3. 先找近两年的系统综述、指南和决定性研究，再扩大到近五年的关键研究。
4. 记录检索日期、数据库、完整查询式、筛选条件、结果数和关键标识符。
5. 对中国人群、国内诊疗路径或本土政策相关问题，再补充中文文献线索；明确网页线索与正式数据库记录的区别。
6. 若可访问 ClinicalTrials.gov 或其他注册平台，检查正在进行的同题研究。
7. 若已暴露 OSF 工具，可搜索预印本、注册报告与开放数据；若没有，标记“本轮未核查”，不要调用不存在的本地脚本。
8. 对决定选题的 1 至 3 篇论文，在可获得全文时使用文档阅读工具核对方法、样本、结果和局限；摘要不能支持的细节不要补写。

若当前环境无法检索，只交付可执行的检索方案，并把缺口状态标记为“未验证”，不能声称缺口成立。

将结果归为：

- `CONFIRMED`：现有证据未直接回答该具体问题；
- `PARTIALLY_FILLED`：已有部分答案，需要收窄人群、暴露、结局或方法；
- `CLOSED`：近期高质量证据已直接回答，应换方向；
- `UNVERIFIED`：检索条件不足，暂不能判断。

只把有检索记录支持的状态写成前三类。

### 6. 形成候选方向

给出 1 个推荐方向和最多 2 个备选方向。每个方向必须包含：

- 一句话研究问题；
- 结构化框架；
- 当前机制层级；
- 文献缺口及证据状态；
- 最小可行设计；
- 数据、伦理、偏倚和竞争风险；
- 为什么适合用户现有条件；
- 下一步最小行动。

“发表潜力”只能基于问题质量、证据空白、方法适配度和期刊范围作分级判断，不承诺录用。

## 完成检查

- 至少形成 1 个具体、可检索、可执行的问题；
- 结构化框架与研究类型匹配；
- FINER 至少覆盖可行性、伦理和相关性；
- 机制层级已标注，或已解释为何保持描述性设计；
- 缺口状态有检索记录支撑，无法检索时标为 `UNVERIFIED`；
- 所有文献标识符可追溯，不编造引用；
- 数据可得性、伦理、关键偏倚和竞争风险已说明；
- 给出 1 至 3 个明确的下一步动作。
