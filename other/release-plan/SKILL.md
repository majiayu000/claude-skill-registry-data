# 发布方案设计Skill

## 适用场景
版本上线前,制定可执行、可验证、可回滚的发布方案。

## 执行步骤
1. 明确变更内容与影响范围(服务、数据、配置、第三方)。
2. 选发布策略:全量 / 分批(按比例)/ 金丝雀 / 蓝绿,按风险选。
3. 设计分批节奏:每批比例、观察时长、放行条件(错误率/延迟/业务指标)。
4. 写验证清单:发布后必验项(核心链路 + 本次变更点)。
5. 写回滚预案:触发条件、回滚动作(版本/配置/数据补偿)、责任人。
6. 约定发布窗口与值守安排。

## 规范要点
- 变更描述必须可对应到代码/配置 diff,禁止「优化若干问题」式笼统描述。
- 每批放行必须有量化条件(如:错误率 <0.1% 且 P95 <500ms 持续 10 分钟)。
- 回滚预案必须写清「什么情况触发 + 第一步做什么」,禁止「视情况回滚」。
- 数据库变更必须评估兼容性:先扩后缩、双写过渡、大表变更在线执行方案。
- 生产发布必须附「总控 + 安全合规」双签名审批结论。

## 输出模板
```
## 发布方案
变更内容 / 影响范围 / 策略(灰度/全量+批次) / 放行条件 / 验证清单 / 回滚预案 / 发布窗口与值守
```

## 自检清单
- [ ] 变更内容可对应 diff
- [ ] 放行条件量化
- [ ] 回滚预案可执行
- [ ] 生产发布有双签名审批
