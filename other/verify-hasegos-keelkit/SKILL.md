# 구현 후 검증 · 체크리스트

## 1. 직접 검증할 때 지킬 것

| 대상 | 규칙 |
|---|---|
| 사용자 데이터 | 지우거나 초기화하지 않는다 |
| 임시 자원 | 세션 scratchpad에만 둔다. 프로젝트 폴더에 임시 파일을 두지 않는다 |
| 전역 환경 | 사용자 전역 패키지에 설치하지 않는다. 임시 venv 등을 쓴다 |
| 결과 | 항목별 통과 / 실패를 출력하고, 실패는 원인을 확인한 뒤에만 고친다 |

실행 환경이 없으면 정적 검사까지만 하고, 실행 검증을 못 했다고 보고한다.

## 2. 사용자용 체크리스트

구현 보고 끝에 준다.

| # | 무엇을 | 어떻게 | 기대 결과 |
|---|---|---|---|
| 1 | 확인할 동작 한 가지 | 복사해서 쓸 수 있는 명령 / 화면 경로 | 보이는 결과 |

- 정상 흐름 → 실패 흐름 → 경계 순서.
- 직접 검증에서 이미 통과한 항목은 표시해 둔다.

## 3. 정리

사용자가 기능을 "확정"이라고 하면 그 기능의 임시 산출물(검증 스크립트, 임시 venv, PR 초안 등)을 지우고, 지운 목록을 결과 보고에 한 줄로 적는다. 삭제이므로 확인을 받는다 (Claude에서는 hook이 요청한다).
