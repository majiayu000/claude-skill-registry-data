# 产品版型与符号蒸馏

**产品属性 = 功能属性 + 符号属性；产品设计候选 = 版型 + 符号方案；生成图 = 产品设计候选 + 画面协议。** 版型是可复用的产品款式/结构底座，包含模块及关系、功能、单套组成与件数、尺寸、材料、固定外观和已知工艺约束；符号方案承载可替换的图形、颜色、文字、风格与情绪表达。两者只能在适配的产品部位和工艺边界内组合。产品设计候选不自动代表已打样、可量产、合规或有市场需求；本 Skill 负责可追溯的产品视觉数字化与图片生成，不以概念图代替生产和市场验证。版型和符号都必须有文字规范及由图像模型抽取/重绘的图片。原始商品图是证据；模型生成的抽取图是待核对的中间结果，不能反过来充当原商品事实。完整术语与组合规则见[多模态版型 + 符号架构](references/architecture.md)。最终交付的提示词文件提供可复制的文字与图片相对路径；图片作为同目录资产由 Agent 实际加载。

本 Skill 有两个入口：用户要把已有商品数字化时执行下方 **Extract**；用户已有提取包、要“版型 + 新符号/主题 → 新产品视觉”时执行 [Gen 流程](references/gen-workflow.md)。Gen 不把节日、活动、固定副图类型或张数硬编码为 Skill 规则；先从用户输入和项目记录填入已有信息，仅就影响正确性的缺项提问。主图沿用已核对版型；**新主图须先由用户确认，期间按反馈持续修订；得到明确确认后才开始副图的详细设计与生图。** 副图按新主题重新规划，不搬用原商品副图的场景图。一次生成任务共享一套符号母稿并记录依赖、提示词、模型、输出与复测结果。

## Extract：产品视觉数字化

1. **确定来源与目标。** 识别自有产品、用户图/设计稿、ASIN/SKU、站点、目标画面，以及复现或换符号。复现主图时必须取得并保存原始主图文件，把它定为画面评分依据；只有设计稿而无主图时不能宣称“主图相似度达到 90%”。用户指定数据源时优先使用；有 ASIN/SKU 且未指定来源时，用 Codex 内置浏览器查看 Amazon 前台实际可见的主副图、A+ 与商品资料；只有图片时从图片开始。下载可用的高清主副图，逐张记录它能补足的主图盲区，例如局部印花、文案、织纹、折法或随附配件，并登记来源冲突。副图是抽取证据，不作为主图画面的构图目标，也不在独立重组时直接提供给子代理；把核实过的细节蒸馏进文字和模型生成的版型/符号图。区分套装实际包含的物件与目标主图中可见的物件；设计稿/刀模说明展开结构，listing 说明当前售卖宣称，折叠后的可见比例和主图里可见的符号位置以目标主图为准。未知或未经实物验证的内容不补造。
2. **拆分契约。** 版型固定可复用的模块/部件及其关系、产品功能、单套组成与各部件件数、材质、尺寸比例、实体裁切/折叠结构、底布及固定色、印花区域的位置/面积/方向/密度，以及来源资料能够证实的生产工艺约束；未知工艺不推断。符号槽填写主题图案、数字、口号及槽内允许改变的印刷色；画面协议固定构图、机位、背景、光线。刀模图需区分画板、裁切线、折痕和成品边缘。跨功能品类或结构配置建立新版型；只换主题时保持版型与画面协议版本不变。
3. **让图像模型生成抽取图。** 以来源图和上述契约为约束，由图像生成/编辑模型分别生成：无主题印花的版型基底图，以及按可替换区域分隔的原始符号图。版型图保留真实件数、比例、材质、固定色与异形轮廓；符号图只含原有可变图案和精确文案。松散素材图只用于识别符号；高保真复现还需由模型生成与载体配准的印刷图或区域蒙版，并核查模型是否仍改变比例。明确每张来源图和输出图的角色。生成新主题时复用已核对的版型图，让模型另生新符号图。图片内容的生成或修改由图像模型执行。
4. **组合为轻量提示词。** 版型文字使用稳定的 `{{槽位名}}`，原始或新符号包逐槽填入。`prompt.md` 是可交付的文字入口：包含无空槽的合成提示词、版型图与符号图的角色和相对路径，以及使用说明。文字须用图像可见特征辨认每张输入图，不只依赖上传顺序；列出所有必须出现的符号类别、数量、颜色与裁切位置，“稀疏”只约束间距，不允许漏掉必要符号。图片保存在同目录的 `images/`，桌面 Agent 以 `prompt.md` 所在目录解析路径并实际加载图片；可另保留 `prompt-text.md` 方便编辑复制。记录 MIME、SHA-256 和生成条件；图片改变时更新路径及哈希，并确认文件可读。复制或移动时保持整个提取目录结构。
5. **独立生成、对照、迭代。** 在重组前固定以原始主图为目标的评分项和硬门槛。让独立子代理只用第 4 步的提示词及其版型/符号图片生图，不把原始主图或设计稿作为重组输入。主代理对照原主图评分；未过硬门槛或低于 90/100 时定位是来源理解、抽取图、合成提示词还是生成模型的偏差，修订对应资产并重新由子代理生成，保留每轮输入、结果和评分。只有达到门槛的版本才标为相应模型的可交付基线；换用其他生图模型要单独复测，不能沿用前一个模型的分数。若平台强制加水印，将它和产品印花误差分开记录。工具无法稳定满足时如实记录限制，不给失败图打通过标签。换主题还需检查符号槽外是否发生变化。细节见[复测协议](references/evaluation-protocol.md)。

## Extract 完成条件

- 版型和符号各有文字说明与模型生成图；用户能按提示词中的相对路径从同一提取目录取得图片。
- 每张抽取图都已对照原图；独立子代理生成的基线图已对照原主图，逐轮失败项和未验证项如实记录。未达到预设硬门槛及 ≥90/100 时，交付状态仍为草稿。
- 当目标是“仅符号变化，其余一致”时，使用同一版型图上的受区域限制编辑或合成流程，并核对印花区域外是否变化；整图参考生图只能作为近似概念图，不能仅凭提示词承诺非符号区域一致。
- 对外复制区只有一条完整提示词；图片的相对路径、MIME 与哈希对应实际文件。换符号时仅更换符号包和符号图，除非用户明确要求新版型。
- 交付网页端上传图片 + 粘贴提示词，以及桌面 Agent 按相对路径读图的两种[手动测试步骤](references/manual-test-guide.md)；桌面 Agent 默认读 `prompt.md` 并加载图片文件。

目录、槽位和图片角色见[扩展架构](references/architecture.md)。历史纯文字提示词及旧 JSON schema 继续作为旧记录，不是本多模态流程的验收依据。
