# 足式与人形机器人产品规格

## Purpose

把复杂地形移动和全身操作场景转成可验证要求，帮助产品经理理解状态估计、运动规划、全身控制、学习策略、执行器和安全恢复之间的实现路径与取舍。

## Input

可提供目标任务、地形、楼梯/门、操作对象、载荷、作业时长、人机混行、候选形态、现有平台或演示视频。没有目标值时先建立规格项和验证方法，不以行业演示数字替代需求。

示例：`使用 legged-humanoid-product-spec，定义一款工厂巡检并操作阀门的人形机器人MVP。`

## Key Concepts

- **形态需要任务证明**：类人环境不自动意味着必须用人形机器人。
- **接触决定能力**：足端、手端与环境的接触位置、摩擦和力决定稳定与操作。
- **全身耦合**：负载、手臂动作和外力会改变平衡、落足和关节余量。
- **策略与安全分层**：学习策略可提高泛化，但不应绕过独立约束、低层控制和保护链路。
- **跌倒是系统事件**：要处理人员风险、设备损伤、任务恢复、数据记录和人工救援。

## Application

### 1. 证明形态选择

比较轮式底盘、轮式机械臂、四足、轮足、双足和人形。评估地形覆盖、操作空间、任务成功、能耗、速度、成本、维护、跌倒后果和部署周期。说明为什么更简单形态不能满足核心任务。

### 2. 定义ODD和身体包络

记录通道、门、楼梯、坡度、台阶、地面摩擦/柔软度、扶手、障碍高度、光照、温度、雨尘、人员距离和可用支撑。定义身高、肩宽、臂展、可达空间、自由度、整机质量和重心变化。

### 3. 写足式移动规格

覆盖站立、起步、停止、转向、倒退、侧移、坡面、楼梯、跨越、蹲起、受扰恢复、跌倒和起身。指标包括速度、稳定持续时间、地形通过率、足端打滑、恢复成功、能耗和人工干预。

技术路线可比较模型控制/MPC、全身控制、轨迹优化、模仿学习、强化学习和混合方案。选型依据必须包含ODD、算力、训练数据、可约束性、可复现性和失效检测。

### 4. 写操作与全身协同规格

定义目标识别/位姿、可达空间、单/双臂载荷、重复精度、抓取对象范围、末端执行器、力/扭矩、顺应性、工具使用、身体支撑和任务确认。测试操作动作对平衡与关节热负荷的影响。

### 5. 定义自主、遥操作与数据闭环

为每个任务状态标记自主执行、远程确认、遥操作接管或现场操作。定义接管延迟、视角/触觉反馈、权限、通信中断行为和恢复。学习能力需说明数据来源、标注、仿真到现实差距、版本回归和现场回流。

### 6. 定义硬件与能源约束

覆盖执行器峰值/持续力矩、关节速度、背隙、传动、制动、热降额、碰撞耐受、线束、传感、计算平台、电池和散热。把连续任务与峰值动作分开验收。

### 7. 定义安全与恢复

覆盖夹挤、撞击、跌倒、甩动、失稳、失电、失控、过温和误操作。定义速度/力限制、保护状态、急停、缓降/制动、可控倒地、起身条件、禁区和人工救援。

### 8. 建立分层验证

使用 [规格与验证模板](references/legged-humanoid-requirements.md)，从单关节/执行器、子系统、仿真、吊架/保护环境、受控地形、完整任务、连续现场到规模部署逐级验证。

## Examples

### 四足巡检

巡检能力不仅是“能上楼”。还要定义传感器视角、停稳采集、楼梯材质、扶手/人员干扰、背负载荷、续航、跌倒后果、远程接管和异常区域隔离。

### 人形阀门操作

拆成到达、定位阀门、判断状态、建立支撑、抓握、施力、监测旋转、确认结果和退出。全身平衡、末端力控和任务确认缺一不可；先验证阀门阻力分布和标准化可能性。

## Common Pitfalls

- **用步态视频定义产品**：好看但无法完成稳定任务。修正：按端到端任务成功和干预验收。
- **只写峰值力矩与载荷**：连续动作过热降额。修正：定义持续工况、占空比和热稳态。
- **学习策略包办安全**：长尾输出不可控。修正：设置独立约束、监控、保护和回退。
- **忽略跌倒运营成本**：设备、场地和人员受损。修正：量化跌倒率、损伤、起身和救援时间。
