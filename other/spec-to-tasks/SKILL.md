# spec-to-tasks — разбиение спецификации на задачи

## Шаги

1. Прочитать `docs/spec/requirements.md`, `docs/spec/consistency-model.md`, `docs/tasks.md` (если есть), `docs/adr/`.
2. Найти REQ без задач и задачи, чьи REQ изменились после создания (Changelog спецификации).
3. Для каждого такого REQ составить задачи по шаблону. Предпочитать **вертикальные срезы** (протокол → сервер → клиент → e2e для одного сценария), а не «весь бэкенд, потом весь фронт».
4. Размер: S (≤ 2 ч) или M (≤ 1 день). L — разбить дальше.
5. Упорядочить по зависимостям; задачи ядра `packages/crdt` — раньше потребителей.
6. Записать в `docs/tasks.md`, существующие ID задач не менять.
7. Всё, что в спецификации неясно и мешает разбиению, — **не додумывать**, а вынести в `## Вопросы к спецификации` в конце `tasks.md` и сообщить пользователю.

## Шаблон

```markdown
### T-007: Слияние перемещений стикера (move×move)

- **REQ:** REQ-012
- **Статус:** todo | in-progress | review | done
- **Размер:** M
- **Зависит от:** T-003
- **Затрагивает:** packages/crdt, packages/protocol, packages/sim
- **Готово, когда:**
  - тесты `REQ-012: *` написаны агентом test-author и зелёные
  - property-набор CRDT включает операцию move (скилл crdt-op)
  - `npm run check` зелёный, PR смёржен
```

## Правила

- Задача без REQ допустима только для инфраструктуры (помечается `REQ: infra`).
- Статус `done` ставится только со ссылкой на смёрженный PR.
