# 业务场景测试执行Skill

## 适用场景
功能测试环节,基于已评审的测试用例执行场景化测试,规范执行过程并如实记录结果。

## 执行步骤
1. 环境准备:确认被测版本、构建号、配置项与依赖服务状态,执行前留档环境信息。
2. 数据准备:构造前置数据(账号、订单、权限、存量数据),标注数据来源(造数脚本/手工构造/生产脱敏),保证可重复构造。
3. 用例执行:逐条执行,禁止跳步;同步留存证据(截图、日志、响应报文),证据按「用例编号+步骤号」归档。
4. 结果判定:实际结果与预期结果比对,判定为通过/失败/阻塞/未执行四态之一。
5. 汇总:统计通过率,失败用例转缺陷流程,阻塞与未执行用例标注原因。

## 规范要点
- 结果如实呈现,不得粉饰:通过数、失败数、未执行数与实际执行一致,禁止事后修改判定。
- 未执行的用例必须标注「未执行」及原因(时间不足/环境缺失/依赖阻塞),不得记作通过,不得静默删除。
- 阻塞用例标注阻塞原因与解除条件,解除后安排补测并补记录。
- 失败判定前先排除环境与数据问题:同一失败至少复现一次再定缺陷,复现不了标注「偶现」并附频率。
- 环境与数据留档完整,保证任何人可按记录复现结果。

## 输出模板
```
## 测试执行记录
| 用例编号 | 前置数据 | 实际结果 | 判定 | 证据编号 | 备注 |
## 执行统计(通过/失败/阻塞/未执行)
## 失败用例清单(转缺陷)
## 未执行用例清单(附原因与补测计划)
```

## 自检清单
- [ ] 环境信息(版本/构建号/配置)留档
- [ ] 每条用例有实际结果与证据
- [ ] 未执行/阻塞用例已标注原因,未混入通过数
- [ ] 失败用例已复现确认并有转缺陷记录
- [ ] 执行统计与明细一致
