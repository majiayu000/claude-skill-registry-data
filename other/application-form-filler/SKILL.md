# 申请表单填写助手

## 何时使用本技能

当用户想要：
- 回答求职申请表上的具体问题
- 填写 Greenhouse、Lever、Ashby、Workday 或任何 ATS（申请人跟踪系统）上的文本框
- 撰写"介绍一下你自己"或"为什么想加入我们"这类开放题的回答
- 获得干净、可直接复制粘贴的申请答案
- 提到："帮我填一下"、"这里写什么"、"回答这个问题"、"申请表"、"表单字段"

## 核心原则

申请表单的答案应该直接且具体 —— 而不是把求职信硬塞进一个文本框。每个字段都有其目的。把目的清晰地回答了，然后就停笔。

**答案应该给人的感觉是：** 一个真实的人亲手打出来的，而不是套模板填出来的。

## 动笔之前

务必先阅读：
1. **职位描述（JD）** —— 呼应它的措辞与侧重点
2. **候选人的简历/个人资料** —— 提取真实的项目、角色与量化数据
3. **具体的问题** —— 只回答被问到的内容，而不是你希望被问到的内容

如果用户没有提供简历或 JD，动笔前请先索要。

## 问题类型及应对方式

---

### 类型 1：经验/背景类问题

**示例：**
- "你在 [某技术] 方面有多少年经验？"
- "描述你在 [某领域] 的经验"
- "你用过哪些后端框架？"

**格式：**
```
[技术/技能] —— [X 年]。[一句话说明用它做过什么，落到一个具体
项目或场景]。[可选：同类技术的其他工具]。
```

**规则：**
- 置顶写出最常用/最相关的技术
- 年数要诚实 —— 不要夸大
- 每个说法都要落到具体项目或职位上
- "描述经验"类问题：最多 2-4 句话，一句话一个项目
- 如果经验是间接的（相邻领域），就直说，然后转向相关的部分

---

### 类型 2：为什么选这家公司 / 什么吸引你

**示例：**
- "你为什么想加入 [公司]？"
- "这个职位哪里吸引你？"
- "为什么你很合适？"

**格式：**
```
[这家公司/职位真正有意思的具体点 —— 不是泛泛之谈]。
[这与你实际做过的某件事之间的关联]。
[可选：一句话说明为什么是这个领域，而不仅是这家公司]。
```

**规则：**
- 必须针对这家公司 —— 不要套话
- 必要时先做公司调研再作答
- 关联到真实做过的工作，而不是空想
- 表单字段控制在 150 字以内
- 不要把 JD 复述给对方听

---

### 类型 3：作品集 / 工作样例

**示例：**
- "附上其他你引以为豪的作品"
- "链接到相关项目或仓库"
- "描述一个你端到端做过的项目"

**格式：**
列出项目，每个项目配一行描述和链接。最相关的放最前面。

```
[项目名称]（[线上地址] | [github 地址]）—— [一句话：它是什么
+ 一个佐证]。[如相关，注明所用技术栈]。
```

**规则：**
- 只放与职位相关的项目
- 一定附上链接（线上演示 > GitHub > 什么都不放）
- 如果项目有付费用户或可量化的使用量，说出来 —— 说一次就够
- 不要为显得高产而堆砌无关项目

---

### 类型 4：技术技能类问题

**示例：**
- "你用得最深入的前端框架是哪些？"
- "给你的 Python 能力打个分"
- "描述你在云基础设施方面的经验"

**格式：**
对于开放式文本框：
```
[主要技能] —— [X 年]。[具体用途：用它构建了什么，在什么场景]。
[次要技能] —— [X 年]。[同上]。
[如存在相关差距，诚实注明]。
```

对于打分/下拉框：选诚实的等级 —— 不准确就不要为了追求高分而虚报。

**规则：**
- 年数 + 场景胜过单独的年数
- 直面差距，而不是掩盖
- 如果要求打分，就诚实地打 —— 虚高的评分会在技术面试中带来麻烦
- 对于用过但很久未用的技术栈，注明这点

---

### 类型 5：开放题 / "介绍一下你自己"

**示例：**
- "介绍一下你自己"
- "描述你的职业背景"
- "你在下一份工作中想寻求什么？"

**格式：**
```
当前职位 + 在那里做什么（1 句话）。
简述相关的过往经历（1 句话）。
你想寻求什么 / 为什么是这个职位（1-2 句 —— 具体到这家公司）。
可选：一个相关的项目或副业（1 句话）。
```

**规则：**
- 从当前职位写起，而不是教育背景
- 大多数表单字段控制在 100-200 字
- 结尾落在向前看的表述上（你想要什么，而非你走过什么）
- 不写性格标签句（"我热爱……"）—— 只写事实和项目

---

### 类型 6：情境/行为类问题

**示例：**
- "描述一次你解决复杂技术问题的经历"
- "讲一个你端到端主导的项目"
- "你如何处理跨团队协作？"

**格式：** 压缩版 STAR（不写标签，只写行文）

```
[一句话交代背景]。[你具体做了什么 —— 2 句话]。[结果，尽量带
量化数据 —— 1 句话]。
```

**规则：**
- 要具体 —— 点出项目名、技术、团队规模
- 不要泛泛而谈（"我看待问题的方式总是……"）
- 控制在 150-250 字
- 全程第一人称、主动语态
- 以结果收尾，而不是"学到的教训"（那留给面试）

---

### 类型 7：观点/前瞻类问题

**示例：**
- "你认为哪些技术对未来最重要？"
- "如果时间无限，你会学什么？"
- "你觉得 5 年后 AI/[某领域] 会怎样？"

**格式：**
给出真实观点。挑一两个点，简要说明理由。

**规则：**
- 要有真正的立场 —— 含糊的回答无法让人记住
- 观点要扎根于领域知识或真实经验
- 控制在 100-150 字
- 不要处处留有余地 —— 明确表达一个观点，并承认这只是一种视角

---

## 输出格式

始终把答案放在纯代码块中，方便干净地复制粘贴：

```
[答案文本]
```

如果要提供多个答案（每个字段一个），使用独立的代码块，并在每个块上方加标注：

**React 经验年限：**
```
4 年。在 Screenr（AI 招聘 SaaS）、一个基于 Tauri 的 POS 系统以及多个客户
项目中使用过。需要 SSR 的场景也用过 Next.js。
```

**描述你的后端经验：**
```
……
```

## 篇幅校准

| 字段类型 | 目标篇幅 |
|------------|---------------|
| 单行文本 | 1 句话 |
| 简答 | 2-4 句话 |
| 长答 / 多行文本框 | 100-250 字 |
| "描述你的经验" | 150-300 字 |
| "介绍一下你自己" | 100-200 字 |
| 作品集 / 链接栏 | 列表式，不写段落 |

拿不准的时候，短一点更好。招聘方看表单答案只是扫一眼。目标是清晰、令人印象深刻，而不是面面俱到。

## 需避免的常见错误

**复述 JD：**
❌ "我对这个职位很感兴趣，因为你们正在寻找能构建可扩展后端系统的人……"
✅ "真正吸引我的是那个实时性约束 —— 医疗数据要做到毫秒级延迟，和大多数后端工作完全不是一个量级的问题。"

**空洞的性格标签：**
❌ "我是个快速学习者，在协作环境中如鱼得水"
✅ [直接描述实际做过的工作 —— 特质自然会显现]

**过度谦虚铺垫：**
❌ "虽然我可能没有正好 5 年经验，但我相信我的经历……"
✅ "职位要求 5 年 —— 我有 3 年，但我交付过的系统都是面向生产环境的。"

**罗列没有语境：**
❌ "React、Vue、Angular、Next.js、TypeScript、Node.js……"
✅ "React 是我的主力前端框架 —— 4 年，跨 Screenr 和多个客户项目。Vue 和 Angular 各用了约 3 年，主要做仪表盘和管理后台。"

**为了填满篇幅而注水：**
❌ 为了显得高产而堆砌不相关的项目或经历
✅ 只保留与这个具体职位相关的内容
