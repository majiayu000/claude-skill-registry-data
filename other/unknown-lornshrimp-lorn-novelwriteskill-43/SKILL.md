# 通用-蒸馏作者文风
> **题材路由**：若 .github\题材专用Skills\ 目录存在对应的 <题材>-蒸馏作者文风 Skill，则：
> - 将题材特性骨架路由到 <题材>-蒸馏作者文风，该 Skill 位于 .github\题材专用Skills\ 目录。

> 核心理念借鉴自 [女娲 · Skill造人术](https://github.com/alchaincyf/nuwa-skill)：不是复制作者的文本，而是**提炼作者的可测量文笔 DNA**——让写/审/改 Skill 能按这套 DNA 约束输出，而不是凭空模仿。

1. **跨域复现验证**：每种核心发现必须在 ≥ 2 种场景类型中验证成立，否则降级为"场景特定习惯"。

## 文风可移植性评估（仿写场景强制）

> 完整评估方法（绑定度判断表、文笔内核提取、移植技法三步法、一致性检查）详见 `references/文风可移植性评估与移植技法.md`。

### 必须执行的硬规则

1. **文风-题材绑定度判断**：逐维度标注是 `题材绑定` / `作者独立`，决定文风能否跨题材移植。

## 多作者风格融合策略

> 完整融合策略（主辅法/分域法/交集法、冲突仲裁、命名注册规则）详见 `references/多作者风格融合策略.md`。

当需要把 2–3 位作者的文风特征融合到同一项目中时，支持三种融合策略：**主辅法**（推荐首用）、**分域法**（维度级分工）、**交集法**（共性优先）。

---
```text
作者 [A] → §一 句长 + §二 段落 + §七 情绪表达（节奏与情绪域）
作者 [B] → §四 对话 + §十 声口 + §十四之二 语气与语体（对话与声口域）
作者 [C] → §三 感官 + §六 比喻 + §十一 时间 + §十二 空间（感知与构图域）
```

**产出方式**：一份"综合风格模板"，每节标注数据来源作者。

#### 策略 C：交集法（共性优先）

对多位作者的同一维度分别统计，提取"多数成立"的共性规律作为综合基线。具体操作方法同作品蓝本交集法，将"蓝本"替换为"作者"即可。

### 多作者冲突仲裁

同作品蓝本冲突仲裁规则，另补充文风特有的冲突类型：

| 冲突类型 | 处理方法 |
| --- | --- |
| **声口趋同风险** | 若主风格和辅风格的声口差异化指纹均偏弱（人物句长差异度 < 0.2），融合后可能产生更严重的声口趋同。应引入第三位作者在该维度的数据作为参考基线，或明确降低综合模板在此维度的置信度 |

### 综合风格模板产出命名

综合风格模板写为：

```text
蒸馏产物/作者风格模板/[合成标识]-综合风格模板.md
```

命名规则同作品蓝本：主辅法用 `[主作者]-[辅作者]-综合`；分域法用 `[赛道名]-[题材]-综合`；交集法用 `[赛道名]-共性综合`。

### 在 Agents.md 中的注册

综合风格模板注册为一组关联条目：

```markdown
### 作者风格模板（合成）
- 合成标识：[如 "作者A-作者B-综合"]
- 主模板路径：蒸馏产物/作者风格模板/[合成标识]-综合风格模板.md
- 融合策略：[主辅法 / 分域法 / 交集法]
- 融合日期：YYYY-MM-DD
- 适用平台：[平台名] 或 默认
- 源模板：
  1. [作者 A] — 路径：蒸馏产物/作者风格模板/[作者A]-作者风格模板.md — 贡献维度：§一 句长 / §二 段落 / §七 情绪
  2. [作者 B] — 路径：... — 贡献维度：§四 对话 / §十 声口
```

合成条目与单作者条目在 `Agents.md` 中并列存在，名称以 `（合成）` 后缀区分。下游 Skill 自动发现时，**合成条目优先级高于单作者条目**。

### 单作者蒸馏 → 合成蒸馏的流程关系

同作品蓝本：默认流程先分别蒸馏各作者（各注册独立条目到 Agents.md），再做合成；可应要求跳过独立注册直接合成，但合成结果必须引用各源模板信息。

## 执行流程（概要）

> 完整执行流程（含 Phase 0-5 详细步骤、档案包结构、检查点表格、双 Agent 精炼细则）详见 `references/执行流程检查点清单.md`。

| Phase | 步骤 | 关键闸门/硬规则 |
| --- | --- | --- |
| **Phase 0** | 需求澄清 | 确认作者名、取样范围、聚焦维度；默认全 9 维 + 前 30 章 + 网络搜索 |
| **Phase 0.5** | 创建蒸馏档案包 | 必须创建 `[作者名]-作者风格档案/` 下 `sources/` + `references/research/` + `synthesis/` + `validation/`；不落档案不得标高置信 |
| **Phase 1** | 信息采集 | 按优先级采集 9+ 维度；信息源黑名单：知乎、微信公众号、百度百科 |
| **Phase 1.5** | 采样 Review | 输出质量摘要（样本量/一手占比/风险），用户确认后方可进入 Phase 2 |
| **Phase 2** | 统计与提炼 | 按模板逐项填充；追加跨域复现验证、神似层提炼、矛盾张力记录 |
| **Phase 2.5** | 提炼确认 | 输出提炼摘要（核心指纹/可量化字段/高风险估算/神似层摘要），用户确认后方可进入 Phase 3 |
| **Phase 3** | 产出与注册 | 生成模板 `.md` → 写入 `蒸馏产物/` → `Agents.md` 注册 |
| **Phase 4** | 质量验证 | 四项验证：留出样本回测、迁移干跑、反抄袭检查、生成力测试 |
| **Phase 5** | 双 Agent 精炼 | Agent A：可执行性审阅；Agent B：风格边界审阅 |

## 禁忌清单的来源区分（强制）

禁忌清单中的每条禁忌必须标注来源类型，不得混写：

| 来源类型 | 标注前缀 | 可靠性 | 下游处理 |
| --- | --- | --- | --- |
| 统计推断 | `[统计]` | 中—受样本范围限制 | 作为强约束参考，但允许在跨作品场景下被质疑 |
| 作者自述 | `[自述]` | 高—有作者自觉证据 | 作为硬门禁，不得违反 |
| 外部评论推断 | `[评论]` | 低—二手判断，需交叉验证 | 仅作为软建议，不得作为硬门禁 |

- 若同一条禁忌同时有统计推断和作者自述支撑，标注 `[统计+自述]`，可靠性最高。
- 在 Phase 1.5 采样 Review 中，必须单列"禁忌来源分布"。

## 三模板冲突仲裁规则（新增）

当作者风格模板、作品蓝本模板、写作研究模板同时作用于同一字段且约束不同时，按以下优先级裁决：

| 冲突场景 | 优先顺序 | 裁决逻辑 |
| --- | --- | --- |
| 同一字段三模板均约束 | 作者风格 > 作品蓝本 > 写作研究 | 用户显式指定优先于结构参照，结构参照优先于平台默认 |
| 作者风格与写作研究冲突 | 作者风格优先 | 一手统计 > 二手研究结论；但平台硬门槛（如"起点前 300 字必须有冲突"）不得被作者"慢热"风格覆盖 |
| 作品蓝本与写作研究冲突 | 蓝本优先 | 验证过的结构规律 > 通用研究建议 |
| 平台硬门槛 vs 任何模板 | 平台硬门槛优先 | 若写作研究中的某条约束标注了"平台硬门槛"（如起点追读率底线），覆盖作者风格和蓝本的同字段约束 |

**硬规则**：
- 冲突裁决必须在蒸馏报告中显式记录，不得暗中取舍
- 若裁决导致作者风格模板的某条约束被覆盖，必须在该约束旁标注覆盖来源与理由
- 若裁决后仍无法确定，保留冲突供用户决策，不得强行调和

## 风格DNA符合度审计

> 完整审计流程（审计维度表、JS 散度计算方式、综合符合度公式、符合度分级、审计报告格式、闭环动作、禁忌触发特殊处理）详见 `references/风格DNA符合度审计.md`。

蒸馏的终极检验标准：**用这套模板约束写出来的正文，和原作者本人的文风是否几乎一模一样**。

### 审计时机

当且仅当：
1. 存在通过 Phase 4 验证的**作者风格模板**
2. 下游 Skill 已产出可供比对的成品正文（≥ 3000 字）
3. 用户明确要求审计

### 核心方法

逐维量化对照。取原作者的非取样章节作为"自身波动基线"——产出正文的差异值越接近基线，仿写越成功。
