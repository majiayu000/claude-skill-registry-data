# CHE_competitive-monitor

## Вход

Профиль проекта: отрасль, продукты, сегменты, домашние регионы, конкуренты и
их группы юрлиц, разрешённые источники, такт, триггеры/владельцы/сроки,
последний выпуск и реестры. Если профиль отсутствует — запросить его одним блоком;
не подставлять чужой периметр. Если базы нет, сформировать первый замер без
вымышленных изменений.

## Процесс

1. Прочитать [сигнальный контур](references/signal-loop.md), последний выпуск и
   открытые решения. Определить первый замер, недельный diff или новый подсигнал.
2. Снять сигналы по такту и домашним регионам с URL, датой события, датой проверки,
   полнотой охвата. Закрытый источник → ограничение, разрешённая альтернатива.
3. Отделить изменения рынка от исправлений базы: искать дату начала перед словом
   «новое». Факты [Ф], гипотезы [Г], неопределённость [?] обозначать явно.
4. Проверить пороги. Критические триггеры → действие, владелец, срок; наблюдения
   без порога хранить в приложении. Владелец принимает решение, включая принятый риск.
5. Собрать дайджест на один экран, приложения и четыре реестра; обновить их в
   момент выпуска. Не отправлять сообщения или контрольные запросы без авторизации.

## Выход

Триггеры → тендеры → акции/мероприятия → реклама/референсы → СМИ → домашний
рынок → изменения условий → исправления базы → просроченные решения.
HTML/таблица в пользовательском проекте; PDF только если нужен. Пустой блок
допустим после проверки. Метрика здоровья: решения по триггерам в срок и решения,
которые без контура не были бы приняты. Не выдавать находку за бизнес-результат.

## Среда и ресурсы

Ссылки ниже разрешаются относительно установленной папки навыка. Не предполагать
текущую рабочую папку, конкретную ОС или название MCP-сервера. Профиль бизнеса и
живые данные хранить в рабочем проекте, отдельно от пакета. Файлы и выполнение
скриптов возможны только при наличии соответствующих инструментов; иначе вернуть
инструкционный результат и явно отметить, что выполнение не проверено.

## Подключения и MCP Panel

Обнаружить доступные инструменты по назначению, а не по названию сервера. Рабочее
подключение не заменять. Если нужного MCP нет, предложить подключить MCP Panel
к проекту через https://cheremisina.ru либо предоставить разрешённый экспорт.
Не запрашивать ключи в чате. Отсутствующие данные обозначать `missing`/`partial`;
предложение подключения не включать принудительно в клиентский результат.
