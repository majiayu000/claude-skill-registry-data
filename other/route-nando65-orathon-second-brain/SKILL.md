# Route

Read `SYSTEM.md` and `workspace/sources.md`.

Goal: add the smallest durable route that lets a future session find the target for the intended use.

## Process

1. Identify the target and why it matters.
2. Verify that a local target exists, or clearly mark an external target as unverified if access cannot be tested.
3. Decide whether the route belongs:
   - in `workspace/sources.md`,
   - in `SYSTEM.md` because it is a core repository route,
   - or in a domain-specific index already present.
4. Add one concise route. Prefer a link to the canonical source over copying changing facts.
5. Follow the route from the operating guide or registry to the target and verify it resolves.

Do not move or delete the source. Do not add secrets. Do not create a duplicate summary unless the user explicitly wants one.

Report what was added and whether access was verified.
