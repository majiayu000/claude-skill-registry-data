# 监控指标配置Skill

## 适用场景
为系统配置监控大盘与告警规则,保证问题可发现、可定位。

## 执行步骤
1. 确定监控对象:基础设施(CPU/内存/磁盘/网络)+ 应用(接口/依赖/线程池)+ 业务(核心指标)。
2. 覆盖黄金指标:错误率、延迟、流量、饱和度,每层都配。
3. 设置告警阈值:基线值 + 抖动系数,分级(P1 紧急/P2 重要/P3 提示)。
4. 配置告警收敛:防抖窗口、聚合去重、静默期,避免告警风暴。
5. 配置通知渠道与值班路由。

## 规范要点
- 告警必须有可行动性:收到告警知道「看哪、做什么」,纯噪音告警要删。
- 阈值来自基线而非拍脑袋:参考历史数据设定,忙时/闲时分开。
- 覆盖率要求:核心接口 100% 有指标,依赖(DB/Redis/MQ/第三方)100% 有监控。
- 告警分级与响应时限挂钩:P1 必须有人立即响应。
- 大盘分层:全局总览 → 服务详情 → 单接口/单链路,逐层可下钻。

## 输出模板
```
## 监控指标清单
| 层 | 指标 | 采集方式 | 大盘位置 |
## 告警规则
| 规则 | 条件 | 级别 | 通知 | 响应时限 |
```

## 自检清单
- [ ] 黄金指标四类全覆盖
- [ ] 阈值有基线依据
- [ ] 告警可行动、不刷屏
- [ ] 核心依赖全覆盖
