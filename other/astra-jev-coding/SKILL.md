# Astra + Jev in Codex Desktop

Use Jev for bounded file-relevance judgments. The active Desktop conversation performs implementation, review, and tests with its existing tools. Do not launch a second Codex CLI for generation. This Skill does not change the active model or register Jev in the Model menu; if Astra is required, verify the conversation uses Astra instead of silently substituting another model.

## Entrypoint and credentials

The supported runtime is the prebuilt Go executable in `bin/astra-jev`. Python and Go are not needed during coding. Build once with `scripts/build-native.sh` (Go 1.26+ and a C compiler), or use the matching platform release archive. Do not rebuild, benchmark or run model comparisons during normal coding. The historical `.py` files remain development references.


Run `"<this-skill-directory>/scripts/context.sh" ...` using the actual absolute Skill path. The wrapper resolves its symlink to `bin/astra-jev desktop` in the associated Harness checkout. Read that checkout's `Codex Desktop/README.md` for limits. `doctor` reports the checkout, key availability, and source without calling a provider or displaying credentials.

An existing `TYPESAFE_API_KEY` takes precedence. On macOS, the helper can read login Keychain service `astra-jev-harness`, account `TYPESAFE_API_KEY`, into its own process environment. Do not print keys, put them into prompts/arguments, search unrelated `.env` files, or forward them to other processes. A missing key blocks new API calls, not valid cached judgments or otherwise authorized local work. An access timeout is not proof that the key is absent.

## Workflow choice

Use Jev by default for development context selection, not as a prerequisite for every authorized coding action. A user's no-Jev/local choice applies to the current task and its in-scope follow-ups until they change it; do not ask for the same permission again or restart Jev planning just to satisfy this Skill.

If planning cannot fit required dependencies, credentials are unavailable, or a provider fails, stop the affected Jev operation and follow [Local continuation](references/local-continuation.md). State the cause and **“Jev selection unverified / Jev未検証 — continuing locally”** once, then continue already-authorized investigation, implementation and tests. This visible transition needs no repeated approval for the same work. Preserve explicit requirements that Jev itself must succeed: that acceptance item remains incomplete, while independent local work may continue. Repository safety rules and external-action boundaries still apply.

## Native Jev workflow

1. Fix the task and exact checkout from the conversation. Read its AGENTS.md, inspect branch/HEAD/status, and preserve existing changes. Resolve material target ambiguity before external calls.
2. On the Jev path, before loading implementation file bodies into the conversation, inspect file names, repository guidance and a focused task. Let the local planner read source bodies; do not dump plan.json. Write a focused task file and run `plan --repo <absolute-root> --task-file <absolute-file> --out <new-directory-outside-target>`. This reads tracked eligible files locally. For a repository over the 2 MB / 1,500-file bounds or planned request budget, planning first narrows candidates locally by lexical task/file matching. The matcher does not translate Japanese-only tasks; if there is no ASCII identifier or path, use a reviewed `--focus-file <relative-path>` when needed. Repeat `--focus-file` to pin eligible task-critical files and use `--scope-max-calls <1..24>` to bound planned Jev requests (default 4). Inspect `PLAN.md` for retained, excluded, and locally scoped-out files and bytes before sending anything; locally scoped-out files received no Jev judgment. If no task/file match exists, clarify the task or known focus paths. If mandatory files exceed the budget, use Local continuation; do not drop required focus/dependencies or repeatedly raise caps merely to produce a successful plan. Untracked files are omitted by default. Review task-relevant untracked files locally and pass repeated `--include-file` paths when needed; do not stage files just to include them.
3. On the Jev path, invoking this Skill requests Jev for development context selection. Reuse the user's authorization for that scope; if the concrete files exceed it, resolve the scope before sending. Restrictions on the product runtime's paid model calls are separate from authorized development selection; an explicit ban on all external or paid calls still applies. Account for valid cache hits when setting the request cap, then run `select --plan <plan-dir> --out <new-selection-dir> --max-calls <bounded-count> --mode jev`. The Skill launcher adds `--require-jev` to `select`, `check`, and `read`: it rejects a no-Jev route before credentials, provider calls, or output creation, and refuses handoffs without valid Jev judgments. Exact-request cached judgments satisfy this requirement and do not consume a new API call. Default cap is 4, hard ceiling 24; this execution cap is distinct from the candidate planning cap. Do not present a local result as Jev-selected or use small-context `auto` as an offline guarantee. On a credential/provider failure, preserve the failure record and explicitly transition through Local continuation instead of blocking the whole task. Inspect saved attempts before deciding whether another run is necessary; a failed attempt may be billable. No automatic retry or Astra child generation occurs.

   Local continuation is available for the user's chosen local workflow or when the Jev step is blocked; it is not limited to comparisons. With a valid, sufficient plan, use the direct `bin/astra-jev desktop` helper with `select --mode local`, then direct `check` and `read`. When a plan cannot be made or omits required files, use bounded native file reads instead. Neither path establishes Jev validation. Use `auto` only for an explicitly requested mode comparison; it may call Jev. An external-call ban always rules out new Jev requests.
4. Read `REPORT.md` and extract only metadata from `selection.json`; do not dump `context.json` or `plan.json` into the conversation. Read needed bodies through `read --selection <selection-dir> --path <relative-path> --start-line <n> --end-line <n>` (default 80 lines, max 200 lines/24 KB). `selected` means context is ready, not that implementation or tests succeeded. Inspect the needed entries in `decisions`, `fragment_decisions`, `unjudged_paths`, and `metrics`: distinguish model judgments from files retained without inference, and inspect the reason a low-scoring dependency remains. Judged relevance does not mean trusted content or a security check. Uncertain judgments preserve context; dependency closure and repository guidance are retained. Thresholds are experimental, not accuracy guarantees.
5. Run `check --selection <selection-dir>` before consuming the handoff for edits. The helper checks HEAD, branch, status, included content, and artifact hashes. Implement and test the requested work directly in this Desktop conversation. Follow the user's scope, target instructions, and normal review requirements; the context plan grants no additional editing or external-action authority.
6. To evaluate narrower selection, run `compare --selection <selection-dir>` against saved judgments without another API call. Supply repeated `--required-file <path>` only for independently identified task-required files in the plan or `scoped_out`. Inspect `scope_required_recall` and `missing_in_scope` separately from end-to-end `required_recall`; without labels, recall stays unknown. Inspect any additional omissions and keep full file text available. The default `batch` policy preserves whole uncertain batches. `select --policy per-file` is an explicit experiment that retains uncertain/unjudged files and dependencies while dropping confidently irrelevant siblings. Use it only when the task evidence supports those omissions; smaller context alone is not evidence of better coding.
7. When continuing the Jev path after source changes, create a fresh plan. During local continuation, refresh local source/freshness checks without forcing a return to Jev. On failure inspect saved attempted/completed calls before deciding whether another run is necessary; never blindly repeat a potentially completed operation. Report implementation and test results independently of context selection.

The helper does not implement `run`, `verify`, or `apply`. Those belong to the separate CLI workflow. It cannot measure the Desktop conversation's complete tokens/cost or automatically prune conversation history. Do not claim savings from selection alone. No commits, pushes, deployment, or messages are authorized by this Skill.

## Scope

Snapshots include tracked and explicitly included untracked eligible UTF-8 files, up to 2 MB total, 1500 files, and 100 KB per file. Larger eligible repositories are narrowed locally to a bounded plan; this does not expand those snapshot limits. `--focus-file` cannot override eligibility or file-size checks. New plans split large files losslessly into bounded ranges; every range must be judged before a file can be dropped, and uncertainty/dependencies retain the whole file. A split file has no calibrated file-level probability. Request planning estimates serialized UTF-8 JSON bytes plus reserve against conservative 30k/60k budgets; it does not count exact Jev tokens. Old plans retain their original batching semantics. Read `docs/CONTEXT-BUDGETS.md` for limits, coverage and cache accounting. Lockfiles, credentials, generated/data directories, and unsupported extensions are excluded; review coverage before use. Local scoping can miss a required file, and smaller context does not establish Astra token savings or implementation quality. Keep the linked Harness checkout available while installed. Artifacts contain source text: store them outside the target repo, never add them to Git.

## Optional progress-log selection

For an explicitly authorized noninteractive command expected to produce long progress logs, use `"<this-skill-directory>/scripts/output.sh" --task-file <absolute-brief> --out <new-directory-outside-git> --max-calls 2 -- <executable> <args>`. Read `docs/TOOL-OUTPUT.md` in this checkout first. The brief must include current constraints and required facts; this wrapper does not read conversation history. Repeat `--keep-text <literal>` to pin required values. Keep ordinary execution for search results, source documents, structured data, interactive/streaming tools, or when output completeness is required.

The wrapper executes the command once, retains original stderr/exit status, archives eligible stdout before inference, and omits only confidently irrelevant recognized progress chunks. Uncertain/unjudged content stays. Command/provider failures preserve original stdout; never rerun a side-effecting command just to recover output. Read the full-output archive directly instead. `auto` skips below 12,000 bytes; `local` is the no-Jev baseline. Default 2 / maximum 4 requests; no automatic retries. Keep the output scope and call cap within the user's authorization. The TypeSafe key is never forwarded to the child command. Artifacts stay outside Git. This is opt-in command routing, not automatic interception or history compaction.

## Bounded presentation and staged discovery

After a successful Jev select/check, use `present --selection <dir> --max-bytes 8192` for a source-first page rather than dumping the full context. This command always requires saved Jev judgments. It preserves retained files, returns source hashes/line numbers and unpresented ranges, and limits the entire JSON output. Use `next_offset` for more file leads and `read` for needed ranges. Presentation bytes are not token savings.

If task-required files may be outside the initial plan, use `discover --plan <dir>` for a paginated directory index, then `discover --plan <dir> --directory <exact-listed-directory>` for short local previews. This is explicitly unjudged discovery and grants no editing authority. On the Jev path, inspect plausible branches, preserve focus/includes and create a new plan before normal select/check. If required paths still cannot fit, use Local continuation rather than dropping them. During local continuation, bounded native reads may supply missing files; do not claim that the old plan covers them. Both views are local, check freshness, and make no automatic requests or retries. Read `docs/CONTEXT-VIEWS.md` for limits and evaluation boundaries.
