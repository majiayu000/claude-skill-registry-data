# UI自动化脚本开发Skill

## 适用场景
自动化测试环节,为 Web/移动端关键路径开发 UI 冒烟自动化脚本,保证脚本稳定可维护。

## 执行步骤
1. 选型评估:按团队技术栈、维护成本、运行速度评估框架;具体框架/工具的 API 与参数以官方文档为准,不凭记忆编写。
2. 场景选取:只自动化关键路径冒烟(登录、核心业务主流程、支付/下单链路),不追求 UI 全量覆盖。
3. 定位策略:优先稳定属性(id/data-testid),其次语义化定位(role/label),禁止依赖样式类名与绝对坐标。
4. 脚本编写:每步操作前校验页面状态,步骤间解耦,断言写在关键节点。
5. 稳定性处理:
   - 等待:优先显式等待元素状态(可见/可点击),禁止固定 sleep 凑合。
   - 重试:网络抖动类失败重试 2-3 次,每次重试记录结果。
   - 失败留证:自动保存截图、DOM 快照、执行日志。
6. 运行与维护:接入 CI 定时执行,定位器变更随版本同步更新。

## 规范要点
- 脚本可重复执行:用例间数据隔离,不依赖执行顺序,不依赖上次执行残留。
- 断言是脚本灵魂:只点击不校验等于没测,每个关键动作后必须有状态/结果断言。
- 结果如实呈现:失败用例报告真实失败原因,不得通过无限重跑掩盖问题;多次执行结果不一致的用例单独归类「flaky」并跟踪整改。
- 未执行的用例标注未执行,不得计入通过。
- 定位器失效导致的失败归类为脚本缺陷,与产品缺陷分开上报。
- 具体框架 API、浏览器驱动能力以官方文档为准。

## 输出模板
```
## UI自动化脚本交付说明
| 脚本编号 | 覆盖链路 | 框架 | 定位策略 | 等待/重试策略 | 断言点 |
## 冒烟执行报告(通过/失败/flaky/未执行)
## flaky 用例清单(附整改跟踪)
```

## 自检清单
- [ ] 覆盖关键路径,未过度自动化
- [ ] 每条用例有明确断言
- [ ] 显式等待 + 有限重试,无裸 sleep
- [ ] 失败有截图/日志证据
- [ ] flaky 单独统计并跟踪
