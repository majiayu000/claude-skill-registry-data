# 交互流程设计Skill

## 适用场景
PRD 明确后,为核心场景设计交互流程,确保主路径通畅、异常分支有出口,不出现死路。

## 执行步骤
1. 选定核心场景(登录注册、下单支付、提交审核等)。
2. 画主流程:起点 → 步骤 → 终点,标注每步的输入与校验。
3. 补异常分支:校验失败、超时、权限不足、资源不足、重复提交。
4. 补状态分支:登录/未登录、新客/老客、有无数据。
5. 检查每个分支都有出口(回到主流程/明确终止提示),无死循环。

## 规范要点
- 每步标注:触发动作、系统校验、成功去向、失败去向。
- 失败必须给用户可理解的反馈(提示 + 可恢复操作),禁止静默失败。
- 耗时操作必须有加载态与超时处理(重试/取消)。
- 涉及资金/权限/数据变更的流程,必须含二次确认步骤。

## 输出模板
```
流程:订单支付
[进入收银台] → 校验登录态(未登录→跳登录,回跳收银台)
  → 选择支付方式 → [确认支付](二次确认)
    → 调起支付 → 加载态(10s 超时→重试/取消)
      → 成功 → 支付结果页(可查看订单)
      → 失败 → 失败页(原因 + 重试/换支付方式)
```

## 自检清单
- [ ] 主流程步骤完整
- [ ] 异常分支全覆盖且有出口
- [ ] 无静默失败
- [ ] 资金/权限类操作有二次确认
