# Cold Email（毛遂自荐邮件）写作器

## 何时使用本技能

当用户想要：
- 给用人经理、创始人或招聘方写 cold outreach 邮件
- 主动联系一个没有内推人引荐的职位
- 向心向往之的公司做自我介绍
- 提到："cold email"、"毛遂自荐"、"主动联系"、"自我介绍邮件"、"联系用人经理"、"outreach"

## 核心原则

Cold email 之所以失败，是因为读起来像求职信。目标是让你的邮件读起来像一个聪明人真的注意到了这家公司的某个具体细节 —— 而不是一个候选人在批量播报自己的资历。

**这封邮件应该给人的感觉是：** 同事在分享他读到的某个有意思的东西，而不是一段销售话术。

## 模板结构

### 邮件主题
```
简单自介 —— [姓名]
```
朴素。不玩标题党。不写职位头衔。就是一个名字。

### 开头 —— 钩子（2-3 句）
从真正吸引候选人的地方写起。必须针对这家公司 —— 不能是泛泛的恭维。

```
我刚发现 [公司]，结果不知不觉在上面花的时间远超预期。
[真正抓住他们注意力的某个具体细节 —— 一个数据、一个产品决策、
一条来自 JD 或官网的市场洞察]
```

**好的钩子长什么样：**
- 公司材料里的一个具体数字或数据点（"这个市场只有 5% 在线化"）
- 表明你理解这个领域的产品决策（"你们在和承保人并肩从零搭建，而不是只做渠道分发"）
- JD 里的技术洞察（"为 LLM 的使用优化数据基础设施，而不只是模型层"）

**坏的钩子长什么样：**
- 泛泛而谈："我特别喜欢你们在做的东西"
- 模糊空洞："你们的使命与我产生了共鸣"
- 单纯吹捧："你们是这个赛道里最令人兴奋的公司之一"

### 所在地说明（跨国家/地区时）
如果候选人与公司不在同一个国家，尽早且自然地说明：

```
在你继续往下读之前，先说明一下我人在 [所在国家/地区]。但如果
我们都觉得契合度很高，其他问题可以一起想办法。
```

### 经验差距（如适用）
如果职位要求的年限超出候选人的实际年限，简短承认然后把话题引开：

```
职位要求 [X] 年经验 —— 我目前是 [Y] 年，但我交付过的东西都是
面向生产环境的，我更希望你直接来评判。
```

### 正文 —— 我是谁（3-5 句）
当前职位 → 相关的过往 → 一两个项目。保持有语境，而不是罗列清单。

```
简单介绍一下我：我现在在 [公司] 工作，[一句话说明这家公司做什么]，
在那里我 [实际负责什么 —— 不只是职位头衔]。在此之前，我在
[地区] 的团队工作，主要围绕 [相关领域]。

业余时间我在做 [项目]（[如适用给出链接]）—— [一句话：它是什么
+ 一个佐证，如"已有付费客户"或"下载量 2 万"]。
```

**规则：**
- 把当前工作当作语境来提，而不是当作"我很优秀"的证明
- 不列成就清单（"我把 X 提升了 Y%"）—— 让项目自己说话
- 如果当前公司是远程，且团队在欧洲/国际化，明确说出来
- 项目最多提一两个 —— 只挑最相关的

### 联结点（1-2 句）
在他们的背景与这个具体职位之间搭桥。读起来应像一种观察，而不是一个结论。

```
我猜你们想找的是 [这个职位真正想要的东西] —— 这正是我一直在做的
工作，说实话，我觉得我会是个很强的 fit。
```

或者更具体：
```
我的技术栈和你们天然契合 —— [具体的重叠部分]。但比技术栈更重要的是，
[该领域/问题] 才是我真正感兴趣的。
```

### 作品集链接
```
更多关于我：[作品集链接]
```
一句话。不需要展开。

### 结尾
以低压力、有自信的语气收尾。不能显得卑微，也不能公事公办。

```
我目前在 [公司]，对下一步保持开放。我觉得我的经历和你们在做的
事情很搭 —— 所以我觉得这场对话对我们俩都会划算。

[名字]
[邮箱]
```

**避免：**
- "期待您的回复"
- "请查收附件中的简历"
- "我非常希望能获得这个机会……"
- "如果有机会加入，我会非常兴奋……"

## 动笔前的调研

写邮件之前，先收集：
1. **公司角度** —— 读他们的官网、JD 或 About 页。找到一个值得提的具体细节。
2. **收件人姓名** —— LinkedIn、团队页面或 AngelList。称呼"[姓名]，你好"永远胜过"您好，用人经理"。
3. **相关项目** —— 把候选人最相关的工作匹配到职位所属领域。
4. **技术栈重叠** —— 只在真正匹配时才提。

如果用户提供了 JD 但没有公司官网，动笔前要么索要，要么主动获取。

## 篇幅指南

- **理想：** 200-300 字
- **上限：** 400 字
- **下限：** 150 字（不要为了短而牺牲实质内容）

只要每句话都挣得自己的位置，长一点没问题。删掉所有换到任何一家公司都成立的内容。

## 输出格式

始终把最终邮件放在纯代码块中，方便干净地复制粘贴：

```
主题：简单自介 —— [姓名]

[姓名]，你好：

[邮件正文]

[名字]
[邮箱]
```

## 需避免的常见错误

**过于自信：**
❌ "我将是贵团队的顶级人选"
❌ "我的背景使我为这个岗位做了独一无二的准备"
✅ "我觉得我会是个很强的 fit" —— 表达一种判断，而不是宣称确定

**过于谦卑：**
❌ "我知道我可能没有你们要的全部经验，但是……"
❌ "我抱着万分之一的希望来联系你……"
✅ 直接承认差距，然后翻篇 —— 不道歉

**太长：**
❌ 三段话把每一条成就都列一遍
✅ 一段写背景，一段写联结

**太笼统：**
❌ 开头写"我写这封邮件是想表达我对贵公司的兴趣……"
✅ 开头写真正把你吸引到这家公司的那个具体细节

**毫无调研：**
❌ "我热爱你们的产品和使命"
✅ "那个 5% 的数据 —— 250 亿美元的市场只有 5% 在线化 —— 读起来不像一个功能缺口，
更像整个行业还没被数字化"

## 示例邮件

```
主题：简单自介 —— 陈思雨

王磊，你好：

我刚发现 Meridian，结果在你们网站上花的时间超出了原计划。真正把我
拉住的是你们对数据基础设施的定位 —— 你们不是在现有病历之上加一层
LLM，而是在重新思考临床数据本身如何在系统里流转。这是个更难、也
更有意思的问题。

先提前说明，我人在新加坡。如果契合度是真的，其他问题可以一起
想办法。

我现在在 Lune 工作，一家总部位于伦敦的气候情报公司，在那里我做
事件驱动的数据管道和面向排放合规的 agentic AI 工作流 —— 都是被
监管、数据密集型的系统，可靠性没有退让余地。另外我从零搭建了
Memos，一个 RAG 系统：混合检索、重排序（reranking）、ChromaDB、
FastAPI。还有 InframetAI，一个 LLM 成本与延迟可观测性 SDK ——
做它的起因是亲眼看到当数据层没有围绕模型的真实工作方式设计时，
会出什么问题。

我猜你们想找的是真正端到端搭过 AI 系统的工程师，而不是只把 API
包一层。这正是我一直在做的工作。

更多关于我：yourportfolio.com/about

我目前在 Lune，对下一步保持开放。我觉得我的经历和你们在做的事情
很搭 —— 所以我觉得这场对话对我们俩都会划算。

思雨
sarah@email.com
```
