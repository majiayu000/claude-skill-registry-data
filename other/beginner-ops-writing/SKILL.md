# 新手操作说明

属于开源包 Solo to Team · 一人成队（solo-to-team-skills）。

## 含什么

写给「电脑／手机不熟的人」看的操作步骤写法：原则条目、自检清单、2 个虚构示例（假应用、假界面文案，一眼可辨虚构），每例附不合格写法对照。本技能只管**怎么把步骤写清楚**，不管派谁做、也不管交活前怎么核证据。

## 适合谁

- 需要请负责人或委托方本人点一下、复制一行、打开某一开关的执行人
- 经常写「点复制／点确定」却害对方找错按钮的人
- 想让不了解内情的新手照着做一次就成、少追问的小团队总控

## 怎么用

1. 按包根 [README](../../README.md) 里你所用宿主那一段加载本技能；不装也行，直接把本文当写法参考读。
2. 凡要请新手在屏幕上点、复制、选择、输入：先按下文原则起草步骤。
3. 发出前自检：每步是否只有一个动作、是否点名唯一、是否写了「做完会看到什么」、有没有凭猜写位置。
4. 位置或字样没核实过：先看屏／请对方截图再写，不猜。

## 依赖

- **写法本身不绑平台**：原则适用于任何需要「请人在屏幕上跟做」的协作环境，不用任何工具、不要额外权限，记事本里也能照着写。
- **本包在各宿主上能否加载、怎么调用**：见包根 [README](../../README.md)「各宿主怎么装、怎么叫」，本技能不另写安装步骤。其中 Grok Bot 为「支持，需手动配置」：把本文 Save 为私有技能后按名调用；Claude Code 结构已备、不在首发支持之列。
- 若某一步依赖某产品的专有界面（例如某笔记 App、某系统设置页），须在步骤里写明「在某某产品界面」；没在该产品上跟做核过，不写「已支持」。

## 示例

见下文第 4 节：示例一「在假笔记设置页只开一个开关」，示范点名唯一、不碰另外两项、做完会看到什么、没看到就停；示例二「请本人来点一下」，示范只有本人能做的那一步怎么写。两例均为虚构，无真实密钥、二维码、可识别屏文案、真路径、真账号。

## 验证到哪

原则提炼自「一人总控＋多助手」队内长期使用的操作说明写法；公开包保证的是**步骤写法可照做**。能否减少「点错／追问」，见同仓 `../ops-case-notes/` 里各条「仍未解决」和文末验证说明；本技能正文不下效果结论。

一句话：**写给屏幕前的新手看——一次一步，点名唯一，说清做完会看到什么。**

## 1. 目的

操作说明是给**不了解内情的人**用的。读者看不见你脑子里的上下文，也认不出「那个复制」。目标只有一条：对方照着做一次就成，不必回头追问「点哪个」。

## 2. 原则

### 2.1 大白话，只写屏幕上能看见的

- 用日常说法，少用对方屏幕上根本看不到的黑话。
- 每步说清：**在屏幕哪儿、长什么样、第几个、挨着什么**。
- 不提对方这会儿看不见的后台状态。

### 2.2 一次一步；说清做完会看到什么

- 每步只安排**一个动作**（点一下、滑一下、复制一行、打开一个开关）。
- 写完这一步后，对方应看到什么：颜色变了、开关到右侧、剪贴板有字、某行高亮等。
- 没看到预期结果：写明「停下，告诉执行人／总控，不要接着点」。

### 2.3 几样长得像时，点名唯一一项；其余写「不碰」

- 屏幕上有两项以上都能「复制／确定／开」时，必须点名**对的那一个**。
- 写法粒度建议：`第几行 ＋ 那一行开头的字 ＋ 点哪边哪个图标`。
- 例（结构示范，非真界面）：「点第一行『DEMO-POST 到』最右边的复制图标；第二行、第三行不碰。」

### 2.4 没核实过的位置，不凭猜

- 按钮在哪、文案是什么，没亲眼看过或没对照过当前截图，就先别写死。
- 能请对方截一张、或执行人先看清再写，更好；能在图上圈出目标最好。
- 「应该在设置里」这类猜测，不算合格步骤。

### 2.5 和常见系统明显不同处，一句带过

- 若某一步在 Windows 与 Mac（或桌面与手机）上位置／叫法不同，用**一句**对照即可，不展开教程。
- 例：「若你用的是另一套系统，同类开关可能在『系统偏好』而不是『设置』里——以你屏幕上实际看到的为准。」

### 2.6 短而准

- 每步一两句；不铺陈解释、不讲原理故事。
- 需要备注时，把备注压成半句，挂在动作后面，不另开长段。

### 2.7 发出前谁过一眼

- 步骤写完后，最好由**看过同一块屏幕**的人逐句核一遍再发给新手。
- 未核过的说明，不直接推给负责人／委托方本人操作。

## 3. 自检清单（写完勾一遍）

- [ ] 每步是否只有一个动作？
- [ ] 是否写了「在哪儿／长什么样／第几个／挨着什么」？
- [ ] 有没有两样以上长得像却没点名唯一、没写「不碰」？
- [ ] 是否写了「做完会看到什么」和「没看到就停」？
- [ ] 位置和文案是否核实过（不是猜的）？
- [ ] 凡须本人亲自完成的步骤，只写请本人来，不写代做办法。
- [ ] 步骤若依赖某产品专有界面，是否写明了产品名？未验证是否避免了「已支持」？

## 4. 虚构示例

> 以下应用名、界面文案全部虚构，仅示范写法。请勿对照任何真实产品。

### 示例一：在假笔记设置页只开一个开关

**场景**：请新手在桌面应用「云朵便签 Demo」（虚构）里打开「同步到演示本」。设置页上有三个长得很像的开关。

**发给新手的步骤（合格写法）**：

1. 打开应用「云朵便签 Demo」。点左侧栏最下面一项「设置」（文字左边有个齿轮图标）。  
   **做完会看到**：右侧换成一整页，顶上标题是「演示设置」。
2. 在「演示设置」页往下滚，滚到分组标题「同步（演示用）」就停。这一组从上到下有三个开关，左边的字依次是：  
   - 「同步到演示本」  
   - 「同步到练习本」  
   - 「同步到归档本」  
   **做完会看到**：三行字都在屏幕上，每行右边各有一个圆钮，现在都在左边。
3. **只开第一行**「同步到演示本」：点它右边的圆钮。  
   **「同步到练习本」「同步到归档本」都不碰。**  
   **做完会看到**：第一行的圆钮滑到右边、轨道变亮；下面两行的圆钮仍在左边。
4. 如果找不到「同步到演示本」这六个字，或点了圆钮没滑到右边：**停下**，截一张当前屏幕发给执行人，别的开关都不要点。

**不合格写法（对照用，勿照做）**：

> 「进设置把同步打开。」

问题：没说设置在哪、三个同步开哪个、开完是什么样，也没说出错了怎么办。新手很可能三个全开，或开错一个还以为做完了。

> 「在设置里找到同步那组，把第一个打开，应该就行了。」

问题：比上一句好，但「第一个」没写字样，界面改版、顺序一变就会点错；「应该就行了」是猜，没写做完会看到什么、没看到怎么办。

### 示例二：只有本人能做的那一步

**场景**：执行人已在虚构应用「小橙记账 Demo」里备好一份导出，最后一步「确认导出」须由账户本人点，执行人不能代点。

**合格写法**：

1. **这一步请你本人来点**，我这边不能代你点。  
   在「小橙记账 Demo」顶部点「导出」，弹出的小窗里只有一个蓝色按钮「确认导出」，点它。  
   **做完会看到**：小窗关掉，顶部出现一条绿字「已导出（演示）」。
2. 没看到绿字，或弹窗里不止一个按钮：**停下**，截图发我，不要点别的。

**不合格写法**：

> 「你别管了，我远程替你点。」

问题：把只能本人做的事改成代做。合格做法是请本人来点，并把那一下写清楚。

## 5. 和同仓其他技能怎么分工

| 技能 | 管什么 |
|---|---|
| 本技能 `beginner-ops-writing` | **怎么写**给新手看的跟做步骤 |
| `../dispatch-accept-verify/` | 活派出去以后怎么登记、到点查、回「已接」 |
| `../evidence-before-done/` | 说「做好了」之前怎么亲手核证据 |

三支可一起装：先写清步骤（本技能）→ 派人跟做并收回来（`dispatch-accept-verify`）→ 交活前核过再宣称完成（`evidence-before-done`）。

## 6. 平台说明（摘要）

- 本技能教的是**说明文写法**，不绑定某一家助手产品的专有命令。
- 本包在八家宿主上的加载与调用状态，统一见包根 [README](../../README.md)；本技能不重复列各家装法。
- Grok Bot：支持，需手动配置（Save 为私有技能后按名调用）。装上技能只是让助手能照这套写法起草步骤，不会因此多出任何自动化；这只指 Grok Bot 这一款产品，不代表 Grok 的其他客户端。
- Claude Code：结构已备，不在首发支持之列。
- 任何「请在某某 App 界面操作」的步骤，以该 App 当前界面为准；界面改版后须重核文案与位置。
