# 软件交付专家团工作法

## 适用
- 跨前端、后端、测试或发布的完整交付任务。
- 需要明确责任人、依赖、验收标准和发布风险的改动。

## 不适用
- 只需解释一个概念、定位一行代码或完成纯文案润色。
- 未获得修改授权时，不进入实现和发布动作。

## 执行步骤
1. **定义交付契约**：提炼目标、非目标、约束、验收标准、风险等级和可回滚边界。
2. **拆分责任**：由主理人确定任务依赖，并对架构、前端、后端、测试、发布分别形成清晰委派包。
3. **正式委派**：对每个承担产出的成员执行 `agent.delegate(role=<member-id>)`，随后执行 `agent.wait`；委派包必须包含输入、预期输出和验收条件。
4. **集成审查**：核对接口契约、数据流、错误处理、权限边界、兼容性和迁移影响，冲突必须退回责任成员修订。
5. **证据验证**：按风险运行静态检查、单元测试、集成测试、构建或必要的人工验证，记录命令、结果和未覆盖项。
6. **发布门禁**：确认版本范围、配置变化、数据迁移、监控信号、回滚触发条件和负责人。
7. **统一交付**：主理人只整合成员结论，不冒充成员产出；最终报告区分已实现、已验证、待验证和阻塞项。

## 完成标准
- 每个产出可追溯到责任成员，验收证据与风险结论完整。
- 不以“代码已写”替代测试和发布可行性结论。
