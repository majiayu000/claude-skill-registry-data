# /tour

Goal: the user finishes knowing where their information lives, what happens automatically, and what's always their call. Show, don't lecture. One stop at a time; after each, ask "Make sense? Want to try it?" and wait. Let them skip any stop. Keep each explanation to 2–4 sentences. `HOW-IT-WORKS.md` is the written version; mention it at the end.

## Try it with sample data first (before setup)

If `profile/preferences.md` still says `SETUP: not done` (the user hasn't set up yet), offer this once before stop 1: "Want to try it with sample data first? I can make a separate practice copy filled with a made-up job search (Alex Rivera), so you can click around the boards and pages before you share anything about yourself. Your own folder stays exactly as it is." If they'd rather set up now, suggest `/start` instead. If they say yes:

1. Run `bash .claude/skills/tour/scripts/make-sample.sh` (Windows without bash: `powershell -NoProfile -ExecutionPolicy Bypass -File .claude\skills\tour\scripts\make-sample.ps1`). It makes a new folder **next to** this one, named after it plus " (sample - Alex Rivera)", with a copy of the app and the sample data. It never writes into this folder; it refuses a folder that already exists, a spot inside this folder, and links.
2. If it says the folder already exists, it's probably a sample they made before: offer to open that one, or to make a second one with the name on the `suggest:` line (add `--name "<that name>"`, or `-Name` on Windows), or to remove the old one first (step 5).
3. Tell them where it is (the `open:` line) and how to open it, in plain words: in the Claude desktop app, start a new session and choose that folder; in a terminal, open the folder and start Claude there; in Codex, add it as a new project. The app asks whether to trust the new folder (say yes, so the boards show). Everything in it is made up: Alex Rivera, the companies, the people, the emails. Nothing is sent unless they press Send in Gmail themselves.
4. In the sample they can try `/pipeline`, `/outbox`, `/contacts`, `/job-inbox`, `/apply-kit`, `/today`, `/mock-interview`, the dashboard and the flashcards. When they're ready for the real thing, they come back to **this** folder and type `/start`.
5. When they're done with it, offer to delete it: `bash .claude/skills/tour/scripts/make-sample.sh --remove` (Windows: `make-sample.ps1 -Remove`, plus `--name`/`-Name` if it has a different name). It deletes only a folder it made that still holds the sample, and refuses anything else. Run it from this folder, not from inside the sample.

**Never put the user's own details into a sample folder.** If a session opens inside one (it has a `.sample-workspace` file and the preferences say `name: Alex Rivera (sample)`), say once that this is the practice copy. The tour there can use the sample rows, drafts and pages for every hands-on step (they're made up, so no "Practice" rows are needed), and must not run `/start` there: if the user starts telling you about themselves or asks to set up, point them back to their own folder.

**First, check the panels:** is a tool named `mcp__interview-room__interview_start` listed (loaded or deferred)? If not, say once: "Panels need a recent Claude Code version and a trusted folder. Updating may help, but you don't need them: everything works right here in the chat (say 'show my board', 'show my outbox', 'mock interview')." Then use the chat versions for stops 3–5 (show the tracker change by asking you, show the draft text in chat, run the mock interview in chat).

**The tour never changes the user's real records.** Every hands-on step uses practice data only: one practice job row (company `Practice Co`, role `Practice Role - delete me`, status `interested`, `source` = `tour`, next step "Try the board", due today), added with a normal file edit, and practice files whose names or subjects start with "Practice". Remove all of it at the end of the tour, or as soon as the user stops early. If the tracker has no jobs, add the practice row when you reach stop 3. If it already has real jobs (or contacts), show those read-only and narrate what the buttons would do; offer the practice row only if the user wants to press buttons themselves, and then point them to that row only.

## Stops

1. **The big idea.** Setup built this from the user's own resume. Their facts live in `profile/master-resume.md`; every job lives in `jobs/tracker.csv` (offer to show it, and mention it opens in Excel). Claude reads and updates these; panels and pages show them.
2. **Today.** Run `/today` for real and point out where each line came from. Mention the short pop-up when a session opens (due alerts): it lists up to 3 things due today or tomorrow and stays quiet when nothing is due; `/today` always has the full list.
3. **The board.** Ask them to type `/pipeline`. On the practice row only (never a real job), walk them through pressing **Update…**, changing the stage, and pressing **Mark next step done**. Then read that row of `jobs/tracker.csv` back to them to prove it saved. No practice row (they have real jobs and didn't want one)? Point at their real jobs and explain what each button would do, without pressing anything. If panels are available, point out the one-line summary above the prompt (it also shows contact follow-ups due and new job leads). (No panels showing? Do the same changes by asking you in plain English.)
   Then, in one or two sentences, name the other boards without walking through them: `/job-inbox` (new openings from `/find-jobs` to save or skip), `/contacts` (their networking board), and `/apply-kit` (every answer an application form asks for, with Copy buttons, while they fill it in). Without panels, the same things work in chat: "show my contacts", "job inbox", "apply kit".
4. **Drafts and the Outbox.** Draft a harmless practice email to the user themselves into `outbox/` (subject "Practice: Outbox tour", no `job:` or `contact:`). Ask which of their own addresses to send it to, offering the one in their master resume if there is one; don't assume it's the address their Gmail is connected to. If they'd rather not, skip the email demo. Never invent an address or save a placeholder recipient. Ask them to type `/outbox` and look at **Create Gmail draft…** (only works if Gmail is connected), **Copy**, **Discard…**. Explain that nothing sends unless they press the button, and that `outbox_mode` is `draft-only` by default (if it says `send`, tell them not to press Send on the practice draft). Let them discard the practice draft, and if they made a Gmail draft from it, remind them to delete that one in Gmail.
5. **Interview Room.** Offer a one-question practice: run `/mock-interview` with style `behavioral` and 1 question ("Tell me about a time you improved a process."). Show the mic or dictation, the clock, the **Done answering** button, and the scorecard. If the panel shows a tip about downloading a higher-quality voice, point it out (Mac only; a minute in System Settings, and it makes the interviewer sound far more natural).
6. **Pages.** Open `pages/flashcards.html` (give them the path to double-click). Show flip and swipe. Explain the dashboard is a snapshot ("refresh my dashboard") and the portfolio is their public one-pager. If this session has the Artifact tool, offer to publish the flashcards privately for their phone, following the `pages` skill.
7. **Safety switches.** Show `autonomy` and `outbox_mode` in `profile/preferences.md`, what each setting does, and that only the user changes them. Mention Claude asks before editing their master resume. Add one line on scams: job seekers are a top target, so Claude flags suspicious recruiter mail, and a real employer never asks for money or a check deposit, or for bank details before a written offer; ID and right-to-work checks before an offer are normal in some countries, but only through the employer's official process. And one on backups: `/my-data` saves a private copy of everything in one step.
8. **Finish.** Remove any practice job (re-read the tracker and delete only the `source` = `tour` row), practice draft, and the practice mock-interview debrief file you created, plus any practice lines in `history/activity.md`; if you refreshed the dashboard during the tour, refresh it again. Then give them the same "first week" plan as `/start` (draft notes to their former managers, pick jobs to match their weekly application goal in `profile/preferences.md`, one mock interview). Commands to remember: `/today` and `/menu`; their board is `/pipeline`; and if they're ever unsure what they want, `/explore`. Point to `HOW-IT-WORKS.md`. Ask what they want to do first.
