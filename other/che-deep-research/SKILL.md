# CHE_deep-research — Deep Research

## Назначение

Генерирует отчёт с верифицированными источниками через структурированный конвейер: накопление доказательной базы, управление идентификаторами источников, верификация утверждений и прогрессивное создание отчёта.

**Принцип автономности:** Работать независимо. Делать допущения из контекста. Останавливаться только при критических ошибках или непонятных запросах. Явно указывать ключевые допущения в Введении и Методологии.

---

## Дерево решений

```
Анализ запроса
+-- Простой поиск? --> СТОП: использовать WebSearch
+-- Отладка? --> СТОП: стандартные инструменты
+-- Нужен комплексный анализ? --> ПРОДОЛЖИТЬ

Выбор режима
+-- Быстрое исследование --> quick (3 фазы, 2-5 мин)
+-- Стандартное исследование --> standard (6 фаз, 5-10 мин) [DEFAULT]
+-- Критическое решение --> deep (8 фаз, 10-20 мин)
+-- Исчерпывающий обзор --> ultradeep (8+ фаз, 20-45 мин)
```

**Допущения по умолчанию:** Технический запрос = техническая аудитория. Сравнение = сбалансированная перспектива. Тренд = последние 1-2 года.

## Фазы конвейера

| Фаза | Название | Quick | Std | Deep | Ultra |
|------|----------|-------|-----|------|-------|
| 1 | SCOPE (определение границ) | Д | Д | Д | Д |
| 2 | PLAN (стратегия) | - | Д | Д | Д |
| 3 | RETRIEVE (сбор данных) | Д | Д | Д | Д |
| 4 | TRIANGULATE (верификация) | - | Д | Д | Д |
| 4.5 | OUTLINE REFINEMENT (адаптация структуры) | - | Д | Д | Д |
| 5 | SYNTHESIZE (синтез) | - | Д | Д | Д |
| 6 | CRITIQUE (критика) | - | - | Д | Д |
| 7 | REFINE (доработка) | - | - | Д | Д |
| 8 | PACKAGE (генерация отчёта) | Д | Д | Д | Д |

**Важно:** Фазы 3–5 работают как итерационный цикл (поиск → хранилище доказательств → уточнение структуры → черновик → верификация → дополнительный поиск при необходимости), а не как строгие последовательные шаги.

## Контракт на вывод

**Обязательные разделы:**
- Executive Summary (200–400 слов)
- Введение (границы, методология, допущения)
- Основной анализ (4–8 выводов, 600–2000 слов каждый, со ссылками)
- Синтез и инсайты (паттерны, импликации)
- Ограничения и оговорки
- Рекомендации
- Библиография (ПОЛНАЯ — каждая ссылка, никаких плейсхолдеров)
- Приложение: Методология

**Выходные файлы** (все в настраиваемом runtime-каталоге результата):
- Markdown (основной источник истины)
- `sources.jsonl` — реестр источников со стабильными ID
- `evidence.jsonl` — хранилище доказательств с цитатами и локаторами
- `claims.jsonl` — реестр утверждений со статусом верификации
- `run_manifest.json` — запрос, режим, допущения
- HTML (стиль McKinsey)
- PDF (профессиональная печать)

**Стандарты качества:**
- 10+ источников, 3+ на каждое ключевое утверждение (независимые, не только по счёту)
- Каждое фактическое утверждение немедленно цитируется [N] с записью в `evidence.jsonl`
- Верификация поддержки утверждений обязательна: непроверенные факты не проходят
- Никаких плейсхолдеров, никаких сфабрикованных ссылок
- Приоритет прозы (≥80%), буллеты редко

## Финальный quality gate

Перед выдачей результата применить по отдельности критерии
`evals/shared.csv` и `evals/skill-specific.csv` по инструкции

## Среда и входы

Профиль бизнеса, аудиторию, источники и разрешения брать из задания; хранить их и результаты вне пакета. Методолог навыка не становится автором материала автоматически. Использовать только объявленные инструменты. Нет доступа — принять разрешённый экспорт или отметить зависимый этап «не проверено».

Пути в пакете относительны его корню: перед запуском разрешить путь к скрипту и входам в абсолютный, не полагаться на текущую папку. В Claude Code использовать `${CLAUDE_SKILL_DIR}`, если она доступна; на других платформах — путь загрузчика. Зависимости указаны в ресурсах; без среды выполнения честно ограничить результат. Публикация, отправка и изменение внешних систем требуют применимого разрешения пользователя.
