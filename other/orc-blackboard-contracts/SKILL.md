## Build the contract

1. Draw a table with one row per blackboard key: producer, consumers, Malli schema, description, and whether the value may be absent. Include initial inputs, node reads/writes, and each `:delegate` seam. Use a key for one domain fact, with stable meaning across the tree.
2. Define each key with the narrowest honest Malli shape. ORC rejects `:any`, `:some`, fieldless `:map`, and collections without a specific item/value schema, even when nested. An explicit `[:map ...]` declares known fields; `[:map-of key-schema value-schema]` is for genuinely dynamic keys. Avoid `:map-of` as a substitute for designing known fields.
3. Describe every model-facing key and nested field in Malli `:description` properties. Preserve explicit record-local field/type meanings when reusing a shared vocabulary: the same nested name such as `status` can mean artwork readiness in one record and business outcome in another. A name-only description lookup must not overwrite those meanings. State semantics, units/ranges, provenance and what counts as missing; a type alone does not explain a field. Verify the actual selected request mode against the consuming ORC/SIO revisions. Newer input-field-guide paths carry shown nested input meanings; older paths omitted some descriptions. Do not import either behavior into an uninspected checkout. See [context-flow visibility](references/context-flow.md#absence-code-context-and-model-visibility) and [model/SIO](../orc-model-sio/SKILL.md). Keep unnecessary context out of `:reads` without dropping meaning needed for the obligation.
4. Declare `:reads` and `:writes` on leaves that support them. A `condition` reads the key in `:check` and has no `:writes`; an `llm-condition` has `:reads` but no `:writes`; `llm-decision` writes exactly one boolean/enum answer (or string with runtime options), without a second rationale field. Other nodes should read only the keys needed for their task and own their result keys. Check that every read is either an initial input or produced on each route that reaches the node. Check that parallel siblings have disjoint write keys unless an explicit merge step owns the combination. Ordinary LLM leaves may expose a concise, described rationale when the task or downstream assessment needs it; preserve an explicit consuming contract without making rationale universally mandatory. Keep its ownership separate for concurrent/per-item work. See [model/SIO](../orc-model-sio/SKILL.md) for ordinary rationale versus native finite assessment.
5. At a delegate, treat the child as an isolated blackboard: map parent `:reads` into child inputs and child result `:writes` back into parent keys. Verify schemas and values on both sides. A declared absent read can arrive as nil; when valid, use `[:maybe concrete-schema]` and handle it, or use a route that omits the read. An optional field does not automatically accept nil. Delegate does not coerce a string into a map. Reconcile only the current invocation's matching result, not stale outputs left under another specialist's keys.

A deterministic `condition` compares a top-level blackboard key through `:check`; it does not interpret a nested path. If an LLM writes `{:assessment {:route "lookup" ...}}`, either expose the route as its own typed key or add a code transform that copies `:assessment/:route` into a top-level `:route` key before comparing the enum. The transform extracts structured data; it does not classify language. For bounded re-ticking, put `:on-fail :running` inside that condition's `:check`; see the [authored controller](../orc-compose-specialists/references/authored-controller.md).

## Decision-model results

For native semantic decisions, keep assessment availability, original finite answers/probabilities when supplied, policy-derived route, evidence/candidate revision and observed tool result distinct. Use described enums and concrete records; missing judgments are unavailable, not semantic false or zero. Do not require a generated reason from a model that produces none. Name host reason codes as policy output. Registered native boolean/Choice providers are reached by decision/condition nodes; a custom `code` client explicitly builds unsupported protocol questions/criteria. Inspect the actual question, input guide and finite option descriptions for the selected integration. See [decision contracts and observability](../orc-decision-models/references/contracts-and-observability.md).

## Structured map behavior to verify

For model-visible capability catalogs and per-tool argument/result contracts, read [orc-tools](../orc-tools/SKILL.md). Distinguish the typed LLM proposal, selected host tool schema and returned result; validation at one boundary does not establish the others.

Code validators/actions need a declared typed output. Every required write must exist and satisfy its declared schema on each successful return, including waiting/rejection branches. Required nullable writes may contain nil; required presence must not be confused with a non-null value. Use a complete write set or one typed outcome envelope with optional internal fields; do not declare a non-null receipt that only the effect branch can produce. A valid result shape must not fail after its side effect has already committed. Verify the public tick and projection, including the receiving node. Keep fixture-specific expected answers and call counts in experiment verification; reusable application checks should enforce observed provenance, actual runtime prerequisites, coverage and arithmetic.

Code receives `:inputs` keyed by the actual declared blackboard keys, with runtime capabilities on the received context itself. Use `[{ :keys [inputs] :as ctx}]`; do not assume a nested `:context`. A keyword key such as `:assessment` is not the string `"assessment"`; tool argument schemas may separately use string keys. Map each boundary explicitly. Verify the receiving node's actual input map and native nested values before diagnosing missing output.

Check parent and nested semantics in the actual request, including collection item fields, absent optional fields and active union branches. An older omission report is not evidence of a current defect. If the consuming mode lacks a needed meaning, carry it explicitly in the node instruction or described input data and verify that request; see [model/SIO](../orc-model-sio/SKILL.md).

For an LLM leaf, ORC turns a top-level output key with explicit `[:map [:field ...] ...]` into individual SIO output fields, then reassembles the returned fields under the original blackboard key. An output with `[:map-of ...]` stays one field. A code leaf returns native Clojure values. Test the *actual blackboard value* and the query projection after a tick, rather than assuming the raw model response shape is the blackboard shape. Resolve a delegate's durable outputs with public `value-log-resolve-writes` using runtime context and its completion event; the inline `value-log-latest-values` helper does not follow child references. See [node-output readback](../orc-observe-debug/references/evidence-path.md). An absent required field, schema-forbidden null, invalid enum, or rejected schema should fail visibly; diagnose the contract and provider response rather than filling required values with a template. Nullable value and optional presence are different: the historical parser/executor discrepancy is documented in [structured-output boundaries](../orc-model-sio/references/structured-output-boundaries.md); the qualified repair path above preserves required null through writes, reads and replay.

A producer's declared rationale can be an explicit downstream read alongside its actual artifact, goal and qualified facts. Keep ownership and provenance clear. Provider-native reasoning is separate metadata, not a value obtained by naming a blackboard key `reasoning`; see [passing explanations between specialists](../orc-model-sio/references/reasoning-and-completion-budgets.md#pass-explanations-between-specialists-deliberately).

Keep structured source records as typed data when possible. ORC already serializes complex inputs: placing pre-serialized JSON inside a text field can expose escaped quotations after another serialization. For prose citations, define the canonical decoded source text and verify the model quotes that representation. For structured facts, consider exact source identity plus field/path and typed value, checked against the retrieved record. A factually correct answer can still fail an exact quote contract because of representation mismatch. Inspect the real request, parsed quotation and canonical source before changing provenance checks; do not strip escapes with regex or weaken validation to accept arbitrary text.

Example contract (adapt keys and descriptions to the domain):

```clojure
(sheet/blackboard
  {:request [:string {:description "User's request, including their actual intent and constraints"}]
   :assessment [:map {:description "Decision evidence for the requested next action"}
                [:action [:enum {:description "Selected action the tree will route to"}
                          "answer" "lookup" "clarify"]]
                [:reason [:string {:description "Short reason grounded in the request"}]]]
   :reply [:string {:description "Final response to show the user"}]})
```

The initial campaign reproduced collisions between flattened map writes and stripped namespaces. The current private ORC candidate now assigns collision-safe wire aliases and reassembles the original typed output paths automatically; SIO also restores colliding typed keys inside nested fixed maps through its paired plan. Authors keep the domain keys and ordinary node configuration. Reserved alias-like authored names are protected. Direct SIO top-level output declarations with duplicate wire names still reject; do not confuse that boundary with ORC's distinct original write paths. These are privately verified repairs, not support implied by an older dependency pin. Validate the actual blackboard values and public projections, including missing/invalid inputs; do not rename fields or add a consumer parser to conceal a compiler defect.

A valid Malli domain schema is not automatically supported by the selected strict compiler. At SIO `242769ba`, required nullable and optional nonnull fields work, while `:or`, dispatched `:multi`, `:map-of` and optional-plus-nullable fields have specific strict compilation exclusions. Those are historical exclusions. The current private paired compiler supports optional-nullable tagged presence, bounded disjoint unions/finite literal dispatch and typed dictionary entry codecs. Ambiguous/custom structures and provider whole-schema limits remain explicit restrictions; verify the loaded source rather than applying either status universally. Do not erase those distinctions or substitute loose strings. See [rich shapes and whole-schema limits](../orc-model-sio/references/model-portability.md#rich-shapes-and-whole-schema-limits) for historical limits, implemented private paired codecs and remaining endpoint-admission boundaries.

## Review result

Return the contract table, the revised blackboard and node seams, a real or clearly labeled simulated tick result, and any unresolved schema ambiguity. Do not claim a complete end-to-end proof from schema construction or a unit test alone.

Source pins, boundary observations and proof limits are in [context flow](references/context-flow.md#source-and-proof-boundary). Recheck the target checkout before implementation.

## Assessment contracts

For judging contracts read [orc-judges](../orc-judges/SKILL.md). Keep immutable subject/completion identity, scope membership, evidence readiness, rubric version, selected band and derived score explicit. Score-only assessments carry absent feedback; failed, pending and ungradable outcomes carry no invented low grade. Jev probabilities, expectation and confidence are distinct from the primary band. Verify descriptions in the actual request as well as the declared blackboard.

For retrieval, validate that the returned source identity equals the exact identity requested from the discovery observation, on every attempt and retry, before passing it to generation or persistence. A well-formed result with a different ID is a failed selected retrieval. Comparing a generated note to that wrong result does not establish the requested provenance. For intentional identity remapping, require a described, validated mapping from the original observation.

## Contracts for generated researcher work

Read [researcher contracts](../orc-repl-researcher/references/setup-and-contracts.md) and [generated palettes](../orc-repl-researcher/references/palettes.md) for recursive adaptive stages. Type and describe the outer writes, every fresh generated write, map item binding and augmented aggregate. The original item fields plus named child writes form map results. Read computed/history values with get-var; get-input loads original blackboard inputs and can overwrite a computed same-named variable with nil. File-backed/forwarded survivor hydration has reproduced gaps at the source-status pin; do not loosen schemas to conceal them. A later [composed contract proof](../orc-repl-researcher/references/model-contracts.md#typed-composition-and-saved-frontier-recovery) preserves complete typed inputs through inline and emitted specialists and a SQLite reopen, but does not establish every storage backend or interruption window.

## Code validation receipts

At the inspected private candidate, a code leaf declaring `:writes []` and returning `{}` fails the code return contract. For a validation step, use a supported condition or declare a meaningful typed validation receipt and return it only after the checks pass, such as `{:source-validated true}`. Keep failed checks as failures. This is generic consumer contract handling, not a model parser or a fabricated default.

Zero declared writes are distinct from an empty data value: a leaf declaring a map output can return `{:packet {}}` when that empty record satisfies its schema. Required nullable outputs similarly use an explicit key such as `{:note nil}`; missing and present-null are different. Verify the consuming revision before relying on convenience return wrapping.
