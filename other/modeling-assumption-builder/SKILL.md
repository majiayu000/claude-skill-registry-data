# 建模假设整理器 / Modeling Assumption Builder

假设的价值不在于让论文看起来规范，而在于告诉读者模型在哪些条件下才可能成立、什么时候应该停止相信它。
这个 skill 从题面、方程、数据处理和代码中把前提逐条抠出来，再按对结论的影响决定先检验哪一条。

## 何时使用 / When to use

- 已选定模型（或团队已确认的主候选），需要把隐含前提写成可审查的假设
- 论文的“模型假设”只有“忽略次要因素”“认为数据真实可靠”等空话
- 方程、数据清洗、参数估计或求解过程可能偷偷引入了额外条件
- 需要检查线性、独立、平稳、正态、守恒、单调、同质性等前提是否有证据
- 要为灵敏度、压力测试和模型局限安排优先级

**不适用于** / Not for：

- 题目目标和变量尚未明确 —— 先用 `modeling-problem-reading-coach`
- 仍在比较模型家族或结构（即便手上已有草稿）—— 用 `model-selection-tutor`
- 已有完整模型，要从结论倒查所有漏洞 —— 用 `model-critique-coach`
- 只想润色论文里的假设段落 —— 先完成本流程，再由 `paper-structure-coach` 安排位置
- 只查单条方程的量纲或极限 —— 用 `dimensional-analysis-checker` / `limiting-case-validator`
- 只想选统计检验方法（t 检验、卡方、秩和）—— 不属于本 skill，直接回答即可；模型里的正态、独立等前提能不能用
  仍在本 skill 范围

## 需要的输入 / Inputs

| 输入 | 必填 | 说明 |
|---|---|---|
| 模型用途与作用域 | 是 | 模型要回答什么，只在哪些时间、空间、对象和情景内使用 |
| 变量账本 | 是 | 符号、定义、类型、单位、范围和来源 |
| 模型结构 | 是 | 方程、流程、目标函数与约束，或足够精确的文字结构 |
| 数据与处理步骤 | 否 | 抽样、缺失、聚合、标准化、异常处理、训练 / 验证划分 |
| 参数与求解设置 | 否 | 给定值、拟合参数、先验、初值、容差、随机种子和停止条件 |
| 当前假设清单 | 否 | 用作审计起点，不默认完整或正确 |

没有模型结构时，只能整理**候选假设**，不能声称已经找全。共享状态、ID 和交接格式见
`../_shared/modeling-work-contract.md`。

## 先分清什么不是假设

| 类别 | 例子 | 正确处理 |
|---|---|---|
| 题面事实 | 题面明确给出容量为 100 | 记来源与状态，不改写成“假设容量为 100” |
| 定义 | 风险分数定义为三个指标的加权和 | 说明这是操作化定义，并检查是否回答原概念 |
| 校准 / 估计结果 | 由数据拟合得到 $k=0.42$ | 绑定数据与运行，不列作现实假设 |
| 设计选择 | 时间步长取一天、阈值取 0.5 | 写选择理由与替代值，必要时做敏感性检查 |
| 数值近似 | 最大迭代 1000 次、网格间距 0.1 | 检查收敛和离散误差，不冒充数学前提 |
| 模型假设 | 接触率在观察期内不随时间变化 | 登记作用域、后果和反证测试 |

一个句子可能包含两类内容，要拆开。例如“为简化计算，假设各站需求独立且服从正态分布”至少是两个
统计假设；“为简化计算”只是动机，不是合理性证据。

## 流程 / Process

### 1. 从五个入口抽取隐含前提

逐个扫描，不只看论文现有假设段：

1. **自然语言**：忽略、近似、代表、典型、均匀、稳定、随机、独立、充分等词
2. **方程与约束**：线性可加、连续可微、无延迟、守恒、封闭边界、参数恒定、无交互
3. **数据处理**：缺失机制、采样代表性、聚合不失真、测量误差、标签可靠、时间对齐
4. **估计与验证**：误差分布、独立同分布、训练与未来同分布、参数可辨识、指标足以代表目标
5. **数值与代码**：初值依赖、收敛容差、随机性、离散步长、截断、自动修复或静默删值

每条只写一个可判断的命题。避免“其他条件不变”“忽略次要因素”这种没有对象和范围的句子。

### 2. 分类并登记

使用以下类型：结构、物理、统计、行为、数据、测量、计算 / 数值。每条 `A` 至少写：

- **精确陈述**：什么在什么范围内成立
- **理由**：题面、数据、文献、机制、可解性或暂时缺省；理由不等于验证
- **作用域**：时间、空间、群体、参数范围、情景
- **模型作用**：它使哪个方程、参数、推断或求解步骤成立
- **失效后果**：如果不成立，哪些结果或结论受影响
- **承重性**：结论是否依赖它；高 / 中 / 低，并说明依据
- **测试**：可观察的反证、诊断或压力场景
- **状态**：verified / student-provided / inferred / unverified / missing

无法验证的假设不一定要删除，但必须降低结论强度并写进限制。

### 3. 做数学一致性审计

按模型适用项检查：

- **量纲**：加减项、等式两侧、指数 / 对数输入、归一化基准
- **守恒**：质量、人数、概率、流量、预算是否凭空出现或消失
- **符号与界**：概率在 $[0,1]$，容量非负，库存不超过上限
- **单调与凸性**：模型是否真的保证论文声称的方向或可解性
- **对称 / 同质**：交换对象是否不应改变结果；若应改变，异质性在哪里表达
- **初始与边界条件**：问题是否有唯一解，条件是否来自题面

有执行能力时，量纲一项交给物理库的确定性脚本（路径相对本 skill 目录；在别处运行时写完整路径）：

```bash
python3 ../../physics/_shared/scripts/dimcheck.py model.dim
```

`model.dim` 的格式见脚本开头的说明：`[symbols]` 每行 `符号 = 量纲`，`[check]` 每行 `名字 = 表达式 ; 期望量纲`。
脚本只认 M L T I K N J 七个基本量纲；人数、车辆数、金额这类计数单位借一个本模型用不到的基本量纲代表（例如
`S = N` 表示“人”），并在注释里写明。记成 `1` 会漏掉“$\beta SI$ 与 人 / 天 不一致”这类错误。退出码 0 全部通过，
1 有不一致，2 输入写错。没有执行能力时按上面的清单人工核对，标“未执行”。

详细量纲与验证层次按需读 `../_shared/validation-playbook.md`。

### 4. 做极限与反例检查

为高承重假设至少设计一个会让它暴露的检查：

- 输入为零、全相等、极大 / 极小、只有一个对象时，结果应怎样
- 删除某类数据、改变时间窗或换一个区域后，结论是否保留
- 允许相关、非线性、时变或异质后，结果变化多大
- 多组参数是否产生几乎相同输出；若是，不单独解释这些参数
- 数据缺失若不是随机，当前处理会朝哪个方向偏

预先写期望、指标和判断规则；不要等看到结果再定义“通过”。

### 5. 查重复、冲突、循环与偷渡

- 两条假设是否只是同一前提换说法，造成“证据很多”的错觉
- 两条假设是否互相冲突，例如既称参数恒定又按阶段变化
- 是否用待证明结论当作假设，使模型必然得到想要的答案
- 同一效应是否在数据修正和方程参数中重复计入
- 数值近似是否悄悄改变了原模型，例如截断负值却仍称守恒

### 6. 按风险排序并修订

优先级由两个维度决定：**失效对核心结论的影响**与**当前证据的不确定性**。先测“高影响 + 低证据”，
而不是先测最容易画图的参数。

修订方向按代价从小到大：缩小作用域、改弱措辞、补数据 / 诊断、换结构、把结论改为情景性结论。
不要为了显得严谨，把一条假设改写得更绝对。

### 7. 让使用者确认并交接

先给完整登记表，再问最多 4 个会改变模型结构或结论的问题。使用者确认的是**团队愿意采用这个前提及其风险**，
不是确认它客观为真。

把高风险 `A`、对应 `T`、受影响 `M / C` 与未决数据交给实现或批判阶段。

## 工具与跨 Agent 降级 / Tool fallback

- 能读方程、代码和数据处理文件时按五入口核对；不能读时明确只审了使用者贴出的部分。
- 能计算时执行量纲、小例、极限或参数扫描并记录结果；不能执行时给检查设计，标为未运行。
- 有单位库或符号工具可辅助，但工具通过不等于现实假设得到验证。
- 能独立审查时让审查者寻找遗漏与循环；不能时做一遍“如果这条为假会怎样”的反向自审。
- 核心流程不依赖宿主 API，结果可完整返回在对话中。

## 边界 / Boundaries

- **不虚构合理性**：没有数据、机制或来源时，只能写“为可解性暂取”或 `unverified`。
- **不把题面事实降格成假设**：这样会让模型看似拥有并不存在的自由度。
- **不把假设写成结论**：假设“方案公平”会使公平评价失去意义。
- **不以“符合实际”收尾**：必须说明符合哪段现实、由什么证据支持、在哪个范围内。
- **不把数值设置藏进数学假设**：步长、容差、随机种子和初值要单独验证。
- **不把相关当独立、把稳定当平稳**：这些是强统计前提，需要具体诊断。
- **不替团队接受风险**：可以排序和建议，采用高风险假设需要使用者确认并在论文中披露。
- **不代写虚假假设段**：可以基于团队真实模型整理表达，不能补造实验、来源或现实依据。

## Token 控制 / Token discipline

- 先扫描模型结构与数据流，现有假设段只作一个入口
- 同义假设合并后再排序；每条保持单一命题
- 低承重、证据充分的条目压缩，高承重条目保留完整测试与后果
- 新证据到来时只更新关联的 `A / T / C`，不重贴全表
