Playwright MCP・claude-in-chrome でブラウザ操作するスキル全般に共通する
「未ログイン時のハンドオフ」パターンを、都度その場で組み立てるのではなく
再利用可能な手順として持つ。パスワード・二段階認証の入力は Claude が代行
してはならない領域であり、`human-task-scheduling`(人間にしかできない
作業の引き継ぎ)と同じ「Claude が代行できない作業をユーザーに委ねる」型の
一種だが、対象が電話等ではなくブラウザのログイン操作である点が異なる。

## 1. 未ログイン検出の判断基準

次のいずれかが見えたら未ログインと判定する。

- サインイン・ログインへのリンク/ボタンが、本来ログイン後にしか出ない
  位置(ヘッダーのアカウント領域等)に表示されている
- 操作対象のページがログイン画面そのものへリダイレクトされた
- アカウント名・アバター等、ログイン済みを示す要素が見えない
- 操作しようとした要素(例: 送信ボタン)がログイン専用ページに置き換わった

判定に迷う場合は、`get_page_text`/`read_page` でページの状態を読み、
「ログイン」「サインイン」に類する語の有無で機械的に判定する — 見た目の
印象だけで判断しない。

## 2. ログイン画面への誘導

1. ログイン画面が既に表示されていればそのまま、そうでなければログイン
   リンクをクリックしてログイン画面に遷移する。
2. ユーザーに次を明示して引き継ぐ(`human-task-scheduling` と同じ
   「トークスクリプトを渡すだけで終わりにしない」規律の徹底):
   - どのサービス・どのアカウントへのログインが必要か
   - パスワード・二段階認証コードの入力は Claude が行わない(触れない)こと
   - ログインが完了したら知らせてほしいこと
3. ユーザーからの応答を待つ。この間、対象タブへの操作(フォーム入力・
   クリック等)は一切行わない — ログイン中の画面遷移に割り込むと、
   意図しない操作(誤タップ等)を招く。

## 3. ログイン完了の確認

ユーザーから「ログインした」と伝えられても、それだけで再開しない。
`tabs_context_mcp`/`get_page_text` 等で対象タブの状態を再取得し、
未ログイン検出基準(§1)に使った要素が消えている(アカウント名が
見える、ログインリンクが消えている等)ことを確認してから再開する。
確認できない場合は、もう一度状態を尋ねる。

## 4. 再開手順

ログイン完了を確認したら、中断した箇所から作業を続ける。ページを再読込
した場合は、ナビゲーション状態(どのタブ・どのURL)を最初から再確認して
から操作を再開する — ログイン前後でURLやページ構成が変わっている
ことがある。

フォームを保存する前、またはアクセス障害が起きたときは、共有参照資料
`reference/browser-operations.md` を必ず全文読んで、その手順に従う。

## 5. なぜ再発頻度が既に低いか

personal ホストの Playwright MCP は、本人が普段使う Firefox のプロファイルを
専用の複製へ一方向に同期し、その複製で素の Firefox を操作する
(`docs/claude/claude-mcp-servers.md`)。普段の Firefox でログイン済みの
サービスは、エージェント側でログインし直さずに入れる。このため、このハンドオフが
必要になるのは、普段の Firefox でもログインしていないサービスのときに限られる —
毎回発生する手順ではない。

同期は一方向なので、エージェント側のブラウザでログインしても、次に MCP を
起動したときの同期で消える。未ログインのときは、§2 で本人に頼むログインを、
エージェントのブラウザでなく**普段の Firefox で**行ってもらう。完了を確認したら
(§3)、`/mcp` から playwright を再接続する(再接続で起動ラッパーが同期をやり直す)。
エージェントのブラウザは headless で画面に出ないので、本人が閉じる操作はできない。
ラッパーに SIGTERM を送ると Firefox ごと終わることは確認済み(2026-10-28)。`/mcp` の
再接続が旧い process を終えてから起動し直す順序かは未確認で、旧い Firefox が残って
いれば、同期は飛ばされる(stderr に「複製の Firefox が使用中」と出る)。同期されない
ときは、MCP を一度切って(`/mcp`)から再接続する。

**セッション限りのクッキーで認証するサービスは、普段の Firefox でログインしても、複製へ写らないことがある**(F63)。
2026-11-19、本人が普段の Firefox でログインし、`/mcp` で playwright を再接続したが、複製のブラウザでは、予約ボタンを押すと
ログインの画面が出たまま(`login_modal` が表示)だった。原因の候補は 2 つあり、どちらかは未確認である: (1) ログインのクッキーが
セッション限り(有効期限なし)で、複製へ写らない(ラッパーの同期は `sessionstore.jsonlz4`・`sessionstore-backups/` を除く:
`crates/playwright-mcp-launcher/src/lib.rs:28-29`。セッション限りのクッキーがそこに保存されるかは未確認)。(2) 再接続のとき、
複製の Firefox が使用中で、同期が飛ばされた。このようなサービスでは、エージェントのブラウザで操作を完結させる前提を置かず、
代わりの手順にする: 本人が普段の Firefox で操作(予約など)し、エージェントは確定メールなどの読み取りで結果を確かめる。

ユーザーに依頼するログイン手順(どのウィンドウで、どのボタンを押し、
何が表示されたら完了か)は、共有 `AGENTS.md`「人に依頼する手順は、場所を
問わず『フル』で書く」の 5 要素で書く。「ログインしてください」だけで
済ませない。
