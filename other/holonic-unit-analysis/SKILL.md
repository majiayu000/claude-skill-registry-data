# holonic-unit-analysis

## When to Use

当需要解构一个复杂系统（如品牌、产品、知识体系）以理解其组成部分及结构时description

## Core Logic

# 执行步骤

1.  **定义系统边界与核心“心灵单位”**
    *   **输入**：待分析的复杂系统（例如：一个个人品牌、一门课程、一个社区）。
    *   **操作**：识别该系统中最基本、可独立标记且具有完整功能的最小组成部分。
        *   **思考提示**：这个系统由哪些不可再分（在当前分析维度下）的“积木块”构成？
        *   **示例**：对于“个人品牌”，最小单位可能是“一种核心观点”或“一项具体技能”；对于“课程”，可能是“一个知识点模块”。
    *   **判断标准**：识别出的单位在系统语境下是完整的（自身有意义），并且是构成更大结构的基础。
    *   **输出**：系统核心“心灵单位”的定义与示例列表。

2.  **绘制等级包含结构**
    *   **输入**：上一步识别出的核心“心灵单位”。
    *   **操作**：自底向上，构建单位的包含与组合层级。
        1.  将多个基础单位组合，形成更高一层的、更复杂的功能单元。
        2.  重复此过程，直至抵达待分析系统的整体本身。
        3.  检查每一层单元是否同时满足：**a) 自身是下一层单位的完整整体；b) 自身是上一层单位的功能性部分**。
    *   **判断标准**：层级结构清晰，每层单元都具有“整体/部分”双重属性，且组合逻辑合理。
    *   **输出**：一个从基础单位到整体系统的多层等级结构图。

3.  **分析层级间的“涌现”与“约束”关系**
    *   **输入**：绘制好的等级结构图。
    *   **操作**：分析不同层级间的相互作用。
        *   **向上分析（涌现）**：低层级单位通过特定方式组合，如何“涌现”出高层级单位所具有的新属性或功能？（例如：单词组合成句子，涌现出“语义”）。
        *   **向下分析（约束）**：高层级单位如何为低层级单位的活动和关系设定规则或边界？（例如：品牌调性约束其内容主题的选择）。
    *   **判断标准**：能够明确指认出至少一种“涌现”属性和一种“约束”关系。
    *   **输出**：对关键层级间“涌现”属性与“约束”关系的文字描述。

# 输出格式要求
以分析报告形式呈现：
1.  **分析对象**：[系统名称]
2.  **核心心灵单位**：[单位定义] 示例：[示例1， 示例2...]
3.  **等级结构图**：（可视化或文字描述层级，例如：L1：核心观点 -> L2：内容系列 -> L3：产品矩阵 -> L4：个人品牌）
4.  **层级关系分析**：
    *   **关键涌现**：[高层级名称] 的 [涌现属性] 源于 [低层级名称] 的 [组合方式]。
    *   **关键约束**：[高层级名称] 通过 [约束规则] 限定了 [低层级名称] 的 [活动范围]。
