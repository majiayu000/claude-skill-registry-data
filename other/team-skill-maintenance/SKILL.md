# Team Skill Maintenance

让指定 Raft 成员在正确的执行环境中使用经过选择的技能，并留下可核对的版本与验证记录。根据当前请求进入推荐、编写、安装或更新阶段。

## 确定需求与执行范围

- 从成员当前工作出发，明确希望改善的行为和判断效果的实际任务。候选优先解决已有缺口，并与现有技能、项目规则和技术栈相容。
- 区分本次要交付推荐、仓库 PR 还是成员安装。核对会话中已有授权及其覆盖的成员、技能和操作；在已确认范围内直接推进，缺失的信息只询问影响当前动作的部分。
- 新技能可先选一位成员试用，再根据反馈推广；用户已指定安装范围或已有适用验证时，按该范围执行。
- 按当前 Raft 规则领取需要执行的任务，在原会话报告结果。仅做推荐或讨论时交付结论即可。

## 选择并固定技能内容

- 阅读官方或原维护者的技能正文，以及实际会用到的 references、脚本和依赖。结合维护状态、许可、运行时要求与执行行为判断适配性；社区热度作为发现线索。
- 推荐时给出来源、适用工作、预期收益和必要依赖。涉及本地命令、下载或外部写入的技能，说明这些动作与本次需求的关系。
- 用仓库地址、技能子目录和完整 commit SHA 确定安装来源。将分支或标签解析到具体提交，再核对实际文件；需要改编时保留适用许可，并让改编版本进入自己的版本管理。
- 编写技能时，正文保留触发条件、关键决策和执行边界，条件性操作细节放到有明确读取时机的 references。按仓库已有约定维护索引及分发入口。
- 在本仓库中，通用能力放 `skills/`；依赖 Raft 成员、工作区或协作机制的能力放 `raft/skills/`。用于 Raft 的通用技能仍按通用能力归类。

## 找到目标成员的实际环境

- 用 `raft user info <name>` 核对稳定用户名、成员类型和当前状态。结合目标成员的运行时上下文、管理界面或可核验配置，确定所在电脑、工作目录和运行时。
- 当前执行者的电脑与 cwd 只代表自己。把目标工作区和成员身份对应起来后，再读取该路径适用的指令、技能搜索目录与相关配置；身份定位只读取必要信息。
- 工作区、电脑或运行时无法确认时，继续完成来源审阅等独立工作，并说明缺少哪项定位信息。CLI 缺命令或字段时，先检查对应 `--help` 和当前 Manual，区分版本差异与资源状态。
- 对 Codex 工作区安装、更新或排查加载问题，读取 [Codex 工作区安装与验证](references/codex-workspaces.md)。其他运行时按目标版本的文档核实路径和加载机制。

## 安装、更新与验证

- 在临时目录准备固定版本的完整技能目录，检查同名技能、已有副本和本地改动。安装工具显式指定目标路径，使影响范围与获准成员一致。
- 更新时先保存可恢复的旧副本及版本记录，比较完整目录后替换，避免把已删除的旧文件留在新版本中。遇到来源不明或未解释的本地改动，保留现场并确认这些改动的归属和处理方式。
- 依次核对文件集合与内容、格式及必要依赖、运行时实际发现路径和启用状态。发现检查使用目标环境；每位获准成员分别验证。
- 安装或发现失败时，先查明路径、配置或版本差异，再作针对性修复；更新失败可在原范围内恢复保存的副本。需要扩大写入范围或重启在用服务时，先核对该动作的授权。
- 将“文件已安装”“运行时可发现且启用”“实际任务效果已验证”分别记录。行为验证采用获准的代表性任务；来自用户的试用反馈明确标注为反馈。

## 留下可维护的交付记录

在维护者自己的持久笔记中，按成员记录：身份与电脑、运行时和目标路径、仓库及子目录、完整提交、文件校验、安装日期、授权消息、验证范围，以及更新时的旧版本恢复位置。私有路径与会话证据留在原有可见范围内。

通过 Raft 在原会话简洁交付结果，附可访问的 PR 或必要下一步。仓库合并与成员安装分别记录；固定版本副本只在执行更新后改变。以后依据实际使用反馈改进技能，并按当次范围更新获准成员。
