# 重构方案推荐Skill

## 适用场景
技术债务治理执行环节,依据「偿还优先级排序Skill」的结果,为确定要偿还的债务输出分批次重构方案,指导开发执行与验收。

## 执行步骤
1. 明确重构对象与动机:引用债务台账条目 ID,说明解决什么问题。
2. 定义目标:重构后形态 + 可验证量化指标(复杂度阈值、覆盖率、债务消除数量)。
3. 划定范围:明确改与不改清单,防止范围蔓延。
4. 划分批次:按依赖关系与风险从小到大分批,每批独立可交付。
5. 为每批定义步骤、验收标准、回归与回滚要求。

## 方案模板要求
| 章节 | 内容要求 |
|---|---|
| 目标与动机 | 对应债务 ID;重构后形态;量化指标(如:圈复杂度全部 ≤10、覆盖率 ≥80%、消除 N 条债务) |
| 范围 | 改动清单与明确不改清单(避免夹带需求开发) |
| 批次计划 | 每批:内容、执行步骤、预估人日、批次间依赖 |
| 步骤 | 每批内按「先补测试 → 再小步重构 → 后验证」顺序列提交步骤 |
| 验收标准 | 每批独立可验收:功能等价 + 指标达标 + 静态检查通过 |
| 回归与回滚 | 回归测试范围、灰度策略、回滚方案与触发条件 |

## 规范要点
- 重构以「功能不变」为前提:先补测试或明确等价性依据,再动业务代码。
- 单批规模建议 ≤ 3 人日,便于评审、回滚与降低风险。
- 重构与需求开发严格分离:同一批内禁止夹带新功能或顺手修改无关代码。
- 验收标准必须可执行可度量,禁止「代码更清晰」「质量更好」式验收。
- 每批必须给出回滚方案:回滚方式(提交回退/开关切换)与触发条件。

## 输出模板
```
## 重构方案
### 目标与动机(对应债务 ID)
### 范围(改/不改清单)
### 批次计划
| 批次 | 内容 | 执行步骤 | 预估人日 | 依赖 |
### 验收标准(每批独立列出)
### 回归与回滚要求
```

## 自检清单
- [ ] 目标有量化指标且对应债务 ID
- [ ] 批次拆分有依赖说明,单批 ≤3 人日
- [ ] 每批验收标准可度量
- [ ] 包含回归范围与回滚方案
- [ ] 明确不改清单,无夹带需求
