# pre-mortem-analysis

## When to Use

在启动一个重要项目或关键行动之前，用于主动识别和防范风险description

## Core Logic

# 执行步骤

1.  **设定失败场景**
    *   **输入**：初步的项目计划或目标。
    *   **操作**：想象一个未来时间点（如项目结束后），假设项目已经彻底失败。用一句话清晰描述这个最糟糕的结果（例如：“产品上线后用户流失率达95%”）。
    *   **判断标准**：失败场景是否具体、严重且令人信服。
    *   **IF** 场景设定成功，**THEN** 进入步骤2。

2.  **集体头脑风暴（或个人深度思考）**
    *   **输入**：设定的失败场景。
    *   **操作**：召集相关方（或独自思考），基于“项目已经失败”这个既定事实，逆向倒推，尽可能多地列出可能导致这一失败的所有原因。鼓励畅所欲言，不批评任何想法。
    *   **判断标准**：是否列出至少5-10个不同维度的失败原因（如技术、市场、团队、执行等）。
    *   **IF** 原因列表充分，**THEN** 进入步骤3。

3.  **原因归类与优先级排序**
    *   **输入**：失败原因列表。
    *   **操作**：将原因按类别（如技术风险、运营风险、市场风险）分组。评估每个原因的发生概率和潜在影响程度，筛选出少数几个（如3-5个）最关键、最可能发生的风险。
    *   **判断标准**：是否识别出高概率、高影响的“致命”风险。
    *   **IF** 关键风险已确定，**THEN** 进入步骤4。

4.  **制定应对方案**
    *   **输入**：关键风险列表。
    *   **操作**：针对每一个关键风险，制定具体的预防措施（如何降低其发生概率）和应急预案（如果发生了如何减轻损失）。将措施整合到原始计划中。
    *   **判断标准**：每个关键风险是否都有对应的、可行的应对策略。
    *   **流程结束**。

# 输出格式要求

输出一份风险防范清单，格式如下：
*   **预设失败场景**：[一句话描述]
*   **Top 风险项**：
    *   **风险1**：[描述]，**概率**：[高/中/低]，**影响**：[高/中/低]
        *   **预防措施**：[具体行动]
        *   **应急预案**：[具体行动]
    *   **风险2**：...
*   **计划修订要点**：[指出原计划中需要修改或加强的部分]
