## 黄金三章核心公式（新增——吸收自知乎《起点八股文》）

> **来源**：知乎·去超越《起点八股文》（2026-06-21）。

黄金三章的核心公式为四个环环相扣的要素：

```
令人不安（生死攸关）的处境
→ 急待提升的地位
→ 充满希望的外挂（书名简介中的噱头）
→ 能被展望的美好未来（短暂解决危机、暂缓行刑）
```

### 开篇落地操作法

一种可行的写法：开篇围绕书名和简介构建冲突，开篇点题，迅速展现：

1. **主角有待提升的处境**——让读者在 300 字内感知到"主角现在的位置很危险/很憋屈"
2. **能够快速提升该处境的金手指**——亮出外挂，让读者看到"改变的可能"
3. **金手指的用法快速展示**——不要让读者猜"这外挂到底怎么用"，第一次使用就要清晰展示
4. **后续即将面临的危机**——点明"现在的缓解只是暂时的，更大的危险在后面"
5. **留下如何使用金手指破局的悬念**——读者知道主角有武器，但不知道他怎么用这把武器对付下一个敌人
6. **快速构建读者期待**——基于目前的低地位 + 金手指，让读者自然联想出"未来会有多爽"的展望

### 黄金三章与黄金一段的关系

黄金三章与"黄金一段"（前 150–300 字）并不矛盾，而是**分层协作**：

- **黄金一段**负责：在读者划走前制造认知缺口，让他决定"继续读"
- **黄金三章**负责：完成"压抑→蓄力→首次爽点释放"的完整闭环，让他决定"追更"
- 黄金一段是门票，黄金三章是留住客人的第一道菜——两道关都必须过。

### 2026 年重定义：从"黄金三章"到"黄金三屏"（新增——吸收自知乎桐梦书涵）

> **来源**：知乎·桐梦书涵《黄金三章已死？2026年爆款开头新公式》（2026-07-01），头部平台 1000 本签约作品数据分析。

2026 年的阅读决策模型已发生根本性变化：**读者在"三屏"（~1000 字）内完成是否追读的决策，而非三章。** 黄金三章并未失效，而是被压缩了时间窗口：

**关键数据**：
- 新读者 3 秒跳出率：47%
- 坚持读完第一章的比例：仅 31%
- 读者决策窗口：2019 年 ~90 秒 → 2026 年 ~40 秒
- 75% 的读者在前 2000 字内已做好"追不追"的决定

**实操含义**：黄金三章的启动闭环必须压缩到 **前 1000 字** 内完成。"压抑→蓄力→首次爽点释放"的传统三章节奏，在 2026 年应改为"三屏节奏"：

| 传统三章（6000–9000 字） | 2026 三屏（~1000 字） | 操作要点 |
|---|---|---|
| 第1章：压抑/困境建立 | 第1屏（0–300字）：冲突前置 | 直接把核心矛盾怼到读者脸上，不做铺垫 |
| 第2章：蓄力/反抗准备 | 第2屏（300–700字）：加码+信息差 | 推进冲突、释放异常信号、制造"为什么"追问 |
| 第3章：首次爽点释放 | 第3屏（700–1000字）：信息差爆发 | 释放第一个读者没预料到的信息/反转，形成认知缺口 |

**三屏通过后的宽容度提升**：一旦读者做出了"这本书有点意思"的判断，他对后续节奏的宽容度会大幅提高——因为你已经建立了"值得信任的故事讲述者"的初印象。**承诺与一致原理**：人一旦做出初步判断，后续会自动找理由支持该判断。

**不适用提醒**：历史种田文、乡土慢生活文等品类不强制要求三屏节奏。但都市、玄幻、科幻、无限流等竞争激烈的品类，2026 年没有资格慢热。

### 2026 年冲突前置的实操方法（新增——补充黄金三章公式）

黄金三章的核心公式（令人不安的处境 → 急待提升的地位 → 金手指 → 美好未来）在 2026 年面临新的执行约束：**"令人不安的处境"必须在第一句话就出现，而非第一段/第一屏。**

**冲突前置的两条具体路径**（来自桐梦书涵 2026 数据研究）：

1. **跳过可预测环节**：读者已能预测的情节（主角参加拍卖会→被羞辱→捡漏）直接跳过，从**读者预测之外的反常结果**切入。案例：跳过拍卖会铺垫，直接从"我花了三千万拍下的不是法宝，而是一张纸条"开始——第一章读完率从 34%→57%。

2. **"信息差冲突"前置**：开篇不是"介绍主角处境"，而是制造"读者知道主角不知道的信息 / 主角知道读者不知道的信息"的沟渠。沟越大，读者越想翻过去。

## 第1章三大致命错误——避坑清单（新增——吸收自知乎桐梦书涵）

> **来源**：知乎·桐梦书涵《为什么很多新手写的小说第1章就被编辑毙了？3个致命错误你中了几个》（2026-07-12，含真实投稿数据与编辑审稿案例）。

**第1章的任务只有一个——让读者想看第2章。任何妨碍这个目标的写法，都是错误。**

### 错误一：信息倾泻症（毙稿率 ~80%）

把「作者知道的」全部倒给读者，而不是让读者「慢慢发现」。开篇几千字全是世界观介绍，读者连主角是谁都不知道。

**避坑公式**：
```
信息展示 = 情节需要时才出现 + 每次只给1个新信息 + 用角色对话/行动带出
```

- 网文不是教科书——读者没有义务先学完你的世界观再来看故事
- 世界观设定应像冰山：只露出 10%，90% 藏在文字背后
- 正面案例：《诡秘之主》第 1 章没有介绍 22 条神之途径，只写了一个普通大学生在异世界醒来
- 数据：某玄幻投稿从 3000 字世界观设定 → 改为从主角被退婚开始写，追读率从 8%→35%

### 错误二：无冲突开场（毙稿率 ~60%）

第 1 章没有任何钩子，主角起床、吃饭、上班，平淡无奇。

**避坑公式**：
```
开场冲突 = 反常事件 + 主角反应 + 未解疑问
```

- 网文的黄金法则：「开篇即冲突」——前 300 字必须出现一个反常事件
- 读者不需要知道主角早上几点起床——他需要被一个悬念抓住
- 数据：某都市投稿从 2000 字"日常起床" → 改为"收到陌生短信：你的合同被改了"，追读率从 12%→47%

### 错误三：路人甲配角（毙稿率 ~50%）

第 1 章出现了多个配角但没有一个有记忆点，工具人属性太强。

**避坑公式**：
```
配角记忆点 = 1个反常习惯 + 1句口头禅 + 1个与主角对立的小目标
```

- 配角的存在价值不是「推动情节」，而是「让主角更立体」
- 读者对具体细节的注意力远超抽象描述——"左手缺一根手指的丫鬟"比"她是个忠诚的丫鬟"记忆留存率高数倍
- 正面案例：《红楼梦》丫鬟——袭人温柔体贴、晴雯刚烈倔强、平儿聪慧隐忍，每个都有鲜明性格
- 每个配角都应该有自己的"小秘密"

### 三错误综合自检

写完第 1 章后，用以下三问验证：
1. **信息倾泻**：把本章所有"介绍性段落"标出来——删掉后故事还能不能成立？
2. **无冲突**：前 500 字发给朋友，问"你想继续看吗？"
3. **路人甲**：给本章每个配角加 1 个反常细节——如果没有，这个配角的存在是否必要？

## 黄金三章逐章作战图——每章只做一件事（新增——吸收自知乎南梦）

> **来源**：知乎·南梦《网文开篇怎样快速抓住读者的注意力？》（知乎专栏"小说写作技巧分享"，2026-06-24）。

黄金三章的每章只承担一个核心任务。任务交叉或任务缺失都会导致读者流失。

### 第一章：抓眼球，留住人

第一章唯一的任务是——让读者点进来就不想走。要做到以下三点：

**1. 第一句就出事（100 字内）**

直接抛出冲突、悬念或情绪。三种有效开局句式：

| 类型 | 示例 | 驱动原理 |
| --- | --- | --- |
| 悬念式 | "三年之后，我要让你跪地求饶！" | 未完成的威胁——读者想知道三年间发生了什么 |
| 冲突式 | "退婚？可以，但你会后悔的。" | 人际关系反常——读者想知道为什么、怎么后悔 |
| 情绪式 | 用强烈的羞耻/愤怒/委屈开场，让读者瞬间代入 | 情感卷入——读者与主角共享第一时间的情绪反应 |

> **硬规则**：前 100 字内必须有冲突/悬念/情绪三者之一。纯描写、纯背景、纯日常 → 不合格。

**2. 500 字内让主角出场**

让读者迅速建立"这是谁、当下处境是什么、为什么我要关心他"的认知。主角出场过晚，读者会在困惑中流失——"我到底该关心谁？"

**3. 章末必须留钩子**

三种经典钩子：
- **悬念钩**：挖一个坑，下一章才填
- **冲突钩**：矛盾升级，架打了一半
- **反转钩**：突然揭露真相，刷新前面所有认知

**第一章核心检验标准**：读者看完后至少有**一种**强烈情感——心疼、愤怒、好奇、兴奋、震惊。但不能是"无感"。"无感"是网文开头的死刑。

### 第二章：立人设，让读者喜欢上主角

在开局，读者留下来不靠"设定牛"，而靠"我关心这个人"。这一章要：

1. **深化主角的性格**：通过一个选择或行动，让读者看到主人公的动机、软肋、底线。比如一个"怕死"的主角为了救一只猫出手，人设就立住了。
2. **展开人物关系**：引入重要配角，制造化学反应（师徒、死对头、暧昧对象等）。
3. **发展第一个冲突**：为第三章蓄力。
4. **不！要！大段说明！**：用剧情带出设定，而不是停下叙事去讲背景。比如主角第一次炼丹失败，顺便说明丹药品级——读者在紧张中自然就记住了。

### 第三章：亮卖点，给读者一个追下去的理由

这一章要完成"承诺"——告诉读者这本书的核心爽感是什么。

1. **亮出金手指/系统/核心主线**：不要平淡地写"叮，系统绑定了"，而是让金手指的首次亮相自带冲突或反差。比如主角在最狼狈的时候，最强能力突然觉醒。
2. **章末留下一个能牵动整本书主线的悬念**：不是随便的一个坑，而是让读者忍不住想"后面会怎样？"的大钩子。
3. **确立故事方向**：让读者隐约感到这本书要讲的是一个"废柴逆袭"还是"扮猪吃虎"还是"重生复仇"——期待感就此锚定。

### 金手指亮相的平台时限

不同平台对金手指亮相的容忍时限不同。创作时以项目 `Agents.md` 中声明的 `主输出平台` 为准：

| 平台 | 金手指建议亮相时限 | 说明 |
| --- | --- | --- |
| **番茄小说** | 前 1000 字 | 免费阅读平台读者耐心最短，核心卖点必须在极早期亮相 |
| **七猫** | 前 800 字 | 比番茄更短的耐心窗口，金手指几乎要在开篇同步出现 |
| **起点中文网** | 前 2000–3000 字 | 付费平台读者有较高容忍度，但仍不应晚于第 3 章 |
| **其他平台（默认）** | 前 2000 字 | 未指定平台时以此基线为准 |

> **注意**：此表中的"字"指读者实际看到的正文字数（即章节正文的 CJK 字数），不含作者有话说、章节后记等附属内容。金手指亮相不能太晚（读者等不及），也不能太生硬（像说明书）。最佳时机——在读者最想知道"怎么办"时，给出解法，爽感就上来了。

## AI小说创作的提示哲学——不要给AI题材，给AI矛盾（新增——吸收自知乎阿虚研究社）

> **来源**：知乎·阿虚研究社《如何提示才能让AI写一篇优秀的小说?》（2026-07，9 赞同）。核心论点：AI写小说失败的根本原因不是模型能力不足，而是提示的人把小说这件事想简单了。AI最需要的不是自由发挥，而是边界和矛盾。

以下六条原则是本 Skill 所有写前准备与正文创作的上游提示哲学。在构造任何 AI 写稿提示之前，先用六条原则做一次"提示质量"的快速自检。

### 原则一：给AI一个人物矛盾，而不是一个题材

这是最重要的一条原则。AI 不怕你给它设定多，它怕你不给它矛盾。

| 错误做法（给题材） | 正确做法（给矛盾的人） |
| --- | --- |
| "写一个复仇故事" | "写一个被所有人认为已经放下仇恨的人，其实每天都在用最温和的方式准备复仇" |
| "写一个穿越故事" | "写一个现代人穿越到古代拼命传播平等思想，结果发现这个世界其实是未来人搭建的历史模拟器——真正被困住的不是古人，是他自己那套现代优越感" |
| "写一个末世故事" | "写一个靠卖净水器发财的人，末世后发现唯一水源被一群孩子控制，他第一次必须向自己瞧不起的人低头" |

**原理**：AI面对100条世界观设定→产出百科条目。AI面对一个人物内心无法调和的矛盾→产出故事。好小说不是设定推动人物往前走，而是人物身上有一个他自己也解决不了的缺口，外部事件只是不断把这个缺口撕开。

**自检**：构造提示时，先问自己——这个故事的核心矛盾，能在一句话里说清楚吗？格式：谁 + 在什么压力下 + 为了什么目标 + 做了什么错误选择 + 最后付出了什么代价。

### 原则二：不要说"文笔好"，说清楚你不要什么

"文笔好"是一个没有验收标准的词。AI会把它理解为形容词更多、句子更漂亮、比喻更密。

**有效提示是说清楚不要什么**：
- 不要堆砌形容词
- 不要用"命运、宿命、黑暗、光明、救赎"这类抽象词硬撑氛围
- 不要一上来解释世界观
- 不要让角色把心理活动直接说出来
- 不要写成影视解说腔
- 不要用"他不知道的是"这种廉价悬念
- 不要让反转靠作者临时宣布——反转必须来自前文已埋下但读者没意识到的细节

**原理**：AI最需要的不是鼓励，而是边界。你不堵住捷径，它就会往最熟悉的套路里滑。真人作者写作时会本能地讨厌某些俗套，AI没有这种羞耻心——你必须把你的审美羞耻感写进提示词里。

### 原则三：三层前置分析——先拆故事，再写正文

不要让AI直接写正文。在写正文之前，强制它完成三层分析：

```text
第1层：故事核心压缩
  → 用一句话概括：谁，在什么压力下，为了什么目标，做了什么错误选择，最后付出了什么代价

第2层：人物外部目标与内部缺口
  → 外部目标：他嘴上想要什么
  → 内部缺口：他真正害怕什么、最不愿承认的欲望是什么

第3层：场景设计（不是剧情大纲）
  → 剧情大纲的问题："第一章发生A，第二章发生B，第三章反转C"——看起来有推进，其实每一章都可能是空的
  → 场景设计的优势：每个场景必须有人想达到目的、必须有人阻拦、必须有新的信息或新的损失、场景结束后人物的处境必须比开始时更难

等我确认三层分析通过后，再让AI写第一场正文。
```

**原理**：逼AI先想清楚故事为什么成立，而不是直接进入文字表演。AI一次写完整篇，很容易前面铺设很好后面开始赶进度——因为模型天然倾向于把"写完"当成比"写好"更优先的目标。分层提示把AI从一个"代写机器"变成一个"陪你拆故事的编辑"。

### 原则四：场景化提示——像导演给演员说戏

不要给AI抽象的剧情描述，给可执行的戏剧条件。

| 错误做法（抽象剧情） | 正确做法（可执行戏剧条件） |
| --- | --- |
| "写一段主角发现真相的剧情" | "写一场主角发现真相的场景。地点是废弃档案室。主角的表面目标是找一份失踪人口名单，真实目标是证明父亲没有背叛他。阻力不是敌人追杀，而是档案管理员一直在用一种过分平静的态度阻止他继续查。场景必须通过物件、对话停顿、错误编号、被撕掉的照片来推进，不允许直接解释真相。结尾让主角拿到答案，但答案必须让他比不知道时更痛苦。" |

**可执行戏剧条件五要素**：
1. 场景地点与氛围
2. 角色的表面目标 vs 真实目标
3. 阻力的具体形式（不是抽象概念，是可感知的行为）
4. 信息的推进手段（物件/动作/对话/环境——不允许直接叙述解释）
5. 场景结束后的局面变化（必须比开始时更难/更复杂）

### 原则五：核心一句——不要顺滑剧情，要难以处理的选择

> 提示AI写小说时，最重要的一句话是：**不要给我顺滑的剧情，给我难以处理的选择。**

这个要求把AI从"安排事件"拉回到"制造困境"：

| 普通设定 | 加"难以处理的选择"后 |
| --- | --- |
| 主角想变强 | 他想变强，是因为他一旦承认自己弱，就等于承认父亲当年抛弃他是对的 |
| 主角想复仇 | 他复仇的对象其实是唯一真正理解他的人——复仇不再只是爽点，而变成了自毁 |
| 主角想拯救世界 | 拯救世界的前提是亲手摧毁他一直相信的正义 |

**原理**：小说最需要的就是痛苦——不是哭天喊地，而是人物必须在两个都不舒服的选择之间做决定。AI最擅长补全，不擅长痛苦；但小说最需要的偏偏是痛苦。读者不是因为你设定多才继续看，而是因为他想知道这个人接下来会怎么选。

### 原则六：反例提示 + 烂稿自检——帮AI避开捷径

**反例提示**：不只给正向要求，给反例。AI往往不是不会写，而是太会走捷径：

```
不要写成网络小说简介风格
不要用"然而他不知道的是"制造悬念
不要让角色在对话里解释世界观
不要让反派主动说出自己的计划
不要让人物突然崩溃大喊
不要用"眼神里闪过复杂的情绪"这种偷懒句子
```

**烂稿自检**：在写正文前，先让AI列出这个故事最可能出现的五种烂稿问题，并在写作时主动避开。坏处是AI不一定会完全避开，好处是它被拉到了"质量意识"里，而不是只顾着完成任务。

### 完整提示词模板（三阶段）

> 以下模板可直接使用或按需裁剪。模板的核心不是文字本身，而是它强制AI在写正文之前完成"故事验证"——这是区别于"帮我写一篇小说"的本质差异。

**第一阶段：故事验证（不写正文）**

```text
你不是来直接写爽文的。你现在是一个严苛的小说编辑，任务是先帮我把故事做扎实，再写正文。

故事类型：【悬疑/科幻/权谋/都市/短篇反转等】
核心设定：【用三到五句话写清楚世界观，不要超过五句】
主角：【身份、欲望、恐惧、秘密、错误认知】
故事核心：写一个关于【主题】的故事，但不要直接说教。故事必须通过人物选择体现主题。

请先不要写正文，先完成以下分析：
1. 用一句话概括这个故事真正的冲突。
2. 写出主角的外部目标和内部缺口。
3. 写出主角最不愿面对的真相。
4. 设计三个关键场景，每个场景都必须包含：目标、阻力、代价、场景结束后的局面变化。
5. 找出这个故事最容易写俗的地方，并给出规避方案。
6. 列出五条写作禁忌，比如不要用哪些套路、哪些词、哪些桥段。

等我确认以后，你再写第一场正文。
```

**第二阶段：场景施工（逐场景执行）**

场景提示不是"写一段XX剧情"，而是"写一场包含目标/阻力/代价的XX场景"。可执行戏剧条件要求参见原则四。

**第三阶段：烂稿自检（每场景写后）**

每写完一个关键场景，让AI自检：这个场景有没有推进人物困境？场景结束后局面有没有变得更难？有没有任何一句话可以删掉而不影响理解？

### 提示哲学与本 Skill 既有流程的关系

六条原则和模板**不替代**本 Skill 现有的写前校验→控制卡→落正文流程。它们是提示构造层的上游方法论——在你构造具体写稿提示之前，先用六原则检查：

- 你给的提示是在描述"题材"还是在描述"矛盾的人"？（原则一）
- 你的"质量要求"是可验收的具体禁止项，还是"文笔好"这种空话？（原则二）
- 你让AI先做故事分析了吗，还是直接要正文？（原则三）
- 你的场景描述是可执行的戏剧条件，还是抽象剧情梗概？（原则四）
- 你给了AI"难以处理的选择"吗？（原则五）
- 你给了反例和自检指令吗？（原则六）

如果六条中有三条以上不满足，提示质量判为不足，先修提示再写正文。

## 创作视角铁律（强制）

- 写正文前先确定：摄像头架在谁的肩上？这一章读者透过谁的感官在看世界？
- **摄像头视角**：只写主角看到的、听到的、闻到的、身体感受到的。主角不知道的事，读者就不能提前知道。
- **禁止上帝视角偷跑**：不写别人的内心活动、不写远处发生的事、不替角色宣布"他很害怕"——让角色自己的身体反应出来。
- 开篇尽早建立视角归属；若读者读了好几段还不知道"跟着谁"，就是视角塌了。
- 写完后用五感替换法自查：搜索 很/非常/特别/极其/无比，全部删掉，换成具体感官描写（手心出汗、喉结滚动、胃缩、耳鸣、视野发白）。
- 详见 `通用-去AI味重写` 的 `references/视角塌陷与五感替代诊断修复卡.md`。

### 创作视角的 80/20 分配法（新增）

来自知乎高赞答主陈清扬的视角分配经验，可作为创作视角铁律的补充执行规则：

- **80% 正文用主角的限知视角**——不要写「一个东西怎么样」，而是写「一个东西对主角来说怎么样」——是让主角冷了、热了、担心了还是犹豫了。坚持这个写法能直接提升代入感。
- **20% 正文留给配角视角和上帝视角**，只在以下三种场景切换：
  - 主角牛逼/耍帅的情节 → 用配角视角看主角，让读者通过别人的眼睛感受到主角的强大
  - 主角知道配角不知道的信息 → 用配角视角制造信息差，让读者期待主角什么时候摊牌
  - 交代主配角之间的信息差 → 短开上帝视角，让读者知道双方各自掌握什么

详细执行规则与示例见 `../通用-执行场景单元/references/知乎精华_五感视角与节奏执行规则.md` 的第二节。

### 仿写场景的叙事视角选择指南（新增）

当 `Agents.md` 中注册了"作品蓝本模板"且当前项目为仿写场景时，写正文前需要比通用视角铁律多走一步：**确认本章视角与蓝本同位置章节的视角关系**。以下选择方案来自《改写小说的系统方法论研究》的视角转换技法：

| 与原蓝本同位置章节的视角关系 | 操作 | 预期效果 | 适用条件 |
| --- | --- | --- | --- |
| **保持一致** | 使用与蓝本相同的叙述者身份和镜头距离 | 读者体验与蓝本一致，代入感稳定 | 本章是对蓝本结构的直接遵循，需要保留原来的爽感引擎体验 |
| **视角反转** | 把蓝本的主角视角改为配角视角，或反派的视角 | 从"成为主角"变为"目睹传奇"，天然拉开抄袭嫌疑 | 蓝本配角群体丰富，存在未展开的叙事盲区 |
| **人称转换** | 蓝本是第一人称 → 改为第三人称限制；反之亦然 | 人称改变会连带改变叙事距离和信息控制方式 | 蓝本的视角类型与目标平台的读者习惯不匹配（如起点更习惯第三人称） |
| **微观聚焦** | 从蓝本的"全景叙述"改为"局部特写"——只写一个感官通道或一个物件 | 创造强烈的沉浸感和悬念感 | 本章是一个关键的情绪节点或转折点，需要放慢节奏增加密度 |

**视角选择后必须验证**：
1. 新的视角是否还能让读者感受到蓝本同位置章节的"核心爽感引擎"？如果不能 → 回退保持一致
2. 新视角是否导致了关键信息无法释放？如果是 → 需要在章节内增加信息补充机制（如通过对话、环境细节等自然补出）

### 正文落稿前的环境交互与文字密度校准（新增——吸收自知乎答主小恐龙）

落正文前，对每个场景段落实施加以下两层补检：

**层一：环境—角色交互检查**
每个环境描写段落后，确认角色与环境产生了物理或精神上的交互（被环境冷到、使用场景器物、因环境做出判断、被环境改变轨迹）。如果角色与环境互不触碰，需补一个交互动作——否则环境是可替换的装饰品，代入感会从根部受损。
详细交互机制见 `../通用-执行场景单元/references/知乎精华_文笔四维与交互框架.md` 第二节。

**层二：一笔多用密度检查**
每个场景动作写完后追问：这个动作除了推进剧情，还能同时承载什么？——人设塑造、关系提示、伏笔、基调渲染、氛围奠定。
"一笔多用"不是堆信息，是让一段表面清晰简洁的文字在暗处多干活。正文中每段纯粹只做一件事的文字，都应考虑能否与临近功能合并。
详细规则与示例见 `../通用-执行场景单元/references/知乎精华_文笔四维与交互框架.md` 第四节。

## 阅读流畅度硬规则（新增——吸收自知乎答主好难说故事）

> **市场诊断**：知乎喷神看过不下5000部新手作品，其中过半不流畅。最反直觉的发现是——这些不流畅的作品**遣词造句并不差**，甚至不输职业作者。问题全出在写作习惯和心态上，跟文字水平无关。

以下三条硬规则对应最常见的三种"文字没问题但读起来难受"的病灶。

### 规则一：禁止强迫解释（强制）

**病灶描述**：不管写到什么新事物，必须大段大段解释一遍——新人物出场先写五六百字背景、新物体出现先写来历外形作用、新事件发生先写来龙去脉。作者心态是"不解释清楚读者就看不懂"。

**纠正规则**：
1. **延迟解释原则**：凡是新出现的事物/人物/事件，除非不解释会导致读者完全无法理解当前冲突，否则默认**先写它在当前场景中的作用/表现，把解释推迟到后续章节**。
2. **金庸验证标准**：写入一段解释前，先问——"乔峰用擒龙功时，金庸有没有先把这功夫的来历、传承、乔峰怎么得到、如何学会的全部说一遍？"（没有。不影响读者看。）
3. **解释字数门禁**：首次出现的新事物/人物的背景解释，单处不得超过150字。超过则必须拆分到后续2-3章中分散释放。
4. **只解释"当前场景需要的部分"**：主角见到一个人，读者只需要知道ta此刻的身份和与当前场景的关系，不需要ta的完整生平。需要更多信息时再补。

**验收**：正文写完后，全文搜索"原来""其实是""实际上""也就是说"等解释性引导词，逐句判断是否可删。一处解释超过200字即判为触犯本条。

### 规则二：段落与标点纪律（强制）

**病灶描述**：三种子类型——①一句话一段（误以为便于手机阅读）；②标点滥用（两三个字一个标点）；③把对话和动作描述分开成独立段落。

**纠正规则**：
1. **段落长度**：手机阅读单段不超过3行为宜（约100-150字），但一句话一段不可取。一段是否换行不看"写了多少字"，看"这一段的意思是否讲完了"。
2. **标点纪律**：可在适当位置多加逗号让读者喘口气，但不得两三个字或一个词就加一个标点。正确的节奏是"一口气能读完的短语长度"。
3. **对话-动作一体化**：同一人物的对白和动作必须放在同一段落，不得把"「小二，给我来壶酒。」"和"赖头和尚抓着酒杯把桌子砸得震天响"分成两段——读者需要明确的时间和空间次序才能流畅阅读。

### 规则三：视角纪律补充——禁止场景内全视角轮换（强制）

> 正文创作视角铁律已覆盖"禁止上帝视角偷跑"和"80%主角视角"，以下补充一个最常见且隐蔽的视角事故。

**病灶**：一个场景内有N个人物，作者非要把每个人的视角轮流切换一遍——即使只有5个人，也要让读者跟着5双眼睛各看一圈。信息确实都交代清楚了，但读者被来回兜得疲于奔命。

**纠正规则**：
1. 一个场景只需要把视角固定在一个角色身上，用ta的眼睛看就够了。
2. 需要切换时，只切换到 **1-2个关键人物**（当前对手/重要配角），且必须有明确的过渡信号（段落分界+过渡词）。
3. 切换后必须尽快回到主视角，不要让读者在多个视角间迷失。
4. 同一段落内绝对禁止视角跳跃——上一句还在写主角，下一句就跳到门外去了。

**验收**：写完场景后，逐段检查"这一段的摄像头在谁身上"。若同一段落内出现两个不同的"感知主体"，判定为视角事故。

## 私有化叙事原则（新增——吸收自知乎精华）

> **核心理念**：仿写场景（存在作品蓝本模板）下，正文创作面对的核心矛盾是"既要保留蓝本的精髓，又不能写出抄袭感"。解决之道不在内容层面（换人称/换场景），而在技法层面——**只抄技法，不抄句子，用自己的生命体验反哺技法**。这适用于任何需要参考他人作品的创作场景。

### 技法剥离法

正文创作时，若有一句话或一段描写让你拍案叫绝，禁止直接仿写句式。改为以下三步剥离：

1. **剥离技法**：这句话的技法内核是什么？——不是"句式结构"，而是"它为什么打动人"（示例：马尔克斯名句的技法内核是"时间折叠"——用一句话在未来-现在-过去三个时空中自由穿梭，瞬间营造巨大的苍凉感）。
2. **跳过句式**：原句的具体用词、节奏、标点结构——这些必须全部放弃，一个都不留。
3. **注入私货**：用你自己的经历、观察、情感记忆去灌满这个技法。如果你童年最深的记忆是父亲倒闭的工厂和院子里的梧桐树，就用那个画面去填充"时间折叠"技法。

### 私有化叙事的验收标准

| 层级 | 成功标志 | 失败标志 |
| --- | --- | --- |
| 技法层 | 读者感受到相同的情绪冲击力（苍凉/震撼/温暖） | 读者识别出这是"某某句式"的变体 |
| 句式层 | 没有一处与原句相同——用词、节奏、标点都不同 | 存在句式结构高度相似（"多年以后+面对+名词+某人物+回想起+某场景"） |
| 内容层 | 填充的是你真实的经历/观察/情感记忆 | 填充的是公共化的、模板化的"仿写例句" |

### 仿写质量控制

- 做完技法剥离后，做**反向查重测试**：把剥离后的句子放在搜索引擎里搜，如果能看到"某某名家也这样写过"，说明技法剥离不彻底——继续压缩技法定义直到只剩抽象功能描述。
- 实话说：仿写练到极致比原创更难。原创只需要面对白纸，仿写要同时面对白纸和原作的幽灵——你既要挣脱它的引力，又不能丢掉它的精髓。
- 本原则的终极目标不是让作品永远停留在仿写状态，而是让仿写成为通往原创的跳板。当你在创作中发现"这个技法已经不够用了，我需要创造自己的技法"时，说明你已经跨越了这个阶段。

## 开篇不铺垫（强制）

新手最常犯的开篇错误：大段文字讲解世界观、铺垫、人物介绍，这样直接劝退读者。

**千万不要铺垫** —— 直接把主角扔进冲突里。

正确的开篇做法：
- 第一章就抛出核心冲突，让读者跟着紧张。
- 开篇尽早亮出核心驱动力：读者知道"主角凭什么能赢"或"这个故事会往哪个方向走"。
- 不要在开篇写大量环境描写、世界观说明或人物背景介绍。
- 具体开篇量化标准（字数密度、冲突时限、回报时点）由主输出平台的 `通用-输出*版` Skill 提供。

### 补充原理：设定是静态的，故事是动态的（吸收自知乎虚空圣堂）

> **来源**：知乎·虚空圣堂《如果让你给刚入行的网文新人一个建议》（2025-02-19）。

"开篇不铺垫"的核心支撑逻辑：**设定是静态的，故事是动态的。**

- **开篇不铺垫不是因为"读者没耐心"**——这只是表层原因。底层原因是：静态信息没有驱动力。读者无法被"玄黄大陆有三大皇族八大王族"推着往下读，只能被"王虚一觉醒来发现自己变成了兔子，而且不能赢这场比赛"推着往下读。
- **读者接受信息的方式不是靠硬塞，而是通过故事推进的过程中一点点透露**——落正文前问自己：这条设定信息是在"故事水流"中自然出现的，还是我从岸上铲了一铲子土扔进水里的？

**实操验收**：写完开篇后通读一遍，标记所有"读者此时还不需要知道"的信息段落——它们就是本应延迟释放的静态设定。删除或推迟到故事水流经过它们时再放出来。

### 龟兔赛跑的两版对照（虚空圣堂案例）

以下对照是本原则最直观的执行教材：

| 错误写法（纯设定堆砌） | 正确写法（故事切入） |
|----------------------|-------------------|
| 开头先铺世界观：玄黄大陆×黑暗大森林×三大皇族八大王族×兔族龟族背景 | 开篇第一句：王虚一觉醒来发现自己变成了一只兔子 |
| 信息方向：作者→读者（单向倾倒） | 信息方向：通过主角的困惑和探索→自然释放 |
| 读者感受：在读设定文档 | 读者感受：在看一个"为什么不能赢"的谜题 |
| 驱动力：零（静态文本） | 驱动力：穿越+立即冲突+核心悬念（"千万不要赢"） |

> **解读**：两版的核心差异不在"写得长不长"，在**以什么为信息锚点**——前者以"世界"为锚点，所以所有信息都围绕世界展开；后者以"主角的困惑"为锚点，所以所有信息都围绕主角的行动和疑问展开。正文创作时，永远选择后者。

## 开篇人物展示五维法：身份→处境→性格→能力→欲望（新增——吸收自知乎网文老刀·五维立人设体系）

> **市场诊断**：大量新人写十几万字无法签约，剧情逻辑通顺、没有明显毒点，但读者反馈"主角形象平淡，看完完全记不住"。问题从来不在剧情编排，根源出在人设塑造上。网文读者耐心十分有限，往往只翻看前三章就决定是否追读。如果前三章主角立不住，后续几十万字都属于无效码字。
> 
> 来源：网文老刀17年实战（知乎想法，2026-06-15）

开篇写正文时，人物展示不能靠"慢慢铺垫，后面自然丰满"，而必须在落笔时就有意识地通过以下五维逐层递进展示。**五维不是人物设定表，而是写作时的展示顺序与展示方法。**

### 五维展示规则

| 维度 | 落地要求（写正文时做什么） | 常见错误（禁止做的事） |
| --- | --- | --- |
| **① 身份** | 借助环境、随身道具、下意识小动作自然流露身份信息。不用写"他当过兵"，写站姿、自律性、行事习惯 | 大段文字罗列年龄、职业、家庭背景等干巴巴信息 |
| **② 处境（压力）** | 身份落地的同时困境同步给到。没有压力就没有代入感，没有困境就没有追读欲望 | 前三章通篇日常琐事、平淡人际关系，全程没有冲突矛盾 |
| **③ 性格** | 用选择与行动暴露本性——当众受辱攥紧拳头是隐忍、困境中帮弱者是真善良、嘴上吐槽私下帮人是嘴硬心软 | 堆砌善良/隐忍/高冷等抽象形容词 |
| **④ 能力** | 用具体事件结果证明——旁人束手无策他能破局、众人慌乱他能稳住、细微线索只有他能捕捉。区分日常能力与隐藏底牌 | 安排全员轮番夸赞，或能力设定笼统样样不精 |
| **⑤ 欲望** | 必须写出具体执念。不只是"变强/逆袭"，而是"被裁员后在30岁前攒够首付""查清母亲死因"。欲望越具体，读者期待越强 | 主角全程被动，遇事只会应付，如同没有自主想法的工具人 |

### 前三章逐章展开顺序

这五维不是一次性塞进第一章，而是按以下节奏在正文中逐层释放：

| 章序 | 展开维度 | 对读者完成的心理动作 |
| --- | --- | --- |
| **第1章** | 身份 + 核心困境 | 好奇——"主角是谁？正在遭遇什么麻烦？" |
| **第2章** | 性格 + 能力（释放初级爽点） | 认可——"这个人物并不软弱，手里有底牌" |
| **第3章** | 欲望 + 长远目标 | 期待——"想看主角能否圆梦" |

### 五维互咬合规则（强制）

写前三章时，必须确保五维服务于 **同一个人物内核**，不能互相冲突：

- ✅ **正向咬合示例**：底层出身 + 长期受压处境 + 隐忍内敛性格 + 过人隐藏实力 + 翻盘夺回尊严的执念 → 所有维度汇聚出"外低调、内锋芒"的统一人设
- ❌ **反面崩人设示例**：冷血顶尖杀手身份 + 泛滥圣母心性 + 天下第一武功 + 佛系种田的欲望 → 各维度互相冲突，人物形象割裂

**自查方法**：写完前三章后，逐章提取主角在这五维上的表现列成一张表，检查是否存在逻辑相悖的维度组合。有一条矛盾就必修。**五维互咬合检查是前三章写后自检的最低门槛。**

### 与本 Skill 既有规则的协同

- 五维法与本 Skill 的"开篇不铺垫"原则一致——身份信息通过细节流露而非背景说明，就是"不铺垫"的具体执行方式。
- 五维法的"能力"维度与本 Skill 的"核心驱动力设定"互补——能力展示回答"主角凭什么能赢"，欲望维度回答"读者凭什么跟到底"，两者缺一不可。
- 五维法的处境维度与本 Skill 的"爽点预告模式"衔接——第一章不是写爽点，是预告爽点的方法是：让主角身处困境（处境维度），预告"下一章他有能力破局"（能力维度）。

## 核心驱动力设定（强制）

在开始落正文前，必须先问自己这个问题：
- **读者为什么要跟着这个人物走？他们在等什么？在担心什么？**

这就是"核心驱动力"——不是主角要去做什么，而是"读者跟着的理由"。它是一个**具体的问题**，而不是抽象的悬念。

示例对比：
- ❌ 错误：主角发现自己是失忆的（只是信息）
- ✅ 正确：主角发现自己是失忆的，而现在有人要杀他，他必须在24小时内想起自己是谁或者逃出去（这是问题，驱动读者往下看）

故事框架：**某人 → 渴望 → 遇阻 → 改变**
- 某人：一个具体的角色
- 渴望：他想要什么（要具体）
- 遇阻：什么力量阻止他（要有真实代价）
- 改变：他最终怎样改变（要不可逆）

## 网文基础模版：爽点预告模式与真实节奏（新增——吸收自知乎丁文韬与流浪的蛤蟆）

> **核心洞察**：为什么新手很难在第一章就写到爽点？因为第一章的根本任务不是写爽点，而是告诉大家——"我就要写出一个大爽点了，你们快看下一章"。

### 网文的基础模版：预告→延迟→兑现→再预告

网文最底层的读者驱动机制，不是一个章接一个章地写爽点，而是一个**持续的爽点预告链**：

```text
第1章：预告"第2章有大爽点" → 读者翻到第2章
第2章：预告"第3章有更大的爽点" → 读者翻到第3章
...
第N章：爽点预告已经撑不住了 → 必须兑现
第N+1章：兑现爽点
第N+2章：开始预告下一个更巨大的爽点
```

**核心规则**：
1. **第一章不是写爽点，是预告爽点**——让读者觉得"下一章肯定爽"，然后翻页。
2. **逐章预告→延迟→再预告→直到极限→兑现**——能"忽悠"多久取决于你的信息释放技巧和读者期待管理能力。
3. **兑现后立刻开始下一次预告**——用更大的爽点承诺覆盖已兑现的爽点，形成持续追读链。
4. **预告不能永远不兑现**——当读者开始觉得"又被耍了"时，就是必须给出爽点的信号。

**实操含义**：写每一章正文前，先问自己——"这一章是在预告爽点，还是在兑现爽点？"如果是在预告，下一章或下几章必须有一个明确的爽点兑现节点。连续预告超过读者耐心阈值（通常3-5章）而不兑现，读者就会流失。

### 节奏的定义：推动读者感觉有趣的点儿，而不是故事进度

> **最被误解的概念**：很多作者以为节奏=故事推进速度（"主角干了A→干了B→干了C"就是节奏快），但这是一场巨大的误会。

**真正的网文节奏** = **推动读者感觉有趣的点的分布密度和时机**，而不是故事进度的快慢。

经典的高段位节奏示范——让读者**知道即将发生什么，但故事在吊胃口，一点一点推进细节**：

```text
1. 敌人出现
2. 危机临头
3. 受挫
4. 得到解决问题的办法
5. 策划解决问题
6. 读者已经明白了：敌人掉入了主角的反杀陷阱
7. 读者无比期待主角反杀
8. 但故事仍旧在四平八稳地展开
9. 一点一点推进细节
10. 反复吊着读者的胃口
```

**关键**：在第6-9步这个区间，读者"知道要发生什么"但"还没看到发生"——这是节奏最值钱的地带。这个地带的长度和质量，决定了读者感受到的"爽感浓度"。

**简化版**（降级方案）：
```text
敌人出现 → 危机临头 → 受挫 → 开挂 → 解决问题
```

**不能再简化了**，再简化就不好看了。

### 什么不是节奏

```text
❌ 主角去干了件事
❌ 主角又干了件事
❌ 主角呦呦呦切克闹，干了件事
```

这三行不是节奏，只是**事件清单**。没有蓄力、没有读者期待积累、没有"知道要来了但还没来"的等待感——就不构成节奏。

**判断标准**：如果把你写的章节概括为"主角做了A→去了B→做了C"，而没有在任何节点上让读者产生"接下来会怎样？""快来了快来了！"的心理活动，那么这章只有事件推进，没有节奏。

### 写正文前的节奏自检（强制）

落笔写每一章正文前，自问以下问题并记录答案：

1. **本章在爽点预告链中的位置**：是预告章、兑现章，还是过渡章？
   - 预告章：正文中必须有让读者相信"下一章会爽"的具体信号
   - 兑现章：正文中必须有让读者感到"值了"的具体回报
   - 过渡章：正文中必须有"过渡不白过"的小回报或新预告
2. **本章是否在"读者知道要来了但还没来"的区间中做了文章？**
   - 如果是：这是好节奏——正文中应保留并强化这个区间
   - 如果不是：正文是否变成了单纯的事件推进？如果是，需要重新设计
3. **把本章概括成"主角做了A→做了B→做了C"——读起来像节奏吗？**
   - 如果像事件清单：说明本章只有推进没有节奏，需要插入蓄力-期待-延迟的环节
4. **本章结尾是否形成了"下一章会有更爽的"的读者预期？**
   - 如果没有：章末钩子需要重新设计，不能只是总结或收尾

**验收**：如果上述四个问题无法清晰回答，本章正文的节奏设计尚未完成，不得进入落稿阶段。

## 人物落地快检（新增——写前强制）

> 核心问题：正文写出来之后才发现"人物没立住"，返工成本极高。此快检在落笔前确认人物传记素材已经就位、可以被直接使用。

写每一章正文前，必须完成以下三项快检：

1. **出场人物传记就位检查**：本章所有出场人物的人物传记是否已存在且已读取？若传记版本过期或缺失，先标记降级，不要凭记忆即兴写人物。
2. **正文可调用素材提取**：每个核心出场人物的传记中是否有"正文可调用素材清单"？若没有，本章人物行为靠写手即兴发挥——在章末标注此风险。
3. **控制卡人物执行要求核验**：本章控制卡中是否已写入"人物执行要求"（每个人物本章要体现的心智模型/声口特征/至少一个独特动作）？若没有，先回到控制卡补齐，再落正文。

快检通过后，写正文时遵循以下人物锚定原则：
- 人物第一次在本章出场时，先查传记的压力反应微镜头，确认当前的默认反应基线
- 人物开口说话时，先查声口即时贴，确认句长/语气/禁忌词
- 人物做关键判断时，先查决策启发式，确认默认判断规则
- 若本章场景与传记中的误判预设场景匹配，优先触发该误判

## 开篇量化标准与避坑指南

本节定义通用的开篇写作原则。平台特定的量化标准（字数密度、冲突时限、回报时点）由主输出平台对应的 `通用-输出*版` Skill 提供。

### 通用开篇原则（平台无关）

- 开篇必须快速建立冲突或异常——不要让读者等。
- 第一章出现的需要读者记住的新名字应尽量精简，多余角色用感官特征替代。
- 即使主角眼下处于劣势，也应在开篇尽早让读者看到"他会反击"的信号。
- 回忆信息用碎片化方式在行动间隙插入，不要在开篇用大段回忆替代眼前冲突。

### 平台特定开篇标准

- 若已配置主输出平台，开篇量化标准从对应 `通用-输出*版` Skill 的 `references/平台共性执行细则.md` 读取
- 包括但不限于：前 N 字冲突密度要求、金手指亮相时点、点击转化率红线、开篇毒点清单等

### 开篇通用自检清单（落稿前必过）

[ ] 开篇前几句话是否就有冲突/异常/压力信号？
[ ] 读者读完后是否心里产生了一个具体的追问？
[ ] 是否尽早亮出了核心驱动力或回报预期？
[ ] 是否避免了长篇背景介绍、世界观说明书式的开头？
[ ] 主角是否在开篇就表现出了某种反抗或逆袭的苗头？
[ ] 是否有过多需要读者记住的新名字被塞进了开篇？

### 章纲→正文自审五问（新增——吸收自知乎精华"如何把大纲蜕变成沉浸小说"）

> **问题**：正文读起来像"剧情大纲"或"工作汇报"，毫无沉浸感。核心原因不是在遣词造句层面，而是在**从章纲到正文的每一轮扩写中，没有问自己"这一轮我补了什么让读者感到自己在场"**。
>
> 来自知乎答主的实战经验：先用章纲扩写成正文，再带着以下五个问题自审修改，反复5-6遍，直到每一个问题都能给出肯定回答。

正文初稿完成后、进入润色或审阅之前，先用这五个问题做一次快速自筛。这五问对应从"大纲体"到"沉浸正文"的五道加工工序，可以在正文文件头部或工作笔记里逐条标注回答：

1. **开场戏是什么？**——开篇有没有一个具体的场景/画面，还是只有信息说明？从章纲扩写时最容易犯的错就是把"发生了某事"展开成"说明某事"，而不是展开成"读者能看到、听到、感受到的现场"。如果开篇读起来像剧情摘要，就说明还没有把"事"转化成"戏"。

2. **冲突强度如何，有没有情绪？**——这一章里的冲突是否让读者感受到压力、紧张或期待？如果冲突被写成了"主角遇到了一个问题，然后解决了"，那只是干巴巴的事件推进。读者要的不是"知道发生了什么"，而是"感受到发生了什么"。从章纲扩写时，检查每一个冲突节点是否附带了人物的心理反应、生理反应或即时决策。

3. **舞台背景搭不搭配，有没有沉浸感？**——环境描写是服务于情绪和氛围，还是可替换的通用背景？如果去掉环境描写后情节完全不受影响，说明背景还没有"进戏"。检查每个环境段落是否与角色的情绪状态产生了呼应、反差或推动关系——而不只是"故事发生在一个地方"。

4. **人物细节刻画到没到位？**——人物有具体的动作、反应、习惯、小动作，还是只有功能性的"说了话""做了事"？从章纲扩写时，最容易丢失的就是人物的"人味儿"——那些与情节无关但让人物鲜活起来的细节。检查每个人物出场时是否至少有一个可被读者记住的细微动作或反应。

5. **整体节奏是否连贯？**——读起来顺不顺，有没有段落之间断档、信息跳过、或叙述节奏忽快忽慢的地方？把写完的正文通读一遍（建议出声朗读），标注出所有"读到这里卡了一下"的位置。

**自审验收标准**：以上五问中若任意一问回答"否"或"不确定"，则本章正文尚未完成"从章纲到正文"的转化，不应进入润色或定稿阶段。把该问对应的段落标记出来，修改后再过一遍自审，直到五问全部通过。

**配套练习法**（来自同一来源）：初学阶段可先用AI生成章纲→扩写成正文→五问自审修改→记住改后的体感→脱离模板自己写一气呵成。以5-6轮为一次完整练习周期，目的是把"这五问"内化为写作直觉，而不是永远依赖对照清单。详见 `通用-章节创作闭环` 的练习方法入口。

## 信任读者原则——正文创作的核心心智模型（新增——吸收自知乎"我的世界"&猴姆）

> **核心判断**：加速的第一步不是删，是信任。信任你的读者能从动作里读懂情绪，能从结果里反推过程。

### 原则一：不代替读者思考

正文创作中最隐蔽的拖沓源是作者"不信任读者能理解"——于是每一处都忍不住停下来解释、铺展、渲染、说明前因后果。

- **红线**：不在读者已经能自己推断的地方继续解释。判断标准——如果删掉某句/段解释后，读者仍能从上下文准确理解人物动机/事件逻辑，则该解释属于"不信任读者"的多余产物，直接删除。
- **执行提示**：写完一段后，遮住解释性句子，看上下文是否仍然成立。如果成立，删。

### 原则二：动作优先于说明

同一份信息，用动作展示比用文字说明快 3 倍以上。

- **错误**："他很难过，因为他想起了前妻。"（说明）
- **正确**：他翻通讯录翻到"前妻"两个字，停了三秒，把手机扣在桌上。（动作）
- 正文创作时，优先问"这个情绪/信息/关系能不能用角色做什么来表达"，而不是"我该怎么解释给读者听"。

### 原则三：避免文人式自恋

> 来源：自知乎答主猴姆（新知答主）

作者常见的自恋陷阱：忍不住在作品里炫耀自己的才华、脑洞、知识储备——恨不得读者从字里行间看出你是个多有才华的人。

- **自恋诊断三步法**：
  1. 这句话是为了推进故事、塑造人物、让读者获得情绪体验，还是为了让读者觉得"这个作者真有才/真幽默/真细腻"？
  2. 如果答案是后者，直接删。你的读者不是来欣赏作者陶醉的。
  3. 如果某段让你觉得"写得太精彩了舍不得删"——把它放 24 小时再回看。如果回看时它的叙事功能仍然清晰，保留；如果只剩"写得好但没用"，删。

### 补充原理：阅读是体验，不是分析（新增——吸收自知乎顾里木图的小酒馆）

> **来源**：知乎·顾里木图的小酒馆《网文写作怎么样走进读者的内心》（2026-07-09）。

"信任读者"的底层原理：**读者阅读时不是在"分析"你的故事，而是在"体验"它。**

大脑处理分析与体验用的是完全不同的区域。分析是理性脑，负责判断"这合不合理"；体验是情感脑，负责感受"我在不在里面"。读者的第一反应从来不是"这写得好不好"，而是**"我进去了吗"**。如果他进不去，他根本不会进入分析阶段——直接划走了。

**实操含义**：落正文前，对每一段问自己——这段内容，读者需要"动脑子理解"还是"用身体感受"？

| 动脑子（分析模式） | 用身体感受（体验模式） |
|-------------------|---------------------|
| "她站在阳台上，回想着过往的五年。" | "她把戒指摘下来，放进抽屉最深处。" |
| 读者启动理性脑整理信息 | 读者直接看到画面，没动脑子就进去了 |
| 读者变成了分析者 | 读者变成了体验者 |
| 容易划走 | 不容易划走 |

**感官信息的力量**：它绕过读者的"防御系统"——读者没有时间思考"我该不该信你"，因为他已经进入了一种感觉里。一旦身体被勾住，大脑才会跟着留下来。

此原理与"信任读者原则"的关系：信任读者的第一步不是"不解释那么多"，而是"让读者直接体验，不需要他们先分析再感受"。

### 原则四：节奏的底层逻辑——集中、专注、克制、高频率

> 来源：自知乎答主半盏清茶煮春秋（新知答主，461赞同）

快节奏正文创作的四个设计原则，在落稿前自检：

| 原则 | 含义 | 创作执行 |
|------|------|---------|
| **集中** | 所有剧情紧紧围绕核心卖点/主线聚集、压缩 | 正文中超过 3 句偏离主线的描写/说明 → 标记删除或压缩 |
| **专注** | 剔除繁琐细枝末节，专注于一条线、一件事 | 连续 2 段以上处理不同事务 → 判断是否需要另开一章；单章内不宜超过 2 条并行线 |
| **克制** | 时刻警惕肆意挥毫泼墨的冲动，能收得住 | 写完一段后问"如果只留现有的 50%，信息还完整吗" |
| **高频率** | 加快节奏是为了让卖点/亮点/爽点以更高频率出现 | 每 500 字检查一次：读者从最近 500 字里拿到了什么？如果什么都拿不到（无信息/无情绪/无推进），标记为"空心段落" |

## 写作生动化铁律（新增——吸收自知乎答主好难说故事·喷神）

> **核心诊断**：你的文笔不是差，是不生动。不生动才是正文最致命的缺陷。而"不生动"的根本原因不是词汇量不够，是**多用了形容词，少用了动词**。
>
> 来源：知乎喷神《我感觉我的文笔有点差，但不知道差在哪里，怎么解决呢？》——此回答获 267+ 赞同。

以下四条铁律解决同一个问题：正文怎么从"文字正确但无感"变成"文字鲜活有画面"。它们不是写作技巧建议，而是在落稿前和落稿后必须逐条检查的硬性验收标准。

### 铁律一：多写动词，少写形容词（强制）

**病灶**：写一个人物出场，用"一道清亮的女声响起"这类抽象形容词开头。形容词的问题是——读者无法在脑子里生成画面。"清亮的女声"是什么样的？闭上眼睛能想象出来吗？如果不能，这句就是废笔。

**纠正规则**：
1. **动词优先原则**：能用动词表达的信息，不用形容词。同样的场景——不写"一道清亮的女声响起"，而是写"女孩一边啪啪拍打主角的脸颊，一边神色紧张地查看左右身后"——三个动词（拍打、查看、左右身），一个画面，直接在读者脑子里形成了一个场景。
2. **选词"着力点"测试**：写一个词前，自问——"闭上眼睛，这个词能在读者脑中形成画面吗？"如果能，保留；如果不能（如"清亮的""美丽的""让人印象深刻的"），换成有着力点的动词+基础描写组合。
3. **形容词替换表**：

| 空洞形容词 | → 替换为 |
|---|---|
| 清亮的（声音） | 具体行为+情绪（女孩压低声音，手指抓紧袖子） |
| 安静的（环境） | 具体感官（只听见墙上的钟在走） |
| 帅气的/漂亮的（外貌） | 具体动作+他人反应（他进门时，前台的女人愣了片刻） |
| 紧张的（气氛） | 身体的微反应（喉结滚动、手指敲桌、呼吸变浅） |
| 恐怖的（场景） | 视觉焦点+身体反应（那具尸体缺了半边脸，他的胃猛地抽了一下） |

4. **动词驱动的验收标准**：正文写完后，统计前 300 字中动词与形容词的比例。如果形容词数量超过动词的 1/3（即每 3 个动词才允许 ≤ 1 个形容词），判为形容词过度，需优先替换最空洞的形容词。

### 铁律二：开篇第一段必须拉读者入场（强制）

**验收方法**：写完第一段后，闭上眼睛，这段文字能不能在你的脑中形成一个场景画面？如果有画面，通过。如果没有画面（"一道清亮的女声响起"这种抽象叙述不可能形成画面），这一段就是废笔，必须重写。

**更严格的版本**（好难说故事原话）：
> 我这么多年来一直信奉一个原则：**开篇第一段，要一下子就把读者拉进故事里。** 最起码，也要让你看上一眼，脑子里立刻就会出现一个场景，一个生动的场景。

实操时，落稿前先检查第一段的第一个动作——它是否在读者的想象力里生成了一个具体影像。如果第一段是"对白+抽象形容词"的组合，大概率是废笔。重写方向：把形容词换成"基础描写+动词+着力点的词语"。

### 铁律三：人物必须动起来——静止描写即无趣（强制）

**病灶**：人物出场后只有静止的描写（外貌描述、身份说明、衣着打扮），没有跟随情节推进的即时行为。结果是"人物没有动起来，情节也没有动起来"。

**纠正规则**：
1. **出场即行为**：人物第一次出现在本章时，必须附带一个当前场景下的即时行为（动作/反应/判断），而不是先来一段静止的外貌或身份描述。
2. **行为暗示情绪**：不要用形容词宣布情绪，用行为暗示。示例：
   - ❌ 她很担心
   - ✅ 她一边拍打主角的脸颊，一边神色紧张地查看左右身后——读者的直觉判断：她很担心，而且这里有危险
3. **行为制造牵连感**：人物的行为必须与其他人物或场景产生牵连。两个陌生人坐着说话缺乏张力；但"女孩在危险的地方坚持叫醒主角"——读者立刻感知到两人关系很好，事件有重量。
4. **通过行为留悬念**：人物的行为自带信息缺口——女孩为什么紧张？这里是什么地方？他们为什么会在这里？这些悬念一起，不需要任何背景交代，故事已经开始了。

**验收**：写完每个新人物出场的场景，逐段检查"这段是否只是静止的描写"。如果删掉这段描写后读者仍然不知道这个人物对当前场景做了什么贡献，说明人物没有动起来。

### 铁律四：你不是在写作文，是在讲故事（心态硬规则）

**心态转变**：
> 写出来的东西是打算拿出来卖钱的，不是交上去给老师批阅拿分数的。这是两个完全不同的赛道。你需要的是让读者感兴趣、有迫切的阅读欲望，不是写几个形容词，让老师多给你几分。

**实操含义**：
1. **从讲故事而非写作文的角度出手**：想想你跟朋友叙述自己经历时是怎么说的——有画面、有动作、有先后顺序、有情绪起伏。但一下笔就切换成了"作文思维"——追求句式工整、用词华丽、逻辑完美。把"作文开关"关掉，打开"叙事开关"——你面对的不是阅卷老师，是一个在手机屏前随时会划走的读者。
2. **减法比加法难**：新人的普遍毛病不是"写得太少"，而是"不知道哪些不该写"。"文笔生动"不是靠多写形容词实现的，是靠**去掉不必要的信息、保留最核心的画面和推进感**实现的。每写一段，问自己——删掉这段，故事逻辑受影响吗？如果不受影响，说明它在制造"无意义的文字量"而非故事推进力。
3. **你不是没有写作能力，是没用对赛道**：很多人认为"我文笔不好所以写不好小说"，但这个判断是错的。大多数新人的文字基础足够写网文，问题是把写作文的方法用在了讲故事上。换赛道后，同一段文字的生命力可以完全不同。

## 段落节奏快慢控制规则（新增——吸收自知乎"写作技巧——如何把控小说节奏"）

> **来源**：知乎·黛西若《写作技巧——如何把控小说节奏？》（2026-06-30）。
>
> 节奏控制不是玄学，是一套可以量化和执行的写作规则。以下规则在落正文时作为段落级别的执行标准。

### 规则一：分清快慢两种叙事，选择对应的写法

| 节奏类型 | 适用场景 | 句法要求 | 描写策略 | 字数密度 |
| --- | --- | --- | --- | --- |
| **快节奏** | 打斗、对峙、突发危机、激烈冲突 | 多用短句，一句一事，少用从句和修饰限定 | 只写动作和直接反应，不堆砌风景和内心碎念 | 密——用最少字推进最大信息量 |
| **慢节奏** | 回忆、独处、细腻感情、关系铺垫 | 允许中长句，增加感官细节的嵌入位置 | 增加触感、气味和小动作细节，放慢镜头 | 疏——用细节让读者停留在场景中 |

**验收标准**：写完每个场景段落，判断其节奏属性。若快节奏场景出现超过 2 句以上的风景/内心描写，判定为节奏拖沓。若慢节奏场景连续 3 句没有感官细节（触觉/嗅觉/听觉），判定为节奏跑快。

### 规则二：松紧循环——一段紧张后必须跟一段舒缓

**核心规律**：一段紧张冲突后，必须配一段舒缓情节。目的是避免读者看得疲惫。

| 紧（冲突/高潮） | → 松（缓冲/沉淀） |
| --- | --- |
| 激烈争吵 | 两人安静谈心 |
| 生死险境 | 短暂休整、规划出路、想解决方案 |
| 追击/搏斗 | 喘息、检查伤势、复盘 |

**验收**：落正文时检查每段紧张冲突后，是否在 2 个自然段内给出了一个"松"的段落让读者呼吸。连续 3 段以上全是紧张推进，无论单段写得多好，读者都会在读到第 3–4 段时开始疲劳。

### 规则三：靠篇幅和段落结构调节节奏

- **冲突剧情**：用短段落和少文字，尽可能多用动词。动词多了读者就会跟着动作走，一个动作接一个，节奏明显加快。
- **情感铺垫**：用长段落多细节，从视听嗅三个感觉和细节上入手，让段落变得细腻，读者自然放慢阅读速度。
- **章末留悬念**：每章结尾留一个悬念拉高读者对下一章的期待。
- **章首用平缓**：每章开头用相对平缓的场景，让上一章的紧绷感得以缓和，再逐步拉入本章冲突。

### 规则四：三个最常见的节奏陷阱

写正文时需规避（对应审阅 Skill 的检查项）：

1. **全程打斗冲突，没有缓冲** → 人物形象空洞，读者对"谁在打、为什么打"的感知越来越模糊。
2. **大段无关日常和冗长心理戏** → 主线停滞拖沓，读者失去方向感。
3. **快慢切换生硬** → 刚写完生死场面，立刻切入无关琐事，读者情绪断裂。

**写后自检口诀**：写完一章检查每个段落——这里是冲突还是铺垫？前后段落有没有快和慢的对比？有没有跟主线毫无关系的多余文字？冲突字数砍砍砍，铺垫细节加加加，但要合理。

## 段落执行纪律：一段只做一件事与重要词重复三次（新增——吸收自知乎顾里木图的小酒馆）

> **来源**：知乎·顾里木图的小酒馆《网文小白开始写小说，有哪些快速掌握的写作技巧？》（2026-07-01）。

以下两条是段落级执行规则，落正文时逐段验收：

### 纪律一：一段只做一件事（强制）

**规则**：一个段落只做一件事——描写环境、推进对话、展示动作、刻画心理，四选一。不要把三件事塞进一个段落。

**原理**：段落是读者的"呼吸间隔"——一段太密，读者喘不过气；一段太长，读者容易走神。

**违规示例**：
```text
他推开门，房间里拉着窗帘很暗（环境）。"有人吗？"他问（对话）。没人回答，他握紧了口袋里的刀（动作+心理）。
→ 三个功能塞进一段，读者被不同信息层拖着跑。
```

**合规写法**：
```text
他推开门。房间里拉着窗帘，暗得让人眯眼。
"有人吗？"
没人回答。他在门边站了几秒，手指摸到口袋里的刀柄——硬的，凉的。
→ 三段各司其职：环境→对话→动作+心理。
```

**验收**：写完每个段落后，提取该段的核心功能（环境/对话/动作/心理）。如果一个段落提取出≥2个核心功能，且这两个功能可以拆到不同段落而不损失叙事效果——说明违反了纪律一，需要拆分。

### 纪律二：重要的词重复三次（建议）

**规则**：重要的名词、地名、物品、一句话，在全文范围内安排**三次显性出现**。第一次是信息（告诉读者"有这个东西"），第二次是强调（让读者记住"这个东西很关键"），第三次是记忆锚点（读者一看到它就会自动激活情感分量）。

**原理**：读者在碎片化阅读中很难一次记住新信息。三次重复是最低有效剂量——第四次出现时，这个词已经自带情感重量了，不再需要作者额外解释。

**实操示例**：
- 一个关键地名：第一次在对话中被提及 → 第二次在地图上出现 → 第三次主角到达该地时读者已有"就是这个关键地方"的预期。
- 一个关键物品：第一次被主角发现 → 第二次使用时展示功能 → 第三次在危机中被想起/被激活。
- 一句关键伏笔台词：第一次有人说出 → 第二次在不同情境下被复述 → 第三次在真相揭示时由同一个口中说出——情感火山爆发。

**验收**：正文写完后，搜索全文中的重要名词——每个名词最少出现 2 次，核心名词（书名/简介中承诺的卖点关键词）最少出现 3 次。少于 2 次的，判断是否可以被读者自然记住；不能的，在后续章节中补一次回指。

## 延迟释放：重要情感节点的写作技法（新增——吸收自知乎顾里木图的小酒馆）

> **来源**：知乎·顾里木图的小酒馆《网文小白开始写小说，有哪些快速掌握的写作技巧？》（2026-07-01）。
>
> 核心原则：重要情感节点（坏消息、死讯、背叛、诀别、震惊真相），不要让人物当场完整宣泄。

### 三层序列法

听到坏消息后，人物的正确反应序列是：

```
第一层：愣住/空白（信息未处理阶段）——"他站在电话前，没动。"
第二层：做一件普通的事（无意识缓冲）——"他转过身，把掉在地上的书捡起来，放回桌上，又拿起来翻了一页——他不知道自己翻的是什么。"
第三层：情绪才开始流（延迟爆发）——"他坐下来，把手盖在脸上。肩膀开始抖。"
```

### 为什么延迟释放比当场宣泄更有力

| 当场宣泄 | 延迟释放 |
|---------|---------|
| 情绪一次性消耗完 | 情绪在人物和读者之间共同承载 |
| 读者只是"接收"了情绪 | 读者和人物一起"经历了"情绪 |
| 场景结束后读者没有余韵 | 场景结束后情绪还在延续 |
| 适合低龄/快餐向写法 | 适合希望读者记住"这一刻"的场景 |

### 实操示例

```text
❌ 当场宣泄（低段位）：
她看完短信，眼泪就掉下来了，"为什么……"她哭着滑坐在地上。
→ 情绪已释放，读者无事可做。

✅ 延迟释放（高段位）：
她看完短信，把手机翻了个面扣在桌上。然后站起来，去厨房倒了杯水。水接满了也没关，水流了一地。她低头看着水漫过拖鞋的边沿，才慢慢蹲下来，把脸埋进手臂里。
→ 读者从"低头看水满溢出"这个漫长瞬间里，和人物一起感受到了那口气有多沉。
```

### 适用场景

- 人物得知亲近之人死讯 / 重伤
- 人物被最信任的人背叛 / 出卖
- 人物听到不愿面对的判决 / 真相
- 人物的重大梦想破碎 / 计划落空
- 人物在长期压抑后的关键情绪决堤

**例外规则**：当情绪本身是悬念的一部分（如角色在假装悲伤），或场景需要极端快速推进节奏时，允许省略延迟释放层，直接写动作推进。

### 常见错误补充：情绪刚起来就翻篇了（新增——吸收自知乎顾里木图的小酒馆）

> **来源**：知乎·顾里木图的小酒馆《网文写作怎么样走进读者的内心》（2026-07-09）。

延迟释放的对立面不是"当场宣泄"——还有另一种更隐蔽的灾难写法：**写了情绪触发点，但没给情绪留展开空间就直接翻篇。**

最常见表现：主角受了委屈、失去了重要的人、被误解了——然后下一句就是"第二天早上，她照常去上班了"。情绪刚起来就没了。读者刚准备好要痛，你已经翻篇了。

**纠正原则**：在情绪即将爆发的地方，慢下来。

延迟释放要求的是"情绪的呈现方式"（通过动作/细节展示而非直抒胸臆），而这个补充原则要求的是"情绪的展开时间"——不要在情绪刚触及读者时就切换场景或推进剧情。

**新增案例**：

```text
❌ 情绪刚起就翻篇：
她最好的朋友去世了。她很伤心。第二天早上，她照常去上班了。
→ 读者刚感受到"去世了"的冲击，情绪通道还没来得及打开就关了。

✅ 在痛的地方停下来：
她最好的朋友去世了。
她回家的路上买了朋友最爱喝的那款酸奶，走到门口才想起来——她不用买了。
她站在冰箱前，不知道该把酸奶放进去还是扔掉。
她把酸奶放进了冰箱。三个小时后她打开冰箱看了一眼，又关上了。
→ 读者从"不知道该拿这件事怎么办"的茫然里，感受到那种比大哭更接近"痛"的真实形状。
```

三个小时后的冰箱回看——这个细节比任何"她很伤心"的描述都更有力，因为它展示了**情绪的余波不是一次释放完的，它会在不经意间反复回来**。

## AI 上下文管理原则：避免上下文污染（新增——吸收自知乎 zzZZ）

> **来源**：知乎·zzZZ《小说写作有什么是AI永远取代不了的？》（2026-07-11），关于 AI 辅助长篇创作中"上下文污染"问题的系统性分析。

### 核心问题：上下文污染

使用 AI 辅助写长篇小说时，最常见的误区是"为防止 AI 忘记设定，把知道的东西几乎都给了它"——角色档案、世界规则、剧情大纲、未来安排、未公开伏笔，甚至作者后台设计。

但 AI 并不因为知道更多就写得更好。**当 AI 所处的信息位置是错的，它只会用更自然的语言，继续写出同一种错误。**

"上下文污染"不是资料太多，也不是对话窗口太长。真正的问题是：**性质不同的信息被放进了同一个上下文，却没有告诉 AI 它们分别属于什么层级、能在什么地方使用。**

### 三类典型污染表现

| 污染类型 | 表现 | 诊断信号 |
|---------|------|---------|
| **已确定内容与过程方案混在一起** | AI 把旧设定写回来、把候选方案当事实 | 正文中出现已废弃的设定或"可以这样写"的候选被当作确定事件 |
| **幕后信息进入故事现场** | 人物知道不该知道的事，说话像作者借嘴 | 人物行为基于"完整的作者认知"而非"角色当前的信息视野" |
| **创作视角和读者视角混在一起** | AI 以全知视角评价正文，替正文补因果 | AI 审阅结论说"逻辑成立"但真实读者读不懂 |

### 四道边界：解决上下文污染

#### 边界一：内容边界

长篇项目中的资料至少应分成三类，各做标记：

| 类别 | 定义 | 在上下文中的标记方式 |
|------|------|-------------------|
| **已确定·当前有效** | 经过确认、正在使用的事实性内容 | 作为"当前依据"提供 |
| **候选·未定方案** | 正在讨论、尚未采用的选项 | 显式标注"候选/待确认" |
| **已过时·历史记录** | 曾经有效但已被替代的旧版本 | 不放入当前创作上下文，仅作追溯参考 |

**不能只靠文件日期或上下文顺序让 AI 自己猜**。创作者需要明确告诉它：这一次哪些是事实、哪些只是参考、哪些已经作废。

#### 边界二：任务边界——三问法

写正文前，对当前要提供给 AI 的上下文执行三问筛选：

```
① 这一次必须知道什么？
② 什么东西即使不知道，也不影响完成任务？
③ 什么东西一旦看到，反而会污染当前视角？
```

**"低上下文"不是故意少给资料，而是只给准确、必要、当前有效的资料。**

不同任务需要不同的上下文粒度：
- **写一个场景**：需要当前人物状态、场景目标、与前文的衔接、本段风格要求、不能违反的必要设定
- **检查前后逻辑**：可以多看时间线、规则和已发生的事实
- **判断读感**：只应该看读者当下真的能看到的内容

#### 边界三：视角边界

同一份正文，可以从三个不同位置来看，各自需要不同的上下文：

| 视角 | 关心什么 | 应该看到什么 | 不应该看到什么 |
|------|---------|-------------|---------------|
| **创作视角** | 当前场景如何变成可读的故事 | 人物当前的认知、情绪、关系、行动目标 | 完整的未来计划、作者后台设计 |
| **校验视角** | 前后有无矛盾、人物是否知道不该知道的事 | 已确定规则、时间线、已发生事实 | 作者意图、未定方案 |
| **读感视角** | 普通读者能不能看懂、哪里跳读、章末是否想继续看 | 读者能看到的内容 | 作者的幕后解释、未来安排 |

#### 边界四：决策边界

AI 上一轮提出的修改建议、下一轮不应自动升格为已确定设定；初稿临时写出的细节，不应让后续项目围绕它补逻辑。

不同输出必须有不同状态：
```text
候选 → 可以讨论，但未采用
待验证 → 可以试写，但不能进入长期设定
已采纳 → 经过确认，成为后续依据
已过时 → 只保留为历史，不再参与当前创作
```

只有经过明确确认的内容，才能升格为后续创作依据。否则，AI 的每一次自由发挥，都可能在项目里新增一个需要被其他文件配合的"事实"。

### 与 References 系统的关系

本 Skill 现有的 "继续读取的 references（强制读取门禁）" 机制已经建立了"内容边界"的基础框架——它区分了不同层级、不同用途的引用文件。四道边界原则是对该框架的补充解释：

- **references 中的"必读"文件** → 对应"已确定·当前有效"
- **references 中的"按需加载"文件** → 对应"仅当任务需要时提供"
- **跨 Skill 引用（如人物传记）** → 对应"只提取当前场景需要的部分，而非全量加载"

在调用本 Skill 执行正文创作时，应主动应用任务边界的三问法对 references 做一次筛选，而不是机械地把所有必读文件全量塞入上下文。

### 最后的判断

如果 AI 写出来的正文让人感觉"人物说话像设定说明书"——先问一句：这真的只是文笔问题吗？

- 人物说话像在替作者解释设定 → 可能是因为 AI 看到了人物不应该知道的作者后台
- 情节还没发生就失去悬念 → 可能是因为 AI 在写当前场景时带着未来几章的设计
- AI 审阅结果总在替正文找补 → 可能是因为它和创作过程共享了同一套幕后信息

如果 AI 所处的信息位置就是错的，那么"写得自然一点"只会让它用更自然的语言，继续写出同一种错误。

	4. 再把控制卡落成场景与正文：`通用-执行场景单元`
	5. 再用“场景串章与章级回报分配卡”确认哪一场负责抓眼、哪一场负责中段回报、哪一场负责章末钩子。
	6. 正文首轮必须把本章应有的场景、回报、升级与章末钩子一次写进正文，并把正文字数直接推到达标区间附近；只有已经明确记录结构性缺口时，才允许后续补写，不得把“后续再慢慢扩写”当常规流程。

	7. 章首不够抓时，再调用：`通用-强化章节开头`
	8. 章末驱动力不足时，再调用：`通用-强化章末钩子`
	9. 全章需要整体提纯时，再调用：`通用-正文润色`
	10. 若 `## 作者有话说` 初稿偏复盘、讲设定、讲创作过程或剧透过重，再调用：`通用-润色作者有话说`
	11. 模板腔、假人声或机械表达明显时，再调用：`通用-去AI味重写`，并先做一句病灶诊断，再锁定三档手术强度。

- 阶段 D：最小复检清单
	12. 落稿后必须完成一组字数复检：**正文字数检测必须使用 `scripts/count-chapter.ps1`**，不得用 `Len`、`NoWhitespaceLen`、编辑器字符数或目测代替。字数参数按以下优先级确定：① 项目 `Agents.md` 中主输出平台指定 → ② 主输出平台对应 `通用-输出*版/SKILL.md` 的"平台默认字数范围" → ③ 通用回退值（中文正文 2500–5000 CJK，作者有话说 150–300 CJK）。正文门禁只看 `BodyCJK / MeetsMinCJK / WithinRange`，`MeetsMinCJK` 必须为 `True`，`WithinRange` 最好为 `True`。`## 作者有话说` 用 `scripts/count-afterword.ps1` 单独校验。

## 极其快的节奏与极其强烈的冲突——正文层实施方法（新增）

快节奏与强冲突不能只停留在大纲设计里，必须落实到每个场景、每段对话、每一句中。以下是可直接套用的正文执行规则。

### 快节奏的正文层实施

**1. "前 300 字"的多层信息密度**
每章的前 300 字应该用最少的词汇传达最多的信息：
- **是谁**：主角或关键角色出场（不用详细外貌，用一个最扎眼的识别符）
- **在哪**：具体的地点（不是"办公室"，而是"13 楼财务部的那间隔间，窗帘拉到一半"）
- **发生了什么**：眼下的冲突或异常（不是铺垫，而是"已经进行中的问题"）
- **有多危险/紧迫**：读者为什么要紧张（倒计时、威胁信号、身体反应）

示例（快节奏）：
```
陈勉推开财务部隔间的门时，王主任的脸色已经白透了。屏幕上的转账记录还在滚动——200 万，按每笔 10 万分出去，只用了三分钟。

"不止这个。"王主任颤抖地指向另一个窗口，"从年初开始。两年。"

陈勉的心沉了一下。两年。这不是临时挪用，这是有预谋的。

楼下，执法部队的车刚停在门口。
```

这 200 字里已经传达了：人物、地点、冲突（侵吞公款）、时间压力（执法部队要来了）、危险强度（从两年前开始）。

**2. 场景切换的"快速断推进"**
不要用过渡段描写角色的移动、思考或休整；直接切到下一个有冲突的场景：
- ❌ 慢：陈勉冲出办公室，冲进电梯，脑子里混成一团。这一刻他忽然明白了什么，转身要往楼下跑……
- ✅ 快：陈勉冲进电梯。楼下，执法部队已经登上了大厅。

快速切场能直接制造"不给主角（和读者）喘息时间"的压迫感。

**3. 对话里的"叠加信息"而非"轮流问答"**
每一轮对话都应该同时承载多个层面的信息，而不是纯粹的信息交换：
- 表层：谁说了什么
- 中层：说话时的态度转变或隐藏目的
- 深层：这句话对下一步行动的直接推动

示例（强对话）：
```
"两年。"王主任的声音里混着哭腔，"我想举报，但你知道的，他在上面有人。"

陈勉不说话。

"我没办法。"王主任继续说，声音更低了，"但如果有人敢动他……我可以作证。"

这不是示弱，这是威胁——王主任在告诉陈勉，如果官方动作太大，他会反咬。

陈勉抓起电话："我需要十分钟。"
```

每句话都在改变局面：从"我是受害者"→ "我也有隐形的权力"→ "我随时可以反水"。

**4. "动作-反应-后果"的紧凑三段式**
不要让一个动作的后果延迟显现；应该在同一场景内快速循环：
```
陈勉砸了手机。[动作]

王主任跳起来，往门外看。[反应 1]

对讲机里传来"已锁定财务部"的声音。[反应 2 - 并行的环境反应]

陈勉的脸色变了——他刚砸的手机里有定位器。[后果 1 - 代价显现]
```

这样的紧凑节奏能让读者感受到"每个动作都在改变局面，每个选择都有代价"。

### 强冲突的正文层实施

**1. 每场场景的"三元对立"设计**
一个有力的场景应该让至少三方的利益或立场发生碰撞，而不是简单的"主角 vs 敌人"：

示例：
- 主角想逃脱（目标 A）
- 搭档想自保，劝主角放弃（目标 B - 与主角冲突）
- 敌人在追，但也想抓活的（目标 C - 与主角冲突，但与搭档的目标有交集）

这三方的目标互相缠绕，导致"没有绝对的盟友，也没有绝对的敌人"的复杂局面。

**2. 对话中的"立场碰撞"而非"信息传递"**
任何对话都不应该是纯粹的Q&A；应该是两个诉求的碰撞：
- 甲的诉求：隐瞒真相，继续冒充
- 乙的诉求：揭露真相，得到补偿

对话的每一句都应该在争夺主动权：
```
"你为什么要背叛我？"陈勉问。

"背叛？"搭档冷笑，"我救了你的命。那笔钱本来是给刺客的，我拦了下来。"

陈勉愣了一下。

"但现在你欠我的。"搭档继续说，"要么跟我一起消失，要么我把你的身份卖给官方。三秒钟选择。"
```

这里每一句对白都在改变主权关系：从"被背叛者"→ "被救者"→ "被勒索者"。

**3. "人物目标与主角目标的冲突"的具体化**
不要让冲突停留在"立场不同"的抽象层面；应该具体到"这一刻，双方都想要同一个有限资源"：

**资源例子**：
- 同一条逃脱路线
- 唯一能证明清白的证据
- 掌握关键信息的那个人
- 有限的时间窗口

这样冲突就不是观点差异，而是**实实在在的竞争**：
```
证人只愿意见一个人，而且要在十分钟内。

陈勉和搭档都需要这个证人的证词，但理由完全相反：陈勉要证明自己无罪，搭档要栽赃陈勉。

两人同时冲向证人的住处。
```

这是**真正的冲突**——不是能商量的，也不是能各让一步的。

**4. "代价与选择"的不可逆性**
每个场景的结尾，主角都应该因为这场冲突而付出**不能撤销的代价**：
- 失去了一个信任的人
- 暴露了一个隐藏的筹码
- 激怒了一个之前不是敌人的势力
- 被迫做出违背原则的选择

示例：
```
陈勉逃了，但代价是让搭档被抓。

现在有两种可能：
1. 搭档会在刑讯中吐出陈勉的所有秘密
2. 搭档会用陈勉的秘密去和官方协商，牺牲陈勉来保护自己

两种都意味着，陈勉失去了唯一知道他全部真相的人。下一卷，他会被迫找新的信任对象，而新对象未必可信。
```

**5. 场景中的"权力位移"与"信息翻面"**
强冲突的场景应该让读者感受到**局面在剧烈改变**，而不是"说了很多话但局面没变"：

标记方式：
```
场景开始时：主角掌握主动权（知道敌人的位置，但敌人不知道他在哪）
场景中段：信息翻面（敌人突然出现，说"我们早就知道你在这里了"）
场景结尾：权力彻底反转（主角被包围，敌人要求投降或死亡）
```

每一次权力位移都应该以**具体的新信息**为触发点，而不是"敌人的运气更好"这样的虚弱解释。

### 场景字数与节奏的控制

为了确保"快"的体感，应该控制场景的字数与密度：
- **快速冲突场景**：1500-2500 字 / 场，信息密度高，动作快，对话有张力
- **复杂谈判 / 对话场景**：2000-4000 字 / 场，允许更多对话轮换，但每轮都必须改变局面
- **环境与逃脱场景**：1500-2000 字 / 场，短场景能制造"时间紧迫"的感受

禁止出现 4000+ 字的单场景，除非这个场景本身就是"卷级高潮"。长场景容易让节奏显得拖沓。

### 正文撰写时的"快冲突"检查清单

落稿时自检以下项目：

[ ] 前 300 字是否同时传达了人物、地点、冲突、紧迫感？
[ ] 场景切换是否避免了过渡段和休整时间？
[ ] 每轮对话都在改变局面（权力、信息、关系）吗？
[ ] 每个场景是否都有"动作 → 反应 → 后果"的紧凑三段式？
[ ] 是否有"三元对立"的多方角色冲突，而非简单的"主vs敌"？
[ ] 冲突的资源是否具体（路线、证据、时间窗口），而非抽象（立场、信念）？
[ ] 每个场景的结尾是否都有不可逆的代价或局面改变？
[ ] 是否有明确的"权力位移"或"信息翻面"时刻？
[ ] 场景字数是否合理（避免 4000+ 字的拖沓）？
[ ] 是否避免了"说了很多话但局面没变"的虚弱场景？

## 写前裁判源复核（强制）

- 正文落稿前，必须认真仔细阅读与本章实际出场人物对应的人物传记，以及与本章背景、技术、规则、证据、程序链、世界观有关的故事设定文档。
- 不得只凭章纲标题、上一章印象、题材套路或局部摘要直接开写；凡涉及人物动机、能力边界、关系状态、设定代价、证据机制的内容，都必须回到作者侧裁判源核对。
- 若同一人物传记或故事设定存在多个版本，必须先确认当前可执行的最新版本；若关键裁判源缺失，必须先补齐、定位或明确阻断，不能边猜边写。
- 若本章涉及多人、多条设定线或复合背景，必须把“谁的传记必须重读、哪份故事设定必须重读”列成最小清单，再进入正文施工。
- 正文、`## 章节后记` 或回写摘要里，至少要能说清本章具体服从了哪些人物传记约束、哪些故事设定约束，避免把裁判源读成摆设。

## 默认输出口径

- 默认直接产出可给读者阅读的章节正文成品。
- 默认同文件交付：正文、`## 作者有话说` 与 `## 章节后记`。

- 本 Skill 只处理章节级正文文件的创建、重写与回写，不承担分部 / 分卷独立文件的落盘规则。
- 若作品有分部，章节文件统一落在 `小说正文/第X部/第Y卷/`。
- 若作品无分部，章节文件统一落在 `小说正文/第X卷/`。
- 章节文件名默认不带日期，沿用项目既有章节号与短标题规则。

## 最低交付

- 有完整章节正文，而不是梗概或施工建议。
- 有清晰的章首抓力、中段回报与章末驱动。
- 有可直接保存的 `## 作者有话说` 与 `## 章节后记`，且 `## 作者有话说` 已写成“一个小细节 + 一点点共鸣 + 一个小问题”的读者向小剧场。

- 首轮成稿默认应尽量直接过正文字数门禁，不把结构性缺口留给后续反复扩写。
- 能说明本章主卖点怎样被看见、强化或延续。

## 开篇、排版与单章节拍共性要求（新增）

- 前 `300` 字默认至少完成两件事：人物当前处境、眼前损失风险、一个必须马上处理的异常或冲突。
- 若当前属于第一章到第三章，默认还要检查黄金三章职责：第一章立人物抓手与第一麻烦，第二章让人物顶上第一个挑战，第三章必须给一次可感知的小高潮、反击或更强升级。
- 单章默认应尽量看出“**钩子 → 蓄力 → 爆发 / 回报 → 留钩**”四拍；哪怕某一拍偏轻，也不能长期缺失。
- 正文优先用动作、感官、物件、口气、停顿、错位反应来传情绪，不要用抽象总结和作者说理替代现场压力。
- 默认按手机端友好处理：句子能短则短，段落能轻则轻，连续大黑块要警惕，尤其是开头与回报位。

## 研究回灌补强（2026）

- 情感向长篇默认参照“黄金三章”闭环：第一章立危机与处境、第二章加压并给破局抓手、第三章给首次可感知回报或反击。
- 开篇前 `300` 字未见冲突 / 异常 / 压力时，默认视为起手风险；开篇前 `1000` 字至少应能看见一次明确回报预期。
- 单章优先维持“钩子 → 蓄力 → 爆发 / 回报 → 留钩”的读者节拍，避免只有说明没有动作、只有铺垫没有兑现。
- 正文表达优先“情绪具象化”而非抽象总结：通过动作、感官、空间反常、物件变化和对话错位来交付情绪。
- 情感相关章节默认可参考“爽点 / 苏点约 `3:1`”的密度控制，防止全章只有关系拉扯而缺乏推进回报。

说明：`## 章节后记` 为强制交付项，不适用“若适用”口径；执行时以 `references/章节附属构件与后记规范.md` 与下文“硬规则”为准。
## 创作阶段留存检查（新增——与留存模型联动）

在正文初稿完成后，执行本章留存自检（参照 `../../写作研究/网文留存模型.md`）：

1. **300字情绪检查**：前 300 字内是否有可感知的情绪信号（冲突/异常/情绪锚点/悬念缺口）？若无，标记为章首留存风险。
2. **中段回报检查**：中段（30%-70% 篇幅处）是否有至少一个可指认的"读者赚到了"时刻（回报类型：身份抬升/关系推进/信息开口/局面反击/代价付出/认知升级）？
3. **认知负荷检查**：内部处理段（回忆/推理/独白/设定说明）最长连续是否超过 300 字？若超过，是否有外部打断（对话/动作/第三方介入/环境变化/身体反应）？
4. **章末驱动检查**：章末是否留下确切的续读钩子（新威胁/未完成动作/信息缺口/关系未闭合），而非以总结/抒情/留白收尾？
5. **动词密度检查**（新增）：本章冲突核心段（约200-300字）的动词密度是否 ≥ 50%？若低于50%，优先将形容词/抽象表达替换为动作描写。注意"感到""觉得""知道""认为"等非动作动词不计入。（参照 `网文留存模型.md` §八 动词密度留存基线）

任一自检不通过 → 优先修改对应段落后再进入润色阶段。
## 题材竞对分析接入要求（强制）

- 若当前任务服务某个题材，且该题材目录下的 `竞对分析/` 已存在与当前项目、当前平台或当前赛道相关的竞对分析报告，落稿前必须先读取并纳入本章判断。
- 若目标平台为起点中文网，或未注明平台但默认按起点口径处理，且当前题材目录下尚无可用竞对主报告，写关键章节前应优先调用 `通用-分析竞对作品`，至少补齐 **Top10 候选池、`3–5` 本主样本与四层深拆速览**；若任务限制导致本轮无法补齐，必须显眼记录盲区，并降低本章放行强度。
- 不得把这些报告只当成背景资料；必须显式对比本章的抓力、回报、人物付费价值、信息差、钩子与读者记忆点，说明本章准备在哪些维度追平、反超竞对。
- 正文创作的默认目标不是“把这一章写顺”，而是让当前作品在关键维度上**全方位超越竞争对手**；若本章看不出明确超越路径，应继续返工而不是直接放行。

## 起点化竞对吸收口径（新增）

当正文服务起点中文网，或未标平台而默认按起点基线处理时，默认把竞对吸收拆成以下四层，并直接翻译成本章的落稿约束：

- **市场数据层**：用榜单位次、均订 / 首订 / 收订比代理信号、推荐资源位等，倒推本章在前 `300 / 1000 / 3000 / 6000` 字、章末续读驱动与题材归类效率上至少该达到什么强度。
- **内容创作层**：重点吸收主样本在开篇切入、场景冲突、人物抓手、规则边界、信息差、代价显影、章末钩子上的做法，把它翻成控制卡、场景职责与正文动作链，而不是只记一句“这本书节奏快”。
- **运营策略层**：重点吸收主样本的追读工程、回报密度、本章说讨论点、更新节奏匹配与卷首 / 卷尾功能位，把它翻成“章首抓眼—中段回报—章末留钩”的执行要求。
- **受众反馈层**：重点吸收本章说 / 书友圈 / 书评区里高频被夸的爽点、被骂的拖点、老白读者不耐烦的病灶，提前写进本章避坑与加码策略。

起点语境下，默认尽量使用以下术语，而不是写成空泛的“读者喜欢这个章”：`均订`、`高订`、`首订`、`追订`、`收订比`、`分类月票榜`、`畅销榜`、`本章说 / 段评`、`书友圈`、`老白读者`。拿不到精确值时必须写成代理信号，不得伪造具体数字。

## 本层职责

- 统一承接章节正文创作的通用输入、输出、流程和文件回写要求。
- 统一承接“正文 / 作者有话说 / 章节后记”的通用结构规范。
- 统一承接写前资源清单、输入模板、交付标准、自检与后记模板。
- 把开头、章末、整章精修、去 AI 味等专项问题路由到更专门的通用 Skill。
- 当正文要进入去 AI 味回炉时，默认把“需保留的钉子、推荐强度、主要病灶”一并交给 `通用-去AI味重写`，避免只喊一句“去味”。

## 与其他 Skill / Prompt 的边界

- 如果当前任务发生在某个题材目录，并且该题材已建立 `题材名-创建小说正文` 包装层，则应优先通过题材 Skill 进入，再由题材 Skill 路由到本通用 Skill。
- 本 Skill 负责跨题材稳定复用的正文创作骨架。
- 题材 Skill 负责题材读者口径、题材硬约束、题材技法、题材禁行项与题材样例。

## 硬规则

- 默认目标是**直接写出读者可读的章节正文**，而不是停在提纲、分析或施工建议上。
- 默认不采用“先写一个明显偏短的草稿，后面再靠多轮扩写补到门槛”的常规路径；首轮应尽量一次写到足够字数，只把补字留给小范围微调或结构性回炉。
- 除非用户明确要求“只做构思 / 不落文件”，否则应把结果直接写回目标章节文件。
- 开写前必须认真仔细阅读本章相关人物传记与故事设定 / 背景设定文档；若关键裁判源未读、未定位或版本未确认，不得凭常识补完后直接落稿。
- 正文必须服从作者侧裁判源（大纲、人物、设定、时间线、台账）；如有冲突，以裁判源为准。
- 正文落稿前，必须先确认本章如何呈现、强化或延续主卖点；不得把卖点写到大纲里、落稿时又丢掉。
- 章节前段与关键回报位必须尽快让编辑和读者感知到“这本书最值得继续看的地方”，不得把卖点埋到过晚位置。
- `## 作者有话说` 只允许做三件事：用一个贴着正文的小细节交换情绪、给读者一点现实共鸣、留下一个小问题；不得写成章节点评、创作总结、设定讲义或直白剧透。
- `## 作者有话说` 不得直接明示本章 / 本系列的核心思想、暗线结论或制度判断；包括“所有制”“阶级”“分配权”这类主题词，只可借问题与生活小场景引导读者自行联想。
- `## 章节后记` 必须至少覆盖：本章定位、功能点落地核对、冲突与悬念、爽点登记、伏笔与回收、设定/程序呈现、人物发展、证据要素、钩子类型、数字纪律检查、偏离记录、后续铺垫、读者吸引点与优化建议。
- `## 章节后记` 只做作者侧复盘与校验，不得替正文补剧情、补动机、补关键证据或补本该在正文里看见的回报。
- `正文` 属于读者沉浸区，严禁出现章节自指 / 连载导览 / 作者讲评式话术，如“这几章”“前几章”及其“前面几章 / 前面这几章”变体、“后几章”及其“后面几章 / 后面这几章”变体、“整章”及其“这整章 / 这一整章”变体、“上一章”“下一章”“本章 / 这章主要”“后文会”“我们会看到”“读者会发现”等；若要交代承接，只能改写为人物当下记忆、局势余波、身体后果、物件残留或未完成动作。
- 上述禁例按“模式族”理解，不以列举为穷尽；例如 `前/后(+面) + 这? + 几章`、`这?(一)?整章`、`(上/下)一章`、`(本/这)章` 都属于同类出戏表达。
- 章末驱动必须靠新变量、新后果、未完成动作或具体危险来成立，不得用“下一章……”之类预告句替代钩子。
- 不得把人物写成只有高光、没有短板；重要角色至少要让读者看见他在能力、情绪、关系或选择上的真实阻力。
- 章节正文文件名默认不带日期；若新建文件，仍必须服从上文的 `小说正文/` 工作目录与章节层级规则；`## 作者有话说` 与 `## 章节后记` 作为同一正文文件的组成部分，也不得额外改成日期版文件名，除非用户明确要求另存归档副本。
- 交付前不得只凭目测判断篇幅是否达标；**正文字数检测必须使用 `scripts/count-chapter.ps1`**，不得用 `Len`、`NoWhitespaceLen`、编辑器字符数或目测代替。字数参数按以下优先级确定：① 项目 `Agents.md` 中主输出平台指定 → ② 主输出平台对应 `通用-输出*版/SKILL.md` 的"平台默认字数范围" → ③ 通用回退值（中文正文 2500–5000 CJK）。正文门禁只看 `BodyCJK / MeetsMinCJK / WithinRange`，`MeetsMinCJK` 必须为 `True`，`WithinRange` 最好为 `True`。`## 作者有话说` 用 `scripts/count-afterword.ps1` 单独校验。
- 若需要在后记、日志、摘要或审阅报告中记录篇幅数据，必须直接引用脚本输出字段 `Len / CJK / BodyCJK / MeetsMinCJK / WithinRange / MeetsAll`；不得改写成“正文字数：XXXX（去空白统计）”之类的替代口径。
- Prompt 可以变薄，但执行时不得因为 Prompt 变薄而漏读本 Skill 及其 references。
- 若项目或题材层另有更严格的时间、编号、平台、视角或格式约束，必须继续服从题材层。

## 完成检查

- 是否已读取本 Skill 声明的 references
- 是否已认真仔细阅读本章相关人物传记与故事设定 / 背景设定文档，并确认使用的是当前可执行的最新版本
- 是否已按默认顺序组合调用上游 / 下游相关 Skill
- 是否已直接产出“正文 + 作者有话说 + 章节后记”完整结构
- 是否已确认本章卖点没有在落稿中失踪，并且在前段或关键回报位被有效看见
- 是否已确认 `## 作者有话说` 不是书评 / 复盘 / 设定讲义，而是“一丢丢创作花絮 + 一点点共鸣 + 一个小问题”的读者向小剧场
- 是否已确认 `## 章节后记` 的强制字段完整、与正文逐项对应，且没有拿后记偷补正文缺失内容
- 是否已对正文区块完成“章节自指 / 连载导览腔”复检，并清掉“这几章 / 前几章 / 前面几章 / 前面这几章 / 后几章 / 后面几章 / 后面这几章 / 整章 / 这整章 / 这一整章 / 上一章 / 下一章 / 本章 / 这章 / 后文会 / 我们会看到 / 读者会发现”等出戏措辞
- 是否已显式运行字数门禁（参数按主输出平台对应 `通用-输出*版/SKILL.md` 的"平台默认字数范围"或项目 `Agents.md` 指定值确定），并确认正文 / 作者有话说字数都在合理范围内
- 是否已确认篇幅门禁判断使用的是 `BodyCJK`，而不是“去空白统计”或其它自定义字符数
- 是否已把结果写回目标文件，或明确遵从用户“不落文件”的要求
- 是否已完成自检，而不是只生成正文就停下
