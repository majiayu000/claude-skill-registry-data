# 通用-补充构建素材库
> **题材路由**：若 .github\题材专用Skills\ 目录存在对应的 <题材>-补充构建素材库 Skill，则：
> - 将题材特性骨架路由到 <题材>-补充构建素材库，该 Skill 位于 .github\题材专用Skills\ 目录。
> - 命中本技能时，必须优先强制加载当前 Skill 与 <题材>-补充构建素材库。


> 本 Skill 负责在已有素材库中执行"缺件诊断→定向搜索→格式落盘→索引更新→写入搜索日志"的全流程闭环。

## 硬规则（强制）

**三轴设计理念**：
- **扩展轴（题材层）**：当一个题材积累的素材量超过通用01-05池的覆盖范围（参见"可扩展——题材层"规则），在同级创建 `题材名/` 作为子素材库
- **深化轴（文件分裂）**：单文件超 100 条时，按子类拆分为子目录+多个文件（参见"可深化——文件分裂"规则）
- **搜索轴（情绪锚索引）**：`00_素材库总索引.md` 末尾维护跨池的情绪锚汇总表，配合 `grep_search` 快速定位（参见"可搜索——情绪锚索引"规则）

### 可扩展——题材层

> **问题**：01-05 通用池服务于当前小说的情节供血。但当你开新题材（如从都市职场转悬疑推理），不同题材的情绪锚/节奏/人设差异巨大，混在同一个池里互相干扰。更根本的问题是：**01-05 的分类逻辑本身来自女频都市情感题材，并非放之所有题材而皆准。**

因此在新建题材子库之前，必须先做**结构适配门禁**检查，确定通用池分类对该题材是否有效、哪些池需要替换、哪些池需要新增。

---

#### 结构适配门禁（新建题材子库前的必检项）

> **核心原则**：题材子库不是通用 6 池的简单复制。每个题材应该拥有匹配自身叙事特征的自有池体系。

**检查方法**：逐池回答以下问题，记录"保留/替换/禁用/新增"决策：

| # | 池名称 | 检查问题 | 决策 | 理由 |
|---|--------|---------|------|------|
| 01 | 情节桥段池 | 通用池中 A/B/C（职场商战/家族内斗/关系推进）的分类逻辑是否覆盖该题材的核心冲突类型？ | 保留/替换子类/禁用 | — |
| 02 | 名场面高光池 | 该题材是否有"可供读者截图传播的高光时刻"？其情绪递进节奏是否与通用池一致？ | 保留/禁用 | — |
| 03 | 人物设定池 | 该题材的人物类型是否超出"霸总/女主/反派/配角"框架？ | 保留/替换子类/禁用 | — |
| 04 | 轻悬疑反转池 | 该题材的悬念是靠"情感真相揭露"驱动，还是靠其他方式（世界之谜/案件推理/技术诡计）？ | 保留/替换/禁用 | — |
| 05 | 冷幽默毒舌池 | 该题材是否需要大量嘴炮/毒舌/金句供血？ | 保留/禁用 | — |

**执行规则**：
1. 新建题材子库前，必须先输出一张结构适配门禁表，记录逐池判断结果
2. 门禁表必须写入 `题材名_索引.md` 的"结构适配决策"段，供后续补充者参考
3. 被禁用的池直接跳过（不在题材子库中创建空目录占位）
4. 门禁表将来若发现原判断不合理，可修订并更新索引中的记录

#### 触发条件（扩展后）

出现以下**任一**情况时，应在 `素材库/` 同级下新建 `题材名/` 子素材库：

**数量驱动**（原规则，继续有效）：
- 当前项目切换到不同题材（如从"都市职场"切到"太空科幻"）
- 通用池中"与当前题材无关"的条目数超过 30%（说明池已被稀释）
- 同一题材的素材总量超过 200 条，且仍在快速增长

**结构驱动**（新增规则）：
- 通过"结构适配门禁"检查后，发现 **≥ 2 个池需要替换子类**，且替换幅度超过子类总量的 50%——说明通用池的分类轴已经偏移，不值得在通用层修补，应直接建题材子库
- 需要新增 **≥ 1 个当前 01-05 体系完全不存在的池类型**（如科幻需要"故事设定档案库"）——说明通用层不提供该维度的分类位置
- 题材的**核心叙事驱动力**与通用池设计时的驱动力不同（如通用池为"情感驱动力"设计，新题材为"解谜驱动力"或"世界观探索驱动力"）——说明情绪锚索引体系不通用

#### 题材所需池类型推断

> 新建题材子库时，不照搬通用 01-05 编号——而是按题材特征推断"这个题材需要哪些池"。

**推断维度**：

| 题材特征 | 需要的池类型 |
|---------|-------------|
| 冲突依赖外部事件/案件驱动 | → 事件/案件引擎库（可映射为 01 情节 -> 替换子类） |
| 冲突依赖人际关系/情感张力 | → 关系推进库、对话冲突库（可映射为 01C/01B） |
| 高光时刻依赖情绪爆发/反转/打脸 | → 名场面高光池（保留 02） |
| 高光时刻依赖认知冲击/解谜瞬间/设定震撼 | → 名场面高光池（保留 02，但分类逻辑替换为"解谜高光""设定揭示"等） |
| 人物是驱动核心 | → 人物设定池（保留 03） |
| 人物是世界观载体（如异能、赛博改造） | → 人物设定池（保留 03，但需增加能力/改造维度字段） |
| 有技术/规则/系统体系需要维护 | → **故事设定档案库**（新增 06）——存放技术原理、规则条款、程序链、证据载体 |
| 有空间/场景/氛围的叙事需求 | → **空间场景库**（新增 06/07）——存放典型空间的感官描述、氛围清单、空间剧本 |
| 需要离奇/灵异/超自然的气氛 | → **诡异氛围库**（新增）——存放氛围描述、异常征兆、感官细节 |
| 需要系统化的诡计/手法/谜题 | → **诡计手法库**（新增）——存放推理诡计、谜题设计、误导与线索编排 |
| 需要大量毒舌/金句/冷幽默调节节奏 | → 冷幽默毒舌池（保留 05） |
| 不需要毒舌调节（严肃/压抑/学术风格） | → 冷幽默毒舌池（禁用） |

**新增池的编号规则**：
- 通用 01-05 保留为通用层体系，不以题材层的加入而变更
- 题材子库中新增的池，编号从 **06 开始顺延**（无论通用层有多少池）
- 允许跳号，允许不在题材层中出现 01-05 中的某几个池（被禁用的池直接省略，不保留空编号）
- 编号在题材的 `_索引.md` 中重新声明，不与通用层的编号互相引用

#### 题材子库规则

1. **入口文件**：每个题材子库必须有一个 `题材名_索引.md`，格式参照 `00_素材库总索引.md`，此外额外包含"结构适配决策"段（记录门禁检查表）
2. **编号去前缀**：题材子库的子文件不使用字母前缀（如 `A_职场商战桥段.md`）——直接以意义命名（如 `跃迁引擎事故.md`），避免与通用池的编号体系冲突
3. **优先查子库**：写作时先查当前题材的子库，再回退到通用池。题材子库中不存在的通用桥段，用通用池补位
4. **新建后注册**：题材子库建好后，必须在 `00_素材库总索引.md` 末尾"子素材库注册表"中登记（路径+创建日期+覆盖池列表）
5. **情绪锚索引改为题材私有**：情绪锚索引在 `题材名_索引.md` 中独立维护，不再放到通用总索引中，避免跨题材的情绪锚混在一起失效
6. **通用池只增不减**：题材子库的新增池、禁用池只影响题材自己的素材操作，通用 01-05 池永远保留不动

### 可深化——文件分裂

> **问题**：单文件持续追加条目（如职场商战 80+ 条、冷幽默 100+ 条），迟早会因文件过长导致查找困难和编辑性能下降。

**分裂阈值**：

| 计量指标 | 触发分裂 | 建议动作 |
|----------|---------|---------|
| 单文件条目数 | 超过 **100 条** | 拆为子目录 |
| 单文件行数 | 超过 **500 行**（不含空行与分隔线） | 拆为子目录 |
| 文件内子类数 | 超过 **5 个 `##` 二级标题** | 每个二级标题拆为单独文件 |

**分裂操作规范**：

以当前 `A_职场商战桥段.md`（≈80+条，含 A01-A04 四个子类）为例：

```text
分裂前：                        分裂后：
01_情节桥段池/                  01_情节桥段池/
├── A_职场商战桥段.md   →       ├── A_价格博弈与竞标/
│                               │   ├── _index.md        # 本目录索引
│                               │   ├── 01_沉默战术.md
│                               │   └── ...
│                               ├── B_会议对决与职场博弈/
│                               │   ├── _index.md
│                               │   └── ...
│                               └── C_行业声誉与危机管理/
│                                   ├── _index.md
│                                   └── ...
```

**分裂硬规则**：
1. **保留入口文件**：原文件保留为入口，内容替换为本目录的文件列表索引（`_index.md` 格式），各子文件条目的编号前缀保持不变
2. **`_index.md` 格式**：

```markdown
# [池名]

> **原文件**：`原文件名.md`（已分裂为子目录，YYYY-MM-DD）
> **总条目**：[N] 条

| 子文件 | 内容 | 条目数 |
|--------|------|--------|
| 01_沉默战术.md | 价格博弈与竞标对决 | 20+ |
| 02_会议对决.md | 会议博弈与职场对决 | 15+ |
| ... | ... | ... |
```

3. **全局编号不变**：子文件内的条目编号（如 `A01-07`）继承原文件体系，不重新编号
4. **子目录名称**：用原二级标题的缩写，最多 8 个中文字符
5. **分裂后更新总索引**：在 `00_素材库总索引.md` 的"文件结构变更记录"表中登记分裂操作

### 可搜索——情绪锚索引

> **问题**：素材散在多个池的多个文件中，写某一章时需要"一个爽的打脸场面"——但不知道它在哪个池、哪个文件里。

**方案**：在 `00_素材库总索引.md` 末尾维护一张**跨池的情绪锚索引表**。

**情绪锚索引表格式**：

```markdown
## 情绪锚索引

| 情绪锚 | 条目示例（池/编号/标题） | 池 | 数量 |
|--------|-------------------------|----|------|
| 爽     | 01A｜A01-01 用对手漏洞反制 | 情节桥段池-职场商战 | 30+ |
| 爽     | 02｜F01 签字离婚           | 名场面高光池 | 20+ |
| 心理战 | 01A｜A01-03 沉默战术       | 情节桥段池-职场商战 | 15+ |
| 悬疑   | 04｜D01-01 旧书里的合同    | 轻悬疑反转池 | 50+ |
| 毒舌   | 05｜E01-01 女主→男主       | 冷幽默毒舌池 | 100+ |
| ...    | ...                       | ... | ... |
```

**构建与维护规则**：
1. **初始构建**：在每次大规模补充后，由助手扫描各池文件的 `**情绪锚**：` 字段，汇总去重后写入此表
2. **索引条目的条件**：情绪锚出现频次 ≥ 3 次的才入索引（低频锚不值得维护）
3. **维护时机**：每次补充落盘 + 总索引更新时，同时更新此表
4. **配合 grep 搜索**：写作时，在 VS Code 中按 `Ctrl+Shift+F`，用情绪锚关键词搜索即可跨池定位：

```text
# 示例：搜索所有"心理战"标签的素材
Ctrl+Shift+F → grep: "情绪锚.*心理战" → 路径: 素材库/
```

5. **路径级精准搜索**：如果需要限定池：

```text
# 只在悬疑池中搜"证据"
grep: "证据形态" → 路径: 素材库/04_轻悬疑反转池/
```

6. **索引不做实时同步**：素材条目持续增加，索引在每次补充操作时批量更新即可，不需要每次新增一条就同步一次

### 条目录入格式规范

所有素材池中的条目必须遵循以下字段结构。**缺字段的条目不得入库**。

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| **标题** | 是 | 精炼概括本条素材的名称 | "用对手的漏洞反制对手" |
| **字数** | 是 | 该素材展开成文的预计字数范围 | "3000-5000字" |
| **情绪锚** | 是 | 核心情绪标签（爽/虐/燃/悬疑/催泪/暗爽/心理战等） | "专业碾压" |
| **梗概** | 是 | 1-3段话描述情节/场景/冲突的完整轮廓 | "招标会上，对手用苏棠上一家客户的数据来攻击她…" |
| **设计逻辑** | 推荐 | 该素材为什么有效，核心设计意图 | "沉默是最有力的谈判武器——让对方先沉不住气" |
| **适配故事面** | 推荐 | 该素材对应哪个故事面/M0/X线 | "X01 事业线" |

名场面高光池的条目**额外强制**包含 **金句** 字段——"读者想截图发朋友圈"的核心台词或旁白。

### 补充前必须做缺件诊断

在任何补充动作之前，必须先读取 `00_素材库总索引.md`，检查缺件方向：

1. **素材密度对标**：对比各池当前条目数与总索引中声明的"各卷素材密度目标"，找出低于目标密度的池
2. **覆盖方向缺口**：总索引中"本轮大规模搜索覆盖"表记录了已覆盖的方向，未覆盖的方向即为搜索缺口
3. **搜索日志检查**：读取 `搜索日志/` 下的搜索记录，确认某方向是否已做过搜索、搜索质量如何
4. **空池检查**：检查各池文件是否为空或条目不足（如当前 `03_人物设定池/` 为空）

得到缺件清单后，再规划补充顺序和搜索策略。

### 网络搜索范式

补充素材时，搜索策略按素材池类型区分：

| 池类型 | 推荐搜索方向 | 关键词组合 |
|--------|-------------|-----------|

- 每次搜索需记录到 `搜索日志/`（格式见后）
- 每条搜索结果必须清洗成标准素材格式后才能入库

### 总索引必须同步更新

每次补充素材落盘后，必须更新 `00_素材库总索引.md`：

- 更新对应素材池的"素材条目"计数
- 在"本轮搜索覆盖"表中追加本次补充的搜索方向和产出条目数
- 更新"更新日期"为当天

### 搜索日志必须同步记录

每次执行网络搜索后，必须在 `搜索日志/` 下的对应文件中追加搜索记录行，格式如下：

```text
| [序号] | [搜索关键词] | [搜索工具] | [有效结果数] | [备注] |
```

若搜索量大，可在 `搜索日志/` 下新建 `03_搜索素材汇总.md` 等增量文件，但需在总索引中声明。

### 条目录入质量门禁

每条素材在落盘前必须通过以下自检：

- [ ] 字段完整（至少标题+字数+情绪锚+梗概填充）
- [ ] 梗概有画面感：不是一个抽象概念，而是读者能直接想象的场景
- [ ] 情绪锚明确：读者知道读了这段是什么情绪预期
- [ ] 有区分度：不是"不说也知道"的套路描述，而是有具体细节/反转/金句
- [ ] 不与同池已有条目雷同（检查同池文件）
- [ ] 情绪锚/字数估算合理（字数估算偏差不超过 30%）

## 各池类型差异

### 01_情节桥段池（A/B/C）

- 每条必须包含清晰的情绪锚——读者预期读完这段的情绪
- 梗概必须包含具体人物、场景、对手、冲突、转折
- 设计逻辑可选但推荐——解释该桥段为什么有效

### 02_名场面高光池（F）

- 额外强制字段：**金句**
- 名场面必须达到"读者想截图发朋友圈"的传播级效果
- 优先收集"打脸反杀""催泪情感""反转震撼"三类

### 03_人物设定池

- 当前为空池，初次填充使用以下子类别结构：

```text
03_人物设定池/
├── A_霸总人设.md
├── B_女主设定.md
├── C_反派模板.md
├── D_配角原型.md
└── E_人物关系动态模板.md
```

- 人物条目的格式（区别于情节条目）：

| 字段 | 说明 |
|------|------|
| **人设标签** | 核心记忆点（如"极度信奉道教戒律的道士"） |
| **底层欲望** | 驱动这个人物的核心需求 |
| **核心矛盾** | 他/她与外部世界或自身的核心冲突 |
| **反差细节** | 让人物立体的反差行为 |
| **声口特征** | 标志性说话方式、用词习惯 |
| **适配故事面** | 可服务于哪些故事面/X线 |

### 04_轻悬疑反转池（D）

- 每条必须包含清晰的"发现→推导→揭晓"逻辑链
- 细节必须包含具体证据形态（实物/文件/照片/录音/行为异常等）
- 反转不能依赖"巧合"，必须有合理前置铺垫

### 05_冷幽默毒舌池（E）

- 每条必须适配目标人物的身份关系场景（怼男主/怼白月光/怼恶配角等）
- 金句标准：聪明不刻薄、犀利不伤人、一本正经地荒诞
- 优先收集"可三连击"的对话组——不是孤立一句话，而是有来有回的对话组合

### 竞品拆解

> 竞品拆解目录存放的是面向整部作品的分析底稿，**不是**可直接取用的素材条目。
> 竞品拆解中提取出的可复用桥段、手法、金句，应清洗后归入对应的01-05素材池。
> 若需直接制作素材条目，使用"通用-分析竞对作品"Skill。

- 条目采用"原文段落+拆解分析"的双段结构
- 拆解分析必须包括：作者用了什么手法、这段为什么抓人、可以借鉴什么
- 并非全文照搬，而是精选"可复用的技巧片段"
