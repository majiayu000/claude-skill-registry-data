# 合作谈判

完成一份可执行的关系图、谈判方案、边界与退出机制。PT只是工作流入口，不是本Skill的专属问题。

## 工作流程

1. 用 `references/problem-catalog.yaml` 明确本次合作必须作出的决定和候选PT。
2. 列出关键相关方，区分其真实利益、资源、实际行为、影响力和转向条件。
3. 在 `references/normalized-solutions.yaml` 中按 `problem_refs` 读取NSL，比较共同目标、交换条件、风险、权利和失效边界。
4. 区分共同利益、可协商差异和不可接受边界；信息不足时每轮只问一个会改变谈判方案的问题。
5. 设计提案顺序、交换条件、权限安排、验证里程碑、重谈信号和退出机制。
6. 从已选NSL进入 `references/source-solutions.yaml`，再用 `references/source-index.jsonl` 核对2～4条原典依据。

## 交付契约

默认给出：

1. **主要判断**：是否以及以什么条件合作，并说明匹配PT。
2. **相关方关系图**：利益、资源、行为证据、顾虑和转向条件。
3. **谈判方案**：目标、筹码、提案顺序、可交换项和验证步骤。
4. **边界与退出**：核心权利、不可接受条件、依赖控制、重谈与退出触发器。
5. **下一检查点**：何时检查对方是否兑现，带回什么证据。
6. **证伪条件与原典依据**：什么事实推翻合作判断，以及原文与现实判断的关系。

## 继续与交接

- 当前任务尚未完成时继续同一谈判交付物，不讨论下一站。
- 已发出提案但结果尚未出现时等待现实反馈，停止追加推演。
- 用户带回回应时，先判断合作假设被支持、削弱还是推翻，再调整条件或结束。
- 若任务变成整体战略重评，保留相关方事实、PT和谈判结果并交回 `$mao-strategy`；主入口未安装时明确本Skill边界。不要直接指定另一个专业Skill。
- 达成协议、决定退出或无需继续时明确结束。

不得把合作方法用于操纵、欺骗、胁迫或违法规避，不把普通意见分歧升级为敌我关系。只提出知情、自愿、可退出的合法方案。
