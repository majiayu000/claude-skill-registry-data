# 通用-生成章节控制卡
> **题材路由**：若 .github\题材专用Skills\ 目录存在对应的 <题材>-生成章节控制卡 Skill，则：
> - 将题材特性骨架路由到 <题材>-生成章节控制卡，该 Skill 位于 .github\题材专用Skills\ 目录。
> - 命中本技能时，必须优先强制加载当前 Skill 与 <题材>-生成章节控制卡。


控制卡不是摘要，而是施工命令。它要回答“这一章怎么写”，而不是“这一章大概写什么”。

## 缓存优化说明

本 Skill 的结构遵循前缀缓存优化原则。控制卡是写前施工的高频调用任务（每章一次），调用时：

- **缓存层（永久不变）**：frontmatter + 核心任务清单 + 中段回报/章末钩子的判定标准 + 就绪判定规则 → 每次调用完全相同，按底价计费
- **项目层（同项目内不变）**：references 清单 + 题材竞对分析接入要求 + 风格/蓝本模板自动发现规则 → 仅在切换项目或新增模板注册时变化
- **可变层（每次变化，不写入本文件）**：本次目标章号、上游卷纲/章纲内容、本章特殊约束 → 由用户每次调用时指定
- 人物传记、故事设定、卷纲等上游文件通过 references 声明强制加载，其固定部分随本 Skill 一起进入缓存前缀

## 卖点保真要求（强制）

- 每张控制卡都必须说明：本章对主卖点的关系是强化、兑现、转化、保温还是暂时铺垫。
- 若本章不是卖点显性回报章，也必须写清它怎样避免卖点断供，以及下一次卖点回报将在何处接棒。
- 若控制卡无法说明“这一章读者为什么还会继续记得本书卖点”，说明本章准备仍不合格。
### 仿写场景下的引擎保真施工（新增 — 当存在作品蓝本模板时强制）

当 `Agents.md` 中注册了"作品蓝本模板"且当前项目为仿写场景时，生成控制卡前必须：

1. 读取蓝本模板的 **§十七 仿写内核卡** 中的"核心爽感引擎"和"金手指-主线绑定模式"
2. 确认本章对核心爽感引擎的关系——是以下哪一类：
   - **显性兑现**：本章让读者直接感受到引擎的快感（如爽文的反击/打脸章、悬疑的线索揭示章）
   - **隐性蓄力**：本章为下一次显性兑现做准备（如信息收集、资源积累、关系铺垫）
   - **引擎升级**：本章扩展了引擎的能力边界（如金手指升级、规则边界突破）
   - **引擎转向**：本章把引擎引向新的问题链方向（如问题漂移的转折点）
3. 若连续 3 章没有显性兑现核心爽感引擎，视为**引擎失温**——即使结构上没犯错，读者也会开始感觉"这本好像没有当初看蓝本时那种感觉了"
4. 在控制卡中显式写出：**本章对核心爽感引擎的贡献类型**
5. 同时检查**本章的情节密度是否匹配蓝本的同位置预期**：
   - 若蓝本在第 10 章左右的节奏特征是"事件密集、快速推进"，本章的控制卡不能安排成"缓慢过渡、氛围为主"
   - 若需要放慢节奏（如核心角色死亡后的哀悼章），应在控制卡中**显式标注放慢的理由**，否则按节奏失配处理
6. **因果倒置与结构重组选项（读取蓝本§十七 仿写内核卡后判断）**：
   - 若蓝本内核卡标注了"因果倒置适用方向"，则判断本章是否适合使用因果倒置——即把蓝本同位置章节中"因为 A 所以 B"的逻辑翻转为"因为 B 所以 A"
   - 若使用因果倒置，控制卡必须写清：原因果链是什么、倒置新逻辑是什么、引擎是否仍能运转
   - 若蓝本内核卡标注了"适用结构重组技法"，则判断本章是否对应某个技法（如"线索合并""模块化设计"等），若适用则写进控制卡施工要求

### 控制卡密度门槛（新增）

控制卡要足够"密"——下游写手拿到后能直接开工，不需要自己补剧情或推断"这一章到底要发生什么"。密度门禁标准：

1. 每个场景单元必须有明确的入场状态、冲突对象、目标与退场状态
2. 中段回报与章末钩子必须写明具体类型与触发条件，而非泛写"有回报"
3. 若控制卡读完仍需要写手自行补充中间过程，判定为密度不足
4. **情节密度三档标注（仿写场景强制）**：当本章参照蓝本的同位置章节时，在控制卡顶部标注本章的情节密度档位：
   - **高密度（事件压缩）**：本章要把蓝本中 X 章的内容压进 1 章——控制卡必须写清哪些事件被合并、如何合并
   - **中密度（节奏对齐）**：本章的节奏密度与蓝本基本一致
   - **低密度（细节扩展）**：本章把蓝本中的某个关键瞬间扩展为独立章——控制卡必须写清扩展的内容是什么、为什么值得扩展

### 留存快手与情绪刺激布点（新增——与留存模型联动）

控制卡新增两个强制性字段，确保写前施工阶段就面向读者留存：

**1. 留存快手字段（控制卡顶部必填）**
在控制卡顶部新增一行：`留存快手：{一句话写清本章唯一的"读者续读驱动力"}`。

这行回答的是：**读者看完本章后，凭什么还想看下一章**？不是一个章节摘要（"本章主角去调查案件"），而是一个续读驱动力陈述（"读者看完后迫切想知道：这个证人到底隐瞒了什么"）。

留存快手的设计原则：
- 必须是一个读者读完本章后**心里留下的未解缺口**
- 不能等于章末钩子——它是"全章读完后的心理状态"，钩子是"章末的具体操作"
- 如果写不出留存快手，说明本章的续读驱动力还没设计清楚，先回上游补设计再开写

**2. 情绪刺激布点（控制卡正文新增）**
在控制卡的四拍（钩子/蓄力/回报/留钩）分配中，新增"情绪刺激点标记"：

```text
0-300字: 钩子(冲突起手 → 情绪刺激类型: 冲突/异常)
300-1500字: 蓄力+升压( → 情绪刺激标记: 信息推进 × 2)
1500-2500字: 回报释放( → 情绪刺激类型: 爽点/反转/关系推进)
2500-3000字: 留钩( → 钩子类型: 悬念式/反转式/情绪炸弹式/信息投放式)
```

每章至少标注 2 个情绪刺激点（1 个中段回报 + 1 个章末钩子），并确认这两个刺激点的类型不重复。

**3. 不确定性设计字段（新增——与范式转换联动）**
在控制卡中新增一行：`本章留给读者的最大不确定性：{一句话写出本章结束时读者心里最想问的问题}`。

不确定性是追读驱动的真正引擎——读者翻页不是因为"知道了答案"，而是因为"不确定自己猜得对不对"。这个字段回答：**读者读完本章后，心里最放不下的那个"到底会怎样"的疑问是什么？**

不确定性设计原则：
- 好的不确定性不是"故意不说清楚"，而是"让读者有空间推断但不确定推断是否正确"
- 不确定性 + 确定性 = 1。如果本章把一切都说清楚了（确定性=1），读者就没有翻页动力了。留白 = 读者的参与空间
- 如果写不出这个字段——或者写出来的问题读者自己就能回答——说明本章的不确定性设计不足，先补设计再开写

示例对比：
| 写法 | 确定性 | 读者反应 |
| --- | ------ | ------- |
| "主角找到证据，决定明天去报案。" | 高——读者知道下一步 | "哦，明天看。"（可能忘） |
| "主角找到证据。但证据上多了一个不该出现的指纹。" | 低——读者不确定这意味着什么 | "谁的指纹？这意味着什么？"（必须追） |

**4. 写前逻辑链四问（新增——吸收自知乎执光赴君·资深网文作者24本签约经验）**

在生成控制卡的场景拆解之前，**必须先想清楚并记录以下四个问题的答案**。任何一个问题答不上来，都意味着本章的逻辑骨架还没搭好，不要先拆场景：

```text
① 主角核心想要什么？（本章的主角目标）
② 为什么想要？（动机——这个目标对主角意味着什么）
③ 他打算怎么拿到？（行动方案——主角在本章会采取什么行动）
④ 过程中会被谁阻碍、遇到什么困难？（冲突来源——对手或障碍是什么）
```

这四问是每一章写前的逻辑底线。控制卡中必须显式写清这四问的答案，否则下游写手开工时缺少全局判断依据，容易写出"空有场景堆砌但主角不知道自己在干嘛"的章节。

### 章纲描述字数基线（新增——吸收自知乎 NOVEL-OVE 框架）

> **来源**：知乎·杞鋂《【第5招】NOVEL框架写百万字小说之OVE三框架：根据百万字小说大纲生成百万字章节细纲》（2026-05-05），付费专栏。

控制卡中的"核心事件描述"部分（章纲层）应有字数基线意识，避免控制卡本身因信息过载或不足而失去施工指导价值：

- **参考基线**：每张控制卡的核心事件描述部分（即章纲内容，不含模板固定字段）推荐 200-350 字。
- **超限处理**：若核心事件描述超过 350 字，说明本章试图塞入过多事件——应拆分到多章，或压缩次级事件。
- **不足处理**：若核心事件描述低于 200 字，说明本章内容可能不足以支撑一个完整章节——应补入次级事件、细节扩展或关系推进，使其达到章节应有的内容密度。
- **偏离规则**：高潮章、过渡章、多线交汇章等特殊类型章可适当偏离基线，但偏离时必须显式标注原因（如"高潮章，事件密度高，允许 400 字"）。

### 逐单元确认策略（新增——吸收自知乎 NOVEL-OVE 框架）

生成控制卡时，推荐采用**逐单元确认**的工作策略，而非一次全量生成所有章的控制卡：

1. 将上游分配的内容按事件单元（每卷 5-7 个）分组。
2. 每次只为一个单元生成该单元各章的控制卡。
3. 当前单元控制卡生成后，执行密度门禁检查（见"控制卡密度门槛"）和留存快手确认。
4. 确认通过后再进入下一个单元。
5. 逐单元策略的好处：① 降低单次认知负载，防止超上下文窗口溢出。② 每单元可独立调整节奏，不影响其他单元的设计。③ 便于发现单元间的钩子类型重复或回报时机同质化。

若用户明确要求一次性全量生成，先在日志中记录 `risk_continuous_generation` 警示，再执行。

**5. 因果闭环强制标注（新增——配合写前逻辑链四问）**

控制卡中的每个场景单元，除了标注入场/冲突/退场状态外，还必须标注该场景的"因果链"：

```text
场景1: 原因（前章/前场景的什么状态触发了本场景）→ 效果（本场景结束后改变了什么——主角状态/关系/信息/局势变化）
```

因果闭环标注原则：
- 每个场景必须有"原因"和"效果"两项，缺一不可
- 效果不能写成笼统描述（如"主角了解了情况"），必须写具体变化（如"主角确认了嫌疑人X的作案时间线存在漏洞"）
- 如果某个场景写不出"效果"，说明该场景在本章中没有存在的必要——删掉或合并

因果闭环与不确定性字段、留存快手字段的关系：因果闭环回答"事件逻辑"，不确定性回答"读者心理"，留存快手回答"续读驱动"——三者互补但各有侧重，不可互相替代。

**6. 起承转合结构完整性检查（新增——吸收自知乎南梦）**

> **来源**：知乎·南梦《一篇文章说清楚小说写作基本功：起承转合》（2026-03-02，26 赞同）。

控制卡交付前，必须验证本章的起承转合四段结构是否完整。起承转合是任何叙事单元（单章/场景单元/卷级弧线）的最小完整骨架——缺少任何一段，结构即不成立。

**四段检查清单**：

| 阶段 | 检查项 | 判定标准 | 不通过的后果 |
| --- | --- | --- | --- |
| **起** | 本章是否有明确的主角目标？是否有对应的阻碍？ | 目标 + 阻碍二者缺一不可；阻碍必须对目标构成实质性难度 | 读者不知道"这一章要解决什么问题"——开篇即失焦 |
| **承** | 主角是否为打破阻碍采取了实际行动？行动是否产生了结果？ | 行动 + 结果二者缺一；结果可以是正面/负面/中性，但不能是"无结果" | 读者感觉"主角在摸鱼"——中段塌陷 |
| **转** | 是否有意料之外的事件或信息介入？转折是否产生了新的悬念？ | 意外 + 转折二者缺一；转折必须让读者产生"接下来会怎样"的追问 | 读者感觉"剧情太好猜"——翻页动力断供 |
| **合** | 本章是否有一个明确的终点（不是事件自然停止而是有意义的闭合）？是否为下一章留了引子？ | 结局 + 新篇二者缺一；新篇引子不能是模糊的"后面还有故事"，必须是具体的悬念/未解问题/新出现的威胁 | 读者感觉"这章看完可以停了"——续读断供 |

**控制卡施工规则**：
- 控制卡的四拍（钩子/蓄力/回报/留钩）设计应与起承转合四段对齐——"起"对应钩子，"承"对应蓄力，"转"对应回报前的蓄力顶点或回报本身，"合"对应留钩
- 如果控制卡中某个场景单元的起承转合四段不完整（如只有"起→承"而没有"转→合"），说明该场景在本章中未完成闭环——要么在本章内补全，要么在本章控制卡中标注"跨章场景（转+合延至第X章）"
- 如果连续 2 章控制卡均缺少"转"段（无意外/无转折），标记为"结构重复→读者预测性过高风险"
- **套娃检查**：检查本章的场景单元是否出现三层以上嵌套——如果是，需要在控制卡中标注"套娃深度>3，存在主线迷失风险"，建议合并或剪裁分支

## 内容边界与决策边界：控制卡的信息分层管理（新增——吸收自知乎 zzZZ）

> **来源**：知乎·zzZZ《小说写作有什么是AI永远取代不了的？》（2026-07-11），关于 AI 辅助长篇创作中"上下文污染"与四道边界的系统性分析。

控制卡作为上游资料和正文施工之间的中间件，天然需要做信息分层管理——不是把所有上游资料原样堆进控制卡，而是在控制卡层面完成一次**信息提纯与边界标记**。

### 内容边界：控制卡使用的三类资料

生成控制卡时，接触的上游信息应显式分为三类：

| 类别 | 定义 | 在控制卡中的处理方式 |
|------|------|-------------------|
| **已确定·当前有效** | 经过确认、正在使用的事实性内容（人物当前状态、已发生事件、已揭示设定） | 作为"当前施工依据"写入控制卡的场景描述和人物状态段 |
| **候选·未定方案** | 正在讨论、尚未采用的选项（替代方案、不同走向的设计） | 不在主控制卡中体现；如需标注，在控制卡备注区显式写"候选/待确认" |
| **已过时·历史记录** | 曾经有效但已被替代的旧版本 | 不放入当前控制卡，仅在有追溯需要时另做历史参考文件 |

**实操规则**：
- 上游提供的章纲/卷纲可能包含多个版本或修改痕迹。生成控制卡前，先确认当前使用哪个版本作为依据。
- 如果上游资料中存在"旧设定尚未清理"的嫌疑（如旧版人物关系还留在设定文档中），在控制卡中只写当前有效版本，并在控制卡头部做一行版本声明：`依据版本：{文件名/日期}`。
- 控制卡本身也不应积累废弃内容——修改控制卡时，旧版本直接覆盖而非追加"补丁说明"。

### 决策边界：控制卡输出内容的状态管理

控制卡生成的各类输出，需要明确标注决策状态，避免 AI 在后续创作中把"候选"误当成"已确定"：

```text
已确认 → 控制卡主文本中写入，下游可将其作为定稿依据
待验证 → 控制卡中用【待验证】标注（如 "主角在这一章完成首次金手指触发【待验证】"）
候选方案 → 控制卡备注区列出，不在主文本中体现
```

**实操规则**：
- 控制卡中的核心事件链和人物行为应全部标记为"已确认"状态——这是下游写手开工的依据。
- 如果设计到一半感觉"这里可能有更好的方案"，不要在控制卡中用模糊描述（"主角可能去东市也可能去西市"）——而是选定一个主要方案作为已确认，把其他方案写在备注区作为备用选项。
- 控制卡交付后，若下游写手在正文创作中发现了更好的走向，正文落地后先更新控制卡的决策状态（候选→已确认），再据此调整后续章节的控制卡。

参见 `通用-创建小说正文` 的 `## AI 上下文管理原则：避免上下文污染` 中更完整的四道边界框架。

## 题材竞对分析接入要求（强制）

- 若当前任务服务某个题材，且该题材目录下的 `竞对分析/` 已存在与当前项目、当前平台或当前赛道相关的竞对分析报告，生成控制卡前必须先读取并纳入本章施工判断。
- 若已配置主输出平台，且当前题材目录下尚无可用竞对主报告，生成控制卡前应优先调用 `通用-分析竞对作品` 补齐最小结论集；若任务限制导致本轮无法补齐，必须显眼记录盲区，并降低本章开写就绪判定。竞对分析的目标平台由主输出平台配置决定。
- 不得把这些报告只当成背景资料；控制卡必须显式说明本章准备在哪些维度追平、反超竞对，以及哪些旧坑必须避开。
- 控制卡的默认目标不是“能开写就行”，而是让当前作品在关键维度上**全方位超越竞争对手**；若看不出明确超越路径，应继续补施工而不是草率开写。
### 爽点施工四原则——压抑释放、分层布点、变奏轮换、预期管理（新增——吸收自知乎桐梦书涵"爽点设计公式"）

> **来源**：知乎·桐梦书涵《爽点设计公式：让读者通宵追更的5个方法》（2026-06-20），数据引用：阅文集团《2025网文读者行为白皮书》、起点中文网2025年度月票榜。

以下四个原则是生成控制卡时判断本章爽点设计是否合格的核心检查框架。控制卡交付前，必须逐项确认四原则全部覆盖。

#### 原则一：压抑-释放循环——"低谷"比"高峰"更重要

**核心公式**：压 → 反压 → 爽

| 阶段 | 叙事操作 | 控制卡标注要求 | 常见错误 |
| --- | --- | --- | --- |
| **压** | 给主角设置合理的困境——不是随便找个反派来打脸，而是让读者觉得"这确实很难解决" | 标注本章的压抑源是什么（外部压力/内部矛盾/信息不对等/关系危机） | 困境太轻飘——读者觉得"这有什么难的" |
| **反压** | 让主角的应对遇到意外挫折——主角在努力但遇到了阻碍，激发读者的保护欲和代入感 | 标注反压的具体形式（计划失败/新信息打乱/盟友背叛/时间不够） | 反压缺失——主角一路顺利，没有"意外" |
| **爽** | 释放要精准——不是单纯地打脸，而是让读者觉得"这个反转合理，且超出预期" | 标注释放的具体形式（碾压/智取/关系翻面/真相揭露）及力度等级（小爽/中爽/大爽） | 释放过于轻易——没有成本的成功不叫爽 |

**心理学基础**：对比效应（Contrast Effect）——人们对一个刺激的感知，会受到之前刺激的影响。没有前面的压抑，就没有后面的释放。最爽的场景是"主角从绝境中逆转"。

**控制卡密度要求**：每个场景单元都必须自问——本场制造了什么"不爽"，又摘走了什么"不爽"？如果答案只有"推进了剧情"而没有情绪起伏，说明场景设计不完整。

**数据参照**：追读率排名前 10% 的作品，平均每 1.8 章出现一次情绪高峰；排名后 10% 的作品，这个数字是 4.7 章（阅文 2025 白皮书）。

#### 原则二：三级爽点分层——不是"一直爽"，而是"有节奏地爽"

**行为经济学基础**：边际递减效应——当一个人连续获得同类刺激时，每一次刺激带来的满足感会递减。

| 爽点层级 | 频率 | 定义 | 控制卡标注要求 | 示例 |
| --- | --- | --- | --- | --- |
| **小爽点** | 每章 ≥1 个 | 解决一个小问题、获得一个小收获、打破一个小僵局 | 在控制卡场景拆解中标注至少 1 个小爽点位 | 唐三使用暗器的瞬间、小舞展现身法 |
| **中爽点** | 每 3–5 章 1 个 | 打败一个重要对手、获得关键情报、突破一个瓶颈 | 在控制卡中显式标注中爽点位置及类型 | 关键战斗胜利、重要线索揭示 |
| **大爽点** | 每卷 1 个 | 改变整个故事走向的转折点、核心秘密揭露、主角命运重大转变 | 在卷级启动表中标注大爽点位置及蓄力章节分配 | 卷末决战、核心身份揭露 |

**数据参照**：起点 2025 月票榜前十作品，中爽点平均间隔 3.2 章，大爽点平均间隔 28 章。

**控制卡施工规则**：
- 生成控制卡时，先确认本章在当前卷的爽点层级位置——是日常小爽章、中爽积蓄章、中爽兑现章还是大爽蓄力/兑现章
- 连续超过 5 章没有中爽点 → 爽点断供风险，必须在控制卡中补充中爽点位
- 连续 3 章每章都有中爽点 → 爽点过密风险，读者审美钝化
- 大爽点之前至少预留 3 章的蓄力空间（压→反压→蓄力→爆发）

#### 原则三：爽点变奏——同样的"胜利"，不同的写法

**心理学基础**：感觉适应（Sensory Adaptation）——同类型爽点的重复会导致读者免疫。连续写 10 章主角打脸升级，读者反而会弃书。

三个变奏方向（控制卡中至少选其一做显式标注）：

| 变奏方向 | 操作方式 | 控制卡标注示例 |
| --- | --- | --- |
| **情绪类型变奏** | 同样是"胜利"，轮换使用：轻松碾压的爽 / 绝境逆袭的爽 / 布局完成的爽 / 意外收获的爽 | `本章爽点情绪类型：绝境逆袭型` |
| **对手类型变奏** | 不要总是打脸同一种反派：嚣张纨绔 → 老谋深算 → 体制性压迫 → 亲密关系中的对抗 | `本章对手类型：老谋深算型（与上一章的嚣张纨绔型形成变奏）` |
| **获得类型变奏** | 不只是"打脸"才算爽：获得新技能 / 揭露真相 / 赢得盟友 / 打破误解 / 保护重要的人 | `本章爽点获得类型：揭露真相（与上一章的武力碾压形成变奏）` |

**变奏施工规则**：
- 连续 2 章不得使用同一种情绪类型的爽点
- 连续 2 章不得打脸同一种类型的对手（除非是同一对手的多阶段对抗——此时应在控制卡中标注"多阶段对抗，非重复变奏"）
- 每 5 章内至少覆盖 2 种不同的获得类型
- 如果连续 3 章都是"打脸嚣张配角"模式 → 变奏失效，读者会出现"怎么又是这种剧情"的吐槽

#### 原则四：读者预期管理——先给半满足，再给超预期

**行为经济学基础**：多巴胺奖励机制——多巴胺的分泌不仅在获得奖励时，更在"期待奖励"时。而且，"不确定的奖励"比"确定的奖励"更能刺激多巴胺分泌。

**核心策略**：半满足 → 超预期

| 阶段 | 操作 | 控制卡标注要求 |
| --- | --- | --- |
| **半满足** | 满足读者一部分期待，但不完全满足。如读者期待主角突破境界——让主角获得突破的契机，但设置一个延迟（"需要三天时间炼化"） | 标注本章的"半满足"内容：读者期待什么 → 本章满足了哪部分 → 延后了哪部分 |
| **超预期** | 在满足期待的基础上，给额外惊喜。如主角不仅突破了，还意外获得了一个特殊能力；或突破过程中意外发现了一个秘密 | 标注本章的"超预期"内容：超出读者预期的额外收获是什么 |

**控制卡施工规则**：
- 如果本章明确告诉读者"主角下一章一定会突破"——读者的期待感会降低（确定性太高→多巴胺不分泌）
- 如果本章让读者觉得"主角可能会突破，但也可能遇到意外"——读者的期待感会更强（不确定性→多巴胺分泌）
- 读者最失望的剧情模式（知乎 2025 投票第一）："期待已久的场景，结果就这？"——勾起了期待就必须给足满足，甚至超额满足
- 控制卡中标注"半满足+超预期"时，必须写清：读者期待什么 → 本章半满足了什么 → 超预期的额外收获是什么

## 平台竞对吸收口径

当已配置主输出平台时，默认把竞对吸收拆成以下四层，并翻译成写前施工约束。具体平台术语与指标由主输出平台对应的 `通用-输出*版` Skill 提供：

- **内容创作层**：重点吸收主样本在章首切入、动作链、信息差、人物抓手、规则边界、回报位与钩子位上的做法，把它翻成控制卡里的唯一职责、四拍分配、场景职责与风险提示。
- **运营策略层**：重点吸收主样本的追读工程、讨论点设计、更新节奏匹配、关键章功能位与评论触发设计，把它翻成中段回报与章末留钩施工要求。
- **受众反馈层**：重点吸收平台读者高频被夸的值点、被骂的拖点、读者不耐烦的病灶，提前写进本章控制卡的避坑和加码清单。

## 三公理施工检查（新增——吸收自知乎桐梦书涵）

生成控制卡时，用三条底层公理检查本章的施工设计是否成立（详见 `CommonSkills/通用-强化章节开头/references/黄金三章底层三公理.md`）：

| 公理 | 控制卡施工检查项 | 不达标信号 |
|------|----------------|-----------|
| 注意力公理 | 本章是否包含至少一个「未完成事件 + 可立即共情」的入口？ | 本章入口是交代/铺垫而非钩子 |
| 预期差公理 | 本章的中段回报/爽点是否建立在「先钉读者预期→再打碎」上？ | 反转没有先建立预期，读者觉得"莫名其妙" |
| 情绪投资公理 | 本章是否完成了对某人物/关系的情绪「存款」或「取款」？ | 本章无任何情绪账户变动 |

**预期差公式落地**：`爽感 = 结果 − 预期`。控制卡的"中段回报"字段必须写清两件事：① 读者在进入本章前预期是什么（明示或暗示）；② 本章交付的结果如何偏离这个预期。只写"结果"不写"预期"的回报设计，是无效回报。

**情绪投资落地**：控制卡的"情绪刺激布点"中，标注每个刺激点是「存款」（增加读者对人物/关系的投入）还是「取款」（兑现此前的情绪投资）。虐文/正剧/群像允许长期大额投资；快节奏爽文必须"小额高频"——避免读者等太久失去耐心。

## 何时使用

- 在正式写章节前，需要把卷纲 / 章纲压缩成可执行的本章控制卡。
- 中段容易塌，需要先明确本章任务、回报、冷线回归和钩子。
- 用户希望先看章名候选、POV、节奏档位、场景单元，再决定是否动笔。

## 控制卡输出路径规约（强制）

> **背景**：控制卡是写前施工命令，不是正文的一部分。执行闭环时经常被误放入 `小说正文/` 目录，导致控制卡与正文文件混排。

### 默认输出目录

- 控制卡文件默认写入 `写作控制卡/` 目录，而非 `小说正文/` 或其他产出目录。
- 目录结构：`写作控制卡/第X部/第Y卷/控制卡_第X.Y.Z章_<YYYY-MM-DD>.md`
- 若无法推导部 / 卷：`写作控制卡/未分类/控制卡_第X.Y.Z章_<YYYY-MM-DD>.md`

### 路径推导规则

编写或调用 `create_file` 落盘控制卡前，必须按以下优先级确定路径：

1. 若用户显式指定了输出路径 → 使用用户指定路径
2. 若从上下文可推导 `第X部` / `第Y卷` → `写作控制卡/第X部/第Y卷/控制卡_第X.Y.Z章_<YYYY-MM-DD>.md`
3. 只有章号无部卷 → `写作控制卡/未分类/控制卡_第X.Y.Z章_<YYYY-MM-DD>.md`

### 路径合规门禁

控制卡文件路径必须以 `写作控制卡/` 开头。**任何情况下不得将控制卡写入 `小说正文/`、`审阅意见/`、`阅读笔记/`、`书评/` 或其他非控制卡目录。**

若检测到控制卡的目标路径不以 `写作控制卡/` 开头，必须：

1. **阻断**写入动作
2. 重新推导正确路径
3. 记录路径修正原因到日志

### 题材包装层的控制卡路径路由

题材级的控制卡生成包装 Skill（如 `都市悬疑-生成章节控制卡`）在路由到本 Skill 时，必须：

- 检查题材项目根目录下是否存在 `写作控制卡/` 目录
- 若不存在，**主动创建**后再写入，不得回退到 `小说正文/`
- 若题材规则指定了不同的控制卡目录结构（如 `都市悬疑/写作控制卡/`），以题材规则为准

## 本 Skill 的核心任务

每张控制卡至少要写清：

1. 本章**必须改变什么**。
2. 哪条线要推进，哪条线要回归。
3. 本章中段的**明确回报**是什么。
4. 本章的主要场景单元和压力变化。
5. 本章风险：最容易写崩的点是什么。
6. 章末留给下一章的钩子类型与对象。
7. 本章怎样让主卖点继续被看见或被记住。

## 最小核心与问题引擎校验（新增——吸收自知乎精华）

- 开卡前必须先写一句"最小核心"：`谁在什么处境下，为了什么目标，正被什么阻力压迫`。
- 若该章属于第一章或卷首章，控制卡必须显式写出"问题引擎"：读者看完本章后心里要留下的具体追问是什么。
- **问题引擎的优先类型——人际关系反常**（来自陈野亮理论）：最有效的问题引擎不是"这件事的结果是什么"，而是"这两个人之间到底是什么关系？为什么他们会这样？"——让读者对人际关系的真相产生追问，比让读者对事件结果产生追问更具黏性。
- 若控制卡只有信息点、设定点、背景点，没有可被读者追问的问题，视为未达开写条件。
- “问题引擎”必须与本章动作链绑定，不能只写抽象悬念词（如“真相如何”）而没有现场触发物。

## 章节四拍与首屏控制（新增——吸收自知乎精华）

- 控制卡默认要写清本章的四拍分配：**钩子、蓄力、爆发 / 回报、留钩**，至少说明哪一拍最重、哪一拍绝不能缺位。
- 若本章承担卷首、卷中转折或关键续读职责，控制卡里必须显式写出前 `300` 字准备让读者看到什么人物抓手、眼前麻烦或反常信号。
- **首屏抓力优先使用"人际关系反常"**（陈野亮式）：让读者第一眼看到的不只是"有事发生"，而是一段反常的人际关系正在展开。宁可让读者先看到"妻子的手机上出现了一条不该出现的消息"，也不要先写"她今天工作很忙"。
- **"交易本质"自检**：控制卡写完首屏部分后，问——"读者读完前 300 字如果关掉，ta 得到了什么？"如果答案是"背景交代"或"气氛铺垫"，说明首屏没有完成交易。- **"切片开头"指令（新增——包罗万象式）**：控制卡中首屏部分不得写成"大纲式概括"（如"主角被公司开除，心情低落"），必须写成"切片式瞬间"——指定一个最高压、最反常、最戏剧化的具体画面作为开篇锚点。若控制卡的首屏描述是概括性的而非场景性的，视为未达开写条件。
- **"三句法"写前检查（新增——包罗万象式）**：控制卡写完首屏指令后，检查：开篇三句话是否各自承担了"疑问/情绪/代入"中的至少一项？如果有任何一句只是"信息说明"而非"勾引读者"，标记为这条控制卡的风险点，在写正文前须先解决。
- **桥段新鲜度检查（新增——吸收自知乎《最近弃了七本书》教训）**：控制卡生成后，先对比最近 5-10 章的核心桥段指纹，确认本章的推进方式没有与近期章节高度雷同。若本章桥段与 3 章内的某章属于同一指纹类型，必须在控制卡中标注"桥段等同风险"并至少在触发条件、人物反应、或预期结果中做一项变异处理。不得连续 3 章使用同一桥段指纹。
- 中段回报不能只写"推进了主线"；必须写成读者可感知的具体收益：关系推进、误判修正、局面反击、信息开口、身份抬升或代价落地。
- 若本章主要是保温章，也必须写明如何维持卖点可见度，避免连续多章只有流程推进没有值回票价的变化。

## 三章节奏循环：跨章微型弧线设计（新增）

> **来源**：自知乎精华《如何写好一个优质的长篇小说？》（摘星，2026-06-17）。
>
> **社区验证**：七猫作家交流区精华帖（收藏642）中"期待感与爽点"板块（14篇）是该帖最大板块，验证了节奏控制是创作社区的核心焦虑点。本 Skill 的章节四拍设计、三章节奏循环、爽点预告链正是该社区最关注的能力——本 Skill 应作为高频维护对象。

单章控制卡的黄金公式解决的是"一章之内怎么安排"，但读者追读是一章接一章的。连续3章的安排决定了读者是否会一口气读下去，还是读到某章中间就放下。**三章节奏循环**是介于"单章控制卡"和"卷级节奏"之间的中间层设计工具。

### 三章节奏循环的默认模式

连续3章（或按实际字数等比缩放）应遵循以下节奏循环：

| 章序 | 功能 | 核心任务 | 章末钩子类型建议 |
| --- | --- | --- | --- |
| **第1章：铺垫/蓄力** | 释放新信息/设定新悬念/建立新预期或蓄积情绪 | 铺垫本章循环的核心冲突所需的信息或条件 | 偏"悬念式"或"信息投放式"——让读者想知道更多 |
| **第2章：冲突/推进** | 让铺垫的信息转化为实际的冲突/压力/对抗 | 给出实质性的冲突事件——对话碰撞、势力博弈、关系摩擦或能力对抗 | 偏"反转式"或"情绪炸弹式"——在章末给出冲击 |
| **第3章：小高潮/回报** | 兑现前两章蓄积的情绪,让读者感到"这3章读值了" | 完成一个小回报——打脸/反转/揭示/关系突破/技能升级/信息落地 | 偏"悬念式"——给出回报的同时打开新的追问 |

### 三章节奏循环的应用规则

- 三章节奏循环是"默认模式"而非"铁律"——一卷内约60%-70%的3章组应按此模式运行，剩余的3章组可以根据剧情需要做变体（如连续两组铺垫→一组双倍回报）。
- **三章节奏循环不是强制的章节边界**——不要求每3章机械切换循环。自然的分组可以打破章节边界（4章完成一轮、2.5章完成一轮等），但原则上不应出现连续6章以上没有"小高潮+回报"章的情况。
- 生成单章控制卡时，应检查本章在前3章组中的定位（第1/2/3章位），并据此调整本章的回报规模和章末钩子强度：
  - 处于"第1章位"的控制卡：中段回报可以偏小（信息推进/关系细节），章末钩子需要足够强以驱动读者进入第2章
  - 处于"第2章位"的控制卡：冲突强度需明显大于第1章位，章末钩子应制造"不能停"的紧迫感
  - 处于"第3章位"的控制卡（小高潮章）：中段回报需达到"值回这3章票价"的强度，章末钩子打开下一个3章循环的问题
- 若连续2个以上的3章循环都以同一种情绪类型结尾（如连续2轮都是"打脸爽"结尾），判为情绪类型重复疲劳——需在下一轮的第3章位切换回报类型（从"打脸爽"切换到"信息揭示"或"关系突破"）。

### 与情绪刺激密度设计的关系

本循环与 `references/爽点递进与300_1000_3000节奏锚点.md` 中的情绪刺激密度设计协同工作，而非互相替代：

- **三章节奏循环**是"章节组"级别的节奏设计工具，回答"连续3章作为一个最小单元，如何分配功能"
- **情绪刺激密度设计**是"卷级"的情绪点布局工具，回答"全卷范围内情绪刺激如何分布"
- 两者结合：每一组三章循环的中应至少包含1个中刺激点（完整的打脸流程/关系突破/关键信息揭示），分布在循环的第2-3章
### 四节奏实用控制技巧（新增——吸收自知乎精华"网文节奏与爽点把控"）

> **来源**：知乎"网文节奏怎么把控？爽点怎么安排才能让人通宵追更？"（桐梦书涵，2026-06-06）。

以下四种节奏控制技术作为控制卡生成的可选工具箱，在遇到节奏设计困难时按需调用：

**技巧一：情绪曲线法——卷级节奏预设计（适用于先规划后开写的卷首章）**
- 在生成控制卡前，若本章是卷首章或卷中关键转折章，先画一条本卷的"情绪曲线概览"：横轴是章节号，纵轴是"读者看完这章后的情绪强度"。
- 标准曲线模板（约30-50章一卷）：
  - 开头（第1-2章）：中等（建立背景，让读者了解情况）
  - 第3-5章：下降（给主角制造困境）
  - 第6-10章：持续下降（困境加深，读者开始焦虑）
  - 第11-12章：突然上升（主角尝试反杀但失败）
  - 第13-15章：持续上升（主角找到突破口）
  - 第16-20章：最高点（主角成功反击，情绪爆发）
  - 第21-25章：逐渐下降（收尾+为下一卷埋钩子）
- 控制卡中标注：**本章在图中的位置**（处于曲线的"困境加深段"还是"爬升段"），据此调整中段回报和章末钩子的强度。处于"下降段"的控制卡应确保钩子足够强以维持追读，处于"上升段"的控制卡应聚焦回报兑现。

**技巧二：假胜利——制造反差爽感（适用于卷中转折章或连续推进后的反转章）**
- "假胜利"指在读者以为剧情顺利时，设置一个"看似胜利但实际没赢"的情节。主角前几场赢得艰难→第三轮却输了——但"输"不是真输，而是在过程中发现了对手弱点/获得了更好机缘/得到了大能赏识。
- 控制卡中若使用此技巧，必须标注：
  - **读者当前预期**：读者以为主角会顺利取胜/圆满解决
  - **假胜利的具体设计**：主角表面上失败了/没有得到想要的结果
  - **实际获得的反差收益**：读者跟着主角"失望"之后获得的"双倍补偿"（比直接胜利更大的机会/信息/资源）
- 适用风险提示：假胜利不能"为反转而反转"，必须有逻辑上成立的后续收益。连续使用假胜利会让读者产生"又是套路"的免疫力，建议每卷最多使用1-2次。

**技巧三：信息释放节奏设计（适用于所有章节——控制卡必修字段）**
- 很多控制卡的问题在于：信息释放速度要么太快（开局全盘托出世界观），要么太慢（读者失去探索欲）。
- 控制卡的场景单元描述中，必须标注每个场景的**信息释放状态**：
  - **设谜**：抛出读者不知道但想知道的信息缺口
  - **部分揭示**：给出部分信息，同时制造新的疑问
  - **完全揭示**：解决一个旧疑问，但指向更大的谜团
- 默认原则：把信息释放速度压到读者"想知道"但"还不知道"的状态。读者不是在等待爽点，而是在追逐信息的路上不知不觉读完全书。
- **信息差驱动力检查**：如果控制卡中所有信息都是"读者已经知道的"或"作者直接告诉读者的"，没有制造"读者比角色知道更多/更少"的信息差状态，判为信息释放设计不足。

**技巧四：时间压迫感——高潮段加速（适用于卷末高潮章或关键决战章）**
- 当剧情进入高潮阶段时，通过设置"倒计时"来制造紧迫感。
- 控制卡中如果有倒计时设计，必须标注：
  - **倒计时窗口**：明确的时间限制（"法阵将在三天后完全激活""敌人离城只剩十里了""灵药必须在子时之前服下"）
  - **章节时间推进**：每一章往前推进多少时间，读者会被紧迫感裹挟着往下读
  - **截止后果**：倒计时截止时具体会发生什么——这个后果必须足够严重，否则倒计时无效
- 使用规则：倒计时只适用于高潮段卷（全卷最后的3-5章），不宜在卷中段使用。如果在卷中段使用倒计时，必须同时准备倒计时结束后继续展开剧情的设计（如"倒计时被延期""倒计时提前触发但后果与预期不同"等变体）。

**技巧五：松紧循环——节奏呼吸感设计（新增——吸收自知乎"写作技巧——如何把控小说节奏？"）**
- **核心原则**：一段紧张冲突后，控制卡必须规划至少一段舒缓情节作为读者呼吸空间。"紧张→舒缓→紧张→舒缓"构成章节级的"心跳节奏"。
- **控制卡必填字段——松紧对位表**：
  ```markdown
  | 段落序号 | 节奏属性（紧/松） | 场景内容 | 估算字数 |
  |---|---|---|---|
  | 1–2段 | 紧（冲突/高潮） | 主角与对手对峙 | ~400字 |
  | 3段 | 松（缓冲） | 主角退到角落喘息、检查伤势 | ~200字 |
  | 4–6段 | 紧（冲突升级） | 对手逼近，主角被迫做出抉择 | ~600字 |
  | 7段 | 松（沉淀+过渡） | 安静下来的时刻，新线索浮现 | ~150字 |
  ```
- **验收标准**：写完松紧对位表后检查——连续几段"紧"之后是否预留了"松"的槽位？若连续 3 段以上标注为"紧"而无任何"松"段，标记"节奏疲劳风险"并必须在其中一个紧段内嵌入一个短呼吸句（哪怕是主角一个深呼吸、一个停顿、一句内心冷笑话），否则控制卡不能放行。
- **与已有字段的关系**：松紧循环的"紧段"对应本 Skill 已有"情绪刺激布点"的冲突/高潮标记，"松段"对应中段回报或信息释放段落。松紧对位表是对情绪刺激布点的段落级细化，确保布点之间有合理的呼吸间隔。
- **场景单元内的松紧自检**：每个场景单元内部也要画出微型松紧曲线——一个纯"紧"到底的场景会失去层次感，一个纯"松"到底的场景会让读者失去耐心。场景单元内的松紧交替是"好读"的底线门槛。

**技巧六：大高潮阶梯法——把高潮拆成三到五个阶段（新增——吸收自知乎顾里木图的小酒馆）**

> **来源**：知乎·顾里木图的小酒馆《网文小白开始写小说，有哪些快速掌握的写作技巧？》（2026-07-01）。

**核心问题**：很多控制卡只写了"本章是高爆发章"或"本章是高潮章"，但没有进一步设计**高潮的内部阶梯**。结果写正文时，所有情绪一次性释放完——读者爽完就没东西了。

**阶梯法规则**：每一次高潮事件（卷级或章级的核心爆发），在控制卡中拆成 3–5 个阶梯阶段：

| 阶梯 | 阶段名称 | 控制卡标注内容 | 读者情绪 |
|---|---|---|---|
| 第 1 阶 | **紧张建立** | 第一层冲突信号出现，但尚未正面碰撞 | "要来了吗？" |
| 第 2 阶 | **升级** | 冲突正式爆发，双方第一次正面交锋 | "紧张！" |
| 第 3 阶 | **对峙** | 势均力敌的拉扯——信息差/底牌/代价逐渐浮出水面 | "谁会赢？" |
| 第 4 阶 | **爆发/转折** | 决定性一刻——主角亮底牌/关键信息释放/关系翻面 | "值了！" |
| 第 5 阶 | **余震/后续** | 爆发后的连带后果、情绪余波、或新问题浮现 | "然后呢？" |

**控制卡中的标注格式**：
```markdown
**本章高潮阶梯设计**：
- 第 1 阶（~500 字）：主角收到威胁信——紧张建立
- 第 2 阶（~600 字）：正面冲突——反派当面施压，主角被迫应对
- 第 3 阶（~800 字）：对峙拉扯——双方底牌试探，矛盾升级
- 第 4 阶（~600 字）：爆发——主角亮出关键证据，反派溃败
- 第 5 阶（~300 字）：余震——反派的最后一句话暗示更大的暗流
```

**执行规则**：
1. 阶梯不少于 3 阶，不多于 5 阶。小于 3 阶 = 没有蓄力过程，读者情绪爬升不足。大于 5 阶 = 蓄力过长，读者在等待中疲劳。
2. 第 3 阶（对峙）是最容易写垮的——控制卡必须标注"本章对峙阶段的信息差/底牌/代价是什么"。如果没有可标注的信息差内容，说明对峙阶段设计不足。
3. 第 5 阶（余震）不是可选项——高潮爆发后余震阶段负责开启下一个问题引擎。没有余震的高潮会在读者心里迅速冷却。
4. 如果本章的高潮不跨章（爆发和余震在同一章内完成），第 4–5 阶合并为一阶（作为章末钩子位置）。

**与本 Skill 既有规则的关系**：
- 阶梯的第 3–4 阶通常对应"情绪刺激布点"中的回报/爆发标记，第 5 阶对应章末钩子。
- 阶梯法的各阶段字数估算应与"三章节奏循环"中对应章位的字数分配一致。
- 如果本章属于"兑现章"（爽点预告链定位），阶梯的第 4 阶（爆发）必须达到"兑现质量门禁"标准——高于读者在预告阶段积累的预期。
## 前三章人物展示控制卡序列：身份→处境→性格→能力→欲望（新增——吸收自知乎网文老刀·五维立人设体系）

> **市场诊断**：大量新人写十几万字无法签约，剧情通顺无大毒点，但读者反馈"主角形象平淡，看完记不住"。根源是前三章没有完成人物展示的系统设计。
> 
> 来源：网文老刀17年实战（知乎想法，2026-06-15）

当控制卡服务于前三章（或新卷的首三章）时，不能只按三章节奏循环的通用模式分配"铺垫→冲突→小高潮"，还必须为前三章的**人物展示**单独做系统性规划。以下五维展示法为前三章控制卡专项要求，与三章节奏循环并行执行。

### 前三章五维展示分配

| 章序 | 控制卡必须标注的人物展示维度 | 对读者的心理动作 | 控制卡中的施工指令示例 |
| --- | --- | --- | --- |
| **第1章** | 身份 + 核心困境 | 好奇——"主角是谁？在遭遇什么麻烦？" | "出场使用xx环境物件/下意识动作流露身份；困境在身份落地时同步给出" |
| **第2章** | 性格 + 能力（释放初级爽点） | 认可——"这个人物不弱，有底牌" | "设计一个选择或行动暴露性格；安排一个事件结果证明能力（具体/稀缺/反差）" |
| **第3章** | 欲望 + 长远目标 | 期待——"想看主角能否圆梦" | "暴露主角内心的具体执念（非空泛口号）；明确长期目标，制造读者追读预期" |

### 控制卡中的五维一致性检查

前三章控制卡生成完毕后，必须追加一道五维一致性检查：

1. **逐章提取**：第1章控制卡标注的身份原型 + 处境类型、第2章标注的性格标签 + 能力定位、第3章标注的欲望方向
2. **列成一张五维配置表**：身份 / 处境 / 性格 / 能力 / 欲望
3. **冲突检测**：检查是否存在互相矛盾的维度组合（如"冷血杀手身份 + 圣母心性 + 佛系欲望"）。只要有一项不一致，标记为"人设崩塌风险"并返回修改
4. **一致性通过标准**：五个维度能够自然收敛到同一个人物内核——用一句话能说清"这是一个怎样的人"

### 与本 Skill 既有规则的协同

- 五维展示法与本 Skill 的"三章节奏循环"互补：节奏循环回答"这三章的情绪功能怎么分配"，五维展示回答"这三章的人物形象怎么建立"，两者在三章控制卡中必须同时存在。
- 五维中的"困境"（处境维度）与本 Skill 的"最小核心"（谁在什么处境下、为了什么、正被什么压迫）直接对应——控制卡的"最小核心"字段应优先由处境维度和欲望维度导出。
- 五维一致性检查应在本 Skill 原有的"留存快手→不确定性→情绪布点"字段之后、控制卡最终放行之前执行，作为一道独立门禁。与读者期待管理（新增——吸收自知乎丁文韬与流浪的蛤蟆）

> **核心原则**：控制卡不只是回答"这一章写什么"，更要回答"这一章怎样让读者相信下一章会爽"。

### 本章在爽点预告链中的定位

生成控制卡时，必须首先判定本章在全书爽点预告链中的位置，并在控制卡顶部显式标注：

| 定位 | 定义 | 本章核心任务 | 风险提示 |
| --- | --- | --- | --- |
| **预告章** | 本章不兑现大爽点，而是制造"下一章会爽"的读者预期 | 给出一个足够具体的爽点预告信号（临界状态/即将到来的冲突/倒计时/一波未平一波又起） | 预告必须足够强，不能让读者觉得"又被耍了" |
| **蓄力章** | 本章处于两次爽点兑现之间，为本卷/跨卷的大回报做铺垫 | 提供小回报维持读感（信息推进/关系变化/小反击），同时为下一次大爆点积累势能 | 蓄力不能超过2-3章，否则读者耐心会耗尽 |
| **兑现章** | 本章是爽点预告链的终点——读者等待的回报终于出现 | 让读者感到"这章值了"：打脸/反转/揭示/升级/关系突破 | 兑现质量必须高于读者预期，不能"就这？" |
| **过渡章** | 本章承接上一章的余波，为下一阶段的爽点预告链做铺垫 | 至少给一个小回报或新预告，不让读者白读；明确标注"过渡不白过"的具体内容 | 连续过渡章是最危险的节奏毒药 |

**标注格式**：
```markdown
**爽点预告定位**：[预告章/蓄力章/兑现章/过渡章]
**已连续预告/蓄力**：X 章（若超过3章未兑现，标记⚠️）
**本次预告的兑现窗口**：第 X 章前后
**本轮预告链的"终极爽点"**：一句话说明读者最终在等什么
```

### 读者期待管理：预告-延迟-兑现的节奏设计

控制卡中的"中段回报"和"章末钩子"必须与爽点预告链联动设计：

**1. 预告章的章末钩子设计**
- 预告章的本质不是"让读者想知道"，而是**"让读者相信下一章会爽"**
- 章末钩子必须包含具体的爽点预期信号——不只是一个问题（"接下来会怎样？"），而是一个明确的回报预期（"主角的反杀马上就要开始了"）
- 示例对比：
  - ❌ 弱预告："陈勉关上门，外面有人在等他。"（太模糊，不够具体）
  - ✅ 强预告："陈勉推开门，外面站着的正是他要找的王主任——而王主任手里拿着那一天的转账记录。"（具体、冲突可感、读者知道下一章有事发生）

**2. 蓄力章的中段回报底线**
- 蓄力不是"什么好事都不发生"，而是**小回报不断+大回报蓄力**
- 控制卡必须标注本章的"最小回报"：即使本章是蓄力章，读者读完至少拿到了什么？（新信息？关系小推进？认知升级？）
- 若控制卡写不出蓄力章的最小回报，说明这一章读者没有读下去的理由

**3. 兑现章的兑现质量门禁**
- 兑现章的中段回报必须高于读者在预告阶段积累的预期
- "高于预期"的判断标准：读者读完回报段后，不是"哦，果然是这样"，而是"卧槽，比我想的还狠"
- 兑现章控制卡必须写清"超出读者预期的那个具体增量是什么"

**4. 过渡章的过渡不白过检查**
- 过渡章控制卡必须在显眼位置标注"过渡不白过"的具体内容
- 至少满足以下一项：新信息冒头（不只是前情回顾）、关系有微妙位移（不只是原地踏步）、为下一段预告链埋下第一颗种子

### "预告链条长度"的自我诊断

控制卡生成后，运行以下诊断：

1. **当前预告链已持续几章了？**
   - 1-2章：正常，继续预告
   - 3章：开始有风险，控制卡中检查预告信号是否足够强
   - 4章以上：⚠️ 高风险！必须在下一章或下下一章安排兑现，否则读者流失

2. **当前预告链的"最终爽点"是什么？**
   - 如果控制卡写不出"读者最终在等什么"——说明预告链本身是虚的，读者可能在等一件连作者都没想好的事
   - 必须回炉到卷纲层面，确认本轮预告链的终点是什么

3. **如果本章是兑现章：兑现力度够吗？**
   - 同场景比较：用同样字数，同样冲突类型的其他章节的爽感浓度
   - 如果低于最近2-3章同类场景的浓度，视为兑现不足

4. **如果本章是预告章：预告信号够具体吗？**
   - 读者读完本章后，能不能说出一句具体的话描述"下一章会发生什么"？
   - 如果不能（比如只是"有大事要发生"这种空洞预告），预告信号太弱，需要加码

### 控制卡中的爽点预告链标注规则

每个场景单元中，必须标注该场景对爽点预告链的贡献：

```markdown
### 场景单元 1：[场景名称]
- **对爽点预告链的贡献**：强化预告（让读者更确信"下一章会爽"）
```

```markdown
### 场景单元 2：[场景名称]
- **对爽点预告链的贡献**：部分兑现（本章不是完整的兑现章，但在这个场景给出了一次小回报）
```

**门禁**：如果所有场景的贡献都是"推进剧情"或"信息交代"，没有场景承担"预告/兑现/蓄力"职责，则判为控制卡密度不足——这一章的正文读者没有理由读完。

## 人物执行要求（新增——强制）

> 核心问题：控制卡规划了本章"发生什么"，但如果没有同步规划"人物怎样被看见"，正文写出来就容易变成情节流水账、人物面目模糊。

生成控制卡时，必须从出场人物的传记中提取"正文可调用素材清单"（见 `通用-设计人物传记/references/正文可调用素材清单.md`），并写入控制卡的场景单元中。每一章至少完成以下三项中的两项：

### 人物执行三必查

1. **每个人物在本章至少要有一个"只有他会这样做"的瞬间**
   - 来源：传记中的决策启发式、压力反应微镜头
   - 落位：控制卡场景单元的 beat 描述中必须显式标注"人物动作来自 XX 心智模型/启发式"
   - 反例：人物在本章只是"出现、说话、推动信息"，但没有做出任何体现其独特认知规则的选择

2. **每段高冲突对话必须至少有一个人物展现了声口特征**
   - 来源：传记中的声口即时贴、表达DNA
   - 落位：控制卡的场景单元"对话链"中必须标注"人物 X 的声口特征：短句/断言/不问只判"
   - 反例：遮住名字后，对话双方说的话可以互换——这说明声口未分化

3. **若本章场景与某个人物的诚实边界/误判预设场景匹配，必须触发至少一次**
   - 来源：传记中的诚实边界、误判预设场景
   - 落位：控制卡的"中段回报"或"章末钩子"中标注"本章触发了人物 X 的 XX 盲区/误判"
   - 反例：人物传记写了"他看不懂纯情感驱动的行为"，但本章他面对朋友哭诉时应对自如

### 人物执行要求的记录格式

控制卡中每个场景单元的人物参与字段，默认按以下格式补齐：

```markdown
### 场景单元 N：人物执行要求

**出场人物与本章行为锚点**：
- [人物A]：本章要体现的心智模型 → [具体哪个模型]；来自传记压力反应微镜头 → [哪个微镜头]；本章标志性动作/判断 → [一句话]
- [人物B]：本章要体现的决策启发式 → [具体哪条]；来自传记声口即时贴 → [哪句/哪种情境]；本章标志性台词 → [一句话]
```

### 传记素材缺失时的降级处理

- 若出场人物传记缺少正文可调用素材清单，控制卡必须标注"人物 XX：传记缺正文可调用素材，本章人物执行靠写手即兴发挥"
- 若核心人物连续 3 章控制卡都出现此标注，必须在控制卡风险提示中记录"人物空心化风险：传记未提供可执行素材，人物可能逐渐失去辨识度"
- 此标注同时作为信号，提示应回补传记的正文可调用素材清单

## 多方案预生成与路径选择（新增——吸收自知乎专栏"卡文、套路化、细节空洞？我是这样用AI解决小说创作三大顽疾的"）

> **核心理念**：不让AI直接"写方案"，而是先让AI"生成选项"，你再从"鉴别和雕刻"中做出更好的决策。这不是"AI给你一个答案"，而是"AI给你一堆宝石毛坯，你来决定切哪一颗、怎么切"。

### 为什么需要这一步

控制卡的传统工作流是：上游输入 → AI生成一份控制卡 → 用户确认。但关键决策点如果只有单路径输出，你天然失去了"比较"的视角。当控制卡只有一份时，你无法判断"这真的是最好的切入点吗"。多方案预生成就是在钉死之前，先打开视野。

### 适用决策点

以下类型的决策点，默认执行多方案预生成，再从中选择/融合：

- **章首切入方式**：同一章的开头，至少生成 2–3 种不同切入点（如：异常物件切入 vs 关系反常切入 vs 倒计时压力切入）
- **情节走向分支**：当本章面临"主角往左走还是往右走"的关键选择，至少生成 2 条方向路径，分别描述利弊
- **中段回报类型**：同一段剧情，至少生成 2 种不同类型的回报方案（如：信息回报 vs 爽感回报 vs 关系回报）
- **章末钩子类型**：至少生成 2 种钩子类型（如：新危机 vs 揭露 vs 未完成动作），并评估哪种对下一章的驱动力更强
- **爽点/爆点落位**：当本章需要安排爆点但位置不确定时，生成 2–3 种不同密度/位置的方案

### 操作格式

控制卡的关键决策点处，按以下格式输出：

```markdown
## 决策点：章首切入方式

### 方案 A：[方案简述]
- 具体做法：[1–2句话说明]
- 优势：[本条路径最值钱的地方]
- 风险：[最容易崩的地方]
- 对本章节奏的影响：[加速/蓄力/突转]

### 方案 B：[方案简述]
- 具体做法：[1–2句话说明]
- 优势：[本条路径最值钱的地方]
- 风险：[最容易崩的地方]
- 对本章节奏的影响：[加速/蓄力/突转]

### 方案 C（可选）：[融合/折中方案]
- 如何结合A和B的优势：[说明融合方式]
- 适用条件：[何时值得选这个方案]

> **选择后**：将选定的方案写进下面的控制卡主体内容中，不再保留方案列表。
```

### 使用原则

- **不要每个决策点都做多方案**——只对真正影响本章走向的关键决策点执行多方案预生成。纯执行性决策（如过渡场景的先后顺序）不值得多方案消耗上下文。
- **每个方案必须有可区分的利弊**——如果两个方案除了表述不同之外实质上没区别，说明这个决策点不值得多方案，选一个直接推进。
- **优先展示差异化**——三个相似的方案不如两个真正对立的方案有价值。如果只能生成高度相似的变体，说明这里不需要多方案决策。
- **多方案是手段，不是目的**——选完后立即合并为单一控制卡继续推进，不要在控制卡正文里保留"未选方案"的残留。

### 用户角色升级

当启用多方案预生成时，用户的角色从"接受方案"升级为"做出判断"：读完2–3个方向后，用户需要明确回答哪个方向最符合本章的唯一职责和卖点保真要求。这个"判断动作"本身就让用户对本章的理解更深一层——而不是被动接收一份AI生成的控制卡然后直接开工。

### 数据预演倒推法（新增）

> **来源**：知乎《稿费从1000到50000，写好大纲决定你稿费的上限》（顾里木图的小酒馆，2026-06-15）。

在生成控制卡前，可尝试一种逆向规划方法——先设定一个明确的阅读数据目标，再倒推本章的施工要求：

1. **设定目标**：如"第30章时完读率达到20%""前3章追读率>35%"等。
2. **倒推要求**：要达到这个数据，前N章需要有几个高潮、几个悬念、几个反转？把这些倒推出的关键节点标在大纲和对应章节的控制卡顶部。
3. **对标施工**：当前章的施工控制卡需要在"本章对数据目标的贡献是什么"一栏中明确回答——"这一章必须出什么效果才能让读者持续读到第30章"。

**适用场景**：
- 用于有明确数据意识或首发平台的章节创作场景。
- 在尚无明确数据的纯创作阶段不做硬性要求，但"倒推进度思维"本身仍有助于让每章更有方向感。
- 若已配置主输出平台且该平台有明确的推荐/首秀机制（番茄/起点/七猫等），建议启用此方法。

## 唯一职责、beat、情感弧与就绪判定补强（新增）

- 每张控制卡都必须单列“**本章唯一职责**”与“**不应包含**”：唯一职责需要能用一句话说清本章让读者完成什么认知 / 情绪 / 追问；不应包含则负责声明哪些线、不该在哪些位置抢跑的解释与结论不在本章处理。
- 每个场景默认补齐：`POV`、场景目标、情感转变、参与角色、情感基调、冲突 / 张力来源、信息流、与下一场景的关系、过渡方式、建议字数。
- 每个场景默认拆 `1–4` 个 beat，并标 `承重 / 灵活`；承重 beat 负责本章叙事承重，默认不得删除或无故换序，灵活 beat 可合并、弱化或换实现方式。
- 情感弧必须写清读者情感入口、读者情感出口与弧线模式；若入口出口几乎无变化，本章大概率会读感发平。
- 控制卡尾部默认补一张“钩子链验证”：上章出口钩、本章入口响应、本章出口钩、下章预期响应；上章钩子断裂且无解释，默认降级处理。
- 就绪判定默认分 `Green / Yellow / Red`：`Green`=职责、beat、情感弧、钩子链、节奏权重、字数分配都齐；`Yellow`=缺 `1–2` 个非核心项但 writer 可谨慎推进；`Red`=唯一职责说不清、承重 beat 漏失、钩子链断裂、连续重章无调整方案等，需先回炉。

## 执行顺序

0. 若按起点口径执行且当前题材目录下缺少可用竞对主报告，先调用 `通用-分析竞对作品`，补齐 `Top10 候选池 → 3–5 本主样本 → 四层深拆` 的最小结论集。
1. 读取上游卷纲 / 章纲 / 单元案 / 相关台账。
1.5. **读取本章出场人物的人物传记**，重点提取"正文可调用素材清单"（压力反应微镜头、声口即时贴、误判预设场景、关系拉扯动作库）；若传记缺少此清单，在控制卡中标注降级。
2. 若按起点口径执行，先吸收竞对主样本四层结论，并写清本章要追平 / 反超的关键项。
3. 先做冷线与债务扫描，再决定本章要承接谁。
4. 先钉死六件事：核心改变、主推进线、回归压力、中段回报、主要风险、章末钩子。
5. 先用“上游供血对齐与回填接口表”钉死本章承接哪个故事面、位于本卷哪一段、属于显性回报章还是保温章。
6. 若本章结构位置发虚，先用“九部件预埋与进度节奏微表”确认本章所在段落与 3–5 个节拍。
7. 按模板输出控制卡：身份、任务、回报、场景、风险、标题候选、钩子。
8. 若控制卡无法说清中段回报，说明本章仍未准备好。
9. 若本章需要拆成 3–5 个较清晰的动作单元，继续按场景单元拆分法展开。
9.5. **日常场景的配角建设用途检查（新增）**：若本章包含日常场景，在控制卡中标注每段日常场景承担的配角建设职责——"这段日常让读者认识了哪个配角？记住了他什么特征？"；若日常场景不承担任何配角建设职责，标记为"真.日常风险"并建议重写（详见 `通用-执行场景单元/references/日常裂缝启动与中段回报.md` 的"日常裂缝的核心先决条件"部分）。
10. 输出结果优先服务正文创作，而不是取代正文创作本身。

## 默认输出口径

- 默认输出一张可直接服务正文创作的控制卡。
- 默认同时检查卷纲、冷线、回报、章末钩子与章名候选。
- 默认同时输出“唯一职责 / 不应包含 / 情感弧 / beat / 钩子链验证 / 就绪判定 / writer 注意事项”。
- 若用户只要极简控制卡，也至少不能删掉“中段回报”和“章末钩子类型”。
- 若任务是长篇连载，默认同时检查前 300 / 1000 / 3000 字的节奏锚点与爽点递进。

## 最低交付

- 能解释这章为什么非写不可。
- 能一句话说清本章唯一职责，并写清本章不该提前处理什么。
- 能指出本章主推进线。
- 能指出本章中段回报。
- 能指出本章与主卖点的关系。
- 能拆出 3–5 个带压力变化的场景单元。
- 能说清本章风险与钩子类型。

## 本章在全篇节拍地图中的定位（新增）

生成控制卡时，必须先判断本章位于全篇节拍地图的哪个区间，再据此校准本章的节奏权重与爆点强度：

| 章节区间 | 本章所处区间的核心任务 | 对控制卡的约束 |
| --- | --- | --- |
| 1–10 章 | 建立世界观、核心冲突、主角目标 | 每 2–3 章必须有一个小钩子；若本章处于钩子位，章末钩子强度不得低于"新危机"或"新代价"级 |
| 11–30 章 | 第一个大副本，展示成长体系 | 每 5 章必须有一个中等爆点；若本章处于爆点位，中段回报必须是读者可感知的具体收益 |
| 31–50 章 | 关系深化，铺垫中期危机 | 埋伏笔为主，但每章仍需至少一处关系位移或信息推进 |
| 51–70 章 | 中期高潮，世界观第一次扩展 | 每 3 章一个爆点；控制卡必须显式写清本章如何为下一个爆点蓄力 |
| 71–100 章 | 终极冲突铺垫，全员集结 | 每章都有推进；不得出现纯保温无推进的章节 |
| 101–120 章 | 最终决战，解决所有主线 | 爆点密集；控制卡的"不应包含"字段尤其重要——禁止在收官阶段引入未铺垫的新设定 |

### 定位校准规则

- 控制卡必须显式写出"本章位于全篇节拍地图的哪个区间"，以及"本区间的核心任务对本草的具体约束"。
- 若本章的节奏属性（钩子/蓄力/爆发/回报/转承）与所在区间的爆点密度要求明显不匹配（如在"每 3 章一个爆点"的区间连续安排"蓄力"章），必须在风险提示中标注并给出补偿方案。
- 若本章处于两个区间的交界处（如第 10 章与第 11 章之间），控制卡应同时考虑前后区间的约束，优先服从更紧迫的一方。

## 与其他 Skill / Prompt 的边界

- 本 Skill 是正文创作前的上游准备层。
- 本 Skill 不直接完成正文，也不负责终审评分。
- 连续性热度管理应由 `通用-管理连续性冷热线` 继续承接；两者可联动但不互相替代。
