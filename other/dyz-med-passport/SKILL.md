# 医学论文项目状态文件

## 定位

`paper/project-passport.yaml` 是轻量状态索引，不是电子数据采集系统、临床试验主文件、伦理记录或提交系统。
源数据和正式文件仍是权威来源，passport 只保存路径、版本、状态和必要摘要。

## 隐私与最小化

- 只记录工作流真正需要的信息；
- 不保存患者级数据、凭证、完整通讯地址或不必要的个人资料；
- 人工确认可记录角色、日期和来源，除非项目确需，不强制写真实姓名；
- 敏感信息优先记录受控文件路径，而不是复制内容。

## 创建与读取

1. 若项目已有 passport，先读取并保留未知字段。
2. 若不存在，仅在需要共享状态且用户已同意写入位置时按[项目状态模板](templates/project-passport.template.yaml)创建最小文件。单技能可直接使用明确输入，不强制创建 passport、安装兄弟技能或连接数据库。
3. 只从用户确认、现有工件或实际检查报告填值。
4. 不确定值使用 `unknown`、`not_checked`、`needs_confirmation` 或空值；不得合理猜测。

## 建议记录的内容

- 项目标识、稿件标题、研究类型和目标期刊；
- 研究问题、设计、主要结局及其确认状态；
- 当前阶段、稿件版本和关键产出路径；
- 数据、统计、文献、伦理、注册和作者信息的来源状态；
- 已完成检查、报告路径、日期和结论；
- 开放问题、风险、待办和人工决定；
- 投稿前最终批准状态。

每项已确认事实尽量带 `source`、`confirmed_by_role` 和 `confirmed_at`。

## 更新规则

1. 只修改与当前任务有关的字段。
2. 不覆盖冲突事实；保留各来源并将状态改为 `conflicting`。
3. 工件用稳定 `id` 寻址，保留用户实际 `path`，绑定 `version` 与原始字节 `sha256`；有当前版本的相应验证才记录为 `complete`，文件存在不够。
4. 检查逐次记录完整 `inputs`、`scope`、`execution_status`、`applicability`、`domain_result`、`report` 和日期。执行完成、领域结论及当前有效性分开，不能把 `not_run` 写成通过，不能把 `completed` 或校验器退出0当科学PASS。
5. 外部投稿、作者批准和伦理确认只能由明确的人类决定更新。批准绑定目标工件版本/哈希、角色、带时区确认时间及可定位的人类原始来源；单个布尔值或状态字符串不是批准证据。校验器不认证身份、同意、权限或科学正确性。
6. 输入内容/版本变化使依赖它的旧检查与批准失效，无关文件不触发全部失效。字节哈希不能识别排版与科学内容：默认 stale；只有明确内容等价证据且重核定位后，才可另建当前版本检查记录，保留旧记录而非改写旧哈希。
7. 旧1.0或无绑定记录保留为 unverified，未知扩展字段和历史原样保留；未知核心状态明确报错，不能自动升级。问题处理状态与验证关闭分列，回复完成不等于已验证关闭。
8. 写入前后核实来源，仅修改当前任务相关索引，追加历史并验证 YAML/JSON；只读校验不会替用户重写或批准。

## 只读版本核验

字段、路径、兼容规则和退出码见[工件合同](references/artifact-contract.md)。本技能内置[验证脚本](scripts/validate_passport.py)，可独立运行，无兄弟目录导入。JSON只需标准库；YAML缺少既有PyYAML时报告 blocked，不安装。

从实际加载的本技能目录定位脚本；下面的 `<本技能目录>` 须替换为 `SKILL.md` 所在目录的绝对路径。在医生的论文项目根目录运行，输入及 `--root` 指向论文项目，不把项目材料写入技能安装目录。

```powershell
python -B "<本技能目录>/scripts/validate_passport.py" paper/project-passport.yaml --root .
```

`--root` 是所有记录路径的根；省略时为 passport 所在目录，不能自动把 `paper/` 当项目根。输出逐项问题、执行状态、领域结果与 freshness。0仅合同及绑定有效，1合同/文件错误，2参数错误，3存在 stale/unverified，4缺YAML依赖。只核验声明的依赖和文件字节，不发现所有遗漏输入，也不替代科学审查或人类授权。状态读取不会运行分析、写作、修订或投稿。

## 输出

默认更新：

- `paper/project-passport.yaml`

存在关键未确认项时，可另生成：

- `paper/runtime/open-items.md`

不要因为开放项存在就自动阻止其他 Skill；由具体任务根据风险决定是否需要确认。

## 验收标准

- YAML 有效，字段语义稳定；
- 没有患者级数据或不必要个人信息；
- 已确认事实有来源；
- 冲突、未知和未运行状态未被掩盖；
- 工件路径、版本、字节哈希与检查输入集合可核对；过期检查不能证明当前稿件通过；
- 人工确认可定位到绑定版本的来源，机器校验不替代人审；
- 旧记录、扩展字段与历史未被删除或自动升级。
