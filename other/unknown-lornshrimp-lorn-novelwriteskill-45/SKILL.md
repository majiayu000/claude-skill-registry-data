## 何时使用

- 在多平台输出之前，先把一章整理成更干净、更稳定的母稿。
- 当前源稿平台腔太重，不利于后续再改写到其他平台。
- 需要保住事件链、情绪主轴与章末钩子，但去掉只适合单一平台的冗余壳层。
- 你想减少后续多平台改写时的返工，先把不可动的核心钉牢。

## 不适用情形

- 你要直接做平台差异化输出与落盘。
- 你要把母稿写成平台无差别中性稿。
- 你只想单平台终稿精修，而不是做派生前的底稿纯化。

## 常见触发词 / 用户说法速查

- 先把母稿提纯一下
- 这份底稿太像某个平台了
- 多平台前先修源稿
- 帮我把这章变成可派生母稿
- 先把平台壳层去掉但别磨平

## 本 Skill 的核心任务

1. 提炼一份**更适合派生改写**的母稿口径。
2. 保住：
   - 事件链
   - 角色目标 / 阻力 / 代价
   - 关系变化
   - 规则边界与证据关键点
   - 章首抓力、中段回报、章末钩子
3. 去掉或压低：
   - 单一平台过重口癖
   - 重复强调与重复补偿同一信息
   - 过度解释
   - 不利于跨平台迁移的局部腔体与外壳
4. 默认把“这几章 / 前几章 / 前面几章 / 前面这几章 / 后几章 / 后面几章 / 后面这几章 / 上一章 / 下一章 / 本章 / 这章 / 后文会 / 我们会看到”这类章节自指 / 连载导览 / 作者讲评腔视为必须先清掉的作者壳层，否则会被后续平台版本复制放大。
5. “整章 / 这整章 / 这一整章”同样属于必须先清掉的作者壳层；它们看起来像在总结稿件而不是在讲故事，一旦留在母稿里，后续平台改写会继续放大这种出戏感。
6. 默认把“抽象自述 + 动词模板 + 口径名词”句群视为必须先清掉的污染壳层（例如“我这边/我心里…对齐/校准…，说到底/换句话说…口径/日志…，只求…”）；若母稿存在该类句群，禁止进入平台适配阶段。7. **保护爽点预告链（新增——吸收自知乎丁文韬与流浪的蛤蟆）**：提纯母稿时，爽点预告链（预告→蓄力→兑现→再预告更大的爽点）是最容易被"磨平"的对象——因为提纯操作天然倾向于"只保留核心事件信息"，而预告-延迟区间在信息层面上看起来像是"可以压缩的冗余"。这是最大的误区。以下是保护规则：

   a. **每章首先标注爽点预告定位**：在母稿文件的元信息区（文件头部注释或标记行）标注本章是预告章/蓄力章/兑现章/过渡章
   
   b. **预告信号不得压缩**：凡是制造"好事/坏事要来了"的读者预期的段落，字数可精简但预告信号本身不得删除。精简预告段时只砍"修辞冗余"，不砍"制造预期的叙事单元"
   
   c. **蓄力-期待区间不得压缩**：原文中"读者知道要来了但还没来"的延迟区间，是节奏最值钱的地带。提纯时如果只保留事件结果、取消延迟过程，后续所有平台版本都将失去这个节奏区间——且无法在平台改写层重新补回，因为节奏是在母稿层设计的
   
   d. **跨章预告链的衔接信号不得删除**：如果本章末尾为下一章留下了一个具体预告信号（如"那个人下周就会出现"），提纯时不得以此信号"未在本章产生结果"为由压缩它——它是下一章追读的直接驱动
   
   e. **预告-兑现周期的完整标记**：在母稿的章目录信息区，标注当前爽点预告链的状态——"上次兑现：第X章；本次预告指向：第X章前后；已连续预告X章"。这能帮助后续所有平台改写环节知晓当前的读者预期积累到了什么程度
## 研究回灌补强（2026）

- 母稿提纯时必须保住三类锚点：
   1. 开篇抓力锚点（首屏冲突 / 异常 / 风险）；
   2. 人物情绪锚点（可共情的现实痛点与选择压力）；
   3. 章末驱动锚点（下一步必须追读的未决问题）。
- 不得把“提纯”做成“去情绪”：应去平台壳，不去情绪主轴；应去重复解释，不去关键回报。
- 手机端可读性属于母稿质量的一部分：连续大段、说明墙、句群过匀必须先在母稿层拆解，不把负担留给平台改写层。

## 平台差异化黄金三章母稿保留规则（新增——2026 深度研究整合）

母稿提纯时，若已知后续目标平台，必须按以下规则保留或调整开篇结构，避免提纯后不适配目标平台：

| 目标平台 | 母稿开篇必须保留的要素 | 母稿阶段可削弱的要素 | 提纯禁区 |
| --- | --- | --- | --- |
| **起点中文网** | 悬念密度、信息差层次、主角独特能力/金手指的铺垫 | 过度直白的爽点释放 | 不能削掉合理性铺垫和逻辑链条 |
| **番茄小说** | 前 150 字的最强爽点/冲突直接呈现、极快的情绪释放 | 冗长的背景说明、慢节奏悬念铺垫 | 不能削掉情绪钩子的爆发力 |
| **七猫小说** | 通俗易懂的开篇直给、绝境→金手指→反转的快速展开 | 文学性描写、复杂的设定分层 | 不能削掉"给够信息让读者不困惑"的底线 |
| **晋江文学城** | 情绪锚点、关系张力、内心活动密度 | 高密度的打斗/物理冲突 | 不能削掉人物情绪线和关系张力 |
| **知乎盐选** | 第一句话即最强钩子、类第一人称的语言质感 | 第三人称客观叙述的铺垫 | 不能削掉叙事距离的拉近感 |
| **今日头条** | 第一段即冲突、下一段即反转、每 500 字一个钩子 | 过渡性描写、氛围渲染 | 不能削掉短促节奏和强钩子密度 |
| **GoodNovel（英文）** | 前 300 字内完成"抛绝境→立人设→留钩子" | 文化特定指涉（中方特有梗） | 不能削掉跨文化可理解的情绪张力 |

**母稿提纯核心原则**：在不确定最终目标平台时，母稿应优先保留所有平台通用的开篇要素（情绪钩子、人物锚定、认知缺口），而仅将"平台特有的结构偏好"留给后续适配阶段处理。

## 事故复盘回写（2026-05-11）

- 已验证：在 AI 不可用时改走脚本正文改写，会制造模板垃圾句群并污染后续全部平台分支。
- 本 Skill 强制规定：母稿提纯阶段不得使用脚本做正文生成兜底；若 AI 不可用，必须中止并回写 `blocked_ai_unavailable`。


## 执行顺序

1. 先判断目标是：从现有源章提炼母稿，还是在已有底稿基础上继续提纯。
2. 若输入文本当前位于 `小说正文/`，它只作为提纯输入来源；提纯后的母稿应新建或回写到 `提纯母稿/`，不得继续落在 `小说正文/`。
3. 先分清两层内容：
   - 必须钉死的核心层
   - 后续可分化的平台层
4. 先查事实和证据有没有松动。
5. 再查章首、中段、章末三个关键支点是否成立。
6. 再查人物当章压力是否具体、可感。
7. 最后处理不利于派生的单平台壳层与重复句群。
8. 复检：后续改写到其他平台时，是否更容易拉出差异化版本。

## 默认输出口径

- 默认面向平台派生前的母稿提纯，不直接生成多平台终稿。
- 默认对象是准备进入多平台流程的中文母稿。
- 提纯母稿允许且应优先放在 `提纯母稿/` 文件夹中。
- 不允许把提纯母稿放在 `小说正文/` 文件夹中；`小说正文/` 只承载章节正文成品，不承载派生前母稿。
- 默认直接回写或新建 `提纯母稿/` 下的母稿文件。

## 最低交付

一次合格的多平台母稿提纯，至少要做到：

- 明确哪些内容是后续所有平台都不能丢的核心。
- 让章首、中段、章末三处关键支点成立。
- 保证证据 / 规则关键点、时间、关系、目标与代价稳定。
- 保留足够可分化空间，让后续平台适配能各写各的。

## 硬规则

- 不得把母稿提纯理解成“去平台感、去个性、去锋利”。
- 不得为了后续好改而把事件、代价、规则、证据、钩子磨平。
- 不得提前把母稿改成某个平台专属腔，再拿它反向套别的平台。
- 不得混用平台稿回修母稿，母稿必须作为源头处理。
- 不得把提纯母稿存放、回写或新增到 `小说正文/` 文件夹；提纯母稿允许且应优先放在 `提纯母稿/` 文件夹中。
- 不得把章节自指、下一章预告或作者讲评口吻误当成“连载感”；真正的连载感来自未完成动作、关系余波、新变量与具体风险。
- 不得把文本提纯成无味白底稿。
- 不得使用模板句堆叠或随机句群补字数；凡出现“对照项落在”“先把同一句话拆碎”“先把顺滑的解释拆开”“只求能追溯/复核/对得上”等污染短语族，必须先清零。
- 不得使用 `scripts/append_cn_unique_monologue.ps1`、`scripts/append_cn_unique_narration.ps1`、`scripts/append_cn_unique_thirdperson.ps1`、`scripts/rephrase_cn_body.ps1`、`scripts/rephrase_en_body.ps1`、`scripts/cn_lexicon_profile_transform.ps1` 进行母稿正文生成或补字。

## 与其他 Skill / Prompt 的边界

- 本 Skill 处理的是**派生前的底稿纯化**，不是最终平台适配。
- 若用户只想精修单一平台正文，应优先用对应的正文润色类 skill。
- 多平台输出与落盘流程应由平台适配 / 输出 SOP 继续承接。
