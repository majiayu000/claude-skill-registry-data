# Video → Superprompt — 레퍼런스 영상 해부기

레퍼런스 영상(웹사이트 스크린 레코딩·광고 클립·인터랙션 캡처)을 **원본 없이도 재현
가능한 수준**의 단일 프롬프트로 변환한다. 출처 = MengTo/Skills `codex/video-to-superprompt`
(MIT) — 절차는 계승, 산출 규약만 이 레포 기틀에 맞춰 배선했다.

**이 스킬은 작업 도구다(제품 코드 아님).** 결과물은 프롬프트·문서이지 `viewer/` 산출이
아니다. 영상 자체를 새로 만드는 일은 storyboard-v1/v2·seedance 쪽이 담당한다.

## 0. 착수 게이트

- 영상에 **실제로 접근할 수 있어야 한다**(로컬 경로·업로드·URL). 못 열면 **추측 금지** —
  정확한 경로/URL을 되묻는다. 안 열어보고 쓴 분석 = 오류(§0 "안 열고 쓴 값 = 오류").
- 산출 목적을 1줄로 확정한다: **재현**(그대로) / **영감**(분위기만) / **부분 이식**(그 모션만).
  목적이 갈리면 프롬프트의 강제 수준이 달라진다.

## 1. 기술 검사 — 값은 재생기가 아니라 도구가 말한다

```bash
ffprobe -v error -show_entries format=duration -show_entries stream=width,height,r_frame_rate,codec_name -of default=nw=1 <영상>
```

전환점 우선으로 프레임을 뽑는다(균등 분할은 차선 — 장면이 바뀌는 지점을 놓친다).

```bash
ffmpeg -i <영상> -vf "select='gt(scene,0.25)',showinfo" -vsync vfr frames/scene_%03d.png   # 장면 전환 감지
ffmpeg -i <영상> -vf fps=2 frames/t_%04d.png                                                # 보강용 등간격
```

뽑은 프레임은 **반드시 눈으로 본다**(Read로 이미지 열람). 파일이 생겼다 ≠ 내용을 봤다.

## 2. 5층 해부 — 층을 섞지 마라

| 층 | 뽑아야 하는 것 |
|---|---|
| 스토리 | 목적, 섹션 순서, 각 구간이 관객에게 시키는 일, 전환 흐름 |
| 레이아웃 | 뷰포트 기준, 그리드/컬럼, 고정(sticky·fixed) 영역, 카드 구조, 여백 리듬 |
| 모션 | 지속·딜레이·이징, 스태거 간격, 시차(패럴랙스), 마스크, **스크롤 스크러빙 여부** |
| 비주얼 | 타이포 스케일·웨이트, 색 역할(배경/전경/강조), 표면(글래스·그림자), 아이콘 문법 |
| 기술 | 무엇으로 만들 수 있나 — 순수 CSS / GSAP+ScrollTrigger / Canvas / WebGL |

수치는 **프레임 타임코드에서 역산**한다(눈대중 "빠름/느림" 금지 — `0.8s ease-out`처럼).

## 3. 자산 계획

- 실제 URL이 있으면 그대로 적고, 없으면 **플레이스홀더명**을 정한다(`hero-loop.mp4` 등).
- AI로 생성해야 하는 자산은 **본 프롬프트에서 분리**해 별도 생성 프롬프트로 뺀다.
- 폰트·로고·인물 등 **권리 있는 자산은 재현 대상에서 제외**하고 대체 지시를 적는다.

## 4. 슈퍼프롬프트 조립

붙여넣기 가능한 **단일 코드블록 하나**로 낸다. 필수 구성:

1. **자산 맵** — 경로/플레이스홀더 ↔ 쓰이는 위치
2. **디자인 언어** — 타이포·색 역할·표면·라운드·간격 규칙
3. **섹션별 해부** — 순서대로, 각 섹션의 레이아웃 + 그 안의 모션
4. **모션 시스템** — 이징·지속·스태거·트리거(스크롤 %·뷰포트 진입률)
5. **접근성** — `prefers-reduced-motion` 시 무엇이 멈추고 무엇이 완성 상태로 고정되는지 **항상 포함**

## 5. 이 레포에 적용할 때 (기틀 접속점)

- **값 계승 우선** — 분석 결과의 hex·px를 그대로 쓰지 마라. 구현 단계에선 `viewer/index.html`
  `:root` 토큰으로 환산해 적는다(팔레트 = 폐쇄형 · 자유 hex 금지). 프롬프트엔
  「색 = 이 레포 accent 토큰」처럼 **역할**로 쓴다.
- **부품 계승** — 새 컴포넌트를 그리기 전에 `디자인기틀/CII_컴포넌트계승인덱스.md`에서
  같은 역할 부품을 먼저 찾는다. 없을 때만 신설 제안.
- **레퍼런스 지목** — 구현 착수 1줄에 "레퍼런스 = 이 영상 §구간"을 명시한다(창작 금지 축).
- 산출 문서 자리 = `docs/reports/{yymmdd}_{라벨}_영상해부.md`.

## 흔한 실수

- **영상을 안 열고 씀** — 가장 큰 오류. 프레임을 뽑아 눈으로 본 뒤에만 쓴다.
- **등간격 프레임만 사용** — 전환점을 놓쳐 "무엇이 언제 바뀌는지"가 통째로 빠진다.
- **모션을 형용사로 기술** — "부드럽게" 대신 `0.6s cubic-bezier(...)`, 스태거 `70ms`.
- **스크롤 메커니즘 뭉갬** — 스크럽(스크롤 위치=재생 위치)과 트리거(진입 시 1회 재생)는
  완전히 다른 구현이다. 어느 쪽인지 프레임으로 판정해 명시한다.
- **reduced-motion 누락** — 접근성 지시 없는 프롬프트는 미완으로 본다.
- **한 덩이로 안 냄** — 여러 블록으로 흩어지면 붙여넣기 계약이 깨진다.
