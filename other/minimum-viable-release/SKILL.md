# minimum-viable-release

## When to Use

当完成一个创作（文章、产品原型等）后，因自我怀疑或追求完美而犹豫是否发布时description

## Core Logic

# 执行步骤

1.  **输入**：一个基本成型的创作物（初稿、产品原型等）。
    **步骤**：评估“完成度”。检查该创作物是否已包含最核心的价值主张和基本功能/内容，能够向受众传递核心意图。
    **判断标准**：能否用一句话向目标用户清晰说明这个作品是什么、解决什么问题。
    **常见误区**：将“附加功能”、“美化修饰”或“完备性”误判为核心价值，导致迟迟无法达到“可发布”状态。

2.  **步骤**：心态校准。主动接受“初期作品质量可能不佳”和“发布后可能被视为新手”的可能性，明确发布的核心目的是“获取反馈”而非“获得赞誉”。
    **判断标准**：是否已将成功标准从“作品完美”调整为“获得可用于改进的反馈”。
    **常见误区**：将个人身份与作品初期质量过度绑定，因害怕负面评价而放弃发布。

3.  **步骤**：选择发布渠道。选择一个与目标受众匹配且心理压力较小的渠道进行发布（如小范围社群、早期用户名单、特定平台）。
    **判断标准**：渠道是否能触达真实的目标用户，且发布行为本身是可执行、低成本的。
    **常见误区**：选择过于公开或庞大的渠道，因心理压力而行动瘫痪；或选择完全无法获得反馈的渠道。

4.  **步骤**：发布并引导反馈。执行发布，并主动设计方式引导有价值的反馈（如提出具体问题、设置反馈表单、鼓励评论）。
    **判断标准**：发布动作是否已完成，并设置了收集反馈的机制。
    **常见误区**：被动等待反馈，不主动引导，导致反馈数量和质量不足。

5.  **步骤**：处理反馈。
    **IF** 获得具体反馈：
        **步骤**：分析反馈，区分是“偏好问题”还是“价值缺陷”，并据此规划下一版本的具体改进点。流程结束，进入迭代开发。
    **ELSE**（未获得反馈）：
        **步骤**：分析原因。是受众不匹配、价值主张不清晰，还是反馈渠道不畅？根据分析结果，返回步骤1（调整核心价值）或步骤3（调整发布渠道）。
    **判断标准**：是否基于反馈结果（无论有无）形成了明确的后续决策（改进或调整方向）。
    **常见误区**：对全部反馈照单全收，失去创作主线；或完全无视所有反馈。

# 输出格式要求
输出一个包含以下要点的发布决策简报：
1.  **发布物核心价值**：用一句话描述。
2.  **目标发布渠道**：具体渠道名称及选择理由。
3.  **反馈收集机制**：计划如何获取反馈。
4.  **成功度量**：定义本次发布视为“成功”的最低反馈标准（如：获得3条具体改进建议）。
