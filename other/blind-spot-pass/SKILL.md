# Blind Spot Pass

找出用户完全没有考虑过的事、缺少的领域知识，以及他们尚不知道的“好”可以是什么样。目的不是立刻选方案，而是让用户具备判断下一轮候选的知识。

1. 从输入和 context 判断用户的起点、经验和任务范围。无法判断且会影响解释深度时，先询问并等待回答；已有信息不重复问。
2. 扫描任务涉及的代码和已有文档，明确覆盖的文件与未检查区域。没有代码时说明领域调查范围。寻找未文档化约束、半成品或失败尝试、继承的潜在 bug 和用户缺少的判断标准。
3. 逐条解释发现，最重要的在前。每条包含：证据（文件与行或一手来源）、为什么会咬到这次任务、需要补的知识、如何影响后续方案。事实与推测分开；尚未调查的风险标为待核验，不编造覆盖。
4. 用户不懂某个领域的“好”时，先用具体对比解释判断标准，再让他们选择。需要参考物时，在 unknowns 内返回其 References 分支；独立使用时询问是否有参考，只有得到委托才派子代理寻找。
5. 已确认的事实与 sharp edges 进入地图；需要选择的事项进入后续 known unknowns 队列；还不明确的记为 OPEN 并写明解锁条件。

完成：用户已看到并理解重要盲点，覆盖与局限已披露，每条发现有证据或明确的不确定标记，以及后续去向。需要用户反馈时停下，不代表用户作答，不开始实现。
