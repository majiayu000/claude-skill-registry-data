# 특허 명세서 구성요소·파이프라인 구체화 스킬

## 0. 핵심 사상

1차 명세서 본문에서 "~부", "~모듈", "~엔진" 같은 **구성요소 단락**은 추상적인 역할 기술("~을 수행하도록 이루어질 수 있다")만 적혀 있는 경우가 잦다. 이 상태에서는:

- **진보성** — 무엇을 어떤 기준으로 처리하는지가 안 보여 차별성 약화
- **기재요건(특허법 §42③)** — 통상의 기술자가 재현 가능한 수준의 구체성이 부족
- **균등론 대응** — 후속 회피 설계에 대한 방어망이 부재

본 스킬은 1차 본문에 두 가지 단락 보강을 자동 적용하여 위 약점을 동시에 메운다:

- **(모드 A) 구성요소 판단 기준 3단 보강** — 각 ~부/~모듈에 대해 *판단 기준 → 적용 방식 → 효과* 3단 단락을 끼워넣음
- **(모드 B) 데이터 처리 파이프라인 통합 단락** — 모든 구성요소가 어떻게 데이터로 연결되는지(provenance·식별자 연계)를 한 단락으로 묶음

본 스킬은 [kr-patent-definition-insertion] 다음, [kr-patent-embodiment-addition] 이전 순서로 호출된다. 정의된 용어를 가지고 구성요소를 구체화한 뒤, 변형 실시예로 외연을 확장하는 흐름.

### ⛔ 절대 금지 — 청구범위 비수정 원칙

본 스킬은 **본문(특히 "발명을 실시하기 위한 구체적인 내용" 절)에만** 단락을 부가한다. 【청구범위】 섹션 — 【청구항 1】~【청구항 N】 — 은 **절대 수정하지 않는다**. 보강 단락은 *잠재적 종속청구항의 후보*가 될 수 있는 형태로 기술하되, 실제 청구항화 여부는 추후 분할/계속출원 또는 보정 단계의 별도 결정 사항.

## 1. 모드 A — 구성요소 판단 기준 3단 보강 (프롬프트 ②)

### 1.1 적용 대상 식별

본문에서 다음 패턴을 추출:

- "~부(NNN)", "~모듈(NNN)", "~엔진(NNN)" 등 도면부호를 가진 구성요소
- 해당 단락이 *역할만 추상적으로* 기술되어 다음 중 어느 하나가 본문에서 읽히지 않는 경우:
  - (a) 입력을 어떤 기준으로 분류하는지
  - (b) 처리를 어떻게 분기하는지
  - (c) 임계값·우선순위·선택 정책이 있는지

### 1.2 표준 3단 템플릿

```
[1단] 판단/선정 기준 (i, ii, iii 형식, 최소 3개)

보다 구체적으로, 상기 [구성요소]는 다음의 기준에 따라 [동작/판정/선정]을(를) 수행할 수 있다.
i) [기준1] — [무엇을 결정하는지]
ii) [기준2] — [무엇을 결정하는지]
iii) [기준3] — [무엇을 결정하는지]
다만, 본 발명에서 상기 기준은 이에 한정되지 않는다.

[2단] 각 기준의 적용 방식

보다 구체적으로, 상기 [구성요소]는 상기 [기준명]에 따라 ~할 수 있다.
예를 들어, [구체 시나리오 1]의 경우 ~로 처리될 수 있다.
예를 들어, [구체 시나리오 2]의 경우 ~로 처리될 수 있다.
다만, 본 발명에서 상기 적용 방식은 이에 한정되지 않는다.

[3단] 효과 단락

이와 같이, 상기 [구성요소]가 [기준]에 따라 [동작]함에 따라, [기술적 효과 — 정확도/효율/신뢰성 등]가 [발생할/달성될/확보될] 수 있다.
```

### 1.3 적용 예시

대상: "정합성 데이터 생성부(340)는 확장 지식그래프를 기반으로 정합성 데이터를 생성한다." 한 줄짜리 추상 단락.

보강 결과:

```
[1단] 보다 구체적으로, 상기 정합성 데이터 생성부(340)는, 다음의 기준에 따라 계획 노드(510)와 성과 노드(520)의 매칭을 수행할 수 있다.
i) 임베딩 벡터 간의 의미적 거리 — 두 노드의 주제 영역의 일치 정도를 결정함.
ii) 노드 간의 그래프 경로 거리 — 두 노드가 동일한 과제 트리 하위에 속하는지를 결정함.
iii) 사용자 지정 가중치 — KPI 노드와 같이 정량적 중요도가 높은 계획 노드에 대한 매칭 우선순위를 결정함.
다만, 본 발명에서 상기 매칭 기준은 이에 한정되지 않는다.

[2단] 보다 구체적으로, 상기 정합성 데이터 생성부(340)는, 상기 의미적 거리 기준에 따라 임베딩 벡터 간 코사인 유사도가 임계값 이상인 노드 쌍을 우선 매칭 후보로 선정할 수 있다. 예를 들어, KPI 노드(513)와 논문 노드(521)의 경우, 정량 수치 일치도가 우선되어 처리될 수 있다. 예를 들어, 세부 과제 노드(514)와 특허 노드(523)의 경우, 기술 분야 일치도가 우선되어 처리될 수 있다. 다만, 본 발명에서 상기 적용 방식은 이에 한정되지 않는다.

[3단] 이와 같이, 상기 정합성 데이터 생성부(340)가 복수의 기준에 따라 계획-성과 매칭을 수행함에 따라, 단일 척도만으로는 식별이 어려운 의미·정량 양 측면의 부합성이 입체적으로 평가될 수 있다.
```

### 1.4 삽입 위치

- 해당 구성요소를 처음 도입하는 단락 **직후**
- 구성요소가 도면 단락(예: "도 N을 참조하면, …" 단락) 안에 포함된 경우, 도면 단락 흐름을 깨지 않도록 다음 문단으로 분리하여 삽입

## 2. 모드 B — 데이터 처리 파이프라인 통합 단락 (프롬프트 ③)

### 2.1 삽입 위치

모든 구성요소 개별 설명이 끝난 직후, **방법 단계(S110, S120, … SXXX)** 설명으로 진입하기 **전**의 브릿지 위치. 통상 "이상에서 살펴본 [시스템명]에 의하여 수행되는 [방법명]에 대하여 살펴본다" 류의 브릿지 문장 직전.

### 2.2 표준 4요소 템플릿

```
나아가, 본 발명에 따른 [시스템명]은, 상기 [구성요소들]이 데이터 처리 파이프라인을 이루도록 결합되어 동작할 수 있다.

(a) 흐름 구조 — 각 처리 단계의 출력 데이터가 후속 단계의 입력 데이터로 제공되는 구조로 이루어질 수 있다. 보다 구체적으로, [구성요소1]의 출력이 [구성요소2]의 입력으로 제공되고, [구성요소2]의 출력이 [구성요소3]의 입력으로 제공되어, 처리가 단계적으로 누적될 수 있다.

(b) 데이터 변환 흐름 — 입력 데이터의 형태(예: [원본 형태])는 중간 데이터의 형태(예: [중간 표현])를 거쳐 최종 데이터의 형태(예: [최종 산출 형태])로 변환될 수 있다.

(c) Provenance 플래그 — 각 단계에서 생성되는 중간 데이터에는 [출처/방식을 나타내는 플래그 또는 식별자]가 함께 저장되어, 후속 단계의 처리 또는 [근거 추적·검증·리포팅]에 활용될 수 있다. 예를 들어, 상기 플래그는 i) [출처 식별], ii) [처리 방식 식별], iii) [신뢰도 상태], iv) [재처리 가능 여부] 중 적어도 하나를 포함할 수 있다.

(d) 식별자 연계 — 각 구성요소 간 데이터는 [고유 식별자 / 키]에 의하여 상호 연계(provenance)되며, [데이터의 출처·생성 시각·처리 이력]이 일관되게 추적될 수 있다.

다만, 본 발명에서 상기 파이프라인의 구성 방식 및 데이터 식별자의 종류는 이에 한정되지 않는다.
```

### 2.3 플래그 카테고리 (consistency-check 4단계 플래그 연동)

본 스킬의 모드 B에서 기술하는 provenance 플래그는, `kr-patent-consistency-check`의 본문 4단계 플래그 체계(검증 성공/확인 필요/검증 실패/미확인)와 정합되도록 작성한다. 명세서 안에서 한 가지 플래그 체계가 일관되게 사용되어야 균등론 대응에 유리.

### 2.4 적용 예시

대상: "수신부(310) → 지식그래프 생성부(320) → 지식그래프 확장부(330) → 정합성 데이터 생성부(340) → 연차보고서 생성부(350)" 5개 구성요소 개별 설명 직후.

보강 결과:

```
나아가, 본 발명에 따른 연구개발 성과 관리 시스템(100)은, 상기 수신부(310), 지식그래프 생성부(320), 지식그래프 확장부(330), 정합성 데이터 생성부(340) 및 연차보고서 생성부(350)가 데이터 처리 파이프라인을 이루도록 결합되어 동작할 수 있다.

(a) 흐름 구조 — 상기 수신부(310)의 출력은 상기 지식그래프 생성부(320)의 입력으로 제공되고, 상기 지식그래프 생성부(320)의 출력은 상기 지식그래프 확장부(330)의 입력으로 제공되며, 이러한 단계적 누적을 통하여 최종적으로 상기 연차보고서 생성부(350)에서 연차보고서 데이터가 산출될 수 있다.

(b) 데이터 변환 흐름 — 입력 데이터의 형태(예: 비정형 PDF·DOCX 텍스트)는 중간 데이터의 형태(예: 정규화된 메타 데이터, 노드·엣지 표현의 지식그래프)를 거쳐 최종 데이터의 형태(예: 연차보고서 데이터 및 연결 정보)로 변환될 수 있다.

(c) Provenance 플래그 — 각 단계에서 생성되는 중간 데이터에는 출처와 처리 방식을 나타내는 플래그가 함께 저장될 수 있다. 예를 들어, 상기 플래그는 i) 정규 규칙에 의하여 결정적으로 추출된 데이터에 부여되는 "검증 성공" 플래그, ii) 언어 모델에 의해 보완 추출된 데이터에 부여되는 "확인 필요" 플래그, iii) 추출 실패 데이터에 부여되는 "검증 실패" 플래그 및 iv) 외부 데이터 부재로 비교가 이루어지지 않은 데이터에 부여되는 "미확인" 플래그 중 적어도 하나를 포함할 수 있다.

(d) 식별자 연계 — 각 구성요소 간 데이터는 노드 ID 및 고유 식별자(예: DOI, 특허 출원번호, ORCID)에 의하여 상호 연계되며, 연차보고서 데이터의 각 문장의 근거가 되는 확장 지식그래프(600)의 노드가 노드 단위로 추적될 수 있다.

다만, 본 발명에서 상기 파이프라인의 구성 방식 및 데이터 식별자의 종류는 이에 한정되지 않는다.
```

## 3. 작업 절차

### Step 1: 보강 대상 추출
- 본문에서 "~부(NNN)", "~모듈(NNN)", "~엔진(NNN)" 패턴을 모두 추출
- 각 구성요소의 첫 도입 단락이 1.1의 (a)(b)(c) 점검 항목을 만족하는지 확인
- 만족하지 않는 구성요소를 모드 A 대상으로 등록
- 모든 구성요소의 개별 설명이 끝난 위치를 모드 B 삽입 후보로 등록

### Step 2: 모드 선택
- 구성요소 단위 보강 → 모드 A
- 시스템 전체 흐름 통합 → 모드 B
- 통상은 모드 A를 모든 추상적 구성요소에 적용한 후, 마지막에 모드 B를 1회 적용

### Step 3: 템플릿 채우기
- 모드 A 3단 템플릿 / 모드 B 4요소 템플릿을 본문 문맥에 맞게 구체화
- 도면부호는 원본 체계 유지 (신규 부호 발명 금지)
- 청구항 한정 용어는 [kr-patent-definition-insertion]에서 이미 정의된 형태 그대로 사용

### Step 4: 삽입 및 일관성 검증

체크리스트:
- [ ] 모드 A의 [1단][2단][3단] 표지는 *내부 작성 마커*이므로 최종 본문에서는 삭제하고 자연스러운 단락 흐름으로 통합
- [ ] 모든 종결 어미가 "~할 수 있다" / "~될 수 있다" 형태
- [ ] 모든 단락 말미에 "다만, 본 발명에서 ~는 이에 한정되지 않는다"
- [ ] (i), (ii), (iii) 열거 적극 사용
- [ ] 구체 예시는 "예를 들어, ~"로 시작
- [ ] 도면부호 원본 체계 유지, 신규 부호 0건
- [ ] **【청구범위】 섹션이 byte-단위로 원본과 동일** (불변식)

### Step 5: 사후 점검

본 스킬 종료 직후 다음 자체 점검:
- 모드 A 보강이 들어간 구성요소 N개의 단락에 (a)(b)(c) 점검 항목이 모두 본문에서 읽히는가?
- 모드 B 통합 단락이 (a)(b)(c)(d) 4요소를 모두 포함하는가?
- consistency-check H섹션 규칙 4(청구항-명세서 정합성), 5(부재번호 흐름 정합성), 8(의미 비약 방지)에 위배되는 표현이 없는가?

## 4. 흔한 실수 (Don't / Do)

| ❌ Don't | ⭕ Do |
|---|---|
| "다양한 방법으로 수행될 수 있다" 같은 빈 문장 | 구체적 기준 i)/ii)/iii) 최소 3개 열거 |
| 효과 단락(3단) 누락 | "이와 같이, ~함에 따라, ~될 수 있다" 명시 |
| 한정 부정 누락 | 단락 말미에 "다만, 본 발명에서 ~는 이에 한정되지 않는다" |
| 청구항에 없는 신규 기준을 새로 발명 | 청구항·정의 단락에서 이미 사용 중인 용어 범위 안에서 풀어쓰기 |
| 모드 B를 각 구성요소 단락 안에 분산 | 모드 B는 모든 구성요소 설명 종료 후 1회로 묶음 |
| 도면부호 신규 발명 | 원본 부호 체계 유지 |
| 청구범위 섹션 수정 | 본문 단락 부가에만 한정 (불변식) |
| 모드 A 내부 마커 [1단][2단][3단] 본문에 잔존 | 최종 본문에서 마커 제거, 자연스러운 단락 흐름 |

## 5. 다른 스킬과의 관계

- **이전: `kr-patent-definition-insertion`** — 용어 정의가 본문에 인라인 삽입된 후 본 스킬 호출. 정의된 용어를 모드 A·B에서 그대로 사용.
- **다음: `kr-patent-embodiment-addition`** — 본 스킬로 구성요소 골격이 보강된 후, 변형 실시예(16 기술 도메인 + 8 설계 결정 축)로 외연을 확장.
- **점검: `kr-patent-consistency-check`** — 본 스킬 종료 후 H섹션 규칙 4·5·8 자체 점검 권장.
- **오케스트레이션: `kr-patent-full-workflow`** — 11-Stage 흐름의 Stage 6.5 (권리범위 보강 — 구성요소·파이프라인 구체화)에서 본 스킬을 호출.

## 6. 본 스킬을 사용하지 말아야 할 경우

- 사용자가 청구범위 자체의 수정·확장을 요청하는 경우 (본 스킬 범위 밖)
