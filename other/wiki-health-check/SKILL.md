# Wiki Health Check

你对 `physics-wiki/` 执行结构化健康检查，遵循 `physics-wiki/templates/wiki健康检查工作流.md` 和 `physics-wiki/templates/定期健康检查节奏.md`。

你的目标是 **发现问题并分类**，不是为了清零 warning 而盲目操作。

## 检查类型

### 1. 轻量检查

适用于每次正式 wiki 维护后、新增/移动/重命名/合并/拆分页面后、raw ingest 后。

检查项目：
- `llmwiki-tool lint` 运行结果
- `wiki/log.md` 是否有本次维护记录
- `wiki/index.md` 是否收录新正式页面
- broken-link 分类处理情况

### 2. 专题检查

适用于完成一个知识链页、综合讲义页、路线图阶段或一批相关页面后。

检查项目：
- 轻量检查的所有项目
- 双向链接完整性（用 `llmwiki-tool refs` 检查知识链页与节点页的链接）
- 空页面检查（新页面非空行 ≥ 5 行）
- 机械堆链接检查（链接是否有自然上下文）
- 路线图是否包含新页面

### 3. 全量检查

适用于周期性检查（建议每周/每两周）、大量页面变更后、发现 wiki 结构混乱时、开始新学习阶段前。

检查项目：
- 轻量 + 专题的全部项目
- raw backlog 积压情况
- 重复页面检查
- 页面质量抽查（参照 `wiki页面质量评分检查表.md`）
- 知识链页与路线图状态
- log 完整性
- 首页结构合理性

## 工作流程

### 第一步：确定检查类型

确认用户需要的检查粒度，或根据上下文自动判断（默认全量检查）。

### 第二步：运行命令

```bash
# 基本 lint
llmwiki-tool lint

# 如果需要结构统计
llmwiki-tool scan physics-wiki/wiki

# 如果需要检查特定页面的双向链接
llmwiki-tool refs to <页面路径>
llmwiki-tool refs from <页面路径>
```

### 第三步：解析与分类

对 lint 输出逐条分类，遵循 `CLAUDE.md` 中的 broken-link 处理原则：

| 类型 | 处理建议 |
|---|---|
| 已有近似页面 | 改链接指向已有页面 |
| 普通术语 | 去掉 `[[ ]]` 改普通文字 |
| 确实需要独立页面 | 记录为"建议新建"，不擅自创建 |
| 乱码链接 | 修正编码或重写 |
| raw/templates/log 误链 | 取消双链或改路径引用 |
| 暂不处理 | 记录原因 |

### 第四步：补充检查项

根据检查类型，补充：
- **index 覆盖**：新正式页面是否收录，raw/templates/log 是否误入
- **log 完整性**：最近维护是否都有记录
- **raw 积压**：`physics-wiki/raw/` 目录和 `backlog.md` 是否有待处理材料
- **页面质量**：抽查 1-3 个页面（核心概念页、最近新增页、枢纽页）

### 第五步：生成报告

输出结构化报告，分三个优先级：

```
需立即处理 > 建议后续处理 > 暂不处理
```

## 输出格式

### 轻量检查报告

```
## Wiki 健康检查报告

### 检查信息
- 类型：轻量检查
- 时间：YYYY-MM-DD
- 命令：llmwiki-tool lint

### 检查结果
- broken link：N 个（分类说明）
- log 完整：是/否
- index 覆盖：是/否（列出缺失页面）

### 处理建议
- 需立即处理：
- 后续处理：
- 暂不处理：

### 建议再次运行 lint
- 是/否
```

### 全量检查报告（补充字段）

```
### 额外检查
- raw 积压：M 个文件待处理（优先处理建议）
- 页面质量抽查：[页面名] = 评分/等级（仅全量检查）
- 重复页面风险：无/发现（说明）
- 知识链页状态：[页名] = 正常/需更新
- 路线图状态：[页名] = 正常/需更新
- log 完整性：自上次检查以来共 N 条记录

### 总体判断
- wiki 状态：健康/基本健康/需关注/需维护
```

## 注意事项

1. **不盲目建页**：broken link 不等于必须创建页面
2. **不机械堆链接**：不为了 orphan 清零强塞链接
3. **不修改文件**：除非用户明确要求修复，本 skill 默认只读检查
4. **早期不苛求**：知识库早期不追求 orphan/index 覆盖清零
5. **报告不存 wiki**：健康检查报告不是正式知识页
6. **建议而非强制**：只给出分类和处理建议，修改需用户确认

## 输出风格

- 优先用表格展示结构化结果
- broken link 逐条列出原始文本和建议处理方式
- 优先级标签：`[立即]` `[后续]` `[暂缓]`
- 结尾明确建议：是否需要再次运行 `llmwiki-tool lint`
