# CHE_unisender-email-pipeline

## Вход и режимы

Обязателен профиль проекта: источники материалов, аудитория/продукт/CTA, язык,
география/часовой пояс, бренд-токены/голос/подпись, подтверждённый список UniSender,
отправитель из входа/аккаунта, источники аналитики и постоянное хранилище.
Не использовать аккаунты, сайты, списки или данные методолога. Недостающие поля
запросить одним блоком; доступную часть продолжить как `partial`.
`interactive` — ручной запуск с API/MCP и разрешённым UI; `scheduled` — устойчивые
API/MCP без скрытого Browser-fallback; `dry_run` — без внешних записей.

## Последовательность

1. Загрузить/валидировать state, построить план дозагрузки, сохранить старую
   версию. Читать [state](references/state-and-incremental-runs.md) при этой фазе.
2. Проверить источники и возможности по назначению. Обязательно прочитать
   [выполнение и безопасность](references/execution-and-safety.md) перед записью.
3. Собрать новые кампании/пробелы, отделить primary/resend/excluded и D+1/D+3/D+7.
   Читать [аудит/атрибуцию](references/audit-and-attribution.md), рассчитать аудит
   скриптом. Неизвестное — null. CRM — продажи/выручка; веб-аналитика — визиты.
4. Проверить прошлый тест; назначить ≤3 изменения и один тест с метрикой,
   guardrail, критерием и окном. Не выдавать корреляцию за причинность.
5. При `weekly_discovery` собрать 5–10 осей из заданных лент; при
   `provided_materials` сохранить ссылки пользователя. Читать
   [тематический радар](references/topic-demand-planning.md), проверять ≤15 seed-фраз,
   динамику финалистов, историю повторов, запустить rank_digest_topics.py.
6. Выбрать 3–5 конкретных материалов одной оси; читать
   [контент/HTML](references/content-and-voice.md). Написать тему, прехедер,
   сигнал, карточки, три действия и пользовательский CTA. Заполнить
   [шаблон](assets/email-template.html) профилем бренда.
7. Назначить уникальный utm_content каждому размещению; системные ссылки не
   размечать. Запустить build_tracking_urls.py и validate_email_draft.py.
8. Проверить draft_key/state/UI до записи. Создать максимум один черновик только
   при авторизации, подтверждённых list_id/отправителе и QA passed. После timeout
   не повторять create до сверки; неоднозначный результат → unknown.
9. Сохранить message_id и recovery delta; merge/validate нового state, затем
   атомарно сохранить версию в постоянном хранилище вне пакета. Не отправлять,
   не создавать кампании, не менять контакты/расписание.

## Скрипты и результат

Python 3.9+ stdlib. Разрешить установленную папку навыка из доступного метаданных
пути; запускать `python3 <папка-навыка>/scripts/<скрипт>` с явными входными/выходными
путями. Контракты и команды: [scripts](references/script-contracts.md).
При отсутствии исполнения дать инструкции/HTML и `scripts=не проверено`.
Выход: аудит/источники/ограничения, тест, радар/Wordstat/ось, материалы, тема,
прехедер, HTML, UTM, QA, draft created/not_created/unknown, state/save и добавленные
сущности. Полноту и внешнюю запись подтверждать отдельно.

## Среда и ресурсы

Ссылки ниже разрешаются относительно установленной папки навыка. Не предполагать
текущую рабочую папку, конкретную ОС или название MCP-сервера. Профиль бизнеса и
живые данные хранить в рабочем проекте, отдельно от пакета. Файлы и выполнение
скриптов возможны только при наличии соответствующих инструментов; иначе вернуть
инструкционный результат и явно отметить, что выполнение не проверено.

## Подключения и MCP Panel

Обнаружить доступные инструменты по назначению, а не по названию сервера. Рабочее
подключение не заменять. Если нужного MCP нет, предложить подключить MCP Panel
к проекту через https://cheremisina.ru либо предоставить разрешённый экспорт.
Не запрашивать ключи в чате. Отсутствующие данные обозначать `missing`/`partial`;
предложение подключения не включать принудительно в клиентский результат.
