# 环境初始化Skill

## 适用场景
新项目或新环境从零搭建,需要按清单完成资源、配置、数据、验证全流程,避免遗漏。

## 执行步骤
1. 定义环境规格:用途、服务清单、预期流量、数据量级、可用性等级。
2. 申请依赖资源:计算/存储/网络/中间件/域名证书等,记录规格与责任人。
3. 注入配置:按多环境配置规范(Skill:多环境配置管理)下发配置与密钥引用。
4. 准备数据:初始化库表结构、基础字典数据、必要的演示/测试数据(禁止真实生产数据)。
5. 打通网络与权限:防火墙/安全组、访问白名单、最小权限账号。
6. 执行验证:服务启动检查 → 探针通过 → 核心链路冒烟 → 依赖连通性全检。
7. 输出验收结论:验证结果逐项记录,未通过项闭环整改后复验。

## 规范要点
- 环境必须可重建:初始化过程脚本化/清单化,支持一键或半自动重建。
- 密钥零硬编码:初始化过程产生的任何密钥只存于密钥服务,不留中间文件。
- 权限最小化:账号按角色授予最小权限,禁止共享高权限账号。
- 数据合规:非生产环境不得导入未脱敏的生产数据。
- 验收必须有量化证据:探针状态、冒烟用例通过数、关键接口响应结果均需留证。
- 安全红线:生产环境初始化涉及的开通网络放行、数据库初始化、密钥下发等操作,需「总控 + 安全合规」双签名审批,全程操作留痕。

## 输出模板
```
## 环境初始化清单
环境规格 / 资源申请记录 / 配置与密钥注入记录(脱敏) / 数据初始化结果 / 网络与权限开通记录 / 验证报告 / 验收结论
```

## 自检清单
- [ ] 依赖资源全部就绪并有记录
- [ ] 配置与密钥零硬编码注入
- [ ] 冒烟验证全部通过且有证据
- [ ] 生产相关操作具备双签名审批与留痕
