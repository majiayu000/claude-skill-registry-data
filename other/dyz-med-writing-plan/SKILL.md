# 医学论文论证地图与写作计划

## 何时使用

适用于新稿动笔前、现有稿件结构混乱时，或某一章节缺少清晰论证任务时。用户直接要求写引言、方法、结果、
讨论或摘要时，交给对应分节 Skill；用户要求全面诊断现有稿件时，交给 `dyz-med-manuscript-diagnose`。

## 核心原则

1. 计划只能建立在用户提供或已核实的事实、数据和文献上。
2. 把“已知事实”“本研究结果”“作者解释”“待核实假设”分开记录。
3. 观察性、横断面或探索性研究不得在计划中预埋未经支持的因果结论。
4. 缺少文献、统计结果或研究设计信息时，保留明确缺口，不用合理猜测补齐。
5. 计划服务于写作，不改变研究问题、结局定义、分析方案或原始数据。

## 所需输入

尽量读取：

- 研究问题、研究设计、研究对象、主要与次要结局；
- 研究方案、注册信息或项目状态文件；
- 已核实的统计结果、表格和图；
- 关键文献清单、精读记录及矛盾证据；
- 现有章节草稿和目标期刊要求（如已确定）。

输入不完整时仍可生成“可用骨架”，但要逐项标出 `missing`、影响及需要谁确认。

## 工作流

### 1. 建立事实底板

列出研究问题、设计、样本、暴露或干预、对照、主要结局、关键分析和现有证据。每项注明来源位置与状态：
`confirmed`、`provisional`、`missing` 或 `conflicting`。

### 2. 建立全文论证地图

至少定义：

- `known_before`：已有证据真正支持什么；
- `gap`：仍未解决的具体问题；
- `added_by_this_study`：本研究新增什么；
- `core_claim`：最核心、且不超过研究设计能力的一句话；
- `claim_boundaries`：允许、需谨慎和禁止的表述；
- `evidence_support`：每条核心论断对应的数据、文献或推断。

若存在矛盾证据，必须进入地图，不能只保留支持性文献。

### 3. 制定章节计划

为引言、方法、结果、讨论和摘要分别列出：

- 每段的功能与主题句；
- 必须使用的数据或文献；
- 不能在该段出现的内容；
- 与前后章节的衔接；
- 尚未解决的问题和输出目标。

分节顺序可根据稿件类型和目标期刊调整，不把 IMRaD 当作所有论文的唯一结构。

### 4. 做一致性检查

核对：

- 研究目的与主要结局一致；
- 方法能回答研究问题；
- 结果计划覆盖预设结局，并区分预设与探索性分析；
- 讨论中的解释不超过结果和证据；
- 摘要结论不超过正文；
- 每个关键论断都能找到证据来源或明确标为待核实推断。

## 交付物

优先在项目目录生成或更新：

- `paper/writing/manuscript_argument_map.yaml`
- `paper/writing/section_plans/`
- `paper/writing/claim_graph.yaml`
- `paper/writing/paragraph_evidence_plan.yaml`
- `paper/writing/open-questions.md`

如果用户只需要对话内结果，可用同等结构直接呈现，不强制创建文件。

## 验收标准

- 核心论断、证据和研究设计能够互相追溯；
- 各章节职责互不混淆；
- 因果、机制和临床应用表述有明确边界；
- 矛盾、缺失和不确定信息没有被隐藏；
- 计划可以直接交给各分节 Skill 使用。

## 写作质量与教学

需要改善段落结构或解释修改理由时，按需读取[写作方法与合成样例](references/writing-craft.md)。在现有论证地图上做反向提纲，不新建竞争的事实源。样例不是实际研究证据，也不能作为隐藏盲评答案。
