# /retro-lost — ретро потерянных сессий

## ⭐ ОСЬ ВОЗРАСТА: когда сессия — потеряшка и какое ретро ей положено (anton 02.09.2026)
Потеряшка = сессия без касания **>24 часов** (было 5 дней; сканер `retro_lost_scan.py`,
`MIN_AGE_DAYS=1`). Возраст решает ГЛУБИНУ ретро — поле `retro_mode` в строке кандидата:

- **1–5 дней (`classic`)** — контекст ещё тёплый, мир не успел далеко уйти → **классическое
  качественное ретро**: полный набор шагов профиля узла (см. таблицу профилей ниже),
  включая контрибьют-тест, тесты панелью и docstring-паспорта на хабе.
- **>5 дней (`lite`)** — поезд ушёл (в другом или том же направлении — неважно, догонять
  дорого) → **облегчённое ретро**: шаги 0/0-бис/1/2/3/7/8, БЕЗ шагов 4/5/6/7-бис/9.
  RECALL при этом ПОЛНЫЙ — это не то, что режется (опасность №1 никуда не делась).

Ось возраста ⊥ оси профилей (хаб/пир): сначала возраст выбирает classic/lite, потом профиль
узла режет своё. Итог = ПЕРЕСЕЧЕНИЕ (пир-лайт + classic всё равно без панели ломателей —
она хабовая рельса; хаб + lite не делает панель даже при живой рельсе). MAX_AGE_DAYS=30
(амнистия) не тронут.

## Чем отличается от живого /retro и почему
Сессия брошена дни назад: контекст холодный, автора нет, мир УШЁЛ ВПЕРЁД. Отсюда три сдвига:
1. **RECALL — главный шаг, а не разминка.** Опасность №1 (Антон: «чтобы не суммаризировать
   старьё»): торжественно записать урок, который соседняя сессия уже записала, или судить
   артефакт, который с тех пор переписан/удалён. Каждый вывод сверяется с СЕГОДНЯШНИМ
   состоянием: память + MEMORY.md, grep волта, реестр задач, git log затронутых файлов
   ПОСЛЕ даты сессии. Урок уже записан → строка «уже в домах, дубль не создаю». Артефакт
   переписан позже → судим текущую версию, не сессионную.
2. **Часть живого ритуала НЕ нужна.** Compact-блок Антону — некому жать. Growth-log — только
   если в сессии был реальный спор/решение. Биты дня — протухли (сюжетно ценное → черновик
   в content-mine, не в канон задним числом). Drift-audit с подъёмом дочерних сессий — только
   если RECALL доказал, что направление ещё живо и не подхвачено.
3. **Сессия не отвечает** — все вердикты со степенью уверенности; «зачем это строили» без
   улики в транскрипте = 🤔 гипотеза, не факт.

## Шаги (на одну сессию-кандидата)
0-пре. **ВЗЯТЬ кандидата ДО разбора** (иначе вторая ночная сессия возьмёт того же):
   ```bash
   python -B "$HOME/.claude/scripts/retro_lost_scan.py" take <sessionId> --holder "<taskId>" --json --receipt-out "<absolute-receipt.json>"
   ```
   Путь receipt обязан быть абсолютным и вне репозитория. `rc=0` доверяй только когда durable
   receipt exists и JSON содержит непустые `question_id`, `session_id`, `logical_file_id`,
   `holder` и `epoch` как positive integer. Receipt сохрани до подтверждённого DONE для replay
   после crash. `exit 7` — **его разбирают прямо сейчас**, бери следующего. `exit 3` — уже
   закрыт. Захват снимается сам в `mark-done`; умерла сессия — протухает за 3 часа и кандидат
   возвращается в очередь. `list` занятых больше не показывает и пишет их число в stderr.
   Зачем: маркер done ставится только В КОНЦЕ, а разбор идёт минуты — между «взял из списка»
   и «пометил» две сессии спокойно брали один sessionId и правили одни файлы (§7.7). Класс
   «дедуп покрывает прошлое, но не летящее», `Breakage-Journal` 13.08 / 22.08 / 22.08.
   ⚠️ В БАТЧЕ (шаг 0-бис) захватывать НАДО КАЖДОГО участника батча, а не только первого.
   ⚠️ **ТОЛЬКО ПОЛНЫЙ sessionId** (замер 13.09): `take` принимает ОБРЕЗАННЫЙ id из 8 символов,
   печатает «взял: cd8e196d» и отдаёт `exit 0` — захват ложится на несуществующий ключ, а
   реальный кандидат остаётся свободным для соседней ночной сессии. Списки и группировки
   удобно печатать короткими id, но в `take`/`mark-done` подставляй полный — резолви его
   из выдачи `list` (`sessionId`), а не из своей таблички.
0. **Вход**: строка кандидата от сканера (path, project, sessionId, hint). Прочитать транскрипт
   ЭКОНОМНО (§6.1) готовым прибором: `python ~/.claude/scripts/retro_lost_extract.py <path> [N]`
   — отдаёт первый промпт, стройку, bash-команды и хвост, файл в контекст не тянет. Точечное
   дознание — grep. Транскрипт >2 МБ целиком не читать никогда; свой экстрактор не переизобретать
   (грабля «сид назвал цель, не назвал рельсу», журнал 21.08 строка 876).
   ⭐ **0-бис — БАТЧ ОДНОЙ РУТИНЫ (anton 22.08, «переработай рутину»):** у кандидатов теперь
   есть `hint` (первые слова первого промпта). Кандидаты с одинаковым hint = прогоны ОДНОЙ
   рутины → разбирать ОДНИМ батчем: один инвентарь по образцу + сверка судьбы находок каждого

8 свежих + 2 с хвоста → и только теперь `take` каждого. 22.08: батч одной рутины по hint = ОДНА единица,
mark-done всем её сессиям — так ночь закрывает 20-30 сессий. На единицу: чтение ≤
экстрактор+греп, вердикты Opus. Не уложился в 10 до 06:00 — остановиться, очередь подождёт
(сканер отдаст завтра). Отчёт рутины: одна строка в 03 «retro-lost: закрыто N, очередь M»
— по правилу §7.4 суточного ритма, без спама.

## Границы
- ⛔ Не чинить код брошенной сессии по ходу ретро (это отдельная задача с владельцем) —
  исключение: карв-ауты Breakage-Journal (потеря данных/безопасность/секреты) → сразу.
- ⛔ Не поднимать дочерние сессии без RECALL-доказательства «ещё нужно и никем не подхвачено» (сессия-копатель по 7-бис — не исключение: её RECALL-доказательство = сама карточка, созданная в этом прогоне; на чужие/старые карточки копателей не плодим — дедуп по taskId).
- ⛔ Не переписывать историю: ретро-заметка судит, что вышло, а не редактирует сессию.
- Tier-2 находки (секрет в транскрипте открытым текстом и т.п.) → аск в 02 немедленно.

## ⭐ ДВА ПРОФИЛЯ: ХАБ-ПОЛНЫЙ и ПИР-ЛАЙТ (anton 22.08, голосовые hub:5697+hub:5699)
Приказ дословно: «рутина, которая обязана быть на КАЖДОМ пире… она действительно должна быть
на каждом компьютере, потому что на каждом компьютере свои юзеры, свои пиры… не централизовано
на хабе, а у каждого… 5-10 потеряшек в сутки… по упрощённому варианту… но полное рекол».

**Почему децентрализация вообще возможна и обязана быть — ЗАМЕР 22.08:** транскрипты
`~/.claude/projects/*/*.jsonl` НЕ синкаются между узлами (строка `/projects` в `~/.claude/.stignore`;
проверено — в общих project-папках на хабе и на Маяке по 0 `.jsonl`), маркеры done в
`~/.claude/logs/` тоже не в whitelist синка. Значит: узел физически видит ТОЛЬКО свои сессии,
хаб чужие потеряшки разобрать не может НИКОГДА, два узла не подерутся за одну сессию и общий
реестр маркеров не нужен (single-writer-shard не требуется — шард и так один на узел).
Очереди на 22.08: хаб 627, Маяк 88 при 0 маркеров (то есть 88 сессий Маяка не разбирал никто).

⚠️ **ИСКЛЮЧЕНИЕ, найдено 10.09.2026 (хаб, прогон ночной догонялки): проекты `ssh-*` видны ДВУМ
узлам.** Сессия `b1398d37` работала на Маяке в `/root/Obsidian/…`, а её транскрипт лежит на хабе
в проекте `ssh-b1398d37-…`, потому что ssh-сессию открыли отсюда. Маяк разобрал её 23.08 и
поставил СВОЙ локальный маркер, хаб об этом маркере не знает и получил её в очередь снова
17 дней спустя. Значит утверждение «два узла не подерутся» верно для обычных проектов и НЕВЕРНО
для `ssh-*`: там от дубля спасает только RECALL (шаг 2), поэтому у кандидата с проектом `ssh-*`
RECALL по слову из первого промпта в `01-Conversations/Claude/Retros` обязателен ДО разбора, а не
после. Строка класса в журнале: `ssh-sessii-vidny-dvum-uzlam-dedup-tolko-recall`.

**Какой профиль сейчас работает — говорит РУТИНА, а не хостнейм.** Гейт явный: сид рутины
пишет «профиль ПИР-ЛАЙТ» или «профиль ХАБ-ПОЛНЫЙ». Нет строки профиля в сиде → ПИР-ЛАЙТ
(безопасный дефолт: дешевле и ничего не пишет в канон), но **ВСЛУХ**: первая строка отчёта =
«⚠️ профиль не назван в сиде → взял ПИР-ЛАЙТ». Молчаливый дефолт = тихая деградация хаба, если
строка профиля из его сида когда-нибудь пропадёт (находка панели ломателей 22.08, Grok #1).
⛔ Не угадывать профиль по hostname — неизвестный узел молча получил бы дорогой профиль.

| | ХАБ-ПОЛНЫЙ (`auto-hub-260811-retro-lost-nightly`) | ПИР-ЛАЙТ (каждый узел) |
|---|---|---|
| объём | 10 единиц/ночь | **10 единиц/сутки** (anton 02.09: «оставил бы десять»; было 5) |
| шаги 0, 0-бис, 1, 2, 3 | да | **да, без урезания — RECALL полный** («полное реку») |
| 4 контрибьют-тест | да | ⛔ нет |
| 5 тесты панелью ломателей | да | ⛔ нет (панель — хабовая рельса) |
| 6 docstring-паспорта | да | ⛔ нет (правка чужого кода = не задача лайта) |
| 7 хвост → карточка | да | да |
| 7-бис сессия-копатель | да | ⛔ нет — только карточка со ссылкой на sessionId |
| 8 заметка + mark-done | да | да |
| 9 личинка спотыканий | да | ⛔ нет (shadow хаба) |
| модель | Opus | Opus (вердикт уезжает в библиотеку = суждение, §6.2) |
| рельса | подписка узла | **подписка ЭТОГО узла** — на пирах баки простаивают, §6.3 «жги оплаченное» |

**Что лайт НЕ режет:** RECALL (иначе получаем пересказ старья — та самая опасность №1),
проверку судьбы артефакта по реестру и git, честное «🤔 гипотеза» без улики.

### Имя файла заметки лайта — с КЛЮЧОМ УЗЛА, иначе sync-conflict
`01-Conversations/Claude/Retros/retro-lost-<ГГГГ-ММ-ДД>-<MACHINE_KEY>-<слаг>.md`.
Причина: волт общий на 6 узлов, у всех своя пятёрка потеряшек в один день; имя без ключа узла
= драка Syncthing за файл (три ломателя из трёх назвали это первым риском 22.08).
То же для карточек `10-Tasks`: слаг несёт узел. Хаб пишет как раньше (его имя уже уникально).

### Ветка «это была КНИГА / длинный текст» (anton hub:5699)
Дословно: «может, книгу даже не дописали нужную… это была важная книга, нужно хотя бы сделать
саммари, о чём она была, и поставить точку… и сложить в нашу гигантскую библиотеку, возможно
эти куски книги понадобятся». Признак: сессия писала главы/лонгрид/книгу и оборвалась.
Действие лайта: ⛔ не дописывать. Саммари «о чём это было + где куски лежат + почему встало»
+ точка с запятой (что нужно, чтобы продолжить) → в библиотеку волта, и строка в отчёте.
Механизм для этой ветки держит сессия-сестра `auto-hub-260822-lost-retro-decentralized-scale`
(голосовая hub:5699) — если она уже отдала прибор, лайт зовёт ЕГО, а не изобретает свой.

### Границы лайта (сверх общих)
- ⛔ Не писать в канон-дома (CLAUDE.md, Библия, MEMORY.md) — правило из чужой брошенной
  сессии проходит через хаб; лайт только кладёт заметку и карточку.
- ⛔ Узел коллеги разбирает СВОИ сессии; чужое личное в общий волт не выносить (обобщённо).

  ночью спят»). Слот выбирает узел под своего человека, не хаб.
