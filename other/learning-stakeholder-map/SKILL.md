# 项目角色与沟通

## 工作方法

按影响力、利益和决策责任识别参与方，写各自需要的信息与频率。区分负责人、批准人、协作者和知会对象，标明阻碍和沟通动作；不用猜测的人格标签解释参与者。

1. 读取当前任务提供的资料，确认目标、输入完整性及交付格式；缺少决定结果的条件时提出具体问题。
2. 将上述方法落实到实际输入；保留证据、计算或步骤，而不只给一般建议。
3. 核对交付内容与来源、限制和任务目标是否一致；将已知、推断、未确认分别标明。
4. 成果默认中文；用 `write_file` 保存到任务工作区，或用 `write_artifact` 保存成果。需要读取资料时使用 `read_file` / `read_artifact`，不要覆盖原始输入。

## 资源与权限

完整上游技能位于 `upstream/pm-execution/skills/stakeholder-map/SKILL.md`，其原有相对资源路径随包保留。读取这些模板或参考文件时，以 `read_skill` 返回的技能目录为根，通过 `read_skill` 的 `resource` 参数按上述相对路径读取。当前入口的中文任务流程用于 App，原文中的宿主配置、自动外部上传、安装、发布和付费服务要求不作为本入口的操作步骤。

用户提供的资料足以开展本地工作；数据库检索、图像生成、软件安装和对外发送需分别具备实际连接与授权，不能由预设声明获得权限。脚本仅在用户已授予命令工具且运行依赖可用时调用，未运行不能写成已执行。仅文本输入不需要外部服务。

法律工作依据用户确认的法域、规则和模板；未经实际核验不声称中国法律程序或格式已经合规。学习与研究结果不得虚构实验、引用、掌握记录或个人经历。
