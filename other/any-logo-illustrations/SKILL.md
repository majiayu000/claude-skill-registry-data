# logo 醬手繪配圖

## 核心定位

把專案的 logo 本身變成一個會做事的角色，用它來解釋內容裡的關鍵判斷、流程、結構、狀態或隱喻。目標不是商業插畫、PPT 資訊圖或可愛卡通，而是一張清爽、有記憶點、讀得懂但不像說明書的手繪解釋圖。

視覺 IP 叫 **logo 醬**。牠的身體就是 logo，長出手腳與表情，認真做一件荒誕但成立的事。logo 醬必須參與畫面的核心動作，不能只是站在旁邊當裝飾，而且是整張圖唯一的彩色物件。

## 動筆前先讀專案設定

`references/logo-chan.md` 的「專案設定」那一節決定四件事，每個專案只改那一節：

1. **logo 檔**——要餵給圖像模型的參考圖，必須是無文字版
2. **擬人化配方**——`character-recipes/` 裡選一個，整批圖只用同一個
3. **logo 主色**——決定批註要避開哪個色系
4. **批註色**——不可與 logo 主色同色系

沒讀這一節就開始生圖，會撞色或用錯配方。

## 身體不用文字描述

**不要在提示詞裡描述 logo 長什麼樣。** 把 logo 檔當參考圖餵進去就好。

這是實測結論：文字描述撐不住外形，描述得越細，模型越容易在幾種錯誤解讀之間擺盪，而且每次方向不同。改餵參考圖之後一次到位。提示詞裡關於身體只留一句「身體就是參考圖那個 logo」，其餘交給參考圖。

## 兩種模式

動筆前先決定用哪一種。**預設是怪誕正文模式**，只有使用者明說要做論文圖、方法架構、實驗設計或投影片圖解時，才切到學術圖解模式。

| | 怪誕正文模式（預設） | 學術圖解模式 |
| :--- | :--- | :--- |
| 適用 | 文章正文配圖、部落格、社群貼文、機構對外宣傳 | 論文插圖、計畫書圖解、簡報投影片、內部會議 |
| 禁流程圖／架構圖 | 是 | 否，允許方法架構、實驗設計、資料流 |
| 節點上限 | 不畫節點圖 | 5–7 個 |
| 白底、手繪、留白 | 必須 | 必須 |
| logo 醬動手做事 | 必須 | 必須 |
| 漸層、陰影、向量風、實照 UI | 禁 | 禁 |

模式判斷不確定時，問使用者一句，不要自己猜大的。

## 畫面比例

| 用途 | 比例 |
| :--- | :--- |
| 文章正文配圖、投影片 | 16:9 |
| 社群貼文 | 1:1 |
| 論文圖（單欄） | 3:2 |
| 論文圖（雙欄跨欄） | 4:3 或 1:1 |

沒指定用途時預設 16:9 橫版。

## 先讀這些參考

依任務需要讀取，不要一次塞滿脈絡：

- `references/logo-chan.md`：logo 醬的定義、專案設定、批註配色避讓表、識別要件。**每次都要讀。**
- `references/character-recipes/`：擬人化配方。依專案設定選一個讀。
- `references/style-dna.md`：風格 DNA、顏色、比例、兩種模式的邊界、禁忌。
- `references/composition-patterns.md`：結構型、學術圖解專用結構型、原創隱喻方法、防重複規則。
- `references/prompt-template.md`：單張生圖提示詞範本，含必帶的 IP 描述區塊。
- `references/qa-checklist.md`：生成後檢查與迭代規則。
- `logo/`：logo 原始檔。挑無文字版餵參考圖。
- `assets/examples/`：已產出的圖，只作低頻視覺校準，不進入預設生成路徑。不要照抄構圖、物件或批註。

## 工作流程

### 1. 消化內容

先讀使用者給的正文、連結、Markdown 檔、論文草稿或擷圖內容。提煉：

- 核心觀點是什麼
- 哪些段落承擔認知轉折
- 哪些內容適合用圖解釋
- 哪些地方只適合文字，不需要圖

不要平均配圖。優先選「認知錨點」：核心判斷、兩個斷點、輸入輸出循環、分流、前後對比、承接路徑、常見坑、角色狀態變化。

論文與計畫書則優先選：方法整體架構、關鍵模組的運作機制、實驗設計的對照關係、資料處理管線、本方法與既有方法的差異點。

### 2. 先出配圖策略

如果使用者只是說「分析怎麼配圖」，先給 shot list。每張圖寫清楚：

- 放在哪個段落或哪一節後
- 圖的主題
- 核心意思
- 用哪種模式
- 結構型
- 比例
- logo 醬在圖裡做什麼
- 建議元素
- 建議正體中文批註詞

預設 4–8 張。內容很短時 1–3 張；長文也不要輕易超過 9 張。

### 3. 單張生成

如果使用者明確要求「生成／輸出／做圖」，不要停下來等確認；用內建 `image_gen` 每張單獨生成。不要把多張圖拼在一張裡。

**每次都要把專案設定指定的 logo 檔當參考圖一起送出。**

每張圖只講一個核心結構。提示詞必須包含：

- 指定比例
- 純白背景、黑色手繪線稿、大量留白
- IP 描述區塊（照 `prompt-template.md` 帶上，身體只說「就是參考圖那個 logo」）
- 選定配方的提示詞片段，並填入這張圖的視線或姿態目標
- logo 醬作為核心動作主體，且是畫面唯一的彩色物件
- 依專案設定的批註色，少量正體中文手寫批註
- 明確要求所有文字為正體中文，禁止簡體字
- 依模式帶上對應的模式約束句
- 禁止在圖裡出現 logo 上的機構名稱或字環文字

一批圖之間不要重複隱喻。生第二張以前，先回頭看前面用過什麼物件和動作，避開它們。

### 4. 檢查與迭代

生成後照 `references/qa-checklist.md` 檢查。優先重生成或局部編輯的狀況：

- 角色跟 logo 原檔並排認不出是同一個東西
- 專案設定列的識別要件掉了（鏤空、內部分割、某個小元素）
- logo 醬只是裝飾
- 畫面其他物件也被上了色
- 批註色跟 logo 主色撞色
- 圖上出現簡體字，或出現 logo 的機構名稱
- 畫面太滿、太像流程圖或 PPT（怪誕正文模式下）
- 跟同一批的其他圖撞了隱喻

走形與簡體字用 `prompt-template.md` 裡對應的局部編輯提示修，不要整張重生成。

### 5. 儲存交付

把最終圖存到 `assets/examples/`，依序命名 `01-主題名.png`、`02-主題名.png`。保留原始生成檔，不要覆蓋既有資產，除非使用者明說要替換。

## 輸出口徑

生成前的策略輸出要短而準。生成後的交付要包含：生成了幾張、每張圖的用途、儲存路徑、哪些圖最穩哪些是可選。不要長篇解釋風格理論。

## 語言

所有輸出、圖上文字、批註、檔名一律使用臺灣正體中文，禁止簡體字與支語用詞。「臺」不寫成「台」（「平台」一詞例外）。「示例」一律寫「範例」。
