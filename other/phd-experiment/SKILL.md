# 实验设计与结果登记

先读取 [本地操作约定](../phd-manager/references/local-workflow.md)，列出项目、论文和实验，取得已有记录与关联 ID。

## 设计实验

从研究问题提取可证伪假设、操纵/比较因素、对照或基线、样本/数据来源、主指标、评价条件以及失败判定。依学科决定是否需要功效分析、重复测量、随机化、盲法、数据划分或消融，不把计算实验模板强套给所有研究。

将可执行方案写入 `hypothesis`、`method`、`metric`、`baseline`；更长方案保存为文件并填入 `artifactPath`。用户尚未给定的预算、样本数和预期效应标为待定。新方案使用 `status: "planned"`、`origin: "ai"`；计划任务可关联 `experimentId`。

## 运行与登记

- “计划运行”仍是 `planned`；用户明确报告或工具实际启动了运行才可设为 `running`。执行实验需具备用户授权、现有环境与运行入口，不能因为本 skill 被调用就宣称后台实验正在运行。
- 登记现成结果时，先读取用户提供的结果文件、日志或明确陈述；保留指标单位、数据集/样本范围、对比基线、运行设置、实际时间和已知异常。文件不存在或打不开时不能说已核验。
- `result` 写可被材料支持的观测；`evidence` 写来源位置与核验范围。只有同时具备真实结果和证据时才设为 `completed`。用户口述可记录为“用户报告，未独立复核”，不能伪称亲自运行。
- 启动失败、缺资源或等待依赖可设为 `blocked`，在 notes 中写原因与下一项解除条件。失败和负结果同样是有效记录，不得删除以改善结果。
- 生成图表、统计或比较时沿用原始数据与计算结果，保留处理方法。尚未实施统计检验时不写显著性结论。

## 完成

通过 CLI 保存并回读。汇报方案/结果存放位置、实际执行到哪一步、支撑结论的证据与仍待验证的问题。更新关联论文的 `experimentIds` 时保留已有元素；实验完成不会自动让论文或任务全部完成。
