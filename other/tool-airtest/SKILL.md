# Airtest跨平台游戏与应用UI自动化 技能卡

## 基本信息

- **中文名称**：Airtest跨平台游戏与应用UI自动化
- **来源仓库**：[AirtestProject/Airtest](https://github.com/AirtestProject/Airtest)
- **上游参考分支**：`master`
- **参考提交（使用前核对）**：`d729c631d2032521be1e2168a249a2a89d79af2a`
- **许可证线索**：Apache-2.0；文件：`源码\LICENSE`

## 功能概览

1. 基于图像识别定位界面元素并执行点击、滑动、文本输入等设备动作
2. 通过 Python/命令行编排设备连接、应用安装与启动，以及脚本回放
3. 提供断言、截图、录屏和 HTML 步骤报告，便于失败定位

## 适用范围

- 用于模拟器或 Android/Windows 游戏的界面状态识别、后台操作编排、回放和证据采集；适合放在 UI 采集/动作层。

## 不能替代的边界

- 不解析 IL2CPP 元数据，不定位 native 函数、指针链或 ABI；不提供游戏状态真值、服务端回执、网络协议重放、崩溃守护和 AI 策略证明。图像匹配成功不等于动作被游戏接受。

## 输入与输出合同

```text
输入：设备连接信息、应用包名/窗口、模板图像或 Poco 选择器、动作序列、超时与断言条件。
输出：动作执行日志、截图/录屏、断言结果、HTML 报告和失败步骤证据。
失败：设备不可达、模板未匹配、控件不存在、动作超时或断言失败时返回失败并保留原始现场。
后置：输出必须绑定项目、目标版本、平台/ABI（如适用）、时间戳和证据路径。
```

## 接入原则

1. 核对实际源码版本与说明中的参考提交后，先做最小、可撤销、可回放的接入。
2. 任何地址、线程、设备、模型、资源或协议输入都必须记录来源、版本和后置状态。
3. 工具输出是候选或观测，必须与项目专项规则、状态机和真实成功证据交叉验证。
4. 失败时保留原始错误和现场证据，不把命令退出码、识别命中或 Hook 安装当作业务成功。
5. 与 MuMu/ADB、OpenCV、PaddleOCR、uiautomator2 可组成采集和 UI 层；不能替换项目的 IL2CPP、状态机或生命周期守护。

## 与 Codex 项目路由的边界

- `l-gameassist`：负责游戏目标、进程/设备连接和现场任务编排；本技能只提供本卡标注的工具能力，不能扩展为未登记的内存、Hook、协议或输入能力。
- `l-reverse`：负责逆向/静态或运行时证据路由；本技能的输出必须按目标版本、模块、ABI 和现场回读复核，不能把候选分析直接当作成功结论。
- `l-dev`：负责构建、依赖、配置、部署、回滚和服务维护；本技能不替代发布门禁，未完成依赖、许可证、异常恢复和回滚检查时不得发布。
