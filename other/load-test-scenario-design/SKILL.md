# 压测场景设计Skill

## 适用场景
性能压测环节,基于容量目标与真实流量模型设计五类压测场景,输出可执行的压测方案。

## 执行步骤
1. 明确目标:业务容量目标(QPS/并发)、指标目标(响应时间/错误率/资源水位)、验收判定标准。
2. 梳理流量模型:基于生产监控或线上真实数据确定接口调用占比、读写比、数据量级,禁止拍脑袋定比例。
3. 设计五类场景:
   - 基准测试:低并发单接口摸底,获取单机基准指标,作为后续场景的对照。
   - 负载测试:按预期流量逐步加压至目标值,验证目标水位下各项指标达标。
   - 峰值测试:按真实峰值系数(通常目标值 1.5-2 倍,以实际数据为准)短时冲击,验证削峰与保护能力。
   - 稳定性测试:目标负载持续 8-24 小时,观察内存/连接泄漏与指标慢增长。
   - 瓶颈探测:阶梯加压直至指标劣化,定位瓶颈所在层,为扩容/调优提供数据。
4. 逐场景定义参数:并发曲线、时长、数据量、监控指标、判定标准。
5. 输出场景设计文档与执行计划,同步确认回滚预案。

## 规范要点
- 场景参数必须来自真实业务数据(峰值系数、业务配比),引用数据标注来源与采集时间。
- 压测前四确认:环境与生产隔离、数据脱敏或独立造数、监控采集就绪、回滚预案就位。
- 结果如实呈现:指标未达目标必须如实记录,不得通过放宽指标或挑选好数据重测来掩盖问题。
- 未执行的场景必须标注「未执行」及原因,不得省略后宣称压测完成。
- 具体压测工具的脚本语法与参数以官方文档为准。

## 输出模板
```
## 压测场景设计
| 场景类型 | 目标 | 并发 | 时长 | 加压曲线 | 数据量 | 判定标准 |
## 流量模型说明(业务配比/峰值系数及数据来源)
## 执行计划(顺序/环境/数据准备/监控项)
## 回滚预案
```

## 自检清单
- [ ] 五类场景齐备且目标与判定标准明确

- [ ] 判定标准可量化
- [ ] 环境隔离与数据准备方案明确
- [ ] 有回滚预案
