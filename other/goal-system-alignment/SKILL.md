# goal-system-alignment

## When to Use

当设定新目标或检视现有目标时，确保目标能通过高效的行为系统自动达成description

## Core Logic

# 执行步骤

1.  **目标澄清与分解**：将抽象或宏大的目标转化为清晰、具体、可衡量的子目标或里程碑。
    *   **输入**：一个希望达成的目标（如“掌握一门新技能”、“实现职业转型”）。
    *   **判断标准**：目标被分解为一系列按逻辑或时间顺序排列的、可执行的小任务或阶段成果。
    *   **输出**：一份目标分解清单或路线图。
    *   **常见误区**：目标过于模糊（如“变得更好”）；分解后的任务仍然不可执行或不可衡量。

2.  **系统缺口分析**：对比“达成目标所需的行为系统”与“个人现有的行为系统”，找出缺失或薄弱环节。
    *   **输入**：步骤1的目标分解清单，以及对个人现有习惯、技能、资源（时间、精力、知识）的认知。
    *   **判断标准**：能够明确指出为了完成每个子目标，当前缺少哪些具体的习惯、技能、知识或资源。
    *   **输出**：一份系统缺口清单，列出缺失的组件（如“每日练习30分钟的习惯”、“XX专业知识”、“一个反馈渠道”）。
    *   **常见误区**：高估现有能力，忽视基础技能的缺失；只关注知识缺口，忽视习惯或环境等系统要素。

3.  **设计反馈机制**：为每个需要建立或加强的系统组件（尤其是行为习惯）设计即时、清晰的反馈回路。
    *   **输入**：步骤2输出的系统缺口清单，特别是与重复性行为相关的部分。
    *   **判断标准**：为每个关键行为定义了明确的完成标志（输出），并设定了检查频率和调整规则。
    *   **输出**：一套针对关键系统组件的反馈规则（例如：“每日写作后，记录字数和主观难度评分；每周回顾，若连续三天评分>7，则增加字数目标”）。
    *   **IF** 缺口是知识类，**THEN** 反馈机制可以是“测试-纠正”循环。
    *   **IF** 缺口是行为习惯类，**THEN** 反馈机制必须是“执行-记录-回顾”循环。
    *   **常见误区**：反馈延迟过长，无法及时调整行为；只有负面反馈（惩罚），缺乏正面反馈（奖励）；反馈指标与最终目标关联度低。

4.  **嵌入现有系统**：将新设计的目标子系统与个人生活中稳定运行的现有系统（如每日作息、工作流程）进行绑定或整合。
    *   **输入**：步骤3设计的反馈机制，以及对个人现有日常流程的了解。
    *   **判断标准**：新系统的触发点（何时开始）被明确锚定在某个现有日常活动之后或之前。
    *   **输出**：一个明确的“如果-那么”执行计划（例如：“如果每天早晨喝完咖啡，那么我就打开编程教程学习25分钟”）。
    *   **常见误区**：新系统完全独立于现有生活节奏，难以启动和维持；绑定点选择不当（在精力耗尽时安排高难度任务）。

# 输出格式要求
输出应包含以下部分：
1.  **目标分解图**：展示主目标到可执行任务的分解结构。
2.  **关键系统缺口**：列表形式，说明缺失什么及为何关键。
3.  **核心反馈回路设计**：描述1-2个最重要的反馈机制是如何运行的。
4.  **系统嵌入计划**：给出将新行为嵌入日常的具体“如果-那么”语句。
