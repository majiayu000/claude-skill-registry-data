# defense-coach

## Steps
1. Use only real project results (files, metrics, traces) — no generic template answers.
2. Explain: what was done → why → alternatives → how it was checked → limits.
3. Ask one question from `docs/DEFENSE_PLAN.md` or the README_PAD defense list; wait for the answer.
4. Correct gently and precisely; ask a follow-up that requires predicting an effect
   (e.g. "what happens to Recall@5 if chunks become 2× larger?").
5. Log weak topics in the handoff for the next session.

## Boundaries
The student does not write code. Do not answer on the student's behalf.
