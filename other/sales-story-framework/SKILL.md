# sales-story-framework

## When to Use

当需要设计说服性内容（如销售文案、演讲、提案）时description

## Core Logic

# 执行步骤

1.  **定义问题**
    *   **输入**：目标受众画像、市场观察。
    *   **操作**：清晰描述目标受众正在面临的一个具体、可感知的问题或挑战。
    *   **判断标准**：受众是否能立即认同“对，这正是我遇到的麻烦”。
    *   **输出**：一个精准的痛点陈述。

2.  **放大影响**
    *   **输入**：已定义的痛点。
    *   **操作**：阐述如果该问题持续存在，将对受众的生活、工作、情感或目标产生何种负面后果（放大痛苦）。
    *   **判断标准**：是否让受众感受到解决问题的紧迫性和必要性。
    *   **输出**：对问题后果的生动描述。

3.  **引入方案**
    *   **输入**：放大后的痛点、你的产品/服务/观点。
    *   **操作**：将你的产品/服务/观点作为解决上述问题的直接方案推出。清晰说明其核心功能或主张。
    *   **判断标准**：方案是否看起来是针对前述问题的合理且直接的答案。
    *   **输出**：与痛点紧密关联的解决方案陈述。

4.  **提供证明**
    *   **输入**：解决方案陈述。
    *   **操作**：提供证据证明该方案有效。可以是客户见证、案例研究、数据结果或个人成功经验。
    *   **判断标准**：证据是否可信，能否降低受众的怀疑和风险感知。
    *   **输出**：增强方案可信度的证据。

5.  **号召行动**
    *   **输入**：已被说服的受众（处于信任状态）。
    *   **操作**：给出一个极其简单、明确、无摩擦的下一步指令（如“点击购买”、“预约通话”、“下载指南”）。
    *   **判断标准**：行动指令是否清晰到不容误解，且执行路径简短。
    *   **输出**：一个明确的行动号召（CTA）。

# 输出格式要求
按照“问题 → 影响 → 方案 → 证明 → 行动”五步结构，生成完整的说服性文案或演讲提纲。
