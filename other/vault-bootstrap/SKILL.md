# Vault Bootstrap

Build the smallest structure that supports the user's real work.

## Workflow

1. Inspect an existing directory before proposing migration.
2. Interview one high-impact question at a time using [references/onboarding-interview.md](references/onboarding-interview.md).
3. Record purpose, success criteria, information types, retrieval and output needs, privacy boundaries, tools, naming, and maintenance capacity.
4. Choose an architecture using [references/architecture-options.md](references/architecture-options.md).
5. Apply personalization rules from [references/personalization-rules.md](references/personalization-rules.md).
6. Present the proposed folders, files, reason for each, and migration impact.
7. If writes are authorized, create only needed directories and adapt files from [assets/minimum-vault](assets/minimum-vault). Read back the result.
8. Run one low-sensitivity intake example and verify retrieval and update behavior.

Never infer permission to import, publish, delete, or reorganize existing material.
