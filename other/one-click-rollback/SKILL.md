# 一键回滚执行Skill

## 适用场景
发布后故障,按预案执行版本回滚,快速恢复服务。

## 执行步骤
1. 判定触发:对照回滚预案的触发条件(错误率/功能不可用/数据异常),确认回滚必要性。
2. 上报确认:生产回滚按预案授权执行;预案外操作先上报主Agent/总控。
3. 执行回滚(按优先级):
   - 配置回滚:切回上一版本配置(最快)。
   - 代码回滚:镜像/制品回退到上一版本 tag,流量切回。
   - 数据补偿:涉及数据变更时,评估是否需要补偿脚本(谨慎,先备份)。
4. 恢复验证:核心链路冒烟 + 指标观察(错误率/延迟恢复正常)。
5. 记录:回滚原因、动作、耗时、验证结果,输出回滚报告。

## 规范要点
- 先止损后归因:回滚期间不做根因分析,恢复优先。
- 回滚动作必须来自预案或经审批,禁止现场即兴改配置。
- 数据类回滚最危险:能不动数据就不动;必须动时先备份、双人复核。
- 回滚后保留现场(日志、指标快照、上一版本制品)供复盘。
- 回滚完成 ≠ 结束:必须输出复盘报告(根因、改进、防止复发)。

## 输出模板
```
## 回滚报告
触发原因 / 回滚动作 / 耗时 / 恢复验证数据 / 现场保留清单 / 复盘结论
```

## 自检清单
- [ ] 触发判定有依据
- [ ] 动作符合预案或经审批
- [ ] 恢复验证通过
- [ ] 现场已保留、复盘已输出
