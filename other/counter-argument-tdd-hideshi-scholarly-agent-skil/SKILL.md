# 反論・反証駆動執筆スキル (Counter-Argument TDD)

## 目的
テスト駆動開発（TDD: Red ➔ Green ➔ Refactor）の規律を文章執筆に応用し、論文の本文を書く前に「どのような批判・反論・反証事例が考えられるか」を先にテストケースとしてリスト化し、それを乗り越える論証を執筆することで、査読や批判に強い論文を作成する。

## 発動タイミング
- 各節・パラグラフの執筆を開始する前
- 新しい論点・主張を構築する際

## 処理サイクル

```text
[1. 想定反論の記述] ➔ [2. 反論克服執筆] ➔ [3. 推敲・論理洗練]
```

### Phase 1: 想定反論の記述
節やパラグラフを執筆する前に、`docs/design/test-cases.md` に想定反論・懸念点を記述する。

反論リストの作成には、以下の**段階的対話パターン**（[認知スキャフォールディング原則 S4](../../../rules/ja/cognitive-scaffolding-rule.md) 準拠）を採用する：

1. まずエージェントが1つの反論候補を提示し、「この方向の反論はありえますか？」と問う。
2. ユーザーが応答したら、次の反論軸を1つ提示する。
3. 定型チェック（異質性チェック・数値解釈チェック）を順に1つずつ確認する。
4. 「他に思いつく反論はありますか？」とオープンに聞くのは**最後**にする。

記述フォーマット：

```markdown
## 節: 第3章第2節「17世紀における流通経済の変容」
- [ ] **反論1 (Counter-Argument)**: 「同時代の農村部では依然として自給自足的交換が主流であったのではないか？」
- [ ] **反論2 (Exception Source)**: 「史料Aの記述は特定の都市特有の現象に過ぎないのではないか？」
```

#### 1. 異質性チェック（Heterogeneity Check & 証跡必須化）
反論リストの作成時、以下の定型チェックを必ず実施する：
- **「この分析対象の集団・カテゴリを均質に扱うことへの反論はないか？」** を自問する。
- 分析対象が社会集団（労働者、移民、受給者等）である場合、スキル階層・地域・ジェンダー・世代等の内部分化に関する反論を**最低1件リストに列挙するか、非該当の理由（例: 「純粋概念分析のため対象外」）を `docs/design/test-cases.md` に明記**しなければならない。
- *※本チェックは [claim-evidence-gate](../claim-evidence-gate/SKILL.md) の `Internal Heterogeneity` 軸の事前検証として機能する。*

#### 2. 数値解釈反論チェック（Data Re-Interpretation Check）
統計数値の変化や比較数値を主張に用いる場合、以下の汎用3軸の反論を検討し、該当するものをテストケースとして `docs/design/test-cases.md` に追加する：
- ① **変化のペース・弾力性（Pace & Elasticity）**: 背景指標（マクロGDP等）の大きな変化に対して、数値の改善速度が緩慢すぎないか。（例: 高成長に対する不平等改善の遅さ）
- ② **絶対水準の評価（Absolute Benchmark Evaluation）**: 数値変化後の到達点自体が、なお国際的・学術的・臨床的な警戒線（閾値）を実質的に超過していないか。
- ③ **変化の構成要因分解（Factor Decomposition）**: 数値変化の主因が一次市場所得の構造的改善か、一時的な政策財政移転（4Ps給付等）や測定手法の改定によるものか。

#### 3. 派閥チェック（Faction Check）
反論リストの作成時、`docs/<paper-id>/literature/literature-matrix.md`（単一論文リポジトリでは `docs/literature/literature-matrix.md`）の係争ステータス列を確認し、以下を実施する：
- `contested` / `contradicted` の文献・命題に依拠した主張がある場合、**対立陣営の代表文献からの反論を最低1件**テストケースとして列挙する。
- 係争ステータスが `unknown` のままの屋台骨主張がある場合、`literature-search` Step 1.5（対立陣営探索）への差し戻しを検討する。

通時的論文では、チェリーピッキング（断面選定）、アナクロニズム（造語概念の過去への読み込み）、伝播証拠の欠如を、未列挙なら追加する（[`diachronic-claim-typing`](../diachronic-claim-typing/SKILL.md)）。

*※本チェックは「想像の反論」を「実在の反論」で補強し、[claim-evidence-gate](../claim-evidence-gate/SKILL.md) の `Field Disagreement` 軸の事前検証として機能する。*

### Phase 2: 反論を包摂・克服する本文執筆
AIと共同で本文を記述する際、上記で定義した反論リストを一つずつクリアするように文章を構成する：
- 農村部の例外に言及し、「本稿の議論は都市部に限定される」と範囲を明記する。
- 史料Aだけでなく史料B・Cとの比較を加え、地域的偏りを補正する。
- クリアした反論にチェックを入れる。

### Phase 3: 推敲・論理洗練（トピックセンテンス・主旨明示）
すべての反論がカバーされた後、段落冒頭に結論・主張（トピックセンテンス）を配置し、接続詞や論理展開を自然で流暢な学術文体（常体「である」「解釈される」）へと推敲する。

## ⚠️ 出力境界規律（Output Boundary Rule）
本スキルおよび本説明書内で用いる内部管理用語（TDD, Red, Green, Refactor, テストケース, Phase, フェーズ等）は、**エージェントの処理規律および `docs/design/test-cases.md`（内部設計文書）内でのみ使用する**。

- 論文本文（`docs/chapters/` 配下のファイル）に出力するテキストには、これらの内部用語やメタファー表現を**一切含めてはならない**。
- 本文の見出し・段落には、純粋な学術的表現（例:「想定される反論に対する検討」「統計要因説に対する実証的検証」等）のみを使用する。
