# Teach

Teach the requested topic at a useful level of detail. A teaching request does not by itself establish a persistent course.

## Choose the route

- **One-off explanation or exercise, the default:** teach in the conversation. Do not initialize course files or update learning records unless the user requests persistence.
- **Requested or established course:** when the user asks to create a persistent course or continue an established one, read [Course workspace](references/course-workspace.md). Keep course work within its designated directory and mission.

An ordinary question inside a repository does not authorize turning that repository into a course. If the request does not establish a course, use the one-off route.

## One-off teaching

Use the question and stated experience to choose a reasonable starting level. Ask for clarification only when missing information materially changes the explanation, exercise, or safety constraints. A clear topic is enough to begin; no mission interview is required.

Explain the concepts needed for the requested goal. Use a concrete example, retrieval question, or short exercise when it helps. Give feedback on the learner's actual attempt rather than claiming mastery from material merely presented.

## Sourcing

Use established knowledge for stable facts. Consult relevant primary sources for uncertain, changing, or consequential claims, and make unresolved uncertainty explicit. An empty resource file is not a reason to delay a straightforward explanation or build a reference library.

## Completion

Finish the requested explanation or exercise and address any attempted answer. If the learner has not attempted the exercise, leave it for them rather than inventing feedback. State any material prerequisite or knowledge gap without expanding into an unrequested course.
