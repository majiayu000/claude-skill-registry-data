# CHE_skill-regression-check — Проверка исправления навыка

Основа из архивного heal — одинаковые входы до и после изменения. Это проверка поведения инструкции, а не обучение весов модели.

1. Установи точный навык, его исходную поддерживаемую папку, версию и наблюдавшуюся ошибку. Прочитай инструкции и только относящиеся к сбою ресурсы. Не меняй установленный кеш плагина вместо исходного пакета. Если исходник не найден, подготовь локальный diff и обозначь установку как незавершённую.
2. Сохрани исходную версию или diff для возврата. В отдельной папке проверки зафиксируй реальные обезличенные входы и ожидаемое наблюдаемое поведение. Добавь несколько релевантных граничных случаев и случай, где навык вообще не должен применяться. Число случаев определяется риском, а не универсальным N=10.
3. До изменения выполни доступные безопасные прогоны. Для каждого запиши вход, версию навыка, фактический выход, критерий, вердикт и доказательство. Мысленный разбор обозначай «статический разбор», запуск валидатора — «проверка структуры», исполнение сценария — «поведенческий прогон». Не подменяй одно другим.
4. Отдели ошибку инструкции от отсутствия доступа, сбоя инструмента, неполных данных и неверного ожидания. Исправляй только подтверждённую причину. При изменении SKILL.md используй доступный skill-creator и его проверку структуры.
5. Повтори те же случаи при сопоставимых условиях. Где возможно, добавь новый случай, не использованный при правке. Отрази улучшения и регрессии по каждому критерию. Один успех не доказывает надёжность; проценты считай только по фактически выполненным случаям.
6. Если изменение ухудшило обязательный сценарий, исправь или верни только собственную правку. Не удаляй проверки данных и доступов ради сокращения времени. Сообщай ускорение только при измеренных сопоставимых затратах; при отсутствии метрик пиши «не измерено».

Для внешних сервисов предпочитай фикстуры или тестовую среду. Прогон не даёт нового разрешения на рассылку, публикацию, изменение CRM, расходование платного API или запись памяти. Учитывай уже разрешённый объём, не запрашивая его повторно. Если воспроизведение требует отсутствующего разрешения, закончи безопасную часть и точно назови непроверенное.

Останови цикл после исправления и релевантных проверок; если прогресса нет, сообщи причину, не запускай бесконечное «самолечение». Итог: причина → правка → реальные результаты до/после → непроверенное → исходник и состояние установки. Не объявляй публикацию новой версии плагина выполненной на основании локального diff.
## Среда и входы

Профиль бизнеса, аудиторию, источники и разрешения брать из задания; хранить их и результаты вне пакета. Методолог навыка не становится автором материала автоматически. Использовать только объявленные инструменты. Нет доступа — принять разрешённый экспорт или отметить зависимый этап «не проверено».

Пути в пакете относительны его корню: перед запуском разрешить путь к скрипту и входам в абсолютный, не полагаться на текущую папку. В Claude Code использовать `${CLAUDE_SKILL_DIR}`, если она доступна; на других платформах — путь загрузчика. Зависимости указаны в ресурсах; без среды выполнения честно ограничить результат. Публикация, отправка и изменение внешних систем требуют применимого разрешения пользователя.
