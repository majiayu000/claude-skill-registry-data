# journal — журнал для итогового отчёта

Отчёт курса требует: разбиение на задачи, что доработано руками и почему, какие MCP и скиллы использовались, какие модели на каких задачах, отчёт независимого проверяющего. Журнал копит это по ходу, чтобы не восстанавливать по памяти в декабре.

## Шаги

1. Собрать факты из текущей сессии и `git log --oneline` с момента последней записи журнала.
2. Дописать запись **в конец** `docs/report/journal.md` (создать файл с заголовком `# Журнал разработки`, если его нет). Прошлые записи не менять.
3. Пункт «Руками» не выдумывать: если из сессии непонятно, что человек правил сам, — написать `уточнить у автора` и спросить пользователя одним вопросом.

## Шаблон

```markdown
## 2026-09-20 — T-007 / REQ-012 move×move

- **PR / коммиты:** #14 (a1b2c3d, d4e5f6a)
- **Модели:** Opus 5 — реализация; Sonnet 5 — test-author
- **Скиллы:** implement-req, crdt-op
- **Агенты:** test-author
- **MCP:** Playwright (проверка синхронизации в двух вкладках)
- **Что сделал агент:** слияние перемещений, генератор move в arbitraries
- **Руками:** поправил дробный индекс при вставке в пустую колонку — агент трижды генерировал off-by-one
- **Расхождения / находки:** property convergence нашёл зависимость от порядка Map (seed 81723) → регрессионный тест
- **Цена:** ~$1.8 / 40 мин (если известно)
```
