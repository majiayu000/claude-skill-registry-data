description: 在规划和实现前，为 Agent Harness 5.0 创建或细化设计产物。
---

## 何时使用
- 需要生成、细化或评审设计稿、界面方向、交互状态、视觉系统或设计验收口径时使用。
- 现有 Product-Spec.md 或 Design-Brief.md 仍不足以指导实现，需要先把体验变成可检查的设计 artifact 时使用。
- 实现结果与预期不一致，需要回到设计层重新定义页面结构、状态、内容层级或交互边界时使用。

## 依赖输入
- 现有设计稿、截图、原型、品牌素材和视觉参考优先级最高。
- Design-Brief.md 次之；没有 Brief 时再参考 Product-Spec.md、用户叙述、业务规则和历史决策。
- 需要目标设备、布局密度、关键工作流、状态清单、内容样本、可访问性要求和技术限制。
- 大量视觉研究、组件库说明、行业资料或长规范放入 `references/`，按需引用。

## 第一性原则与边界
- Agent Harness 5.0 以目标、标准、边界驱动设计：每个视觉和交互决定都要服务可验收的体验目标。
- 设计稿优先于 Design-Brief.md，Design-Brief.md 优先于 Product-Spec.md；当设计稿缺失时，先补足设计 artifact 再推动实现。
- 设计产物必须能被实现 agent 观察和验收，避免只给抽象形容词。
- 不把 design-maker 变成实现 planner；技术方案只作为可行性边界，不替代 dev-planner 的验证。
- 不在主文档塞入重型知识；用 references 承载长材料、样例库和研究证据。

## 验收标准
- 关键屏幕、状态、内容层级和交互结果足够清晰，可直接转化为实现验收点。
- 明确哪些设计决定来自设计稿、Brief、Spec 或新补充假设。
- 覆盖默认、空、加载、错误、边界数据、响应式/设备差异等必要状态。
- 标出不可牺牲的体验标准，以及可以在实现阶段协商的弹性范围。

## 产出
- 可执行的设计 artifact 描述、设计稿生成提示、状态清单、组件/布局规范或设计评审结论。
- 必要时输出 references 清单、素材需求和需要用户确认的设计问题。
