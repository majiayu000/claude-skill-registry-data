# 目标创建器

创建一条 `/goal` 指令，让 Codex 能自主追求有边界的结果，同时由用户保留启动权限。

## 何时使用

当用户要求让 Codex 执行一个阶段、完成 DEV-PLAN.md 的某一部分、收尾一个有边界的实现切片，或准备自驱执行指令时使用此技能。

不要用于产品探索、需求不清、开放式设计决策，或需要用户反复判断的工作。

## 必要输入

- 已接受的 `Product-Spec.md` 章节或需求 ID。
- 涉及 UI 时，相关 `Design-Brief.md` 或设计 artifact 引用。
- `DEV-PLAN.md` 中的阶段或任务范围。
- 当前项目约束、受保护分支、范围外文件或区域。
- 可在此工作区运行的具体验证命令。

## 原则

- 将整条指令控制在 4000 字符以内。
- 写目标、标准、证据和边界；不要叙述过程。
- 完成标准必须可客观检查：命令已运行、输出已粘贴、文件已变更、清单项已满足、审查结果已附上。
- 相关时包含项目门槛，例如构建、测试、功能 smoke check 和两阶段 code review。
- 边界必须真实且具体。不要写“保持代码干净”这类模糊约束，除非已转化为可观察检查。
- 最终 `/goal` 由用户发送；不要静默启动自主执行。

## 验收标准

生成的 goal 满足以下条件时才可接受：

- 只识别一个阶段或一个连贯范围。
- 列出可验证的完成标准。
- 指明验证命令或 artifact 检查。
- 声明明确的范围外边界。
- 当代码或发布 artifact 受影响时，包含审查和发布门槛。
- 足够短，可作为单条 `/goal` 指令粘贴。

## 产出

返回可直接复制的 `/goal` 块，并附简短说明，列出用户发送前应确认的假设和边界。
