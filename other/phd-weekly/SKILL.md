# 科研周报

先读取 [本地操作约定](../phd-manager/references/local-workflow.md)，定位仓库和当前项目。本技能默认读取与写出报告文件，不为美化周报改动科研状态。

## 生成

1. 执行 `node cli.mjs list projects` 获取项目 ID，随后执行 `node cli.mjs report --project <id>` 和 `node cli.mjs state --project <id>`。不限定项目时省略 `--project`。
2. CLI 报告期为截至今天的最近七个日历日。用户要求不同日期区间时，在实际状态与活动记录上明确筛选区间；活动没有完整历史快照，不能把当前状态当作任意历史时点状态。
3. 使用确定性报告作为事实底稿，检查其中的“本期变化”和“当前状态”。一条完成任务若没有本期完成的证据，只能放入累计状态，不能写成本周完成。
4. 核对用户提供的日志、稿件、结果和会议记录，只写材料支持的内容。记录不足时明确“本期进展记录不足”，不要从任务标题补写成果或数字。
5. 组织为研究目标、本期证据与进展、当前论文/实验状态、阻塞及待决策问题、下期建议。下期建议与已确认安排区分；从现有记录引用标题和必要的文件/来源路径。
6. 用户需要可保存文件时写入指定路径；无指定时保存到 `outputs/weekly-<projectId>-YYYY-MM-DD.md`，全项目报告使用 `all` 替代项目 ID。写入前检查文件是否存在；除非用户明确要求更新同一周报，否则使用 `-v2`、`-v3` 等未占用后缀，避免静默覆盖。报告期和生成日期写在正文。只在用户要求同步新事实时调用相应更新技能，写完后重新生成底稿。

## 质量检查

- 每个“完成”“提升”“验证”是否能对应实际记录或用户明确确认？新增实验计划不能算实验结果。
- 当前百分比是人工估计；数量来自当前记录。状态数量与本期完成数量不要混用。
- 对统计结果保留指标、对比基线和条件。没有检验结果时不写“显著提升”。
- 导师原话来自真实 `meetings`；模型评价和可能的解决方法标为 AI 建议。
- 不自动发送给导师、不自动设置定时任务。用户请求的是可直接使用的周报时，交付完整成稿和保存位置。
