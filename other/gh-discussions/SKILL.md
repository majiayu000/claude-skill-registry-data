# /gh-discussions — Q&A-дверь, где ответ становится Answer

> 🧒 В конце отчёта Антону — блок «Простыми словами» ([[eli5-always]]).

## Зачем отдельная дверь (приказ Антона 03.09: «сделай ОТДЕЛЬНУЮ ДВЕРЬ ПОД ДИСКУССИОНС»)

Discussions — не «issues, только сбоку». Разница механическая: у Q&A-категории есть
кнопка **Mark as answer**, и помеченный ответ — единственная на GitHub форма публичного
признания «этот человек решил мою проблему».

Общий комментинг эту дверь не покрывает физически, и это замерено, а не предположено.
Главное гнездо `/rep-reply` — `anthropics/claude-code` — имеет `hasDiscussionsEnabled:
false` и **ноль дискуссий при 144 001 звезде**. Туда этим скиллом ходить некуда.

Набор репо у двух поверхностей **почти не пересекается** (замер 04.09.2026, 22 вендорских
репо): Discussions включены у 10 из 22, и среди выключенных — `modelcontextprotocol/python-sdk`,
`pydantic/pydantic-ai`, `openai/openai-agents-python`, `crewAIInc/crewAI`, `ollama/ollama`,
`huggingface/transformers`. Это и есть разрыв, который скилл закрывает.

⭐ **Разрыв доказан отдельно, а не выведен из удобства** (§5.4 — выгодный вывод требует
усиленной проверки). `gh search` не имеет подкоманды `discussions` вовсе (только
`code/commits/issues/prs/repos`), и рельса `/rep-reply` дискуссии физически не видит:
04.09 запрос `gh search issues --repo google/adk-python "load_skill re-returns"` вернул
**пустой массив**, тогда как тот же текст через `search(type: DISCUSSION)` находит
дискуссию **#6997**. Тот же `gh search issues` по слову `load_skill` при этом честно
отдаёт 5 ИССЮ — значит поиск исправен, а дискуссии для него просто не существуют.

## Шаг 0. Гейты (30 секунд, до первой буквы)

- **RECALL**: писали ли мы в этот тред. `python3 ~/.claude/scripts/gh_discussions.py mine <owner/repo> <N>`
  — проверяет ВСЕ три наши личности (`tonydzi`, `Palo-Alto-AI-Research-Lab`, `secondbrainstarter`).
- **Прерывание №1**: живой человек ответил на наше прошлое исходящее → отвечаем ЕМУ сегодня.
- **Автономия**: GitHub-коммуникацию шлю САМ, без «+» и без гейта [коллега] (§4.7). Tier-2
  остаётся: юр. подписание, деньги, удаление чужого, масс-действия.
- ⛔ Красная черта: одинаковый текст веером в несколько дискуссий. Спам ≠ громкость (§1.5).

## Шаг 1. Есть ли дверь вообще

```bash
python3 ~/.claude/scripts/gh_discussions.py surfaces            # дефолтный набор
python3 ~/.claude/scripts/gh_discussions.py surfaces owner/repo # точечно
```

Три исхода, и путать их нельзя:

| знак | что значит | что делаем |
|---|---|---|
| ⛔ | `hasDiscussionsEnabled: false` | двери НЕТ, идём в issues → `/rep-reply` |
| ◻️ | Discussions есть, но **нет answerable-категории** | это форум, а не Q&A: механики Answer нет, кармы не будет |
| ✅ | есть Q&A-категория | идём дальше, на Шаг 2 |

◻️ — не теория: `vllm-project/vllm` держит **489 дискуссий и ноль Q&A-категорий** (замер 04.09).
Зайти туда и ждать Answer — значит ждать кнопку, которой в репо не существует.

## Шаг 2. АУДИТ ДВЕРИ — кому вообще достаётся Answer

Это главный шаг и главное отличие от соседей. `/issue-match` меряет очередь PR;
здесь меряется **кому досталась карма**.

```bash
python3 ~/.claude/scripts/gh_discussions.py audit <owner/repo> [--sample 50]
```

Скрипт разбирает последние помеченные ответы на четыре класса — **бот · сам автор
вопроса · человек из проекта · ЧУЖАК** (`authorAssociation: NONE`/`FIRST_TIME_*`) — и
считает долю чужака. Чужак = наш класс: мы приходим без прав в репо.

## Шаг 3. ОХОТА — открытые вопросы без ответа

```bash
python3 ~/.claude/scripts/gh_discussions.py hunt <repo> [<repo>...] \
    --kw "memory,session,timeout" --days 30 --limit 30
```

Живой пример 04.09 (`run-llama/llama_index` + `openai/codex` + `openai/openai-python`,
`--kw memory`): 87 открытых без ответа всего, из них свежее 30 дней — 2.

⛔ **Ключевые слова гоняем ПОШТУЧНО, не веером.** GitHub AND-ит термины внутри одного
запроса, поэтому `--kw "memory,session,timeout"` одной строкой отдаёт «Всего открытых без
ответа: 0» на живой двери, где те же слова по одному дают 18 / 100 / 32 (замер 06.09.2026,
подтверждён 08.09.2026 на `PrefectHQ/fastmcp`). Ложный ноль читается как «кандидатов нет» и
молча закрывает прогон — цикл по одному `--kw` обязателен.

Сортировка неслучайная: **сначала треды с 0 комментариев** (помечены 🚪). Там Answer
никем не занят и вопрос ещё не остыл.

Банк тем берём тот же, что у `/rep-reply` (карта «тема → наш артефакт» в его SKILL.md) —
дублировать её здесь запрещено, один источник. Разница в ФОРМЕ входа: там мы приходим
в чужой БАГ, здесь отвечаем на чужой ВОПРОС.

## Шаг 4. ОТБОР (все пункты обязательны)

1. Категория **answerable** — иначе Answer поставить физически некому.
2. Дискуссия **открыта**. `is:unanswered` этого НЕ гарантирует: у `adk-python`
   `is:unanswered` = 381, а `is:open is:unanswered` = 340 → **41 закрытая дверь (10.8%)**
   выглядела бы живой. Скрипт пришивает `is:open` сам, руками про это забывают.
3. Живость решает **последний РЕАЛЬНЫЙ комментарий**, а не `updatedAt` (его двигает
   лейбл-свип бота — грабля замерена в `/rep-reply` дважды).
4. У нас есть **артефакт с датой**: замер, репозиторий, строка Breakage-Journal, код.
   Совет без артефакта — не наш жанр, скип.
5. Мы в треде **ещё не писали** — Шаг 0, все три логина.
6. Наш пуант **ещё не сказан** другим отвечающим. Сказан → скип или апвоут.

Нарушен любой пункт → строка `skip` с причиной в лог, НЕ отвечаем.

## Шаг 5. ОТВЕТ — факт с репро, не эссе

Жанр Q&A жёстче, чем у issue: человек пришёл с вопросом и хочет **работающий ответ**,
а не рассказ о нашей архитектуре. Длинное эссе Answer не получает — его получает
короткий проверяемый рецепт.

Каркас:

1. **Первая строка — раскрытие Майкрофта, с юмором** (§3.3): `hi, this is Mycroft,
   Anton's synthetic cofounder — ...`. Один раз на тред, сверху, не подписью снизу.
2. **Прямой ответ в первых двух предложениях.** Не «мы тоже это проходили».
3. **Репро или команда**, которую читатель выполнит за минуту и увидит тот же результат.
   ⭐ **Опубликованный кусок прогоняется ДОСЛОВНО перед отправкой** (оплачено 23.09.2026,
   browser-use#3856): рабочий скрипт был зелёный, а сокращённый для коммента сниппет врал —
   в нём `aria-ref=e4` вместо `e3`, потому что из HTML выпал `<h1>` и сместилась нумерация.
   Поймано только тем, что кусок вырезали из черновика (`sed -n '/```python/,/```/p'`) и
   запустили КАК ОПУБЛИКОВАНО. Каждый комментарий `# -> ...` в сниппете = вывод, который
   реально напечатался; не прогнал дословно — комментарии из сниппета убираем (§5.4,
   [[red-first-or-the-test-is-fake]]).
4. **Цифра с датой из нашего замера** — то, что нельзя нагенерить.
5. **Честная граница**: чего мы НЕ проверяли, на какой версии/ОС мерили.
6. **Предпоследняя строка — встречный вопрос автору** («какая у тебя версия?»), он двигает
   тред и повышает шанс, что автор вернётся и нажмёт Mark as answer.
7. ⭐ **Последняя строка — подпись-CTA** (anton 10.09, голосовая hub:6539). Одна строка со
   ссылкой `github.com/tonydzi`, формулировку варьировать. Источник —
   `$OBSIDIAN_VAULT/08-Templates/github-touch-signature.md`, карта поверхностей —
   `$OBSIDIAN_VAULT/08-Templates/outbound-signature.md`. Discussions живут в поиске дольше
   issue, поэтому ссылка тут работает годами. Проверка перед отправкой: последняя строка
   несёт `github.com/tonydzi`? Нет → не отправляем. ⛔ Подпись — НЕ просьба про Answer
   (см. запрет ниже): ссылка на профиль, а не «отметьте меня».

Язык = язык треда (грабля 11.08: русский коммент в англ. тред пришлось переписывать).
Абзацы: мысль длиннее трёх предложений разбиваем пустой строкой (§9.10).

⛔ Просить пометить как Answer — нельзя. Карма выпрашиванием не берётся, а репутация
горит быстрее, чем строится.

**Отправка** (единственное действие наружу, всё остальное read-only):

```bash
# новый комментарий верхнего уровня
gh discussion comment <N> -R <owner/repo> --body-file <файл>
# ответ на конкретный комментарий — позиционный аргумент = ID/URL комментария
gh discussion comment <comment-id|comment-url> -R <owner/repo> --body-file <файл>
```

⚠️ `gh discussion` в gh 2.96 помечен **preview и меняется без предупреждения**. Синтаксис
перед прогоном рутины сверяем `gh discussion comment --help`, а не по памяти.

## Шаг 6. Leak-гейт — обязателен ДО отправки

```bash
python3 /Users/<имя>/Obsidian/_imports/leak_scan.py <файл-черновика>
```

Exit 0 = чисто, **1 = FAIL, не отправляем**, 2 = ошибка пути (это НЕ «чисто»).
Затем анти-слоп: текст с плашкой Майкрофта из-под `/ai-slop` выведен (одно из трёх
исключений), но ban-лист и ритм всё равно перечитываем глазами.

## Шаг 7. СЛЕД — счётчик и Connect

Каждое действие → строка JSONL в `~/.claude/logs/gh_discussions.jsonl`:

```json
{"ts":"2026-09-04T12:00:00Z","node":"<hostname>","actor":"gh-discussions",
 "event":"answer|skip|audit","repo":"owner/repo","number":123,
 "artifact":"имя","outcome":"posted|skipped|marked_answer","reason":"..."}
```

Метрика успеха здесь **своя, и она не «ответил человек»**: считаем **принятые Answer**
и повторный осмысленный контакт того же человека. Ответ без Answer — не провал, но и
не победа; 0 ответов за прогон = норма.

Дальше по конвейеру: автор выглядит способным (живые коммиты, наш домен) → карточка CRM
(§1.6 — способность, не известность). Сильный тред → черновик в `/content-mine`.
Ответили → ответы НАМ ловит `/contrib-watch`; их мяч + тишина >3 дней не бампаем.

## Шаг 8. УРОЖАЙ — а Answer-то помечают? (добавлен 07.09.2026)

Метрика лейна объявлена в Шаге 7 («считаем принятые Answer»), поэтому её надо МЕРИТЬ,
а не чувствовать. Прибор:

```bash
python3 ~/.claude/scripts/gh_discussions.py harvest            # все треды из лога
python3 ~/.claude/scripts/gh_discussions.py harvest --limit 10 # только последние
```

Он берёт из `~/.claude/logs/gh_discussions.jsonl` все строки `event=answer`, спрашивает
у GitHub `isAnswered` и печатает две цифры: сколько ответов помечено Answer и в скольких
тредах последний комментарий по-прежнему НАШ (= человек ещё не ответил).

⭐ **База для сравнения, замер 07.09.2026: 0 помечено из 20 · наш комментарий последний
в 19 из 20.** Это не повод молчать в отчёте — это повод НАЗЫВАТЬ число. Три ночи ответов
с прогонами дали видимость и ноль Answer; если через неделю цифра не сдвинется, вопрос
не «писать ли лучше», а «та ли это дверь» — и решает его Антон, увидев число.

⛔ Не подменять урожай удобной метрикой («ответов отправлено N») — §5.4, выгодный вывод
требует усиленной проверки, а не ослабленной.

## Границы

- **READ-ONLY по умолчанию.** `gh_discussions.py` не публикует ничего. Наружу уходит
  ровно один осознанный вызов `gh discussion comment` после Шагов 4-6.
- ⛔ Не создаём свои дискуссии этим скиллом (это `/consumer-hunt` и `/release-slice`).
- ⛔ Не спорим в чужом доме: несогласие = факты + вопрос, не крестовый поход.
- ⛔ Reddit/X/форумы — не сюда (своя матрица площадок §3.2). Только GitHub.
- ⛔ Выдуманные цифры. Каждое число — из вывода команды, которую реально прогнали;
  не замерено → так и пишем «не замерено» (§5.4).
- Подпись в GitHub-тредах: `Assisted-by:`, НЕ `Co-authored-by:` (§3.3, поправка DR-701).
- ⭐ **ФЛОТ:** скилл синкается на все машины и любой узел может звать его руками, но
  СУТОЧНАЯ РУТИНА живёт на ОДНОМ узле — иначе N машин отвечают в один тред N голосами.
  Вторая страховка — гейт дублей Шага 0: аккаунт один на весь флот, `mine` видит
  комментарий любого узла. Лог локален узлу, истина по дублям = `gh`, не лог.

## DoD — «готово» только когда всё шесть

1. `surfaces` отработал: у цели ✅ (Q&A-категория есть), не ⛔ и не ◻️.
2. `audit` отработал: вердикт 🟢 или 🟡 с названной долей чужака; 🔴/⚪ → не идём.
3. Гейт дублей `mine` показал «нас в треде нет».
