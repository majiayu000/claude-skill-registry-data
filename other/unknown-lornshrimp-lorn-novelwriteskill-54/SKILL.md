### 步骤 2：双轴评分读取与强制 IF/THEN 分流

**调用 skill：** 无（编排器自执行）；加载 `../../写作研究/网文留存模型.md` 获取平台权重配置。**注：无 skill 调用的步骤不豁免步骤 2 的强制执行义务。**

**扮演角色：** 质检员角色。不代入任何创作或审阅视角，只做评分提取、双轴比较与循环调度决策。

**职责：** 从主审阅报告中提取技法分与留存分，根据以下 IF/THEN 规则执行强制分流。**本步骤的唯一职责是提取双轴评分 → 按双轴门槛做前置过滤 → 执行 IF/THEN 规则 → 根据结果分流，不得擅自改变分流目标。**

**【前置过滤：双轴各达标检查】**
提取报告中的双轴评分：

```text
技法分 = X.X/10（从报告中 `- 技法分：X.X/10` 提取）
留存分 = X.X/10（从报告中 `- 留存分：X.X/10` 提取）
```

前置过滤规则：
```
IF 技法分 < 6.0 或 留存分 < 5.0：
   → 标记为"双轴前置过滤未通过（技法=XXX/留存=XXX）"
   → 强制进入步骤 3（改稿），不检查综合评分
   → 必须优先修复不达标轴

IF 技法分 ≥ 6.0 且 留存分 ≥ 5.0：
   → 标记为"双轴前置过滤通过"
   → 进入综合评分 IF/THEN 分流
```

**【强制 IF/THEN 闸口规则（前置过滤通过后执行）】**
```
IF 综合评分 <= 9.2：
   → 你 MUST 进入步骤 3（改稿），不得进入步骤 6
   → 修改后必须进入步骤 4（复审），不得跳步

IF 综合评分 > 9.2 且这是 首轮 达标（前一循环 <= 9.2）：
   → 标记为"首次过线，进入稳定性验证轮"
   → 你 MUST 进入步骤 3（改稿），不得进入步骤 6
   → 修改后必须进入步骤 4（复审），不得跳步

IF 综合评分 > 9.2 且这是 连续第二轮 达标（前一循环也 > 9.2）：
   → 允许进入步骤 6（完成回执）
```

**硬性规则（违反即为流程违规）：**
- 9.2 不算通过，必须**严格大于** 9.2。
- 综合评分取值为保留两位小数后的数值。
- **双轴前置过滤优先于综合评分检查**——技法分 < 6.0 或留存分 < 5.0 时，不检查综合评分，直接进入步骤 3。
- 若竞对维度的量化结论仍有关键显著落后项（单维度 < 7.0/10），即使综合评分表面 > 9.2，也不得过线（强制进入步骤 3）。
- 步骤 2 的输出只有一个：进入步骤 3（改稿）或步骤 6（收尾）。不得在步骤 2 结束后擅自跳步或改变执行顺序。

1. 从主审阅报告中定位 `- 技法分：X.X/10` 和 `- 留存分：X.X/10`
2. 执行双轴前置过滤检查
3. 若通过，从主审阅报告中定位 `- 综合评分：X.X/10`，提取数值 X.X
4. 按上述 IF/THEN 规则执行分流

**完成标记：** checkpoint.nextStep = 3（改稿）或 6（收尾），写入日志。

### 步骤 3：按审阅报告修改提纲

**调用 skill（强制加载，不得跳过）：** `通用-设计总大纲` 或 `通用-设计分卷大纲`（及对应的题材包装层），按**对象路由规则**选择。必须通过 `skill()` 工具加载对应 Skill，逐字执行其 SKILL.md 指令。按需调用 `通用-设计标题`、`通用-设计故事面`、`通用-设计事件案件引擎`、`通用-设计线索伏笔与回收台账`（及对应的题材包装层）——按需调用的专项 Skill 也必须通过 `skill()` 工具加载，不得凭经验直接改写。

**扮演角色：** 小说作者角色（修订模式，参考 `.github/agents/小说作者.agent.md`）。**退出审阅者立场**，切换到作者视角。审阅报告是修改依据，修改以"解决问题"为目标，不是以"回应每一条意见"为目标。修改前重新阅读上级分配文件，确保修改方向不偏离上级分配。

**职责：** 根据最新审阅报告中的问题、修改建议与优化思路，对提纲做针对性修改。

**硬性规则（违反即视为流程违规）：**
- 必须直接写回目标提纲文件，不得只在聊天里给建议版。
- 修改必须覆盖上一轮核心扣分项（特别是阻断点/风险）。
- 必须吸收审阅报告中的问题、修改建议与"冲击 9.2+ 的优化思路"。
- 若存在竞对分析资料，修改必须至少落地 1 条"竞对借鉴动作"并补齐 1 条"竞对落后项"。
- 不得引入新的重大口径冲突。
- **步骤 3（修改）完成后，必须进入步骤 4（复审）。修改 → 复审 是强制配对，不得改完不审，也不得审了不改直接进入下一轮。**

**专项强化诊断与调用**（按需执行，不强制全部调用）：

| 诊断问题 | 调用 Skill | 处理范围 |
|---|---|---|
| 各级标题（卷名/章名等）抓力不足、与平台风格不匹配 | 通用-设计标题（及对应的题材包装层） | 对应标题层级的重新设计 |
| 故事面供血不足、卷级承接关系发虚、硬抓手不清晰 | 通用-设计故事面（及对应的题材包装层） | 对应故事面文件或总纲中故事面章节 |
| 单元案/事件引擎结构不成立、主线供血不足、规则显影不到位 | 通用-设计事件案件引擎（及对应的题材包装层） | 对应单元案文件或分卷中案件设计章节 |
| 线索台账/伏笔台账缺失、回收窗口不明确、推理公平性不足 | 通用-设计线索伏笔与回收台账（及对应的题材包装层） | 对应线索/伏笔台账文件或分卷中线索章节 |

1. 按对象路由规则加载对应的主设计 Skill（及题材包装层），代入作者角色
2. 读取当前版本的目标提纲 + 最新审阅报告 + 上级分配文件
3. 逐条对照审阅报告中的阻断点、风险项与扣分项，判断问题所属层级：
   - **[标题层]**：卷名/章名抓力不足、风格不匹配 → 调用通用-设计标题（及对应的题材包装层）
   - **[故事面层]**：供血不足、卷级承接发虚 → 调用通用-设计故事面（及对应的题材包装层）
   - **[事件/案件层]**：事件引擎不成立、主线供血不足 → 调用通用-设计事件案件引擎（及对应的题材包装层）
   - **[线索/伏笔层]**：台账缺失、回收窗口不明确 → 调用通用-设计线索伏笔与回收台账（及对应的题材包装层）
4. 针对性地按需调用上述一个或多个 Skill 执行专项修改
5. 修改后的提纲直接**覆盖写入**原目标提纲文件

**文件写入：** 修改后提纲覆盖写入原目标提纲文件

**完成标记：** checkpoint.nextStep = 4，写入日志。

### 步骤 4：复审（强制完整模板 + 差异对比）

**调用 skill（强制加载，不得跳过）：** `通用-审阅总大纲` 或 `通用-审阅分卷大纲`（及对应的题材包装层），按**对象路由规则**选择。必须通过 `skill()` 工具加载对应 Skill，逐字执行其 SKILL.md 指令。

**扮演角色：** **切回审阅者角色（参考 `小说审阅者.agent.md` 的审阅立场）**。完全退出作者立场，以独立审阅者视角重新对修订版提纲进行全面审阅。本轮不仅检查上一轮问题是否修复，还要重新发现修改引入的新问题。标准不因"已经改过一轮"而降低。

**硬性规则（违反即视为流程违规）：**
- 必须是**对当前修订版本的完整、从严、独立的重新审阅**，而非只检查旧问题是否已修复。
- 不得以"与上一轮相比有进步"替代独立评分。
- 若存在竞对分析资料，必须重新判断竞对维度的领先点/落后点变化。
- 禁止通过"降低审阅口径"换取高分。
- **审阅报告必须使用完整模板**，不得写简版。至少需要包含步骤 1 规定的所有板块 + "与上一轮审阅的差异对比"。

**【强制门禁：审阅报告模板完整性检查】**
写入后、宣告完成前，逐项验证报告是否包含完整模板的所有板块 + 差异对比说明。缺失任一 → 判定为简版，回退重写。

1. 按对象路由规则加载对应的审阅 Skill（及题材包装层），代入审阅者角色
2. 读取修改后的目标提纲 + 上一版审阅报告（用于对比）+ 上级分配文件 + 相关裁判源
3. 执行全面审阅，使用完整审阅报告模板
4. 对照上一轮问题给出差异说明（已解决/部分解决/未解决/新增问题）
5. 报告中必须包含双轴评分：
   - `- 技法分：X.X/10`
   - `- 留存分：X.X/10`
   - `- 综合评分：X.X/10（权重：技法W_+留存W_=平台名）`
6. 若存在竞对分析资料，必须更新竞对量化模块（含留存竞对比对）
7. 审阅报告**覆盖写入**同一主报告路径
8. 执行模板完整性检查，确认无缺失

**文件写入：** 审阅报告覆盖更新到主报告路径

**完成标记：** checkpoint.nextStep = 2（回到评分读取与分流），写入日志。

### 步骤 5：循环控制（嵌入在步骤 2→3→4→2 中）

本步骤不是独立操作步骤，而是对 2→3→4→2 循环的约束规则：

- 回炉-审阅循环默认最多执行 **8 轮**（不含首次审阅 步骤 1）。超过 8 轮仍未达标时：
  1. 暂停循环，评估是否需更换模型、调整提示词口径或补充裁判源
  2. 第 8 轮评分若反而低于第 7 轮，强制截停
  3. 高原期判定需要**连续两对评分差距均 < 0.15**：若第 N 轮评分与第 N-1 轮差距 < 0.15，不得直接截停——**必须再执行一轮"精修 + 独立复审"**得第 N+1 轮评分。仅当 |Score(N)−Score(N-1)| < 0.15 **且** |Score(N+1)−Score(N)| < 0.15 同时成立时，才判定进入高原期，强制截停。若复审差距 ≥ 0.15，高原期不成立，继续正常回炉循环
  4. 不得单纯重复"改→审"循环
- "首次过线后追加稳定性验证轮"不计入 8 轮限制——验证轮是因达标而附加的必要步骤，不是因未达标而继续回炉。

## SOP 执行日志

每次执行本 Skill，都必须在 SOP执行日志/大纲审阅/ 中创建或更新一份日志文件，用于断点恢复。

日志至少包含：executionId、目标提纲路径、对象类型、主报告路径、checkpoint（nextStep/phase/nextAction）、每轮回炉的 iteration 与评分纯数字、最终完成状态。

## 完成定义

只有同时满足以下全部条件，才允许宣告闭环完成：

1. 步骤 0→4 已在本次执行中实际跑完，而非依赖历史文件推断。
2. 目标提纲已被本次最新修改轮覆盖更新。
3. 主审阅报告已被本次最新复审覆盖更新。
4. 连续两轮独立审阅综合评分均严格大于 9.2。
5. 若竞对维度存在，竞对量化卡无关键显著落后项（单维度 >= 7.0/10）。
6. 日志中的 status 与 checkpoint 已与真实状态一致。
7. 当前聊天输出的是步骤 6 的完成回执模板，而非阶段汇报。

## 常见触发词 / 用户说法速查

- 把这份大纲审到过线
- 一直回炉到 9.2+
- 用同一份报告循环复审
- 这份总纲/分卷反复改到过线
- 给我一个大纲优化闭环

## 不适用情形

- 只做一次性审阅、不改稿：优先使用通用-审阅总大纲 或 通用-审阅分卷大纲
- 只新建大纲、不跑审阅闭环：优先使用通用-设计总大纲 或 通用-设计分卷大纲
