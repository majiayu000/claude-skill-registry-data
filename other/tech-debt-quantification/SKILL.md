# 技术债务量化Skill

## 适用场景
技术债务治理环节,将架构层面「感觉欠债很多」的定性判断转为可度量指标,建立债务台账,支持定期复测与趋势跟踪。

## 执行步骤
1. 确定度量维度:按下表选择项目可采集的指标,明确采集频率(建议每迭代一次)。
2. 采集数据:工具自动扫描 + 人工盘点结合,记录工具名、版本、扫描时间。
3. 计算指标并逐条登记入债务台账。
4. 定期复测,与历史快照对比(趋势分析使用「质量趋势分析Skill」)。

## 量化指标
| 指标 | 定义 | 计算方式 |
|---|---|---|
| 债务率 | 重构总成本 / 项目总开发成本 | 估算人日之比 |
| 债务密度 | 债务条目数 / 千行代码(KLOC) | 台账条目数 ÷ 代码规模 |
| 违规密度 | 规范违规数 / KLOC | SonarQube/Lint 报告 |
| 圈复杂度均值 | 全部函数圈复杂度平均 | 见「代码复杂度计算Skill」 |
| 覆盖率缺口 | 目标覆盖率 − 实际覆盖率 | 见「单元测试覆盖率Skill」 |
| 债务利息 | 因债务产生的月均额外维护耗时 | 人工估算,按模块分摊 |
| 高风险债务占比 | 高风险条目数 / 债务总条目数 | 台账统计 |

## 台账登记规范
台账字段固定:ID、位置(文件/模块)、描述、类型、风险级(高/中/低)、估计成本(人日)、登记日期、状态(待处理/处理中/已偿还)。

## 规范要点
- 所有数字必须有来源:工具名 + 版本 + 扫描时间;人工估算注明估算口径与估算人。
- 禁止「债务很多、代码很乱」式无指标结论,必须落到具体数值。
- 债务条目必须能定位到具体文件/模块,不可整包笼统登记。
- 指标口径一经确定保持稳定,口径变更需在新报告中注明。

## 输出模板
```
## 技术债务量化报告
| 指标 | 数值 | 来源/口径 | 与上次对比 |
## 债务台账明细
| ID | 位置 | 描述 | 类型 | 风险级 | 估计成本 | 状态 |
## 量化结论(债务规模、利息成本、高优项)
```

## 自检清单
- [ ] 每个指标有数据来源与采集时间
- [ ] 台账字段完整、条目可定位
- [ ] 人工估算已注明口径
- [ ] 与上次快照有对比
