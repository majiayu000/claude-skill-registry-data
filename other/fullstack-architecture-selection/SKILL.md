# 全栈架构选型Skill

## 适用场景
项目起步或重大技术改造,需要基于需求与非功能约束做技术选型,输出可决策的对比方案。

## 执行步骤
1. 提取约束:团队技术栈、QPS/数据量/延迟/一致性要求、部署环境、成本、合规。
2. 列候选方案:每层(语言/框架/存储/中间件/部署)列 2-3 个主流选项。
3. 按维度打分:生态成熟度 / 性能 / 团队熟悉度 / 运维成本 / 扩展性 / 合规。
4. 输出选型结论 + 理由 + 备选方案 + 风险与权衡。
5. 标注不确定项:未验证的技术点给出 PoC 验证路径。

## 规范要点
- 优先稳定主流方案,不追冷门新技术(除非需求明确要求)。
- 选型必须「方案 + 理由 + 备选 + 风险」四要素齐全,禁止只给结论。
- 数据库选型必须说明一致性模型与扩展路径(分库分表时机)。
- 不编造版本号与特性:不确定的版本特性标注「需验证」。
- 大模型相关选型必须考虑:模型可用性、Token 成本、私有化部署要求。

## 输出模板
```
## 技术选型结论
| 层 | 选型 | 版本(如确定) | 理由 | 备选 |
|---|---|---|---|---|
## 风险与权衡
## 待验证项(PoC 清单)
```

## 自检清单
- [ ] 每层有结论+理由+备选
- [ ] 约束与选型一一对应(无凭空选型)
- [ ] 风险与权衡已写明
- [ ] 不确定项有验证路径
