# 物品内的真实三维场景窗口

默认平台为 **Minecraft 1.20.1 / Forge 47.4.10 / Java 17**。尊重目标项目的 Forge 47.x 补丁选择，更换版本后重新验收。用户无需选择预设或手写参数，用自然语言描述内部世界即可。

真实场景至少包含三维几何、独立相机和深度遮挡；窗口只是展示与裁剪区域。将“场景内容 → 相机/投影 → 离屏颜色与深度 → 物品窗口 → 原物品装饰”分开。内部深度不直接写入外部世界；物品对外仍使用窗口面的深度。

## 自由设计

先读 [设计与空间契约](references/design.md)。自由确定内容、布局、主体、留空、颜色、动作、观察方式、开口与承载物。观测站、花园、画廊只是测试场景，不是主题枚举。

- 微缩景观：用 scene graph 或新增 Backend。任意三角网格可以表达复杂形状，不让所有主题变成方块换色。
- 现有 Minecraft 世界/镜面：按 [Forge 扩展](references/forge-integration.md) 实现。当前模板没有完整世界视图，收到该需求时补适配器，不用微缩模型冒充。
- 曲面、多孔、多窗口、骨骼承载物：允许新增窗口和几何适配器；单个平面是参考实现，不是设计上限。
- 纹理、粒子、光源、脚本轨道和场景交互：按需求增加字段与消费者。明确哪些已实现，不输出无人解析的 JSON/NBT。

## 制作流程

1. 识别任务是创建原型、研究还是落地已有模组，读取目标版本、模型、renderer 与既有效果，保留原动作/姿态。
2. 将自然语言转成简短方案，先决定内部空间和观察语义。自由设计仍需按目标设备、图标尺寸与同屏数量设置预算。
3. 普通微缩场景先用 [场景格式](references/scene-format.md)。运行 `python scripts/scaffold.py <空目标目录>` 生成独立 Forge 1.20.1 工程；该脚本不安装 mod 或启动游戏。
4. 用 `python scripts/validate_scene.py <场景.json>...` 检查配置。按 [验收方法](references/validation.md) 检查空间、动画、遮挡、窗口和状态。
5. 用户要求已有物品生效时增加对应 adapter；示例 window 物品不是所有原版/MOD 物品支持的证明。
6. 构建生产 JAR 并执行 reobfJar。实际游戏交付需在授权实例验证。已通过的环境与限制见 [证据](references/runtime-evidence.md)，新 backend 不继承旧认证。

## 渲染不变量

- 相机点、窗口平面与内部几何在同一空间。off-axis 的窗面不因观察点平移滑动，远近物有不同视差；lookAt(中心)是另一种语义。
- GUI 使用显式虚拟眼位；手持用实际 item pose 与 ModelView 逆变换，不重复减世界相机。背面示例映射到另一正面视图，不是真正双向玻璃盒。
- 改分辨率不改构图；mask 与 FBO 的 V 方向分别检查。内部深度提供自遮挡，窗面对外提供物品深度。
- 原缓冲先提交，FBO 内容必须在复用前消费；延迟多物品绘制需独立目标或含视图/时间/资源代次的缓存键。
- finally 恢复改动的 framebuffer、viewport、矩阵、深度/混合/剔除、scissor、shader、纹理和颜色。新 Backend 改动灯光、雾或 stencil 时扩展状态集合。
- 重载使缓存/shader/FBO 失效；尺寸变化重建；退出世界释放。不能简单交换 Minecraft.level 冒充跨维度渲染。

随附资产是原创微缩场景 Java/GLSL/JSON 工程。Immersive Portals、Veil、Lodestone 仅作架构参考，不捆绑其源码/二进制或复制其 1.21 API。
