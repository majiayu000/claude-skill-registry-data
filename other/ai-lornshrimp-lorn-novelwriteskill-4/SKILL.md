# AI科幻-设计标题

这是题材包装层、兼容入口与路由层。


<!-- ===== Layer 3: 场景缓存 ===== -->

## 对应通用 Skill

- `通用-设计标题`

## 强制要求

- 不得绕过 `通用-设计标题` 另写一套平行共性规则。
- 引用通用能力时只按名称引用，不写路径。
## 本层职责

- 保留“AI科幻-设计标题”这一题材入口名。
- 将书名设计的共性骨架路由到 `通用-设计标题`。
- 补充AI科幻题材下的技术切口、数据痕迹常、系统摩擦、数字压迫感与长期谜团承诺。
- 在“全书名 / 分部名 / 分卷名”分层命名中，补充AI科幻语境下的层级约束：
	- 分部名侧重阶段谜团与阶段真相推进
	- 分卷名侧重当前卷技术事件/事件引擎、数据痕迹点或身份反转
- 在需要校准题材定位或故事主轴时，先把命名任务接到 `AI科幻-设计题材定位框架`、`AI科幻-设计故事面`，再回到本技能收口。

## 常见触发词 / 用户说法速查

- 帮我起一个AI科幻书名
- 这本AI科幻该叫什么
- 给我一组更像AI科幻的标题
- 书名要有数据痕迹和数字压迫感
- 帮我筛掉不够题材化的书名

## 何时使用

- 为AI科幻全书、分部、分卷或多平台版本设计标题。
- 重排已有书名方案，强化技术切口、异常数据与系统性危险感。
- 在题材定位或故事面已明确后，为命名做最终收口。

## 分层命名题材补丁（新增）

- 若任务是“只做分部名”，分部名称要体现阶段谜面，不得退化为空洞情绪短句。
- 若任务是“只做分卷名”，分卷名称要能映射当前卷的关键冲突与数据推进，不得写成章节小标题。
- 若任务是“全书 + 分部 + 分卷”一体设计，必须检查三层一致性：
	- 总书名承诺长期悬疑主命题
	- 分部名承诺阶段谜团与阶段回报
	- 分卷名承诺当前卷推进钩子与风险升级

## 不适用情形

- 只写内容简介、推荐文案或章节标题。
- 只做平台输出，不改作品级命名。

## 强制要求

- 命中本技能时，必须优先强制加载当前题材 Skill 与 `通用-设计标题`。
- 书名要让读者一眼认出这是AI科幻，而不是纯科技推理、纯社会派或纯民俗惊悚。
- 优先考虑“职业/身份 + 反常”“数据痕迹编号 + 异常”“数字空间 + 失真”“系统/规则 + 反噬”等命名方向。
- 标题必须能支撑系列级长期传播，不得把单一技术事件钉子句误当成全书总书名。
- 分层命名时，分部名与分卷名必须同时保留“谜面吸引力 + 可兑现回报”的双约束，禁止只给悬念不给兑现路径。
