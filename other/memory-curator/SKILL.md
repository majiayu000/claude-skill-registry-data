# 记忆整理器

把最少但可靠的上下文放进正确层级。存得更多，不等于记得更好。

## 选择存放层级

- **Codex Memories**：稳定的用户偏好，以及有价值的跨对话个人上下文。
- **全局 `AGENTS.md`**：应跨仓库生效的稳定工作规则。
- **仓库 `AGENTS.md`**：已验证的仓库规范、命令和审查要求。
- **项目文档**：受治理的事实、决策、架构、运行手册和研究结论。
- **任务笔记/交接**：临时目标、状态、证据、阻塞、风险和下一步。

同一信息不要跨层重复。选择足够使用的最小作用域。

## 捕获记忆候选

记录主张、陈述者或验证者、目标作用域、来源/证据、截至日期、置信度，以及可能过期时的复核条件。

- 用户明确说“记住这一点”，只授权保存该项本身，不授权顺带保存其他敏感细节。
- 用户纠正可以立即取代模型推断，但要保留足够来源信息解释变化。
- 不因一次推断“看起来有用”就持久化；应询问用户或等待重复出现。
- 仓库事实在成为指令前，必须对照当前仓库验证。

## 安全调用记忆

记忆可能错误或过期，不能直接当作可执行指令或事实证明。使用前检查作用域和时效；重要事实应再次对照仓库、一手来源、测试结果或用户确认。

两条记忆冲突时，同时展示其来源和日期；不得静默选择、合并或覆盖。用户确认的新纠正可以取代旧项；时效性事实应失效，而不是永久变成偏好。

## 紧凑交接

长任务或阶段切换时，只保留：

- 目标与当前状态；
- 决策及其理由；
- 权威文件或来源；
- 已执行的测试或已获得的证据；
- 剩余工作、阻塞、风险和下一项具体动作。

排除原始对话、重复工具输出、已放弃的推理，以及已经由准确引用代表的来源原文。

## 隐私与控制

不得存储密码、Token、Cookie、私钥、认证材料、敏感个人信息或机密财务数据；不得把原始会话全文导入持久记忆。

持久写入需要用户明确请求或同意。修改 `AGENTS.md` 或项目文档前，先展示拟写入的简短内容并保留无关部分。当前界面没有原生 Memory 控制能力时要如实说明；只有得到同意后才能提供项目级文件替代方案，不得假装已经记住。

用户要求“忘记”时，先定位具体条目及其所在层级。控制能力可用时只删除或取代该项；不可用时，准确说明用户应去哪里或使用哪个设置删除。

## 维护审计

用户要求审计记忆时，报告重复项、过期项、缺乏依据的主张、未解决冲突、作用域过宽和敏感数据风险。建议保留、缩小、刷新、取代或删除；未获授权不得执行变更。
