# Agent Orchestrator

这是调度规则，不是运行时、权限系统或后台服务。遵守当前环境和用户的授权边界；加载本 Skill 不会获得额外工具、执行权限或跨客户端兼容保证。

## 1. 定范围，决定是否拆分

- 确认目标、现有项目、可修改范围和验收条件。区分 **分析 / 设计 / 实现 / 审查**；按用户要求交付，不把“设计模块”理解成“实现模块”。
- 关键业务规则、破坏性操作目标或必要输入不清楚时，先问具体问题。可以继续不依赖该答案的安全工作，但不要替用户编造会影响业务结果的规则。
- 简单或紧耦合任务由主智能体完成。确实能减少关键路径或提供独立核验时才拆分，动态选择角色与数量；不固定“设计、开发、测试”三人组。
- 需求清楚就推进。只有用户要求确认方案或现有权限机制要求批准时才加人工关卡；主智能体验收不是向用户逐步求批准。

## 2. 核对工具和资源

准备委派时先读 [运行能力与降级](references/runtime.md)：发现真实的创建、通信、等待/查询、中断能力及其限制，记录工具返回的 agent ID。普通聊天窗口、新任务页面、模型别名都不等于子智能体工具。

若工具、委派授权或必要能力缺失，说明具体限制，改为主智能体分阶段执行；不能虚构创建记录。环境未公开并发上限时明确记为未知，从小批次开始，遇到限额停止新增并回收已完成子智能体，不把试探结果宣称为平台上限。

## 3. 先建依赖，再派任务

- 用 [任务与状态记录](references/ledger.md) 建立轻量任务表：ID、负责人、依赖、允许写入范围、交付物、验收条件、状态。简单任务可直接在回复中记录，无需建文件。
- 由一个主智能体统一拆分、派发、协调和验收。子智能体完成自身任务并上报跨任务问题，不递归委派、不指挥其他执行者，也不替主智能体验收。
- **只有前置成果由主智能体验收通过，依赖任务才可开始。** 前置智能体自报完成不算通过；编码任务必须收到已验收的设计版本。
- 依赖按本阶段真正需要的交付物建立，不按角色、目录或最终调用关系排先后。有调用关系的模块，若已验收的契约足以独立实现和验证，可共同依赖契约并行开发；不要把调用方误设为必须等待被调用方实现完成。涉及模块协作时读 [协作边界与并行](references/parallel-boundaries.md)。
- 前置已满足、能独立交付与验证的任务可并行；同时写同一文件或父子目录视为冲突。由主智能体拆开所有权或串行处理；共享工作区和 Git worktree 都不能替代集成检查。
- 先选择本轮主智能体要推进的工作，再分配独立任务；不要把唯一前置任务派出去后无事等待。

## 4. 分发和推进

按 [任务分发与返回模板](references/dispatch.md) 生成完整、自包含提示词：目标、背景、输入、已验收前置版本、范围/非目标、文件所有权、交付位置、验收/验证、约束、阻塞处理。不假定子智能体掌握完整聊天记录。

记录返回 ID 和执行状态，按真实工具语义通信和等待，避免高频空轮询。等待期间做不冲突的工作。子智能体返回后置为 `submitted`，不直接置为 `accepted`。谁先提交，就先检查谁；有具体问题只派回对应任务，不等无关任务全部结束。验收通过后即可推进已就绪的依赖任务，不设置无必要的整批等待关卡。

失败、超时、工具限额、权限拒绝或阻塞时记录原因，决定补充上下文、缩小任务、改派或向用户说明。缺省每任务最多两次执行尝试（首次 + 一次返工）；有新证据且仍在授权范围内才调整预算，记录原因，绝不无原因重试。

前置设计变化时暂停受影响任务，使用真实工具中断/通知并确认已停，再使旧验收结果失效。验收新版本后，发送变更点和新输入版本，重验受影响的成果。不可一边改接口一边让下游按旧版继续写。

## 5. 验收、集成和交付

按 [验收与报告模板](references/acceptance.md) 检查真实文件、差异、接口/字段/业务规则及命令结果；子智能体的“已完成”“测试通过”只是待核对的报告。

按实际影响选择审查强度：普通小改动由主智能体验收；高风险改动或用户明确要求时安排未参与该改动实现的独立审查者。需要独立审查时读 [风险分级与独立审查](references/review.md)，提供需求、稳定候选版本、改动差异和测试证据；审查意见不替代主智能体的最终验收。能力不足时披露缺口，不把自查声称为独立审查。

不合格时给出具体问题、证据和通过标准，回到 `rework`，再在预算内发起新尝试。修复后核对原问题、修复差异和受影响回归；涉及独立审查的问题要定向复查，新增高风险变化则扩大审查范围。不重复审查无关任务，不重置尝试预算；不得将未通过的结果提供给依赖任务。

所有必要子任务通过后，由主智能体完成跨任务集成检查。单项验收与最终集成分开记录：基于模拟数据、桩或替身通过的模块测试，不等于真实模块已联通。最终报告实际成果、验证证据、未验证部分、残余风险和必要用户决策。分析/设计/审查请求交付对应报告，不借验收之名修改业务代码。

任务表用于记录而非自动恢复承诺；进程重启后须重新核对工具状态、文件和验收证据。需要确定性检查 JSON 记录时，按 [记录格式](references/ledger.md) 使用 `scripts/check_ledger.py`；它不创建智能体，也不能证明记录中的工具调用或测试真实发生。
