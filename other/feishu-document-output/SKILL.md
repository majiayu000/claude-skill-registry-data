# 飞书文档输出

把已有事实、判断和操作材料加工成可直接使用的中文工作文档。重点是文体匹配、事实不变、便于执行和飞书排版稳定，而不是把所有内容套进同一个模板。

## 工作方式

1. 先确认领域内容是否已经足够。缺少事实或分析时，先完成相应领域工作；不要用写作填补证据缺口。
2. 根据读者要完成的任务选择文体。读取 [document-profiles.md](references/document-profiles.md) 中对应部分，并使用其中指向的单个模板。
3. 记录不得改写的内容：数字、日期、版本、专有名词、引用、URL、代码、命令、配置项和明确结论。
4. 先编辑结构，再编辑语言。结论、风险和下一步前置；删除空洞开场、重复总结、口号和机械连接词。
5. 输出飞书友好的 Markdown，并在交付前执行事实与格式检查。

用户指定的结构、语气或模板优先。模板是最低内容检查表，不是必须保留全部标题的固定表单；删除不适用章节，不得编造内容补齐模板。

## 语言要求

- 用具体对象、动作、条件和结果替代“赋能、抓手、闭环、全面提升”等抽象表达。
- 不为了整齐把所有章节凑成三点，也不强行使用“首先、其次、最后”或结尾总结。
- 区分事实、推断、建议和待确认项；保留原有不确定性。
- 不虚构作者经历、语气、引语或现场细节，不故意加入错别字伪装人工写作。
- 操作项同时写验证方式；行动项同时写负责人和期限。信息未知时标记“待确认”，不要猜测。

## 飞书 Markdown 约束

- 正文只有一个一级标题，主体使用二级和三级标题。
- 不输出 YAML frontmatter、原始 HTML 或依赖特定渲染器的扩展语法。
- 列表嵌套默认不超过两层；复杂分支改成小标题或表格。
- 表格默认不超过六列；单元格出现长步骤时改用分节列表。
- 代码使用带语言标识的围栏代码块；命令、配置和输出不要混在同一代码块。
- 链接文字说明目标，不使用连续裸 URL；本地图片或无法访问的附件必须提示。
- Mermaid、复杂公式和交互组件没有经过目标飞书环境验证时，提供文字或静态图降级说明。

## 交付检查

- 锁定内容与来源一致，没有改动数字、版本、命令、引用或结论。
- 文档开头一屏能说明对象、范围、当前结论或读者动作。
- 标题可检索且能概括内容；没有“相关说明”“问题记录”等含糊命名。
- 无空章节、未替换的 `〔填入…〕` 标记、未闭合代码块和失效的内部锚点。
- 只交付一份最终 `.md`；除非用户要求，不同时提供多个近似版本。

只生成文件不代表可以发布。创建或修改飞书在线文档属于外部写入，必须有用户对该动作和目标位置的明确授权。
