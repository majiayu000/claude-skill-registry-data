# MoneyForward 仕訳候補 登録前確認・登録後反映確認

ユーザーが MoneyForward の「自動で仕訳」画面等で見せてきた仕訳候補（スクリーンショット）
について、登録前に内容を確認し、登録後は実際に MCP で反映されたことを検証する、
2フェーズのレビューフロー。

## フェーズ1: 登録前レビュー（画像を受け取ったら）

### Step 1: 内容の整合性チェック

画像から読み取れる仕訳候補について:

- **貸借バランス**: 借方合計 == 貸方合計 になっているか
- **税区分と金額の整合**: 課税売上/課税仕入の税額が金額に対して概ね妥当か
  （10%区分なら税抜金額のおよそ1/11が税額）
- **摘要**: 取引先名・内容が読み取れるか。仕訳Noが振られていれば控えておく
  （登録後の反映確認で使う）

### Step 2: 重複登録の懸念チェック（MCP突合）

`mfc_ca_currentOffice` で認証・会計期間を確認後、`mfc_ca_getJournals` で該当取引日
付近の既存仕訳を取得し、同一取引日・同一金額・同一取引先の仕訳が**既に登録済みで
ないか**確認する。

```
mfc_ca_getJournals { "start_date": "<取引日-7日>", "end_date": "<取引日+7日>", "per_page": 100 }
```

- 同一内容の仕訳が既に存在する → 重複の懸念として報告し、登録を一旦保留するよう伝える
- 存在しない → 登録して問題ない旨を報告

#### 売上の入金は「予定実現」で紐づける（重複と誤判定しない）

MFクラウド請求書から発行した売上（例: 大石運輸倉庫 業務委託料）は、売上計上と同時に
**入金予定の未実現仕訳**（普通預金 / 売掛金、入金予定日付）が自動作成される。
見分け方は `entered_by: "JOURNAL_TYPE_BILLING"` かつ **`is_realized: false`**。

- 未実現仕訳は帳簿・試算表に反映されない → **同額の既存仕訳があっても二重計上ではない**
- 入金明細（「連携サービスから入力」画面）は**新規登録しない**。以下で紐づける:
  1. 「予定実現」列の「実現」にチェック
  2. 勘定科目のプルダウンで紐づける入金予定の仕訳（未実現の No.）を選択
  3. 「登録」
  → 請求書側の入金ステータスも「入金済み」になる
  （公式: https://biz.moneyforward.com/support/account/guide/journal02/infoguideiv_temporary_journalsrenewal_00.html ）
- 「実現」を使わず普通に登録すると、帳簿は正しいが未実現仕訳が残り続け、
  請求書が「未入金」のままになる（2026年5〜8月分 No.59/73/84/87 がこの状態だった → 下記で修正済み）
- 入金予定日（15日）と実際の入金日（10日前後）はずれるのが通常

#### 「実現」を使わずに登録してしまった場合の直し方（2026-10-01 実施済み）

公式FAQ（https://biz.moneyforward.com/support/account/faq/journal/j11.html ）の方法1:

1. `mf-backup` でバックアップ
2. 仕訳帳で、普通に登録した入金仕訳（`JOURNAL_TYPE_NORMAL`）を削除
   → 明細は「未仕訳」ではなく**「対象外」**になる（「連携サービスから入力」には出てこない）
3. 仕訳帳で未実現仕訳を開き「実現」ボタン → 請求書側も「入金済」になる
4. **仕訳帳から実現すると、日付は入金予定日のまま・普通預金の補助科目が空になる**。
   実際の入金日と補助科目（三井住友 残高別普通1672921）に直す（画面 or `mfc_ca_putJournals`）
5. 試算表で売掛金の期末残高が「未入金の請求書の合計」と一致するか確認

請求書は削除しない（削除するのは会計側の仕訳だけ）。

### Step 3: 既存パターンとの比較（定期取引の場合）

取引先・摘要が過去の取引と同じパターン（例: 毎月の業務委託料）に見える場合、直近数ヶ月分
の同種仕訳（勘定科目・税区分・金額）と比較し、パターンから外れていないか確認する。

### Step 4: 結果報告

```
## 仕訳候補レビュー結果

- 貸借バランス: OK / 要確認
- 税区分と金額: OK / 要確認
- 重複懸念: なし / あり（該当仕訳: No.X、YYYY-MM-DD）
- 既存パターンとの整合性: 一致 / 差異あり（詳細）

→ 登録して問題なさそうです。 / この点だけ確認してから登録してください。
```

## フェーズ2: 登録後の反映確認

ユーザーが「登録した」と報告してきたら、実際に MoneyForward 側へ反映されているかを
MCPで確認する。**ユーザーが既に登録済みと言っている場合、`mfc_ca_postJournals` で
自分から新規登録は行わない**（二重登録防止。あくまで確認のみ）。

### Step 1: 該当仕訳を検索

```
mfc_ca_getJournals { "start_date": "<取引日>", "end_date": "<取引日>", "per_page": 100 }
```

取引日をまたぐ可能性がある場合（月末締め等）は前後数日を含めて検索する。

### Step 2: 反映内容の確認

- 該当する仕訳が**1件だけ**存在するか（重複登録されていないか）
- 借方/貸方の勘定科目・税区分・金額がフェーズ1で確認した内容と一致するか
- `entered_by` / `is_realized` 等のフィールドで想定通りの状態か

### Step 3: 結果報告

```
## 反映確認結果

仕訳No.<number>（取引日: <date>）が正しく1件だけ反映されています。
- 借方: <account_name> <value>円 <tax_long_name>
- 貸方: <account_name> <value>円 <tax_long_name>
```

重複や不一致があれば、その旨を明確に報告する（このスキル自身では削除・修正操作は
行わない。修正が必要な場合は `mf-backup` でバックアップを取ってから対応する）。

## 注意

- **このスキルは仕訳を新規作成・変更しない**。読み取り専用の確認のみを行う
  （登録操作は必ずユーザー自身が MoneyForward Web 画面で行う）
- フェーズ1とフェーズ2は別ターンで実行されることが多い（ユーザーが画面を見せる →
  実際に登録する、の間に間隔が空く）。それぞれ独立して呼び出せるようにする
- ユーザーが「登録した」と言った直後にフェーズ2を実行する場合、MoneyForward側の
  反映に若干のタイムラグがある可能性がある。0件でもすぐに「反映されていない」と
  断定せず、再取得を促す
- 一括の突合チェック（課税仕入の仕訳に請求書PDFが揃っているか等）は
  `mf-invoice-check` を使う。本スキルは「今まさに登録しようとしている1件」の
  ピンポイント確認用
- `mfc_ca_postJournals` を呼ぶ判断が必要な場面（ユーザーから明示的に登録を依頼された
  場合）は、必ず `mf-backup` を先に実行してからにする
