# Capture

The exploring phase. Only one job: get material out of the writer's head and onto
disk, before any structure can make the missing things invisible.

Structure comes later, in `writing-outline`. Premature structure is the enemy: the
moment material is grouped or sequenced, the gaps stop showing. Resist it.

1. Start from whatever the user already said and keep them talking. Push for the
   concrete: the example, the number, the scene, the line they would actually use,
   the moment that made them want to write this. An abstraction is a placeholder,
   not a fragment.
2. Every time a keeper appears — from the user or from you — append it verbatim to
   one markdown file. A fragment is one sentence, one line, one image, one scene.
   Never clean it up on the way in; cleaning is later work.
3. If the user gave no path, ask once where to save, then remember it.
4. First write: a single H1 working title and nothing else. No metadata, no
   sections, no dates.
5. Stop when the user stops producing. Say what still isn't in the pile (a missing
   antagonist motive, no ending in sight) — naming a gap is capture's other job.

## What is a fragment

A fragment is any text that might survive into the final piece. The bar is "would
the author recognize this as good raw material", not "is this a self-contained
argument". It may be illegible to a cold reader; it must be legible to its author.

Deliberately heterogeneous. What qualifies:

- A sharp sentence with no home yet.
- A claim plus its one-line justification.
- A vignette, an anecdote, a code snippet, an overheard line.
- A half-thought: "something about how X feels like Y — work this out later."
- A contradiction the writer can't resolve yet.
- A complaint, a confession, a punchline.
- A **leading word**: a coinage or borrowed metaphor the whole piece could hang on
  (one term that names the idea, the way _tracer bullets_ names a whole pattern).

Of these, the leading word is the most valuable fragment to land. Name the right
one here and it shapes structure, transitions, and title downstream. When the
conversation circles a recurring idea, push to coin the word for it.

For fiction, fragments include the same material wearing different clothes: a
line of dialogue, a character's tell, an image, a "what if", a setting detail
that carries mood, a scene ending. Capture them identically.

## File format

```markdown
# Working title

A first fragment lives here. It can be multiple paragraphs, or one line.

---

A second fragment.

---

> A quote the user wants to keep around.

A reaction to it.

---

- A cluster of related observations
- That hang together by feel
- And want to be near each other
```

Separated by `\n---\n`. No headings inside the body, no tags, no order beyond
arrival order.

## Rhythm

Append silently as keepers appear — "adding that" in passing, not a save dialog.
Before every write, re-read the file from disk: the user may have edited,
reordered, or deleted fragments between turns; their changes win. Never
overwrite. Only append, or edit a specific fragment in place when asked.

"Cut the last one", "sharpen that one", "merge those two" are first-class
instructions at any time.

## Out of scope

Grouping, labeling, ordering, outlining, and evaluating quality. If the user asks
"which of these are any good?", that is the boundary: name that shaping is next
and offer `writing-outline`.
