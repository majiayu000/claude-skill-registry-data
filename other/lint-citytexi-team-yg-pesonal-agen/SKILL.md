# lint — 위키 상태 점검 워크플로우

`wiki/` 전체를 점검해 문제를 보고한다. 세부 규칙은 항상 `wiki/CLAUDE.md`(위키 스키마)를 따른다.

## 실행 순서

1. **`python3 wiki/script/lint.py`** — 기계 검사(민감패턴·frontmatter·링크 무결성·의존 방향·
   고아/약연결·raw 정합·출처 추적·status). 위반 0건까지 고친다. 매번 임시 스크립트를 새로 짜지 않는다.
2. 스크립트가 못 하는 항목만 읽어서 판단 — 아래 점검 항목 2(모순·해소분 하류 반영)·5(데이터 공백)·6(stale).

## 검사 제외

`wiki/templates/`·`wiki/script/`는 스키마 산출물이다. **고아 페이지·깨진 링크·frontmatter·status 검사에서 제외**한다(플레이스홀더 링크가 오탐을 만든다). 단 템플릿 자체가 현행 스키마와 어긋나면 항목 6(stale)으로 잡는다.

## 점검 항목

1. **민감 데이터**: 이메일·전화번호·API 키·비밀번호 패턴 탐지. **발견 시 자동 수정 금지** — 파일명:줄번호를 사용자에게 보고하고 처리 방법(삭제·마스킹·private 폴더 이동)을 확인한다. 처리 전까지 커밋 금지.
2. **모순 감지**: 같은 주제 페이지 간 상충 내용 → `open-questions.md`에 미해결 항목 등록.
   - **해소분 하류 반영도 함께 본다**: 상태가 `해소됨`으로 바뀐 항목의 결론이 관련 concept·entity
     페이지에 실제로 반영됐는지, `⚠️` 마커가 제거됐는지 확인. (신규 모순만 보면 "해소됐는데
     개념 페이지만 옛 서술"이 남는다 — 2026-07-27 정렬 기준·2-1 스태거 사례.)
3. **고아·약연결**: 인바운드 0 = 위반, 1(대개 index만) = 참고(편입 검토).
4. **링크 없는 언급**: 페이지 없이 언급만 되는 엔티티·개념. 페이지 생성 임계 기준 충족 시 생성 권고, 미달이면 무시.
5. **데이터 공백**: 채울 수 있는 빈 영역 또는 조사 권고 주제.
6. **stale 정보**: 최근 원본과 모순되는 오래된 내용.
7. **판본 상태(`status`) 무결성**: **`python3 wiki/script/check-status.py`를 실행한다.** 눈대중 금지.
   `sources/` 프론트매터 `status`가 단일 진실, `index.md`는 투영. 스크립트가 검사하는 것 —
   필드 누락 / 값 오류 / `superseded`·`partial`의 `superseded_by`·`scope` 누락 / 깨진 참조 /
   `superseded_by` 체인이 `current`에서 끝나는지(사이클·끊김) / 역방향 정합 / index 투영 불일치.

   **파일명 계열로 대체 관계를 추론하지 않는다** — `superseded_by` 명시가 유일한 근거. 이 항목은 자동 수정 후 보고 가능.
8. **출처 추적(provenance)**: `concepts/`·`entities/` 본문이 인용한 `[[소스]]`가 프론트매터 `sources:`에도 있는지. 없으면 소스 개정 시 하류 페이지를 역추적 못 한다.
9. **의존 방향**: 정책 콘텐츠 페이지(`concepts`·`entities`·`sources`·`overview`·`open-questions`)가 구현 문서(`parfait/` 등)를 링크하지 않는지. 위키는 플랫폼 비종속이어야 하며 참조는 **구현 → 위키 단방향**. 위반 시 링크를 지우고 "플랫폼 + 심볼" 데이터 서술로 바꾼다.

## 출력

`wiki/synthesis/lint-YYYY-MM-DD.md`에 `wiki/CLAUDE.md`의 보고서 템플릿대로 저장한다.
완료 후 `log.md` 끝에 `## [YYYY-MM-DD] lint | 점검 완료, N건 발견` 기록.
