# AIGC Character Sheet

Persona Blueprint：从人脸设计到完整角色设定表的可复用工作流。

标准工作流的最终产物是 **Character reference sheet**，核心是设计有辨识度、能持续复用的人物及其统一设定。单个人物同样是完整任务。日韩可爱轻修图是可选风格，批量是可选功能，不把所有请求转成造脸库。

## 标准主流程

1. **先生成人脸。** 按气质、骨相、妆容和风格制作清楚的人脸基准图；有用户指定的现成人脸时可复用。只要文字设计时仍只交付文字。
2. **用户 approve。** 展示基准图，等待用户明确认可这张脸。未认可时只按反馈改脸，不提前生全身或设定表；修改后的候选重新等待认可。
3. **服装输入。** 认可后请用户上传服装参考图，或明确回复“无输入/无/你搭配”。没有附件不等于无输入。用户已经给过服装或明确授权自行搭配时沿用，不重复询问；参考图若有人，只取服装，不带入其人脸。
4. **生成最终设定表。** 读取 [角色设定表](references/character-sheet.md)，将已认可的人脸作为身份锚点，结合服装参考或授权补全的搭配生成白底写实三视图、六表情、服装/设备细节与配色板。用户有反馈则定点修正设定表；交付该表及其可复用记录即完成主流程。

阶段和输入记录见 [工作流合同](references/workflow.md)。最终设定表之后不默认续做场景图、自拍或视频；只有用户额外要求时才继续这些扩展。

## 本轮任务与锁定项

先判断当前用户要文字设计、图片生成还是图片编辑。“设计角色、改 prompt、更新 Skill”交付文字/文件；明确要求实际出图或编辑图片才调用图像工具。不因上一轮生过图或工具可用就自动出图。缺工具时给完整 prompt，不声称出图。

内部记录本轮目标、数量、已选人物、已知/未知结构、允许变化项、妆容与风格；不要求用户填表。

- **原创单人：** 将气质转为一套具体结构与妆容，先读 [人物结构](references/character-structure.md)。选择一个主导表现路径，避免全脸所有部位同时强化。
- **固定脸换妆/换场景：** 锁定人物已知骨相、软组织、五官、基础肤色与标记，实际引用该人的基准图。未知的眼窝/面中深度保持未知，不借补全结构之名改脸。
- **同妆不同脸：** 先固定同一套妆容的六项合同，再设计不同结构，按相对位置适配；读 [妆容适配](references/makeup-adaptation.md) 和 [不同脸检查](references/design-contract.md)。
- **局部修改：** 只改指定项，交付完整新稿。例如只换唇色不能顺带改变唇形、光泽、唇缘、眼妆或拍摄。
- **多人物/批量：** 仅在明确需要不同人物时使用阵容规则与 [可选规划器](references/batch-cast.md)。同一人的变体、亲缘相似不强行拉成不同脸。
- **角色设定表：** 以用户已认可人脸为基础，服装输入/无输入已确定后制作，见 [设定表模式](references/character-sheet.md)。不要绕过主流程中的脸部认可或服装选择。

参考图分别标明身份、妆容、风格或构图用途；“只参考妆容”不能把参考人物的脸一起带过去。图区分可见、推测、未知，不把侧光阴影当成确定骨相。

## 始终保留的当前偏好

人脸基准照、三视图的正面与六表情特写，默认头部端正、双眼水平、下巴中性、直视镜头，不随机歪头或斜相机。设定表的侧面保持真实90°侧向，背面保持真实背向，不为直视镜头回头；所有视图头部都自然端正。自然面部不对称可保留，不要求镜像复制两只眼。

所有最终图片与生图 prompt 均要求无可见文字、无手写署名、无水印、无标志/账号。不得带入参考项目的作者署名；文档里的 MIT 版权说明是合法来源标注，不是画面元素。

人物年龄、性别呈现、基础肤色、发色沿用用户选择，不因气质或日韩风格自动改成唯一脸型、冷白皮或固定年龄。未指定时使用成年虚构角色；不将“可爱”解释成未成年化。

## 设计顺序

1. **人物结构。** 原创人物分别确定整体比例、眉骨/眼窝、颧部、下颌/下巴及软组织，写相对宽度、位置和过渡。柔和、圆润也能有明确结构；不默认深眼窝、高颧骨、尖下巴。再选眼鼻唇与自然眉形。固定脸或局部修改不触发原创补全。
2. **妆容与气质。** 在不改脸的前提下，按视觉目标选择妆的落点、方向、颜色与材质。淡妆/日常妆/浓妆只是强度，不能代替具体妆容。先选一个主要重点，其余配合。
3. **风格与肤质。** 按本轮请求选择自然、编辑、复古、自定义方向，或 [日韩轻修图预设](references/social-style.md)。风格、修图强度、妆容、基础肤色四者分开；没有指定时用干净、克制的人像表达，不自动追加“可爱网红”。
4. **取景与交付。** 人脸基准可用 4:5 头肩浅色背景；主流程最终设定表默认白底2:1横版，三视图、六表情和细节分区清楚。生活自拍、镜面自拍、他拍与视频首帧只在额外提出时处理，视频扩展见 [视频交接](references/video-handoff.md)，未实际出视频不声称时间一致性已验证。
5. **检查。** 核对用户锁定、骨架/软组织/妆光是否混淆、妆容是否适配、头姿目光与无文字要求。不同人物按全阵容逐对检查，不只比较首人或最近十二人。可用 `python3 scripts/check_design.py PLAN.json` 检查已编码条件；它不判断图像质量或骨相语义。

## 保留干净的摄影质感

少量尺度合适的低对比细节足够，不同时堆叠毛孔、泛红、眼下纹理和斑点；不主动增加噪声、颗粒或重复细纹覆盖。出现“脏感”时先处理色偏、斑驳与过强微对比，不用更多瑕疵强化真实，也不直接把整张脸磨平。

光源需要有来由，脸、颈肩与场景曝光相容。唇釉的局部高光不等于全脸油亮；清透不等于提白。修图可以整理色彩与细节，不能把不同角色统一缩鼻、瘦脸、放大眼睛。

“减少 5%–10% 真实感”仅是日韩轻修图预设的主观尺度，不是通用默认或 API 数值。不要编造模型参数或从外观认定具体模型。调用图像工具时遵循可用的 imagegen 指引，本地图先查看，参考图通过真实图像输入提供，不只在文字里写“同一个人”。

## 输出

默认一句角色方向与一个完整中文 prompt；用户要求英文时再给英文。提示词按人物结构→妆容→表情造型→必要拍摄组织，优先本轮硬约束，合并重复形容。多角色每人独立完整，修改后给完整新稿，不写“其余同上”。不默认展示 JSON、评分或内部检查表。

通用模板见 [提示词](references/prompts.md)；需要可用创作起点时读 [融合后的四份案例 prompt](references/integrated-prompts.md)，按当前人物与拍摄要求适配，不无条件套用整段。

用户已认可的三种实际成图、精确执行 prompt 和图像文件已固化，按需读 [已认可样例](references/approved-examples.md)。新人物可复用风格配方，不默认复用样例的脸；用户明确选中某人时才引用其图片锁定身份。它们不限制其它风格，也不构成视频效果验证。

新增三套人脸→设定表的实测记录见 [公开示例](references/public-examples.md)，只在需要复现风格或布局时读取；新人物不默认继承样例人脸。

已认可的六表情设定表、原始人脸与实际执行 prompt 见 [设定表案例](references/approved-character-sheet.md)。通用模板只复用布局、内容要求与一致性方法；不强制新人物沿用案例的年龄、五官、蓝衣白裤或日韩风格。

用户明确要“陪我走一遍流程”时，读 [逐步引导](references/guided-session.md)。按当前阶段给一份具体可修改的方案，询问影响结果的少量偏好，不一次抛出整张参数表；用户要求直接出图时不额外增加确认步骤。

只有实际出图后才检查、保存图片并报告可见结果；文字差异不等于图片异脸，固定身份指令不等于同脸保证。失败优先单点修正，通常至多两次后说明问题，不无限重试。不自动启动大量生成。
