# 투고 묶음

원고를 투고하기 직전의 일을 맡는다. 투고 판을 동결하고, 투고처가 받는 파일을 모두 만들고, 익명성과 사실과 규정을 점검하고, 투고 화면에 넣을 값을 정리한다. 제출은 사용자가 한다(공통 규칙 6). 이 스킬은 그 직전 단계까지 준비한다. research-session의 공통 규칙을 따르고, 진행은 research-session 8절의 틀로 보인다.

원고 내용은 이 스킬 전에 고정되어 있어야 한다. 내용을 고치는 일은 paper-quality-loop, paper-readability, paper-condense가 맡는다. 심사 뒤의 수정본 제출은 rebuttal이 고친 원고에 이 스킬을 쓴다.

## 0. 시작할 수 있는 조건

아래 가운데 하나라도 맞지 않으면 시작하지 않고 이유를 알린다.

- 원고의 고정판이 있다(paper-quality-loop 3절, rebuttal 7절까지 마친 수정본, 또는 사용자가 고정한 판의 경로와 해시).
- 투고처가 정해졌다. research-portfolio의 투고처표나 프로젝트 설정의 원고 절에 마감, 쪽 상한, 익명 여부, 템플릿이 적혀 있다.
- 투고처 규정(저자 안내, 템플릿, 익명 규정, 재현 자료 규정)을 이번 세션에 원문에서 확인했다. 열지 못하면 그 항목을 "가정"으로 적고 사용자에게 확인을 요청한다.

## 1. 동결

1. 투고 폴더를 만든다: `<원고 폴더>/투고/<투고처>-<YYYY-MM-DD>/`.
2. 고정판을 그대로 복사하고 원본의 경로와 해시를 `동결.md`에 적는다. 여기서부터 원고 내용을 고치지 않는다. 고칠 것이 나오면 고정판에서 고치고 다시 동결한다.
3. 숫자 대장(fact-check 2절)과 결과 파일의 커밋 해시를 `동결.md`에 적는다.
4. 동결 시각과 판을 현황과 승인기록에 적는다.

## 2. 만들 것

투고처가 받는 것만 만든다. 대개 다음과 같다.

| 산출 | 내용 | 점검 |
|---|---|---|
| 일반본 PDF | 저자, 소속, 감사의 글이 있는 판 | 템플릿, 쪽 수, 글꼴 포함 |
| 익명본 PDF | 익명 심사용 판 | 3절 익명 점검 |
| 보충 자료 | 부록, 추가 표, 증명 | 본문이 가리키는 번호와 맞음 |
| 재현 자료 | 코드와 자료의 익명 저장소나 압축 파일 | 4절 |
| 투고 화면 값 | 제목, 초록, 키워드, 주제 분류, 저자 순서와 소속, 이해 상충, 추천 심사자와 제외 심사자, AI 사용 고지, 자료 공개 문장 | 5절 |
| 편지 | 편집자에게 보내는 글(투고처가 받을 때) | 주장 목록과 같은 크기 |
| 수정본일 때: 변경 표시본, 답신, 대응표 | rebuttal이 만든 것 | 대응표의 각 항목이 가리키는 원고 위치가 수정본과 맞음, 답신과 대응표의 내용이 같음 |

빌드는 실제 투고 클래스와 글꼴로 한다(paper-condense 6절). 두 판을 각각 두 번 빌드해 쪽 수, 오류, 미정의 참조, overfull이 없는지 본다.

## 3. 익명 점검

익명 심사 투고처면 익명본과 재현 자료에서 다음을 모두 본다.

1. 본문: 저자 이름, 소속, 감사의 글, 과제 번호, "우리가 앞서 보인", "우리의 이전 연구" 같은 자기 지시. 자기 인용은 투고처 규정대로 3인칭으로 쓴다.
2. PDF 메타데이터: 작성자, 제목, 만든 프로그램, 경로. `pdfinfo`나 같은 도구로 보고, 비우는 명령으로 지운다.
3. 그림과 표: 그림 안의 글자, 스크린샷의 사용자 이름, 파일 경로, 기관 로고.
4. tex 원본을 함께 내면: 주석, 판과 심사와 관문의 이력, `\author`, 글꼴 경로의 사용자 이름.
5. 재현 자료: 4절 4번의 금지어 검사.
6. 링크: 개인 저장소, 개인 홈페이지, 실명 계정이 드러나는 URL.

찾은 것과 고친 것을 `익명점검.md`에 표로 남긴다. 금지어는 프로젝트 설정의 지킬 것과 `code/scripts/export-artifact.sh`의 목록을 함께 쓴다.

## 4. 재현 자료

1. 프로젝트에 `code/scripts/export-artifact.sh`가 있으면 그것으로 `code/`만 새 이력으로 뽑는다. 작업 저장소의 이력, 교류 기록, AI 흔적을 넣지 않는다.
2. 자료는 공개 가능한 것만 넣는다. 원자료를 넣을 수 없으면 받는 법과 전처리 스크립트를 넣는다.
3. README에 환경, 설치, 한 명령으로 주요 표를 다시 만드는 법, 걸리는 시간을 적는다.
4. 금지어를 검사한다. `export-artifact.sh`가 뽑을 때 한 번 거르고, 3절 익명 점검의 금지어(프로젝트 설정의 지킬 것, 저자와 소속, 과제 번호)로 한 번 더 거른다. 찾은 것은 고치고 다시 뽑는다.
5. 새로 띄운 에이전트가 README만 보고 빈 환경에서 주요 숫자 하나 이상을 다시 만든다(공통 규칙 3). 숫자가 원고와 같은지 fact-check로 대조한다. 다시 만들지 못하면 그 사실을 사용자에게 알린다.
6. 익명 저장소 서비스에 올리는 일과 공개 범위를 정하는 일은 사용자가 한다. 이 스킬은 올릴 폴더와 금지어 검사 결과까지 준비한다.

## 5. 투고 화면 값

투고 화면에 넣을 값을 `투고화면.md`에 한 곳에 모은다. 사용자가 복사해 붙일 수 있게 칸마다 글자 수 제한과 현재 글자 수를 적는다.

- 제목, 초록은 동결한 원고와 글자 하나까지 같아야 한다. 차이를 스크립트로 비교한다.
- 키워드와 주제 분류는 투고처 목록에서 고른다. 목록을 열지 못하면 "가정"으로 적는다.
- 저자 순서, 소속, 교신저자, ORCID는 사용자가 확인한다. 도구가 채우지 않는다.
- 추천 심사자와 제외 심사자, 이해 상충은 사용자가 정한다. 도구는 투고처 규정과 칸만 준비한다.
- AI 사용 고지, 자료 공개, 연구윤리 문장은 원고의 문장과 같게 쓴다.

## 6. 마지막 점검

새로 띄운 에이전트가 투고 폴더만 보고 다음을 점검한다. 만든 쪽이 채점하지 않는다.

| 항목 | 통과 조건 |
|---|---|
| 쪽 수, 단어 수, 초록 길이 | 규정 안 |
| 템플릿과 글꼴 | 투고처 클래스, 글꼴 포함 |
| 익명 | 3절 항목 모두 0건 |
| 사실 | 동결판 대비 fact-check 차이 0, 원자료 검산 불일치 0 |
| 인용 | 참고문헌 항목 모두 실재, 확인 수준이 비어 있는 것 0 |
| 보충 자료 | 본문이 가리키는 번호가 모두 있음 |
| 재현 | 빈 환경에서 주요 숫자 1개 이상 재현 |
| 투고 화면 값 | 제목과 초록이 원고와 같음, 글자 수 제한 안 |
| 고지 | AI 사용, 자료 공개, 연구윤리 문장이 투고처 요구대로 있음 |
| 수정본 | 대응표 항목마다 원고 위치가 맞음, 변경 표시본이 수정본과 같은 판 |

하나라도 통과하지 못하면 고치고 다시 점검한다. 고칠 수 없는 것(규정을 열지 못함, 재현 불가)은 사용자에게 보인다.

## 7. 사용자에게 넘기기

마침 보고로 넘긴다. 사용자가 할 일을 순서대로 적는다.

```
== 끝 | <프로젝트> | 투고 묶음: <투고처> | HH:MM (걸린 시간 n분, 어림 n분) ==
결과   : 일반본 10쪽, 익명본 10쪽, 보충 자료 6쪽, 재현 자료 1, 투고 화면 값 14칸
확인   : 마지막 점검 9/9 통과, 익명 0건, fact-check 차이 0, 재현 숫자 2개 일치
바뀐 것: 투고 폴더 1 (아래 링크)
남은 것: 사용자 할 일 4건
         1 익명 저장소에 재현 자료 올리기  2 저자와 소속 확인
         3 추천 심사자 정하기  4 제출
다음   : 제출하면 제출 시각과 접수 번호를 알려 주면 승인기록과 현황에 적는다
```

제출 뒤에 사용자가 알려 주면 제출 시각, 접수 번호, 제출한 파일의 해시를 승인기록, 현황, research-portfolio의 연구 지도에 적는다. 제출 확인 메일이나 화면을 보지 못했으면 "사용자 보고"로 적는다.

## 8. 하지 않을 것

- 제출 버튼을 누르지 않는다. 투고처 계정에 들어가지 않는다.
- 동결한 뒤 원고 내용을 투고 폴더에서 고치지 않는다.
- 추천 심사자, 저자 정보, 이해 상충을 도구가 정하지 않는다.
- 익명 저장소 서비스에 올리지 않는다.
- 규정을 확인하지 못한 항목을 확인한 것처럼 적지 않는다.
