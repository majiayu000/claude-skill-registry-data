# Code Review

При ревью кода проверяй каждую из областей.

## Цель
Найти дефекты в корректности, безопасности, качестве и производительности до слияния изменений.

## Функциональность
- [ ] Код делает то, что заявлено в описании задачи/PR
- [ ] Граничные случаи обработаны
- [ ] Обработка ошибок корректна и не «глотает» исключения

## Безопасность
- [ ] Нет секретов и учётных данных в коде
- [ ] Пользовательский ввод валидируется и экранируется
- [ ] SQL-запросы параметризованы, нет инъекций

## Качество
- [ ] Соответствует стилю проекта
- [ ] Нет хардкода, который должен быть конфигурируемым
- [ ] Функции сфокусированы и хорошо названы

## Тестирование
- [ ] Новая функциональность покрыта тестами
- [ ] Тесты осмысленны, а не ради покрытия
- [ ] Существующие тесты проходят

## Производительность
- [ ] Нет очевидных узких мест
- [ ] Нет избыточных вычислений в циклах

## Формат результата
Группируй находки по критичности: **Critical / Major / Minor**. Для каждой —
конкретное исправление.
