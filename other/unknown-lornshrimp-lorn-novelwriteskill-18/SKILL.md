# 通用-审阅总大纲
> **题材路由**：若 .github\题材专用Skills\ 目录存在对应的 <题材>-审阅总大纲 Skill，则：
> - 将题材特性骨架路由到 <题材>-审阅总大纲，该 Skill 位于 .github\题材专用Skills\ 目录。
> - 命中本技能时，必须优先强制加载当前 Skill 与 <题材>-审阅总大纲。


> **头号要求：禁止吹捧，客观分析。** 审阅中不得出现无依据的称赞、吹嘘性描述或主观美化。所有判断必须基于文本事实、可验证标准与明确扣分依据，优先指出问题与改进方向。

总纲审阅看的是这组文件能不能作为全书战略蓝图，而不是文案好不好看。

## 总纲包对象边界（强制）

- `小说总大纲.md` 默认承载小说的主线故事，是主线推进、阶段里程碑与终局收束的基准文档。
- `故事面/` 下各文件默认主要承载支线故事；它们不是主线总纲的注释页或拆分副本，而是各自能成立、能持续供血的完整故事文件。
- 审阅时必须同时判断：主线与支线是否相互交织、相互联系、相互推动，并共同服务全书长期连载。
- 不得因为 `小说总大纲.md` 与 `故事面/` 共享人物、事件、线索、阶段节点，就直接判成“重复维护”；这通常是主支线联动的正常设计结果。
- 只有当多份文件在没有新增职责差异的前提下机械重复同一信息，或彼此口径冲突、互相打架时，才可判为冗余维护或总纲层不一致。

## 继续读取的 references（强制读取门禁）

**以下所列 references 文件必须通过 `read_file` 工具逐文件读取，不得因"已有相关知识"、"之前执行时已读过"、"该文件只是参考"为理由跳过任何一条。** 每条 references 按其标注的必读等级强制执行：

- 标注 **必读** 的文件：必须读取，少一条即视为流程违规，不得开始执行流程。
- 未标注必读的文件：必须读取，但读取后可仅提取与当前任务直接相关的段落，不要求逐字通读。
- 若文件路径指向的文件不存在（如引用的外部路径未就位），必须在日志中显式记录 `reference_missing_{refName}`，不得静默跳过。

每个参考文件在 `## 默认执行顺序` 中有对应的读取步骤说明，此处仅汇总文件清单与用途概览。

- `references/总纲审阅专属检查清单.md` — 逐项检查清单（含商业节奏、情绪刺激密度、市场定位三步审阅等扩展检查项），在步骤 2 通读总纲包时逐条核对
- `references/总纲审阅完整模板.md` — 审阅报告的**主骨架**，在步骤 4 构建报告时加载（完整覆盖阅读链路确认、概览复核、P0 工程化核查、题材专项核查、超长篇工程化、系列连贯性、机制递进、时间线、主题承诺、商业节奏与情绪刺激密度审阅、问题分级、评分、具体回写建议等）；不得退化成简版报告
- `../../写作研究/网文留存模型.md` — 留存评分共享基线，定义留存工程审计的量化依据与平台基线，在步骤 3.6 留存工程审计前加载
- `references/总纲审阅报告增补.md` — 报告骨架的补充字段 / 扩展版本，在步骤 4 中与完整模板交叉对照，补充题材专项段与总纲层专项评分项
- `references/腾讯专栏总纲审阅阶段规划与长线供血增补.md` — 跨平台通用：总纲的阶段规划（新书期/上架期/稳定期）与中段长线供血检查，在步骤 3.2 加载

## 默认执行顺序

总纲审阅按以下步骤执行，每一步标注了应读取的参考文件：

### 步骤 1：审阅前准备
1.1 确认总纲包对象范围（至少包括 `小说总大纲.md`、`故事面/`、`伏笔与回收总纲.md`），收集所有待审文件的路径。
1.2 若项目根存在 `Agents.md`，执行 `## 风格/蓝本/写作研究模板自动发现规则` 并加载对应的蒸馏模板对标维度。
1.3 加载 `references/总纲审阅专属检查清单.md`，作为逐项核对的底表。

### 步骤 2：通读与结构核验
2.1 完整通读总纲包全部文件，不做中断判断。重点确认：总纲包对象边界（主线 vs 支线职责）、M0 / X / C 体系完整性、四阶段机制递进、单元案矩阵供血逻辑。
2.2 执行"一句话概括验证"：当前总纲能否用一句话说清"主角是谁、在什么处境下、想要什么、被什么阻挠"。
2.3 执行"市场定位三步审阅"：人物代入感审查 → 剧情关注点映射审查 → 设定冗余度审查。

### 步骤 3：专项审阅
3.1 情绪节奏审阅：检查全书是否存在长时间单一情绪、卷级情绪底色是否明确、情绪转折是否有钉子事件。
3.2 加载 `references/腾讯专栏总纲审阅阶段规划与长线供血增补.md`，按新书期 / 上架期 / 稳定期评估总纲的阶段规划与中段供血链。
3.3 执行起点爆款总纲快筛（10 秒快筛 + 3 分钟深评），按潜力分档（S/A/B/C）辅助判断。
3.4 若加载了蒸馏模板对标维度，按蒸馏对标审阅规则执行对标审计。
3.5 **执行主角主动性与主线清晰度审阅**（吸收自知乎《最近弃了七本书》核心教训）：
   - 检查主角在每卷中是否有明确的**主动目标**——目标是否是主角自己想要、而非系统/外部事件强塞的。
   - 检查主角行为链中是否存在连续3章以上的"纯被动反应"窗口（只有防卫/应对/接任务，没有主动选择/出击）。
   - 检查总纲章清单中是否存在"日常碎片堆砌"——章节推进靠"又发生了一件事"而非主角的主动决策驱动。
   - 检查是否出现同一桥段指纹的过度重复（同一情节模式在一卷内出现≥2次、在全书中出现≥4次而未做变异设计）。
   - 以上各检查项的问题均标注来源层：`[主角主动性] / [主线清晰度] / [桥段重复]`。
3.6 **执行留存工程审计**（新增——从读者留存角度审查总纲的底层设计，回答"这本书凭什么让读者持续追下去"）：
   - **总纲层留存基线检查**：
     - 总纲是否规划了全书层面的情绪刺激点分布（小刺激点 ≥1 个/章、中刺激点 ≥1 个/3-5 章、大刺激点 ≥1 个/卷）？
     - 前 N 章留存工程：首卷是否有至少 3 个可指认的"值回时间"回报点？前 5 章是否有"冲突→应对失败→更深层冲突→反击信号"的递进结构？
     - 平台留存适配：若目标平台为七猫/番茄，总纲的回报密度设计是否达到免费平台的留存基准；若为起点，总纲的中段讨论点设计是否充分
   - **主角主动性卷群审计**：
     - 每卷是否都有主角的主动目标（不是系统/外部事件强塞的任务）
     - 是否存在连续 2 卷以上主角处于纯被动反应状态的窗口
   - **情绪节奏总纲审计**：
     - 全书是否至少有两种大情绪底色交替（不是全程爽或全程憋）
     - 卷级情绪底色是否形成对比与递进
     - 情绪转折点是否由具体的钉子事件驱动
   - **留存风险红灯**（总纲层，参照 `../../写作研究/网文留存模型.md` §5.3）：
     - [ ] 是否存在连续 2 卷以上主角无主动目标的设计窗口
     - [ ] 全书情绪底色是否单一（只有"爽"或只有"压抑"中的一种）
     - [ ] 首卷前 5 章是否无法满足目标平台的留存基线
     - [ ] 中段（30-80 万字区间）是否存在超过 2 卷的回报预留真空
   - 以上各检查项的问题均标注来源层：`[留存工程总纲层] / [留存工程卷群层]`。

3.7 **执行倒推验证检查**（新增——吸收自知乎南梦·超长篇构思）：从终局出发反向验证总纲的结构完整性与逻辑连贯性。

   **检查项一：终局画面锁定检查**
   - 审阅总纲包中是否描写了全书结局的最终场面与情感落点？如果只有"主角赢了""大团圆"这种抽象描述，而非一个可被"看见"的具体场面，标记"终局画面缺失→方向锚点不明确"为 Critical。
   
   **检查项二：反推前提验证**
   - 假设终局画面成立，逐卷验证"要到达这个终局，前一卷必须完成什么前提"：
     - 倒数第 1 卷的前提：倒数第 2 卷是否完成了？
     - 倒数第 2 卷的前提：倒数第 3 卷是否完成了？
     - 依此类推，一直推到首卷。
   - 如果倒推过程中发现某卷的前提条件在该卷中不存在（前后不连贯），标记"逻辑前提断裂→卷间衔接缺失"为 Critical。
   
   **检查项三：冗余分卷检查**
   - 用倒推法检查：如果去掉某一卷，终局是否仍然可达（只是路径不同），还是根本不可达？
     - 去掉后可到达→该卷可能存在冗余，标记"分卷冗余→缺乏存在必要性"为 Warning。
     - 去掉后不可到达→该卷是关键节点，标记通过。
   
   **检查项四：主支线终局归拢检查**
   - 所有支线的终局是否也在终局画面中找到了归拢位置（即支线结局不影响主线终局的推进，但至少应在主线终局中留下痕迹）？
   - 如果某条支线的结局完全独立于终局画面之外，标记"支线独立游荡→未归入终局"为 Warning。

   以上各检查项的问题均标注来源层：`[倒推验证]`。检查项一/二命中任意一项按 Critical 处理，检查项三/四按 Warning 处理。

### 步骤 4：构建审阅报告
4.1 加载 `references/总纲审阅完整模板.md` 作为报告主骨架。
4.2 交叉对照 `references/总纲审阅报告增补.md`，补写题材专项段、总纲层专项评分项与题材化结论重点。
4.3 确保报告完整覆盖：阅读链路确认、概览复核、P0 工程化核查、题材专项核查、超长篇工程化、系列连贯性、机制递进、时间线、主题承诺、商业节奏与情绪刺激密度审阅、市场定位审阅、情绪节奏审阅、一句话概括验证、卖点保真检查、问题分级、评分、具体回写建议、要求对照、执行顺序、总体结论。
4.4 给出 Green / Yellow / Red 战略入库判定。

### 步骤 5：评分与总体结论
5.1 按检查清单逐项评分（综合评分不低于 9.20 的为高可用总纲）。
5.2 每个问题标注来源层：`[总纲结构层] / [卷群分配层] / [执行接口层]`。
5.3 输出最终审阅报告，附蒸馏对标结论（若已执行）。

## 作者风格画像嵌入与审阅回流（自动）

  - **审阅回流（S5 触点）**：审阅结论交付后，作者取舍（坚持 / 反驳 / 采纳）的原话 → 按 L2 模板归档样本库 + 立场回填母题层 / 显影层

## 风格/蓝本/写作研究模板自动发现规则

若当前服务的项目根目录存在 `Agents.md`，审阅总纲前必须：

1. 读取项目根目录的 `Agents.md`；若其中声明了 `主输出平台`，检索三类模板时优先匹配"适用平台"与主输出平台一致的模板，无匹配时回退到"适用平台：默认"的同类模板
2. 若 `Agents.md` 中注册了"写作研究模板"——读取对应路径的模板文件，将其作为题材×平台总纲审阅基线
3. 若 `Agents.md` 中注册了"作者风格模板"——读取对应路径的模板文件，将其作为文风承诺、人物声口与叙事距离适配审计依据
4. 若 `Agents.md` 中注册了"作品蓝本模板"——读取对应路径的模板文件，将其作为跨卷节奏、信息释放、回报间隔与钩子轮换审计依据
5. 本 Skill 只消费与总纲审阅相关的字段；若模板字段与总纲主模板或平台硬规则冲突，平台硬规则与总纲主模板优先
6. 若项目根目录不存在 `Agents.md`，或其中未注册对应模板——回退通用默认模式，不报错，不阻断

本 Skill 默认消费字段：

- 写作研究模板：平台结构要求、开篇策略、题材承诺、爽点密度、禁忌类约束
- 作者风格模板：整体文风、叙事距离、对话风格配置、禁忌清单
- 作品蓝本模板：场景节奏分布、信息释放节拍、中段回报指纹、章末钩子指纹、情感弧分布

### 对标审阅执行规则

1. **对标优先度**：作品蓝本模板（结构层对标） > 写作研究模板（平台/题材约束对标） > 作者风格模板（文风基线对标）。若注册了多个同类模板（如多蓝本合成），以合成条目为优先参照。
2. **评分影响**：蒸馏产物对标维度在总纲审阅综合评分中默认按 **25%** 计权。若未完成对标审阅或关键维度偏离显著，综合评分默认不得给高档。
3. **缺模板回退**：若缺少某类蒸馏模板，该对标维度自动跳过，不扣分，不阻断，但需在审阅报告中标记为"蒸馏对标盲区"。
4. **冲突处理**：若蒸馏产物的约束与平台硬规则或总纲主模板冲突，平台硬规则优先。蒸馏产物约束之间冲突时，写作研究模板的硬门禁 > 作品蓝本模板的强约束 > 作者风格模板的软建议。

## 完整模板执行要求（强制）

- 产出总纲审阅报告时，必须以 `references/总纲审阅完整模板.md` 作为主骨架，不得退化成“几段摘要 + 几条建议”的简版报告。
- 报告至少要完整覆盖：阅读链路确认、概览复核、P0 工程化核查、题材专项核查、超长篇工程化、系列连贯性、机制递进、时间线、主题承诺、**商业节奏与情绪刺激密度审阅（含情绪刺激密度、爽点/虐点三阶布局、前N章留存工程、更新可复制性、平台节奏适配——参照 `总纲审阅专属检查清单.md` §十）**、问题分级、评分、具体回写建议、要求对照、执行顺序、总体结论。
- 若当前任务还加载了题材 Skill，则必须在通用完整模板的占位章节中继续补写题材专项段、题材专项评分项与题材化结论重点。
- 若缺少题材专项段，仍必须保留该章节标题并明确说明“待题材 Skill 补写”，不得直接删章。

## 市场定位审阅——总纲的读者向商业向审查（新增）

审总纲时，除了检查结构完整性，还必须从市场定位角度审查：这份总纲是不是"动笔的是你，但看的人是读者"。

### 市场定位三步审阅

**第一步：人物代入感审查**

- 总纲是否显式标注了目标读者群体？若只写了"面向大众读者"或类似空泛表述，视为市场定位缺位。
- 主角设计是否能让目标读者产生"这不就是我吗"的代入感？检查主角的核心欲望、初始处境、痛点是否与目标读者群体的日常焦虑或渴望形成映射。
- 若人物设计可以在不提目标读者群体的前提下看起来"也成立"，说明读者代入感定位仍然缺位，应判为市场定位层风险。

**第二步：剧情关注点映射审查**

- 主线核心冲突是否直接命中目标读者最想看的那个"翻身时刻"或"破局瞬间"？
- 总纲中的剧情设计是否来自目标读者的日常关注点（焦虑什么、渴望什么、想打破什么），还是只是作者的自我表达？
- 若主线剧情删掉目标读者关注点后仍然"通顺"，说明剧情不是从读者情绪长出来的，应判为市场定位层风险——这通常是"明明文笔不差但内容就是没看点"的根本原因。

**第三步：设定冗余度审查**

- 总纲中的设定是否每一处都在给人物增添色彩、给剧情加张力？逐条检查是否有"与人物和剧情都无关"的设定堆砌。
- 开篇设定密度是否过高？检查前三章是否出现大量背景铺垫、世界观说明或人物设定罗列——不管什么题材，没人会看这种开头。
- 若总纲层设定条目数量远超人物和剧情能承载的范围，判为设定冗余风险。

### 市场定位验收判定

- 若总纲无法回答"目标读者翻开前三章后，凭什么觉得这本书是写给他的"，总纲市场定位未达标。
- 若人物设计、剧情设计与设定设计三者中有任一项脱离目标读者群体独立存在，总纲不得判为市场定位合格。

## 情绪节奏审阅（新增）

总纲审阅必须把情绪节奏作为独立审计维度。大部分网文中期卡文的原因不是情节想不出来，而是**情绪节奏断掉了**——整个故事变成了一种情绪颜色。

### 审阅维度

1. **情绪交替检查**：全书是否存在长时间单一情绪（连续多卷全是"爽"或全是"憋"）？三种情绪（爽/憋/揪心）是否在卷群层面有交替？
2. **卷级情绪底色**：每卷是否有明确的情绪底色？卷与卷之间的情绪底色是否形成对比与递进？若连续 2 卷以上使用相同情绪曲线（都是压抑→反击），判为情绪节奏单一。
3. **情绪转折标记**：总纲是否标记了情绪从哪里开始转变？转折场景是否承担"钉子"职责——正式写到这里时，所有内容应靠向这个转折？
4. **情绪检验**：把自己想象成不认识这本书的读者，从头读大纲，感受是否有情绪波澜。若读完大纲情绪是平的，没有任何波澜，说明故事还没有找到它的心脏——这不是大纲详细与否的问题，而是故事本身没有温度。

### 情绪节奏问题的典型信号

- "明明文笔不差，读者追到一半就弃了" → 检查情绪是否只有一种颜色
- "中段章节推进很多，但读起来很平" → 检查是否只有情节推进没有情绪变化
- "读者反馈说'后面越来越没意思'" → 检查情绪曲线是否从卷初到卷尾都在同一水平线上

### 情绪节奏判定

- 若总纲情绪旋律单调（只有"爽"或只有"压抑"中的一种），判为 `P1` 节奏风险
- 若连续多卷使用同一种情绪曲线模板，判为长线节奏疲劳风险
- 若总纲读完后情绪无波澜，判为"故事未找到心脏"，需优先回炉

## 一句话概括验证（新增）

审阅总纲时必须执行一句话验证：

1. 当前总纲能否用一句话说清"主角是谁、在什么处境下、想要什么、被什么阻挠"？
2. 这句话是否写在了 `小说总大纲.md` 的最顶上作为锚点？
3. 若写不出来，说明总纲的核心定位还不够清晰——因为说不清楚的故事，在推荐机制里很难传开。
4. 若这句话存在但总纲内容经常偏离它，说明总纲各卷的设计方向没有对准同一个核心承诺。

### 一句话验证验收

- 总纲审阅报告必须包含"一句话概括"验证结论：通过 / 不通过
- 若不通过，需说明当前最接近核心的一句话是什么、缺失了什么要素

## 卖点保真要求（强制）

- 审阅时必须单独判断主卖点是否突出鲜明，能否被编辑和读者快速识别。
- 必须检查主卖点是否已经进入 `M0 / X / C`、卷群推进与终局闭环，而不是只停在定位口号。
- 若中段多卷无法说明卖点如何持续供血，应判为结构性风险，而不是轻描淡写带过。

## planner / reviewer 镜像补强（新增）

- 审总纲时，默认不只看 `M0 / X / C` 和四阶段递进，还要检查这份总纲是否具备可持续维护的**规划归档骨架**：模板组合声明、章节规划表、`TODO` 状态、章节摘要入口、节奏地图、悬念 / 伏笔追踪、决策日志与最小进度快照。
- 若总纲只会讲故事方向，却没有把后续怎么拆章、怎么维护、怎么防三连重章疲劳写进结构层，默认不得判为成熟战略蓝图。
- 审阅报告里的问题默认标记来源层：`[总纲结构层] / [卷群分配层] / [执行接口层]`。总纲结构层负责主线、主题、生长逻辑；卷群分配层负责卷群与章节波形；执行接口层负责下游能否直接拆成分卷 / 控制卡 / 正文。
- 默认补一个 `Green / Yellow / Red` 战略入库判定：`Green`=结构、追踪器、节奏地图与执行接口齐备；`Yellow`=主干稳定但追踪器或接口仍虚；`Red`=主支线职责混乱、章节规划表缺失、三连重章风险无人接管、主题靠口号硬压人物。
- 审总纲时还要复核“主题是否从人物故事自然长出”；若删掉主题句，故事就站不住，说明这份总纲的主题层仍然偏假。

## 网文长线与签约预判（强制）

- 审总纲时，必须把它视为“是否值得编辑签、是否撑得住长期付费连载”的战略蓝图，而不是单纯结构草图。
- 必须显式判断：`一句话记忆点/题材稀缺度`、`首卷承诺`、`平台主口径`、`中段多卷耐力`、`开篇承诺到终局兑现的一致性` 是否已经在总纲层定型。
- 若总纲出现“首卷很亮、中段断供、终局另起炉灶”或“概念很多、动作很空、人物像功能按钮”的 AI 式总纲病，必须判为战略层风险。

## 起点爆款总纲快筛与潜力分档（新增）

总纲审阅除工程结构外，默认还要回答一个更现实的问题：**这份总纲像不像能在起点竞争位里活下来的蓝图**。

### 10 秒快筛（总纲版）

把当前总纲当作编辑刚拿到的项目蓝图，默认先做一次 `10` 秒级判断；命中以下 `3` 项及以上弱信号时，总纲默认不得判高档：

1. **题材归类是否瞬时成立**：是否能在一句话里说清这是哪种书、主卖点是什么、为什么现在值得写。
2. **题材赛道是否有现实胜算**：是否处在起点当前活跃赛道或平台扶持窗口内；若属于过热老套路，是否拿得出明确差异化路径。
3. **首卷承诺是否锋利**：总纲是否能让人立刻知道首卷靠什么抓追读，而不是“后面会越来越精彩”。
4. **主角抓手是否成立**：主角是否具备低起点、强动机、鲜明方法论与可持续成长空间，而不是只在设定表里强。
5. **长线供血是否一眼可见**：是否看得出中段 `3-5` 卷以后还靠什么持续供血，而不是只有开局点子亮。

### 3 分钟深评（总纲版）

若通过快筛，默认继续做一次 `3` 分钟深评，把爆款判断标准翻译成总纲层审阅问题：

- **题材潜力**：该题材在起点榜单 `TOP50` 是否具备活跃度与持续新作供给；若赛道内卷，总纲是否显式写出反超路径。
- **开篇承诺**：是否明确保证前 `200` 字有钩子、前 `300` 字扔炸点、前 `1000` 字亮金手指或给出等效回报预期。
- **金手指/核心机制**：是否符合“极简逻辑 + 极强变现力”；若设定过于复杂、读者无法瞬时理解，判为快审风险。- **人物关系优先性**：人物是否走在情节前面——即"如果删掉某个人物，情节线是否仍然完整成立？"如果答案为"是"，说明该人物尚未真正织入故事。反之，如果情节改动后人物关系网络完整成立，则关系设计合格。- **三幕比例**：前期 `20%`、中期 `60%`、后期 `20%` 的供血比例是否成立；若中段明显偏空，判为长线疲软风险。
- **IP 伸展性**：是否自然具备卷级高光、关系站队点、短剧/有声/动漫改编友好节点；这不是加分项本体，但可用于判断商业上限。

### 起点潜力分档（总纲审阅辅助口径）

除 `Green / Yellow / Red` 战略入库判定外，按起点口径审总纲时，默认允许再给一层“总纲爆款潜力档位”判断：

| 档位 | 判断标准 | 审阅含义 |
| --- | --- | --- |
| S | 题材归类强、首卷承诺锋利、中段供血清晰、主角抓手硬、终局回收可见 | 这份总纲具备明显的竞品压制潜力 |
| A | 主干稳、首卷与中段可用，存在 `1-2` 个结构短板但可快速修复 | 有较强签约竞争力，但仍需补强 |
| B | 总纲可读，但首卷承诺 / 中段耐力 / 主卖点兑现中至少一项偏弱 | 可继续打磨，但现在还不够强 |
| C | 题材口径虚、首卷承诺钝、中段断供或终局另起炉灶命中两项以上 | 这份总纲会拖累整书竞争力，应优先返工 |

该分档只用于补充回答“这份总纲对爆款链路的助推强度”，不得替代完整审阅结论与问题分级。

### 10 万字中期验证（总纲版）

审总纲若服务起点口径，默认还要回答：**这份总纲是否为前 `10` 万字的增长链路提前留好了结构位**。报告至少补查：

1. 前 `15` 章是否承担清晰分工（拉新 / 稳留 / 转付费），而不是全部挤在“介绍设定”。
2. 首卷与第二卷之间是否存在自然放大关系（不是换地图式硬切）。
3. 中期阶段是否预留至少 `2` 处高光回报位与 `1` 处更贵缺口位。
4. 若当前总纲进入中盘，是否仍能持续制造讨论点与站队点，而非只剩流程推进。

若这四项中有两项以上无法回答，默认判为“中期增长结构不足”，不得给高档战略判断。

### 起点推荐机制映射审阅（新增）

- 总纲审阅时，默认补查“内容结构是否可映射到起点推荐链路”：`新书入库 -> 一轮 -> 二轮 -> 三轮 -> 四轮/上架 -> 智能推荐`。
- 至少回答三件事：
	1. 首卷是否明确承接前期推荐位对追读密度的要求；
	2. 中段是否预埋可支撑推荐放大量的回报节点与争议节点；
	3. `10` 万字后是否存在稳定供血设计与更新执行接口，避免智能推荐期快速失温。
- 若总纲无法解释“推荐位提升后流量进来要看什么、为何会留下”，默认判为商业化结构风险。

### 传播讨论点 / IP 放大口径（总纲版）

总纲审阅时，默认补一条商业放大判断：

- 是否存在天然可传播节点：身份翻面、规则反常、立场站队、关系裂变、制度反噬、社会面冲突；
- 是否存在卷级可改编高光：卷首抓入、卷中爆发、卷尾反转、终局回收；
- 若改编友好度不足，最先该补的是“高光事件密度”还是“可视化载体设计”。

该口径用于回答“这份总纲能不能放大”，不替代结构自洽与供血能力的基础审阅结论。

## 极其快节奏与极其强冲突审阅门禁（新增）

总纲审阅必须把“快节奏 + 强冲突”从写作偏好提升为工程门禁。以下项目默认强制核查并给出明确结论：

### 快节奏总纲审阅门禁

- **卷首启动速度**：首卷前三章职责是否成立（麻烦入场、正面碰撞、首次升级/回报）。若首卷在第 4 章后才进入核心冲突，判为 `P1`。
- **中段供血密度**：是否存在连续多卷“只推进不兑现”。若任意阶段出现连续 `4+` 章等效“无新变量/无回报/无升级”的规划段，判为 `P1`。
- **卷尾交接强度**：卷尾是否只做收束而无新缺口。若卷尾无法回答“下一卷必须立刻处理什么”，判为 `P1`。
- **钩子链完整度**：是否同时存在开篇钩子链、卷内钩子链、长线钩子链。缺任一链路，判为结构风险。

### 强冲突总纲审阅门禁

- **冲突层级递进**：是否具备“外部压迫 → 内部撕裂 → 价值选择”递进。若长期停留在单一外部对抗，判为 `P1`。
- **冲突升级闭环**：是否做到“解决旧冲突会触发新冲突”。若多数冲突彼此平行、互不触发，判为 `P1`。
- **代价可验证性**：是否把代价写成可回指后果（资源损失、关系翻面、身份暴露、规则反噬）。若只有“很痛/很惨”抽象描述，判为 `P1`。
- **对手结构完整性**：是否至少存在卷级对手、跨卷压强、终局敌对与主角自我敌对。若仅靠单一反派支撑全书，判为长线风险。

### 快冲突审阅评分卡（总纲层）

以下维度默认纳入综合评分：

| 维度 | 权重 | 过线标准 |
| --- | --- | --- |
| 启动速度与中段密度 | 20% | 首卷快启 + 中段无连续塌陷 |
| 冲突递进与升级闭环 | 25% | 冲突可级联，不是平行摆放 |
| 代价与后果可验证 | 15% | 关键代价可回指到卷级后果 |
| 卷尾续读与跨卷交接 | 15% | 每卷末都有“更贵缺口” |
| 卖点与冲突绑定 | 25% | 卖点由冲突持续显影与兑现 |

若“冲突递进与升级闭环”或“卖点与冲突绑定”任一项不达标，综合评分默认不得给高档。

### 审阅报告必须回答的问题（新增）

- 这份总纲的“快”是信息快、事件快，还是冲突升级快？若只是信息快，必须指出伪快节奏病灶。
- 这份总纲的“强冲突”是吵闹冲突，还是带代价的结构冲突？若无可验证代价，必须降级判定。
- 当前最该优先回写的 `3` 个冲突节点是什么？各自的最小补丁动作是什么？
- 若要求 `72` 小时回炉，应优先改哪一卷、哪一段链路，才能最快抬升追读与签约通过率？

## 题材竞对分析接入要求（强制）

- 若当前任务服务某个题材，且该题材目录下的 `竞对分析/` 已存在与当前项目、当前平台或当前赛道相关的竞对分析报告，审阅前必须先读取并纳入对照。
- 若工作区中存在蒸馏产物（通过 `Agents.md` 注册的蒸馏作品蓝本模板、蒸馏作者文风模板、蒸馏写作研究模板，或 `写作研究/`、`调研报告/` 等目录下的蒸馏/研究报告文件），审阅前必须优先将其作为竞对对比的核心依据；蒸馏产物中封装的叙事结构约束、风格基线、题材×平台约束等可直接转化为竞对维度评分参照，使竞对判断更准确、更深入、更可举证。
- 若已配置主输出平台，且当前题材目录下尚无可用竞对主报告，审阅前应优先调用 `通用-分析竞对作品` 补齐最小结论集；若任务限制导致本轮无法补齐，必须显眼记录盲区，并下调本轮审阅上限与置信度。竞对分析的目标平台由主输出平台配置决定。
- 审阅报告不得只给内部自洽结论；必须显式判断当前总纲相对竞对在哪些维度已领先、持平或落后，以及最先该补哪条超越路径。
- 若当前总纲在竞对已验证的关键强点上明显更弱，必须直判为竞争风险；总纲审阅的默认目标是推动当前作品在关键维度上**全方位超越竞争对手**。
- 默认按“严酷找差距”口径执行：重点写清当前总纲为什么还赢不过已过审竞对，不得为了安抚作者把明显落后项写成“后面再补也行”的轻问题。
- 竞对维度在总纲审阅综合评分中默认按 `25%` 计权；若未完成量化差距卡，或关键维度仍显著落后且没有 `72` 小时补丁，综合评分默认不得给高档。

## 平台竞对吸收口径

当已配置主输出平台时，默认把竞对对照拆成以下四层，并翻译成评分判断与补丁建议。具体平台术语与指标由主输出平台对应的 `通用-输出*版` Skill 提供：

- **市场数据层**：用平台关键指标代理信号反推这份总纲是否真的支撑题材归类、首卷交易效率、持续付费价值与长线商业厚度。
- **内容创作层**：重点对照主样本在主线承诺、人物驱动、`M0 / X / C` 供血、四阶段机制递进、单元案矩阵与终局闭环上的成熟度，把差距翻成总纲级与卷群级补丁。
- **运营策略层**：重点对照主样本如何制造首卷追读工程、中段供血、卷尾续购缺口、推荐位适配与读者讨论点，把差距翻成阶段波形、卷群排布与回报密度补丁。
- **受众反馈层**：重点对照平台读者高频被夸的抓手、被骂的中段断供病灶、读者对"概念很大但人物像按钮"的敏感点，把差距翻成避坑与加码建议。

- 帮我审总纲
- 看看这套全书总纲稳不稳
- M0 / X / C 有没有问题
- 这总纲能不能撑长篇

## 何时使用

- 审阅总大纲、故事面、伏笔总纲、故事多面体或相关总表级文件。
- 检查主线谜团 `M0`、重要支线 `X`、单元案矩阵 `C` 是否稳定供血。
- 产出可直接落库、可直接回写的总纲审阅报告。

## 报告落盘位置与命名规则（强制）

- 总纲审阅报告必须直接落在项目根下的 `审阅意见/` 目录中，不再额外下沉到总纲专用子目录。
- 总纲审阅报告文件名必须带日期，日期格式固定为 `YYYY-MM-DD`。
- 推荐完整相对路径写法为 `审阅意见/总纲审阅报告_[对象名]_2026-04-15.md`。
- 总纲包本体文件（总纲、故事面、伏笔总纲、故事多面体及相关总表）默认不带日期；日期只用于对应审阅报告。

## 默认执行顺序

0. 若已配置主输出平台且当前题材目录下缺少可用竞对主报告，先调用 `通用-分析竞对作品` 补齐最小结论集。竞对分析的目标平台由主输出平台配置决定。
1. 先确认审阅范围是否真的是总纲包，并区分 `小说总大纲.md` 的主线职责与 `故事面/` 的支线职责。
2. 若已配置主输出平台，先吸收竞对主样本四层结论，并写清本轮审阅重点比对的关键项。
3. 再检查四阶段机制递进与 `M0 / X / C` 关系，以及主支线是否相互交织供血。
4. 再判断单元案矩阵供血能力、跨卷推进与终局闭环。
5. 最后按报告增补输出最小补丁方案。

## 默认输出口径

- 默认输出一份带对象判断、结构风险、卖点风险与最小回写建议的总纲审阅报告。
- 默认同时输出：问题来源层、战略入库判定、`72` 小时最小补丁链与最先要回写的总纲层位置。
- 默认不直接重写总纲本体，除非用户明确要求边审边回写。
- 若已配置主输出平台，报告还必须显式覆盖竞对对照维度的关键项。若未指定目标平台，可标注"本轮不适用"。

## 固定输出骨架（强制）

总纲审阅报告默认按以下固定顺序输出，除非用户明确要求改版式，否则不得跳步或乱序：

1. **快筛结论**（10 秒）：先给“能不能过快审”的结论与阻断项。
2. **深评结论**（3 分钟）：再给结构、供血、冲突、卖点、竞对对照的核心判断。
3. **分档结论**：给 `Green/Yellow/Red`；若已配置主输出平台，可额外补充该平台的特定潜力档位并写明依据。
4. **最小补丁链**：给"先改哪 `3` 处、每处改什么动作词、为什么先改它"。
5. **72 小时动作**：给按优先级排列的短期回炉顺序与预期抬升项。

若未指定目标平台，仍按同一骨架输出；其中竞对或平台字段可标注"本轮不适用"，但不得删掉骨架步骤。

## 最低交付

- 能指出总纲包对象是否完整、`M0 / X / C` 是否成立。
- 能指出 `小说总大纲.md` 与 `故事面/` 的职责边界是否清楚，主支线是否互相推动而不是互相抢位。
- 能指出卖点供血、跨卷推进与终局闭环的关键风险位。
- 能给出最小可回写补丁，而不是只给“总体可用 / 不可用”的结论。

## 复审独立性规则（强制）

- 每一轮总纲审阅都必须把当前版本当作新的审阅对象，重新独立、从严、完整地审一遍，不得把“上一轮问题修没修”当作本轮高分的主要依据。
- 核查上一轮提出的问题是否修复是必要步骤，但这只是一项基础核验，不足以替代本轮对结构、卖点、递进、供血、闭环与可回写性的全面复审。
- 若本轮发现新的结构性问题、遗漏点、弱化段或新的卖点失踪风险，必须如实写入本轮报告，不得因为上一轮修复较多就淡化、跳过或自动抬分。
- 本轮评分只能依据当前版本在本轮完整审阅下的实际表现给出，不得按“修复比例”“改动辛苦程度”或“上一轮分数惯性”顺推加分。

## 审阅重点

- 对象定义是否清楚
- `小说总大纲.md` 与 `故事面/` 的职责边界是否清楚
- 主线与支线是否形成交织推进，而不是各写各的或互相抢位
- 主卖点是否清晰可感、可被快速归类
- 首卷承诺、平台主口径与签约窗口是否明确
- 四阶段机制递进是否完整
- 单元案矩阵是否持续供血主线
- 长篇耐力与中段失温风险是否可预判
- 卖点是否持续供血并被阶段性回收
- 推荐机制映射是否成立（新书四轮、上架、智能推荐对应的结构承接）
- 总纲级连贯性与可回写性是否成立

## 硬规则

- 禁止只评价“设定很多 / 格局很大 / 很有野心”这类抽象印象。
- 若按起点口径执行，禁止跳过 `Top10 候选池 → 3–5 本主样本 → 四层对照` 就直接给高分或高档判断。
- 禁止把 `小说总大纲.md` 与 `故事面/` 默认判成重复维护；先判断它们是否分别承载主线 / 支线的完整故事职责。
- 必须落到对象、结构、供血、闭环与回写动作。
- 必须明确说明这份总纲更偏哪类平台、编辑会先记住什么、首卷承诺与终局是否同向。

## 与其他 Skill / Prompt 的边界

- 本 Skill 负责总纲层审阅与回写建议，不直接代替总纲重写。
- 若用户要直接搭建或重写总纲，应优先使用 `通用-设计总大纲`。
