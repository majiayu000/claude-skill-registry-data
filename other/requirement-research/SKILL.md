# 需求调研分析Skill

## 适用场景
业务方提出的需求模糊、缺少背景与数据支撑,需要通过访谈、问卷、数据分析等方式澄清真实问题与目标,输出可支撑后续用户故事拆解的调研结论。

## 执行步骤
1. 明确调研目标:列出待澄清的问题清单,区分「必须澄清」(影响方案走向)与「可以后置」。
2. 设计调研手段:访谈(1v1/焦点小组)、问卷、竞品体验、历史数据分析,按问题类型匹配手段。
3. 编写访谈提纲:每类受访者一套提纲,单题聚焦一件事,避免诱导式提问(如"你是不是觉得XX不方便"改为"你最近一次使用XX的场景是什么")。
4. 执行调研:记录原话与场景细节,标注「事实」与「受访者观点」,不混写。
5. 整理与归纳:按主题聚类原始信息,提炼需求点 → 问题 → 根因三层结论。
6. 输出调研报告并确认:结论回述给业务方确认,标注遗留问题与责任人。

## 规范要点
- 每个结论必须有出处:访谈原话、数据来源、样本量与样本偏差都要写明。
- 区分「用户说想要的」与「用户真实需要解决的问题」,结论落到问题层,不直接落到功能层。
- 样本代表性声明:调研样本量过小时,明确写"仅代表部分用户,结论待验证"。
- 需求点须带优先级标记(高/中/低)与影响范围,为后续拆分做准备。
- 调研过程数据(录音、问卷原始记录)归档保存,保证可追溯。

## 输出模板
```
# [主题] 需求调研报告
1. 调研目标与问题清单
2. 调研方案(手段/对象/样本量/时间)
3. 原始信息整理(按主题聚类,附出处)
4. 需求点清单(需求 → 问题 → 根因,含优先级)
5. 结论与建议(可支撑的决策/待验证假设)
6. 遗留问题与责任人
```

## 自检清单
- [ ] 每个结论有出处(原话/数据/来源)
- [ ] 结论落在问题层而非功能层
- [ ] 样本量与偏差已声明
- [ ] 访谈提纲无诱导式提问
- [ ] 需求点含优先级与影响范围
