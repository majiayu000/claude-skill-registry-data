# 实时能量 VFX 研究

将参考画面的视觉问题映射到可阅读的实现，帮助选择后续原型和 Forge 渲染路线。根据用户指定阶段交付；研究阶段不擅自扩展到 MOD 编码、游戏启动或部署。

- [references/catalog.json](references/catalog.json)：来源、许可依据、源码符号、迁移边界、优先级和阶段验收，适合更新研究台。

## 分析参考

先读取用户需求，再按视频时间窗口或图像区域记录事实。检查参考是否是实时游戏、离线渲染、素材合成或不明来源；仅凭外观不能确认流体求解器。需要运动判断时查看连续帧，注明采样方式与未观察范围。

分开描述：形状/密度主体、粗尺度卷动、细节侵蚀、三维细丝、气态外晕、辅助颗粒、冲击环/壳、世界背景扭曲、发射/Bloom、生命周期与质量预算。可依据需求只研究相关层。

## 选择技术与阅读源码

优先提供“视觉问题 → 技术 → 已实际阅读的文件/符号 → 学什么 → 平台迁移 → 许可 → 下一步实验”。选择完整源码或作者论文配套实现；推荐依据可以是实现完整性、算法地位、可解释性与版本相符，不仅是 Star 数或成品相似度。

能量核心的合理起点通常是局部三维密度场、flow noise/侵蚀、发射吸收积分与少量连续三维丝。薄壳护盾可以选择表面路径。确有持续输运或障碍物交互需求时，再研究二维或三维流体；不要默认每个技能都有独立三维求解器。

重要边界：

- 噪声平移、flow noise、速度场积分与流体平流是不同机制。curl/noise 无散场不会自行产生聚合；加入径向吸引场后，不再宣称整体无散。势函数空间调制后取旋度与直接缩放速度也不同。
- fBm 提供尺度层次，不自动等于卷吸。坐标 warp 后的导数若未经链式法则处理，不应宣称是原空间的精确导数。
- 局部体积积分需要视线与域交点、相机入域处理、世界深度限制和与步长一致的密度/发射权重。
- 材质 UV 扭曲、密度域扭曲和世界背景采样分开。背景采样需要稳定颜色副本和遮挡约束，禁止采样当前写入附件。
- emission、Bloom、体积散射和地形动态照明分别评估。关闭 Bloom 与辅助粒子后，主体仍应满足结构目标。
- 时域积累要处理技能移动、缩放、爆发、遮挡变化和传送；天空云假设不能直接用于局部技能。

## 迁移与证据

Forge 1.20.1 使用 Java 17 与对应 Forge 分支。研究 Veil、Shimmer、Photon、Lodestone 时核对构建文件；新分支功能不自动存在于旧版。compute/SSBO 需要 OpenGL 能力查询与替代路径，不能从 Minecraft 版本推断其可用。

记录世界颜色/深度、Shader/RenderType、FBO 生命周期、资源重载、窗口 resize、透明合成和状态恢复的接入需求。未构建或未运行游戏时，只称工程设计或静态检查，不声称兼容或达成目标帧率。

性能先估算屏幕覆盖×步数×密度成本、同屏实例和三维格网容量；估算与 GPU 测量明确分开。后续原型应支持按层开关、固定 seed/time、旋转相机、背景切换与回放。
