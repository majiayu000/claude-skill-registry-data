# 无对白动画总流程

## 开始
用户只给主题时，读取项目已有episode.json、characters.json与series-log.json，复用已确认角色。首次没有角色资产时先调用character-bible定稿；不凭空假定已有图片。默认约70秒、9:16、无对白双主角反差喜剧。
详细字段及交接见[工作流契约](references/workflow.md)，开始或恢复时读取。原手册观察数据仅是待核验参考，不能拿来保证产量、流量或一致性。
## 调度
依次使用同级已安装技能：character-bible → story-writer → visual-comedy-director → scene-generator → animation-prompt → sound-designer → video-editor。需要合集且单集齐备时调用ops-compiler。读取实际SKILL.md再执行；若缺失，报告具体技能，不假装执行。
首次角色与分镜由用户确认后再批量生成；已有确认与预算授权沿用，不重复询问。先用少量连续镜头试跑，再扩展。声音方案可提前准备，但最终卡点需等实际视频。
每步更新清单及真实产物路径，角色/分镜改变时标出受影响素材，保留无关通过镜头。中断恢复先检查文件和已提交任务，避免重新生成收费。
用户只要求文本策划时，允许draft角色设定进入编剧和分镜，不要求角色图片；产物保持待审核，不能据此进入媒体生成或标记成片完成。用户只要求某环节时停在指定范围。工具不可用时完成独立可做的文本工作，明确阻塞；不能承诺文字Skill自动获得媒体能力。
## 完成条件
单集只有真实MP4导出并读回参数、完整视听审核后才能称为完成；输出位置、质量缺口、实际费用（仅引用工具可核实数据）一并说明。合集另行验收；默认不发布。

## 项目约定
本技能服务双主角反差、无对白视觉喜剧系列；默认约70秒、9:16竖屏，结尾留钩子。用户的新要求优先。保持已确认角色与画风，不把示例角色强加给其他项目。
每集在用户项目目录保存产物；镜号采用S001等稳定编号，修改内容不随意改号。沿用episode.json清单：episode_id、theme、target_duration_s、character_version、story_path、shots_path、audio_path、output_path、status。首次单独调用时只建立实际需要的文件，不要求先完成全部流程。
路径必须指向真实文件；未完成用null或“待生成”，不用虚构链接。提示词、生成素材、审核通过、导出成片是不同状态。已获授权内继续工作，不重复确认；付费工具遵循实际工具报价与授权流程。
