# xLua Unity/C# Lua 绑定方案 技能卡

## 基本信息

- **中文名称**：xLua Unity/C# Lua 绑定方案
- **来源仓库**：[Tencent/xLua](https://github.com/Tencent/xLua)
- **上游参考分支**：`master`
- **参考提交（使用前核对）**：`59bf42685dbe36fe0e1678a6ba8597f859ef7ca3`
- **许可证线索**：MIT；third-party 组件按 LICENSE.TXT 分别遵循；文件：`源码\LICENSE.TXT`

## 功能概览

1. 在 Unity/C# 中加载 Lua 脚本并调用 C# 类型、方法、属性和事件
2. 支持自定义 struct、委托、泛型/适配器和热更新脚本组织
3. 提供 Unity 工程、运行时库、示例和构建脚本

## 适用范围

- 用于 Unity 托管层脚本策略、配置、热更新和 C#/Lua 互调。

## 不能替代的边界

- 不提供 IL2CPP native 函数定位、进程注入、内存读写、游戏线程自动调度、设备控制、协议或业务成功证明；脚本线程与 GC 需由宿主约束。

## 输入与输出合同

```text
输入：Unity/C# 宿主、Lua 脚本、生成/适配配置、版本和线程上下文。
输出：Lua 返回值、C# 回调、绑定错误、GC/性能日志和脚本状态。
失败：Lua/C# 类型不匹配、生成代码/版本不一致、线程错误或脚本异常时隔离脚本并记录堆栈。
后置：输出必须绑定项目、目标版本、平台/ABI（如适用）、时间戳和证据路径。
```

## 接入原则

1. 核对实际源码版本与说明中的参考提交后，先做最小、可撤销、可回放的接入。
2. 任何地址、线程、设备、模型、资源或协议输入都必须记录来源、版本和后置状态。
3. 工具输出是候选或观测，必须与项目专项规则、状态机和真实成功证据交叉验证。
4. 失败时保留原始错误和现场证据，不把命令退出码、识别命中或 Hook 安装当作业务成功。
5. 与 Luau/sol2 是不同宿主路线；xLua 只负责 C#/Lua 绑定，不替代 IL2CPP 运行时桥接。

## 与 Codex 项目路由的边界

- `l-gameassist`：负责游戏目标、进程/设备连接和现场任务编排；本技能只提供本卡标注的工具能力，不能扩展为未登记的内存、Hook、协议或输入能力。
- `l-reverse`：负责逆向/静态或运行时证据路由；本技能的输出必须按目标版本、模块、ABI 和现场回读复核，不能把候选分析直接当作成功结论。
- `l-dev`：负责构建、依赖、配置、部署、回滚和服务维护；本技能不替代发布门禁，未完成依赖、许可证、异常恢复和回滚检查时不得发布。
