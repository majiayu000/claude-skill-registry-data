# 信息架构设计Skill

## 适用场景
功能范围明确后、绘制线框与原型前,把功能点组织为页面/模块/导航的层级结构,保证用户「找得到、进得去、回得来」。

## 执行步骤
1. 盘点信息资产:从 PRD 功能清单提取全部页面、对象(实体)、操作,列全量清单。
2. 归类分组:按用户任务(不是按部门/系统)把功能聚成模块,模块数控制在 7±2 个。
3. 定义层级:定导航结构(顶部导航/侧边导航/底部 Tab),定每层深度(建议不超过 3 层)。
4. 绘制架构图:文字版树状图表达「一级模块 → 二级页面 → 页面内区域」。
5. 标注入口与路径:每个功能标注用户从何处进入、操作后去向何处。
6. 校验可达性:任意功能从首页 3 次点击内可达;深度过深时考虑拆分或提升层级。

## 规范要点
- 分组依据唯一:同一层级的分组维度必须一致(按任务或按对象,不混用)。
- 每个页面必须有「归属模块 + 页面职责 + 核心操作」三要素,禁止职责不清的万能页。
- 导航命名面向用户:用用户语言,不用系统内部术语(如「订单管理」而非「OMS」)。
- 同级项互斥:一个功能只属于一个模块,出现归属争议时以用户任务路径为准。
- 预留扩展:新功能插入不改变整体结构,标注入口设计上如何兼容未来扩展。

## 输出模板
```
# [产品名] 信息架构
一级导航(模块)
 ├─ 模块A(用户任务视角命名)
 │   ├─ 页面A1(职责:xxx;核心操作:xxx)
 │   └─ 页面A2(职责:xxx;核心操作:xxx)
 ├─ 模块B
 │   └─ ...
全局层:登录/个人中心/设置/消息
入口与路径:功能X:首页 → 模块A → 页面A1 → 弹窗
```

## 自检清单
- [ ] 全量页面/功能无遗漏
- [ ] 分组维度一致,模块数 7±2
- [ ] 层级深度 ≤ 3,功能 3 次点击可达
- [ ] 每页有归属/职责/核心操作三要素
- [ ] 命名面向用户语言,无系统术语
