# 弹性伸缩配置Skill

## 适用场景
业务流量峰谷明显,需要配置自动扩缩容策略,在保障容量与节省成本之间取得平衡。

## 执行步骤
1. 分析负载特征:取 7~30 天用量数据,确认峰谷规律、瞬时毛刺、业务高峰时段。
2. 选定触发指标:CPU/内存使用率、并发连接数、队列积压、QPS 等,选与业务瓶颈最相关的 1~2 个,避免多指标冲突。
3. 设定阈值与步长:扩容阈值与缩容阈值之间留缓冲带(如扩容 70%、缩容 40%),步长按「单实例可承载量」推算,防止抖动。
4. 配置冷却时间:扩缩容动作后设置冷却窗口(如 3~5 分钟),观察期不重复触发,具体数值以云平台官方文档为准。
5. 设置上下限:最小实例数保底防过缩,最大实例数封顶防账单失控。
6. 配置告警与观测:伸缩动作事件告警、容量水位大盘、缩容前保护(连接排空/优雅下线)。
7. 演练验证:压测触发扩容、回落触发缩容,验证策略生效且无抖动。

## 规范要点
- 伸缩必须可观测:每次扩缩事件记录触发指标快照与实例数变化,留痕可追溯。
- 缩容必须优雅:缩容前完成流量摘除与请求排空,禁止强杀实例。
- 阈值必须来自数据:基于真实水位设定,禁止拍脑袋定阈值。
- 抖动必须防住:缓冲带 + 冷却时间 + 步长三要素缺一不可。
- 封顶保底必须设:max/min 实例数强制配置,防止费用失控或服务打挂。
- 安全红线:生产环境调整伸缩策略、临时关闭伸缩、手动强制扩缩等操作需「总控 + 安全合规」双签名审批,操作全程留痕。

