# failure-feedback-loop

## When to Use

当遭遇挫折、失败或结果不如预期时，用于将负面经验转化为成长燃料description

## Core Logic

# 执行步骤

1.  **情绪隔离与事实确认**
    *   **输入**：失败事件及相关情绪（沮丧、羞愧等）。
    *   **操作**：承认并暂时搁置情绪。客观描述失败的具体事实：目标是什么？实际结果是什么？差距有多大？避免在此步骤进行原因分析或自我指责。
    *   **判断标准**：是否能用平静、客观的语言陈述“发生了什么”，而不掺杂“为什么”和情绪化评价。
    *   **IF** 事实清晰，**THEN** 进入步骤2。

2.  **诊断根本原因**
    *   **输入**：客观事实描述。
    *   **操作**：像科学家一样探究原因。使用“五个为什么”或因果分析图，区分直接原因（表面错误）和根本原因（系统性问题、认知偏差、能力缺口、错误假设等）。聚焦于可控因素。
    *   **判断标准**：是否挖掘到至少一个超出表面失误的、更深层次的系统性原因或错误假设。
    *   **IF** 找到根本原因，**THEN** 进入步骤3。
    *   **ELSE** 深入追问或寻求外部视角。

3.  **提取可操作的教训**
    *   **输入**：根本原因分析。
    *   **操作**：将根本原因转化为未来可用的、具体的教训或原则。格式应为：“在未来类似情况下，我应该/不应该...”。确保教训是可控、可执行的。
    *   **判断标准**：教训是否清晰、具体，并能直接指导未来的行动决策。
    *   **IF** 提炼出有效教训，**THEN** 进入步骤4。

4.  **设计纠正与实验方案**
    *   **输入**：提取的教训。
    *   **操作**：基于教训，设计一个具体的、微型的行动计划或实验，用于纠正错误或测试新方法。计划应足够小，以快速实施并获得反馈。
    *   **判断标准**：是否有一个明确的、即将执行的下一步行动，来应用所学教训。
    *   **IF** 方案设计完成，**THEN** 执行该方案，完成从失败到学习的闭环。
    *   **流程结束**。

# 输出格式要求

输出一份失败分析报告，结构如下：
*   **事件事实**：[客观描述目标与结果差距]
*   **根本原因**：[区分直接原因与根本原因，特别是错误的假设]
*   **核心教训**：[1-2条可迁移的行动原则]
*   **下一步实验**：[一个用于验证教训的小型行动计划]
