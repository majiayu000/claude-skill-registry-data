# Mumu模拟器专用技能（MuMu Python API）技能卡

## 基本信息

- **中文名称**：Mumu模拟器专用技能
- **来源仓库**：[u-wlkjyy/mumu-python-api](https://github.com/u-wlkjyy/mumu-python-api)
- **审查分支**：`master`
- **审查提交**：`0640b62cb2cdc45dfa4280a9bd5d11dc3c103095`
- **仓库定位**：Python 管理与采集封装，连接 MuMu Manager CLI、ADB、Nemu SDK 及图像采集能力
- **实现语言**：Python
- **运行要求**：Python `>=3.9`
- **已核对发行版本**：PyPI `mumu-python-api-wlkjyy==1.1.0`
- **当前收录状态**：工具和源码接入状态须在本机核对

- **Codex 安装状态**：源码已下载并固定提交；未安装到 Codex 全局技能目录

## 能力范围

1. 调用 MuMu Manager/CLI 完成模拟器实例的启动、关闭、重启和状态查询。
2. 管理目标应用的安装、卸载、启动、关闭和状态检查。
3. 封装 ADB 连接、基础 shell 命令、文件推送/拉取和设备状态读取。
4. 提供窗口显示/隐藏、窗口布局等管理能力（以目标 MuMu 版本实际支持的命令为准）。
5. 通过 Nemu SDK 进行高速截图或实时帧回调，并可衔接 OpenCV/scrcpy 采集链路。
6. 为后台守护、故障恢复、应用重开和证据采集提供管理层接口。

## 适合解决的问题

- 统一模拟器启动、重启、应用拉起和健康检查流程。
- 为工作项目 AI 提供后台设备连接、截图和文件交换通道。
- 在闪退、卡屏、ADB 失联后重建模拟器/应用连接，并重新发现当前进程。
- 为 UI 状态识别、截图回放和运行证据保存提供采集后端。
- 将模拟器管理动作的输入、后置状态、日志和超时纳入可复现任务合同。

## 不能替代的技能

- IL2CPP 元数据解析、函数定位、`MethodInfo` 校准和 Hook 实现。
- 游戏线程调度、NativeBridge、JNI 或 ARM64/x86_64 ABI 适配。
- PointerScan 指针链扫描、地址稳定性验证和对象语义确认。
- 游戏内退出协议、服务端回执、业务成功判定和对局状态机。
- 游戏策略、AI 决策、动作规划以及功能“百分百成功”的证明。
- 反作弊规避、隐藏进程、驱动或网络协议修改。

## 本机接入前检查

- 分别定位本机 MuMu 管理器、CLI 与 ADB，记录实际路径、版本和文件身份。
- 查询实际 VM、ADB serial、Android 启动状态与应用进程；不沿用其他项目的实例号或设备地址。
- 检查项目管理与采集适配层；外部说明中的调用状态不能作为本机已验证证据。
- Nemu SDK 接入前核对 `external_renderer_ipc.dll`、回调退出及句柄释放；未验证时使用已确认的 CLI/ADB 方法。
- 输入、自动执行、设备模拟信息和网络桥接等操作按当前任务明确范围选择，不从示例配置推定授权。

## 输入与输出合同

```text
输入：project_id、模拟器实例/VM、ADB serial、目标应用包名、管理动作、超时/退避、采集模式
前置：实例身份和版本已确认；当前页面状态可判定；没有旧 PID/旧 serial/旧会话残留
动作：执行唯一的启动、停止、重启、应用管理、ADB 或采集动作
输出：命令退出码、管理器/ADB 返回、后置状态、截图/帧、时间戳、日志和证据路径
后置：重新读取实例、设备、应用和进程状态；需要继续工作时建立新的会话快照
失败：记录原始错误和现场证据，停止依赖旧状态的动作，按守护策略退避恢复；不得伪造成功
```

## 接入原则

1. 本技能只负责模拟器管理和采集层；保留项目既有主流程，不因收录本技能而自动替换。
2. 不默认枚举或切换多设备；每个任务合同固定 VM、serial、包名和版本。
3. 所有外部动作遵循“当前状态 → 唯一动作 → 回读后置状态 → 保存证据”，禁止只看命令返回码。
4. 闪退、卡屏、ADB 失联或桥接断开时，先保存故障证据，再重建连接、重新发现进程并建立新会话；禁止复用旧 PID 或旧页面。
5. `game_input`、`auto_execute` 默认关闭；需要输入时必须由项目任务合同明确授权并经过项目专项规则门禁。
6. Nemu SDK 的回调线程、句柄、共享内存和 DLL 生命周期必须有显式停止和释放路径；异常时不能遗留常驻线程。
7. 采集结果必须带项目、实例、版本、ABI（如适用）、采样时间和来源工具；截图非空不等于游戏功能成功。
8. 依赖固定提交或固定 PyPI 版本，禁止把可变分支、未审查下载包或缓存生成物当作基线。
9. 接入时遵循项目专项规则和当前任务合同。

## 与项目的关系

MuMu API 可以作为项目管理、恢复与采集适配层的候选。先对实际 CLI/ADB 方法做等价行为、失败恢复和状态回读检查，再按当前任务决定是否替换单个适配层；模拟器管理与采集不代表游戏内状态、引擎调用或 AI 决策已经成功。
