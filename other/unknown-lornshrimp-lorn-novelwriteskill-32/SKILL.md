# 通用-蒸馏写作研究
> **题材路由**：若 .github\题材专用Skills\ 目录存在对应的 <题材>-蒸馏写作研究 Skill，则：
> - 将题材特性骨架路由到 <题材>-蒸馏写作研究，该 Skill 位于 .github\题材专用Skills\ 目录。
> - 命中本技能时，必须优先强制加载当前 Skill 与 <题材>-蒸馏写作研究。


> 将"写作研究"从静态参考资料变成可执行的写作约束——不是读完报告就忘了，而是让报告里的每一条可量化结论在每次写作时自动生效。

## 核心区别

| | 作者风格模板 | 作品蓝本模板 | 写作研究模板 |
| --- | --- | --- | --- |
| 蒸馏源 | 真实作者的原始文本 | 一部完整小说的原始文本 | **写作研究报告（结论文本）** |
| 蒸馏方式 | 统计级分析（句长分布等） | 统计级分析（钩子类型等） | **规则提取（从研究结论翻译为执行约束）** |
| 产出的作用域 | 文笔约束 | 结构约束 | **题材×平台约束（默认基线）** |
| 优先级 | 高于写作研究 | 高于写作研究 | **低于用户明确指定，高于通用默认** |

> **前置阅读**：执行蒸馏前，建议先读取 `../../写作研究/网文留存模型.md` 了解留存基线的量化框架，以及 `../../写作研究/GEO小说项目核心参考.md` 了解 GEO 基础框架与 AI 搜索可见性原理，以便在研究报告中识别与留存和 GEO 相关的约束。
>
> **核心理念**：蒸馏的终极目标不是产出一张规则清单让下游打勾，而是让下游**内化每条规则背后的"为什么"**——当遇到规则未覆盖的新场景时，能自行推导出正确的写作决策。详见 `references/约束提取方法论.md`。

## 约束的"为什么"——从形似到神似（强制）

约束提取的核心方法论详见 `references/约束提取方法论.md`。以下为必须遵守的硬规则：

1. **"为什么"归因**：每条硬门禁和强约束必须追加读者心理学根因，无归因不得写入最终模板。
2. **跨报告复现**：只有被 ≥ 2 份独立报告指向同一原理的约束，才能升级为"原则"写入 §五 原则层。
3. **原则层生成力**：蒸馏完成后必须做"新场景推导"测试，验证原则在新场景中仍能指导正确决策。

## 仿写约束提取

当蒸馏服务于仿写场景时，必须追加市场窗口期相关的提取维度。

**核心方法论**详见 `references/仿写约束提取指南.md`。以下为必须遵守的硬规则：

1. **产地标注强制**：所有"当前火/退热/还有空间"类约束必须在来源中标明报告发布日期（`[2026年Q1]` / `[2025年]` / `[时效不明]`）。
2. **素材整合三问**：融合多报告约束时，必须通过"主题统一、风格协调、逻辑自洽"三问检查，未通过则淘汰或标注冲突。
3. **产出位置**：仿写窗口约束写入 §五-B（在 §五 原则层之后）。

## 蒸馏源

### 默认源（无需指定，自动扫描）

蒸馏 Skill 启动时，默认扫描以下位置（均在小说项目内，不从提示词项目直接扫描）：

1. **小说项目根目录的 `写作研究/` 目录**（项目级写作研究，优先级最高）
2. **小说项目根目录的 `调研报告/` 目录**（项目级调研报告，与"写作研究/"同优先级；存放同类题材竞品调研、平台趋势调研等结构化报告）
3. **小说项目根目录的 `CommonSkills/写作研究/` 目录**（通用跨题材写作研究，从提示词项目复制或同步而来）

> 提示词项目中的写作研究文件需要先复制或同步到小说项目的对应目录下才能被默认扫描到。用户也可以通过指定绝对路径或 URL 引入提示词项目内的文件，属于"指定源"。
>
> 若默认源与指定源均未找到有效素材，用户可选择启动**网络搜索**（Phase 0 中由用户自主选择搜索关键词），Skill 将搜索到的网页内容作为蒸馏源处理。

### 指定源

用户可指定以下任一类型：

| 指定类型 | 示例 | 行为 |
| --- | --- | --- |
| 单个文件 | `蒸馏 写作研究/番茄...研究.md` | 只蒸馏该文件 |
| 目录 | `蒸馏 写作研究/` | 蒸馏该目录下所有 `.md` 文件 |
| URL | `蒸馏 https://example.com/research.md` | 抓取网页内容后蒸馏 |
| 网络搜索 | `蒸馏 网络搜索 番茄小说 2026 新趋势` | 使用网络搜索引擎检索相关内容，抓取搜索结果页，对检索到的网页由用户筛选后一并蒸馏 |
| 绝对路径 | `蒸馏 D:/提示词项目/异能志怪/写作研究/` | 蒸馏提示词项目内的目录 |
| 组合 | `蒸馏 文件A + 目录B + URL C` | 合并蒸馏，标注每条约束的来源 |
| 过滤 | `蒸馏写作研究，只看番茄和起点的` | 按关键词过滤报告文件名 |

## 产出与注册

### 产出文件

```text
蒸馏产物/写作研究模板/[题材名]-[平台名]-写作研究模板.md
```

文件名规则：`[题材名]` 从报告标题提取，`[平台名]` 从报告标题提取。综合多份报告时平台名写"综合"。**完整模板结构**详见 `references/写作研究模板格式定义.md`。

### Agents.md 注册

在目标项目根 `Agents.md` 中追加注册条目：

```markdown
### 写作研究模板
- 名称：[题材名]-[平台名]
- 路径：蒸馏产物/写作研究模板/[题材名]-[平台名]-写作研究模板.md
- 蒸馏日期：YYYY-MM-DD
- 素材来源：[N] 份（研究报告/调研报告/网络搜索页面）
- 提取约束数：[N] 条（文笔 [N] + 结构 [N] + 人物 [N] + 禁忌 [N]）
- 适用平台：[番茄 / 起点 / 七猫 / ...] 或 默认
```

**平台注册逻辑**（强制执行）：蒸馏时若报告天然指向某个平台则自动写入对应平台名；若为跨平台综合研究写 `默认` 或用户指定清单；若 `Agents.md` 中尚无主输出平台且本轮平台明确，建议用户指定。

## 执行流程（概要）

> 完整执行流程（含档案包结构、各 Phase 检查点表格、双 Agent 精炼细则、更新已有模板流程、约束依赖图谱、版本漂移检测）详见 `references/执行流程详细检查点.md` 和 `references/约束依赖与版本漂移.md`。

| Phase | 步骤 | 关键闸门/硬规则 |
| --- | --- | --- |
| **Phase 0** | 确定蒸馏源 | 默认扫描 `写作研究/` + `调研报告/` + `CommonSkills/写作研究/`；指定源支持文件/目录/URL/网络搜索/组合/过滤；均无素材时可启用网络搜索 |
| **Phase 0.5** | 创建蒸馏档案包 | 必须创建 `[题材]-[平台]-写作研究档案/` 下 `sources/` + `references/research/` + `synthesis/` + `validation/`；无来源的约束不得写入 |
| **Phase 1** | 逐报告提取 | 按信号词搜索 → 翻译为约束 → 标注来源+置信度 |
| **Phase 1.5** | 提取 Review | 输出质量摘要（约束数/置信/冲突），用户确认后方可进入 Phase 2 |
| **Phase 2** | 合并去重 | 同字段合并/分级/冲突并列；追加"为什么"归因；跨报告复现检测 |
| **Phase 2.5** | 合并确认 | 输出合并摘要（保留数/冲突/候选原则/归因覆盖率），用户确认后方可进入 Phase 3 |
| **Phase 3** | 产出与注册 | 生成模板 `.md` → 写入 `蒸馏产物/` → `Agents.md` 注册 |
| **Phase 4** | 质量验证 | 三项验证：来源追溯、下游干跑、冲突处理；验证结果入档案包 |
| **Phase 5** | 双 Agent 精炼 | Agent A：可执行性审阅；Agent B：来源与冲突审阅 |

### 约束依赖关系图谱

合并阶段（Phase 2）必须梳理三条关系：**母子关系**（一条是另一条的操作化）、**互补关系**（同规则不同角度）、**潜在冲突**（实践中可能互斥）。格式示例见 `references/约束依赖与版本漂移.md`。

### 版本漂移检测

更新模板时必须执行漂移检测：被推翻/被强化/首次新增/未被覆盖。格式示例见 `references/约束依赖与版本漂移.md`。

## 三模板冲突仲裁规则

当写作研究模板与作者风格模板、作品蓝本模板同时作用于同一字段时：

| 冲突场景 | 优先顺序 | 裁决逻辑 |
| --- | --- | --- |
| 同字段三模板均约束 | 作者风格 > 作品蓝本 > 写作研究 | 一手统计 > 结构验证 > 通用研究 |
| 写作研究的"硬门禁" vs 作者风格 | 硬门禁优先 | 平台硬门槛（如"前 300 字必须有冲突"）覆盖一切 |
| 写作研究的"强约束" vs 作者风格 | 作者风格优先 | 非硬门禁的通用建议让步于一手文风统计 |
| 平台敏感度冲突 | 目标平台特化 > 跨平台通用 | 若目标平台为起点，`[起点]` 约束优先于 `[通用]` |

**硬规则**：冲突裁决必须在蒸馏报告中显式记录；被覆盖的约束旁标注覆盖来源与理由；仍无法确定时保留冲突供用户决策。

## 约束符合度审计

> 完整审计维度表、计算方式、报告格式、闭环动作详见 `references/约束符合度审计.md`。

写作研究模板的终极检验标准是：**下游 Skill 依据这些约束产出的正文/大纲，是否真正遵守了模板中的每一条规则**。

### 审计时机

当且仅当以下条件同时满足时启动：
1. 当前项目已存在一份通过 Phase 4 质量验证的**写作研究模板**
2. 下游 Skill 已产出一份可供检查的成品
3. 用户明确要求审计

### 审计方法论

核心是一张**逐条扫描表**——将写作研究模板中的每一条约束，逐一与产出内容对照。按约束硬度分级审计：硬门禁必须 100% 通过，任一条未通过即判定不合规。

## 与其他 Skill 的边界

- 本 Skill 蒸馏**研究报告的结论**（二手研究 → 执行约束）
- `通用-蒸馏作者文风` 蒸馏**原始文本的特征**（一手文本 → 文笔约束），优先级高于本 Skill
- `通用-蒸馏作品蓝本` 蒸馏**原始文本的结构**（一手文本 → 结构约束），优先级高于本 Skill
- `通用-深度研究` 是研究执行 Skill（产出研究报告），本 Skill 是研究蒸馏 Skill（消费研究报告产出约束），可形成闭环
