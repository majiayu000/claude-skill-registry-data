# 建模论文增强规划器 / Paper Enhancement Builder

把“论文不够深入”改写成一组能做、能验收、能放弃的具体修订。增强不是继续堆模型；最值钱的改动常常是修掉
一个数据泄漏、补一个简单基线、把作用域写诚实，或让图表能追到运行。

## 何时使用 / When to use

- 有论文草稿或结构蓝图，想知道下一轮最值得改什么
- 有批判报告或评分表，需要把问题转成有顺序的行动
- 截止时间、算力、数据或成员精力有限，需要做取舍
- 团队想加高级模型、更多图或扩展问题，但不知道收益是否值得
- 已有多份反馈互相重复或冲突，需要去重并设置关闭条件

**不适用于** / Not for：

- 还没有可审查的论文 / 工作包 —— 先完成拆题、模型、代码或 `paper-structure-coach`
- 已有草稿，但章节顺序、段落职责或主张—证据链还没理顺 —— 先用 `paper-structure-coach`，结构稳定后再来排增强优先级
- 需要发现根本性模型漏洞 —— 先用 `model-critique-coach`
- 已经决定修订，只需执行代码 —— 用 `modeling-code-builder`
- 只需 LaTeX 格式与编译修复 —— 用 `latex-paper-formatter`

## 需要的输入 / Inputs

| 输入 | 必填 | 说明 |
|---|---|---|
| 当前论文 / 蓝图 | 是 | 版本、页数、章节、图表和明确缺口；没有草稿时只能规划前置工作 |
| 模型工作包 | 是 | 与论文主张相关的 `Q / D / A / M / T / R / F / C` |
| 已有审查 | 否 | `model-critique-coach` findings、老师 / 队友反馈；记录来源，不虚构权威 |
| 评分规则 / 模板 | 否 | 正式规则优先；没有时不猜评委个人偏好 |
| 资源约束 | 是 | 截止时间、成员、可用数据、算力、页数、允许的 AI 使用范围 |
| 不可改项 | 否 | 已冻结的模型、必须保留的版式或提交要求；同时说明冻结风险 |

“还有多久”会改变计划形状，必须来自使用者或正式截止时间；没有就给按依赖排序的 backlog，不编日期。
共享 ID 与状态见 `../_shared/modeling-work-contract.md`。

## 流程 / Process

### 1. 冻结当前基线

记录论文版本、当前中心主张、已完成的模型 / 运行 / 图表 / 验证、页数和未决问题。没有这个快照，改完后无法判断
增强带来了什么，也容易把原有证据弄丢。

先列 2–4 个**有位置与证据**的现有强项。强项不是礼貌段落，它们决定哪些部分不该被重写。

### 2. 建 gap register

从五条路径找缺口并去重：

1. 原题 / 评分项没有对应论文位置
2. `C -> F / R / T / M / D / A -> Q` 证据链断裂
3. critique finding 没有关闭条件或仍为 open
4. 结构中职责混淆、重复、冲突或页数失衡（结构重排本身交给 `paper-structure-coach`，本 skill 只排序与追踪）
5. 复现、引用、AI 披露和提交格式缺失

每个 gap 写：精确位置 / IDs、观察证据、影响的主张或评分项、严重度、根因与当前状态。多个反馈若指向同一根因，
合并成一项；不要让“反馈很多”虚增优先级。

### 3. 生成有收益路径的候选增强

优先考虑：

- 修 Blocker / High 的数学、数据或实现问题
- 增加简单基线、校准外验证、关键假设测试或稳健性情景
- 处理不可辨识、单位、数据泄漏、边界与作用域
- 缩窄过强结论，补主张—证据与图表—运行追踪
- 把模型选择、假设理由、失败方案或限制说清
- 修复复现链、符号冲突、摘要数字和图表合同
- 删除重复和装饰性复杂度，为真正证据腾页数

只有当新模型、新参数、新数据或新图能回答一个明确 gap，并有时间完成验证时，才把它列为候选。

### 4. 写完整增强卡

每项必须填：

| 字段 | 要求 |
|---|---|
| change | 具体改哪个模型、运行、图表或段落 |
| why now | 关闭哪个 gap / finding / 评分项 |
| expected benefit | 对结论可靠性、解释、决策或可复现性的可观察改善 |
| inputs | 所需数据、代码、来源、作者决定与工具 |
| effort | 人时 / 阶段级估算及依据；没有信息就用 S/M/L 相对量级 |
| dependencies | 必须先完成什么，哪些下游要重跑 |
| validation | 测试、基线、指标和预先规则 |
| acceptance | 什么证据出现才算完成，失败时怎样降级 |
| risk | 最可能卡死或引入新问题的原因 |
| owner type | 需要建模、代码、论文、核查或团队决策；不虚构具体成员能力 |

“让模型更准确”“丰富敏感性分析”“优化表达”都不够具体，不能进入 backlog。

### 5. 排序，不伪造精确分数

先按硬规则：Blocker / 诚信 / 规则覆盖 > 核心结论证据 > 验证与复现 > 解释与结构 > 装饰。
同层再比较：预期收益、依赖解锁、工作量、失败风险与是否能在剩余时间内闭环。

可以用 High / Medium / Low 或明确的 pairwise 判断，不必编一个看似科学的 `8.7/10`。如果评分表给权重，引用正式权重；
没有就不自称代表得分提升。

### 6. 选一个最小可行修订 / MVR

MVR 是在当前资源下能完整闭环的一项或一组最小改动，通常包括：

```text
修根因 -> 重跑受影响结果 -> 更新图表 / 主张 -> 复查限制与复现
```

它必须有停止条件。若验证失败，计划中预先写退路：保留基线、缩小作用域、删除不受支持主张或明确未解决限制。

### 7. 把扩展分成三档

- **Now**：MVR 与阻塞项，当前资源内必须闭环
- **Next**：Now 完成且仍有余量时，能明确提高证据质量的项
- **Park**：有潜力但缺数据 / 时间 / 验证路径；记录重开条件，不在截止前偷偷启动

“加深度学习 / 多目标优化 / 更多指标”若没有 gap 与验收条件，直接进入 rejected，而不是 Park。

### 8. 执行前确认，执行后按条件关闭

先交 backlog 与 MVR 让使用者确认取舍。确认后把代码任务交给 `modeling-code-builder`，模型与假设修订交给
`model-selection-tutor` / `modeling-assumption-builder`，结构交给 `paper-structure-coach`，LaTeX 交给
`latex-paper-formatter`；本 skill 维护状态，不在一个大补丁里同时改模型、跑实验、重写论文和重排格式。

关闭 gap 时附证据 IDs。只是“已经修改文字”不能关闭需要新验证的 finding。


## 工具与跨 Agent 降级 / Tool fallback

- 能读文件时只读当前论文版本、findings、评分表和工作包摘要；按 gap 再定位证据。
- 能检查 Git / 版本时记录基线；不能时用文件日期、名称与使用者确认的版本标签。
- 能执行代码时也不要在规划阶段擅自启动昂贵实验；先确认 MVR，再交给代码流程执行。
- 无文件或执行能力时仍能基于粘贴材料产出 backlog，所有位置与验证状态按实际可见范围标注。
- 工具失败或缺失只影响验证状态，不改变诚信边界。

## 边界 / Boundaries

- **不写通用改进套话**：每项必须指向位置、证据、受影响主张和验收条件。
- **不编评委偏好与分数收益**：只能引用正式评分表或说明方法学收益。
- **不造创新点**：新颖性需要与已有工作和来源核对，不能由措辞宣布。
- **不以复杂度代替质量**：新模型 / 参数 / 图没有可测收益就拒绝。
- **不虚构数据、实验和验证**：缺输入时标依赖，不生成“示例结果”占位。
- **不无限扩范围**：每项有停止条件，Now 先闭环再开 Next。
- **不破坏现有强项**：修改前列出必须保留的已验证贡献与证据链。
- **不一轮代做所有环节**：本 skill 排序和追踪；模型、代码、结构、格式各回所属技能执行。
- **不替作者决定风险接受**：给清晰倾向，最终取舍与提交主张由团队确认。

## Token 控制 / Token discipline

- 反馈先按根因去重，只保留能改变行动的那一份描述
- Backlog 默认 5–8 项；更多内容放 Park，不让主清单失焦
- 每个增强卡一句话描述收益与风险，细节通过 IDs 回查
- 状态更新只回报变动项、证据与下一阻塞，不重贴全表
