# 多模态数据处理结果检索

当用户询问“多模态数据处理平台”“工作流处理结果”“网页爬取结果”“文档解析结果”“处理后数据集”或某个已处理网页/PDF/图片的内容时，使用此 Skill。它检索的是已由多模态数据处理平台成功写入并同步到 DeerFlow 的结果，不联网，也不解析尚未入库的新文件。

## 必须使用的检索方式

只可调用受控的只读脚本，禁止直接访问 Elasticsearch、传入索引名、执行 ES DSL、创建/删除索引或修改数据：

```bash
python3 /mnt/skills/custom/multi-data-process-rag/scripts/search_multi_data_process.py \
  --query "<用户问题中的核心关键词>" --top-k 5 --pretty
```

可选约束：

- 用户指定数据集时，加入 `--dataset-id <id>`。
- 用户指定历史版本时，加入 `--dataset-version-id <version_id> --include-historical`。
- 用户未明确要求历史版本时，**不要**加入 `--include-historical`；默认只检索当前成功版本。
- 用户仅授权某个工作区时，加入 `--workspace-id <workspace_id>`。

脚本通过 DeerFlow Gateway 调用固定的 `multi-data-process-rag` 检索接口；不会在脚本、提示词或命令行中暴露 ES 凭据或同步 Token。

## 回答规则

1. 先检索，再回答；不要根据常识补写数据集未返回的内容。
2. 每个基于检索结果的主要结论都要带回溯引用，优先直接使用结果中的 `citation` 字段。引用至少应包含数据集 ID、版本 ID、标题；有 `source_url` 时同时给出链接。
3. 结果为空时，明确说明“当前已同步的成功版本中未检索到相关内容”，并建议用户确认关键词、数据集/版本或是否完成同步；不得编造内容。
4. 结果中的 `content` 是证据片段，不要声称它是完整原文；长文可概括，但需说明依据的是返回片段。
5. 若用户请求上传、爬取、解析或重跑工作流，转交相应的数据处理功能；本 Skill 只负责已处理结果的检索与问答。

## 版本语义

默认结果只能来自已完成且被标记为当前的版本。工作流的新版本同步成功后会替换同一数据集的当前检索范围；显式查询历史版本才会读取该版本的保留 chunks。失败或仍在写入的版本不能作为聊天证据。
