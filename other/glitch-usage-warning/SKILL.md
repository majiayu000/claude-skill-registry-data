# glitch-usage-warning

## When to Use

当考虑使用非常规、高风险手段（如极端外部压力、药物、未经充分评估的强效工具如AI）来强行突破个人发展瓶颈或加速进入“渠道”时。description

## Core Logic

# 执行步骤

1.  **评估自身发展阶段与经验储备**
    *   **输入**：个人在目标领域的发展历史、知识技能基础、过往应对风险的经验。
    *   **操作**：客观评估自己处于“自然”成长路径的哪个阶段（文中隐喻的“级别”）。审视自己是否有足够的领域知识、核心技能和心智成熟度来驾驭高风险加速手段。
    *   **判断标准**：是否能清晰陈述自己在该领域的现有能力和经验边界。
    *   **IF** 评估结果为新手或基础薄弱（文中喻为“1级”） -> **THEN** **强烈建议避免使用“故障”手段**，转向“channel-entry-strategy”模型。流程结束。
    *   **ELSE** (自评具备一定经验和根基) -> **THEN** 进入步骤2。

2.  **明确风险与代价分析**
    *   **输入**：拟采用的特定“故障”手段（如某种药物、极端财务杠杆、未经验证的AI应用）。
    *   **操作**：系统性地列出该手段所有可能带来的负面后果（健康损害、财务崩溃、心理依赖、技能退化等），并评估其发生概率和自身承受能力。
    *   **判断标准**：是否已识别出至少三个主要风险点，并思考过应对预案。
    *   **IF** 无法承受最坏结果，或风险完全不可控 -> **THEN** 放弃该手段。流程结束。
    *   **ELSE** -> **THEN** 进入步骤3。

3.  **界定精确目标与使用边界**
    *   **输入**：步骤2中分析过的“故障”手段。
    *   **操作**：为该手段的使用设定极其精确、有限的目标和严格的边界条件（如“仅用AI工具生成初稿框架，而非核心思想”、“仅在监督下短期使用某补剂突破平台期”）。明确“何时开始、何时停止、成功标志、失败退出机制”。
    *   **判断标准**：使用规则是否具体、可监控、且具备终止条款。
    *   **IF** 目标模糊或边界开放（如“用它来变得更好”） -> **THEN** 拒绝使用。风险过高。流程结束。
    *   **ELSE** -> **THEN** 进入步骤4。

4.  **执行与监控**
    *   **输入**：带有精确目标和边界的“故障”手段使用计划。
    *   **操作**：在严格遵循预设边界的前提下执行。持续监控自身状态、进展和副作用，与预设的成功/失败标准进行比对。
    *   **判断标准**：是否严格按计划执行，并及时记录反馈。
    *   **IF** 出现计划外的负面效应，或即将触及边界 -> **THEN** **立即停止**，执行退出机制。流程结束。
    *   **ELSE** (在边界内按计划进行) -> **THEN** 在达到预定目标后，按计划停止，并评估整体得失。

# 输出格式要求
采用警示性框架输出：
*   **风险等级**：根据用户描述的情况，给出高/中/低的风险初步判断。
*   **核心警告**：强调该方法仅适用于有充分经验和风险承受力的个体，对初学者极度危险。
*   **必要前提检查清单**：列出用户必须满足的条件（如：扎实的基础、明确的具体目标、严格的边界设定、退出计划），并请用户逐一核对。
*   **替代建议**：优先推荐使用“channel-entry-strategy”等自然增长模型。
