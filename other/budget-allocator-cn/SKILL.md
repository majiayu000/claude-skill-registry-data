# 预算分配与情景推演

核心思想：按**边际转化成本**而非平均成本分钱；尊重每个平台的跑量容量上限。

## 数据契约

近 30–60 天分渠道分天：消耗、转化、成本、后端质量（有效率/成交/ROI）；各渠道预算上限与撞线记录；业务约束（目标成本/目标 ROI、总预算、渠道最低保有量、合同/年框）。

## 流程

1. **统一口径**：把各平台"转化"对齐到同一业务事件（有效线索/首单/付费），用后端系数折算（如 A 平台线索有效率 60%、B 平台 30%，前端成本不可直接比）。
2. **画边际曲线**：按天观察"消耗↑时成本如何变化"，估计每个渠道的容量拐点（消耗超过某值后成本明显抬升）。数据不足时用撞线频率+竞价环境定性判断，并标注低置信。
3. **分层**：
   - 保底层：品牌词/防御性/已验证稳定渠道；
   - 效率层：边际成本低于目标的渠道，优先加预算；
   - 探索层：固定比例（经验 10–20%）给新渠道/新素材/新人群测试，不参与短期 ROI 考核。
4. **情景推演**：对"加 X 万/砍 X 万/目标成本收紧"分别给出分配表与预期转化区间；加预算优先给"未撞线且边际成本低"的渠道，单渠道单次加幅建议 ≤30–50%（避免模型重置与成本跳升）。
5. **节奏**：大促前蓄水期（种草/人群资产）与收割期（效果/搜索）预算比例不同；给出分周节奏表。

## 输出格式

```
## 预算分配方案（总预算 ¥X / 目标：__）
| 渠道 | 现预算 | 建议预算 | 边际成本估计 | 预期转化区间 | 理由 |
### 情景对比：基准 / +X万 / -X万
### 探索预算与测试计划
### 风险与假设（容量估计置信度、后端系数来源）
```

## 约束

- 平均成本低的渠道不等于还能加量（可能已到容量上限）；必须说明容量判断依据。
- 后端系数来自用户数据；没有就明说"暂按前端成本比较，结论可能失真"。
- 不给"全押一个渠道"的建议，除非用户明确接受集中风险。
