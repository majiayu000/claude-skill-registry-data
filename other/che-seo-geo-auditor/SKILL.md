# CHE_seo-geo-auditor — SEO & GEO Auditor (2026)

Комплексная система аудита по стандартам Google Search Essentials, Яндекс.Вебмастер и GEO-оптимизации для AI-движков.

## Маршрутизация

- Полный аудит сайта или пакетный crawl URL → этот skill.
- Одна страница, одно метаописание, контент-бриф, Schema.org или точечная
  кросс-проверка → `che-seo-geo-auditor-pro`.

## Как вызвать

- «Проведи полный SEO/GEO аудит сайта https://example.com. Тип сайта: интернет-магазин.»
- «Просканируй сайт и подготовь полный технический SEO/GEO-отчёт.»
- «Каждый понедельник в 10:00 запускай che-seo-geo-auditor для сайта https://mysite.com»

## Шаг 1 — Сбор данных

### 1a. Автоматический парсинг (Python)

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install requests beautifulsoup4 lxml
python scripts/audit_website.py https://example.com
```

Скрипт извлекает: мета-теги, заголовки, Schema.org, robots.txt, ссылки, изображения.
Результат → `audit_data.json`.

### 1b. Визуальная проверка

Для анализа E-E-A-T и UX использовать доступный в текущей среде браузер,
краулер или HTTP-инструмент. Перед вызовом проверить его доступность.

Проверить: наличие страницы «О нас», профилей авторов, ссылок на соцсети, поп-апов.

Если клиентская страница вернула пустой шаблон, запросить HTML, скриншот или
экспорт краулера. Не заявлять о визуальной проверке, которой не было.

## Шаг 2 — Анализ по чек-листу

Сверить данные с `references/checklist.md`. Приоритеты:

- **Критично**: подтверждённый блокер индексации страницы, которую владелец намерен индексировать, отсутствие HTTPS или canonical на ошибочный адрес. Проверить назначение страницы и канал поиска.
- **Высокий**: существенные проблемы метаданных, загрузки или подходящей типу страницы разметки. Блокировка конкретного AI-бота — факт для сверки с политикой владельца, без автоматического штрафа. Частные страницы и намеренные ограничения не являются ошибкой.
- Отсутствие FAQPage или llms.txt само по себе не снижает оценку. Google прекратил FAQ rich results с 7 мая 2026 года. FAQ-разметка допустима для видимых вопросов и ответов без обещания расширенного результата или AI-цитирования. Источники: [Google Search updates](https://developers.google.com/search/updates), [AI features](https://developers.google.com/search/docs/appearance/ai-features).
- **Средний**: нет alt у картинок, нет TL;DR, слабые E-E-A-T сигналы
- **Низкий**: Open Graph, Twitter Cards, мелкие UX-замечания

Стратегии GEO/LLMO → `references/geo_guide.md`.

## Шаг 3 — Скоринг (0–100)

Начало: **100 баллов**. Снимать баллы с учётом контекста сайта:

| Категория | Диапазон вычета | Принцип |
|---|---|---|
| Критические блокеры | 10–20 за каждый | Прямо мешает индексации или AI-видимости |
| Технический SEO | 5–10 за каждый | В зависимости от весомости для типа сайта |
| Контент и on-page | 3–7 за каждый | Учитывать объём и тип страницы |
| E-E-A-T | 2–5 за каждый | Важнее для YMYL-тематик |
| GEO / AEO | 3–8 за каждый | Критичнее для информационных сайтов |

Шкала: **85–100** отлично · **70–84** хорошо · **50–69** требует работы · **<50** критическое состояние

> Скоринг — оценочный, не механический. Два критических блокера на коммерческом сайте
> весят больше, чем три средних на блоге. Обосновывай вычеты конкретными данными.

## Шаг 4 — Генерация отчёта

Использовать шаблон `templates/audit_report.md`. Заполнить все плейсхолдеры `{{...}}`.

Требования к отчёту:
- Executive Summary с баллом и таблицей по приоритетам
- Визуальные индикаторы: ✅ ❌ ⚠️
- Конкретные рекомендации с основанием: например, добавить Product для страницы реального товара с видимыми ценой и наличием. Тип разметки выбирать по содержимому и актуальной поддержке, не добавлять все типы на каждую страницу.
- Матрица приоритетов: что исправлять в первую очередь

Сохранить отчёт как Markdown в рабочую папку.
