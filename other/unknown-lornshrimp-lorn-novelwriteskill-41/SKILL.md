# 通用-审阅章节正文
> **题材路由**：若 .github\题材专用Skills\ 目录存在对应的 <题材>-审阅章节正文 Skill，则：
> - 将题材特性骨架路由到 <题材>-审阅章节正文，该 Skill 位于 .github\题材专用Skills\ 目录。
> - 命中本技能时，必须优先强制加载当前 Skill 与 <题材>-审阅章节正文。


> **头号要求：禁止吹捧，客观分析。** 审阅中不得出现无依据的称赞、吹嘘性描述或主观美化。所有判断必须基于文本事实、可验证标准与明确扣分依据，优先指出问题与改进方向。

章节正文审阅的第一判断不是“漂不漂亮”，而是“读者有没有被拖进去、有没有拿到回报、下一章值不值得看”。

## 审阅范式声明——技法审阅与留存的深层矛盾（2026-06-23 范式转换）

**本 Skill 执行审阅时，必须意识到一个深层矛盾**：技法优化与读者留存之间并非单调递增关系。各技法维度（去AI味/逻辑严密性/描写质量/结构完整度/人物一致性）在留存视角下都呈现**倒U型曲线**——中等水平对留存最有利，过高反而伤害留存。

> 详见 `CommonSkills/写作研究/审阅范式转换_技法审阅与网文留存的深层矛盾及底层模型重构.md`

这意味着：
- 审阅不应默认"更多技法优化 = 更好"
- 审阅在技法评分之外，必须增加**留存视角**并行评估
- 当技法评分高但留存信号差时，以留存判断为准——因为这是"死亡交叉"
- 同样，当技法评分中等但留存信号强时，不应以技法不足为由过度压制放行

**本 Skill 的审阅报告默认采用"双轴评分"架构**：技法质量评分（从 10 分起扣）+ 读者体验评分（从 0 分起加）+ 三横切预警（过度优化/动词密度/确定性过剩）。参见 `references/章节正文审阅检查清单.md` §十九 和 `references/章节正文审阅完整模板.md` §17.0。

## 读者模型声明（执行审阅前必须切换）

**本 Skill 默认使用以下读者模型进行审阅**——所有审阅结论都必须能回答：在竞争介质的包围下，这一章凭什么让读者不划走？

```text
【审阅读者模型】
- 阅读场景：手机端，碎片时间（通勤/排队/睡前/摸鱼）
- 心理状态：随时可能被抖音15秒爽点、短剧1分钟反转、微信红点打断
- 决策周期：每200字做一次"继续看还是划走"的隐性决策
- 底层需求排序：画面感（动词驱动大脑生成电影）> 参与感（不确定性驱动追读）> 获得感（情绪回报驱动继续）
- 竞争对手：不是其他小说，是所有争夺注意力的介质
```

> 审阅者必须先确认已理解此模型，再开始逐项审阅。若审阅结论在"文学评论家"模型下成立但在"注意力决策者"模型下不成立，以注意力决策者模型为准。

## 默认执行顺序

章节正文审阅按以下步骤执行，每一步标注了应读取的参考文件：

### 步骤 1：审阅前准备
1.1 确认目标章节文件路径，收集本章出场人物传记与故事设定裁判源。
1.2 若项目根存在 `Agents.md`，执行 `## 风格/蓝本模板自动发现规则`（见对应节）。
1.3 加载 `references/章节正文审阅检查清单.md`，作为逐项核对的底表。
1.4 **初稿自筛五问参考**（新增——吸收自知乎精华"如何把大纲蜕变成沉浸小说"）：在进入正式审阅之前，审阅者可以用以下五问做一次快速初筛，判断本章是否已经完成了从"章纲体"到"沉浸正文"的基本转化。这五问不是正式审阅维度的替代品，而是在全面审阅前定位"这章最核心的沉浸病灶"的快捷工具：
   - **问题一·开场戏**：本章开篇是具体场景/画面，还是剧情摘要/信息说明？如果是后者，标记"大纲体残留"。
   - **问题二·冲突与情绪**：本章的冲突节点是否附带人物的心理/生理/即时决策反应？如果冲突被写成了"发生了某事→解决了某事"的干巴巴推进，标记"冲突无体感"。
   - **问题三·舞台沉浸**：环境描写是否与角色的情绪产生了呼应或推动？如果去掉环境后情节不受影响，标记"背景脱钩"。
   - **问题四·人物细节**：出场人物是否有鲜活的具体动作、小习惯或体感细节，还是只有功能性的"说了话、做了事"？标记"人物工具化"。
   - **问题五·节奏连贯**：出声通读或默读后，是否有段落之间断档或叙述忽快忽慢的感觉？标记"节奏卡顿"。
   - **问题六·设定与故事的关系**（新增——吸收自知乎虚空圣堂）：本章是直接进入故事推进（主角在压力中行动/决策），还是先展开了世界观/背景/设定/环境描写再"开始"故事？如果开篇前 300 字的主要内容是静态信息而非动态故事推进，标记"静态设定先行"。此问本质是检测同一个底层病灶——"设定是静态的，故事是动态的"（虚空圣堂核心公式），好的审阅者应在此问中一并观察"信息是通过故事水流自然释放的还是硬塞的"。
   - **朗读审读法建议**（同一来源）：将正文打印或朗读出来做审读，耳朵对"不自然的停顿、重复、节奏失调"比眼睛敏感得多。审阅准备阶段建议出声朗读前300字和章末200字，往往能比默读更早发现沉浸感断裂点。
   - 以上六问初筛结果在审阅报告中可标注来源层：`[初筛]`。若任意一问标记为阳性，在正式审阅（步骤 2-6）中应优先聚焦该方向做深入检查。

1.5 **AI味四信号快速初筛**（新增——吸收自知乎专栏文章《AI 写的小说会被检测出来吗？讲讲原理，别被焦虑带偏》Majx，2026-07-07）：在进入正式审阅前，审阅者可以用以下四组信号做一次轻量级AI味初筛。这四组信号覆盖了AI生成文本在统计层面的主要可检测模式，快速锁定正文中是否需要额外的去AI味审查：

   - **信号一·高频套话**：快速扫描正文中是否有反复出现的句式、神态描写、万能衔接词（"勾起嘴角""眸色一沉""深吸一口气"等）。如果同一套话在全章出现超过3次（如在多个章节片段中出现10次以上同类动作描写），标记"高频套话"为 Warning。
     - **高频套话严重程度分档**（新增——吸收自知乎"网文老刀17年实战"关于四类模板词汇的论述，2026-07-08）：在标记高频套话后，进一步按出现频率分级：
       - 单章 1-2 次同类模板词 → 正常写作，仅标注观察。
       - 连续 3 次以上同类模板词 → 模板化严重，标记为 Warning，建议进入 `通用-去AI味重写` 做局部替换。
       - 5 次以上同类模板词 → AI流水线水文级别，标记为 Critical，必须在放行前完成全章去AI味拆洗。
     - **同类模板词识别清单**：扩展自该来源的四类分类框架，作为高频套话扫描的辅助参考——①手部动作模板（攥紧/指节发白/指尖微颤）；②情绪危机感模板（后背发凉/心头一沉/浑身一僵）；③神态万能模板（眸光微沉/眼底一暗/神色复杂等"微字诀"）；④心理空话堆砌（欲言又止/五味杂陈/悄然/骤然）。详细替换方案参见 `通用-去AI味重写/references/AI句式替换与动作化替代清单.md` §网文四类AI模板词汇专项替换。
   - **信号二·用词太平滑**：检查正文的词汇使用是否过于"安全"——是否每句话的用词都处在最常规的概率通道中，缺乏方言、行业黑话、口语化破格等"不完美但真实"的用词选择。如果连续300字找不到任何非常规用词，标记"用词过平滑"为 Warning。
   - **信号三·风格过度一致**：检查正文的句长分布和语气是否通篇高度统一。如果所有段落都在3-5句、每句都在15-25字之间，且找不到通篇中语气有明显变化的段落，标记"风格过一致"为 Warning。
   - **信号四·结构模板化**：检查正文的起承转合是否呈现可预测的套路结构——每个场景的"进→看→想→做→出"是否过于工整。如果读者能轻易预判下一段的推进模式，标记"结构模板化"为 Warning。
   - **信号五·上下文污染**（新增——吸收自知乎 zzZZ）：扫描正文中是否存在"人物知道不该知道的信息"的痕迹——人物是否站在作者的全知视角说话、行动是否基于完整的作者认知而非角色当前的信息视野。具体检测方法：
     - **幕后信息泄露标记**：检查人物对话和内心独白中涉及的信息是否全部属于"该角色当前场景下能合理知道的范围"。如果人物说出了只有作者或未来章节才知道的信息，标记"幕后信息泄露"为 Warning。
     - **作者借嘴检测**：检查正文中是否有段落读起来像"作者在替人物解释剧情走向"而非"人物在做自己的判断"。标志性信号——人物行动前给出过多"为什么要这样做"的提前解释，或人物对局势的判断过于全面、远超当前可获取的信息量。标记"作者借嘴"为 Warning。
     - **悬念提前释放**：检查正文是否在本章就揭示了本应由后续章节才释放的信息（如人物提前知道了伏笔的答案、矛盾提前被化解）。标记"悬念提前释放"为 Warning。
     - 以上三种子病假如任意一项命中，额外标记"上下文污染风险"。

   - **五信号综合判定**：命中 ≥2 个信号（含上下文污染子项中的 ≥1 项）→ 标记"AI味高风险"，必须在正式审阅中追加去AI味专项审查，并建议进入 `通用-去AI味重写` 流程处理后再重新审阅。命中 1 个信号 → 标记"AI味关注"，在正式审阅的问题分级中持续跟踪。命中 0 个信号 → 正常通过，不做额外标记。
   - 以上初筛结果在审阅报告中可标注来源层：`[AI五信号初筛]`。此初筛不等同于正式的去AI味深度诊断（参见 `通用-去AI味重写` 的十一种结构指纹），仅作为审阅前的快速定位工具。

1.6 **起承转合结构完整性初筛**（新增——吸收自知乎南梦《一篇文章说清楚小说写作基本功：起承转合》，2026-03-02）：在正式审阅前，用起承转合四段框架对本章做一次快速结构完整性扫描。此初筛定位"这章的结构骨架是否完整"，而非深入评估每段的质量。

   - **问题一·起（欲望+障碍）**：本章前 300 字是否让读者清楚知道"主角这一章要解决什么问题"以及"有什么在阻碍他"？如果读完前 300 字仍不知道本章的驱动方向，标记"起段缺失/模糊"为 Warning。
   - **问题二·承（行动+结果）**：本章中段是否有主角为打破阻碍而采取的实际行动？行动是否产生了可感知的结果（正向/负向/中性均可，但不能是"无结果"）？如果中段全是信息交代、场景描写或对话闲聊而无实质推进，标记"承段空洞"为 Warning。
   - **问题三·转（意外+转折）**：本章是否出现了让读者预期被打破的意外事件或信息？转折后是否产生了新的悬念或追问？如果全章剧情走向完全在读者预期之内、没有任何变量介入，标记"转段缺失→预测性过高"为 Warning。
   - **问题四·合（结局+新篇）**：本章结尾是否既有对本段冲突的交代（哪怕是暂时的），又有驱动读者翻看下一章的引子？如果章末只是"事件自然停止"而无钩子/悬念/新问题，标记"合段缺失→续读驱动不足"为 Warning。
   - **综合判定**：命中 ≥2 个问题 → 标记"结构完整性不足"，在正式审阅中优先聚焦结构维度。命中 1 个问题 → 标记"结构关注"，在正式审阅中跟踪对应阶段。命中 0 个问题 → 结构骨架基本合格。
   - 以上初筛结果在审阅报告中标注来源层：`[起承转合初筛]`。

1.7 **第1章避坑三查**（新增——吸收自知乎桐梦书涵《为什么很多新手写的小说第1章就被编辑毙了？3个致命错误你中了几个》，2026-07-12）：**仅当审阅目标为第1章时执行本项检查。** 第1章的任务只有一个——让读者想看第2章。以下三项是新手第1章被编辑毙稿率最高的三个病灶，每个都配有具体判定标准。

   - **检查一·信息倾泻（毙稿率 ~80%）**：扫描前 1000 字中所有"介绍性段落"——世界观说明、修炼体系介绍、历史背景、势力分布等。如果连续 200 字以上的内容以作者旁白方式向读者"教授"设定信息（而非通过人物对话/行动/情节自然释放），标记"信息倾泻"为 Warning。如果前 1000 字的介绍性内容占比超过 40%，标记"信息倾泻严重"为 Critical。
     - 判定辅助：将本章所有介绍性段落标出，逐段问"这段不写行不行？"——答案为"行"的段落越多，问题越严重。
     - 正面参照：好的第 1 章像冰山——读者只看到 10% 设定，90% 藏在故事背后；坏的像教科书——读者被迫先学完才能开始看故事。

   - **检查二·无冲突开场（毙稿率 ~60%）**：检查前 300 字是否包含一个可识别的"反常事件"——打乱了日常秩序、引入了不确定性的信号。如果前 300 字只是主角日常生活（起床、吃饭、上班、走路）、静态场景描写或纯背景介绍而无任何冲突信号，标记"无冲突开场"为 Critical。
     - 判定公式：前 300 字 = 反常事件 + 主角反应 + 未解疑问。缺少任何一项即为不完整。
     - 餐厅比喻验证：如果本章是一个餐厅菜单，前 300 字有没有一道能让读者流口水的菜？

   - **检查三·路人甲配角（毙稿率 ~50%）**：检查第 1 章出场的所有配角（主角以外的角色）。逐个问：这个人物有没有至少 1 个能让读者记住的具体细节（反常习惯/口头禅/视觉特征/小秘密）？如果一个配角只有功能性存在（传递信息/推动情节/充当背景板）而没有任何独立记忆点，标记"工具人配角"为 Warning。如果第 1 章所有配角都被标记，标记"配角群工具化"为 Critical。
     - 配角记忆点公式：1 个反常习惯 + 1 句口头禅 + 1 个与主角对立的小目标 —— 至少满足其一才算"有记忆点"。
     - "左手缺一根手指的丫鬟"比"她是个忠诚的丫鬟"记忆留存率高数倍——具体细节远超抽象描述。

   - **综合判定**：命中 ≥2 个 Critical → 标记"第1章致命错误高风险"，建议进入对应设计 Skill（信息倾泻→`通用-设计故事设定`；无冲突→`通用-强化章节开头`；路人甲→`通用-设计人物传记`）补设计后重新审阅。命中 ≥2 个 Warning（含 Critical）→ 标记"第1章需要修订"。命中 0 个 → 第 1 章基本合格。
   - 以上检查结果在审阅报告中标注来源层：`[第1章避坑三查]`。

1.8 **烂稿自检——审阅前自我弱点预判**（新增——吸收自知乎阿虚研究社"烂稿自检"方法，2026-07）

   > **来源**：知乎·阿虚研究社《如何提示才能让AI写一篇优秀的小说?》。核心方法：在正式进入逐项审阅之前，让AI先列出本章最可能出现的烂稿问题，审阅者将这些预判问题作为审阅起点——用"AI自己最担心的弱点"引导审阅的优先聚焦。

   **操作方式**：

   ```text
   在开始正式审阅前，用以下指令让AI做一次自我弱点预判：

   "在逐项审阅本章正文之前，请先列出本章最可能出现的五种烂稿问题。
   基于本章的题材类型、人物配置、情节密度和节奏特征，判断哪些维度最容易失分。
   对每个问题给出：①具体判断依据（本章哪个特征让你觉得这里容易出问题）；
   ②如果该问题确实存在，最可能出现在本章的哪个位置（章首/中段/章末/特定场景）。"

   然后在正式审阅时，优先聚焦AI预判的五个维度——如果AI预判准确，说明病灶可被自我感知，
   修复优先级最高；如果AI预判不准（某些它没列出的问题更严重），说明存在"盲区病灶"，
   此类盲区在审阅报告中应单独标注并提升为Critical级别。
   ```

   **使用规则**：
   - 烂稿自检在 1.1–1.7 全部完成后、步骤 2 通读前执行——此时审阅者已有背景认知，AI的预判可与背景对照
   - 预判结果**不替代**正式审阅，它是审阅起点的"聚焦镜"——告诉审阅者先看哪里、优先查什么
   - 若AI预判的五个维度与后续正式审阅的实际发现高度重合（≥3/5）→ 标记"AI自检准确"，后续类似章节可提高烂稿自检的权重
   - 若AI预判的五个维度与后续正式审阅的实际发现低重合（≤1/5）→ 标记"盲区病灶预警"，该章存在AI难以自我感知的深层问题，审阅者需要扩大扫描范围
   - 对于第1章或关键转折章，烂稿自检为**强制步骤**；对于日常章节，为**可选建议步骤**

   **烂稿自检结果在审阅报告中的标注**：
   - 来源层：`[烂稿自检]`
   - 格式：列出AI预判的五个问题 → 逐条标注"命中/未命中" → 标注重合度 → 标注盲区发现（如有）

1.9 **年龄层适配检查——节奏与基调对照**（新增——吸收自知乎顾里木图的小酒馆"八层读者画像"）

   > **来源**：知乎·顾里木图的小酒馆《写小说之前，你要知道当下读者喜欢什么、关心什么》（2026-07-09）。数据：《2024中国网络文学蓝皮书》。
   > **前置条件**：本检查仅在项目 `Agents.md` 中已注册"目标年龄层"时执行。若未注册，跳过不阻断。

   在进入正式审阅前，按项目已锚定的目标年龄层，对照以下基准做一次节奏与基调的快速适配检查：

   | 目标年龄层 | 节奏预期 | 基调红线（违规则标记） | 常见失配表现 |
   | --- | --- | --- | --- |
   | **18-22 岁** | 快节奏，前三章必须亮差异化 | 标记：节奏拖沓（连续2章无中爽点）、说教感（任何"你应该"句式）、套路敷衍（系统流但不新） | 节奏像传统文学、主角犹豫不决、缺乏"发疯"式宣泄段落 |
   | **22-26 岁** | 快节奏，第一人称优先，强代入 | 标记：第三人称距离感过强、职场描写悬浮（不符合真实职场逻辑）、缺乏"重来一次"想象元素 | 主角太顺利没挫折、职场戏写成教科书、缺乏社交互动感 |

   | **45 岁以上** | 舒缓节奏，结局圆满 | 标记：节奏过快（跳场景太频繁）、结局阴暗/不圆满、缺乏烟火气细节 | 过度压抑情节、文笔过于花哨、缺乏"温暖""陪伴"感 |

   以上检查结果在审阅报告中标注来源层：`[年龄层适配]`。

1.10 **前3章开篇质量八项自查**（新增——吸收自知乎南梦《网文开篇怎样快速抓住读者的注意力？》）

   > **来源**：知乎·南梦《网文开篇怎样快速抓住读者的注意力？》（知乎专栏"小说写作技巧分享"，2026-06-24）。
   > **适用范围**：仅当审阅目标为前 3 章之一时执行。第 4 章及之后可跳过。

   以下八项是作者写完前 3 章后应逐条自查的开篇质量检验项。审阅时按以下标准逐条对照：

   | # | 自查项 | 审阅判定标准 | 未通过标记 |
   | --- | --- | --- | --- |
   | 1 | 第一章第一句（100 字内）是否有冲突/悬念/情绪？ | 前 100 字内出现至少一个：冲突信号（退婚/追杀/背叛）、悬念（反常现象）、或强烈情绪（羞耻/愤怒/委屈）。若前 100 字为纯描写/背景说明/日常，判定不通过。 | `[开篇自查#1] 首句无钩子` → Warning |
   | 2 | 主角是否在 500 字内出场，并让读者理解了处境？ | 前 500 字内主角必须出场，且读者能回答"他是谁、当下处境是什么、为什么我要关心他"。500 字内主角未出场或出场后处境模糊，判定不通过。 | `[开篇自查#2] 主角出场过晚或处境不明` → Critical（前3章） |
   | 3 | 第一章结束，读者至少有一种强烈情感（不是无感）？ | 读完后读者是否有心疼/愤怒/好奇/兴奋/震惊等至少一种可明确命名的情感。若无感（"嗯，知道了"），判定不通过。**"无感"是网文开头的死刑**——此条为一票否决项。 | `[开篇自查#3] 章末无感` → Critical |
   | 4 | 第二章有没有通过行动/选择让主角更立体？ | 主角在本章是否有至少一个"只有他才会这样做"的行动/选择，通过该行动读者能看到他的动机、软肋或底线。若角色只是被动经历了事件而无主动选择，判定不通过。 | `[开篇自查#4] 主角无主动选择` → Warning |
   | 5 | 设定信息是否通过剧情带出，而不是大段说明？ | 扫描全章所有"介绍性段落"——若存在连续 100 字以上以作者旁白方式说明设定/背景/体系的段落，且该段落删去后故事不受影响，判定不通过。 | `[开篇自查#5] 设定dump` → Warning |
   | 6 | 第三章是否亮出了金手指或核心主线？ | 第三章结束时，读者应已知道"这本书的核心爽感是什么"——金手指亮相、核心主线启动或故事方向确立。若读者读完后仍不知道"这书到底要讲什么"，判定不通过。 | `[开篇自查#6] 卖点未亮出` → Critical（前3章） |
   | 7 | 每一章的结尾，是否都设置了钩子（悬念/冲突/反转）？ | 逐章检查章末 200 字：是否留下了一个读者无法不追问的问题/未完成的冲突/新出现的变量。若某章结尾像自然结束的段落（"嗯，这章讲完了"），判定不通过。 | `[开篇自查#7] 某章章末无钩子` → Warning（第一章为 Critical） |
   | 8 | 3 章看完，读者是否清楚这本书要讲什么样的故事（类型、卖点）？ | 读完 3 章后，读者应能说出一句话概括本书的类型和卖点（如"废柴逆袭""重生复仇""扮猪吃虎"）。若无法概括，说明开篇没有完成"承诺"——读者不知道自己在追什么。 | `[开篇自查#8] 类型/卖点模糊` → Critical |

   **综合判定**：
   - 命中 ≥1 个 Critical → 标记"前3章开篇质量不合格"，必须回炉。回炉路径：Critical #2/#3 → `通用-强化章节开头`；Critical #6/#8 → `通用-创建小说正文`；Critical #7（第一章）→ `通用-强化章末钩子`
   - 命中 ≥3 个 Warning（含 Critical）→ 标记"前3章开篇质量偏低"，建议回炉
   - 全通过 → 前 3 章开篇质量基本合格

   **与既有检查的关系**：本八项自查与 1.7 第1章避坑三查互补——避坑三查聚焦"最常见的致命错误"（信息倾泻/无冲突/路人甲），本八项覆盖"前3章全局质量"（含第2-3章+跨章连贯性）。两者同时执行可形成更完整的前3章开篇质量画布。

   以上检查结果在审阅报告中标注来源层：`[前3章开篇八项自查]`。

1.11 **章回节奏定位检查——本章在三级节奏中的位置**（新增——吸收自知乎"七层模型"）

   > **来源**：知乎·虎兔阅读《好莱坞的"七层模型"中国化：为什么你的网文火得快凉得更快？》（2026-07-18，第5层：市井江湖与说书传统）。

   中国说书人传统经过几百年驯化，形成了三级接受节奏——每章留扣子、每 5 章小高潮、每 20 章大高潮。本章审阅时，必须先定位本章在三级节奏中的位置，再判断本章是否完成了该位置应有的叙事功能。

   ### 三级节奏定位表

   | 本章位置 | 应有功能 | 审阅判定标准 | 未通过标记 |
   | --- | --- | --- | --- |
   | **任意章** | 章末扣子 | 章末 200 字内是否有读者必须翻看下一章才能解开的悬念/未完成冲突/新变量？若章末读起来像自然结束的段落（"这章讲完了"），判定不通过 | `[章回节奏] 章末扣子缺失` → Warning（第1章/关键转折章为 Critical） |
   | **第 5n 章附近（±1 章）** | 小高潮 | 本章或相邻章是否有让读者"爽到"的情绪回报节点（打脸成功/反转揭露/关键线索到手/小Boss被解决）？若连续 6 章以上没有任何情绪高点，判定不通过 | `[章回节奏] 小高潮断供（已连续 N 章无小高潮）` → Warning |
   | **第 20n 章附近（±2 章）** | 大高潮 | 本章或相邻章是否有质变级事件（身份揭露/实力突破/核心关系转折/大Boss战）？若本章已到 20 章节点但内容仍是日常推进，判定不通过 | `[章回节奏] 大高潮缺失（第 N 章，距上次大高潮已 M 章）` → Critical |

   ### 审阅方法

   1. **定位本章序号**：确认本章是全书的第几章。
   2. **回顾上游节奏**：从第 1 章起，标注最近一次小高潮和大高潮分别出现在第几章。
   3. **对照三级铁律**：判断本章当前位置是否触发了扣子/小高潮/大高潮的检查条件。
   4. **检查章末扣子**：所有章节均需检查章末 200 字是否有钩子。
   5. **输出节奏地图**：在审阅报告中输出本章在全书的节奏位置（如"第 23 章，距上次小高潮 2 章，距上次大高潮 3 章——处于大高潮余震期，节奏正常"）。

   ### 与既有检查的关系

   - 本检查与 1.6 起承转合初筛互补——起承转合检查单章内部结构，章回节奏检查单章在全书节奏中的位置。
   - 本检查与 1.7 第1章避坑三查互补——第1章既是"首章"（需避坑），也是"第 1/5/20 章"节奏链的起点。
   - 本检查与 1.10 前3章开篇八项自查中的 #7（每章结尾钩子）一致——此处将钩子检查从"前3章专项"扩展为"全章节通用"。

   以上检查结果在审阅报告中标注来源层：`[章回节奏定位]`。

### 步骤 2：通读与数据核验
2.1 完整通读本章正文一次，不做中断判断。
2.2 加载 `references/章节数据看板与阶段达标线.md`，核验字数门禁（`BodyCJK` 是否达标）、钩子频率、对话占比（25%–55%）、卖点与 AI 痕迹门禁。脚本输出 `MeetsMinCJK / WithinRange` 必须同时为 `True`。
2.3 **阅读流畅度专项审计**（新增——吸收自知乎答主好难说故事）：通读时同步扫描三类文字流畅度事故，作为独立审计维度。
   - **强迫解释检测**：全文扫描解释性段落（标志词：原来、其实是、实际上、也就是说、众所周知）。凡首次出现的人物/物体/事件附带了超过150字的背景说明，标记为"强迫解释"。
   - **分段与标点纪律检测**：检查是否存在三种典型违规——①一句话一段超过连续5段（段落意思未讲完就换行）；②标点密度异常（平均每2-3个字出现一次标点）；③对话与动作描述分离在不同段落（同一人的对白和动作分家了）。
   - **视角纪律检测**：检查同一段落内是否出现两个以上不同感知主体（视角跳跃）。检查场景内是否不必要地轮流切换了过多人物视角（超过主视角+1-2个关键视角）。
   - 以上检测结果在报告中标注来源层：`[阅读流畅度]`。若命中任意一项，必须在问题分级中如实记录，并按 "Critical → 必修" 处理。
2.4 **人物执行审计**：加载 `../通用-设计人物传记/references/正文可调用素材清单.md` 对照人物抓手兑现程度；加载 `../通用-设计人物传记/references/nuwa-深度人物心智模型注入.md` 审计声口一致性、心智模型落地、压力反应匹配、误判/盲区触发、关系拉扯兑现。
2.5 **写作生动化审阅**（新增——吸收自知乎答主好难说故事·喷神）：通读时同步扫描"文字正确但无画面"的病灶，作为独立审阅维度。检测结果在报告中标源 `[生动化]`。
   - **第一段画面验收**：闭眼测试——第一段文字能否在脑中形成具体画面？如果不能，标记"首段无画面"为 Critical 问题（故事在读者脑子里还没开始就已经模糊了）。
   - **动词/形容词比检查**：统计前 300 字中动词与形容词的比例。形容词数量超过动词的 1/3 时，标记"形容词过度"。重点标记以抽象形容词替代具体描写的句子（如"一道清亮的女声"替换为"一边拍打脸颊，一边查看左右"即为合格方向）。
   - **人物动态化检查**：检查本章每个人物首次出场时是否带有即时行为（动作/反应/判断），还是只有静止的外貌或身份描述。人物出场不带即时行为的，标记"人物出场静止"。
   - **事件牵连感检查**：检查本章核心人物之间的关系是否有"事件牵连感"——他们不只是认识/不认识，而是各自的行为对对方产生了实际压力或推动。如果核心人物之间只是在对话中交换信息而没有相互施压/推动，标记"事件无牵连感"。
   - 以上检测项命中任意一项，必须在问题分级中如实记录，并按 Warning → 选修 或 Critical → 必修 分级处理（第一段无画面为 Critical，其余为 Warning）。详见 `通用-创建小说正文` 的"写作生动化铁律"（好难说故事·喷神方法论）。

2.6 **逻辑链与因果闭环审计（新增——吸收自知乎执光赴君·资深网文作者24本签约经验）**

   本章节检查章节内在逻辑是否自洽、因果链是否闭环、爽点是否有足够铺垫。检测结果在报告中标源 `[逻辑链]`。

   **检查项一：写后逻辑复盘三问**
   - 通读后自问三个问题：
     1. **主线推进**：本章内容有没有推动主线发展？如果有任何段落不服务主线，标记为"无效内容"。
     2. **一致性**：本章是否存在前后矛盾的地方（主角行为前后矛盾、设定自相矛盾、信息冲突）？若有，标记"逻辑不一致"为 Critical。
     3. **必要删减**：本章有没有可删除而不影响理解的段落？若有，标记"可删冗余"为 Warning。
   - 以上三项综合判定：≥1 项逻辑不一致 → 逻辑链判定为"断裂"，必须进入 Critical 必修修；仅有可删冗余而无矛盾 → 标记为"可压缩"。

   **检查项二：因果闭环强制检查**
   - 对本章每一个重要情节/转折/事件，逐项验证是否满足因果闭环：
     - 为什么会发生这件事？（因）
     - 这件事发生之后改变了什么——主角状态、剧情走向、人物关系？（果）
   - 凡是无法同时回答"因"与"果"的事件，标记为"无因果闭环"→ 按 Critical 处理。
   - 常见因果崩盘点：主角突然获得机遇无铺垫、反派放水无理由、爽点从天而降无蓄力。
   - 标记说明：
     - "有因无果"（事件发生但无后续影响）→ 标记为"情节断尾"。
     - "有果无因"（转折出现但前文无伏笔/铺垫）→ 标记为"空降转折"。
     - "因果逻辑链缺失"（事件 A→B 之间缺少推理或行动步骤）→ 标记为"跳步逻辑"。

   **检查项三：爽点铺垫充足性检查（跨章）——四维升级版（增强——吸收自知乎桐梦书涵"爽点设计公式"）**

   > **增强来源**：知乎·桐梦书涵《爽点设计公式：让读者通宵追更的5个方法》（2026-06-20），数据引用：阅文集团《2025网文读者行为白皮书》、起点中文网2025年度月票榜。

   以下四个子维度在原有"爽点铺垫充足性检查"基础上进行系统化升级，覆盖压抑-释放完整性、分层频率、变奏轮换与预期管理四个核心审阅维度。

   **子维度 3a：压抑-释放循环完整性检查**
   - 本章的爽点/回报/高潮是否经历了完整的"压→反压→爽"三段结构？
     - **压**：爽点出现前，读者是否感受到了合理的困境？（不是随便找个反派，而是"这确实很难解决"）
     - **反压**：主角的努力是否遇到了意外挫折？（不是一直输，而是"在努力但遇到了意外"）
     - **爽**：释放是否精准——读者是否觉得"这个反转合理，且超出预期"？
   - 如果爽点出现前没有任何压抑期/困境期/蓄力期 → 标记"压抑缺失→爽点无对比"为 Warning
   - 如果爽点释放后没有让读者感到情绪的明显对比（从压抑到释放的落差）→ 标记"释放无张力→缺少对比效应驱动"为 Warning
   - **数据参照**：追读率前 10% 作品平均每 1.8 章一次情绪高峰，后 10% 为 4.7 章

   **子维度 3b：三级爽点分层与频率检查**
   - 确认本章在当前卷的爽点层级位置，并检查频率是否合理：
     - 小爽点：本章是否至少有 1 个可识别的小爽点（解决小问题/获得小收获/打破小僵局）？
     - 中爽点：距上一章中爽点间隔是否在 3–5 章范围内？若间隔 > 5 章且本章仍无中爽点 → 标记"中爽点断供→追读失温风险"为 Warning
     - 大爽点：本章是否为卷级大爽点？若是，前 3 章是否有充分的蓄力（压→反压→蓄力→爆发）？若前 3 章无蓄力直接爆发 → 标记"大爽点蓄力不足→爆发力打折"为 Warning
   - **数据参照**：起点 2025 月票榜前十作品中爽点平均间隔 3.2 章，大爽点平均间隔 28 章
   - 联合最近连续 3 章检查爽点密度是否合理（保留原有规则）：
     - 连续 3 章每章都有 ≥2 个大爽点事件且章间无等待期 → 标记"爽点过密→审美钝化"为 Warning
     - 连续超过 3 章无中段回报或大爽点 → 标记"爽点断供→失温风险"为 Warning

   **子维度 3c：爽点变奏检查（新增）**
   - 检查本章与上一章的爽点是否存在类型重复——同类型爽点连续出现会导致读者感觉适应（审美钝化）：
     - 情绪类型：本章的爽点情绪类型（轻松碾压/绝境逆袭/布局完成/意外收获）是否与上一章相同？相同 → 标记"爽点情绪类型无变奏"为 Warning
     - 对手类型：本章的对手/障碍类型（嚣张纨绔/老谋深算/体制压迫/亲密关系对抗）是否与上一章相同？相同 → 标记"对手类型无变奏"为 Warning
     - 获得类型：本章的爽点获得形式（武力碾压/智谋取胜/真相揭露/盟友赢得/关系修复）是否与上一章相同？相同 → 标记"获得类型无变奏"为 Warning
   - 如果连续 3 章都是"打脸嚣张配角"模式 → 升级为 Critical，"变奏严重失效→读者审美疲劳高危"
   - 联合最近 5 章检查变奏覆盖度：5 章内至少覆盖 ≥2 种不同情绪类型、≥2 种不同获得类型

   **子维度 3d：读者预期管理检查（新增）**
   - 检查本章是否管理了读者的预期——不是"给不给爽点"，而是"怎么给"：
     - 本章是否明确预告了"下一章一定会发生什么"？若是 → 标记"确定性过高→多巴胺预期衰减"为 Warning（确定的奖励不如不确定的奖励更能刺激多巴胺）
     - 本章是否采用了"半满足+超预期"策略？——先满足读者一部分期待但不完全满足（如获得突破契机但设置延迟），再给出超出读者预期的额外惊喜
     - 如果本章勾起了强烈期待但兑现不足（读者反应："期待已久的场景，结果就这？"）→ 标记"期待兑现不足→读者信任消耗"为 Warning
   - 知乎 2025 网文话题统计：读者最失望的剧情类型第一名——"期待已久的场景，结果就这？"

   以上检测结果与步骤 3.4 的节奏密度审阅交叉引用，避免重复标记。

   以上检测结果在报告中标注来源层：`[逻辑链]`。检查项一/二命中任意一项按 Critical 处理；检查项三按 Warning 处理。

2.7 **节奏加速品质审计（新增——吸收自知乎"我的世界"&半盏清茶煮春秋）**

   本章节检测节奏是否受"停滞感"拖累，以及场景切换/内部推进手法是否有效。检测结果在报告中标源 `[节奏加速]`。

   **检查项一：三停滞诊断**
   - 扫描全章是否存在以下三种典型停滞，命中任意一类标记对应类型：
     - **情绪停滞**：主角伤心，花大量篇幅反复描写内心多痛，但情节一步未往前推进。标记"情绪停滞→原地踏步"为 Warning。修正方向：把情绪通过动作/对话外化，而不是靠内省段落填充。
     - **信息停滞**：读者已经能推断出的信息，还让角色重新推理一遍（如读者已知道凶手是谁还让侦探从头梳理证据）。标记"信息停滞→重复展示"为 Warning。修正方向：跳过重复推理，让角色直接使用已知信息做新决策。
     - **解释性停滞**：过度解释动机、背景、前因后果——就像正看球赛到临门一脚突然插播五分钟战术分析。标记"解释性停滞→信息阻断"为 Warning。修正方向：删标志词（"其实""原来""实际上""也就是说"），把背景信息压缩成 1-2 句自然融入场景。
   - 综合判定：全章命中 ≥2 类停滞 → 节奏品质判定为"重度拖沓"，标记为 Critical，必须进入本轮必修；命中 1 类 → "中度拖沓"，标记为 Warning，选择性修。

   **检查项二：场景切换效率检查**
   - 扫描本章中所有场景切换点（段落间/章节间的时空跳转），检查切换方式：
     - 是否老老实实地写了"过渡"（他怎么去、中间发生了什么）——如果是，标记"→过渡性切换"为 Warning。修正方向：用情绪弹射或直接跳转替代。
     - 切换后的第一句话是否直接推进新信息/新动作，还是继续描述环境/氛围——如果是后者，标记"→切换后空载"为 Warning。
   - 综合判定：连续 2 次切换都是过渡性切换 + 切换后空载 → 本章的加速结构可能从根上就没搭好，需要先回卷纲/控制卡重新设计节奏骨架。

   **检查项三：情节锁链审计（场景任务密度检查）**
   - 扫描本章每个场景，判断其完成的叙事任务数量：
     - 该场景是否只推进主线（单一任务）？
     - 该场景是否同时完成了"信息释放+人物关系+悬念埋设"中的至少两项？
   - 场景任务密度 = 完成 ≥2 个任务的场景数 ÷ 总场景数。该比值 < 50% 时，标记"场景任务密度不足→效率偏低"为 Warning。
   - 修正方向：将单一任务场景中的纯信息释放合并到相邻的动作/冲突场景中。

   **检查项四：详略得当审计**
   - 扫描全章的篇幅分配——是否存在"非卖点部分写得和卖点部分一样长"的问题：
     - 本章的核心卖点/亮点/爽点占据了多少篇幅？如果卖点篇幅占比 < 30%，标记"详略失当→卖点篇幅不足"为 Warning。
     - 本章中是否存在"重要性高但无聊"的情节（如买装备、赶路、开会）被写了过多篇幅？如果是，标记"详略失当→非卖点过量"为 Warning。修正方向：东市买骏马式的一笔带过，把篇幅留给真正值得展开的内容。
   - 以上检测结果已在 step 3.4 节奏密度审阅中覆盖的维度（如爽点过密）不重复标记。

   以上检测结果在报告中标注来源层：`[节奏加速]`。检查项一/二按 Critical/Warning 处理；检查项三/四按 Warning 处理。

2.8 **上下文污染审计（新增——吸收自知乎 zzZZ "上下文污染"系统性分析）**

   本章节检测 AI 辅助创作中是否存在"上下文污染"痕迹——即人物是否站在作者的全知视角说话、行动是否基于完整的作者认知而非角色当前的信息视野。检测结果在报告中标源 `[上下文污染]`。

   **检查项一：人物信息视野一致性检查**
   - 逐段扫描本章每个核心人物的对话和内心独白，列出该人物在本场景中"应该知道的信息范围"与"实际表现出来的信息范围"进行对照。
   - 如果人物的措辞、判断、行动基于了"该角色在当前场景下无法合理获知"的信息（如未来剧情走向、其他视角的事件、作者后台设定），标记"信息视野越界"为 Critical。
   - 常见越界信号：
     - 人物对全局局势的判断过于全面、远超当前可获取的信息量
     - 人物行动前给出过多"为什么要这样做"的提前解释——更像作者在向读者解释剧情走向
     - 对话中自然带出了本应由后续章节才揭示的信息
   - 修正方向：将越界的信息判断改写为"基于当前所见所闻的推测/困惑/试探"，让读者和人物一起探索未知。

   **检查项二：悬念侵蚀检查**
   - 检查本章是否在本该"蓄悬念"的位置提前释放了悬念答案——即读者还没有产生"这是怎么回事"的疑问，人物就已经说出了答案或暗示。
   - 标记逻辑：如果人物在本章中的言行暗示了一个"本应由读者自己拼凑出的结论"，而该结论在当前阶段过早暴露，标记"悬念侵蚀→答案前置"为 Warning。
   - 常见场景：人物提前说出了一句本应由读者在后续章节中自己发现的真相；或人物过于顺利地连接了本应需要更多调查/推理才能建立的因果关系。
   - 修正方向：删除或模糊化人物的"超前判断"，改为只写人物观察到的事实，把因果关系留给读者推断。

   **检查项三：审阅视角污染检查（审阅层元检查）**
   - 执行本章审阅前，确认本次审阅所使用的上下文是否包含了"作者后台信息"（如未来章纲、未公开伏笔、作者意图说明）。如果审阅时使用了 AI 创作时的完整上下文，审阅结论可能会被污染——AI 会基于幕后信息替正文补因果，得出"逻辑能成立"的结论，但真实读者没有这些信息。
   - 如果当前审阅过程存在视角污染风险（审阅上下文混入了创作阶段才有的后台信息），在审阅报告中标注"⚠ 审阅视角污染风险"，并在结论中将技法评分下调 0.3–0.5 分作为修正。
   - 参见 `通用-创建小说正文` 的 `## AI 上下文管理原则：避免上下文污染` 中的"视角边界"原则。

   以上检测结果在报告中标注来源层：`[上下文污染]`。检查项一按 Critical 处理；检查项二按 Warning 处理。检查项三为审阅层元检查，不影响本章评分但影响评分可信度标注。

3.4 **节奏密度与情绪结构审阅**（新增——吸收自知乎精华"网文节奏与爽点把控"）

   本审阅项检查章节的节奏密度是否合理、情绪结构是否成立，避免出现以下三种常见的节奏结构型错误：

   **检查项一：爽点密集排布——"审美钝化"风险**
   - 检查本章（或最近连续 3 章）是否过度密集排布爽点（打脸/装逼/升级/反击），导致读者产生"审美钝化"。
   - 标记逻辑：如果最近 3 章中每章都有 ≥2 个大爽点事件（打脸/升级/装逼/碾压），且章间无任何"等待期"或"压抑期"，标记"爽点过密→缺乏期待感"为 Warning。即使单章技法过硬，连续无等待期的爽点排布也会降低下一次爽点的冲击力。
   - 修正方向：考虑将部分爽点延后，在爽点前插入"期待感"段落（主角面临新困境 / 对手施加新压力），让读者先产生"主角什么时候爆发"的预期，再释放爽点。

   **检查项二：只有升级没有情绪——"数字增长无体感"风险**
   - 检查本章的核心升级/突破/胜利是否附带足够的情感代价、动机支撑或情绪积累。如果升级被写成"闭关三年→突破了"或"主角赢了→数据涨了"的干巴巴推进，而没有"为什么这次升级对主角很重要""读者为什么在乎这个结果"，标记"升级无情绪"为 Warning。
   - 区分标准：读者兴奋的不是"修为数字涨了"，而是"主角终于能去救人了""主角终于能打脸那个嘲笑他的人了"。升级必须有困境、情感、或动机的引导才能转化为读者感知的"爽"。
   - 修正方向：在升级/胜利之前增加"为什么这次胜利很关键"的铺垫（困境深化 / 情感羁绊 / 代价显影），让读者的情绪高点和升级结果同时落地。

   **检查项三：缺乏降温章节——"全程高压≠节奏好"风险**
   - 检查最近的连续章节中是否有合理的"降温段落"（日常生活/配角视角/世界观信息自然传递/主角的小挫折或困惑）。如果连续 5 章以上都是高压冲突/紧张推进/连续高潮，没有任何节奏回落，标记"缺乏降温→爽点钝化"为 Warning。
   - 原理：节奏像心跳——有高有低才是生命。合理的降温章节能让爽点效果翻倍。降温章节的关键不是"无聊"，而是"有信息量但有张力"。
   - 修正方向：在连续高压之间插入 1-2 章低密度节奏段（人物互动/世界观显影/信息铺垫/情绪缓冲），让读者有"呼吸空间"，下一次高潮的冲击力会显著提升。

   以上检测结果在报告中标注来源层：`[节奏密度]`。命中任意一项按 Warning 处理；同时命中两项及以上按 Critical 处理——即使单章技法过关，连续的结构型节奏错误也会导致追读下降。

   **检查项四：节奏快慢失调——三种常见时机病灶（新增——吸收自知乎"写作技巧——如何把控小说节奏"）**
   - 检查本章是否存在以下三种节奏快慢控制失当：
     - **全程紧张无缓冲**：本章（或连续多章）是否全程打斗/冲突/高压，没有安排任何"松"的段落让读者呼吸？如果是，即使每段冲突本身写得不错，读者也会在持续高压中产生疲劳，反而削弱对高潮感知力。标记"全程紧张→节奏疲劳"为 Warning。
     - **冗长拖沓阻碍主线**：本章是否存在大段无关日常或冗长心理戏，导致主线推进停滞？区别标准——该段删掉后主线逻辑是否仍完整、读者对角色/事件的认知是否有实质变化。若无实质损失，标记"拖沓段→主线停滞"为 Warning。
     - **快慢切换生硬无过渡**：本章的情绪/节奏切换是否过于突兀——刚写完生死场面立刻转入无关琐事、激烈冲突后直接跳到平淡日常，没有给读者任何缓冲过渡？检查切换处是否有过渡信号（时间推移标记、情绪余波处理、场景自然轮换）。若无合理过渡，标记"切换生硬→情绪断裂"为 Warning。
   - 修正方向：
     - 全程紧张无缓冲 → 在连续高压之间插入 1–2 个低强度场景（人物互动、信息铺垫、情绪缓冲），作为读者呼吸空间。
     - 冗长拖沓阻碍主线 → 判定该段对主线/人物的贡献：若有实质信息或关系推进则保留并压缩字数；若无实质贡献直接删除或合并到其他段落。
     - 切换生硬→在两段之间加入过渡层（时间推移、视角转换的感官缓冲、或角色情绪余波的承接句），让节奏切换更自然。
   - 以上检测结果在报告中标注来源层：`[节奏快慢]`。命中任意一项按 Warning 处理。
### 步骤 3.5 情绪锚点与段落执行品质审计（新增——吸收自知乎精华"写小说要快速掌握的二十个技巧"·顾里木图的小酒馆）

   本章节检查章节正文在情绪锚点、段落纪律、重复修辞与延迟释放四个维度的执行质量。检测结果在报告中标源 `[情绪与段落]`。

   **检查项一：情绪锚点在场检查**
   - 扫描全章，判断本章是否至少有一个"读者读完后脑子里留下的情绪印象"——可以是一句让心头一紧的对话、一个让人会心一笑的细节、一个让人攥紧拳头的反转或一个闷痛的心理顿挫。
   - 如果全章读完只有"情节推进了"而没有"读者体验到了一种情绪"，标记"无情绪锚点"为 Critical。网文读者不是来接收信息的，是来体验情绪的——信息可以忘记，情绪会留下来。
   - 修正方向：在章节中段或章末插入一个专用于"制造情绪体验"的微小瞬间——不一定是大事件，可以是一个有温度的动作、一句有潜台词的对话、一个让读者自己拼出判断的留白。

   **检查项二：段落一章一职检查**
   - 扫描全章段落，判断是否存在"一段塞了多件事"的密集段——同一段内同时做了"环境描写+推进对话+展示动作+心理分析"。如果连续读到3段以上是"多任务段落"，标记"段落密度过载→信息消化不良"为 Warning。
   - 原理：一段只做一件事——一段描写环境，一段推进对话，一段展示动作。段落是读者的呼吸间隔；一段太密读者喘不过气，一段太长读者容易走神。
   - 修正方向：将多任务段落按"环境/对话/动作/心理"切分为独立段落，确保每个段落的功能单一、边界清晰。

   **检查项三：重要词重复三次加速检**
   - 扫描全章，查找是否有"重要的词、物品、地名或句子被重复三次"的设计——第一次出现是信息，第二次是强调，第三次是记忆锚点。第四次出现时它已经自带情感分量。
   - 如果全章没有任何被刻意重复的关键元素，且该章处于需要强化记忆点（人物身份标记、核心道具首现、关键地名）的节拍位置，标记"无三次重复→关键元素记忆锚点缺失"为 Suggestion。
   - 此维度仅在关键元素首次出现的章节中做 Critical 判定，日常章节中按 Suggestion 处理。

   **检查项四：延迟释放执行检查**
   - 本章是否包含重要情感节点（坏消息、死讯、背叛、诀别、震惊真相）？若有，检查释放方式：
     - 是否给了角色"愣住→做一件普通事→无意识动作暴露→情绪才开始流"的渐进序列？
     - 还是角色当场完整宣泄？（当场宣泄 = 延迟释放的反面，消解了情绪蓄力空间）。
   - 如果重要情感节点被"当场完整宣泄"（角色听到坏消息立刻大哭/崩溃/说出一整段心理话），标记"延迟释放缺失→情绪一次性消耗"为 Warning。
   - 原理：延迟释放比当场宣泄更有力，因为读者和人物一起扛了一段时间。
   - 修正方向：在情感冲击时刻插入一个"无意识动作"作为情绪缓冲——洗杯子、整理书架、倒水直到溢出——让情绪在动作的缝隙中自然渗透出来。

   **检查项五：人物辨识度台词审查**
   - 扫描本章核心人物的台词，判断是否有"一听就知道是TA"的辨识度——不看对话标签能否猜出谁在说。
   - 如果所有主要角色的台词调换标签后看不出区别（张三说的换成李四说也不违和），标记"同腔化→人物台词无辨识度"为 Warning。
   - 修正方向：为每个主要角色找到一句话的句式/用词/节奏特征——有的习惯反问，有的喜欢把话只说一半，有的每句必带语气词，有的说了等于没说。同一个人物在不同场景里说的话应该有相同的"气味"。

   以上检查项命中任意一项，在报告中标注来源层 `[情绪与段落]`。检查项一/二按 Critical → 必修处理，检查项三/四/五按 Warning → 选择性修处理。

### 3.6 情绪触发潜力评估：预测读者反应信号（新增——吸收自知乎顾里木图的小酒馆）

> **来源**：知乎·顾里木图的小酒馆《网文写作怎么样走进读者的内心》（2026-07-09）。原文描述的是评论区的真实读者反馈类型；此处转化为审阅者在放行前预测本章是否有潜力触发这些反应的评估维度。

在完成所有维度审阅后、构建报告前，审阅者可以用以下三类**读者情绪反应信号**做一次"换位思考"测试——不是检查正文里写了什么，而是预测读者读完会有什么反应：

| 信号 | 读者反应 | 审阅时问自己 | 对应章节状态 |
|------|---------|-------------|-------------|
| **情绪共鸣** | "看到XX那段我哭了/难受/喘不过气" | 本章是否有至少一个能让读者卸下防御的情绪锚点？ | 如果有 → 通过；没有 → 标记"缺乏情感触点"为 Suggestion |
| **参与型着急** | "主角怎么还不XX""他为什么不去做XX" | 本章是否让读者开始替主角着急/做决策？还是读者只是在冷眼旁观剧情推进？ | 如果有 → 通过；没有 → 标记"读者被动旁观"为 Warning |
| **主动预判** | "我觉得XXX是装的""我猜后面会……" | 本章是否提供了让读者自己推导结论的信息空间，还是把所有判断都替读者做了？ | 如果有 → 通过；没有 → 标记"判断空间不足"为 Suggestion |

**综合判定**：三个信号中命中 ≥1 个 → 本章具备基础的情绪触发潜力。0 个命中 → 本章可能在"功能上正确"但"情感上空转"——即使技法评分过关，也建议在放行前补至少一个情绪触发设计。

**注意**：此评估是预测性判断，不替代真实读者反馈。它的价值在于提醒审阅者——不要在"所有检查项都过了但不知道为什么读者就是不追"的情况下放行章节。如果三条信号全空，说明本章在读者端可能只是"信息传递"而非"情感体验"。

- **项目层（同项目内不变）**：风格/蓝本模板自动发现规则 + references 清单 + 审前裁判源复核要求 → 仅在切换项目或新增模板注册时变化
- **可变层（每次变化，不写入本文件）**：本次审阅的章节文件路径、本章人物/设定快照、用户指定的审阅侧重维度 → 由用户每次调用时指定
- 人物传记、故事设定等裁判源通过 references 声明强制加载，其固定部分随本 Skill 一起进入缓存前缀

2. **评分影响**：蒸馏产物对标维度在章节审阅综合评分中默认按 **20%** 计权（纳入现有十维评分体系，不对十维做减法，而是在审阅报告中作为一个独立的"蒸馏对标审计"板块呈现）。若未完成对标审阅，需在审阅报告中标注"蒸馏对标盲区"。
3. **缺模板回退**：若缺少某类蒸馏模板，该对标维度自动跳过，不扣分，不阻断。
4. **冲突处理**：蒸馏产物对标结论与审前裁判源（人物传记/故事设定）冲突时，以审前裁判源为准。蒸馏产物约束之间冲突时，写作研究模板的硬门禁 > 作品蓝本模板的强约束 > 作者风格模板的软建议。
5. **报告呈现**："蒸馏对标审计"板块在章节审阅报告中建议作为一个独立子章节插入在"十维评分"与"问题分级"之间，不改变现有报告骨架的顺序。对标维度采用"通过/偏移/异常/未覆盖"四级来标记匹配度，而非数字评分，以与十维评分区分。

## 审前裁判源复核（强制）

- 出具任何章节审阅结论前，必须认真仔细阅读与本章实际出场人物对应的人物传记，以及与本章背景、技术、规则、证据、程序链、世界观有关的故事设定文档。
- 不得只凭读感、题材经验、上一轮审阅报告或控制卡摘要直接下结论；凡涉及人物动机、能力边界、关系状态、设定代价、证据机制的判断，都必须回到作者侧裁判源核对。
- 若同一人物传记或故事设定存在多个版本，必须先确认当前可执行的最新版本；若关键裁判源缺失，必须先列为阻断项，再继续审阅，而不是边猜边打分。
- 审阅报告里必须显式写出本轮核对了哪些人物传记 / 故事设定，以及正文哪些细节与之吻合、哪些冲突、哪些仍待补丁。

## 完整模板执行要求（强制）

- 产出章节正文审阅报告时，必须以 `references/章节正文审阅完整模板.md` 作为主骨架，不得退化成“几段点评 + 少量建议”的简版报告。
- 报告至少要完整覆盖：阅读链路确认、内容概要、字数与结构核查、节奏与钩子、题材专项核查、读者端留存信号、大纲与传记落地核查、问题分级、最小返工处方、前后呼应与主题检查、读者体验评估、记忆点评估、评分、具体修改方案、总体结论。
- "字数与结构核查"不得只凭目测；**正文字数检测必须使用 `scripts/count-chapter.ps1`**，不得用 `Len`、`NoWhitespaceLen`、编辑器字符数或目测代替。字数参数按以下优先级确定：① 项目 `Agents.md` 中主输出平台指定 → ② 主输出平台对应 `通用-输出*版/SKILL.md` 的"平台默认字数范围" → ③ 通用回退值（中文正文 2500–5000 CJK，作者有话说 150–300 CJK）。正文门禁只看 `BodyCJK / MeetsMinCJK / WithinRange`，`MeetsMinCJK` 必须为 `True`，`WithinRange` 最好为 `True`。若同文件含 `## 作者有话说`，也必须把它作为独立门禁项单列：中文用 `scripts/count-afterword.ps1`（参数取上述来源），英文或英文平台稿用 `scripts/count-afterword-words.ps1`（参数取上述来源）判断。
- 章节审阅报告中的字数字段，必须显式记录脚本输出的 `Len / CJK / BodyCJK / MeetsMinCJK / WithinRange`；`BodyCJK` 是字数门禁的唯一参考依据（具体范围以主输出平台对应 `通用-输出*版/SKILL.md` 的"平台默认字数范围"或项目 `Agents.md` 指定值为准），`Len` 仅作参考。
- 若报告出现“正文字数：XXXX（去空白统计）”或其它以自定义字符数替代 `BodyCJK` 的写法，视为审阅未完成，必须回炉重跑脚本并刷新报告。
- 若用户要求连同 `## 章节后记` 一起审，至少要核对：位置与标题是否正确、字段是否覆盖本章定位 / 功能点落地核对 / 冲突与悬念 / 爽点登记 / 伏笔与回收 / 设定或程序呈现 / 人物发展 / 证据要素 / 钩子类型 / 数字纪律检查 / 偏离记录 / 后续铺垫 / 读者吸引点 / 优化建议，且这些字段都与正文逐项对应。
- 若当前任务还加载了题材 Skill，则必须在通用完整模板的占位章节中继续补写题材专项段、题材专项评分项与题材化结论重点。
- 若存在上游控制卡、分卷承诺或人物传记约束，报告必须显式指出哪些已兑现、哪些仍悬空，不得只给纯读感结论。

## 十二维双轴评分、处理方分流与骨架忠实度补强（改造版）

> 从"十维技法评分"扩展为"十二维双轴评分（技法10维 + 留存2维）"，以解决内部技法审阅与平台留存标准之间的系统性错位。详见 `references/十维评分_处理方分流_钩子链与骨架忠实度补编.md` §二·五 与 `../../写作研究/网文留存模型.md`。

### 双轴评分执行

1. **技法轴（维度 1-10）**：叙事逻辑、人物一致性、连贯性、场景规划执行、节奏与张力、对话质量、描写质量、去 AI 味、钩子与悬念、字数与密度；每维 `1-5` 分，技法原始分满分 `50`。
2. **留存轴（维度 11-12）**：情绪刺激密度、追读驱动力；每维 `1-5` 分，留存原始分满分 `10`，再减留存红灯扣分（每红灯 -1 分）。
3. **综合评分**：技法分 × W_技法 + 留存分 × W_留存。权重按主输出平台自动选择（详见 `十维评分_处理方分流_钩子链与骨架忠实度补编.md` §二·五 动态权重表）。
4. **放行门槛**：技法分 ≥ 7.0 **且** 留存分 ≥ 6.0 方可绿色放行。

### 处理方与来源层标注（不变）

- 报告中的每个问题都必须同时标注处理方与来源层：`writer / polisher`；`[骨架层] / [扩展层] / [表达层]`。一旦涉及"写什么"，交 `writer`；只涉及"怎么写"，交 `polisher`。
- **新增处理方标注**：留存轴问题标注额外方向——`retention-writer`（需回设计/控制卡）、`retention-polisher`（可回创作/润色）。参照 `网文留存模型.md` §四 留存责任矩阵。
- 默认单列“钩子链验证”：上章出口钩、本章入口响应、本章出口钩、下章预期响应、最近 `3` 章类型是否重复、是否存在断链。
- 默认单列“骨架忠实度评估”：承重 beat 是否在场、顺序是否保持、大纲语言是否残留、是否存在合理偏离、骨架忠实度高 / 中 / 低。
- 默认判定口径沿用 `Green / Yellow / Red`：`Green`=`总分 ≥ 35` 且无单项 `≤ 2` 且无红线；`Yellow`=`25–34` 或有单项 `= 2`；`Red`=`< 25` 或核心维度 `≤ 1` 或命中红线。
- 红线至少包括：因果链断裂、人物知道不可能知道的信息、承重 beat 缺失、情感弧完全未执行、上章钩子未回应且无理由、大纲语言残留超过 `2` 处。
- 若体裁字段明确，审阅时默认上调对应维度的从严程度：悬疑更看信息控制与公平误导，言情更看情感真实性与潜台词，科幻更看概念清晰与一致性等。

### 问题优先级与修订策略（新增）

不是所有问题都值得在每一轮回炉中修订。审阅报告中的每个问题应按以下三级标记优先级，修订环节据此决定修与不修：

| 优先级 | 标签 | 定义 | 修订策略 |
|---|---|---|---|
| 关键问题 | Critical | 导致读者出戏、因果链断裂、人物崩塌的硬伤 | **必须修**，进入本轮回炉 |
| 警告问题 | Warning | 影响阅读体验但不致命（节奏略慢、某段描写冗余） | **选择性修**，按回炉剩余容量决定 |
| 建议问题 | Suggestion | 可改可不改的审美偏好或风格差异 | **看情况修**，通常留到下一批或不做处理 |

修订顺序：先修 Critical，再按剩余容量修 Warning。Suggestion 问题即使本轮不修，也在审阅报告中留存供后续参考。

### 审阅交叉验证（可选强化）

当单次审阅结论不够确定（如处于 Yellow/Red 边界，或问题清单偏长但难以区分硬伤与风格偏好）时，可用不同人格口径的 LLM 做第二轮独立审阅进行交叉验证：

| 人格 | 关注侧重 | 适合场景 |
|---|---|---|
| 文学评论家 | 叙事结构、主题深度、情感共鸣、余韵 | 文风、节奏、情绪连贯性拿不准时 |
| 小说教授 | 技巧运用、节奏控制、人物塑造、读者留存工程 | 技法执行、追读工程拿不准时 |

交叉验证的核心价值：**两个独立审阅都指出同一个问题 → 大概率是真实硬伤，必须修；只有一方提到 → 可能只是风格偏好或审阅者个人口径偏差**，可降级处理。

本机制为可选强化，不做默认执行要求。

本轮审阅中，以下基准数据为强制门禁：

**字数门禁**：
- 中文正文（脚本 `BodyCJK`）：以主输出平台对应 `通用-输出*版/SKILL.md` 的"平台默认字数范围"或项目 `Agents.md` 指定值为准，超出范围视为门禁失败。
- 中文作者有话说：以主输出平台对应平台默认字数范围或项目指定值为准，超出范围视为门禁失败。
- 脚本输出 `MeetsMinCJK` / `WithinRange` 必须同时为 `True`。

**钩子与节奏门禁**：
- 前 200 字钩子：必须存在，类型为冲突 / 悬念 / 异常 / 强情绪 / 动作 / 对话中之一。
- 后 200 字钩子：必须存在，不得是问号或虚空狠话。
- 单章对话占比：25%–55% 范围内（脚本扫描：`grep -c "「" / 总行数`）。
- 中段回报：必须存在，类型为情绪转折 / 处境改变 / 信息释放 / 能力显示 / 关系推进中之一。

**卖点与AI痕迹门禁**：
- 若本章承担卖点回报职责，该卖点必须在本章明确兑现或推进。
- 正文中不得出现以下AI万能句式（每项超过2次视为病灶）：
  - "眸中闪过一丝 X"
  - "XX缓缓说道"
  - "XX心中暗道"
  - "总而言之 / 可以说 / 值得注意的是"
  - "突然 / 忽然 / 猛地"（应通过语序制造意外感，而不是副词）
  - "他非常 X"（应改为动作+生理反应+决策三段式）
- 章节自指（"这几章""前几章""下一章""本章"等）与连载导览腔（"后文会""我们会看到""读者会发现"）视为沉浸事故，命中即为门禁失败。

**规则与证据链门禁**：
- 涉及故事设定、规则机制、证据程序的表述，必须与当前可执行的故事设定裁判源一致。
- 人物的能力边界、代价显现、动机推动，必须与当前人物传记版本相符。

**视角门禁（新增）**：
- 章节主视角必须在首段内确立，且整章保持同一主视角，不得出现上帝视角偷跑（主角不知道的事，叙述却提前说了）。
- 若主视角为第三人称限知，正文中不得出现其他角色的内心活动、远处发生的事、或主角不可能知道的背景信息——除非明确标注为推测/误判。
- 正文不得出现"作者在外部拍摄主角"的视角塌陷病灶：如"他的腿不争气地颤抖""他并不知道这是哪里""潜意识告诉他"——此类表述应改为角色自主感受（"他低头看了一眼自己的腿。在抖。停不下来。"）。
- 禁止用抽象程度副词（很、非常、特别、极其、无比）直接宣布角色情绪，应改为具体感官描写（手心出汗/喉结滚动/胃缩/耳鸣）。命中超过 3 处即为视角门禁失败。

## 起点爆款判断快筛接口（新增）

章节审阅不仅要判断“这章写得顺不顺”，还要判断“这章是否具备起点爆款链路里的继续放大价值”。

### 10 秒快筛（章节版）

默认把本章先按起点编辑 / 老白读者的极短时长快筛一遍；命中以下 `3` 项及以上弱信号时，本章默认不得判高档：

1. **题材归类是否瞬时成立**：读者在标题 + 首屏里，是否能立刻看懂这还是哪种书、这章服务的是哪条主卖点。
2. **前 200 字是否有强钩子**：若前 `200` 字无冲突 / 异常 / 压力信号，按爆款口径直接判首屏危险。
3. **前 300 字是否已扔出炸点**：是否出现了突发意外、强烈反差、关系失衡、倒计时、规则错位中的至少一项。
4. **主角记忆点是否在场**：主角是否表现出鲜明标签、方法论抓手或压力下的独特反应，而不是“正确但无辨识度”。
5. **章末是否有翻页驱动**：本章结束时，读者是否明确知道“有坏事要发生”或“有一个未完成动作必须接着看”。

### 3 分钟深评（章节版）

当章节需要进入细审时，默认补做一次爆款判断标准里的 `3` 分钟深度评估，并把结果翻译为段位级补丁：

- **0–300 字**：是否有突发意外或强烈反差；若无，章首应优先回炉。
- **300–800 字**：危机是否真正降临、目标是否确立；若主角还在被动接收信息，判中段起步偏软。
- **800–1500 字**：是否给出首个微小成就、小奖励、反击苗头或明确回报预期；若没有，判回报延迟。
- **章末**：是否形成“新危机 + 新期待”双钩子；若只是收尾情绪，则判续读驱动力不足。

若章节承担起点强竞争位（卷首章、收费节点、大转折章），审阅报告还应单列判断：

- 金手指 / 关键能力是否仍保持“极简逻辑 + 极强变现力”；
- 人物是否仍具备“低起点 + 强动机 + 反套路 + 立体弧光”的持续吸附力；
- 节奏是否做到了“一波未平一波又起”，而非把冲突写成平推流程。

### 爆款潜力分档（章节审阅辅助口径）

除 `Green / Yellow / Red` 工程判定外，若已配置主输出平台，默认允许再给一层"本章对整书爆款链路的助推强度"判断。

| 档位 | 判断标准 | 审阅含义 |
| --- | --- | --- |
| S | 首屏强钩、主角记忆点强、中段有值回票价回报、章末强驱动，且存在段评 / 本章说讨论点 | 这章具备明显放大潜力，可作为竞对对照中的强章 |
| A | 抓力、回报、留钩三项里至少两项过硬，短板可用局部补丁修复 | 这章能稳住追读，但还未到爆点级 |
| B | 结构基本成立，但首屏 / 回报 / 章末中至少一项偏弱 | 这章能读，但对爆款链路贡献有限 |
| C | 慢热、无回报、无驱动、人物失焦或节奏塌陷命中两项以上 | 这章会拖累整书追读，需要优先返工 |

该分档只用于辅助判断“这章对整书商业链路的贡献”，不得替代完整审阅结论与问题分级。

## 中期验证指标与数据代理信号

章节审阅若已配置主输出平台，默认还要把"读感判断"翻译成"可能映射到什么数据后果"的代理信号。具体平台指标与数据参照标准由主输出平台对应的 `通用-输出*版` Skill 提供。

### 章节级数据代理信号

以下不是硬数据预测，而是审阅时默认要显式判断的**数据后果代理**：

| 审阅现象 | 可能影响的代理指标 | 默认判断 |
| --- | --- | --- |
| 前 200 字无强钩子 | 点击→阅读转化率 | 容易跌破 `40%`，需优先抢修章首 |
| 前 5 章持续无升级 / 无回报 | 第 3/7/15 天留存 | 留存链可能提前塌陷 |
| 章末无明确接棒缺口 | 追读率 / 追订 | 收藏→追读比可能走弱，续读惯性不足 |
| 主角记忆点发虚 | 本章说 / 段评活跃度 | 讨论点不足，角色站队弱 |
| 中段只有解释没有兑现 | 章节留存率 | 低于 `50%` 的风险升高 |
| 关键收费章回报偏软 | 首订 / 追订 | 付费转化与后续追订承压 |

### 10 万字前的章节审阅重点

根据起点爆款判断标准，`60%` 的流失通常发生在前 `15` 章；因此当前章若处于前 `15` 章范围，报告必须额外回答：

1. 这章是在**拉新、稳留、转付费**中的哪一种职责？
2. 这章是否让读者更清楚“这本书最值钱的地方”是什么？
3. 这章是否给出了至少一次可截图、可段评、可站队的记忆点？
4. 这章若表现失血，最先拖累的是转化率、留存、追读，还是付费意愿？

若当前章属于前 `15` 章却无法回答以上任意两项，默认应在审阅报告里单列为**商业链路风险**，而不只写成普通节奏问题。

### 起点章节竞争位分层（辅助口径）

审阅关键章节时，默认允许补一层“这章更像起点哪个竞争位”的判断：

| 竞争位 | 审阅特征 | 判定含义 |
| --- | --- | --- |
| 新书期拉新章 | 首屏极强、题材归类快、问题引擎清楚 | 主要看点击→阅读转化与首轮留存 |
| 追读稳盘章 | 中段回报清楚、关系/冲突持续升级 | 主要看连续追更惯性 |
| 收费转化章 | 回报值高、代价更重、章末强接棒 | 主要看首订/追订映射 |
| 卷尾拉升章 | 闭环旧问题、打开更贵新缺口 | 主要看续卷购买与下卷期待 |

若章节承担某一竞争位，却没有兑现该位最核心的功能，应在报告里直写“功能错配”，而不是只写“这一章略平”。

### 10 万字中期验证（完整版）

当当前章节落在前 `10` 万字区间，或属于前 `15` 章内的关键节点时，章节审阅默认还要借用起点爆款判断标准里的中期验证逻辑，回答“这章对整书中期爆发有没有真实助推”。

审阅时默认至少检查以下四组问题：

1. **拉新能力**
  - 这章是否继续强化题材归类与主卖点，而不是把新读者挡在门外。
  - 若把这章截出来给陌生读者看，是否仍能迅速理解这本书最值钱的地方。

2. **稳留能力**
  - 这章是否提供了明确回报、升级、关系推进或情绪兑现。
  - 是否会让已经读到这里的读者觉得“这一章值回票价”，而不是“只是为了过渡”。

3. **转付费能力**
  - 若本章位于收费前后，是否通过更重代价、更明确缺口、更强角色站队拉高付费意愿。
  - 是否具备“首订章不软、追订章不断”的结构信号。

4. **放大能力**
  - 这章是否至少生成一个可讨论、可截图、可段评、可复述的记忆点。
  - 若完全没有讨论点，即使结构过线，也应下调中期潜力判断。

### S-A-B-C 潜力模型（章节完整版）

在 `Green / Yellow / Red` 与前述章节爆款潜力分档之外，若当前任务明确服务起点口径，默认允许再给一份更偏“中期商业潜力”的 `S-A-B-C` 模型判断：

| 档位 | 章节表现 | 对整书的中期意义 |
| --- | --- | --- |
| S 级潜力 | 章首抓力强、中段回报高、章末强驱动、角色/设定讨论点明确，具备拉新+稳留+转付费三重作用 | 这章是可以抬升整书竞争位的关键章 |
| A 级潜力 | 至少两项核心功能过硬（抓力/回报/驱动/讨论点），剩余短板局部可补 | 这章能稳住追读并支撑后续放大 |
| B 级潜力 | 基本可读，至少完成单一功能，但对拉新或转付费帮助有限 | 这章不会立即拖垮链路，但也难成为强支点 |
| C 级潜力 | 慢热、失血、无回报、无记忆点、功能错配命中两项以上 | 这章会拖累整书在 10 万字前的增长曲线 |

### 报告中的中期验证结论写法（强制）

若启用中期验证，审阅报告里默认至少补一句类似结论：

- **中期判断**：这章更偏 `拉新 / 稳留 / 转付费 / 卷尾放大` 中的哪一种；
- **潜力档位**：`S / A / B / C`；
- **最先拖累项**：若失血，最先拖累的是 `点击转化 / 留存 / 追读 / 首订 / 追订 / 讨论度` 中的哪一项；
- **72 小时补丁重点**：章首、中段、章末里优先救哪一处，才能最快把本章从 `C→B` 或 `B→A`。

## 追读概率评估（新增）

审阅报告中必须显式给出"本章是否促进读者继续追/继续付费"的判断，维度包括：

| 维度 | 强信号 | 弱信号 | 失败信号 |
|------|--------|--------|----------|
| 情感代入 | 主角处境与读者产生共鸣 | 情感表达正确但冷淡 | 只有事件无人物情绪 |
| 悬念驱动 | 章末留下明确未解答问题 | 有疑问但不紧迫 | 平铺直叙收尾 |
| 爽点兑现 | 至少一次主角主动或有效反制 | 只有被压无反制 | 全章被动无翻身点 |
| 记忆点 | 具体、可讨论、可分享 | 正确但平凡 | 无可驻足的细节 |
| 下章连接 | 下章接棒对象明确存在 | 下章方向暗示不足 | 完全不知下章干什么 |

综合判断：
- `强`：预期留存概率 80%+ 
- `中`：预期留存概率 50-80%
- `弱`：预期留存概率 <50%（需马上返工）

## 爽点预告模式审计：预告链兑现与节奏真伪判定（新增——吸收自知乎丁文韬与流浪的蛤蟆）

> **核心洞察**：许多章节"写得没问题但读起来不追"，根因不是文笔不够或情节不够，而是章节在爽点预告链中的定位不清楚——既没有预告"下一章会爽"，也没能让读者觉得"这章值了"。

### 审计维度一：本章在爽点预告链中的定位

审阅时首先判定本章属于哪一类：

| 定位 | 审阅标准 | 通过信号 | 失败信号 |
| --- | --- | --- | --- |
| **预告章** | 本章是否制造了足够强的"下一章会爽"的读者预期 | 章末有具体爽点预期信号（临界状态/倒计时/冲突一触即发） | 章末只是收尾、抒情或"还有下文的陈述" |
| **蓄力章** | 本章虽未兑现大爽点，但给了读者读下去的小回报 | 至少一次信息推进/关系变化/小反击/认知升级 | 纯推进无回报，"主角做了A→去了B→做了C"式事件清单 |
| **兑现章** | 本章的回报是否高于预告阶段积累的读者预期 | 读者读完回报段产生"卧槽"感而非"果然如此" | 回报低于预期，读感为"就这？" |
| **过渡章** | 本章是否做到了"过渡不白过" | 至少满足：新信息冒头/关系微妙位移/新预告链埋下种子之一 | 纯承上启下，读完等于没读 |

**判定**：若本章定位不清晰（无法归类到上述任一类型），判为"爽点预告链断裂"——本章没有在预告链中承担任何职责，读者自然没有追读到下一章的理由。

### 审计维度二：真实节奏 vs 假节奏

审阅时逐段检查：本章的节奏推进方式，是"推动读者感觉有趣的点儿"还是"事件清单"？

**真实节奏特征**：
- 存在蓄力-期待-延迟的区间——读者知道要发生什么但还没看到发生
- 积累读者期待后再释放
- 信息释放选择"最吊胃口的时机"而非"最方便交代的时机"

**假节奏特征**（事件清单）：
- "主角做了A→做了B→做了C"——有推进感但无期待感
- 没有让读者产生"接下来会怎样？""快来了快来了！"的心理活动
- 把所有信息摆在读者面前，没有选择性延迟

**判定**：
- ✅ 真实节奏：本章可以概括为"读者在等X→终于等到了X→开始等Y"的循环
- ❌ 假节奏：本章可以概括为"主角做了A→做了B→做了C"的平推
- ❌ 无节奏：本章可以概括为"信息A→信息B→信息C"的说明

### 审计维度三：爽点预告-兑现周期的健康度

检查本章在全书爽点预告链中的位置是否健康：

1. **从最近一次兑现章算起，已连续预告/蓄力几章了？**
   - 1-2章：正常
   - 3章：注意——如果本章还是预告章，需要确认预告信号是否够强
   - 4章以上：⚠️ 高风险！兑现章已经严重逾期

2. **本章的"爽点预告信号"是否够具体？**
   - 强信号：读者能说出"下一章会发生XX具体事件"
   - 弱信号：读者只能说"下一章大概有事发生"（太抽象）
   - 失败信号：读者读完没有任何关于下一章的预期

3. **如果本章是兑现章——兑现力度是否达标？**
   - 对比最近2-3章同类场景的爽感浓度
   - 如果低于最近均值，判为"兑现衰减"
   - 兑现衰减连续出现2次以上，判为"系统性爽点失血"

### 审计输出格式

在审阅报告中单列"爽点预告模式审计"板块：

```markdown
## 爽点预告模式审计

**本章定位**：[预告章/蓄力章/兑现章/过渡章/定位不清]
**上次兑现章**：第 X 章（已连续 Y 章未兑现）
**节奏类型**：[真实节奏/假节奏/无节奏]
**预告信号强度**：[强/中/弱] — 读者是否对下一章有具体预期
**兑现质量**：[高于预期/符合预期/低于预期]（仅兑现章适用）
**核心判定**：[健康/爽点空转风险/预告链断裂/系统性失血]
```

### 问题分级

| 问题 | 优先级 | 说明 |
| --- | --- | --- |
| 定位不清（无法归入预告/蓄力/兑现/过渡） | Critical | 本章在预告链中没有职责 |
| 假节奏（事件清单替代真实节奏） | Warning | 有推进无期待，需重新设计节奏分布 |
| 爽点空转（连续4章+未兑现/当前预告链超期） | Critical | 读者耐心已接近极限 |
| 兑现衰减（兑现力度低于最近均值） | Warning | 单次不致命，连续2次升级为Critical |
| 预告信号过弱（读者不知道下一章要发生什么） | Warning | 需在章末加码具体信号 |
| 纯推进过渡（过渡章无任何小回报） | Critical | 读者白读一章，严重消耗耐心 |

## 极其快节奏与极其强冲突专项审阅（新增）

章节审阅除常规结构项外，必须单列“快节奏 + 强冲突”专项判定，且给出可执行回炉动作。

### 快节奏专项门禁

- **首屏速度门禁**：前 `120-200` 字内需出现异常/冲突/倒计时/高压动作之一；若开场长时间背景解释，判 `P1`。
- **场景推进门禁**：本章不得出现连续大段“只解释、不改变局面”的段落群；命中则判节奏塌陷。
- **章内节拍门禁**：默认检查“钩子 → 蓄力 → 回报/变线 → 留钩”是否可识别；若只有推进无兑现，判 `P1`。
- **转场效率门禁**：若关键场景间以大量过渡叙述填充，导致压力泄放，判转场效率不足。

### 强冲突专项门禁

- **冲突实质门禁**：冲突必须落在目标对立、资源争夺、关系位移或价值选择上；仅靠吵闹语气不算强冲突。
- **代价显影门禁**：关键冲突后应出现可验证后果（失去、暴露、反噬、反咬、时窗缩短）；若无代价，判伪冲突。
- **权力位移门禁**：章节中应至少出现一次可感知位差变化（主动/被动反转、解释权转移、谈判筹码变化）。缺失判冲突扁平。
- **章末强驱动门禁**：章末应是“未完成动作 + 新风险/新解释/新缺口”之一；若只是总结、感慨或空问号，判 `P1`。

### 快冲突评分卡（章节层）

| 维度 | 权重 | 过线标准 |
| --- | --- | --- |
| 首屏抓力与入场速度 | 20% | 前 200 字有实质压力入场 |
| 中段回报与节拍波形 | 25% | 章中至少一次值回票价兑现 |
| 冲突强度与代价显影 | 25% | 冲突有可验证后果，不是吵架替代 |
| 关系/位差变化 | 15% | 至少一次关系或权力位移 |
| 章末翻页驱动 | 15% | 下章接棒对象与缺口明确 |

若“冲突强度与代价显影”不达标，综合评分默认不得给高档；若“首屏抓力与入场速度 + 章末翻页驱动”同时不达标，直接判不建议放行。

### 报告必须输出的回炉动作（新增）

- 指明本章最先回炉的 `3` 个段位（章首段 / 中段关键场 / 章末落针段）。
- 每个段位必须给出一句“改法动作词”：`删解释`、`补对立目标`、`加代价后果`、`补位差反转`、`换章末落针类型`。
- 若判定为链路失配，必须写清是上游哪一层（控制卡 / 场景职责 / 分卷承诺）导致正文冲突失真。

## 人物执行审计（新增——强制）

> 核心问题：章节审阅通常能发现"节奏平""人物没立住"，但缺少对"人物传记里写的东西到底有没有在正文里被看见"的系统检验。此审计专门解决这个问题。

### 审计前准备

审阅正文前，必须完成以下准备动作：
- 已读取本章出场人物的传记，且确认传记版本是最新的可执行版本
- 已检查传记中是否存在"正文可调用素材清单"（压力反应微镜头、声口即时贴、误判预设场景、关系拉扯动作库）
- 若传记缺少正文可调用素材清单，审计只能做声口判断和心智模型粗略对照，无法做精细化的素材匹配验证；报告中必须标注此降级

### 审计维度

#### 维度1：声口一致性（每章必审）

逐段检查本章中每个人物的对话/独白，对比传记中的表达DNA和声口即时贴：

- **句长**：正文中人物的句子长度是否与传记设定一致？（短句型人物是否出现了长篇大论？长句型人物是否被压缩成了短句机器？）
- **确定性语气**：断言型人物是否出现了"也许""可能""大概"？犹豫型人物是否过于斩钉截铁？
- **禁忌词**：传记中标注的禁忌词是否在本章对话中出现？若出现，记为声口事故。
- **遮名测试**：随机抽取本章中两段不同人物的对话（去掉说话人标签），是否能仅凭句式/用词/语气区分是谁在说话？若不能，判为声口同质化。
- **声口分众**：同一人物在对着不同对象说话时，句式/用词/态度是否有可感知的变化？若对所有对象说话方式完全一样，判为声口单一。

**审计输出**：声口一致性 通过 / 局部问题 / 系统性失败；若为"系统性失败"，报告必须列出至少 3 处具体问题与传记对应的修正锚点。

#### 维度2：心智模型落地（核心人物必审）

检查本章中核心人物的关键判断/选择/行为是否可从其传记的心智模型中推导：

- **判断溯源**：选取本章中人物的 2-3 个关键判断，逐一回溯：这个判断是否符合传记中的心智模型？能否从"心智模型 → 决策启发式 → 具体行为"的链条中得到解释？
- **模型间碰撞**：若本章有两名核心人物在同一场景中做出不同判断，他们的判断差异是否反映了各自心智模型的差异？还是只是"剧情需要他们不同"？
- **误解型模型兑现**：若传记中设定了"误解型"心智模型，本章是否有体现该模型导致人物做出了与其他角色不同的判断？

**审计输出**：心智模型落地 强 / 中 / 弱；若为"弱"，报告必须指出具体缺失项与传记对应的修正锚点。

#### 维度3：压力反应匹配（每章必审）

检查本章中人物面对压力时的反应是否与传记中的压力反应微镜头一致：

- **压力识别**：本章中人物面临了什么压力？（被质疑/被隐瞒/两难选择/被迫求助/当众失误/亲密破防）→ 传记的压力反应微镜头中是否有匹配的类型？
- **反应一致性**：正文中人物的反应（动作+身体+判断）是否在传记微镜头提供的"默认反应基线"范围内？若偏离基线，是否有情节理由（如：心智模型正在被修正、处于极端情境等）？
- **默认反应基线偏离检测**：若正文中人物的压力反应与传记基线明显不同且无情节理由，判为人物行为OOC（Out of Character）。

**审计输出**：压力反应匹配 通过 / 偏离但有理由 / OOC风险；若为"OOC风险"，报告必须指出具体的偏离点与传记基线对比。

#### 维度4：误判/诚实边界触发（核心人物必审）

检查本章是否在传记预设的误判节点上触发了人物的盲区：

- **预设匹配**：传记的误判预设场景中是否有匹配本章情境的预设？若有，正文是否在本章触发了该误判？
- **盲区可见性**：传记中的诚实边界（人物看不到什么/理解不了什么）是否在本章中有体现？人物是否在该盲区上犯了错或做出了不完整的判断？
- **万能人物检测**：若本章中人物面对任何情境都判断正确、应对自如，而传记中明明写了诚实边界——判为"传记与正文脱节"，人物过于万能。

**审计输出**：误判/盲区触发 已触发 / 已体现 / 未触发但合理 / 缺失且应触发；若为"缺失且应触发"，报告必须给出具体的触发建议与修正段落。

#### 维度5：关系拉扯兑现（重要关系必审）

检查本章中的关键关系互动是否体现了传记中关系拉扯动作库的底层动力：

- **底层动力一致性**：本章中关键关系的互动是否在"表面争什么"之下体现了传记设定的"底层动力"（双方心智模型的碰撞点）？
- **拉扯模式兑现**：传记中的标志性互动模式（如"权力博弈型拉扯""信任试探型拉扯"）是否在本章中有可感知的体现？
- **翻面信号**：若本章是关系转折点，是否出现了传记中预设的"翻面条件"？

**审计输出**：关系拉扯兑现 强 / 中 / 弱 / 无关键关系互动；若为"弱"，报告必须指出缺失项与传记对应的修正锚点。

### 审计结果汇总表

审计完成后，报告必须包含以下汇总表：

| 审计维度 | 结果 | 问题数 | 最优先修正项 |
| --- | --- | --- | --- |
| 声口一致性 | 通过/局部问题/系统性失败 | N | [具体段落/台词] |
| 心智模型落地 | 强/中/弱 | N | [具体判断/行为] |
| 压力反应匹配 | 通过/偏离有理由/OOC风险 | N | [具体段落] |
| 误判/盲区触发 | 已触发/已体现/未触发但合理/缺失应触发 | N | [具体段落] |
| 关系拉扯兑现 | 强/中/弱/无关 | N | [具体互动] |

### 传记素材缺失时的审计降级

- 若出场人物传记缺少正文可调用素材清单，审计表中标注"传记缺素材，审计降级为粗略对照"
- 降级后至少完成声口一致性和心智模型落地的粗略判断（基于传记中的表达DNA和心智模型字段）

## 首屏与手机端审阅补充（新增）

- 审阅时默认单列检查前 `300` 字：人物抓手、第一压力、异常 / 冲突、继续阅读问题，至少命中两项才算过线。
- 若正文大量依赖抽象总结、作者说理或空情绪，而缺少动作、感官、后果与关系变化，应在报告里明确判为沉浸风险。
- 若段落长期过厚、句群过匀、手机端阅读容易形成视觉疲劳，应在报告里单列为排版 / 阅读摩擦问题，而不是只算文风差异。
- 单章节拍默认还要检查“钩子 → 蓄力 → 回报 → 留钩”是否成立；若长期只有推进没有兑现，应明确写成结构问题。

## 题材竞对分析接入要求（强制）

- 若当前任务服务某个题材，且该题材目录下的 `竞对分析/` 已存在与当前项目、当前平台或当前赛道相关的竞对分析报告，审阅前必须先读取并纳入对照。
- 若工作区中存在蒸馏产物（通过 `Agents.md` 注册的蒸馏作品蓝本模板、蒸馏作者文风模板、蒸馏写作研究模板，或 `写作研究/`、`调研报告/` 等目录下的蒸馏/研究报告文件），审阅前必须优先将其作为竞对对比的核心依据；蒸馏产物中封装的叙事结构约束、风格基线、题材×平台约束等可直接转化为竞对维度评分参照，使竞对判断更准确、更深入、更可举证。
- 若已配置主输出平台，且当前题材目录下尚无可用竞对主报告，审阅关键章节前应优先调用 `通用-分析竞对作品` 补齐最小结论集；若任务限制导致本轮无法补齐，必须显眼记录盲区，并下调本轮审阅上限与置信度。竞对分析的目标平台由主输出平台配置决定。
- 审阅报告不得只给内部自洽结论；必须显式判断当前章节相对竞对在哪些维度已领先、持平或落后，以及最先该补哪条超越路径。
- 若当前章节在竞对已验证的关键强点上明显更弱，必须直判为竞争风险；章节审阅的默认目标是推动当前作品在关键维度上**全方位超越竞争对手**。
- 默认按“严酷找差距”口径执行：重点写清当前章节为什么还赢不过已过审竞对章节，不得为了照顾作者情绪把留存断裂、回报不足或钩子发虚写成“文风问题”。
- 竞对维度在章节审阅综合评分中默认按 `25%` 计权；若未完成量化差距卡，或关键维度仍显著落后且没有 `72` 小时补丁，综合评分默认不得给高档。

## 平台竞对吸收口径

当已配置主输出平台时，默认把竞对对照拆成以下四层，并翻译成评分判断与补丁建议。具体平台术语与指标由主输出平台对应的 `通用-输出*版` Skill 提供：

- **市场数据层**：用平台关键指标代理信号反推这章是否真的支撑题材归类、追读意愿与持续付费，而不是只在作者视角里"写顺了"。
- **内容创作层**：重点对照主样本在章首抓力、中段回报、冲突强度、代价显影、信息差、关系位移、章末留钩与卖点兑现上的成熟度，把差距翻成段位级补丁。
- **运营策略层**：重点对照主样本如何制造讨论点、催更点、截图点、首屏截停点与章末翻页点，把差距翻成章首、中段关键场、章末落针的补丁。
- **受众反馈层**：重点对照平台读者高频被夸的爽点、被骂的慢热/断供/假钩子病灶、读者对降智/出戏/讲义腔的敏感点，把差距翻成避坑与加码建议。

## 主输出平台自动发现规则

若当前服务的项目根目录存在 `Agents.md` 且其中声明了 `主输出平台`，审阅章节正文前必须按命名约定加载对应的 `通用-输出{平台名}版` Skill，将其平台门禁标准（字数门槛、开篇密度、回报间隔、钩子强度）与竞对对照口径作为本章审阅的约束基线。若未配置主平台或配置缺失，回退通用默认模式，不阻断。

## 报告落盘位置与命名规则（强制）

- 章节审阅报告统一落在项目根下的 `审阅意见/` 体系内，不得直接放回章节正文所在目录。
- 若作品存在分部，报告路径必须为 `审阅意见/第X部/第Y卷/章节审阅报告_第X部_第Y卷_第Z章_2026-04-15.md` 这一类“部 → 卷 → 报告文件”的结构。
- 若作品没有分部，报告路径必须为 `审阅意见/第X卷/章节审阅报告_第X卷_第Y章_2026-04-15.md` 这一类“卷 → 报告文件”的结构。
- 写入报告前，必须先从目标章节正文路径、所属分卷大纲或项目目录结构中确认 `第X部 / 第Y卷 / 第Z章` 标识，并先定位到对应子目录后再落盘。
- 不得因为分部或分卷信息暂时缺失，就把报告退回 `审阅意见/` 根目录；若确实无法判断，必须先把“分部 / 分卷定位信息缺失”列为阻断点，补齐后再写文件。
- 章节审阅报告文件名必须带日期，日期格式固定为 `YYYY-MM-DD`。
- 章节正文主文件，以及其中附带的 `## 作者有话说`、`## 章节后记` 等同文件工作流区块默认不带日期；日期只用于对应审阅报告。

## 常见触发词 / 用户说法速查

- 帮我审这章
- 看看这章值不值得追
- 给我这一章的审阅报告
- 这章章首 / 中段 / 章末哪里有问题
- 帮我分级指出补丁位
- 这章到底是文笔问题还是结构问题

## 何时使用

- 审阅章节正文的实际执行质量与追读价值。
- 需要同时判断章首抓力、中段回报、章末钩子、现实落地与链路失配。
- 需要产出可回写的章节审阅报告。

## 不适用情形

- 只做整章重写或精修，不先出审阅结论。
- 只做开头或结尾的局部强化。

## 默认执行顺序

0. 若已配置主输出平台且当前题材目录下缺少可用竞对主报告，先调用 `通用-分析竞对作品` 补齐最小结论集。竞对分析的目标平台由主输出平台配置决定。
1. 先确认目标章节、上游承接对象，以及本轮必须认真仔细阅读的人物传记 / 故事设定 / 背景设定文档。
2. 若已配置主输出平台，先吸收竞对主样本四层结论，并写清本轮审阅重点比对的关键项。
3. 先按检查清单查章首 / 中段 / 章末三处功能，并判断主卖点是否被快速感知或持续兑现。
4. 再查现实落地、证据 / 规则 / 视角 / 人物一致性，以及对话里的声音差 / 塑人 / 联结是否成立。
5. 再用“章节链路失配审阅表”判断问题主要落在正文表层，还是故事面 / 控制卡 / 场景职责 / 首尾补丁的失配。
6. 用问题分级与补丁动作输出最小修复建议。
7. 生成可回写、可落库的审阅报告。

## 默认输出口径

- 默认输出一份带读者结论、工程结论、问题分级与补丁位的章节审阅报告。
- 默认不直接改正文，除非用户明确要求边审边回写。
- 若主要问题属于 AI 味，默认还要给出去味病灶一句话总结，并建议应进入的手术强度档位。
- 若按起点口径执行，报告还必须显式覆盖：`Top10 候选池`、`3–5` 本主样本四层速览、竞对差距量化卡，以及当前章节最先该补的超越路径。

## 固定输出骨架（强制）

章节审阅报告默认按以下固定顺序输出，除非用户明确要求改版式，否则不得跳步或乱序：

1. **快筛结论**（10 秒）：先给章首/中段/章末是否过线的快速判断与阻断项。
2. **深评结论**（3 分钟）：再给叙事执行、回报密度、冲突强度、卖点兑现、竞对差距判断。
3. **分档结论**：给 `Green/Yellow/Red`；若已配置主输出平台，可额外补充该平台的特定潜力档位并写明依据。
4. **最小补丁链**：给“先改哪 `3` 段（章首/中段/章末）、每段改什么动作词”。
5. **72 小时动作**：给章节级回炉顺序、预计抬升项与复审触发条件。

若未指定目标平台，仍按同一骨架输出；其中竞对或平台字段可标注"本轮不适用"，但不得删掉骨架步骤。

## 最低交付

- 能指出章首、中段、章末的关键表现与短板。
- 能说明问题属于正文表层还是链路失配。
- 能给出具体补丁位置与最小回写建议。

## 复审独立性规则（强制）

- 每一轮章节审阅都必须把当前正文版本当作新的交付物重新独立、从严、全面审一遍，不得因为上一轮问题已修复，就默认本轮应给更高分。
- 核查上一轮问题是否修复很重要，但不足以替代本轮对章首抓力、中段兑现、章末钩子、现实落地、证据规则、人物一致性与卖点保真的完整复审。
- 若本轮发现新的出戏点、新的节奏塌陷、新的证据链问题、新的卖点弱化或新的留存风险，必须如实加入本轮报告，不得因“旧坑补上了”而淡化新坑。
- 本轮评分必须只依据当前版本在本轮完整审阅下的真实表现给出，不得按上一轮分数、修复数量、返工次数或作者投入自动加分。

## 硬规则

- 不能只给情绪化好恶评价
- 若已配置主输出平台，审阅对照应按平台 Skill 要求的竞对维度执行，不得跳过就直接给高分或高档判断。
- 必须指出具体段位、具体问题、具体补丁位置
- 必须同时给“读者结论”和“工程结论”
- 未认真仔细阅读本章相关人物传记与故事设定 / 背景设定文档前，不得出具“人物成立 / 设定成立 / 规则成立 / 证据成立”这类结论。
- 必须明确说明本章的追读反射弧强弱、微爽点 / 中爽点配置与下章接棒对象是否成立
- 必须判断本章有没有把全书卖点写弱、写泛、写没，并给出具体补丁位
- 必须判断对话是否只在搬信息，还是已经承担人物声音区分、人物塑造与读者跟随理由
- 默认审阅对象是章节正文本体；`## 作者有话说`、`## 章节后记`、润色说明、回写标记等即使与正文放在同一文件，也视为工作流设计，不因同文件共存而单列为“读者出戏”或发布事故。
- 不得把 `## 作者有话说` 并入正文 CJK 计数；正文与作者有话说的字数门禁必须分开记录、分开判断。
- 不得把“去空白统计”“NoWhitespaceLen”“编辑器字符数”等替代口径写成正文字数门禁结论；若需要保留参考信息，必须明确标注“仅参考，不参与门禁判定”。
- 只有当作者侧内容实际闯入正文段落、章标题，或用户明确要求按“给读者直接看到的终稿 / 裸发稿 / 合刊稿”口径严判时，才把它视为发布风险。
- 默认报告中的“是否建议直接放行 / 是否可发布 / 是否建议发布”只针对读者可见层（正文、章引语、`## 作者有话说`）；若用户未明确要求审原始工作文件是否可直接裸发，不得写“整文件不建议直接发布”“文件不可直接发布”之类结论。
- 若用户还要求连同 `## 作者有话说` 或 `## 章节后记` 一起审，再对对应区块单独给出作者侧建议；其中 `## 章节后记` 必须重点检查字段完整性、与正文对应关系，以及是否拿后记偷补正文缺失内容；但不得把“存在这些区块”本身当成正文质量缺陷。

## 与其他 Skill / Prompt 的边界

- 本 Skill 负责章节正文审阅与回写建议，不直接代替正文重写。
- 若用户确认问题后要进入改稿，应转入 `通用-正文润色`、`通用-去AI味重写` 或首尾专项强化。
- 当建议转入 `通用-去AI味重写` 时，应尽量说明是皮相拆洗、骨肉重塑还是灵魂重构，不要只给笼统判断。
