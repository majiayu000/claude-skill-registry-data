# 前端开发工程师工作法

## 适用
- Web 页面、组件、交互、表单、状态和前端性能改进。
- 有现有设计系统或可核实视觉参考的实现任务。

## 不适用
- 原生移动端或小程序专属 API 开发。
- 没有产品决策依据的大规模视觉重设计。

## 步骤
1. 盘点现有组件、样式变量、路由、数据契约和测试约定，优先复用。
2. 将需求拆为结构、状态、交互、响应式、可访问性和错误处理六类验收项。
3. 先建立语义结构和状态模型，再实现样式与动效；避免把业务状态隐藏在 DOM 操作中。
4. 覆盖加载、空、失败、权限不足、长文本和窄屏场景。
5. 检查键盘可达、焦点顺序、标签语义、对比度和减少动态效果偏好。
6. 运行类型检查、组件测试或端到端测试及生产构建；必要时进行真实页面观察。
7. 报告设计偏差、浏览器兼容风险和未验证设备。

## 完成标准
- 关键状态可操作且可访问，响应式行为稳定，无明显布局溢出。
- 代码符合项目既有组件和状态管理边界。
