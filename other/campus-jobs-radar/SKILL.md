# 校招岗位雷达

## 铁律（血的教训）

> 🔴 **永远不要只对用户发来的那几张截图做分诊。**
> 实例：作业帮用户发了 4 个岗的截图，我只分析这 4 个就下结论，结果漏掉了全公司匹配度最高的「视频编导」（93%），它根本不在截图里。
> **每次都必须先拉全量岗位列表，再排序，再告诉用户"你截图里的第 X 个其实不如第 Y 个"。**

## 执行流程

### 第 1 步：识别招聘平台（看截图顶部导航/地址栏）

| 平台特征 | 拉全量列表的方法 |
|---|---|
| **mokahr**（`app.mokahr.com/campus-recruitment/<公司>/<id>`） | WebFetch `https://app.mokahr.com/campus-recruitment/<公司>/<id>?locale=zh-CN#/jobs` —— **已验证可直接拿到岗位列表+部门+城市**。注意截图里的 `#/job/<uuid>` 是单个岗位，把路径换成 `#/jobs` 就是列表 |
| **飞书招聘**（`<hash>.jobs.feishu.cn/<id>/position`） | WebFetch `https://<hash>.jobs.feishu.cn/<id>/position`；列表页常是分页的，配合用户截图逐页拼。岗位总数看页面标题（如「开启新的工作(27)」） |
| **公司官网校招页** | WebFetch 官网校招入口 |
| 以上都拿不到 | WebSearch：`公司名 + 2027届 + 秋招 + 岗位列表` / `公司名 + 校招 + 职位类型`。**高校就业网、应届生求职网、牛客、实习僧** 常转载完整 JD 全文（这些站点反而是补齐 JD 的最佳来源） |

### 第 2 步：补齐关键信息（每次都要查）

1. **投递上限** —— 搜 `公司名 + 2027届 + 秋招 + "每人最多" + 岗位`。很多公司限 2-3 个，这直接决定能投几个
2. **内推码** —— 搜 `公司名 + 2027届 + 秋招 + 内推码`。搜到的高校推文里常有通用内推码（如作业帮 `DSCStUpV`、九方 `TDWEPUY`/`V9A4RQR`）
3. **笔试形态** —— 搜 `公司名 + 校招 + 笔试 + 考什么`。有无行测/专业卷/英文卷，直接影响岗位排序
4. **公司风险** —— 搜 `公司名 + 处罚/被罚/整改/业绩下滑/投诉`。**必做**，尤其是金融、教育、医美、币圈类公司
5. **工作地点** —— 标注出来，让用户确认城市接受度

### 第 3 步：按候选人硬参数分诊

> **通用版**：逐条比对 JD 的"任职要求"与候选人真实经历，分三档：硬卡（不满足即不投）/ 加分命中 / 需补知识。
> **如果 `references/USER-PROFILE.md` 存在**（含候选人卡死项、加分项、城市偏好），加载它并按其中的清单逐项打分。
> 该文件为私密档案，**开源时删除**；删除后本 skill 退化为通用版，流程不变。

### 第 4 步：输出格式

```
## 投递规则（已核实）
内推码 / 链接 / 城市 / 流程（有无笔试）/ 投递上限 / 截止时间

## 风险核查（若有）
监管处罚 / 业绩 / 投诉 / 业务模式本质

## 全量岗位分诊表
| 岗位 | 部门 | 匹配度 | 判断 |
（按匹配度降序，🟢投 / 🟡可选 / 🔴不投）

## 推荐投递顺序
1. xxx（简历版本 X）
2. xxx（简历版本 Y）

## 明确不投 + 为什么（一句话）
```

最后必须回答：**"你截图里的岗 vs 我找到的岗，哪个更值得投"** —— 如果截图里的不是最优，直接指出来。
