# 独立游戏剧本文档生成

把一个游戏灵感（或一个现有游戏项目）展开为一份结构完整、可直接指导内容制作的剧本文档。
文档结构按行业通用写法组织，模板见 `references/story-template.md`。

## 工作流程

### 第 0 步：确定输入类型

- **现有项目**：先收集项目锚点——已有/计划中的系统、NPC、地图、数值体系（等级/等阶、
  道具、敌人）。剧本必须锚定这些锚点：人物引用现有 NPC 配置，任务奖励引用现有道具 id，
  成长线引用现有等阶表。**禁止凭空发明项目里不存在且难以实现的系统**。
- **从零生成**：按 `references/story-template.md` 的「灵感追问」一节，最多问 1~2 轮
  （类型 + 核心体验），其余细节自行假设并在文档中标注 `[假设]`。

### 第 1 步：按模板分节撰写

按 `references/story-template.md` 的章节顺序生成：

1. 一句话梗概（Logline）
2. 世界观设定
3. 人物设计（主角/配角/反派/NPC 群像 + 关系网）
4. 剧情主线（三幕结构或章节制 + 关键节点 beat 表）
5. 支线剧情
6. 任务设计（任务表：ID/触发/目标/流程/奖励）
7. 关键对话脚本（如项目有对话系统，用其语法写）
8. 叙事与玩法结合点
9. 文案规范

规模约束：原型级项目主线 3 幕、人物 ≤ 8、任务 ≤ 10；小型项目可放宽到 5 章、
人物 ≤ 15、任务 ≤ 25。

### 第 2 步：一致性校验

成稿前自查三层一致性：

- **人物 ↔ 任务**：每个任务有明确的发布人与动机，且该人物在人物设计中有条目。
- **任务 ↔ 系统**：任务奖励的道具/数值在项目定义表（或新提案清单）中存在；
  触发方式与项目对话/触发器能力匹配。
- **剧情 ↔ 成长线**：主线各幕的节点对应玩家成长阶段（等阶/等级），节奏上
  「剧情推进 = 能力解锁」交替出现。

发现不一致时标注 `[决策]` 并给出取舍结论，不要静默修改。

### 第 3 步：文档落盘

- 单文档项目：`story/README.md` 一份全含。
- 多文档项目：`story/` 目录拆分为「世界观与人物 / 主线剧情 / 任务与支线」
  三份 + `README.md` 作总纲与阅读指引。
