## Шаг 1 — реверс-поиск по ДОСЛОВНОМУ симптому (2 минуты)
```bash
gh api -X GET search/issues -f q='<ключевые слова> in:title updated:>ГГГГ-ММ-ДД' -f per_page=10 \
  --jq '.items[] | "\(.state[:1]) \(.updated_at[:10]) c\(.comments) \(.html_url) | \(.title[:90])"'
```
⛔ **`gh search issues "<много слов>"` ОДНИМ аргументом = ЛОЖНЫЙ НОЛЬ** (замер 14.09.2026, [машина флота]): gh оборачивает всю строку в кавычки как фразу (в URL `%5C%22`), 13 запросов подряд дали пусто, те же слова через `gh api search/issues` — живые треды. Сортировка `updated` топит релевантное в бот-шуме — без `--sort` (по релевантности) + `in:title`. Между запросами `sleep 8`, иначе secondary rate limit 403.
Пробуй 2-3 формулировки (код ошибки `0x…`, статус `Modified, NeedsRemediation`, фраза из диалога). Пусто везде → вердикт ⚪ с названным запросом, конец.

⛔ **`state:open` В КАЖДЫЙ ЗАПРОС** (замер 19.09.2026, [машина флота]): без него выдача уходит в архив — первый круг из 9 запросов дал 13 попаданий, из которых ЖИВОЕ было ровно одно, остальные `closed` за 2025-2026. ⛔ **ГОЛОЕ ЧИСЛО В ЗАПРОСЕ = ЛОЖНЫЙ НОЛЬ** (замер 08.09.2026, 1-й датированный случай `gh-search-golye-chisla-chitayutsya-kak-nomer-issue`): `gh search issues "gemini cli valid license 3501"` возвращает issue **с номером 3501** из случайных репо (BusinessCentral, WordPress/Learn…), а не текстовый матч — выдача выглядит как честный поиск и читается как «фронт пуст». Только ПОСЛЕ этого вердикт core/off настоящий. Замер 23.09: 8 несканированных репо, буквальное «нет в списке = не трогать» выбросило бы 5 целей домена=core (agent-fleet, TangleClaw, recall, pi-cursor-sdk, roost) вместе с 3 настоящими off.
