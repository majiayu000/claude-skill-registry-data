# PRD撰写Skill

## 适用场景
需求分析与验收标准完成后,产出正式产品需求文档,作为研发、测试、验收的统一输入。

## 执行步骤
1. 明确背景与目标:解决的问题、业务价值、衡量指标。
2. 定义用户画像与使用场景(承接用户故事清单)。
3. 列功能清单并标注优先级(P0/P1/P2)与迭代归属。
4. 逐功能写详细需求:规则、状态流转、字段说明、异常场景,关联 AC 编号。
5. 补充非功能需求:性能、安全、合规、埋点、兼容性。

## 规范要点
- PRD 是研发契约:每条功能需求必须能回溯到 AC,禁止「灵活处理」「酌情展示」等不可执行表述。
- 状态流转用文字版状态机描述(状态列表 + 触发事件 + 前置条件)。
- 涉及数据的字段必须说明:类型、必填性、取值范围、脱敏要求。
- 变更历史表:版本、日期、变更点、责任人,PRD 变更必须留痕。

## 输出模板
```
# [产品/模块名] PRD vX.Y
1. 背景与目标(含衡量指标)
2. 用户画像与场景
3. 功能清单与优先级
4. 详细需求(逐功能:规则/状态流转/字段/异常,关联 AC)
5. 非功能需求
6. 数据埋点
7. 里程碑与迭代规划
8. 变更历史
```

## 自检清单
- [ ] 每条功能需求可回溯到 AC
- [ ] 无不可执行的模糊表述
- [ ] 状态机覆盖全部状态与事件
- [ ] 字段含类型/必填/范围/脱敏说明
- [ ] 变更历史留痕
