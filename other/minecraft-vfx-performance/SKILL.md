# Minecraft 体积特效性能优化

先从项目确认版本、渲染阶段与现有兼容管线。识别 GPU 像素/采样成本、CPU 热路径和初始化开销；不要把 FPS 或 CPU 提交时间当成某个 GPU pass 的耗时。

第一人称靠近才骤降时，检查屏幕覆盖率 × 每条射线预算，以及包围盒碰近裁剪面是否误退化成全屏。保持同一场景、时刻、火种/材料、深度和参数进行配对 GPU 计时。

像素覆盖主导的体积场，优先评估较小颜色缓冲积分后按原屏幕深度重建。可以保留三维场、射线采样预算和运动规律，把最重的逐像素工作移出原生分辨率。分辨率比例根据材料细节、边缘稳定性与性能实测选择，不能把某个项目的 1/3 比例当作通用常量。读 [体积积分与深度重建](references/volume-depth-composite.md) 实施或审查此管线。

降低采样次数、降噪声阶数和改动透明度是不同的视觉取舍；需要分别验证。GPU 加速成功后仍检查远景、近景、低视角、侧移、走路晃动、暗色材料与原生/目标光影。火焰场在相同射线的数值一致，不代表低分辨率重建后的屏幕图像一致。

透明气体不会自然遮住地面。用户需要完整炉底等实体背景时，给实际空间中的托底/炭床处理遮挡；不要仅用提高亮度、屏幕色块或全局透明度来掩盖模型缺口。显示密度与配色的修正和性能修改分开记录。

保留现有资源重载与退出清理，尺寸变化重建 FBO；恢复所触及的 GL 状态。只有测量启用时创建/查询 GPU timer。报告实测 GPU/分辨率、pass 范围、暖机与缓存开销、视觉取舍；不把单 pass 改善换算成未测量的整游戏 FPS，也不隐含安装、启动或发布授权。

多层宿主特效、周期噪声缓存、接管回退与当前版工作台交付时，读 [多层体积接入](references/multi-layer-volume.md)。
