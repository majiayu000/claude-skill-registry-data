# 验收标准定义Skill

## 适用场景
用户故事明确后,定义「什么算做完」——AC 是后续开发、测试、验收的共同依据。

## 执行步骤
1. 梳理故事的主流程、边界条件、异常场景。
2. 用「Given(前置)/When(操作)/Then(预期)」格式逐条写 AC。
3. 覆盖四类:正常路径 / 边界值 / 异常与错误提示 / 权限与状态。
4. 校验每条 AC:是否可测试、无歧义、与故事一一对应。

## 规范要点
- 每条 AC 只有一个断言,禁止「且/或」复合断言。
- 不写实现细节(AC 不出现表名、接口名、技术方案)。
- 边界值必须具体(数量、金额、长度、时间),禁止「合理范围」等模糊词。
- 每故事 3-7 条 AC 为宜;超过 7 条说明故事过大,回退拆解。
- 错误场景必须有明确预期(提示文案/状态/无副作用)。

## 输出模板
```
US-001: [故事一句话]
AC-1: Given [前置], When [操作], Then [预期]
AC-2: ...
```

## 自检清单
- [ ] 每条 AC 单断言、可测试
- [ ] 四类场景(正常/边界/异常/权限)已覆盖
- [ ] 无技术实现语言
- [ ] 与故事编号一一对应
