# 纸蓝芽仔图解

## 核心定位

用一套“暖纸底 + Jacky 蓝 + 手写字 + 手绘关系 + 芽仔”的视觉语言，处理三档信息密度：

1. 场景隐喻：把一个观点变成一眼能懂的图像现场。
2. 知识图解：把一个核心知识及其组成、机制或对比解释清楚。
3. 信息可视化：把顺序、因果、依赖、分支、循环、时间或数据关系组织成明确阅读路径。

三种模式是信息密度，不是三套画风。画幅比例是独立选择，不与模式绑定。

## 默认交互

用户只需提供要表达的内容；模式、节点、页数、阅读路径、逐字文本、芽仔动作和蓝色焦点都由本 Skill 提取与规划，不把这些内部工作转交给用户。

- 用户已指定模式、画幅、页数或用途时，服从明确要求；没有指定的部分自动决定。
- 用户说“配图、生成、做图、输出、看效果”，或调用本 Skill 后直接给出内容时，先用一句话说明“推荐模式｜画幅｜预计张数”，随后直接生成，不等待确认。
- 只有当两种模式都合理，且选择会显著改变信息取舍或成品数量时，才提出一个简短选择题；同时给出推荐项与一句理由。每次任务最多询问一次。
- 用户说“先分析、只要方案、不要生成”时，只输出推荐与规划，不调用生成工具。
- 不向用户索要“3–5 个节点”“逐字文本清单”“保留哪些信息”等内部参数；先从用户内容中自行提取。只有原文缺少关键事实、存在相互冲突的数据，或无法安全确定真实 UI 时，才询问缺失信息。
- 对长文章可以按不同段落分别路由，不要求整篇内容只能使用一种模式。

## 第一步：内容建模

在内部回答：

- 读者看完后只需要感受到一个观点，还是需要理解一个知识结构？
- 内容重点是“它像什么”“它是什么”，还是“它如何运行”？
- 哪些词、数字、日期、单位和关系必须逐字保留？
- 删除哪个节点会让理解断裂？
- 芽仔在哪个位置采取行动，才能帮助理解而不是充当装饰？

先写一句视觉任务：

    这张图要让读者在 3 秒内看见______，随后理解______。

写不清时先从原文继续提炼；只有缺少会改变画面含义的关键信息时才询问用户。

## 第二步：按信息密度路由

### A. 场景隐喻｜低密度

- 只表达一个观点、情绪、痛点、冲突或认知转折。
- 即使遮住文字，主要意思仍能靠物件和动作成立。
- 文字只用于点题，不负责解释结构。

限制：一个核心场景、一个主要动作、一个主物件或紧凑物件组、0–3 个短标签。

### B. 知识图解｜中密度

- 回答“它是什么、由什么组成、核心机制是什么、两种状态有什么差别”。
- 需要相对充分地呈现 3–5 个必要概念。
- 关系存在，但不要求读者严格沿步骤执行。

限制：一个中心命题、3–5 个语义节点、4–8 个短标签、最多一个主关系骨架。

### C. 信息可视化｜高密度

- 回答“它如何运行、先后怎样、彼此如何影响”。
- 核心是顺序、因果、依赖、分支、循环、时间线、对比维度或数据关系。
- 标题、步骤、日期、数量、单位或标签必须精确。

限制：先提取信息模块并自动规划页数；每页通常承载 4–6 个可读模块、一个沟通任务和一个明确阅读起点与终点。内容过载时拆页，不缩小文字硬塞。

### 冲突时的优先级

1. 有精确步骤、日期、数值、单位、分支或依赖：信息可视化。
2. 没有严格顺序，但要解释 3–5 个组成或机制：知识图解。
3. 只要建立一个直观认知或情绪共鸣：场景隐喻。

不要把“教程”固定成某个模式：教程中的概念解释可用知识图解，操作顺序和逻辑路径进入信息可视化。

## 第三步：选择画幅

三个模式都支持：

- 16:9 横版：文章正文、视频插图、宽流程。
- 4:3 横版：通用知识卡片、较紧凑图解。
- 3:4 竖版：移动端阅读、小红书、多段纵向路径。

用户指定时严格服从。未指定时按使用场景选择；仍不明确时默认 16:9。比例改变只允许重排构图，不得删减必要信息或改变模式。

## 第四步：规划

生成前在内部形成：

- 模式和选择依据
- 画幅和使用场景
- 一句视觉任务
- 信息块或语义节点，按阅读顺序排列
- 芽仔动作与位置
- 一个主蓝色焦点及其承载的核心信息
- 2–4 个次级蓝色强调及蓝色面积上限
- 必须出现的逐字文本
- 明确不画的内容

这些规划默认只在内部使用。用户只要求方案时再输出规划，不生成；用户要求配图或直接提供内容时，按“默认交互”给出一句推荐后直接逐张调用内置 image generation tool。

## 第五步：生成

- 每张图只承担一个沟通任务。
- 始终把 assets/ip/yazai-paper-blue-anchor-v1.png 作为第一身份与媒介参考。
- 把所选模式文件指定的纸蓝母版作为第二参考，只用于画风、构图倾向与信息密度。
- assets/ip/yazai-canonical-front-v1.png 只用于身份结构核验和身份漂移修复，不作为常规生成风格参考，避免把 3D 塑料质感带回纸面。
- 其他芽仔图片只能参考动作，不得覆盖第一身份参考；旧信息图案例只能参考结构，不得覆盖纸蓝母版。
- 提示词按“信息结构 → 画面主体 → 芽仔动作 → 精确文字 → 风格与避免项”排列。
- 逐张生成和检查，不生成九宫格。
- 必须出现的文字逐字列出，要求每条只出现一次，不添加其他文字。
- 每张图必须有且只有一个第一眼可见的主蓝色语义焦点；蓝色必须承载关键词、核心节点、结论或关键动作，不能只出现在箭头和装饰线。
- 芽仔面罩必须保留单侧反光来表现曲面：所有可见高光集中在同一受光侧，使用一块连续、较宽的柔和弧形反光，可在同侧自然衰减；禁止另一侧光点、孤立圆点、左右对称亮线或八字眉。角色很小时简化反光形状，不得全部删除。
- 生成信息可视化时，任何错误的日期、数值、单位、步骤方向或标签都必须修复后才能交付。

### 生成与清理分层

- 生成工具负责构图、信息结构、角色动作和整体材质；不要把它当作修复单个像素或小污点的橡皮擦。
- 首轮生成后先一次性列出所有结构、文字、身份、反光和背景问题，再决定修复范围。避免“去一点、补一点”的连续整图重绘。
- 结构、信息或整体风格错误，才允许整图重生；文字、局部身份或单个物件错误，只编辑对应区域并锁定其余内容。
- 孤立白点、小斑点、边缘脏像素等面积明显小于画面的微小瑕疵，必须使用真正的局部遮罩、修复画笔或确定性像素清理；不得为此再次整图生成。若当前工具不能精确局部处理，保留最后一张结构正确的原图并说明需要像素级清理，不连续试错。
- 同一张图最多进行一次生成式整体返修。返修后若剩余问题已经是局部瑕疵，立即停止生成式返修，转入局部清理。
- 任何生成式返修都必须从最后一张结构与文字正确的原图出发，不以上一次返修图继续叠加，防止纸纹、阴影和字形逐轮漂移。

## 第六步：交付

生成前只用一句话说明推荐模式、比例、预计张数和必要时的一句视觉任务，不展开内部推理。生成后展示图片，并报告：

- 图片用途和顺序
- 最终文件路径
- 仍需人工复核的生成文字或数据
- 使用过的生成式返修次数，以及是否执行过局部像素清理

在 workspace 内保存到：

    assets/<topic-slug>-yazai-visuals/

按顺序命名，不覆盖旧资产，除非用户明确要求替换。

## 边界

- 视觉封面不在本 Skill 的范围内；封面任务应使用专门的封面工作流。
- 真实按钮位置、菜单路径和产品界面必须使用真实截图，不让生成模型伪造 UI。
- 不虚构事实、日期、引用、来源、品牌、Logo、指标或成功状态。
