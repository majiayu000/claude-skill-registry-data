# elime — あなたが知っていることを土台に解説する

ELI5 は「前提知識ゼロ」の読者を想定する。実際の user はゼロではなく、深く知っている分野を持っている。
その分野の言葉で説明すれば、たとえ話は飾りでなく、構造をそのまま写す道具になる。
この skill は、user が知っていることの記録を持ち、解説のたびにそれを土台にし、反応を見て記録を育てる。

記録: プロジェクト root の `.local/elime-profile.md`（gitignore するローカルの置き場。雛形は同じフォルダの `profile-template.md`）。

## 0. 記録を開く（全モード共通）

`.local/elime-profile.md` を読む。無ければ 2 の `update` を先に走らせて作り、作ったことを 1 行で伝えてから本題へ進む（尋ねない — 中身はローカルの記録で、外へは出ない）。

## 1. 解説（引数が事柄のとき）

0. **区分の使い方を決める**: 記録の分野は「学術・仕事」と「遊び」に分かれている。学術の話に遊びの例えを当てると、構造が合っていても「真面目に扱われていない」と受け取る人がいる。
   - 引数に「遊びで」「学術で」「区分なしで」（同じ意味の言い方を含む）があれば、その回はそれに従う。
   - 無ければ記録の「区分を分ける」の既定に従う（記録に無ければ「分ける」）。
   - **分ける**: 写し先を事柄と同じ区分から選ぶ（学術・仕事の話なら学術・仕事の分野から）。同じ区分に構造の合うものが無いときだけ区分をまたぎ、またぐなら将棋・トランプのような古典的な遊びを先に当てる。
   - **遊びで／学術で**: 写し先をその区分から選ぶ。
   - **区分なし**: 区分を見ずに、構造が一番合うものを選ぶ。
1. **核を分ける**: 事柄の仕組みを、対象の言葉を外して 2〜4 個の要素に言い直す（例: 「キャッシュ」→ 遅い置き場の一部を速い置き場に写す／写しが古くなる問題／どれを残すかの選び方）。
2. **写し先を選ぶ**: 0 で決めた範囲の「使い込んでいる」「触ったことがある」から、各要素と**同じ構造**を持つものを探す。見た目や名前の近さでなく、仕組みが対応するものを選ぶ。1 つの写し先で全要素が対応しなくてよい — 要素ごとに別の写し先を使ってよい。「通じなかった比喩」に載っているものは使わない。
3. **書く**:
   - 最初の 1〜2 文で、写し先の言葉だけで答える（「◯◯で言うと △△ のこと」）。
   - 次に要素ごとに「事柄の側 ↔ 写し先の側」を対応させる。
   - **写し先と違うところ**を必ず 1 つ以上書く（ここを書かないと、たとえ話が誤解を植える）。
   - 写し先の側の用語（ゲームの画面や道具の名前など）は、user が記録・発話で実際に使っている呼び名で書く。user の呼び名を確かめられない語は、名前を出さずに働きで言う（「倉庫」と断定せず「預けておく場所」）。
   - 用語は記録で知っているものだけを説明なしで使う。「まだ知らない」に載る語・記録に無い専門語は、使うなら初出で一言説明する。
   - 長さは記録の「説明の好み」に従う。無ければ短く。
   - 末尾に 1 行、使った写し先を書く（例: 「土台: ◯◯（使い込んでいる）」）。user が比喩を直せるように。
4. **写し先が無いとき**: 構造の合うものが記録に無ければ、無理に例えず、記録で一番近い分野の言葉で平易に説明し、「記録に合う土台が無かった」と 1 行書く。

## 2. 記録を育てる

### 解説のあとの反応から（毎回）

user の次の発話を見て、当てはまるときだけ記録を書き換える。解説しただけでは「知っている」に入れない。

- 比喩が通じた・その語を正しく使って次の質問をした → 事柄を「触ったことがある」へ（根拠: 日付と一言）。
- 「その例えわからない」「◯◯は知らない」→ その写し先を「通じなかった比喩」へ、知らないと言われた語を「まだ知らない」へ。「わからない」だけで何が通じなかったか分からないときは記録しない（比喩でなく説明の詰め込みが原因のこともある）。同じ写し先で 2 回「わからない」が続いたら「通じなかった比喩」へ入れる。
- 「わからない」と返ってきたら、同じ区分の中で一段わかりやすく説明し直す。その回が区分を分けて（または「学術で」で）答えていて、遊びの分野に構造の合うものがあるなら、末尾に「遊び（例: ◯◯）で例えることもできます」と 1 行添える（◯◯ は合う分野の名前。勝手に遊びで説明し直さない — 選ぶのは user）。「遊びで」で答えていたなら、同じように学術・仕事側の候補を添える。
- 「もっと短く」「図で」など説明の仕方への注文 → 「説明の好み」へ。
- 変えたら「観測ログ」の先頭に 1 行足し、user に「elime の記録: ◯◯ を足しました」と 1 行で伝える。

### `update`（記録を作る・作り直す）

1. `python3 ${CLAUDE_PLUGIN_ROOT}/skills/elime/scan_sources.py --root <プロジェクト root>` を実行する（既定で残っている会話記録の全期間を読む）。projects の一覧、user 自身についての memory、user が Claude に送った発話（作業フォルダごと・新しい順・抜粋。自動投入の定型と一時フォルダでの試験は除外済み）が出る。
2. そこから、user が**繰り返し・自分の言葉で**扱っている分野・道具・遊び・仕事を拾う。1 回だけの話題や、Claude が持ち込んだだけの語は入れない。深さは次で決める:
   - **使い込んでいる** — 複数のプロジェクトか長い期間にわたり、user が細部の語彙で話している
   - **触ったことがある** — 扱った跡はあるが浅い・短い
   区分は、学問・研究・仕事・開発・生活の実務を「学術・仕事」、ゲーム・趣味の娯楽を「遊び」にする。
3. 既存の記録があれば、user が手で書いた行と「区分を分ける」の設定・「通じなかった比喩」「まだ知らない」「説明の好み」は消さずに残し、分野の表だけを足す・深さを直す。各行の根拠に、観測した場所（プロジェクト名・日付）を書く。
4. 書き終えたら、足した行・深さを変えた行を user に短く見せる。

### `show`

記録の「区分を分ける」の既定、分野の表、説明の好みを、そのまま短く見せる。

### 既定の切り替え

「区分を分けるのを既定にして／やめて」と言われたら、記録の「区分を分ける」の行を `分ける` か `分けない` に書き換えて 1 行で伝える。

## 記録に書かないもの

秘密の値（token・パスワード）、他人の個人情報、健康などの機微な事柄は、発話に出ていても記録しない。記録は「何を知っているか」だけで、「何をしたか」の日記にしない。
