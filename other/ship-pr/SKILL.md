`/create-pr` → `/loop-ai-reviews` を順に呼ぶ**ラッパー**です。判定基準も手順も持たず、順序だけを管理します。

| やること | 担当 |
| --- | --- |
| **差分を多角的に見る深いレビュー** | **プロジェクト側のスキル**（あるリポジトリだけ） |
| 点検・コミット・PR 作成 | `create-pr` |
| AI レビューの起動 → 完了待ち → 指摘対応を N 周 | `loop-ai-reviews` |
| 周回後の仕上げ（点検・PR 説明の更新） | **`loop-ai-reviews` が内部で `finalize-prs` を1回呼ぶ** |

**`finalize-prs` をこのスキルから呼びません。** `loop-ai-reviews` が担っており、重ねると点検3種が二重に走ります。指摘ゼロで終わった周は差分が動いていないので、そもそも仕上げが要りません（ `create-pr` の時点で点検済み）。

## 進め方

### 1. 周回数の決定

**`--rounds N`** で指定し、**省略時は2** とする。上限5は `loop-ai-reviews` 側で丸められる。

**裸の数値を周回数として解釈しない。** 残りの引数は `create-pr` へそのまま渡す情報として扱う。

**`--screenshot` と `--video` はそのまま `create-pr` へ渡す。** 判定は `update-pr-description` が持つので、ここでは通過だけ。

**AI レビューは1周ごとに課金される。** 開始前に「PR を作成し、AI レビューを N 周回す」と1行伝える。Step 2の深いレビューを回すなら、**それも含めて先に伝える**（サブエージェントを並列起動するぶん重い）。

### 2. 深いレビュー（プロジェクト側にあれば）

**差分をレイヤー別・観点別に分けて見るプロジェクトスキル**が利用可能なら、`create-pr` より先に呼ぶ。無いリポジトリでは**黙って飛ばす**。

- 判定は**利用可能なスキルの一覧**で行う。グローバル側には無いものなので、名前を決め打ちしない
- 指摘の採否は `create-pr` と同じ基準（ `[must]` 相当は原則対応、`[imo]` / `[nits]` は直した結果が良くなるかで判断）。**非対応にしたものは理由をユーザーへ報告する**
- **ここでコミットしない。** 直した分は次の `create-pr` が点検・コミットまで面倒を見る
- **PR を作る前に置く理由**は、指摘を取り込んでから出すとレビュアーが見る差分が最初から整うため。周回の後に回すと、追加コミットが積み上がる

### 3. PR の作成

`create-pr` を Skill ツールで呼ぶ。ユーザーから渡された情報（ブランチ・base・Backlog 等）はそのまま引数に載せる。

**既に PR があるなら中断する。** `create-pr` は新規作成の責務で、既存 PR の更新は `update-pr-description` が担う。この場合は `loop-ai-reviews` だけを呼べばよい旨を伝えて終了する。

### 4. AI レビューの周回

`create-pr` の完了を待ってから、`loop-ai-reviews` を Skill ツールで呼び、Step 1で決めた周回数を渡す。PR が無い状態ではレビューを起動できないので、順序を入れ替えない。

### 5. 完了報告

各スキルの報告を**そのまま二重に貼らない**。要点だけ拾って1つにまとめる。

- **深いレビューを回したなら、その指摘件数と採否**（回していないなら触れない）
- 作成した PR の URL（draft 状態・assignees・reviewers を1行で）
- 周ごとの結果（run ID / 指摘件数 / 対応したコミット）
- 打ち止めた理由

## 出力の目安

- 3〜6行。PR の URL と、周回の結果を1行ずつ
- 途中で止まったときは、どのステップで何が起きたかを明記する

## やってはいけないこと

- **`finalize-prs` を呼ぶこと**。`loop-ai-reviews` が担う
- 各スキルの手順・判定基準をこの本文で再定義すること。**順序だけを管理する**
- **深いレビューのスキル名をこの本文に書くこと**。プロジェクト側にしか無いものを名指しすると、**それが無いリポジトリで存在しないものを案内する**ことになる（ `ask_before_editing_claude_assets.md` ）
- 深いレビューが無いリポジトリで、**無いことを報告すること**。黙って飛ばす
- 深いレビューの指摘を**コミットまでしてしまうこと**。`create-pr` の点検を経てからまとめて1回にする
- `create-pr` の完了を待たずに `loop-ai-reviews` を呼ぶこと
- 周回数の省略時に1周で済ませること。**既定は2**（1周目の指摘に対応した差分を、もう1周見てもらうため）
- PR を ready 化すること（ `no_auto_ready_pr.md` ）

## 例外

- ユーザーが「レビューは要らない」と明示した場合は `create-pr` だけで終える
- ユーザーが「**深いレビューは要らない**」と明示した場合は Step 2を飛ばす
- 既に PR があり、ユーザーがレビュー周回だけを求めている場合は Step 2・3を飛ばす
