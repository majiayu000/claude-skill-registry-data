# Next steps

仅由用户手动调用的纯 skill：根据当前会话，预测用户最可能接着提出的具体请求，而不是制定待办计划。

## 生成建议

1. 找出紧接当前对话的自然续接，明显的续接优先。最多给出 3 个选项；有几条自然建议就给几条，不强凑数量。
2. 每条同时展示短 label 和完整 prompt，按优先级从 `1` 连续编号：`1. 精简标题：完整请求`。label 简短到能一眼辨认动作；prompt 用用户口吻，通常是一句具体请求或一条调用命令，只补执行必需的目标、上下文与参数。已有约束沿用会话，不重复铺陈实施步骤和验收清单。
3. 适合现有 skill 或 slash command 时，优先写真实调用及所需参数。以当前宿主实际可用列表为依据，不为建议加载所有 skill，不猜名称、参数，也不强凑 skill。pi 使用 `/skill:name`，其他宿主使用其真实语法；无法确认调用或缺少参数时写普通请求。

生成阶段只输出建议，不加解释性前言或尾注，不执行。没有自然下一步时回复“暂无下一步建议”；用户明确结束当前任务时回复“当前任务已结束，暂无下一步建议”。不提供 dismiss 选项。

## 执行选择

用户明确选择编号时，只匹配最近仍有效的建议列表，将所选完整 prompt 作为用户请求直接执行，不回显草稿、不填输入框。调查或访谈中的数字答案按当前问题处理；无法判断是否在选择建议时，先澄清。编号无效或列表已失效时，说明无法匹配并请用户明确请求。

选择被接受后，整份列表立即失效，执行失败也不自动重放。用户明确结束当前任务、转入其他任务、生成新建议或反馈无建议时，旧列表同样失效。用户显式引用旧 prompt 时，按新请求处理。

执行沿用会话既有约束与审批要求，并遵循所选 skill 自身流程及宿主调用机制。编号选择不绕过宿主的 user-only 加载限制；工具不支持加载所选 user-invoked skill 时，按宿主可用路径处理。没有可用路径则如实说明；宿主要求用户显式调用时，请用户按其真实语法调用。

## 示例

假设登录修复和测试刚写完、尚未运行；设置页已确认有同样的问题。pi 已确认可用的 model-invoked skill `code-review` 支持以 `main` 为审查基点，会话也已选定该基点：

```text
1. 跑登录测试：运行刚写的登录测试，确认修复有效。
2. 同步设置页：把刚才的修复同步到有同样问题的设置页。
3. 审查本次变更：/skill:code-review main
```
