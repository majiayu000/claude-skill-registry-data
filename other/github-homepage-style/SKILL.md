# 个人GitHub首页布局 v1.0

用户于2026-10-10明确要求保存这版布局，减少以后上传仓库时重复调整格式。基准为念景v0.2.1的README，维护者账号为TUANZIDING。

## 使用方式

1. 先读取目标仓库已有README、语言文档、使用入口及适用的AGENTS.md，确认实际功能与素材。保持原有事实、有效链接和当前版本。
2. 读取[布局规范](references/布局规范v1.0.md)。新首页从[中文模板](assets/中文首页模板v1.0.md)和[英文模板](assets/英文首页模板v1.0.md)开始；只做小修改时保留现有结构，无需重建。
3. 按这版默认顺序组织：宽幅主图 → 居中中英文标题与短定位 → 语言入口和真实状态徽章 → 功能短标签与导航 → 使用场景与辅助主图 → 作品或成果展示 → 快速开始与实际界面 → 工作流 → 能力状态 → 可折叠技术配置 → 共创与文档索引 → 维护者、来源与许可。
4. 默认中文首页加独立完整英文首页。双方保持相同信息层级、事实与入口；在英文文档中重新计算相对链接。用户指定其他语言安排时依其要求调整。
5. 保留大图、留白、短段落、两列展示和简洁表格的视觉节奏。配色、插画和示例依项目主题变化；念景的米白纸张与暖金色是创作工具的案例，不是所有仓库的硬性主题。
6. 检查图片、链接、锚点、启动命令、版本与双语内容。覆盖Markdown及HTML中的图片和链接。删除无用途的章节，替换模板变量，不填造假的徽章、统计、合作或结果。
7. 如任务包括发布，按已有授权操作并核对远程文件；将内容核对、GitHub渲染和浏览器视觉复核分别报告。保存布局本身不授予未来仓库的发布权限。

## 关键取舍

- 用户已选择此布局，通常不再询问“要哪种风格”；仅在现有材料不足以确定重要内容时澄清。
- 将项目定位和首次使用放在技术细节前面。复杂API配置用`details`折叠或链接到文档。
- 美观主图可以是概念视觉；真实截图、既有示例和概念图必须各自明确标记。主图不证明功能已实现，图片内不承载唯一的重要标题、统计或操作说明。
- 无可用主图时，可先使用现有合法素材；需要新生成图片时使用当前可用的图像生成能力并记录来源。不要把念景的图片自动复制到其他项目。
- 仅整理README不会改动应用界面、部署方案或功能。GitHub原生导航、字体和主题不受README控制。
- 自主命名的新文档和素材使用自然名称加版本号，不用下划线；保留已有文件名。`SKILL.md`、`agents/openai.yaml`、`README.md`等是工具指定的固定入口名，不属于自主命名。

## 基准与扩展

[念景首页基准](references/念景首页基准v0.2.1.md)保存了这版的原文快照，仅供排版对照；里面的路径属于原仓库，不是新项目模板。[保存记录](references/保存记录v1.0.json)记录基准提交和文件摘要。

新项目没有画廊、API配置或界面时，省略对应段落，或用真实成果、流程图和文档入口替代；沿用信息层级，不强行填满念景的全部章节。若用户之后修改默认布局，同步更新规范与模板的版本。
