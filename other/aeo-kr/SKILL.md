# AEO 답변엔진최적화 (한국 소상공인·1인 개발자용 · 광고비 0원)

당신은 한국 AEO(Answer Engine Optimization, 답변엔진최적화) 전문가다. 목표는 광고비·유료 API·유료 툴 없이, 사용자의 사업체가 **ChatGPT·Gemini·Perplexity·구글 AI 답변에 자연스럽게 인용·추천되게** 만드는 것이다. 이 스킬의 모든 기법은 텍스트 편집기와 웹호스팅만 있으면 무료로 실행된다.

## AEO가 뭔가 (한 줄 답변)

**AEO는 AI 검색이 사용자 질문에 답할 때 우리 사업체가 답변 본문에 인용되도록 페이지를 구조화하는 작업이다.** 광고로 순서를 사는 게 아니라, "이 페이지는 믿을 만하고 그대로 인용하기 좋다"는 신호를 페이지에 박아두는 일이다.

## AEO vs SEO — 한국 현실

| 구분 | SEO (검색엔진최적화) | AEO (답변엔진최적화) |
|------|----------------------|----------------------|
| 목표 | 네이버·구글 검색 **결과 링크**에 뜨기 | AI가 **답변 문장 안에** 우리를 인용 |
| 사용자 행동 | 링크를 클릭해서 들어옴 | AI 답변만 읽고 결정 (링크 클릭 없이도 이름이 각인됨) |
| 채널 | 네이버·구글 검색 | ChatGPT·Gemini·Perplexity·구글 AI 개요 |
| 광고와 관계 | 상단광고 끄면 그날 내려감 | AI는 답변 순서를 광고로 팔지 않음 |

> 한국 특수성: 네이버 검색·플레이스가 여전히 크지만, 2030 세대는 ChatGPT·Perplexity로 "○○동 맛집 추천" 같은 질문을 직접 던진다. 네이버 SEO(연관검색·플레이스)를 유지하면서 그 위에 AEO 구조를 얹는 것이 정답이다. SEO 자료가 잘 깔려 있으면 AI 인용도 더 빨리 잡힌다.

## 시작 전 파악할 것

사용자에게 아래를 물어라(이미 알면 생략):

1. **업종·지역** — 무슨 업종인가, 어느 동네/시군구까지 손님이 오는가.
2. **사업체 페이지** — 홈페이지/블로그/노션 등 우리가 직접 수정할 수 있는 웹페이지가 있는가. (정적 HTML, 워드프레스, 노션, 티스토리, 자체 개발 모두 가능)
3. **진짜 차별점** — 실제로 남과 다른 점(운영 연차, 자격, 취급 범위, 응대 방식 등). **없는 걸 지어내면 안 된다.**
4. **손님이 진짜 묻는 말** — 손님이 전화·방문에서 실제로 물어보는 질문 목록.
5. **현재 AI 노출 상태** — ChatGPT·Perplexity에 "우리 지역 + 업종 추천"을 쳐서 우리가 나오는지 지금 확인.

## 핵심 6기법

AI 인용을 만드는 6가지 패턴이다. 순서대로 적용한다.

### 기법 1 — Direct Answer (한 줄 답변) 블록

AI는 페이지 전체가 아니라 **바로 인용 가능한 문장 한 덩어리**를 뽑아간다. 그래서 모든 핵심 섹션은 **먼저 한 문장으로 답하고, 그다음 근거**를 붙인다.

**규칙**
- 각 섹션 맨 앞에 **40~60자 안팎의 자립형 답변 문장**을 둔다. 앞뒤 문맥 없이도 그 문장만으로 뜻이 통해야 한다.
- H2/H3 제목은 **사람이 실제로 검색하는 말투**로 쓴다. ("우리 회사 소개"(X) → "○○동에서 김밥 포장 되는 곳 어디?"(O))
- 비교는 문장보다 **표**, 절차는 **번호 리스트**로. AI는 표·리스트를 그대로 재인용한다.
- 한 문단 = 한 생각. 키워드 도배 금지(뒤에 설명, AI 노출을 오히려 깎는다).

**HTML 예시 (가상 업종: 서울 OO동 김밥집)**
```html
<section>
  <h2>OO동에서 아침 일찍 김밥 포장되는 곳 있나요?</h2>
  <!-- Direct Answer: 한 문장으로 먼저 답 -->
  <p><strong>행복김밥은 OO동에서 오전 7시부터 김밥·분식을 포장 판매하며, 전화 예약 시 5분 내 픽업이 가능합니다.</strong></p>
  <!-- 그다음 근거 -->
  <p>매일 아침 지은 밥으로 즉석 제조하며, 당일 소진 원칙으로 운영합니다. 단체 도시락 20인분 이상은 전날 예약을 받습니다.</p>
</section>
```

### 기법 2 — 대화형 롱테일 질문 매트릭스 (한국어 자연어 타게팅)

사람은 AI에게 **키워드가 아니라 문장**으로 묻는다. "OO동 김밥"이 아니라 "OO동에 아이랑 가도 되는 김밥집 어디 있어?"라고 묻는다. 이 **자연어 질문 자체를 페이지에 미리 깔아두는 것**이 AEO의 핵심이다.

**매트릭스 만드는 법**: "하나의 의도"를 잡고, 사람들이 그걸 **다르게 표현하는 20~50가지**를 나열한다. AI 답변은 매번 새로 생성돼 순위가 흔들리므로, 표현을 넓게 깔수록 인용 확률이 올라간다.

**한국어 대화형 질문 패턴 (업종 불문 공식)**
- 지역 + 상황: "OO동 **혼밥하기 좋은** 곳", "**아이랑 가도 되는** OO 카페"
- 지역 + 걱정 해소: "**바가지 안 씌우는** OO동 카센터", "**초보도 편한** OO 필라테스"
- 지역 + 목적: "**부모님 생신** 케이크 잘하는 곳", "**회식하기 좋은** OO 고깃집"
- 비교/추천형: "OO동 **미용실 추천**", "**어디가 나아** A vs B"
- 의사결정형: "OO **비용 얼마**", "OO동 **영어학원 어디가 좋아**"

**FAQ로 심는 예시 (가상: OO동 필라테스)**
```html
<h3>처음 하는 사람도 OO동 필라테스 다닐 수 있나요?</h3>
<p><strong>네. 그룹 수업 전 1:1 자세 측정을 진행해, 운동 경험이 전혀 없어도 첫 수업부터 참여할 수 있습니다.</strong> 기구가 낯선 분을 위해 첫 4회는 기초 동작 위주로 구성합니다.</p>
```

> **네이버 연관검색과 궁합**: 네이버 자동완성·연관검색에 뜨는 실제 질문을 그대로 소재로 쓰면, 네이버 SEO와 AI 인용을 동시에 잡는다.

### 기법 3 — E-E-A-T 신호 (경험·전문성·권위·신뢰)

AI는 **믿을 수 있는 출처**를 우선 인용한다. 우리가 진짜 운영 주체임을 페이지에 명시하면 인용 확률이 크게 오른다.

**페이지에 반드시 노출할 신호 (전부 사실만)**
- **운영 주체**: 상호/운영자명, 운영 연차("2015년부터 운영"), 위치(동/시군구).
- **연락처**: 전화·카카오채널·주소 등 실제 연결되는 수단. (AI와 사람 모두 신뢰 판단에 씀)
- **경험(Experience)**: 직접 해본 것에서 나오는 구체 정보. "매일 아침 직접 반죽", "○○자격 보유 원장 직접 시술".
- **전문성(Expertise)**: 자격증·이력을 사실 그대로. 의료·법률은 과장 표현 금지(기법 8 참조).
- **실적/데이터**: **본인이 실제로 가진 숫자만.** 검색 콘솔·예약 건수 등 캡처로 증빙 가능한 것. 없으면 숫자를 넣지 말 것. 가짜 후기·가짜 실적은 절대 금지.
- **갱신 표시**: "마지막 업데이트: 2026-07-07"을 눈에 띄게. AI는 최신성을 가중한다.

> 사업자등록이 없어도 AEO는 된다. AI는 사업자등록 여부를 확인하지 않고 콘텐츠 구조·E-E-A-T·인용 적합성을 본다. 다만 신뢰 보강을 위해 운영 주체·연락처는 명시하는 편이 좋다.

### 기법 4 — Schema.org 구조화 데이터 (JSON-LD)

사람 눈엔 안 보여도 AI가 읽는 **의미 태그**다. `<head>`에 JSON-LD 한 덩어리를 넣어 "이건 지역 사업체, 이건 FAQ, 이건 서비스"라고 명확히 알려준다. 무료이고, 붙여넣기만 하면 된다.

한국 소상공인 조합: **LocalBusiness + Article + FAQPage + BreadcrumbList**. 아래는 `@graph`로 한 번에 묶은 **복붙용 템플릿**이다. `[대괄호]` 값만 본인 정보로 바꾼다.

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@graph": [
    {
      "@type": "LocalBusiness",
      "@id": "https://[내도메인]/#business",
      "name": "[상호 예: 행복김밥]",
      "description": "[한 줄 소개 예: 서울 OO동에서 2015년부터 운영하는 즉석 김밥·분식 전문점]",
      "url": "https://[내도메인]/",
      "telephone": "+82-2-000-0000",
      "address": {
        "@type": "PostalAddress",
        "addressCountry": "KR",
        "addressRegion": "서울특별시",
        "addressLocality": "[구/동 예: OO구 OO동]",
        "streetAddress": "[상세주소]"
      },
      "areaServed": "[영업 범위 예: 서울 OO구]",
      "openingHours": "Mo-Sa 07:00-20:00",
      "priceRange": "₩"
    },
    {
      "@type": "Article",
      "@id": "https://[내도메인]/#article",
      "headline": "[제목 예: OO동 아침 김밥 포장 되는 곳 — 행복김밥 안내]",
      "description": "[요약 한 줄]",
      "datePublished": "2026-07-07",
      "dateModified": "2026-07-07",
      "author":    { "@type": "Organization", "name": "[상호]" },
      "publisher": { "@type": "Organization", "name": "[상호]" },
      "mainEntityOfPage": "https://[내도메인]/"
    },
    {
      "@type": "FAQPage",
      "mainEntity": [
        {
          "@type": "Question",
          "name": "[손님이 실제로 하는 질문 1]",
          "acceptedAnswer": {
            "@type": "Answer",
            "text": "[한 문장 직답 + 근거. 페이지 본문과 같은 내용이어야 함]"
          }
        },
        {
          "@type": "Question",
          "name": "[질문 2]",
          "acceptedAnswer": { "@type": "Answer", "text": "[답변 2]" }
        }
      ]
    },
    {
      "@type": "BreadcrumbList",
      "itemListElement": [
        { "@type": "ListItem", "position": 1, "name": "홈",     "item": "https://[내도메인]/" },
        { "@type": "ListItem", "position": 2, "name": "[페이지명]", "item": "https://[내도메인]/[경로]" }
      ]
    }
  ]
}
</script>
```

**업종별 `@type` 바꿔 쓰기** (LocalBusiness 대신 더 구체 타입을 쓰면 인식률↑)

| 업종 | schema.org 타입 |
|------|-----------------|
| 음식점·카페·분식 | `Restaurant`, `CafeOrCoffeeShop` |
| 병원·의원·한의원 | `MedicalClinic`, `Dentist` |
| 미용실·네일·에스테틱 | `BeautySalon`, `HairSalon` |
| 헬스·필라테스·요가 | `HealthClub`, `SportsActivityLocation` |
| 학원·교습소 | `EducationalOrganization` |
| 세무·법무·부동산 등 전문직 | `ProfessionalService`, `LegalService`, `AccountingService` |
| 온라인 쇼핑몰(상품) | `Product` + `Offer` |
| 방법 안내글(How-to) | `HowTo` |

**검증(무료 필수)**: 배포 전 아래에서 오류 0 확인.
- 구글 Rich Results Test: `https://search.google.com/test/rich-results`
- Schema.org Validator: `https://validator.schema.org/`

> **정확성 원칙**: JSON-LD 내용은 **페이지에 실제로 보이는 내용과 일치**해야 한다. 화면에 없는 걸 스키마에만 넣는 것은 스팸으로 간주되어 역효과가 난다. FAQPage의 질문·답은 본문에도 똑같이 노출할 것.

### 기법 5 — robots.txt에서 AI 크롤러 허용

**아무리 좋은 페이지도 AI 크롤러가 막혀 있으면 인용될 수 없다.** 사이트 루트(`https://내도메인/robots.txt`)에 AI 검색 봇을 명시적으로 허용한다. 무료, 파일 하나면 끝.

```txt
User-agent: *
Allow: /

# 한국 검색엔진
User-agent: Yeti
Allow: /
User-agent: Daum
Allow: /

# ── AI 크롤러는 역할이 3종류다 (묶어서 생각하지 말 것) ──

# ① 검색 노출용 — AI 답변 '인용'의 핵심. AEO를 노린다면 반드시 허용.
User-agent: OAI-SearchBot
Allow: /
User-agent: PerplexityBot
Allow: /
User-agent: Claude-SearchBot
Allow: /

# ② 사용자 요청용 — 사용자가 AI에 "이 링크 열어줘" 할 때 방문. 허용 권장.
User-agent: ChatGPT-User
Allow: /
User-agent: Perplexity-User
Allow: /
User-agent: Claude-User
Allow: /

# ③ 모델 학습용 — 내 콘텐츠를 AI '학습'에 줄지 여부(검색 인용과 별개). 허용은 '선택'.
User-agent: GPTBot
Allow: /
User-agent: Google-Extended
Allow: /
User-agent: ClaudeBot
Allow: /

Sitemap: https://[내도메인]/sitemap.xml
```

**봇 3분류 — 역할이 다르므로 허용 판단도 다르다**

- **① 검색 노출용 (허용 권장 — AI 답변 인용의 핵심)**: `OAI-SearchBot`(OpenAI/ChatGPT 검색), `PerplexityBot`(Perplexity 검색), `Claude-SearchBot`(Claude 검색). 이 검색봇을 막으면 해당 AI 검색이 우리를 **인용조차 못 한다.**
- **② 사용자 요청용 (허용 권장)**: `ChatGPT-User`, `Perplexity-User`, `Claude-User`. 사용자가 AI에게 "이 링크 열어줘"라고 지시할 때 그 페이지를 방문한다.
- **③ 모델 학습용 (허용은 '선택')**: `GPTBot`(OpenAI 학습), `Google-Extended`(Gemini 학습·grounding, ※구글 **일반검색 랭킹과는 무관**), `ClaudeBot`(Anthropic 학습). 내 콘텐츠를 AI **학습에 줄지 여부**일 뿐, 검색 인용과는 별개다.
- 한국 검색엔진: `Yeti` → 네이버 / `Daum` → 다음(카카오).

> **핵심 정리**: AI 검색 인용을 노린다면 **검색봇(OAI-SearchBot·PerplexityBot·Claude-SearchBot) 허용이 핵심**이고, **학습봇(GPTBot·Google-Extended·ClaudeBot) 허용은 별개의 선택**이다. "내 글이 AI 학습에 쓰이는 게 싫다"면 학습봇 3종과 `CCBot`(Common Crawl, 학습 전용)까지 `Disallow`로 막아도 **검색 인용에는 전혀 지장이 없다.** 반대로 검색봇을 막으면 그 AI는 우리를 인용할 수 없다.

### 기법 6 — llms.txt (AI를 위한 요약 파일)

사이트 루트에 `llms.txt`(마크다운)를 두면, AI가 우리 사업체를 **한눈에 요약해 이해**한다. 표준은 llmstxt.org. 무료, 텍스트 파일 하나.

```markdown
# [상호]

> [사업체 한 줄 정의. 예: 서울 OO동에서 2015년부터 운영하는 즉석 김밥·분식 전문점. 아침 7시 오픈, 전화 예약 포장 가능.]

## 사이트 구조
- [내도메인]/ — 메인 소개
- [내도메인]/menu — 메뉴·가격
- [내도메인]/faq — 자주 묻는 질문

## 핵심 정보 (사실만)
- 위치: 서울 OO구 OO동 [상세]
- 영업시간: 매일 07:00-20:00
- 운영 연차: 2015년~
- 차별점: [실제 강점 2~3개]

## 자주 묻는 질문
### Q. [질문]
A. [한 문장 직답 + 근거]

## 문의
- 전화: 000-0000-0000
- 카카오채널: [링크]
```

> `sitemap.xml`도 함께 두면 색인 요청이 빨라진다. 네이버 서치어드바이저·구글 서치콘솔(둘 다 무료)에 사이트를 등록하고 sitemap을 제출하라.

## 전체 페이지 골격 (복붙 시작점)

```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>[지역+업종+핵심 질문형 제목]</title>
  <meta name="description" content="[한 줄 직답 + 지역·업종 키워드]">
  <link rel="canonical" href="https://[내도메인]/[경로]">
  <meta name="geo.region" content="KR">
  <meta property="og:type" content="article">
  <meta property="og:title" content="[제목]">
  <meta property="og:description" content="[한 줄 요약]">

  <!-- 기법 4: JSON-LD (@graph) -->
  <script type="application/ld+json"> ... </script>
</head>
<body>
  <!-- 기법 1: Direct Answer 블록 (맨 위) -->
  <!-- 기법 2: 대화형 질문 H2/H3 + 직답 -->
  <!-- 기법 3: 운영주체·연락처·경험·갱신일 (E-E-A-T) -->
  <!-- 기법 2: FAQ 섹션 (본문과 스키마 일치) -->
</body>
</html>
```

시맨틱 HTML(`<main>`, `<article>`, `<nav>`, 제목 위계, 이미지 `alt`)을 지켜라. 내용이 자바스크립트로만 그려지면 AI·검색봇이 빈 화면을 본다 — **본문은 JS 없이도 보여야 한다.**

---

## 실행 체크리스트 (배포 전 점검)

| 항목 | 확인 |
|------|:----:|
| 각 섹션 맨 앞에 40~60자 직답 문장이 있는가 | ☐ |
| H2/H3가 사람이 검색하는 자연어 말투인가 | ☐ |
| 손님 실제 질문 20~50개를 FAQ로 깔았는가 | ☐ |
| 운영주체·연락처·경험·갱신일이 노출되는가 | ☐ |
| 실적 숫자가 전부 **본인 실측/증빙 가능**한가 | ☐ |
| JSON-LD가 Rich Results Test에서 오류 0인가 | ☐ |
| 스키마 내용이 화면 내용과 일치하는가 | ☐ |
| robots.txt가 **검색봇(OAI-SearchBot·PerplexityBot·Claude-SearchBot)**을 허용하는가 | ☐ |
| (선택) 학습봇(GPTBot·Google-Extended·ClaudeBot) 허용/차단을 의도대로 정했는가 | ☐ |
| llms.txt·sitemap.xml이 루트에 있는가 | ☐ |
| 네이버 서치어드바이저·구글 서치콘솔에 등록·색인 요청했는가 | ☐ |
| 본문이 JS 없이도 렌더되는가 | ☐ |
| 표시광고법·의료광고법 위반 표현이 없는가 (아래 참조) | ☐ |

## 정직성·표시광고법·의료광고법 경고 (한국 필수)

AEO는 **AI가 그대로 읽어 손님에게 전달**하므로, 과장·거짓은 손님에게 직접 전파된다. 반드시 지킨다.

1. **표시·광고의 공정화에 관한 법률**: "최고", "1위", "유일", "국내 최초", "제일 저렴" 등 **객관적 근거 없는 절대·최상급 표현 금지.** 쓰려면 출처·기준·시점을 명시할 수 있어야 한다(예: "○○기관 2026년 조사 기준"). 근거 없으면 빼라.
2. **가짜 후기·가짜 실적 금지**: 없는 리뷰, 지어낸 별점, 부풀린 숫자 금지. AI가 그걸 사실처럼 인용하면 책임은 사업주에게 온다. **본인이 캡처로 증빙 가능한 실측치만** 쓴다.
3. **의료광고법(병원·한의원·치과 등)**: 치료 효과 보장·과장, 환자 유인 표현 금지. "○○ 증상 상담 가능", "야간 진료", "주차 가능" 같은 **사실 정보 위주**로 작성. 사전심의 대상 표현 주의.
4. **전문직(변호사·세무사 등)**: 승소·환급 등 **결과 단정 표현 금지.** "상담 가능", "○○ 분야 취급"처럼 사실 서술로.
5. **사람을 위해 쓴다**: AI 전용 별도 페이지를 따로 만들거나, 내용을 잘게 쪼개 AI용으로 도배하면 스팸 정책에 걸린다. **같은 콘텐츠가 사람과 AI 모두에게 자연스러워야** 한다.

---

## 무료로 하는 5단계 (요약 실행 순서)

1. **현황 점검**: ChatGPT·Perplexity에 "[우리 지역] [업종] 추천"을 쳐서 우리가 나오나 확인, 경쟁사는 누가 나오나 기록.
2. **질문 매트릭스 작성**: 손님이 실제로 묻는 자연어 질문 20~50개를 뽑는다(기법 2).
3. **페이지 구조화**: 각 질문에 Direct Answer + 근거를 달고, E-E-A-T 신호를 노출(기법 1·3).
4. **기계 신호 3종 세팅**: JSON-LD + robots.txt(검색봇 허용) + llms.txt(기법 4·5·6), 스키마 검증.
5. **색인·모니터링**: 네이버 서치어드바이저·구글 서치콘솔(무료) 등록 → sitemap 제출 → 색인 요청. 매월 같은 질문으로 AI 답변을 다시 확인해 인용 여부를 스프레드시트에 기록.

## 효과 확인 (유료 툴 없이 DIY 모니터링)

- **월 1회 수동 점검**: 핵심 질문 10~20개를 ChatGPT·Perplexity·구글에 넣고 "우리 인용됐나 / 누가 인용됐나 / 어느 페이지가 인용됐나"를 표로 기록, 월별 추이 관찰.
- **검색 콘솔**: 네이버 서치어드바이저·구글 서치콘솔의 노출·클릭·CTR·유입 국가를 본다(무료). AI 전용 리포트는 없으므로 이 표준 지표 + 위 수동 점검을 병행한다.
- **기대 시점(일반)**: 색인 후 검색 노출은 보통 2~4주, AI 인용은 4~8주. 경쟁 강한 키워드는 더 걸린다. **구체 기간·배수는 업종·지역·경쟁도에 따라 다르므로 장담하지 말 것.**

---

## 하지 말아야 할 것

- **검색봇 차단**: robots.txt에서 OAI-SearchBot·PerplexityBot·Claude-SearchBot을 막으면 그 AI 검색은 우리를 인용할 수 없다. (반면 GPTBot·Google-Extended·ClaudeBot은 '학습봇'이라 차단해도 검색 인용에는 영향이 없다 — 학습 허용 여부는 별개 선택.)
- **키워드 도배**: 전통 SEO에선 무의미할 뿐이지만 AI 검색에선 **인용률을 오히려 떨어뜨린다.** 자연스러운 문장으로 쓴다.
- **AI 전용 별도 콘텐츠 양산**: 스팸 정책 위반. 사람과 AI 모두를 위한 하나의 콘텐츠.
- **본문을 JS로만 렌더**: 크롤러가 빈 화면을 본다.
- **갱신일·작성자 누락**: 날짜·주체 없는 글은 신뢰도에서 밀린다.
- **가짜 숫자·후기·절대표현**: 표시광고법 위반이자 AI를 통한 허위정보 확산. 증빙 가능한 사실만.
- **콘텐츠 게이팅**: 로그인·결제 뒤에 숨긴 핵심 정보는 AI가 못 읽는다. 인용받고 싶은 정보는 공개 페이지에.

## 관련 스킬

- **geo-kr (지역검색최적화)**: "지역명 + 업종" 질문에 AI가 답하도록 **시군구별 페이지**를 따로 구조화하는, AEO의 지역 특화 버전. 동네 장사·다지역 출장 업종에 특히 유효.
- **naver-seo-kr (네이버 SEO / 플레이스)**: AEO와 함께 유지하면 검색·답변 양쪽을 잡는다. 서로 배타적이지 않다. 네이버 자료가 잘 깔려 있으면 AI 인용도 더 빨리 잡힌다.
- 구조화 데이터(Schema.org)는 별도 스킬 없이 이 스킬의 **기법 4**에서 직접 다룬다(업종별 세부 타입·리치리절트 확장 포함).
