# 논문 품질 반복

원고를 심사, 분류, 실행, 문체의 바퀴로 돌리고, 시작 전에 적어 둔 기준에 닿으면 멈춘다. 이 스킬은 순서와 멈춤 규칙만 정한다. 각 단계의 방법은 다음 스킬을 따른다.

| 단계 | 따르는 스킬 |
|---|---|
| 주장과 증거, 초록과 서론과 결론, 틀 | paper-framing |
| 배치 실행과 보고, 할일목록 새 판 | research-batch |
| 숫자, 인용, 부등호, 헤지의 대조 | fact-check |
| 문체 | korean-academic-style, english-academic-style |
| 쪽 수 맞춤 | paper-condense |
| 투고 준비 | submission-package |
| 실제 심사평 대응 | rebuttal |

research-session의 공통 규칙을 따른다. 역할별 모델은 프로젝트 설정을 따른다. 프로젝트에 할일목록, 현황, 사전 등록 문서가 있으면 그 규칙이 이 스킬보다 앞선다. 이 스킬은 모의 심사의 반복을 다룬다. 투고 뒤 실제 심사평을 받으면 rebuttal로 넘긴다.

## 0. 시작할 수 있는 조건

아래 가운데 하나라도 맞지 않으면 바퀴를 돌리지 않고 이유를 사용자에게 알린다.

- 처음부터 끝까지 읽히는 초안이 있다. 결과 절이 비어 있으면 심사가 아니라 실험 배치가 먼저다.
- 원고의 범위(주장 목록, 넣을 것과 뺄 것)가 정해져 있다. 없으면 paper-framing 0절의 주장 목록부터 만든다.
- 첫 바퀴 전에 틀을 먼저 심사받았다. 심사 에이전트 하나에 paper-framing의 주장 목록(주장, 증거, 감당 여부)과 잠근 문제 정의만 주고, 주장이 증거에 비해 크거나 정의상 참인 부분이 있는지 묻는다. 여기서 큰 지적이 나오면 원고 심사에 들어가지 않고 paper-framing이나 problem-grill로 돌아간다.
- 원고를 막고 있는 사용자 결정이 없다. 있으면 그 결정을 먼저 묻는다.
- 마감과 쪽 수 상한을 안다.

## 1. 멈춤 기준을 먼저 적는다

첫 바퀴 전에 기준을 `<원고 폴더>/품질반복/기준.md`에 적고 사용자에게 보인다. 사용자가 따로 정하지 않으면 아래 기본값을 쓴다. 바퀴가 돈 뒤에는 기준을 낮추지 않는다. 바꾸려면 사용자가 정하고 승인기록에 남긴다.

| 기준 | 기본값 | 판정하는 쪽 |
|---|---|---|
| 증거가 감당하지 못하는 주장 | 0개 | 총괄 (paper-framing 0절 주장 목록) |
| 원고 숫자와 원자료의 불일치 | 0개 | 독립 검산 |
| 숫자는 맞으나 해석이 틀린 곳 | 0개 | 해석 검산 |
| 큰 지적 | 심사자 모두 0개 | 심사 |
| 새 독자가 막힌 곳(전체) | 3곳 이하 | 새 독자 |
| 쪽 수, 단어 수, 양식 | 투고처 규정 충족 | 총괄 |
| 횟수 상한 | 학회 판 2바퀴, 학술지 판 3바퀴 | |

작은 지적이 남아도 멈춘다. 심사 에이전트는 몇 번을 돌려도 지적을 내므로 지적 0개를 기준으로 삼지 않는다.

횟수 상한을 올리려면 사용자가 정하고, 그 결정과 이유를 승인기록에 남긴다. 총괄이 대신 올리지 않는다. 상한을 몇 번 올렸는지는 바퀴마다 보고에 적는다.

큰 지적은 다음과 같다. 주장을 증거가 받치지 못한다, 증명이나 계산이 틀렸다, 계산은 맞지만 해석이 틀렸다, 전제가 숨어 있어 결론이 달라질 수 있다, 비교군이 없어 결론을 내릴 수 없다, 가장 가까운 선행 연구와의 차이가 불분명하다, 재현에 필요한 정보가 없다.

작은 지적은 다음과 같다. 문장, 배치, 설명 부족, 용어 불일치, 그림과 표의 가독성.

## 2. 한 바퀴

### 2.1 심사

네 역할(심사, 새 독자, 독립 검산, 해석 검산)의 에이전트를 한 번에 함께 띄운다. 학회 판은 다섯, 학술지 판은 여섯이다. 역할별 모델은 프로젝트 설정을 따른다. 모두 새로 띄우고 앞선 대화와 이전 바퀴의 심사평을 넘기지 않는다.

| 역할 | 받는 것 | 내는 것 |
|---|---|---|
| 심사 ×2 (학술지는 ×3) | 익명 원고, 투고처의 심사 기준 | 지적 목록(크기, 위치, 근거), 판정(수락, 소수정, 대수정, 거절) |
| 새 독자 | 익명 원고 | 비전문가로 읽어 막힌 곳과 이유만 |
| 독립 검산 | 원고, 규칙 문서, 원자료 | 원고의 모든 숫자를 다시 계산한 대조표 |
| 해석 검산 | 원고, 규칙 문서, 결과 표 | 숫자마다 원고가 붙인 해석(크다, 같다, 개선, 원인)이 결과 표와 판정 규칙에서 나오는지의 대조표 |

- 심사자에게 지적마다 크다, 작다와 그 이유를 적게 한다. 1절의 정의를 지시문에 넣는다.
- 심사자에게 고칠 문장을 써 달라고 하지 않는다. 지적만 받는다.
- 해석 검산은 독립 검산과 따로 둔다(fact-check 2절). 독립 검산이 모두 맞아도 계산은 맞지만 해석이 틀린 경우가 남는다. 해석 검산은 비교의 방향, 차이를 크다고 부를 근거, 인과를 주장하는 문장, 판정 규칙에 없는 기준으로 내린 결론을 본다.
- 같은 계열 모델만으로 세 바퀴를 넘기지 않는다. 둘째 바퀴 안에 다른 계열 모델이나 사람(교신저자, 동료)의 검토를 한 번 넣는다. 같은 계열은 놓치는 곳이 겹친다. 다른 도구가 있으면 반론자 역할로 맡기고, 프로젝트에 교류 폴더(`00-교류/`)가 있으면 그 절차로 넘긴다. 어느 쪽도 없으면 사용자에게 사람 검토를 요청하고, 그 사실을 바퀴 기록에 적는다.

### 2.2 분류 (총괄)

총괄이 지적을 하나씩 표로 옮긴다. 열은 번호, 낸 쪽, 크기, 위치, 종류, 원자료 대조, 처리, 담당이다.

| 종류 | 처리 |
|---|---|
| 주장과 증거 | paper-framing 0절의 주장 목록으로 돌아간다. 증거를 더할 수 없으면 주장을 줄인다 |
| 실험 | 새 실험이나 재집계가 필요하다. 마감 안에 되는지 어림하고, 안 되면 주장을 줄이거나 한계에 적는다 |
| 사실과 숫자 | 원자료에서 총괄이 직접 다시 계산해 고친다 |
| 해석 | 결과 표와 판정 규칙으로 돌아가 해석 문장을 다시 쓴다. 숫자는 바꾸지 않는다 |
| 문장과 구조 | 해당 문단만 고친다 |
| 받지 않음 | 이유를 한 줄 적는다. 큰 지적은 근거 없이 받지 않을 수 없다 |

- 심사자도 틀린다. 지적을 그대로 믿지 않고, 원자료와 원고를 직접 대조해 지적이 맞는지 확인한 뒤에만 고친다. 대조 결과를 원자료 대조 열에 적는다. 대조해 보니 지적이 틀렸으면 받지 않음으로 두고 근거를 적는다.
- 심사자가 크다고 한 지적을 총괄이 작다고 낮추려면 이유를 적는다.
- 주장을 바꾸는 판단은 총괄이 제안하고 사용자가 정한다. 결정은 승인기록에 남긴다.
- 결과를 본 뒤에는 사전 등록한 판단 규칙을 바꾸지 않는다. 불리한 결과를 빼서 지적을 닫지 않는다.
- 분류가 끝나면 1절 기준으로 판정한다. 모두 충족이면 3절로 간다.

불리한 결과는 공통 규칙 8을 따른다.

### 2.3 실행

- research-batch 절차로 고친다. 진척을 수시로 보고하고 작업 목록에 올린다.
- 원고 수정, 집계, 조판은 실행 역할이 맡는다. 고친 에이전트가 자기 수정을 채점하지 않는다.
- 배치 구조나 일정이 바뀔 때만 research-batch로 할일목록의 새 판을 만든다. 바퀴마다 만들지 않는다.
- 초록, 서론, 결론을 고칠 때는 paper-framing 5절(심사 대응 이동 기록)을 지킨다. 이전 바퀴에서 닫은 지적이 다시 열리지 않았는지 대조한다.

### 2.4 문체

- 이번 바퀴에서 바뀐 문단에만 문체 스킬을 적용한다.
- 전체 적용은 원고를 고정하기 직전에 한 번만 한다. 문체 수정은 사실을 바꿀 수 있으므로, 적용 뒤 fact-check로 대조한다. 숫자, 부등호, 인용, 조건, 헤지가 적용 전 판과 같아야 한다.
- 쪽 수가 넘치면 paper-condense로 줄인다.

### 2.5 바퀴 기록

`<원고 폴더>/품질반복/R<번호>/`에 심사평 원문, 분류표, 독립 검산과 해석 검산의 대조표, 판정을 둔다. 현황 맨 위에 한 항목을 더하고, 현황의 원고 칸을 갱신한다. 통째로 덮어쓰지 않는다.

## 3. 멈춤과 보고

바퀴가 끝날 때마다 진행판으로 보고한다. 바퀴 안에서 심사 에이전트를 띄우면 에이전트 표가 있는 진행판을 보인다. 틀은 research-session 8절(시작 안내, 진행판, 마침 보고)을 따른다. 아래는 이 스킬의 보고에 들어갈 내용의 예다.

```
== 진행 | <프로젝트> | 품질 반복 | HH:MM (R2 끝, 시작 HH:MM, 경과 n분, 남은 어림 n분) ==
전체   [##########--] 기준 5/6
바퀴   R1 [완료]  R2 [완료]  R3 [예정]  (상한 3, 상한 올림 0회)
기준   큰 지적 미충족(심사2 1건: 정리 1 전제) / 감당 못 하는 주장 0 / 숫자 불일치 0
       해석 불일치 0 / 새 독자 막힘 2 / 쪽 수 10/10
지적   이번 바퀴 닫음 14(큰 것 3), 남음 6(큰 것 1), 원자료 대조로 받지 않음 2
검토   다른 계열 또는 사람 검토 R1에 1회
결정   R3로 갈지 사용자 결정
```

- 기준을 모두 채우면 멈춘다. 전체 문체 적용과 fact-check 대조를 한 번 하고 원고를 고정한다. 고정판의 경로와 해시를 승인기록과 현황에 적는다. 투고는 submission-package로 준비한다.
- 횟수 상한에 닿았는데 채우지 못하면 더 돌리지 않는다. 남은 큰 지적과 선택지(그대로 제출, 주장이나 범위 축소, 제출 연기, 상한 올림)를 사용자에게 보이고 결정을 받는다. 상한 올림을 고르면 1절대로 승인기록에 남긴다.
- 마감까지 남은 날이 한 바퀴에 드는 날보다 적으면 새 바퀴를 시작하지 않는다.
- 두 바퀴 연속으로 같은 큰 지적이 남으면 문장으로 풀리는 문제가 아니다. 문장 수정을 멈추고, 지적이 신규성, 비교군, 자명성에 걸리면 feasibility-gate(G0, G2, G3)로, 문제나 주장의 틀에 걸리면 problem-grill로 돌아간다. 어느 쪽으로 돌아갈지와 그 이유를 사용자에게 보이고 정하게 한다.

## 4. 지킬 것

- 없는 사실, 숫자, 인용을 만들어 지적을 닫지 않는다.
- 보고와 문서는 쉬운 한국어로, 평가는 숫자로 쓴다. 논문 본문과 식별자는 영어 그대로 둔다.
- 그 밖의 규칙(만든 쪽이 채점하지 않기, 에이전트 숫자의 재계산, 사용자만 하는 일, 파일 보이기)은 research-session의 공통 규칙을 따른다.
