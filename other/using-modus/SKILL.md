# using-modus

为当前任务补充项目知识和实现证据。先明确要理解、修改或判断什么，再选择足以支持该目标的正文与源码；已有证据充分时直接使用。仅在任务依赖当前项目事实时加载，不能因为会话位于已安装 Modus 的目录就自动介入。若任务实际进入实现修改，则由本 Skill 持有知识留存检查点，直到最终交付前完成语义影响判断。

> **核心不变量**：按任务渐进取证，关键实现结论回到当前源码；业务依据与工程要求共同影响决定和验收，但不扩大用户授权；修改任务在最终答复前完成一次静默的知识影响判断。

## 激活边界

需要理解、修改、评审或排查当前项目，或需要项目知识才能回答业务问题、形成方案或创作文档时，按需使用本 Skill。查询股票、一般问答、翻译用户给出的文字、仅整理用户已提供材料等不依赖当前项目证据的任务，不检查 `.modus/` 或 `modus/`，不检索项目知识，也不触发知识同步。

## C1～C6：按任务消费知识

六阶段是同一任务中的职责，不是六个 Skill、固定调用顺序或六份交付物。简单任务可合并，已有证据充分的动作可跳过，执行中发现新边界再回跳。按下表进入当前需要的章节；章节链接用于定位，只加载当前缺口需要的内容。

| 阶段 | 何时需要 | 当前职责 |
| --- | --- | --- |
| [C1 任务定界](references/consumption.md#c1-任务定界) | 任务开始，或目标、范围、修改意图变化 | 明确要解决的问题及影响结果的未知 |
| [C2 联合定位](references/consumption.md#c2-联合定位) | 尚不清楚所需业务或工程证据在哪里 | 定位主定义、适用规范与实现入口 |
| [C3 证据收敛](references/consumption.md#c3-证据收敛) | 已有材料尚不足以支持当前决定 | 补齐相关条件、例外与实现依据 |
| [C4 产出决策](references/consumption.md#c4-产出决策) | 需要把证据转为方案、解释或修改选择 | 明确保留与改变的行为、取舍和验收依据 |
| [C5 执行与验收](references/consumption.md#c5-执行与验收) | 决定可以落实，或结果需要验证 | 完成任务并核对关键预期是否兑现 |
| [C6 知识留存判断](references/consumption.md#c6-知识留存判断) | 本轮存在下述检查点覆盖的修改 | 判断长期影响，衔接必要的知识维护 |

阶段判断默认留在当前上下文中；仅关键方案、冲突或证据缺口需要向用户说明，不输出固定检查表、不新增执行卡或持久状态。[阶段衔接与恢复](references/consumption.md#阶段衔接与恢复)沿用已有证据；证据充分时直接完成交付，不为凑齐阶段追加工作。

## 知识留存检查点

1. 本轮实际开始修改项目实现、公开契约、运行配置或源码锚点时，在当前 Agent 上下文中保留一个待决的知识留存检查点。它不是文件、命令、扫描、报告、审批或持久状态，不改变原任务节奏。
2. 完成实现与验证后、输出最终答复前，以当前任务目标、实际编辑与差异为起点判断影响，包含本轮新增、删除、移动和已提交的修改；不能只看最后的工作区是否干净。复用本轮已读证据，必要时定向核对差异，不做固定全仓扫描。不接管原有脏改动或其他作者的并发修改；归属不清时先核对，不能把它当作无影响。
3. 本轮变化涉及长期职责、场景、接口、对象、规则、状态、依赖、资源或源码锚点时，加载 `modus-sync-knowledge`。影响尚不明确、出现未归属的新入口或找不到知识落点时，也交给它定向调查；已有正文未提及、候选为空或机械检查返回 `noop` 都不能证明无影响。是否需要写入由调查后的事实决定。
4. 只读理解、诊断、评审、纯知识编辑、无关文档修改及项目外任务不因此授权同步写入。格式或测试等调整只有确认不改变应维护的长期事实时才跳过，不能仅按文件类别排除。已证实无影响时静默结束，不加载同步 Skill、不运行固定检查、不输出 noop。

## 读取方式与边界

助手可直接使用宿主的文件读取与搜索能力，也可按需调用 CLI 获取有界候选。两条路径遵守同一消费协议，CLI 不是前提，也不替代语义判断。定位与取证按[共享检索说明](references/router-details.md#路由)；使用 CLI 时按[便利接口](references/router-details.md#便利接口)传递用途、解释结果并定向续读；规则的性质、适用性与落实方式见[约束使用说明](references/constraint-usage.md)。

自动消费只读本轮源码、用户材料和 canonical `modus/knowledge/`，不读取初始化分析缓存、不启动初始化、不改写知识；跨工作流的隔离范围与降级方式见[普通工作流边界](references/router-details.md#普通工作流边界)。维护仅在 C6 或明确维护请求的授权边界内进行。

用户明确请求创建或维护知识时，分别使用 `modus-init`、`modus-reinit` 或 `modus-update-knowledge`；材料用于当前任务不自动代表持久保存授权。显式要求更新 Modus 软件包时读[包更新说明](references/framework-update.md)。

## Git 提交信息

生成或润色提交信息时，读取 [提交信息约定](references/git-commits.md)，以拟提交的实际差异为依据，优先遵循用户与项目规范。此分支不授予 Git 提交、推送或改写历史的权限。
