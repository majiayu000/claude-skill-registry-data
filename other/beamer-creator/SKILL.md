# Beamer Creator

## 先确定制作契约

从用户材料和已有项目中确认以下信息；能从上下文可靠推断时直接推进，只在会实质改变结果时提问：

- 汇报类型、目标、听众和时长
- 输出语言、标题、作者、日期和画幅
- 是否必须保持源材料顺序与原文表达
- 是否已有模板、既有 Beamer 工程或需要同步的来源 deck
- 是否需要目录、附录、结束页、讲者备注和正式参考文献页

用户未指定时，默认中文、16:9、结论先行；短汇报按时长压缩，不把固定页数当硬规则。不要凭空添加用户没有要求的 appendix、总结、目录或结束页。

## 选择一种工作模式

### 1. 忠实转换

用于用户要求“按原文顺序”“不要重排”或输入已经是成熟提纲的情况。保持章节、段落和论证顺序，只做 Beamer 化压缩、分页和版式适配。

### 2. 汇报重构

用于用户更关心讲清问题而未要求原序的情况。按“问题与目标 → 方法/证据 → 结果 → 限制 → 结论”重组；不要把原文目录机械复制成 frame 标题。

### 3. 既有 deck 合并或同步

用于多个完成的 Beamer 工程、局部更新或来源同步。保留来源 section 的结构和措辞，只复制实际引用的资源；来源变化时只同步受影响 section 及新增依赖。执行前阅读 [references/merge-and-sync.md](references/merge-and-sync.md)。

若用户意图同时符合多种模式，以明确的“保持原样/允许重构”要求为最高优先级，并记录采用的模式。

## 模板策略

1. 已有 Beamer 工程或用户模板：就地保留其主题、宏和目录结构，除非用户要求改版。
2. 没有模板：复制 `assets/template/` 作为起点。
3. 内置模板允许修改内容配置：标题、作者、日期、语言、section 输入、目录开关和参考文献开关。
4. 不经要求不要改变主题、色板、页脚、字号体系或品牌元素。

内置模板目录：

```text
main.tex
config.tex
sections/
figures/
codes/
references.bib
```

正文放 `sections/`，图片放 `figures/`，代码片段放 `codes/`。文件名使用简洁、稳定、表达内容的英文名称；重命名资源后同步修改所有引用。

## 制作流程

### 1. 建立材料清单

- 识别主稿、补充材料、图片、表格、公式和文献来源。
- 有高质量笔记或讲稿时以其为主线，再回查原始材料补证据。
- 区分已核实事实、解释性推断和待核实来源；不得臆造引用元数据。
- 对既有 deck，先解析 `main.tex` 的输入关系和资源依赖，再决定复制范围。

### 2. 先写 frame map

在写 LaTeX 前列出每页的“结论标题、证据、版式、来源”。每个内容页只承担一个核心任务。页数由时长和讲解深度决定：短汇报优先保留关键问题、1--3 个主要证据、必要公式和结论；综述/教学可按 section 展开。

### 3. 写入内容

- 标题写成可复述的结论或明确主题，避免“公式 1”“图表分析”等机械标签。
- 普通内容页优先 3--6 个短要点；解释论证作用，不复制长段落。
- 图片放在首次讲解处；同页多图必须回答同一问题。
- 公式展示深度服从时长和听众：短汇报给定义、关键变量、适用范围和直觉；论文讲解保留关键中间步骤；教学型再完整推导。
- 内容超载时拆 frame，不用缩到不可读；`allowframebreaks` 主要用于参考文献等特殊页面。
- 代码 frame 使用适合模板的 verbatim/listings 方式并实际编译验证。

制作图像、公式、表格或代码页时阅读 [references/layout-patterns.md](references/layout-patterns.md)。处理引用时阅读 [references/citations.md](references/citations.md)。

### 4. 编译与修正

优先运行内置预检脚本：

```bash
python <skill_path>/scripts/build_and_check.py <project>/main.tex --clean --render
```

也可直接编译：

```bash
latexmk -xelatex -interaction=nonstopmode -halt-on-error main.tex
```

迭代阶段可省略 `--clean` 加速；修改字体、模板或引用链后以及最终交付前必须 clean build。按顺序处理：致命错误 → 缺失文件/字体/引用 → overfull → 视觉密度与对齐。不要把“成功生成 PDF”等同于完成。

### 5. 视觉验收

编译后必须检查 PDF 页面或 contact sheet，至少确认：

- 无空白脚手架页、遗留占位符、截断、重叠或不可读小字
- 标题、图片、公式和表格没有越界，连续页面尺寸变化合理
- 中英文和数学字体正常，引用可追溯
- 页面数量和用户要求一致；目录、附录和结束页均为显式选择

完整验收标准见 [references/visual-qa.md](references/visual-qa.md)。

## 交付要求

交付可复现的 `.tex` 源码、实际使用的资源和最终 PDF，并简要说明：采用的模式、页数、编译命令、检查结果以及任何仍待核实的来源。不要交付 LaTeX 中间文件或模板自带的陈旧 PDF。
