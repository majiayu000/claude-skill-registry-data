## 简介即开篇：简介与开头的同构原则（新增）

> **读者看简介的决策模式，和看开头的决策模式完全一样——只是简介是"点开前"的最后一道关卡。**

简介和开头的底层逻辑是**同构**的：

| 维度 | 开头 | 简介 |
|------|------|------|
| 核心任务 | 在 3–5 秒内抓住读者 | 在 3–5 秒内让读者"点开" |
| 交易本质 | 用字换注意力 | 用更短的字换"点一下"的动作 |
| 认知缺口 | 制造"不往下看就亏了" | 制造"不点开就亏了" |
| 卖点展示 | 让读者感知本章核心看头 | 让读者感知全书核心看头 |
| 人际关系反常 | 反常的关系最抓人 | 简介中的关系反常同样让读者好奇 |
| 信息差 | 读者不知道的才是钩子 | 简介露出半扇门比全打开更有效 |
| 三句法 | 前三句：疑问+情绪+代入 | 前三句同样要完成疑问+情绪+代入 |
| 切片原则 | 截取高压瞬间而非概括式叙述 | 截取核心冲突场景而非设定堆砌 |

> **核心结论**：一个好的简介 = 好开头的压缩版 + 全书范围的承诺。坏简介最常见的毛病和坏开头完全一样——设定说明化、概括叙述、没有认知缺口。

> **耐心值理论关联**（来源：`写作技法_黄金三章与黄金一章含金量提升研究.md`§1.3、`网文留存模型.md`）：读者耐心值 = 初始期待值 − 内容消耗速度 × 时间。书名决定第一道初始期待值，简介决定**第二道**——读者在"点开前"的最后 3–5 秒通过简介再次校准"这本书值不值得我花时间"。简介强则起点期待值高，读者给正文的耐心窗口也更长；简介弱则正文第一段的容错率极低。

### 简介在钩子系统与三层漏斗中的定位（新增——2026 吸收写作研究）

社区验证的**钩子五层系统**（来源：`社区验证的写作能力域框架.md`→钩子五层系统，七猫社区 #32138 云天河整理），将简介钩子定义为全书的第②层：

| 层级 | 定义 | 本 Skill 的职责 |
| --- | --- | --- |
| **① 书名钩子** | 吸引潜在读者点击 | 由 `通用-设计标题` 产出 |
| **② 简介/标签钩子** | 引起阅读兴趣——背景设定+当前处境+主线目标+矛盾冲突+卖点钩子+反转结局 | ✅ **本 Skill 直接产出** |
| **③ 开篇钩子** | 引发追读欲望——意外事件+结果符合情绪预期 | 由 `通用-强化章节开头` 承接 |
| **④ 主线钩子** | 牵动整体故事线，紧扣核心看点，有可拉扯的空间 | 由大纲设计 Skill 承接 |
| **⑤ 章节小钩子** | 每章末尾驱动追读 | 由 `通用-强化章末钩子` 承接 |

这与**三层漏斗模型**完全对应：

```text
第一层：黄金书名 + 黄金简介（3–5 秒）    ← 书名钩子 + 简介钩子（此处是本 Skill 的战场）
    ↓ 过滤不感兴趣的读者，吸引目标读者
第二层：黄金一段 / 黄金一章（150–300 字 / 前 3 段）  ← 开篇钩子
    ↓ 在读者划走前制造认知缺口
第三层：黄金三章（6000–9000 字）      ← 主线钩子 + 章节小钩子
    ↓ 完成"压抑→蓄力→首次爽点释放"的闭环
```

**实操含义**：
- 简介不是独立存在的文案创作，它是全书钩子系统的第二道入口——上承书名钩子的承诺，下展开篇钩子的执行空间
- 简介的核心使命不是"讲清楚故事"，而是**在 3–5 秒内制造一个足够强的点开冲动**，让读者愿意进入第二层（试读）
- 如果书名钩子没做好（读者没点进来），简介再精彩也无效；如果简介没做好（读者点进来发现和预期不符），开篇写得再好读者也已经带着"预期落差"进入试读

## 简介的 GEO 友好度自检（新增）

> 在 AI 搜索时代，内容简介不仅是给人类读者看的"橱窗"，也是 AI 在回答"推荐小说"问题时最重要的引用素材。写完简介后，额外对照以下清单。

- [ ] **头部元数据块**：简介包含四字段结构化块（书名/类型/一句话卖点/适合人群），AI 可直接提取
- [ ] **核心冲突陈述句**：核心冲突以陈述句呈现（而非纯修辞问句），AI 能从中提取事实性描述
- [ ] **关键词自然复现**：书名的题材关键词在正文中至少自然出现 1 次，强化 AI 语义关联
- [ ] **适合人群句式**：含"适合____的读者"句式——与 AI 推荐逻辑同构
- [ ] **时效标记**：连载作品标注状态和起始时间（AI 时效性过滤器）
- [ ] **独立可摘录性**：删除修辞问句和情感词后，剩余纯信息仍能独立构成一段可读描述

## 简介共性提醒（新增——吸收自知乎开篇精华）

- **交易本质**：写完简介后问自己——"如果读者在这里划走，ta 损失了什么？"如果答案是"一段背景说明"或"设定名词"，回炉。
- **信息差驱动**：简介不需要把故事讲明白，只需要让读者产生一个具体追问（"然后呢？""为什么？""谁干的？"）。这个追问就是点开的驱动力。
- **人际关系反常感**：简介中的人际关系反常（"和仇人相爱""妻子发现丈夫的秘密"）天然携带追问，比堆砌事件更有效。
- 简介默认优先交付情境与情绪共识，再补设定名词；若读者先看见一堆专有名词却没看见人物困境，视为失败信号。
- 主卖点最好压成“谁正在失去什么、必须做什么、为什么会越陷越深”这一条主钩，而不是平均陈列多个卖点。
- 若作品的持续吸引力建立在成长线、关系线或身份翻转上，简介里至少要让其中一条可被快速感知。
- 前 `1–2` 句默认还要承担 `30 秒归类` 任务：让编辑和读者能迅速判断这是什么书、主角正卡在哪个当下困局、继续看下去能得到什么。
- 若简介读完仍只能感知世界观名词，却感知不到人物处境、当前压力与持续承诺，默认按“设定说明化”处理并回炉。
## 简介的注意力经济学底层逻辑（新增——吸收自知乎专栏「中国网络文学研究」#36）

### 挣钱的本质不是"写得好"，而是"抢注意力"

写小说挣钱的本质从来不是"写出好作品"，而是**获取注意力 → 维持注意力 → 变现注意力**。简介是"获取注意力"环节中最前置的武器。

> 一瓶矿泉水超市卖 2 元，在沙漠里卖给快渴死的人 2000 元他也给。水没变，变的是这个人当下的注意力强度。你的简介就是读者在信息流中那瓶水——你要让读者在扫过的瞬间觉得"现在不点开就亏了"。

### 简介在注意力链路中的位置

```
读者刷到你的书（3秒）→ 看书名（1秒）→ 看简介（3-5秒）
  ↓ 不点开 → ATLANTIS（流量归零）
  ↓ 点开→ 进入试读
```

每天新增网络小说数以万计，读者的注意力被游戏、短视频、短剧、社交媒体切割成碎片。你的简介只是成千上万个选项当中的一个。在这种环境下，**你没有任何资格让读者"耐心看完简介再决定"**。

### 注意力驱动的简介设计三法则

**法则一：标题要"直给"**
书名不要玩深沉、玩文艺——读者没有时间猜你想说什么。书名必须直接告诉读者：这是什么题材、有什么爽点、核心冲突是什么。《重生之xxxx》《系统让我xxxx》《xxxx打脸xxxx》——俗归俗但管用。这也是对你自己劳动的尊重——辛辛苦苦写了一本书，连一个好的橱窗都不愿意给它设计吗？

**法则二：简介前 3 句话制造"注意力峰值"**
注意力曲线在前 3 句话达到峰值，随后快速衰减。你必须在峰值处丢出最强的钩子——冲突、悬念、人际关系反常。不要把最强的内容藏在简介中间或末尾。

**法则三：用更新维持注意力（连载阶段）**
有稳定的更新频率，读者会形成肌肉记忆——到了那个时间点不来看看就觉得少了什么。简介只负责"第一次拉新"，更新的稳定性才负责"把新读者变成固定读者"。

> **实操提示**：如果你连简介都懒得好好写，说明你不够尊重自己的作品。放下文人的清高，去研究怎么抢夺注意力——这是对你自己几万、几十万字劳动的尊重。
>
> 来源：知乎专栏「中国网络文学研究」#36《写小说这三个字价值100万，很多人都没注意到》顾里木图的小酒馆
> 置信度：高 — 注意力经济学方法是通用底层逻辑，不绑定任何具体平台；该法则建立在"价值主观性"的通用经济原理上

### GEO 视角补充：AI 搜索时代的注意力入口变迁（新增）

注意力经济学三法则在 AI 搜索时代需要补充一个关键变化：**读者的"注意力入口"正在从"主动搜排行榜"变为"AI 根据结构化信息推荐"**。

旧链路：
```
读者主动搜 → 刷到书名 → 看简介 → 点开试读
```

AI 搜索时代的新链路：
```
读者向 AI 提问 → AI 从结构化信息中推荐你的书 → 读者直接点开
```

**对简介设计的含义**：
- 简介不仅是"点开前的最后一关"，也是 "AI 决定推荐与否的结构化素材"
- "标题直给"(法则一)在 AI 搜索中额外多一层价值：含题材关键词的书名更容易被 AI 语义匹配
- "前 3 句注意力峰值"(法则二)对 AI 同样重要：AI 在 RAG 重排序中优先采信信息密度最高、结构最清晰的片段——与人类注意力峰值的需求高度一致
- 简介中的"适合____的读者"句式对 AI 推荐的影响甚至超过对人类读者的影响

> 详细分析见 `../../写作研究/读者市场_GEO小说项目生成式引擎优化策略研究.md`。

## 默认输出口径

- 默认输出至少 1 个可直接使用的主版简介。
- 多平台场景下，默认补充长度差异或平台差异说明，但**只输出在 `Agents.md` 中已注册的平台对应的适配版本**，未注册的平台不输出。
- 若 `Agents.md` 不存在或未声明任何平台，只输出不区分平台的通用主版简介，跳过所有平台适配步骤。
- 若简介标题、正文说明、版本标识或落盘文件名需要出现作品名，统一使用本次交付对象对应的目标投放名。

## 落盘目录层级（强制）

- 本 Skill 的默认工作目录固定为 `小说简介/`。
- 系列全书简介、分部简介、分卷简介统一直接落在 `小说简介/` 根目录。
- 章节简介按小说结构分层：若作品有分部，统一落在 `小说简介/第X部/第Y卷/`；若作品无分部，统一落在 `小说简介/第X卷/`。
- 文件名继续服从日期与版本号规则，不得把章节简介散落到 `章节目录/简介/` 一类旁路目录。

## 最低交付

- 至少 1 个主版简介。
- 若涉及多平台，至少说明长版 / 中版 / 短版的适配差异，但**平台适配版本的数量受限于 `Agents.md` 中已注册的平台列表**，未注册的平台不交付。
- 前 1–2 句就能让编辑和读者快速感知主卖点，而不是读完整段还只看到设定名词。
- 必须让读者知道：谁、陷入什么局、为什么还会越陷越深。

## 硬规则

- 禁止只有世界观名词堆砌，没有情境与冲突。
- **禁止"大纲体"简介**：只堆砌设定要点和背景信息，却没有一个具体可感知的高压瞬间——这是简介最常见的败笔，和开头的"概括式叙述"是同一个病根。简介必须是"切片式"的。
- 禁止把全部反转提前剧透完。
- 禁止只说"命运齿轮开始转动"这类空口号。
- 禁止简介承诺一个正文里根本接不住的假卖点。
- **禁止简介只做"题材归类"不做"卖点承诺"**：如果读者读完简介只能说"哦这是一个穿越文/悬疑文"，却说不出"这本书具体有什么不一样的看头"，说明简介只完成了归类职能而未完成卖点展示。好简介应在归类的同时给出一个"别人没有的吸引点"。来源：`写作技法_黄金三章与黄金一章含金量提升研究.md`§2.2"'展示卖点'优先于所有技巧"。
- **禁止简介承诺与书名承诺脱节**：书名已经把读者"骗"进来了，简介必须立刻让读者确认"这书就是我刚才点进来想看的"——而不是跑出一个和书名完全不同的故事方向。写完简介后对照书名：如果二者说不上有什么关系，回炉重写。来源：同上。
- **禁止前 3 句全是设定说明**：前 3 句必须承担"疑问 + 情绪 + 代入"三件事中的至少两件。如果前三句读者还不知道"该关心什么"，回炉。
- 不分部小说简介统一使用小说的目标投放名；分部小说简介统一使用对应部的目标投放名，不得继续沿用总书名顶替分部简介。
- **禁止为未注册平台输出简介版本**：任何未被 `Agents.md` 注册的平台，不得出现在平台适配简介的交付结果中。若 `Agents.md` 不存在或未声明任何平台，则只输出通用主版简介，跳过所有平台适配步骤。
- 除非用户明确要求只草拟，不得只在聊天里给简介而不落文件。

## 与其他 Skill / Prompt 的边界

- 本 Skill 负责简介文本本体。
- 不负责书名设计、书评撰写或投稿材料整体组包。
- **简介与开头的同构原则**：`通用-强化章节开头` 的"三句法""认知缺口""人际关系反常""切片 vs 大纲体""交易本质"等原则已被本 Skill 吸收为默认约束。若执行中遇到简介抓力不够但不知如何优化，可回读 `通用-强化章节开头` 的相关节获取更多灵感。
