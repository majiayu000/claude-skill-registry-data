# focused-work-gameframe

## When to Use

当需要进入高效、创造性的深度工作状态，并将工作体验从“压力”转化为“有挑战的游戏”时。description

## Core Logic

# 执行步骤

1.  **输入**：待完成的创造性/深度任务。
    **行动**：设定明确的“游戏”目标与规则。将任务分解为可在单一专注期内完成的小块，并为本次专注期设定一个具体的、可衡量的产出目标（如“写完文章大纲”、“调试完这个模块”）。
    **判断标准**：目标具体、可衡量，且与分解后的任务块匹配。
    **输出**：本次专注期的明确产出目标。

2.  **输入**：步骤1的产出目标。
    **行动**：设定专注“游戏”的时长。将本次专注工作时长设定为一个有挑战但合理的固定值（推荐4小时，新手可从1小时开始）。
    **判断标准**：时长固定，有明确的开始和结束时间点。
    **输出**：本次专注期的起止时间。

3.  **输入**：步骤1的产出目标、步骤2的起止时间。
    **行动**：执行“游戏”并沉浸。在设定的时间内，关闭所有干扰源（通知、无关网页），只使用与达成目标直接相关的工具，全身心投入以完成目标。
    **判断标准**：期间未处理与预设目标无关的事务。
    **输出**：专注期结束时的实际工作成果。

4.  **输入**：步骤3的实际工作成果、步骤1的预设产出目标。
    **行动**：进行“游戏”结算与反馈。
    - **IF** 实际成果达成或超越预设目标，**THEN** 给予自己明确的正面奖励或认可（如休息、小庆祝）。
    - **ELSE**（未达成目标），**THEN** 分析原因：是目标设定过高、干扰过多，还是状态不佳？记录原因，作为下次“游戏”规则调整的输入。
    **判断标准**：无论成败，都进行了客观复盘，并决定了奖励或调整策略。
    **输出**：复盘结论及对下次“游戏”规则的调整建议（如需）。

# 输出格式要求

向用户呈现一个已配置好的“专注工作游戏框架”：
1.  **游戏目标**：[本次具体的、可衡量的产出目标]。
2.  **游戏时长**：[本次专注的固定时长，如“1小时”]。
3.  **游戏规则**：列出为保障沉浸感必须遵守的规则（如“勿扰模式”、“只开必要文档”）。
4.  **结算机制**：明确达成目标后的奖励，以及未达成时的复盘问题列表。
