# 缺陷分级报告Skill

## 适用场景
缺陷管理环节,对测试发现的问题进行客观定级(P0-P3),撰写规范缺陷报告并跟踪闭环。

## 执行步骤
1. 确认缺陷事实:完整复现步骤、实际结果、预期结果、影响范围、出现频率。
2. 定级:按下述 P0-P3 标准客观定级,拿不准时与开发/产品共同确认,不单方拍板。
3. 撰写报告:一份报告只写一个缺陷,字段齐全(标题/环境/步骤/预期/实际/等级/附件)。
4. 关联追溯:关联用例编号、需求/AC 编号、所属模块,便于影响面统计。
5. 跟踪闭环:状态流转(新建→修复中→待验证→已关闭/重开),验证不通过必须重开。

## 分级标准
- P0:核心链路完全不可用、数据丢失或错乱、安全漏洞、资损,需立即修复并阻塞发布。
- P1:核心功能部分不可用且无可用绕过方案,发布前必须修复。
- P2:非核心功能异常,或存在可用绕过方案,随版本计划修复。
- P3:体验、文案、样式类问题,不影响功能使用,排期修复。

## 规范要点
- 缺陷必须可复现:附完整复现步骤、环境信息与证据;无法稳定复现的标注「偶现」+ 出现频率,不得隐瞒。
- 定级依据客观标准,禁止凭严重程度主观升级/降级;定级理由写在报告中。
- 结果如实呈现:修复未验证通过不得关闭缺陷;验证结果(通过/失败)如实记录。
- 标题格式统一:「模块 + 问题现象」,禁止「有个bug」类无信息量标题。
- 缺陷数据不得遗漏:即使不影响定级的轻微问题也要记录,不私下消化。

## 输出模板
```
## 缺陷报告
| 缺陷ID | 标题 | 等级 | 模块 | 关联用例 | 复现步骤 | 预期 | 实际 | 状态 | 负责人 |
## 缺陷分布统计(按等级/模块/状态)
## 待验证缺陷清单
```

## 自检清单
- [ ] 一份报告一个缺陷
- [ ] 复现步骤与环境完整
- [ ] 定级有依据且记录理由
- [ ] 状态与验证事实一致
- [ ] 关联追溯信息齐全
