# 上下文预算审计

进行只读、以证据为基础的上下文审计。先优化信息流，再压缩真正影响任务质量的指令。

## 盘点范围

只检查当前可访问且与问题相关的部分：

- 全局与仓库级 `AGENTS.md`；
- 用户级和仓库级技能，并区分元数据、正文与参考资料；
- 已配置的 MCP 服务、插件和暴露的工具 schema；
- 重复的规则、提示词、模板、记忆和上下文文档；
- 检索行为：整文件读取、重复搜索、重复来源和过大的工具输出。

Codex 对技能采用渐进加载：启动时主要暴露元数据，`SKILL.md`、references 和 scripts 按需加载。因此不能把所有已安装技能的正文都算作常驻上下文。

## 避免伪精确

能使用 tokenizer 时优先实测；否则必须标明是估算，并保持口径一致。英文或代码密集文本可粗略按字符数除以 4 估算，但中文和结构化 schema 可能明显不同。

分别统计：

- 常驻指令与工具 schema；
- 条件加载的技能正文与参考资料；
- 当前任务读取的内容和会话历史；
- 持久记忆或项目上下文。

报告数量、估算 Token、重复程度、触发范围和置信度。不得臆造上下文窗口大小、缓存行为或单工具开销。

## 诊断分类

- **保留**：高频、独特且简洁。
- **按需加载**：有价值，但只用于特定领域或阶段。
- **合并**：指令或来源内容明显重复。
- **退役候选**：过期、未使用、不兼容或已被完全替代。

重点识别：

- 描述过宽、容易误触发的技能；
- 全局与项目规则重复；
- 只用一两个功能，却暴露大量工具的 MCP；
- 尚未判断相关性就读取整份文档或整个仓库；
- 已经形成结论后仍保留大量重复原始输出；
- 同一事实同时存在于 Memories、`AGENTS.md` 和项目文档；
- 没有时点或失效条件的时效性记忆。

## 按收益排序优化

1. 停用或避免加载无用的工具/MCP；当前操作优先使用针对性连接器或 CLI。
2. 缩窄技能描述，合并重叠技能，但保留各自独有的工作流。
3. 保持 `AGENTS.md` 简短；把条件性细节放入技能 references 并按需路由。
4. 渐进检索：先查元数据和片段，评估相关性，再深读决定性文件或来源。
5. 在阶段边界，用紧凑摘要、证据账本或交接说明替代冗长原始历史。
6. 跨记忆层去重稳定信息。
7. 最后才做措辞压缩；不得牺牲安全、正确性、来源和授权边界。

## 记忆分层

- Codex Memories：稳定的用户偏好和有用的跨对话个人上下文。
- `AGENTS.md`：工作开始前就应生效的稳定仓库规则。
- 项目文档：已审阅的决策、架构、运行手册和权威知识。
- 任务笔记或证据账本：带时点、到期条件或关闭条件的临时状态。

不要把一次性纠正、未验证主张、密钥、凭据、私钥或敏感个人/财务信息写入持久记忆。修改任何持久上下文前先获得用户同意。

## 输出要求

先给出总开销估算和收益最高的三项调整，再提供紧凑明细、每项依据、预期节省区间、质量风险和可逆实施方案。

默认只读。除非用户明确要求，不删除技能、不关闭工具、不修改配置、不重写记忆。获准调整后，必须用同一口径复测并报告实际变化。
