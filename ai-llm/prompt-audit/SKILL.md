# Prompt & Instruction Audit

Чек-лист проверки промтов и инструкций: LLM-промты, goose-скилы, рецепты, `.goosehints`, агенты.

## Цель
Убедиться, что промт/инструкция ясны, полны, безопасны и соответствуют стандарту.

## 1. Ясность и однозначность
- [ ] Цель сформулирована явно
- [ ] Нет расплывчатых формулировок («сделай хорошо», «как обычно»)
- [ ] Термины определены или очевидны из контекста

## 2. Полнота
- [ ] Контекст и фон предоставлены
- [ ] Ограничения и рамки заданы
- [ ] Указан формат результата
- [ ] Есть примеры (вход → выход)

## 3. Структура
- [ ] Логичный порядок шагов
- [ ] Заголовки и списки используются
- [ ] Самое важное — в начале

## 4. Действенность
- [ ] Понятно, **что делать**, а не только «почему»
- [ ] Есть критерии завершения
- [ ] Шаги проверяемы

## 5. Безопасность
- [ ] Нет секретов и ключей в тексте
- [ ] Устойчивость к prompt injection
- [ ] Нет деструктивных действий без требования подтверждения

## 6. Тестируемость
- [ ] Есть пункты верификации
- [ ] Можно прогонять повторно с тем же результатом

## 7. Эффективность (токены)
- [ ] Кратко, без «воды»
- [ ] Нет дублирования

## Аудит goose-специфичных файлов

### SKILL.md
- [ ] frontmatter содержит `name`, `description` и `whenToUse`
- [ ] `description` — без `: ` либо в кавычках (иначе навык молча не загрузится)
- [ ] Контент сфокусирован на одной теме

### Рецепты (recipe.yaml)
- [ ] `title`, `description` + хотя бы один из `instructions` / `prompt`
- [ ] Каждый параметр определён и использован; optional-параметры с `default`
- [ ] Валиден через `goose recipe validate <file>`

### .goosehints / инструкции
- [ ] Приоритетное сверху
- [ ] Ссылки `@file.md` — осознанно, только для нужного контекста

## Формат результата аудита
- Группируй находки: **Блокер / Важно / Улучшение**
- Для каждой находки — конкретная правка
- Выдай итог: «Прошёл аудит» или список исправлений по приоритету
