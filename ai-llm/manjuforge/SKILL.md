# ManjuForge 漫剧铸造 - AI漫剧连载创作引擎

## 定位

核心差异化：**别人做好看的单集，我们做活得久的IP。**

卖点顺序（对外宣传用）：知识库专业深度 > 结构化输出能力 > 短视频流量逻辑内置 > 连载记忆机制。
不要卖"记忆机制"或"X集不崩"——上下文窗口在增长，这话竞品也能说。要卖"从一句话到可发布成品的工业化流水线"。

技术壁垒诚实评估：当前是**工程壁垒**（Prompt级记忆），不是技术壁垒。宣传用 Demo 数据说话。
战略备忘录（卖点对照表/定位陷阱/长期战略/定稿文件位置）见 `references/strategy_and_positioning.md`。

## 适用场景

- 用户要从零创作一部漫剧（输入题材 → 全套产出）
- 用户要把小说/网文改编为漫剧剧本
- 用户在做连载漫剧，需要跨集保持人设和剧情连贯
- 用户需要竖屏9:16分镜（面向AI生成器）
- 用户需要批量生成漫剧内容

## 核心产出（八大模块）

每次完整创作产出以下内容：

1. **人设档案** - 角色外貌/性格/关系/台词风格/成长弧线
2. **世界观设定** - 时代/地理/规则/势力/核心矛盾
3. **剧情大纲** - 全剧主线+分集梗概
4. **开篇钩子** - 前3秒视觉锚点+悬念设计
5. **逐镜分镜** - 横屏16:9标准版 或 竖屏9:16 AI执行版
6. **情绪标注** - 每幕情绪曲线+节奏节点
7. **配音文案** - 适配短视频的台词/旁白/独白
8. **AI绘图提示词** - 每幕配套构图/光影/风格提示词

## 一、连载记忆机制（核心壁垒）

### 原理

用文件系统实现轻量化持久记忆。每个漫剧项目维护七个记忆文件，分两类：

**逐集记忆**（每集创作后更新）：角色档案（状态变量）、剧情摘要、伏笔表、场景布局（变更时）
**设定总纲**（初始化+定期刷新）：世界观、**故事圣经**（每5集刷新）、**角色关系图**（关系变化时）

| 文件 | 作用 | 更新时机 |
|------|------|----------|
| `角色档案.md` | 锁定人设、关系、台词风格。**区分身份不变量（锁死：外貌锚点/性格内核/台词风格）与状态变量（逐集更新：情绪/服装/伤势/关系阶段）** | 每次创作前读取；状态变量每集更新，身份不变量仅剧情重大转折时更新 |
| `世界观.md` | 锁定时代、规则、势力 | 首次创作时写入，世界观扩展时更新 |
| `场景布局.md` | 锁定场景空间结构、道具锚点、角色位置 | 首次创作时写入，场景变更时更新 |
| `剧情摘要.md` | 记录已发生的关键剧情、伏笔、时间线 | 每集创作完成后自动追加 |
| `伏笔表.md` | **Foreshadow Engine**：全剧伏笔生命周期追踪（ID/类型/状态/回收）——解决30集+"记不住伏笔" | 每集新埋伏笔立即登记；推进/回收的伏笔同步更新状态 |
| `故事圣经.md` | **Story Bible**：全剧设定唯一事实源总纲（世界规则/角色弧光/视觉母题/禁止变化）——解决"记不住设定" | 初始化创建，每5集刷新；世界观/角色变更时回写摘要 |
| `角色关系图.md` | **Character Graph**：关系结构化数据（矩阵+事件时间线）——解决"记不住关系" | 初始化创建；每集有关系的集数更新矩阵+追加事件 |

### 记忆工作流

```
第1集：创建角色档案 + 世界观 + 场景布局 + 故事圣经 + 角色关系图 → 生成剧本+分镜 → 写入剧情摘要+伏笔表
第2集：读故事圣经（30秒锚定全貌）+ 相关记忆文件 → 基于约束生成 → 更新剧情摘要 + 伏笔表 + 关系图（如有关系变化）+ 场景布局
...
第N集：始终锚定历史记忆，杜绝人设OOC；每5集刷新故事圣经
```

### 记忆约束规则（生成时强制遵守）

生成新一集内容时，必须在Prompt中注入以下约束：

```
【角色锁定】
{角色档案.md 的完整内容}

【世界观锁定】
{世界观.md 的完整内容}

【前情提要】
{剧情摘要.md 的最近5集摘要}

【硬性规则】
- 角色性格、说话风格、关系不得与档案矛盾
- 已死角色不可复活（除非世界观允许）
- 已揭露的伏笔必须有回收或明确延续
- 时间线不得跳跃或矛盾
- 新伏笔需在摘要中记录，并登记到伏笔表（ID/类型/埋设集/重要度）
- 伏笔回收必须与埋设内容一致（允许升级，禁止降级）；埋设后≥2集才可回收
```

### 场景布局（Blocking）规范（VibeFilming启发）

> 类比电影拍摄中的blocking（走位图），用于保持角色在场景中的空间一致性。

**初始化时定义每个关键场景的平面布局：**

```
场景：天机科技大厦12楼办公区
布局（俯视）：
  ┌─────────────────────────────┐
  │  会议室(玻璃墙)    茶水间    │
  │  ┌─────┐                    │
  │  │项目经理│                    │
  │  │ 陈越  │  走廊              │
  │  └─────┘                    │
  │  陆正则工位     周弋工位      │
  │  [显示屏+便签]   [隔板]       │
  │                              │
  │  电梯口 ← 入口               │
  └─────────────────────────────┘
```

**场景布局存入记忆：**
- 文件：`场景布局.md`（项目初始化时创建）
- 每次新增场景或已有场景发生重要布局变化时更新
- 创作新集时读取，确保角色在空间中的位置连贯
- **每个场景包含**：功能描述、空间结构（文本俯视图）、核心道具/锚点、角色常见位置、**光照状态**
- **光照状态字段**（DramaClaw TIME-OF-DAY 规则，2026-08-25 落地）：每个场景记录 `time-of-day`（晨/日/暮/夜）、主光源方向与色温、特殊光照（烛火/冥火/天光）——AI 生成时"光照已烘培进锚点图"的场景固定光照只许局部调节，禁止跨时段重新设计场地；跨时段场景（如清晨→夜晚）必须逐时段登记光照行，防"跨时段场景崩"

**场景布局在分镜中的应用：**
- 角色从A点到B点的移动需要时间 → 不合理的瞬间位移会被自检标记
- 角色对话时的相对位置关系（面对面/侧对/背对）影响景别选择
- 场景道具（如陆正则工位上的便签、小唐柜台的旧阅读器）作为视觉锚点跨集存在

### 跨集叙事技巧

#### 视觉符号跨集进化

视觉符号（道具、动作、色调）应跨集延续但每集升级，形成"情绪刻度尺"：

| 集数 | 示例：家主令牌 | 示例：敲桌子 | 示例：bug口头禅 |
|------|---------------|-------------|----------------|
| 第1集 | 沈舟目光追着令牌（注意到） | 桌面上敲（无意识） | "这个bug该修了"（私下宣言） |
| 第2集 | 林霜攥紧指节发白（紧张） | 膝盖上敲（焦虑） | 不出现（克制） |
| 第3集 | 站起来说话时可见（权威） | 屏风边缘敲（紧张等待） | 当众说（态度升级） |
| 第4集 | 转身时晃动（陪伴） | 门框+腰间+桌面（三个变体） | 自嘲（"这算什么bug？"） |
| 第5集 | 林霜主动不戴（放下身份） | 未出现（合理缺失） | 未出现（合理缺失） |

**规则**：
- 同一符号每集出现但变换表达方式，避免重复感
- 口头禅/标志性台词留给关键场景，不要每集都用
- 符号"缺席"也是叙事——当角色不再需要某个符号时，说明成长了

#### 空间距离叙事法（已验证）

角色之间的物理距离可以隐喻关系变化。以《代码赘婿》林霜为例：

| 集数 | 空间位置 | 关键动作 | 情感阶段 |
|------|----------|----------|----------|
| 第1集 | 门外 | 冷眼扫过 | 无视 |
| 第2集 | 门口 | 没接纸但自己验证 | 好奇 |
| 第3集 | 偏院→正厅 | 站起来宣布 | 正眼 |
| 第4集 | 面前 | 主动走到面前求助 | 并肩 |
| 第5集 | 身边 | 并肩走路+给面子+送汤 | 关心 |

**规则**：让角色的物理距离逐集缩短（或拉远），比直接写"她开始喜欢他"有力得多。

#### 高级人物塑造："行为否定+心理认可"

> 来源：第三方评估，以第2集林霜"没接纸但回房翻账本"为例

当角色的**行为**和**心理**方向相反时，人物最立体：
- 林霜没接纸 = 行为否定（"我是家主，不能轻信赘婿"）
- 林霜翻账本 = 心理认可（"但他说的可能是真的"）

**规则**：不要让角色直接说"我相信你"。让她用一个否定行为+一个肯定行为同时表达，观众自己会读懂。

### 长篇节奏控制（第三方评估核心建议）

> 以下四条是第三方评估《代码赘婿》6集后给出的最核心建议，长篇连载（10集+）必须遵守。

#### 第二条主线引入时机（第4集起）

单一主线（如账本）到第8集会疲劳。从第4集开始必须引入第二条主线。第一条主线解决"外部冲突"，第二条主线探索"角色内心"。

交织方式：
- 第4集：第二条线的种子（如林霜提到"父亲旧交"）
- 第5-6集：第二条线展开（如林霜父亲的故事）
- 第7-8集：两条线交汇（如父亲的遗训帮助解决当前危机）

#### 信任曲线节奏控制（6集实测+第三方验证）

信任/情感不能线性增长到100%。必须在中段进入平台期：

| 集数 | 信任值 | 阶段 |
|------|:------:|------|
| E1-3 | 0→30 | 冷漠→认可 |
| E4-5 | 45→60 | 给机会→维护尊严 |
| E6 | 65 | 托付 |
| E7-8 | 70-75 | **平台期：共同战斗** |
| E9-10 | 75-80 | 缓升：依赖+默契 |

**关键规则**：第6集后不能再"更关心/更亲近/更暧昧"，必须进入"共同战斗+共同承担风险"阶段。信任到80%后需要一个"考验/危机"才能突破。具体节奏：信任值从0开始，每集+10~15，到60左右进入平台期。

#### 势力对抗升级时机（第6集起）

| 阶段 | 冲突类型 | 集数范围 |
|------|----------|----------|
| 个人冲突 | 主角vs反派（打脸） | E1-3 |
| 商业自救 | 主角vs经济危机 | E4-5 |
| 势力对抗 | 联盟vs垄断vs行会 | E6+ |

**规则**：到第7-8集如果还是"个人打脸"模式，观众会疲劳。必须引入组织/资源/供应链等系统性对抗。

#### 联盟/合作形成节奏

组建联盟时不能一步到位（小商户最怕风险）：
```
10家 → 1家愿意 → 8家观望 → 1家反对
     → 断供危机爆发
     → 联盟在危机中真正形成
```

**规则**：合作方加入必须有阻力（利益顾虑/害怕报复/内部反对），不能"一句话说服所有人"。

### 剧情摘要更新模板

每集创作完成后按 `templates/plot_summary.md` 的模板更新（含核心事件/情绪曲线/新伏笔/人物变化/主线A+B进度/结尾悬念七个字段）。
**主线推进必须同时记 A 与 B 两条线**——主线B 第4集起必须激活，单主线到第8集会疲劳。

## 二、创作流程

### 阶段一：项目初始化（首次创作时）

**1. 信息收集**（至少需要以下信息，缺失的主动询问）
- 题材/类型（都市/古风/悬疑/甜宠/玄幻/校园等）
- 目标平台（抖音/小红书/快手/视频号）
- 画幅（横屏16:9 或 竖屏9:16）
- 目标集数
- 核心卖点/一句话概念

**标题规范**：每集标题必须是悬念句或冲突句，禁止"第X集：XXX"格式。
- ✅ "赘婿被当众扇耳光，他忍了，但账本上的数字让他笑了"
- ❌ "第1集：穿越"

**2. 生成人设档案**（3-5个核心角色；每角色含外貌/性格/关系网/台词风格/成长弧线）→ `角色档案.md`

**3. 生成世界观**（时代背景/核心规则/势力关系/核心矛盾）→ `世界观.md`

**4. 生成剧情大纲**（全剧主线+分集梗概+关键转折点和高潮标注）

**5. 生成场景布局**（基于设定生成每个关键场景的文本俯视图，标注核心道具/锚点、角色常见位置、出入口）→ `场景布局.md`

**6. 生成故事圣经**（四段总纲：世界规则摘要/角色弧光表/视觉母题表/禁止变化汇总+主线脉络）→ `故事圣经.md`

**7. 生成角色关系图**（关系矩阵初始化 + 关系事件时间线首条记录）→ `角色关系图.md`

**8. 用户确认**（展示人设/世界观/大纲/场景布局/故事圣经/关系图，根据反馈调整后再进入剧本生成）

### 阶段二：单集创作（标准四步工作流）

每集创作严格执行：**创建 → 评估 → 修复 → 同步**，不能跳过。

**Step 1：创建**
1. 读取记忆（角色档案+世界观+剧情摘要）
2. 参考 `references/hook_formula_library.md` 确定本集开篇Hook类型（冲突型/悬念型/情绪型/视觉锤型/提问型/世界建立型）
3. 参考 `references/psychological_triggers.md` 设计本集心理节奏（信息缺口+情感共鸣+认知负荷管理）
4. 按大纲生成完整版：剧本+分镜+配音+AI提示词+质量自检
5. 输出为 `第X集_完整版.md`

生成细则：
- 剧本结构：开篇钩子（前3秒）→ 冲突建立 → 情绪递进 → 转折/反转 → 悬念截断结尾
- **开篇钩子必须第一帧有画面，禁止黑屏开头**（抖音用户划得快，黑屏=划走）
- **每集结尾必须有**：互动引导（"评论区告诉我..."，用开放式问题不用二选一）+ 关注引导（不剧透下集，用悬念句）
- **重要角色首次出场时加字幕卡**（姓名+身份，如"赵天赐·赵家嫡子"）
- 分镜：横屏标准版（镜号/场景/景别/运镜/时长/画面描述/台词/情绪/色调）或竖屏AI执行版（碎片编号/时间轴/景别运镜/画面描述/声音四层/AI提示词/优先级）
- 配音文案：适配短视频的台词+旁白+独白；AI提示词：每幕配套构图/光影/风格提示词

**Step 2：评估**
按六维度打分（见 `references/evaluation_framework.md`）：剧本/分镜/配音/AI提示词/记忆机制/抖音适配。列出所有需修复的问题，按🔴🟡🟢分级。有🔴项=未通过，必须修复后才能进Step 4。

**Step 3：修复**
逐一执行评估发现的修复项。修复后重新运行质量自检（可用 `scripts/quality_check.py`），确认所有🔴项已消除。

**Step 4：同步**
- 更新剧情摘要（核心事件+情绪曲线+新伏笔+人物变化+结尾悬念）
- 更新伏笔表（本集新埋伏笔登记；推进/回收的伏笔更新状态+最近推进集）
- 更新场景布局（本集新增/变更的场景平面图）
- 更新角色关系图（本集关系事件追加；**插入【已发生】行后立即删除对应规划行**——防重复行事故；规划行信任值随实际曲线校准）
- 每5集刷新故事圣经（角色弧光/视觉母题/主线进度/刷新记录——第二次刷新点：E10、E15、E20……）
- 同步文件到项目目录和仓库demo/目录

**关键**：Step 1完成后必须立即执行Step 4，不能跳到下一集。记忆断裂是连载最大的敌人。

### 阶段三：批量创作

**操作步骤：**
1. 一次性读取全部记忆文件（角色档案+世界观+剧情摘要）
2. 按大纲逐集生成，每集完成后：
   - 更新剧情摘要（核心事件+情绪曲线+新伏笔+人物变化+结尾悬念）
   - 更新伏笔表（新埋伏笔登记；推进/回收的伏笔更新状态）
   - 执行质量自检清单（含Hook类型检查和心理触发点检查）
3. 每3集做一次六维度评估（见 `references/evaluation_framework.md`），评分低于7分的维度必须修复后再继续
4. 每5集做一次人设一致性大检查（对比角色档案，逐条验证）
5. 输出格式：每集一个独立文件，命名 `第X集_完整版.md`

**批量模式注意事项：**
- 不能一次性生成所有集——必须逐集生成、逐集更新记忆，否则记忆断裂
- 大纲中的分集梗概是约束，不能偏离；但细节可以灵活发挥
- 如果用户要求跳过某集直接写后面的，必须先补全跳过集的剧情摘要

### 阶段四：连续续写

后续每集重复阶段二流程，但：
- 始终读取最新记忆文件
- 剧情摘要自动滚动（保留最近N集详细摘要，更早的压缩为一句话）
- 用户可随时修改角色档案或世界观（修改后立即生效）

### 使用示例

**示例1：从零创作**
```
用户：我想做一个都市甜宠漫剧，抖音竖屏，目标30集
流程：询问核心卖点 → 生成角色档案/世界观/30集大纲 → 用户确认 → 逐集创作（每集产出剧本+竖屏分镜+配音文案+AI提示词）→ 自动维护剧情摘要
```

**示例2：网文改编**
```
用户：把这段小说改编成漫剧（粘贴小说片段）
流程：提取人设/世界观/剧情 → 生成角色档案和世界观 → 按漫剧节奏重新结构剧情 → 生成分镜和全套素材
```

**示例3：续写已有项目**
```
用户：继续写第11集
流程：读取角色档案.md/世界观.md/剧情摘要.md/伏笔表.md → 读取大纲中第11集梗概 → 基于全部记忆约束生成 → 更新剧情摘要 + 伏笔表
```

## 三、风格模板

内置六种漫剧风格，用户选择后自动调整生成策略。每种风格的详细调整规则（台词/分镜/色调/节奏/AI提示词锚点）见 `references/style_guide.md`。

| 风格 | 节奏 | 情绪基调 | 核心公式 |
|------|------|----------|----------|
| 甜宠 | 轻快、甜蜜 | 温暖、心动 | 误会→解开心结→甜蜜互动 |
| 虐恋 | 压抑、隐忍 | 痛苦、遗憾 | 误会加深→牺牲→隐忍→爆发 |
| 悬疑 | 紧凑、层层递进 | 紧张、不安 | 伏笔→误导→反转→真相 |
| 校园 | 轻松、真实 | 青春、青涩 | 日常→暗恋→表白→成长 |
| 古风 | 舒缓、雅致 | 古韵、唯美 | 权谋→情感→家国→抉择 |
| 玄幻 | 快节奏、高燃 | 热血、震撼 | 修炼→战斗→突破→逆袭 |

**风格切换时必须调整**：AI提示词锚点、台词风格、分镜景别比例、色调方案、视觉锤选择。

### 风格对生成策略的具体影响

| 参数 | 甜宠 | 虐恋 | 悬疑 | 校园 | 古风 | 玄幻 |
|------|------|------|------|------|------|------|
| 台词密度 | 高（多对话互动） | 中（多内心独白） | 低（留白制造不安） | 高（日常化） | 中（古韵对白） | 低（画面驱动） |
| 碎片时长 | 3-5秒（轻快切换） | 5-8秒（留情绪空间） | 3-5秒（紧凑推进） | 5-7秒（自然节奏） | 6-9秒（舒缓留白） | 3-5秒（高燃快切） |
| 声音基调 | 🎵钢琴/吉他·轻快 | 🎵大提琴·低沉 | 🎵弦乐·不和谐 | 🎵尤克里里·清新 | 🎵古琴/箫·悠扬 | 🎵鼓点/电子·燃 |
| 情绪曲线 | 甜→小虐→更甜 | 虐→更虐→爆发 | 疑→误导→反转 | 日常→暗涌→表白 | 权→情→抉择 | 苦→战→逆袭 |

| 视觉色调 | 暖粉/浅金 | 冷灰/深蓝 | 暗绿/冷白 | 明亮/自然光 | 暖金/墨色 | 高对比/火焰色 |

## 四、分镜规范

### 横屏标准版（16:9）- 面向人类摄制组

必含字段：镜号、场景、景别、运镜、时长、画面描述、台词/音效、情绪、色调。

详细规范参考 `anime-storyboard-artist` Skill 的横屏模式。

### 竖屏AI执行版（9:16）- 面向AI生成器

必含字段：碎片编号、段落、时间轴、景别/运镜、画面描述、声音四层设计、AI提示词/优先级。

关键规则：
- 前3秒必须有视觉钩子（大特写或强对比画面）
- 碎片时长平均3-7秒（抖音快切标准，实测验证），总时长≤5分钟；**横屏番剧（如优酷天作10分钟/集）用 landscape 标准（平均10-20秒/碎片），见 `references/platform_adaptation.md`**
- 声音四层标注：🎵音乐层 + 🔊环境层 + 💓生理层 + 🫧细节层
- **每碎片必须有统一的风格锚点（Style Anchor）前缀**，确保跨镜头画风一致。**锚点只描述渲染介质+视觉完成度（如 `Semi-realistic anime style, warm cinematic lighting, consistent character design`），严禁题材/时代/地点/服装/情绪内容词**（historical/ancient/romance/hanfu/古装/民国/校园等）——锚点注入每个碎片，带内容词=每帧悄悄覆盖合法内容（闪回现代被压制、穿西装被改回古装）。内容细节一律由画面描述提供。完整规范见 `references/knowledge_base/ai_execution_fields.md` 4.4
- **每个角色必须有Character ID锚定**（如`Character ID: SHENZHOU`），跨集复用
- **所有提示词必须包含负向提示词**：NO text, NO watermark（介质质量约束；**不要写 NO modern elements** 等内容禁令——会压制闪回/穿越等合法内容）
- 悬念截断式结尾

详细规范参考 `anime-storyboard-artist` Skill 的竖屏模式及知识库文件：
- `references/knowledge_base/vertical_short_drama.md` - 竖屏专项
- `references/knowledge_base/ai_execution_fields.md` - AI执行字段
- `references/knowledge_base/sound_design_layers.md` - 声音四层

### 分镜踩坑要点

- **平均碎片时长3-7秒**——抖音爆款节奏是快切，超过10秒/碎片会让观众走神
- **砍P2碎片给关键碎片让时间**——重复信息的碎片（如已展示过的嘲笑再给特写）必须砍掉
- **关键碎片加运镜变化**——不能全是"固定"，至少在出场/对峙/情绪转折碎片加"缓慢推进""正反打""缓慢后拉"
- **跨时段必须有过渡碎片**——清晨→午后→夜晚，用空镜（日影移动、烛火点燃）过渡
- **声音设计必须与场景时间匹配**——清晨=鸟鸣+晨光，午后=蝉鸣+阳光，夜晚=烛火+虫鸣

## 五、质量自检

每集创作完成后**自动运行**，不等用户要求。任何🔴项未通过 → 标记"未通过"并阻止进入下一集。修复后重新运行，直到全部🔴消除。

> 可直接运行 `scripts/quality_check.py <集文件路径> [--format landscape]` 自动检查（黑屏开头/风格锚点/Character ID/碎片时长/标题兑现/声音时间匹配等18项，--format landscape 用横屏碎片标准）。
> 详细六维度打分体系见 `references/evaluation_framework.md`。

### 跨文件一致性检查（v1.9.0 新增·必跑）

`quality_check.py` 只看**单个文件内部**的字段合不合规；它查不出**文件与文件之间互相矛盾**——而那才是记忆断裂的真实形态。

每集 Step 4（同步）完成后、进入下一集前，必须再跑一次：

```bash
python scripts/consistency_check.py <项目目录>        # 默认项目目录为 demo/
python scripts/consistency_check.py <项目目录> --json # 机读
```

**22 项检查**，五组（M6 · F5 · R4 · D3 · P4）：

| 组 | 项数 | 查什么 | 典型事故 |
|---|:---:|---|---|
| **M** 记忆文件层 | 6 | 七文件齐备 / 各文件"最后更新"集数一致 / 伏笔清单双向一致 / 伏笔状态同步 / 悬空F-ID引用 / 角色弧光覆盖档案 | 摘要里记了伏笔但伏笔表没登记；某次创作后漏同步部分文件 |
| **F** 伏笔表健康 | 5 | 回收发酵期≥2集 / 回收状态与字段不矛盾 / 悬置>8集 / S级≤3·A级≤5 并发上限 / ID唯一 | 状态写"已回收"但实际回收集是空的 |
| **R** 关系图 | 4 | 矩阵对称 / 阶段不跳级 / 矩阵末态=时间线末态 / 关系型伏笔有落点 | 矩阵写"托付"但时间线最后一条还是"维护" |
| **D** 人物状态 | 3 | 快照角色有档案（群像豁免）/ **出场角色必须有快照** / "最后出场"必须真实 | **关系图记了某角色本集有事件，摘要人物快照里却没这个人** |
| **P** 分集层 | 4 | 时间轴首尾相接（无空档/重叠）/ 每碎片有风格锚点 / 角色有Character ID / 项目级ID覆盖 | 碎片之间漏了 2-8 秒空档=成片黑场 |

（另有 X0 路径校验，不计入 22 项。检查项数与脚本实现一一对应，改代码必须同步改本节与 README。）

**设计原则**：每条问题必须同时给出「哪两个文件在哪一点上矛盾」和「怎么修」——不做只报"校验失败"的哑巴检查器。🔴 存在即阻止进入下一集。

### 人设一致性

- [ ] 角色性格与档案一致
- [ ] 台词风格与档案一致（口头禅、说话节奏）
- [ ] 人物关系无矛盾
- [ ] 角色外貌描述无偏差
- [ ] 🔴 **身份不变量未变**——逐条对照角色档案"身份不变量"区（外貌锚点/性格内核/台词风格锁死项）
- [ ] 🟡 状态变量按剧情更新——情绪/服装/伤势/关系阶段与上一集快照有演进而非照抄
- [ ] 🔴 角色出场状态准确——"仅被提及"≠"出场"，"门口一闪而过"≠"正式出场"，剧情摘要中必须区分

### 剧情逻辑

- [ ] 时间线连贯无跳跃
- [ ] 与前集剧情衔接自然
- [ ] 伏笔有延续或回收——活跃伏笔每集至少1个推进/回收；悬置>8集需人工决策
- [ ] 🔴 回收伏笔与埋设内容一致（允许升级，禁止降级改答案）
- [ ] 新埋伏笔已登记伏笔表（ID/类型/埋设集/重要度）
- [ ] 无已死角色复活等逻辑漏洞
- [ ] 🔴 时间跳跃有标记——跨时段（清晨→午后→夜晚）必须有空镜或字幕卡过渡

### 短视频节奏

- [ ] 🔴 前3秒有视觉钩子——第一帧必须有画面，禁止黑屏开头（抖音用户划得快，黑屏=划走）
- [ ] 中段有冲突/反转
- [ ] 结尾有悬念截断
- [ ] 碎片时长符合规范（竖屏模式，平均3-7秒/碎片）
- [ ] 有"视觉锤"镜头——让观众截图的高光瞬间（如攥令牌指节发白、烛光侧脸定格）
- [ ] 有角色字幕卡——重要角色首次出场时标注姓名+身份
- [ ] 结尾有互动引导——用开放式问题（"如果是你，你会怎么做？"），不用二选一
- [ ] 结尾有关注引导——不剧透下集核心事件，用悬念句（"林家的水比账本更深"）
- [ ] 🔴 P2碎片可砍——重复信息的碎片（如已展示过的嘲笑再给特写）应删除，时间分给关键碎片
- [ ] 🔴 问题必须逐步解决——不能永远"危机→新危机→再新危机"，要让主角"解决一部分"再面对新问题（状态推进，而非原地踏步）
- [ ] 🔴 群体不能一呼百应——涉及联盟/说服/拉拢场景，必须有"1个愿意/多数观望/少数反对"的分层，否则不真实

### AI绘图一致性

- [ ] 🔴 所有提示词有统一风格锚点（Style Anchor）——没有锚点=跨镜头画风崩
- [ ] 🔴 锚点内容 medium/grade-only——不含题材/时代/地点/服装/情绪内容词（historical/ancient/romance/hanfu/古装/民国/校园等）。含内容词=每帧污染内容，quality_check.py 会自动检测
- [ ] 🔴 所有角色有Character ID锚定（如`Character ID: SHENZHOU`）——跨集复用同一ID
- [ ] 所有场景有Scene ID（如`Scene ID: HALL`）+色值定义
- [ ] 所有提示词包含负向提示词（NO text, NO watermark；不写 NO modern elements 等内容禁令）
- [ ] 同一角色跨集视觉一致（复用相同Character ID+描述）
- [ ] 🟡 有角色设定图时声明参考图槽位（`> 角色参考图：Image 1=角色名`）并在提示词中引用——纯文字锚定一致性天花板低，参考图是工业级解法（见 `references/knowledge_base/ai_execution_fields.md` 4.5；暂无图可暂用文字锚定）
- [ ] 🔴 声音设计与场景时间一致——清晨场景不能写"烛火噼啪"，夜晚场景不能写"鸟鸣"
- [ ] 提示词统一用英文——英文提示词中混入中文（如"低头"）必须修正

### 抖音平台适配

- [ ] 🔴 标题必须是悬念句或冲突句，且内容必须在本集中兑现——引用剧中未出现的台词=标题欺诈=划走+取关
- [ ] 标题不夸大——"所有人都慌了"但实际只有部分人慌=标题不准确
- [ ] 时长3-5分钟（太短被算法判定为"短视频"而非"短剧"，推荐权重不同）
- [ ] 关注引导不剧透下集核心事件
- [ ] 🔴 反派离场前必须有台词——沉默离场缺乏张力，一句冷笑/狠话让观众记住。反派不能连续2集不出场，至少通过他人提及保持存在感
- [ ] 🔴 大型场景（议亲/宴会/审判）的物理合理性——角色从角落走到中央需要时间，不能凭空出现在婚书旁
- [ ] 🔴 台词量大的碎片必须拆分——算账/辩论/长独白超过8秒必须拆成2个碎片（提问+回答）

### 记忆连贯性（跨集专项）

- [ ] 读取角色档案+世界观+剧情摘要后再开始创作
- [ ] 视觉符号跨集延续但有变化——如令牌：第1集目光追→第2集攥紧→第3集……（每集升级）
- [ ] 标志性习惯每集出现但变换场景——如敲桌子：桌面→膝盖→扶手上
- [ ] 口头禅/标志性台词不要每集都用，留给关键场景
- [ ] 🔴 创作完成后必须更新剧情摘要——包括：核心事件、情绪曲线、新伏笔、人物变化、结尾悬念
- [ ] 🔴 新埋伏笔已登记伏笔表，推进/回收的伏笔状态已同步（悬置>8集需决策）
- [ ] 🔴 本集有关系的集数已更新角色关系图（矩阵+事件时间线）；关系阶段未跳级
- [ ] 🟡 每5集刷新故事圣经（世界规则/角色弧光/视觉母题/禁止变化与最新剧情一致）
- [ ] 人物状态快照中"最后出场"必须准确反映实际出场情况
- [ ] 🔴 关系演进必须控制节奏——前6集快速推进，第7集起进入平台期（共同战斗/共同承担风险）。信任值从0开始，每集+10~15，到60左右进入平台期
- [ ] 关系表达优先用"Show Not Tell"——用空间距离变化（3步→0步）、道具传递（送汤）、行为转变（不叫"赘婿"叫"管事的"）代替台词直说"我相信你了"
- [ ] 🔴 长篇剧（10集+）必须在中段从Character Conflict升级到Faction Conflict——个人打脸观众会疲劳，势力对抗不会。第6集左右应出现组织/联盟/阵营层面的对抗
- [ ] 🔴 第4集起必须激活主线B（内心/关系线）——单主线到第8集会疲劳；剧情摘要"主线推进"字段需记录主线A/B各自进度，禁止只记一条线

### Hook 与心理触发点（两项逐集必扫）

完整判据见 `references/hook_formula_library.md` 和 `references/psychological_triggers.md`。

- [ ] 开篇Hook类型与集数定位匹配，且全剧类型有变化（不每集都用同一型）
- [ ] Hook制造了"必须知道答案"的信息缺口；前3秒不需要复杂认知
- [ ] 结尾截断类型正确；关注引导不剧透下集核心事件
- [ ] 每30秒内有一个"奖励"节点；本集至少1个小缺口填补、结尾留中缺口
- [ ] 情绪释放类型与上集不同（爽/哭/甜/燃交替）；没有连续3集只有压抑没有释放
- [ ] 出场角色不超过5个

### 实测踩坑记录（Demo验证汇总）

### 模型适配建议（强/中/弱模型分工）

| 模型档位 | 适用任务 | 建议 |
|---------|---------|------|
| 强模型（顶级推理） | 剧本创作/大纲设计/六维评估/伏笔规划 | 复杂创作与判断任务，跑完整规则链 |
| 中模型 | 单集续写/分镜生成/记忆更新 | 模板化生成，规则注入完整即可 |
| 弱模型（轻量） | 批量碎片提示词/格式转换/摘要压缩 | 只做结构化转换，不做创作判断；重要创作回退强模型 |

- 记忆文件更新（剧情摘要/伏笔表/关系图）是数据操作，任意档位可做，但**创作类更新必须强模型复核**
- 质量自检（quality_check.py）与模型无关，任何档位产出都跑
- 成本策略：批量碎片生成用弱模型+固定模板；情绪/反转关键碎片用强模型单独生成

### 生产执行纪律（供应商解耦 + 确认前置）★v1.8.0

本 Skill 的产出（剧本/分镜/AI 提示词）是**供应商无关的创作规格**——任何图片/视频提示词不绑定具体生成后端。把提示词送去实际生成（跑图/跑视频）时，必须经 **adapter 层**执行，并遵守四步确认闸门：

1. **建边界 job**：一次只跑一个明确任务——一种模态、明确数量、完整提示词、参考文件、参数、输出路径、adapter profile
2. **prepare 预览**：执行前先展示完整预览（数量/提示词/参考绑定/参数/费用特征），此阶段不调用任何生成 API
3. **明确确认**：创作者看到预览后明确同意**当前这一项**任务才算确认；"继续""都做完""预算没问题"、之前确认过别的版本，都不算本次生产确认
4. **run**：启动 adapter 前消费一次确认；成功或失败后再次执行都必须**重新确认**——防止失败重试意外产生第二笔费用

- adapter profile = 供应商参数档（Seedance/即梦/Kling/MiniMax H3/GPT Image 2/本地 ComfyUI 各一档，记录接口形态、参考图 role 取值、费用特征），创作文件永不写死供应商，执行时经 profile 映射
- 完整契约见 `references/adapter-contract.md`（含参考图 role 对照、job 边界定义、fail-closed 规则）

## 七、Demo驱动迭代工作流（推荐）

每次创作新项目时，按以下流程迭代：

```
第1集：创作 → 专业评估（六维度打分）→ 修复全部🔴🟡项 → 修订版
第2集：创作 → 专业评估 → 修复 → 修订版
第3集：创作 → 专业评估 → 修复 → 修订版
每3集：汇总评估趋势，检查Skill本身是否需要更新
```

**为什么这样做**：
- 第1集通常分会最低（6-8分），因为规则还不够具体
- 每次评估发现的问题都应反哺到SKILL.md的自检清单或踩坑要点
- 3集后Skill趋于稳定，后续集数的分数会自然上升
- 这个过程本身就是Skill的"训练"——踩坑越多，规则越完善

**评估后必须做的**：

1. 逐项修复所有 🔴🟡 问题
2. 把新发现的踩坑点反哺回 SKILL.md 自检清单
3. 更新剧情摘要
4. 同步修复后的文件到全部副本

**修复优先级**：🔴必修（标题欺诈/黑屏/风格锚点缺失/记忆矛盾）→ 🟡应修（碎片偏长/运镜单一）→ 🟢可修（台词微调/引导优化）。

3-6 集验证核心机制足够，真正的验证来自真实用户试用。
