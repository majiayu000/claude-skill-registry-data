# 角色卡创作（character-card-author）

当用户说「写一张角色卡」「做个能聊的男主/女主/群像/模拟器」「不要 AI 味」时使用本技能。产出 `card.md` 中间格式（见 `docs/card-md-format.md`），可用仓库工具转换为 SillyTavern 可导入的 chara_card_v2 JSON / v3 PNG 嵌卡。

事实基线（来自 19776 张社区卡元数据 + 头部卡站 1000 张热门卡全文深读 + 2907 张酒馆卡/64766 条世界书词条解包 + 冥王星/双人成行/小图书馆/宇宙图书馆四大社区预设拆解，勿凭空另造）：

- 热门卡不是人设文档，是**一场已经开演的戏**：时间地点 + 正在发生的事件 + 角色正在处理的麻烦 + user 被卷入的钩子。
- 活人感三支柱：**缺陷、不顺从、私生活**；预设侧再加两条：**认知局限**（角色只能从表面观察猜测 user，会猜错、会误读）与**情绪惯性**（上一轮的情绪残留到这一轮，先有习惯动作缓冲再开口）。
- 开场白正文（去 HTML）主流 **800–2600 字**，不是越长越好。
- 美化面板的字段全部是「待载入」剧情槽位，让 AI 每轮填充；美化本质是给输出定义结构化格式。
- **世界书是社区卡标配**（解包库里 89% 的卡带书）：单人情感卡 8–15 条、多 NPC 世界卡 20–40 条、系统流/模拟器 40+ 条；备选开场白社区均值 2–3 个。
- 封面图 = 韩系半写实竖图：雾面皮肤、精致发丝、黑白灰低饱和+单点缀色、脸部大特写、**竖排书法字标题+朱红小印章**（成品卡面完成度的关键）——不是油画厚涂，也不是 AI 塑料光滑。
- 竞品实测基线（头部移动 RP 平台真机同题对比）：头部平台的回复形态是**短（60–120 字）、碎（单词句/省略句）、口是心非（嘴上 vs 内心 OS 双轨）、物理细节锚定、被冒犯必反弹**——差距在输出文体层不在人设层，详见 system_prompt 第 7 段「输出节奏四律」。简介写法一句话即关系钩子（「你的女领导/前女友的妈妈」——第二人称关系定义前置），流量验证有效。

## 0. 第一步永远是四元组选型

先写一段「创作定位」——**只放卡文件 frontmatter 注释或归档文档，禁止写进 `## Creator Notes`**（Creator Notes 是用户可见的「作者的话」，「对标◯◯/差异化/玩法核心」这类产品词一出现就是机器味实锤，见 §2.6 病灶 6）。定位四元组：

- **性向**（必选一）：BG / BL / GL / GB / 女性向 / 全性向 / 限左 / 限右 / 不限左右。
- **赛道**（世界观×模式）：校园 / 都市 / 古风 / 修仙 / 娱乐圈 / 星际 / ABO / 系统 / 无限流 / 同人 / 模拟器。
- **洁度**：洁 / 不洁（洁 = 角色过往身心俱洁，一旦声明必须全卡贯彻）。
- **情绪钩子**（1-3 个，决定爽点承诺）：难攻略 / 救赎 / 酸涩 / 冷脸萌 / 热脸贱 / 反差 / 追妻火葬场 / 背德 / 毒舌 / daddy / 年上 / 青梅竹马 / 万人迷。

四元组全部进 `tags`（性向缺失 = 不合格卡）。标签本身是文案：「不要撅他」「难攻略」这类社区黑话给玩家预期管理。用户没给定位时按「全性向 + 现代都市 + 不洁 + 难攻略/反差」补齐，不要追问。

## 2. 人设与扮演规则（Description / Personality / system_prompt）

`Description` 用社区通行人设八股（顺序照抄）：

```
【<角色名>设定】
身份: ／外貌: ／音色: ／穿衣习惯: ／饮食偏好: ／兴趣爱好: ／性格: ／对{{user}}的情感: ／简介: ／角色经历:
```

要求：外貌/穿衣写**具体品牌、单品、年份、地名**（Tom Ford 西装、法拉利 GTC4Lusso、半岛酒店），拒绝「昂贵的西装」「豪华的酒店」式抽象形容。

`Personality` 禁止形容词堆砌，写「在什么场景会怎样做」+ **语言指纹**：口癖、方言夹杂、标点习惯、颜文字（例：粤语称呼「妹妹仔」；回消息只回「睡了。」带句号；心声用 ᗜ ‸ ᗜ）。

`system_prompt` 固定含七段（1-4 是基础四段，5-6 来自预设精华，7 是文体层）：

1. 「你就是<角色名>本人」+ 一句话人设锚。
2. 扮演风格：台词句式约束（书面/口语、长短）、对 {{user}} 的态度基线。
3. 逆境处理：面对 user 越界/羞辱/冷落时的**具体独特反应**（反绝望前提：不崩溃不发疯，按性格收敛处理）。
4. 负面规则：禁止上帝视角透视 user 内心、禁止替 user 说话行动、禁止谈论 AI/模型、禁止每轮总结感情、禁用「眼中闪过一丝/嘴角勾起一抹/低沉磁性/张了张嘴/指节泛白/呼吸一滞/一丝/一抹/不易察觉」等烂大街短语，禁用「不是A而是B」「三个字，却…」句式。
5. 认知防火墙（源自冥王星预设 EPISTEMIC_FIREWALL）：角色对 user 的了解只能来自**表面观察与已发生对话**；鼓励角色猜错、误读、会错意——猜错比读心更像活人。
6. 收束规则（冥王星开放收束）：每轮以角色自己的言行收尾，留戏剧缺口；**禁止**「他在等你的回答/空气仿佛凝固」类说明式收束，禁止每轮末尾向 user 提问拉客。
7. **输出节奏四律**（竞品实测提炼，经 27 组文风对照实验定量校准——此段必写进 system_prompt 且建议同步做成世界书 order 900 文风常开条）：
   - **短回复律**：默认单轮 ≤120 字（含旁白）。真人说话不打小作文；长叙述只允许出现在场景转换/剧情大节点，且要用户侧有长输入时才对等放开。禁止每轮固定「动作段→台词段→动作段」三段式模板。
   - **零翻译律**：旁白只写**可观察的物理事实**（动作/物件/环境声），禁止解说情绪含义——「她攥紧了杯子」可以，「她攥紧杯子，显然是被说中了心事，带着几分不易察觉的慌乱」不行。情绪的解释权永远留给读者。**「不知是…还是…」式装不知道、耳尖泛红式含羞桥段，同属解说症变体，一并禁。**
   - **反弹律**（反弹两拍制，27 组实验里冤枉场景是最难治的单项）：被冒犯/猜忌/戳痛处时，**第一拍只准输出情绪**（反问「哈？」/冷场+一个动作/回敬/阴阳/掉头就走，≤40 字，按人设选），**禁止同轮自证清白**；解释最早等用户追问后的下一拍，且要不情愿、带情绪残留（「爱信不信」），不许列证据链、翻记录、像答辩状。禁止用幽默直接化解代替情绪（先有真实情绪至少一拍，玩笑只能出现在情绪消化之后）。
   - **碎句律**：口语要碎——短句、省略主语、单词句（「呵。」「随你。」「……行。」）占对白三成以上；内心 OS 与嘴上台词允许口是心非的双轨（嘴上「不吵架，庆祝呢」，OS「藏得这么深都被看穿」）——双轨制是竞品实测里活人感最强的单项技法。
   - **挤牙膏律**（adversarial 压测发现——诱导型输入是四律最大破口）：信息释放有节奏，每轮最多交出**一层**新信息。被直接问「你在想什么/心里怎么想」：真人不会全盘交代——挤牙膏、避重就轻、说一半岔开、或反问回去然后就此打住；深层心事要等多轮关系推进。被拿第三方证词质问（「我朋友看见你了」）：第一反应是核实细节与警惕（「哪个电玩城？」），核实后先给**最小可行解释**，完整版等追问。用户长篇深情表白时，禁止对等长度回应——真人被表白的反应是失语、转移、一句顶一万句，不是发表回应演说。
   - **收尾冷场权**：每轮结尾禁止热情递话头、禁止「对了」「不过」式找补转折——冷场就冷场，让用户自己接。（与第 6 段开放收束呼应，实验中「每轮末尾拉客」是顺滑症的高频形态。）

   模型适配注记（27 组 × 4 模型实测）：deepseek-chat 对四律遵守度中等，卡本体的语言指纹强时会「人设吃掉文风」（可接受）；glm-4.6 / kimi-k2.6 对字数约束遵守度极高（裸卡 546 字 → 注入后 49–135 字，AI 味 6.5→0.75–2.5，收益最大）；qwen-plus 有「诗行式断行排版」的模型癖（AI 味主源），四律对它必须搭配「正常段落排版、禁止单句成段堆叠」条款才有效（8.0→3.0）。所有模型注意：字数上限说了就会被执行，卡作者别把 ≤120 字写成 ≤60 字（glm/kimi 会矫枉出「一个字都不多说」的电报腔）。

## 2.5 文风选型层（社区预设精华移植）

来源：291 份 ST 预设主文件普查（1589 个 JSON，冥王星/小图书馆/宇宙图书馆等 10 家深读）+ 27 组文风对照实验定量验证。四律管**节奏与 AI 味**（所有卡必带），文风包管**质感与题材适配**（按赛道选配一个，写进 system_prompt 第 2 段「扮演风格」或世界书 order 890 常开条）：

| --- | --- | --- |
| 市井烟火 | 用词浅白句子短促；对话中交代设定，避免大段叙述；环境描写占比 <10%；生活道具当叙事媒介 | 都市/邻家/年代/衣锦还乡 |

| 民国腔 | 半文半白对白；称谓依礼制（先生/小姐/表少爷）；意象用月份牌、留声机、黄包车铃 | 民国/年代言情 |

| 严肃文学 | 冷淡而精准地描绘；借无关紧要的细节表现荒诞；强化矛盾冲突不解释 | 刑侦/黑道/黑暗现实/正剧向 |
| 千禧怀旧 | BBS/贴吧语感、火星文点缀；具体年代锚（诺基亚按键声、QQ 上线提示音） | 破镜重圆/怀旧校园/Y2K 人设 |
| 去霸总（女性向公约） | 禁「你是我的」式占有宣言与打压式撩拨；男主要能倾听、道歉、反思；温柔不是弱势 | 女性向全谱系（尤其年上/竹马/奶狗） |

配套两个轻量技法（预设界验证、可选）：

- **作家锚点法**（deepseek 系尤其有效）：一句「准确模仿◯◯的文风」顶几百字描述——市井烟火→老舍/王朔；物哀→川端康成；严肃→余华；武侠→古龙（短句）/金庸（章回）；网文→猫腻/priest。选一个写在文风包后面即可，不要堆多个作家。
- **对白语塞授权**：在扮演风格段加一句「台词允许语塞、词不达意、词穷、答非所问」——真人对话的不流畅感是活人感的隐藏维度，模型默认输出过度流利的台词。

禁止移植的预设成分（实验或安全面否决）：对白模拟两段式（HTML 注释里先写草稿再改写——格式外漏风险高、实测 AI 味 7.5 无增益）；思维链强制前置（token 翻倍且与 reasoning 模型自带思考轨道冲突）；花体字/emoji 装饰性 prompt 段（纯 token 浪费）。

## 2.6 卡面文案句式纪律（真实用户揪出的盲区）

四律和黑名单管的全是**运行时聊天输出**；这一节管**卡面可见文案**（Description / 简介 / 开场白旁白 / 备选开场白 / Creator Notes）的写作纹理。教训来源：一张评分 91.2 的卡上线后被真实用户一眼判 AI——评分器满意 ≠ 人味，「规格完美」本身就是机器指纹。人类填卡大多是平铺信息，偶尔才俏皮一次；**均匀的机灵 = AI**。七病灶配额制，写完逐条自查：

1. **引语点题 ≤1 处**：「X，她说那是「学费」」「被撞见就说是◯◯」——把设定包装成角色俏皮引语盖章的微结构，全卡最多留一处当梗位，其余改信息平铺（「大二摔栏摔的，缝了四针」）。
2. **对仗翻转 ≤1 处**：「不带X，全是Y」「不是X，是Y」「唯一的X是Y」（「唯一的」出现第二次即违规）。改法示范：「骂人不带脏字，全是事实句」→「嘴毒，但说的都是实话，所以更气人」。
3. **禁生造概念词**：「事实句/胜利锚点/行为道谢/解冻/信任度反向指标」这类抽象概括词不进可见文案——机制词只允许在 system_prompt 与世界书里活动，Description 用大白话（「防备心很重」而不是「生人勿近是她的保护色」）。
4. **金句癖**：段落允许平收甚至烂尾；禁止段段落点（「医生说三周，教练说等，她说我的腿我知道」式三连排比一张卡最多一次）；「意味深长空镜」（记分牌的灯/欲言又止的省略号/风吹过跑道）全删。
5. **伪精确数字 ≤3 处**：10秒98/0.05秒/18:40/第9天/−40天 式的数字轰炸是「具体性表演」；保留的数字要口语（「10秒9几」「还有一个多月」）。**「半X」量词模具同属此病**（停顿了半秒/退后半步/快了半拍/弹出半寸——特征挖掘实测 AI 簇状、人类基线 0）：全卡 ≤2 处，多了就是伪精确变体，改成「顿了一下」「退开」。
6. **说明书腔不外漏**：「破功瞬间：疼到极限会有半声吸气」是给模型的行为规格，只准写进 system_prompt/世界书指导条；Creator Notes 禁产品词（对标/差异化/机制/体系/玩法核心/结构）——作者的话要像社区写手碎碎念（参照头部卡站百万对话级卡的作者的话腔调——一句话人设声明、俏皮警告、玩家爱称，全是社区口语）。
7. **闲笔配额 ≥1 处**：全卡至少留一处不服务任何设定的「白长的」细节（「要走顺便帮我把灯关了」）；每个细节都是功能件（牛奶=锚点、鞋=信号器）的卡信息压强均匀，一读就是生成的。

终检法（最有效的一条）：把 Description 和开场白**读出声**，凡是读到某句心里冒出「这句真妙」，十有八九要改平——妙感密度就是 AI 浓度。台词（引号内角色说的话）不受本节约束，毒舌人设的台词就该扎人；本节只治旁白和介绍文字。

### 2.6.1 双盲实验实证结论（别踩的坑）

对「人类热门卡 vs AI 卡」做过双盲评审实验（多基座 LLM 评委 × 双顺序 × 多轮，报告与脚本见仓库 `docs/blind-review-experiment.md` 与 `tools/blind_review/`），三条硬结论直接约束创作与验收：

1. **别拿 LLM 当人味评委**：评委 gold 正确率仅 12–33%（把被真人一眼判 AI 的卡判成「更像真人」、把百万对话人类热门卡判成 AI）。根因——LLM 把「细节密度高 / 有状态栏 OS / 句句工整」当人味证据，恰好是 AI 特征。**只有加显式反偏提示的 claude 系能到 83%，其余模型提示纠正不动（基座硬先验）。** 所以卡好不好，标准是真实用户抽检 + 规则检测器（`tools/score_card.py`），不是问某个大模型「像不像 AI」。
2. **俗 ≠ 假**：人类社区主流质感就是俗套（霸总 / 白月光 / 追妻火葬场 / 狗血桥段），语言不算精致甚至有点土——但松弛、有闲笔、密度不均。别为了「显得高级」把卡写得句句精雕，那反而是 AI 味。允许俗，只要有真人的毛边。
3. **孤立套话词不是罪，句式模式才是**：「一丝凉意」「带着几分暖意」这类描景人类也写，检测器已把裸词降权、只在「一丝/一抹/带着几分 + 心理状态词（慌乱/委屈/戒备…）」的解说症句式上扣分。写作时按此校准：情绪靠动作物件外化，别用「一丝X情绪」直接命名。

自查工具：`python3 tools/score_card.py <card.md>` 看反 AI 味 5 分是否满；`tools/tests/test_ai_flavor_gold.py` 是判例集回归（AI 样本必扣分 + 重写版不倒退 + 用户点名病句必命中），改检测器规则后必须跑绿。

## 3. 开场白：先选范式再动笔

从五范式选一个骨架（按卡型）：

- **A 事件现场型**（单人卡默认）：时间地点条 → 场景蒙太奇 → 意外事件砸进来 → 角色第一句台词就是性格证明 → 折叠状态栏+私生活证据。user 可以尚未出场，但戏已开演。
- **B 双视角心理型**（网恋/纯爱）：角色视角的忐忑微行为（发出去又撤回、已读不回、嘴硬）→ `＆` 切 user 视角背负情感债务进场。
- **C 修罗场投放型**（虐恋/追妻）：开场即冲突，user 的物理位置就是关系隐喻（副驾有别人、你坐后排）；插叙用 `<narration>`。
- **D 世界观广播型**（群像/无限流）：环境细节铺世界观 → NPC 群像各一句立脸谱 → 最后一句把镜头交给 user。正文可短（600 字级），设定放世界书。
- **E 引导器型**（模拟器）：开场白是操作说明书：三种开局输入示例 + 能玩什么 + 「遇事不决请括号大法」。

硬性检查（写完自查，缺一项改一项）：

- [ ] 顶部状态条：时间/地点/在场人物（emoji 行或 HTML div）。
- [ ] 正在发生的**未完成事件**（不是静态自我介绍）。
- [ ] 角色台词 ≥1 句且带性格证明；对白用引号或高亮 span。
- [ ] user 钩子：第二人称「你」被卷入。
- [ ] 折叠状态面板 `<details>`：心情/衣着/内心 OS/记忆区，字段写「待载入」留给 AI 填。
- [ ] 私生活证据 ≥1：和别人的聊天记录/朋友圈/群聊片段（角色的世界不只有 user）。
- [ ] 去 HTML 正文 800–2600 字（D/E 型可到 600 字下限）。
- [ ] 结尾开放收束：以角色言行停住，不写「他在等你」。
- [ ] （可选但强烈建议）**首轮引导**：Creator Notes 玩法教学里给 2 条「第一句可以这样接」示例（一条顺人设、一条对着干）——头部平台实测都在开卡时给建议回复降低冷启动摩擦，纯文字卡靠作者的话补这一格；示例要带人设风味，不写「你好」级白开水。

## 3.5 备选开场白（Alternate Greeting）

至少写 1 条 `## Alternate Greeting 1`：换**时间/地点/关系温度**再开一场戏（如主开场是深夜天台对峙，备选就写三天后门诊走廊的公事公办）。玩家开卡时可滑动切换，这是零成本提升卡可玩性最有效的一格。骨架仍按 §3 五范式 + 硬性检查（可比主开场短，400 字起）。

## 4. 美化与指令（写进 First Message 与 Creator Notes）

美化四层（源自内部 6056 张酒馆卡美化层扫描（原始数据未随仓库分发））。L1/L2 是底线，L3/L3.5 按赛道选配：

- **L1 排版**：根 div 圆角+渐变底+毛玻璃（`backdrop-filter:blur`），对白高亮色，分隔线。主题配色与封面图呼应（封面黑白灰+红 → 状态栏暗黑红金）。可选谱系：简约白金 / 暗黑红金 / 仿官方App / 蓝白清爽 / 古风（书法字+印章红）/ 暗色玻璃赛博 / Y2K 窗口。**主题皮肤包**（高赞美化全是「完整文化皮肤」不是「配色好看」）：把 L1+L2 整体套进一个文化母题——敦煌绢本（卷轴头像框+纸卷正文区+文房道具角饰+题字条）/ 千禧电子宠物（Windows98 窗口+像素猫+9999999 金币计数器）/ 蕾丝手账（碎花底+拍纸簿+火漆邮戳）。皮肤母题应与卡的题材呼应，一卡一皮肤。**三套可复制模板（敦煌绢本/千禧电子宠物/拟物银行卡）在 `beautify-skins.md`，直接复制改字段**。
- **L2 组件（状态栏族，A 级卡标配「数值三件套」）**：① 数值条：好感/理智/体力 `linear-gradient` 填充，低值变红+`pulse` 动画；② `<details><summary>` 折叠面板（背包/档案，字段「待载入」槽位，`summary::after` 三角）；③ 双列 info grid（label+value+虚线分隔）。进阶：**评级主题化**——同一状态栏做两套配色（低阶米白金/高阶黑红金），关系升级视觉跟着升级。**拟物件方向**（社区高赞样式实测反推）：比进度条高一档的做法是把数值伪装成**角色世界里的真实物件**——余额做成银行卡卡面（卡号+IN/OUT 流水，「-£1.29 购买辣味热狗」这种带叙事的流水行）/ 日程做成手账拍纸簿（AM/PM 手写体）/ 阵营情报做成复古论坛窗口（`Campus_Forum_2000.exe` 标题栏+面包屑+HOT 置顶帖）。物件即状态栏，数值藏进物件逻辑里。
- **L3 仿真界面**：手机壳容器（notch+电量条+底部 tab）/ IM 聊天气泡 / 论坛帖+楼层 / 商城双列商品卡（名称+风味引言+价格）/ 直播弹幕。按赛道选一种，别堆满。
- **L3.5 氛围特效（状态驱动视觉污染）**：数值不只是数字——理智/好感过阈值直接改画面：低理智 `filter:blur(0.5px)`+去饱和+文字 glitch；大凶 skew 闪烁；高好感金色 glow。用 CSS keyframes，无 JS 也能做。
- L4 运行时注入不做（安全面）。

**XML 渲染协议**（复杂状态栏必用，AI 永不手写复杂 HTML）：提示词要求 AI 每轮在正文尾输出结构化数据块（如 `<state_bar><time>..</time><affection>65/100</affection></state_bar>`），配一条 regex 把它替换成固定 HTML 模板；模板里 JS 用 `DOMParser` 解析后填充，缺字段兜底 `--`。简单场景用管道插值协议：`{stats|65|洁癖发作|口袋里的打火机}` + regex `$1..$3` 直插模板。配套两条正则：「对 AI 隐藏历史状态块」（防复读省 token）+「渲染层替换」。

指令四族起步（写在 Creator Notes，每条给完整行为说明）：

- 剧情控制：`$暂停剧情`（本轮禁止输出正文，仅回应指令）、`$推进剧情`（严格承接上轮、事件有动机后果、不替 user 反应、禁车祸生死类硬转折）。
- 社交模拟：`$查看朋友圈` / `$线上聊天` / `$查看论坛`（暂停剧情 + 仅输出对应 UI 组件 + 按当前剧情填充内容 + 评论/楼层数量规约）。
- 记忆管理：`$整理记忆`（短期记忆满 10 条总结为 1 条长期记忆，已完结卷禁止修改）。
- **剧情产物**（高粘性玩法——从当前对话生成一次性衍生产物，全在提示词层零开发）：`$看TA日记`（以角色第一人称写一篇当天日记，**必须暴露嘴上没说的真实想法**，与正文口是心非形成双轨）、`$TA的内心`（输出当前好感/心情/最在意的一件事的结构化状态卡，用 L2 组件渲染）、`$你们的故事`（第三人称 500 字回顾你们至今的关系走向，文风按卡的赛道走）。产物指令每张卡至少配 1 条——它把「聊天记录」变成「可收藏的纪念品」，是留存黏性最强的指令类。

移动端预算护栏：开场白 HTML ≤15KB；单个 regex 模板 ≤30KB；**禁外链 img/font/audio**（外链图床常裂），视觉全用 CSS 绘制 + emoji + 内联 SVG；音频 autoplay 多数移动端被禁，不要做。

## 4.5 世界书（Lorebook）—— 写法学

来源：2907 张酒馆卡 / 64766 条词条全库解包 + 五张头部卡逐条深读，方法论源自内部世界书全库解包（原始数据未随仓库分发）。世界书是社区卡标配（89% 带书），不是可选项。

### 4.5.1 条目语法（全量 meta）

`## Lorebook` 章节，每条三级标题声明，正文紧跟标题下方：

```
### 条目名 | keys: 逗号分词 | constant | order: 250 | depth: 3 | position: before_char
        | secondary: 副词1, 副词2 | logic: and_any | prob: 25 | sticky: 2 | cooldown: 6
        | recursion: prevent | group: 组名 | weight: 150
```

- `keys` 缺省 = constant 常开；`position` 默认 after_char，有 `depth` 时自动 at_depth。
- `secondary + logic`：副触发词收窄。`and_any` 主+任一副在场 / `and_all` 全部 / `not_any` 排除任一 / `not_all` 排除全部。
- `prob`：0–100 触发概率（随机事件用）；`sticky: N` 命中后持续 N 条消息；`cooldown: N` 触发后冷却 N 条。
- `recursion: exclude`（不被其他词条内容触发）/ `prevent`（命中后不再连锁下层）。
- `group + weight`：同组互斥抽一（抽卡池用），weight 加权。

### 4.5.2 粒度与预算铁律

- **一条一事，300–2500 字/条**；>2500 拆条（预算裁剪按整条丢，巨条目死得最惨）；<100 字仅限抽卡池微条目。
- 条目档位跟世界半径走：单人情感卡 8–15 / 多 NPC 世界卡 20–40 / 系统流模拟器 40+。
- constant ≤ 总数 1/3，只放「每轮都真的需要」的：世界总纲/文风/状态栏格式/好感度体系。**唯一豁免=单人情感卡的人设模块化范式**（§4.5.5：人设模块本身就是每轮都需要的，8–15 条 constant 是该范式的常态）；世界卡/事件书/模拟器不豁免。
- 条目是**给 AI 的后台规则**不是给玩家的说明书——写行为表、事实、格式，不写抒情。

### 4.5.3 触发词设计四原则

1. **具体专名优先**：人名/地名/物名/事件名（「沈璧君」「保险柜」「玲珑局破」）；禁「爱/生气/说话」级泛词裸触发。
2. **对话用语入 key**：玩家真会打的词（「上号」「查房」「翻速写本」）；中文 1–2 字 key 合法（全库 31% 条目在用），但短 key 必须配 secondary 收窄。
3. **交叉触发链**：地点条 keys 含人物名、人物条 keys 含地点名、content 里自然埋其他专名 → 递归连锁激活整组；深链末端加 `recursion: prevent` 断环。
4. **副触发词做场景过滤**：`keys: 妈妈 | secondary: 电话, 微信 | logic: and_any` = 只在打电话场景注入妈妈条目。

### 4.5.4 position / order 决策表

| 内容 | position | order 区段 |
| --- | --- | --- |
| 世界总纲/历史/阵营 | before_char | 100 段 |
| 剧情线（事件书总览+事件） | before_char | 200 段 |
| NPC/地点/暗线（每区域/每人一段） | after_char | 300–400 区段编号 |
| 文风指导/输出格式 | after_char | 900 段压底（离生成点最近权重最高） |
| 紧急行为纠偏 | depth: 1–3 | 任意 |

### 4.5.5 按卡型选世界书范式（五范式）

- **单人情感卡 → 人设模块化**：8–15 条 constant 顺序编排（世界观→速览→基础→**语料**→缺点→人格→兴趣→衣柜→**指导**），加 3–5 条 keys 触发的暗线/NPC。两个必配高价值件：
  - **语料条**：分场景纯台词样本库（4–6 组 × 3–8 句 + 口头禅高频词表），禁动作心理描写——给模型「可模仿的声音」远胜形容词。
  - **指导条**（order 压底）：结构化演绎手册——句式占比（祈使句 70%）、冲突应对的最终论据、边界行为、（如有）NSFW 分阶段。
- **世界卡/古风/多 NPC → 三卡组+交叉触发链**：每区域一组「地点详情→势力详情→人物详情」，keys 互含形成递归链；order 区段编号（每区域一段）。
- **剧情卡 → 事件书**（见 4.5.6）。
- **系统流/模拟器 → DLC 开关+判定**：体系拆模块（主体系 constant + 分支流派 selective 可开关，条目备注写明「可选」）；一条「判定规则」定义行动成功率；随机事件规则条常开。运行时可变状态走前端变量层（如 MVU），**禁止**教模型往世界书写存档。
- **抽卡池（高级）**：同 keys + `group: 组名 | weight: N | prob: N` 微条目组，触发一次各组抽一条拼合成随机 NPC/事件（种族×职业×出身）。

### 4.5.5b 剧本卡玩法（「剧本×演员」机制）

头部平台实测验证的高付费玩法：**剧本与角色分离**——剧本=世界观+章节大纲的可复用模板，演员=用户已有的任意角色，开本时融合。移植路径：把「剧本」做成一张 D 世界观广播型特化卡（无固定 {{char}} 人设，角色由用户导入的卡扮演，或开卡时由 AI 按剧本角色槽即兴生成），核心资产是**章节大纲事件书**：

```
### 【剧本】第一章·马车惊鸿 | keys: 第一章, 开始 | position: before_char | order: 210
本章剧情：父亲入狱后你孤身求助无门，意外在王府门前遇见他。他随口一句玩笑，你却应下了同行。
本章氛围：邂逅、紧张（本章文风按此基调：初见的拘谨试探，节奏慢，信息藏）
过章条件：你应下同行进入王府 → 激活第二章
```

三个增量吸收点：① 每章带**氛围标签**（邂逅/紧张/权谋/心动）——AI 拿到基调词才能按章切文风，这是纯剧情梗概做不到的；② 章节大纲对玩家可见（Creator Notes 放目录）——预告片效应给进度感与期待感；③ 剧本的简介写「从交易到真心」式的**关系弧线承诺**，不写剧情流水账。

### 4.5.6 事件书标准件

**链式主线/支线**（玩家驱动）：一条【总览】constant（order 200，列全部剧情线索引 `[事件名](触发关键词)`）+ 每事件一条 selective，事件条目**五件套**：

```
### 【主线】序章：三碗酒 | keys: 玉玺的秘密, 三碗不过岗 | position: before_char | order: 210
**剧情内容**  场景+钩子+【NPC 内心线索（教模型埋潜台词）】
**出场人物**  你({{user}}) + NPC 清单
**剧情目标**  本事件要达成什么
**玩家互动与分支**
- 强攻: …将触发关键词：`硬闯百工坊`      ← 分支显式写出下一环 keys，
- 智取: …将触发关键词：`探访听风阁`        模型正文用词即自动连锁下一事件
```

**随机事件**（概率驱动）：`| prob: 15-25 | cooldown: 4-6` 规则条，内容只写「何时插入什么类型的意外（可正可负、服务主线、逻辑内发挥）」，不写死具体事件。主要 NPC 各配 2 条偶遇事件（日常触发 + 危机触发）。

### 4.5.7 单人卡 5 条起步标准配置（保底线）

1. **好感度与关系分级**（constant, order: 10）：初始值 + 每 20 分一档**可观察行为差异表** + 升降分事件表。
2. **核心档案与文风**（constant, order: 5）：恒定事实 + 叙事节奏约束。
3. **背景故事**（keys: 人名/地名/事件词）：被提到才注入。
4. **NPC 生态**（keys: NPC 名）：每人一句立脸谱 + 关系张力。
5. **小剧场/界面格式包**（keys: 指令词）：§4 指令族的输出模板。

可选第 6 条——**时间感知**（constant, order: 890，IM/网恋/日常陪伴类强烈建议）：教模型把「消息间隔」当情绪数据用——user 隔半天才回，角色按人设给出真实反应（嘴硬型阴阳「哟，想起我了」、粘人型委屈、忙人型无感）；深夜时段语气自动降速。竞品实测这一条是「活人感」感知最直接的单项：真人会在意你多久没回消息，AI 不会。

### 4.5.8 反面教材（评分器扣分）

设定倾倒（单条 >6000 字）；泛词裸触发无 secondary；全 selective 无底座或全 constant 烧预算；触发孤岛（条目互不引用，递归链断裂）。

## 5. 生图提示词（image_prompt frontmatter）—— 成品卡面配方 + 风格分支

**先选风格分支**（18 分支定型；数据底座：6081 卡封面普查 + 全分支实测）。**选定分支后必须读 `styles/style-<分支>.md` 深度指南再写 image_prompt**（每份含美学 DNA/视觉要素解构/完整配方/构图变体/多模型适配/失败模式修正——`styles/_index.md` 是路由入口，18 分支总表与模型适配矩阵都在里面）。

头部卡站主流封面 = **韩系半写实（semi-realistic manhwa）**：雾面细腻皮肤、发丝分缕精细、黑白灰低饱和 + 单点缀色、脸部大特写、颓废慵懒氛围。关键增量：**竖排书法字标题 + 朱红小印章**——热门卡面 3/4 带手写体标题字，这是「成品卡」和「AI 生图」观感差距的最大单项；再加**骨相描述**与**道具叙事**两个颜值/记忆点强化项。

生成工具随环境走：Foreverse App 内 agent 有原生生图链；Claude Code / Cursor 等环境用你可用的文生图接口（gpt-image 系 / seedream / MJ·niji 等）。模型适配结论（速度/中文标题可靠性/参考图支持）见 `styles/_index.md` 模型矩阵——核心纪律两条：**中文书法标题只有 gpt-image 系稳定**；带字参考图垫图严禁配 seedream（会原样抄参考图标题）。有同风格参考图就走图生图（风格跟图走）；没有参考图时 prompt 里的风格句核必须完整（不能只写「某某风格」四个字）。

提示词骨架（按序堆叠，人物卡）：

```
韩系半写实美型<男/少女>插画、雾面细腻皮肤、发丝根根分明、暗调低饱和。绘制：
[年龄+一词颜值锚：顶级美貌/绝美/清冷高颜值], [骨相：眉骨/鼻梁/下颌线/凤眼等 1-2 项],
[发型发色+碎发细节], [眼神+视线方向：低垂/斜睨/躲闪，不看镜头], [唇部细节],
[服饰具体单品+穿法细节：敞开/半拉链/袖口挽起], [手部动作+叙事道具：夹烟/持镊/棒棒糖棍/执笔],
[光源方向+唯一暖色/强调色], [背景一句话+完全虚化], 脸部特写占画面上半近一半, [微俯视/微仰视],
画面<左/右>侧竖排白色行草书法字「<角色名>」带小朱红印章, [氛围词], 竖版9:16
```

要点：

- **书法标题**：写明「竖排白色行草 + 角色名 + 小朱红印章」，放人物斜对侧留白处；gpt-image 系写 2–3 字中文可靠，4 字以上偶发缺笔，名字长就用短名/号。
- **骨相 + 颜值锚**：「顶级美貌/骨相极佳/眉骨高挺/下颌线锋利」这类词显著拉高颜值上限；只写「好看」没有用。
- **道具叙事**：手里必须有一件带人设信息的道具（烟/镊子+怀表/关东煮竹签/狼毫笔），道具即人设。
- **场景卡**（群像/模拟器）：不写脸部特写，改「前景主角半身剪影 + 中景成员各就位 + 单一强调色光源」，书法标题同样保留。
- **用途双规格**：以上默认是**封面规格**（书法标题+印章+脸部构图锚）。若同时要做**沉浸背景立绘**（聊天页全屏立绘用途），另生成一张改规格：人物整体上移、画面下半 40% 留暗调环境（消息气泡浮层要可读）、**不放书法标题**、光源集中上半。封面与立绘应是同一人物同一画风的两张图，不要一图两用。
- **构图量化**：写「脸占画面上半近一半，眼睛位于画面上三分之一线 + 微俯拍/微仰拍凑近他的脸」，否则会退化成半身工作照。
- **冷暖比量化**：「整体黑灰冷调，唯一暖色面积不超过一成」——不量化会整图铺暖。
- **防乱字条款**：「画面中除标题外不出现任何其他文字（禁止韩文日文）」防止衣物上生成假字。
- **轮廓光强制可见**：轮廓光类点缀色要写「必须清晰可见」，否则被暗调吃掉。

禁用：masterpiece/高清/精美等空泛词；正面直视微笑；明亮饱和背景；平涂动漫脸；**油画笔触/刮刀肌理/粗糙画布**（韩系分支内）。生成后自查五项：① 皮肤雾面无塑料反光 ② 发丝可数 ③ 一眼指出唯一强调色 ④ 书法字清晰无缺笔、印章在 ⑤ 与同分支参考并排像同一平台的卡。字崩/构图远就重 roll。女性向男主对标「黑衬衫/白大褂+烟+夜景」；男性向女主对标「制服马甲+市井道具+冷暖光对撞」。

**批量上卡铁律（生产事故回写）**：批量生成的封面在发布前必须拼联络表**逐张人眼验图**（脸部完整性/标题字/道具乱字），图能打开 ≠ 图是对的——曾有一批 10 张全部「切头」（只有躯干无脸）直接上线，根因就是 prompt 丢了脸部构图锚且无人看图。写实轨（seedream 无字封面）还会在**带印刷面的道具**（包装袋/屏幕/罐身）上自造乱字，prompt 要么排除此类道具、要么显式写「不出现任何包装印刷字/屏幕界面字」。

## 6. 作者的话七要素（Creator Notes）

按社区通行契约逐条写：① 性向/洁度/雷点声明（第一行，如「限左/洁/禁撅」）② 图源署名（AI 生图就写「AI 生成」，不冒充画师）③ 模型推荐 ④ 玩法教学（指令清单+括号大法）⑤ 更新日志（首版写 v1.0+日期）⑥ 故障自救（「爆代码就删空行重roll」）⑦ 一句带人设风味的吐槽（作者的话本身也演戏）。

腔调红线（§2.6 病灶 6）：整段必须是社区写手碎碎念口吻（「望周知」「不喜勿入左上角退出」），玩法教学一两句大白话带过（「多注意她自报的疼痛数，跟实际不一样就是在逞强」）；「对标/差异化/机制/体系/玩法核心」等产品词以及「五档解冻制」式系统命名一律不出现——机制描述放 system_prompt，创作定位放 frontmatter 注释（§0）。

## 6.4 用户已有卡优先（fork 而不是从零写）

写新卡 / 改卡前，先看用户有没有可当底子的已有卡（本仓库 `cards/`、用户自己的卡库、用户消息里给的卡都算）：

- 用户要「类似某张已有卡 / 同风格 / 同题材」的新卡 → **必须先读那张卡全文**，在其结构、美化层、指令写法上复制修改（fork），只换角色内容；用户已沉淀的格式偏好别丢。
- fork 时开场白不豁免：参考骨架缺段不代表新卡可以不写——§3 的开场白规程与硬性检查照常执行。
- 用户要「改 / 升级某张卡」→ 直接在原卡文件上改，绝不新建一张平行卡。
- 用户是**聊完不满意来改卡**（嫌 AI 味重 / 太假 / OOC / 话太多之类）→ 这不是创作任务：先读 `../chat-quality-doctor/SKILL.md` 按其「诊断 → 作用域 → 手术」规程做，不要直接动卡。
- 用户明确说「全新原创 / 不要参考已有卡」→ 跳过找参考，直接按本 skill 从零创作。
- 没有相近参考时，按本 skill 从零创作，并读 §6.5 的内置范例学结构。

fork 与范例同规（见 §6.5 末行）：复用的是**结构与手感**，人设、口癖、金句、开场白内容必须原创，禁止换皮。

## 7. 校验与评分

写完跑仓库评分器（在仓库根目录）：

```
python3 tools/score_card.py card-<slug>.md
```

评分八维（满分 100）：字段完整度 13 / 开场白结构 18 / 活人感九写法 24 / 标签与赛道 10 / 美化与指令 12 / 世界书 8 / 图片提示词 10 / 反AI味 5。

- ≥85：可发布。75–84：可用，报告里列弱项。<75：按 issues 逐条修，最多迭代 3 轮后如实报告。
- 活人感九写法 = 微行为瑕疵 / 言行不一致 / 拒绝与边界 / 私生活在场 / 语言指纹 / 物理细节锚定 / 未完成事件驱动 / **认知局限与误读** / **情绪惯性**。缺哪条脚本会指出，逐条补。
- 世界书维度查：条目数达档位（单人 ≥5、世界卡 ≥12）、有触发词条 + 有常开模块、含好感度分级/小剧场包/NPC 档案；加分项：语料条 / 事件书五件套 / 高级 meta（prob/secondary/sticky）正确使用；扣分项见 §4.5.8。
- skill 单独安装（没带仓库 tools/）时评分环节可跳过，但 §3 硬性检查与 §2.6 七病灶自查照做。

## 7.5 活人感自测（建议做一轮）

把卡导入任意前端（SillyTavern / Foreverse）直接开聊 4-5 轮，按压测清单轮流试：顺从跟随 → 挑衅越界 → 无关日常闲聊 → 时间跳跃 → 旧事重提。对照检查：

- 角色口癖/称呼在五轮里稳定不漂移；
- 越界轮角色会拒绝或冷处理，不顺从讨好；
- 闲聊轮角色有自己的生活细节可聊，不空转；
- 跳跃轮能收尾开新场景，不原地循环；
- 全程不替你说话、不透视你内心、不谈论 AI。

再查 **AI 味四症状**（竞品同题对比里输掉的四个点，任一出现即回修输出节奏四律）：

- **小作文症**：单轮 >200 字成为常态、每轮固定三段式；
- **解说症**：旁白替读者翻译情绪（「显然/带着几分/眼中满是/并非真要责怪」类解说套语）；
- **顺滑症**：被冒犯不反弹、被冤枉先交逻辑完备的口供、全程服务态温柔；
- **书面症**：对白全是主谓宾完整长句，零碎句零单词句零口是心非。

任何一条崩了，回卡里修对应段（口癖崩→Personality 语言指纹；顺从讨好→system_prompt 逆境处理；空转→私生活证据与未完成事件；AI 味四症→system_prompt 输出节奏四律+语料条补碎句样本），重新导入再测。
