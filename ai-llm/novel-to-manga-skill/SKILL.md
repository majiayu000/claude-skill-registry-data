# 小说转漫画

把一部小说变成一本可翻阅的漫画。四个阶段串行，每阶段产物落在固定工程目录，
ID 互相引用，中途可断点续跑。

## 单章原则（硬性）

**每次任务只做一章的分镜与漫画页。**

- 用户点名章节（如"做第 3 章"）就只做该章；没点名时默认从第 1 章开始（或问用户）。
- 一章完成即停靠，向用户交付本章页面清单；**不自动续做下一章**，等用户点章。
- 设定（S1/S2）是工程基建：第一次建立，之后跨章复用；后续章节出现新角色/新场景时按需补卡、补图，不重做全书分析。

## 前瞻阅读原则（硬性，防张冠李戴）

**只读当前章就拆设定，必然把"后文才揭示身份"的角色张冠李戴。**

- **做第 N 章前，至少读到第 N+20 章**；首次开工至少普查前 30 章。
- 读完立即建《[角色出场总表.md](references/character-tracking-guide.md)`》（`01-设定/角色出场总表.md`）：
  角色档案卡（真实身份/变身形态/首次点名章节/设定图状态）＋逐章出场矩阵＋设定图补录计划。
- **身份以"首次点名章节"为准**：无名角色先挂"待确认"标签，禁止提前绑定已知名；
  同一外形描述（蓝发/法杖/蓬蓬裙）可能属于不同角色，形似≠同一人。
- 亲属代称（"妹妹/少年/少女"）在点名前单独按代称建档，点名后再合并。
- 新角色要先补设定图（S2）再进分镜（S3）；补录优先级：当前章需要 > 未来 3 章内 > 远期提及。
- **设定图状态精确到形态**：同一角色的每个形态/年龄段都是独立的设定图需求
  （如"角色X：魔法少女形态✅ / 幼年便服❌"）。总表里角色级的一个 ✅ 不代表全部形态已补齐。
- **缺图即停（硬性）**：S3 发现任何将被画到的角色/形态/场景没有设定图，禁止用
  "只画背影/局部/虚焦"等理由绕过，必须先回 S2 补图并在停靠汇报里列为 P0 缺口，
  经用户确认后才能继续拆分镜。
- **描述考古（出设定图前必做）**：为任何角色/形态出设定图前，先全文检索该角色的
  全部描写——含本名、别名、代称、变身名，把散落在各章的外貌、服装、气质描述汇总成
  「描述档案」（写入角色档案卡），确保前后文是同一个人的同一定义；设定图提示词只能
  从描述档案取材，禁止凭印象补特征。方法见 [character-tracking-guide.md](references/character-tracking-guide.md)。
- **留白属性禁止自动补全（硬性）**：原著未描写的属性（发色/瞳色等）在描述档案中标注
  "留白"，出图暂停，由用户从候选项中拍板后才可写入设定图。两条禁忌：
  禁止用"与已生成页面一致"作补全依据——无设定图时代的生成页面本就是无据自由发挥，
  拿它锚定＝循环论证；禁止模型以"合理推测"名义静默定值（典型事故：某角色原生发色
  原著留白，早期页面在无参考图时误借已出场角色的配色，设定图反向锚定后两个角色剪影相撞）。

## 工程目录规范

每本小说一个独立工程。工程根目录默认建在当前工作目录下，命名 `<小说名>-漫画工程/`。
用 `python3 {技能目录}/scripts/init_project.py "<小说名>"` 一键创建，结构如下：

```text
<小说名>-漫画工程/
├── 原著/                          # 创作者输入，只读
│   └── 原文.txt
├── 01-设定/
│   ├── 设定总表.md                # 人物卡 / 场景卡 / 世界观 / 画风基准，全部带章节出处
│   ├── 角色出场总表.md            # 档案卡＋逐章出场矩阵＋设定图补录计划（前瞻阅读产物）
│   ├── 伏笔与关键道具表.md        # 伏笔/关键道具：埋设章页→回收章页（契诃夫之枪登记处）
│   └── 设定图/
│       ├── 人物/                  # CHAR-<角色名>-<类型>.png
│       └── 场景/                  # LOC-<场景名>-<视角或时段>.png
├── 02-分镜/
│   └── CH<章号>/                  # 如 CH001/
│       ├── 节拍表.md              # S3 第一交付物：逐拍列剧情节拍，页数由它推导
│       ├── 分镜脚本.md            # 页 → 格 → 镜头表，每格引用设定图 ID
│       ├── 检查清单.md            # 每页引用的设定图/机位图 ID 清单（S4 参考图校验依据）
│       └── prompts/               # 每页提示词文件 CH001-P001.md（改页先改此文件再重生）
├── 03-漫画页/
│   └── CH<章号>/
│       └── CH<章号>-P<三位页号>.png
├── 04-成书/                       # 可选：PDF 合并交付
└── 生成日志.md                    # 每张图的提示词、参考图、状态，断点续跑依据
```

> 各阶段文档在**该阶段开始时**由执行者创建（S1 建两表、S3 建节拍表/检查清单）；
> `init_project.py` 只建目录骨架与初始文件，不要求初始化时一次建全。

ID 规范（一旦建立不得改名，跨文档引用全靠它）：

- 人物设定图：`CHAR-<角色名>-三视图 | 表情集 | <服装/状态变体>`
- 场景设定图：`LOC-<场景名>-<视角或时段>`
- 分镜格：`CH001-G03-02` = 第 1 章第 3 页第 2 格
- 漫画页：`CH001-P003`

已有工程时读 `生成日志.md` 从断点继续，不要重建目录、不要重跑已完成阶段。

## 流程与停靠点

| 阶段 | 范围 | 做什么 | 产出 | 停靠 |
|---|---|---|---|---|
| S1 | 全书一次，跨章复用 | 读小说，拆人物/场景/世界观，定画风 | `设定总表.md` | **确认设定与画风后才进入 S2** |
| S2 | 首次建立 + 按需补 | 生成人物/场景设定图 | `设定图/` 下全部 PNG | 给用户过目，不满意重roll |
| S3 | **单章** | 节拍表落盘 → 点名章节剧情 → 漫画分镜 → 检查清单落盘 | `02-分镜/CH<章号>/` 下 节拍表.md、分镜脚本.md、检查清单.md | 确认分镜后才批量出页 |
| S4 | **单章** | 该章逐页生成漫画（按检查清单自动传参考图 + 文字内嵌） | `03-漫画页/CH<章号>/` | 出页前按检查清单校验参考图，缺图即停；跑完本章即停 |

**页级重生**：用户对某页不满意时，先改 `prompts/CH<章号>-P<页号>.md`，再单页重生；
旧图改名 `*-backup-YYYYMMDD-HHMMSS.png` 保留，不删除。全章完成后可把页面按序合并 PDF 放 `04-成书/`。

出图花钱，三个停靠点是硬性的；用户明确说"一路跑到底"时，可把 S1–S3 合并为一次性确认，
S4 仍逐页落日志。

## 一致性铁律

1. **设定图先行，且精确到形态**：漫画页里每个被画到的角色/形态必须已有对应设定图；
   角色有设定图但该形态没有（如只有成年形态、缺幼年形态）同样算缺图，先回 S2 补图。
2. **身份核实先行**：分镜前对照《角色出场总表》核实本章每个角色的身份与设定图；后文才揭示的身份不得提前使用。
3. **每页必带参考，清单机读**：S3 检查清单里每页列出引用的全部设定图/机位图 ID；
   S4 生成某页前按该清单传参考图，传入前逐项比对——清单里有而没传 = 违规，
   禁止手工凭记忆配参考图。
4. **伏笔必须闭环**：关键道具/伏笔（跨章才回收的"枪"）登记进《伏笔与关键道具表》；
   埋设页必须真的画出"持有/藏匿"动作，回收页必须画出"取出/兑现"动作——两端缺一，观众看到的就是凭空道具。
5. **文字逐字**：台词和旁白用原文逐字写入提示词，标明所属气泡；提示词加"文字铁律"（禁止自创台词、
   禁止 ①②③④ 序号徽章入画）；生成后拼总览图（压到 ≤1MB JPEG 再目检，防请求超限）逐页放大校对。
6. **画风基因唯一**：画风从小说自身推导为「风格基因」（五维：线条/上色/色彩/构图气质/媒介质感），
   写在《设定总表.md》的「画风基准」段，所有出图提示词原样复用，禁止逐页即兴改风格。
   **彩漫 / 黑白漫（网点涂黑）必须由用户在 S1 选定**。去 AI 味是硬要求：负面词清单、不完美注入、
   媒介质感锚见 [style-guide.md](references/style-guide.md)。

## 一次任务的典型请求

```text
用户：把 D:\books\xxx.txt 转成漫画，先做第 1 章

执行：建工程 → S1 全书拆设定（确认画风）→ S2 出本章涉及角色的设定图（确认）
     → S3 拆 CH001 分镜（确认）→ S4 出 CH001 全部页 → 停，交付本章清单

用户：继续做第 2 章

执行：读设定总表与生成日志 → 补新角色/新场景设定图 → S3 拆 CH002 → S4 出页 → 停

用户：继续做第 2 章（标准执行序）

执行：向后读到第 22 章 → 核对/更新角色出场总表（新角色补设定图）→ S3 拆 CH002
     → S4 出页 → 拼总览图逐页质检（文字/徽章/角色一致）→ 停
```

## 出图后端

优先推荐模型：**`gpt-image-2.0`**。若宿主环境只提供旧别名 `gpt-image-2`，可回退；
若使用 Codex 内置 imagegen，则直接调用可用的图像生成工具。

推荐单页规格：`1024x1536`、质量 `high`。gpt-image 系模型对参考图有较强保真能力，
这是角色一致性的基础。单页漫画是一次生成任务，禁止把多页合并进一次调用。
生成后把选定图片移动/复制到工程目录对应位置并按 ID 命名，不要留在默认输出目录。

如果必须通过 OpenAI 兼容 API 出图，使用 [`scripts/generate_image.py`](scripts/generate_image.py)。
API Key 只放 `IMAGE_API_KEY` 环境变量或本机 `.env`，API 根地址只放 `IMAGE_API_BASE`；
不要把凭据或私有网关地址写入提示词、生成日志、工程文件或 Git。

## 版权与文字风险

- 只处理创作者合法持有、有权使用的小说；分析是转化性工作，设定文档不整段复制原文。
- 中文对话框文字由模型渲染，可能出错字：重roll（单页最多 3 次；文字类 1 次不中先转确定性修字，
  修字不成再回用剩余次数）→ 仍失败则该页按无字出图并记录，交用户决定是否后期加字。
