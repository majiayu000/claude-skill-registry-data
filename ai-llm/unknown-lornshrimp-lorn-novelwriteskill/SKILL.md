# 通用-多平台小说适配
> **题材路由**：若 .github\题材专用Skills\ 目录存在对应的 <题材>-多平台小说适配 Skill，则：
> - 将题材特性骨架路由到 <题材>-多平台小说适配，该 Skill 位于 .github\题材专用Skills\ 目录。
> - 命中本技能时，必须优先强制加载当前 Skill 与 <题材>-多平台小说适配。


多平台适配不是改几个词，而是换一套“读者心智 + 节奏分配 + 承载方式”。

## 卖点保真要求（强制）

- 多平台适配允许调整卖点的呈现方式、优先级与镜头承载，但不允许把主卖点适配没了。
- 每个平台版本都必须回答：主卖点怎样被该平台读者更快看见，以及怎样在该平台语境里持续成立。
- 若适配后只剩平台腔调差异，却认不出同一本书的核心吸引力，视为适配失败。

## 母稿前置要求（新增）

- 若源稿仍带明显单平台口癖、事件链不稳、情绪主轴发散或关键钩子尚未钉牢，必须先调用 `通用-提纯多平台母稿`，再进入多平台适配。
- 多平台适配负责“怎么拉开版本”，不负责替松散底稿兜底；若底稿本身不稳，直接分流只会把问题复制到多个平台。
- `通用-提纯多平台母稿` 也属于 AI 生成链路；若 AI 在母稿提纯前就不可用，则本 Skill 与母稿提纯都不得启动，必须直接写入 `blocked_ai_unavailable` 并停止。

## 事故复盘回写（2026-05-11）

- 已验证：在 AI 能力受限时改用脚本批量改写正文，会直接导致平台风格崩坏与模板污染扩散。
- 因此本 Skill 明确要求：AI 不可用时只允许阻塞与日志回执，不允许“先脚本改写再门禁补救”的路径。

## 常见触发词 / 用户说法速查

- 先做多平台适配策略
- 这章上不同平台该怎么拉开
- 帮我做改写前推演
- 这些平台版本开始撞车了
- 别直接轻改，先告诉我平台差异

## 何时使用

- 要把同一章 / 同一片段适配到多个平台。
- 需要先做改写前推演，而不是直接写一份中性底稿再轻改分发。
- 发现多个平台版本开始撞车，需要修复平台感。

## 与其他 Skill / Prompt 的边界

- 多平台输出类 prompt 继续负责编排、落盘、门禁与相似度质检。
- 各平台子 prompt 继续负责本平台硬约束。
- 本 Skill 只负责**跨平台适配方法库**：差异矩阵、推演清单、拉开策略、撞车修复顺序。
- 本 Skill 产出的是适配策略资产，不是可直接发布的章节正文成品。

## 作者风格画像嵌入（自动，只读）

- 若项目根注册了"作者风格进化"数据源（见 `Agents.md`）：**执行中（只读，不提问）**读取 `作者风格画像.md` 的 叙述句法层 + 作者语言库 作为适配边界约束——平台风格拉开时**平台化改写不洗掉作者指纹**（原声金句 / 惯用句式 / 母题显影是各平台版本的公共底座）；未注册则回退默认，不报错，不阻断

## 执行顺序

1. 先读取平台差异矩阵，确认目标平台的核心气质。

> **GEO 维度补充（新增）**：在差异矩阵中额外考虑各平台在 AI 搜索中的可见性特征——起点正版权威高、AI 偏好引用但要求信息完整；知乎问答模式与 AI 同构，GEO 价值最高；番茄/七猫免费流量大但权威感较低。详见 `../../写作研究/GEO小说项目核心参考.md` 的"维度三：平台可见性层"。
2. 再用改写前推演清单，明确本次最该拉开的差异点与压相似度位置。
3. 再读取平台风格总则与撞车修复，确认风格优先级与修复顺序。
4. **检查工作区根目录 `Agents.md` 中是否存在 `## 平台POV基线表` 节**：
   - 若**存在**：读取该节，锁定目标平台的当前人称基线。
   - 若**不存在**：先读取 `references/平台POV基线表_模板.md`，在 `Agents.md` 中创建 `## 平台POV基线表` 节，参照各 `通用-输出*版` Skill 的 `POV 选择指南` 逐平台裁定并写入锁定值，再继续执行。
   - `Agents.md` 的 `## 平台POV基线表` 节为唯一权威源，本 Skill 与所有 `通用-输出*版` Skill 均须服从，不得在 Skill 内部重新裁定。
5. 若平台策略要求切换视角人称（第一/第三人称），再按"人称视角双向转换适配卡"确定转换方向与保真约束。**注意：只有在 `Agents.md` 的 `## 平台POV基线表` 节允许该平台使用目标人称、且已登记偏离原因时，才可执行人称切换。**
5. 明确“本平台在语气、结构或读者预期上，最该比其他平台更强化什么具体特征”。
6. 若需要把推演结果、撞车修复方案或平台差异结论落盘，默认放入 `适配策略/`；若分析对象来自 `小说正文/`，它也只能作为输入来源，不得作为策略文件落点。
7. 再进入正文改写与终检。

## 默认输出口径

- 默认输出是平台差异矩阵、改写前推演、撞车修复结论等适配策略。
- 适配策略允许且应优先放在 `适配策略/` 文件夹中。
- 不允许把适配策略放在 `小说正文/` 文件夹中；`小说正文/` 只承载章节正文成品，不承载适配规划、推演记录或撞车修复方案。
- 若需要落盘，默认直接回写或新建在 `适配策略/` 下。

## 平台人称适配建议（动态读取基线表）

- 本 Skill 及所有 `通用-输出*版` Skill 必须在每次执行前动态读取工作区根目录 `Agents.md` 的 `## 平台POV基线表` 节，查找目标平台的当前锁定人称。Skill 本身不固化人称，最终以本项目当前作品的基线表为唯一权威。
- 同一作品中不同平台的人称可以不同；同一平台、同一作品内的人称必须保持一致，除非已在 `适配策略/` 中记录了经批准的偏离理由。
- 以下按题材×平台给出人称方案选择策略，综合了本工作区都市悬疑（35篇）、异能志怪（22篇）、都市职场（26篇）、女频爱情（4篇）四大题材写作研究及网络搜索数据。

### 跨平台通用原则

- **绝对禁止全知视角**：所有平台、所有题材，全知第三人称均为禁区。全知视角会让读者产生"旁观者"距离感，破坏代入与悬念。
- **限知视角是所有平台的共同底线**：第一人称限知或第三人称限知二选一，不得混用。
- **视角切换必须严格受控**：同一章内不得切换超过1-2次；每次切换必须有明确场景分隔或章节标识。
- **传统网文平台（起点/纵横）读者习惯第三人称**：第一人称会主动缩减受众。除非悬疑/推理/亲历者自述型作品，否则优先第三人称限知。
- **社交媒体/轻阅读平台读者更接受第一人称**：碎片化阅读场景下，"我"的即时情绪冲击力更强。

## 硬规则

- 风格顺序：不允许先写一份中性底稿再轻改分发；压相似度必须服从平台风格，而不是牺牲平台风格。
- 平台区分：中文平台之间必须明显可区分；英文平台之间也必须明显可区分；不允许为了压相似度或贴平台腔而模糊主卖点、削弱卖点落地。
- 人称与研究：人称转换必须可逆且保真，既可 `第一人称→第三人称`，也可 `第三人称→第一人称`；**各平台的人称锁定以工作区根目录 `Agents.md` 的 `## 平台POV基线表` 节为唯一权威源**，若最终选择偏离基线表锁定值，必须在推演清单记录偏离原因并逐条举证；平台研究若明确指向单一平台，应只在矩阵与对应平台链路中使用，不得偷渡回默认未指平台资产。
- 目录纪律：不得把适配策略存放、回写或新增到 `小说正文/` 文件夹；适配策略允许且应优先放在 `适配策略/` 文件夹中。
- 污染禁行：不允许把“抽象自述 + 动词模板 + 口径名词”句群当作平台差异化策略；这类句群属于污染文本，命中即失败。适配前后都必须保证污染短语族清零：`对照项落在`、`先把同一句话拆碎`、`先把顺滑的解释拆开`、`只求能追溯`、`只求能复核`、`只求对得上` 等不得出现在平台正文。
- 脚本禁行：不允许使用 `scripts/append_cn_unique_monologue.ps1`、`scripts/append_cn_unique_narration.ps1`、`scripts/append_cn_unique_thirdperson.ps1`、`scripts/rephrase_cn_body.ps1`、`scripts/rephrase_en_body.ps1`、`scripts/cn_lexicon_profile_transform.ps1` 作为适配主路径。
- AI 阻塞：只要 AI 在母稿提纯或正文适配任一阶段不可用，都必须停止正文适配并写入 `blocked_ai_unavailable`；禁止任何脚本正文改写兜底，避免继续浪费 token 与返工成本。
