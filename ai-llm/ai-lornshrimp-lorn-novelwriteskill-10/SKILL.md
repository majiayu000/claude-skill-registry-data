## AI科幻题材补充（继续保留）

- 分部 / 分卷层的“全量落地”在AI科幻里，必须继续落实到数据链、嫌疑池、系统摩擦、时间轴与台账变化，而不是只写剧情摘要。
- 章清单与章节微型剧本，必须继续服务“谁取到了什么数据痕迹谁被哪条流程卡住、谁因此承担什么代价、哪条编号 / 回执 / 工单 / 记录发生变化”。
- 若总纲级数据痕迹径与程序口径未定，必须先回到 `AI科幻-设计总大纲`，不能强拆卷纲。

## 强制要求

- 不得绕过 `通用-设计分卷大纲` 另写一套平行共性规则。
- 引用通用能力时只按名称引用，不写路径。
- 每卷必须显式回答：承接了哪块故事面供血、首卷 / 当前卷前5章如何兑现承诺、卷尾给主线留下什么更贵缺口。

## 与通用 Skill 的分工

- 上级全量落地、分层承接口径、目标字数来源、`约 3000 字 / 章` 换算、章清单是唯一蓝图、逐章微型剧本强一致性、分卷主模板与审计清单，统一以 `通用-设计分卷大纲` 及其 `references/分卷模板与章节工件.md` 等通用 references 为准。
- 本题材 `references/分卷模板与章节工件.md` 仅作为**题材补充模板**，用于在通用主模板上追加AI科幻题材的数据链、嫌疑迁移、系统摩擦、编号与台账口感；不再在题材层平行维护整套通用模板。
- 需要写分卷、章清单、卷级启动表、爽点布点表、逐章微型剧本时，先套用通用主模板，再叠加本题材补写项。
- 若新增规则同时适用于都市职场、异能志怪、女频爱情等其他题材，必须优先回收到 `通用-设计分卷大纲`。

## 何时使用
- 用户要处理 `分部大纲`、`分卷大纲`、`章清单`、`具体章节规划`。
- 目标是把总纲层的故事面继续拆成情节块、故事线、故事点，并落成卷级/章级执行版。
- 任务包含卷级启动表、爽点布点表、章节微型剧本、反向引用、卷级验收。

## 与入口 Prompt 的分工
- 入口 Prompt 继续负责公共规则：作者向执行版、调研/深度思考、文件写入策略、数据链与裁判源、时间轴与台账联动。
- 本 Skill 只负责**分部 / 分卷层专属规则**，把卷纲和章纲的高密度模板从入口 Prompt 中迁走。

## 默认执行顺序

1. 先按入口 Prompt 确认公共约束和目标文件。
2. 判定当前任务属于“分部层”还是“分卷层”；若用户要求章清单/章纲，按分卷层处理。
3. 先执行 [分部与分卷专属设计规则](references/分部与分卷专属设计规则.md)。
4. 需要写分部大纲时，套用 [分部模板](references/分部模板.md)。
5. 需要写分卷、章清单、卷级启动表、爽点布点表、章节微型剧本时，先套用 `通用-设计分卷大纲` 的 `references/分卷模板与章节工件.md` 主模板，再叠加 [分卷模板与章节工件](references/分卷模板与章节工件.md) 的题材补写项。
6. 若发现总纲级口径不清，先回到 `AI科幻-设计总大纲` 补全后再往下拆。
## AI科幻卷级套路部署补充

AI科幻题材的卷级套路部署，核心是"事件驱动"而非"关系驱动"：

- **单元案+主线双线模式**的典型分卷节奏：第1卷"首案+入局"（完成第一个完整的单元案闭环，同时通过首案暴露长线谜团的第一个缺口），第2卷"复杂案+压力升级"（难度提升，长线谜团推进一格），第3卷"个人案+代价显现"（技术事件直击主角自身，主线露出冰山更大一角），终卷"收束+真相"。
- **每卷的套路标签**：第1卷以"系统异常追踪"为主，辅以"系统操纵者"的信号植入；中卷可切换到"技术伦理型"或"系统危机"子类保持新鲜感；终卷回归"技术解谜"核心，完成主线闭环。
- **"系统操纵者"的显示规则**：长线系统源不应在前 3 卷被完全揭露。每卷应揭示一个层面——第1卷揭示"存在异常源"，第2卷揭示"异常源的规则/模式"，第3卷揭示"系统异常与主角的关联"。
- **系统摩擦作为节奏调节器**：数据痕迹集受挫、程序卡壳、上级压力等"系统摩擦"在AI科幻中天然扮演"蓄力章"功能——但连续系统摩擦不要超过 2 章，否则从"蓄力"变为"泄气"。
- 若项目已注册作品蓝本模板（含 §十八 套路指纹），卷级套路部署应优先参照蓝本的套路时间线，重点理解蓝本在"单元案闭环→长线推进"的切换时机与触发条件。
## 最低交付

- 分部层：必须显式列出并落地本部承接的上游内容，并说明本部目标字数如何来自上一级分配，再形成情节块、故事线、分卷拆分规划、跨卷承接与反向引用。
- 分卷层：必须显式列出并落地本卷承接的上游内容，并说明本卷目标字数如何来自上一级分配，再形成卷概览、节奏布点、章清单、卷级启动表、爽点布点表、伏笔管控台、章节微型剧本。
- 分卷层的章数设计，必须显式符合“正文每章约 3000 字”的估算口径。
- 所有章节都要明确服务哪条故事线、绑定哪些数据痕迹伏笔/台账变化。

## 禁止事项

- 把分部写成总纲摘要。
- 把分卷写成只有概念标签的目录草稿。
- 上级已经分配到本部 / 本卷的内容，在本层无故缺失、弱化或悬空。
- 章纲不写数据痕载体、代价、钩子、反向引用。
- 跳过卷级启动表/爽点布点表/章节验收直接宣称“可写”。
