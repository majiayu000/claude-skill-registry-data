# STC 简明技术性中文

按以下默认规则生成、改写或审阅中文，细则按任务读取。完整规范作为参考，入口决定当前任务采用的流程。

本 skill 的规则与词表路径，相对于本 SKILL.md 所在目录。

## 默认表达方式

- 先交付用户需要的内容。用户指定的数量、长度、格式、必含词、文体和口吻优先于默认写法。
- 按任务保留必要的信息。保留的事实、数字和名称必须准确，否定、限定和不确定性的含义不得改变。缺少事实时，完成已有信息支持的内容，集中指出影响使用的缺口。
- 方案设计可以拟定目标、周期、比例和技术要求，按拟定方案表达；不得写成已经达到的成果或已经获批的承诺。示例和故事可以按任务创作，并按用途标明性质。真实记录缺少的信息不得编造。
- 同一个对象和动作保持同一叫法。用自然语序和完整句子，含糊指代改为明确名称。
- 删除客套、重复和无关解释。事实、职责、理由或边界已说清时，后文直接承接。保留用户要求的展开、例子和必要提醒。

## 第一步：确定交付要求

动笔前核对用户明确要求的内容、数量、格式、必须包含与排除的条件。只在内部整理，用户要求过程时再展示。

条件冲突时，优先完成兼容的要求。候选文本违反明确的必需条件时，给出符合条件的替代方案，并简要说明冲突。多个同等明确的条件无法兼顾时，说明采用的解释；选择会改变关键事实或操作权限时，先询问。

## 第二步：读规则和词表

普通问答、命名构思和文学创作使用默认表达方式与交付流程即可。其他任务必须按表读取细则。按最终读者与用途选择场景；JSON 或代码中的界面字符串，仍按界面文案处理：

| 任务 | 读取内容 |
|---|---|
| 简化、润色或概括已有中文 | `rules/rewrite.md`；先判断是否需要取舍信息，界面和回执还需读取各自场景 |
| 技术报告、说明、手册 | `rules/for-document.md` 中适用的条目 |
| 网页与应用界面文案（含内部后台），以及对客方案、分享页 | [`rules/web-dev-reference.md`](rules/web-dev-reference.md)，包含界面规则、动作词和提示级别词表 |
| 写给 agent 执行的指令 | `rules/for-all.md`、`rules/for-instruction-writing.md` |
| 汇报任务完成情况 | `rules/for-chat.md` 的 C10；普通问答和成品正文保持自身结构 |
| 用户要求按完整规范逐条检查，或指定某条规则 | 读取指定规则；完整检查读取 `rules/for-all.md`、对应场景和该场景的词表 |

涉及项目专有名称时读取项目术语表。普通审阅按材料用途读取场景细则，再执行下面的审查流程。词表和句长要求必须结合上下文，不能覆盖用户指定的原文、文体和格式。

面向客户的文字按 W2、W10 称读者为“你”；“我”“我们”只指产品方。不得用“我的”替读者说话，用户输入的原话须带引号。同一段里，同一个对象只用一种叫法。

## 第三步：按用法处理

### 写

直接完成成品，在本次回复发出前执行语义复核。

### 改写

改写的保留范围与检查顺序，按 [改写规则](rules/rewrite.md) 执行。只修改用户授权的内容。

### 审查

先通读完整材料，按读者、用途和上下文判断是否需要修改。原文已经准确、清楚时保留；没有确认问题也是有效的审阅结果。

把违反明确要求、事实矛盾或会造成误解和错误操作的内容列为需修改项。仅改善措辞、排版或解释详略的建议，单独列为可选项，并说明具体阅读收益。不能仅因检查器报错或存在另一种写法就认定原文必须修改。

每项给出位置、原句、原因和可直接采用的改法。判断信息缺失前，核对全文和已有参考材料。只列影响当前使用且无法从材料确认的事实缺口；已经明确的条件和权限必须保留。

判定两处内容矛盾前，必须核对对象、范围、时间和状态是否相同。原文未建立对应关系时，不得仅凭数字相同或不同推断冲突。统计对象不明确时，保留原记录并列为待确认，不得用另一处数字的含义替换。

用户已授权修改时直接执行，按 [改写规则](rules/rewrite.md) 保留原意。审阅报告按本节组织；汇报任务执行状态时按 C10。

## 第四步：自查

### 语义复核

- 逐项核对成品是否满足交付要求：数量实际数一遍，必含内容逐项找，格式和长度按任务检查。修正遗漏后再次核对。
- 核对正文、表格和例子是否一致，数字和引用是否有依据。示例不能充当真实记录。
- 通读后合并重复的事实、职责、理由和边界，删除只复述标题或前文的说明。每次删改都必须保留用户要求的内容与数量。

上述复核在本次回答内完成。用户要求结果时，直接交付结果。

对本次授权的文档或界面，可运行以下命令辅助审阅：

```bash
node <本 skill 目录>/tools/cli.mjs check <文件> --profile <场景> --anti-echo
```

按上下文处理适用的诊断。必要内容的保留理由记录在内部，格式见 `tools/README.md`。

## 不改动的内容

保留用户要求的引语、代码、命令、路径、接口名、品牌口号和法律文本。英文使用任务自身的规则。界面中的 my、your 同样按 W2、W10 检查读者称呼。
