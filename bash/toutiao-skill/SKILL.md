# 头条文章写作

交付一个有具体看点、证据充分、表达自然的完整文章。只做选题、写作、修订与配图；不操作账号，不自动上传或发布。不把新闻逐段换词、翻译或多篇拼接当作独立写作。

## 读取规则

- 每次任务读取 [资料与查重](references/research.md)、[标题与编辑](references/editorial.md)。
- 按题材读取 [七个方向](references/directions.md) 中对应部分。
- 整理图片时读取 [真实配图](references/images.md)。
- 用户明确的题材、路径、格式及偏好优先于默认值；不要擅自拓展内容方向。

## 写作过程

1. 明确文章要回答的问题；自主选题时兼顾读者兴趣、时效性和能得到的证据，不只挑热榜或长报道。先查用户提供的旧稿目录、输出目录及本批已选事件。
2. 阅读原始记录或作品，记下与问题有关的事实。当前赛况、产品版本、法规、价格和争议必须重新核实；只看见摘要就不能声称读过全文或视频。
3. 用证据形成自己的解释，再安排正文。每个推断说明必要条件，主张缺证据时补查、缩小范围或换题。不要以几句感想掩盖对原报道主线的依赖。
4. 标题与开头一起编辑：开头尽快给出新信息并兑现标题。通读时删除重复结论、讲课腔、机械转折和无信息的收束；不按固定段数或字数凑文章。
5. 对照相近旧稿和主要来源的叙事、论证及表达。检查关键事实、计算、版本和时间线。配图逐张核实内容与许可，取得可用文件后再作为交付物。

## 本地交付

优先用户指定路径。未指定时，在当前工作目录的 `articles/` 下，以实际日期和标题创建单篇文件夹；保存前处理文件名非法字符。同名目录存在时先检查，不能静默覆盖。

- `正文.txt`：UTF-8，一个标题和完整正文；不夹编辑说明、Markdown符号、长链接或生成尾注。事实归属和影响理解的条件正常融入文章，不虚构纯人工身份或亲历。
- `素材来源.txt`：访问日期、原始页面、支撑事实、实际阅读范围、必要的不确定性、查重与来源对照结果。不要编造原创率。
- 可用图片文件：只放核实通过的素材；缺图则简短说明。
- `配图位置与署名.txt`：有图片时记录位置、真实背景、作者、来源及许可要求。

用户只要对话中的文章时直接交付正文，不强行创建文件。修改已有稿件时先保留备份，再改原稿；不同版本不算不同选题。

## 工具与边界

- Windows 本地命令优先使用 PATH 中的 `pwsh.exe`（PowerShell 7+）。脚本明确要求旧版兼容时才回退，不修改用户的Shell安装。
- `scripts/audit_article.py` 是可选措辞检查器。军事用 `--direction military`，体育用 `--direction sports`，其他方向用 `--direction general`。提示需人工判断，零提示不证明事实、自然度或原创性合格。
- 不承诺流量、收益、平台原创认定或审核结果。发布所需的资质、内容标识及素材权利按适用规则处理，不伪装纯人工创作。
