# official-document-generation（正式申报文档生成）

## 触发条件
当用户出现以下意图时使用本 skill：
- "生成/编写/起草 申报材料/政府材料/正式文档"
- "写 零碳工厂/绿色工厂/节能报告/碳足迹报告 建设方案"
- "编制 申报书/评价报告/可行性研究报告"
- "整理 正式申报文档/政府材料"

## 适用范围
- ✅ 正式申报材料（零碳工厂、绿色工厂、节能报告、碳足迹报告等）
- ✅ 政府材料（含官方模板、填写说明、证明材料目录）
- ✅ 需要数据可追溯、应对评审的文档
- ❌ 不适用：纯创意文档、营销文案、内部备忘录

## 强制 4 阶段流程（每阶段有 checkpoint，禁止跳步）

```
[阶段 1: 数据字典]  汇总关键指标 + 权威值 + 来源 doc
   │  ⛔ 拦截：未建字典不得进入框架
   ▼
[阶段 2: 框架]  输出章节骨架，与官方模板对齐
   │  ⛔ 拦截：用户未确认框架不得写正文
   ▼
[阶段 3: 正文]  分章节生成，每三级标题首段标来源
   │  ⛔ 拦截：引用数字必须命中字典
   ▼
[阶段 4: 一致性检查]  全文扫描数字唯一性/单位统一/时间口径
   │  ⛔ 拦截：发现冲突必须修复
   ▼
[输出]
```

## 阶段 1：建数据字典（强制）

**目的**：在写正文前，先把所有关键数字汇总成一张表，每个指标只有一个权威值。

### 数据字典模板
| 指标 | 权威值 | 单位 | 来源 doc | 来源类型 |
|---|---|---|---|---|
| 2025 整车销量 | 150169 | 辆 | doc3 ESG报告 | 第二方 |
| 2025 营业收入 | 348.65 | 亿元 | doc3 ESG报告 | 第二方 |
| 2025 总排放量 | 53747 | tCO2e | doc6 核查报告 | 第三方 |
| 自发光伏电量 | 2022.194 | 万kWh | doc5 通知 | 第一方 |
| ... | ... | ... | ... | ... |

### 权威值优先级（高→低）
1. **第三方核查报告**（如温室气体核查报告、第三方评价报告）— 最高权威
2. **ESG/年度报告**（上市公司公开披露）— 第二权威
3. **内部测算/能源统计表**（企业自有台账）— 第三权威
4. **向量检索多 chunk**（索引文档中多处出现，取多数一致值）— 兜底

**规则**：同一指标若多源冲突，按优先级取值；不得在全文并存两个值。

### 与 document-indexing skill 协作
若已用 `document-indexing` skill 建好索引，可调用查询：
```bash
cd ~/.voyah/skills/document-indexing/scripts
node query.mjs "2025年整车销量" 5
node query.mjs "温室气体总排放量" 5
```
查询结果含 sourceDoc/pageNo，直接填入数据字典"来源 doc"列。

## 阶段 2：输出框架（强制）

**目的**：先出章节骨架，用户确认后再写正文，避免返工。

### 框架要求
- 严格对应官方模板（如"附件2"对应的章节顺序）
- 基本信息表、填写说明、证明材料目录等附属部分必须完整
- 层次保持扁平（最多 3 级标题），避免 1.1/1.1.1 过深
- 每个章节列出：核心论点 + 关键数据（引用字典）+ 数据来源

### 典型官方模板结构（零碳工厂/绿色工厂类）
```
基本信息表
一、概况
  （一）申报单位基本情况
  （二）主要生产工艺或算力设施运行情况
  （三）能源利用状况
  （四）碳排放情况
二、建设基础
  （一）科学算碳
  （二）源头减碳
  （三）过程脱碳
  （四）协同降碳
  （五）智能控碳
  （六）碳抵销和信息披露
三、建设目标分析
  （一）能源消费、碳排放趋势及目标可达性分析
  （二）建设目标
四、建设路径
  （一）主要任务
  （二）重点项目
五、预期成效
  （一）经济效益
  （二）社会效益
  （三）生态效益
证明材料目录
```

**⛔ 拦截**：框架必须经用户确认后才能进入阶段 3。

## 阶段 3：写正文（强制）

### 数据来源标注规则（以三级标题为单位）
- 每个三级标题（如"1. 2025年度能源消费总体情况"）下的**首段**应说明数据来源
- 引用索引数据时标注 doc1-doc7 对应来源
- 关键证明材料在正文中提及对应文件名（如"取自《2025年度温室气体核查报告》"）
- **不要每个数字逐条标注**，以三级标题为单位整体说明即可

**示例**：
```
1. 2025年度能源消费总体情况

本章节全部能源消费数据均取自2025年度能源消耗统计表、年度电力、天然气、汽油原始发票台账，统计周期2025年1月1日至12月31日。

全年外购国网电力6227.753万千瓦时...
```

### 单位规范表（强制）
| 指标类型 | 规范写法 | 禁止写法 |
|---|---|---|
| 功率 | kW（小写k大写W） | KW、kw、Kw |
| 电量 | kWh、万kWh | KWH、kwh |
| 标准煤 | tce | 吨标煤、TCE |
| 二氧化碳排放（纯CO2） | tCO₂ | tCO2、tco2 |
| 二氧化碳当量（含冷媒） | tCO₂e | tCO2e、tco2e |
| 质量 | t、kg | T、KG |
| 体积 | m³、Nm³ | M3、m3 |
| 货币 | 亿元、万元 | 亿、万 |

**关键区分**：
- tCO₂ = 纯二氧化碳（不含冷媒逃逸）
- tCO₂e = 二氧化碳当量（含冷媒 HFC 等温室气体折算）
- 两者**不能混用**，全文必须统一口径

### 篇幅约束
- 目标篇幅：2-3 万字（精炼优于冗长）
- 结构层次：最多 3 级标题（一/（一）/1.），禁止 1.1/1.1.1
- 重点项目：用简洁条目列出（名称/投资/周期/内容/成效），**不要用"项目要素/内容"表格展开**
- 删除重复性描述：同一项目不要在不同章节重复 3-4 次

### 待补充标黄规则
- 所有"待补充"部分必须标黄处理（含 `[待补充]` 占位符 + 含"补充"关键词的整句）
- 最后"证明材料"部分不用管，用户会手动添加

## 阶段 4：一致性检查（强制）

生成完成后，**必须逐项扫描**以下检查点并报告结果：

### 检查清单
- [ ] **数字唯一性**：关键指标全文唯一，无两个冲突值（如 0.0046 与 0.005044 不能并存）
- [ ] **单位统一性**：全文符合单位规范表（kW 不写 KW、tCO₂ 与 tCO₂e 不混用）
- [ ] **时间口径一致**：如"2027年通过认证" vs "2030年通过认证"不能并存
- [ ] **数据来源标注**：每个三级标题首段是否说明来源
- [ ] **权威值优先级**：关键数据是否取自第三方核查报告（而非内部测算）
- [ ] **结构扁平**：层次不超过 3 级
- [ ] **篇幅控制**：2-3 万字，无重复性描述
- [ ] **证明材料目录**：系统完整（参考下方模板）

### 证明材料目录模板
```
1. 企业营业执照、统一社会信用代码复印件
2. 光伏二期合作协议
3. 绿色电力交易凭证、绿电消费凭证
4. [年度]温室气体第三方核查完整报告
5. 《碳排放管理办法》《能源管理办法》内部制度文件
6. [年度]节能报告
7. 核心再生材料、整车碳足迹第三方认证证书
8. 动力电池回收合作协议、全国回收网点台账
9. IOT能碳管理平台功能界面截图
10. [年度]ESG环境社会治理完整年度报告
11. ISO9001/14001/45001/50001体系认证证书
12. 企业近三年无安全、环保、失信处罚信用证明
13. 其他支撑建设方案真实性的配套佐证材料
```

## 与其他 skill 协作
- **document-indexing**：阶段 1 建数据字典时，调用 `query.mjs` 从已索引文档检索关键数据
- 查询结果含 sourceDoc/pageNo，直接用于数据字典和正文来源标注

## 常见踩坑（从零碳工厂建设方案复盘提炼）

### 1. 数据自相矛盾
- **坑**：同一指标全文出现两个值（如光伏发电量 630 vs 733 万kWh）
- **解**：阶段 1 建数据字典时锁定唯一权威值，阶段 4 全文扫描冲突

### 2. 来源标注缺失
- **坑**：大量数据未标注来源，违反硬性要求
- **解**：阶段 3 每个三级标题首段强制说明来源

### 3. 篇幅失控
- **坑**：项目用表格展开导致 4 万字，评审阅读负担重
- **解**：阶段 3 篇幅约束 2-3 万字，项目用简洁条目

### 4. 时间口径漂移
- **坑**：不同章节时间目标不一致（如 2027 vs 2030 通过认证）
- **解**：阶段 4 检查时间口径一致性

### 5. 单位混用
- **坑**：kW/KW、tCO₂/tCO₂e 混用
- **解**：阶段 3 强制单位规范表，阶段 4 扫描
