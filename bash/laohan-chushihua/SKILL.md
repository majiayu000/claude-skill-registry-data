# laohan-chushihua(项目初始化)

两种模式:**新建**(空目录从零建)和**接入**(已有项目补缺入轨)。第一步永远是判断该走哪个分支。

## 模式判定(第一步,必做)

| 条件 | 走哪个模式 |
|---|---|
| 目录为空或不存在 | **新建** |
| 目录有 `.git` 且有代码文件 | **接入** |
| 目录存在但无 `.git`、有文件 | 问用户:要 git init 后接入,还是换空目录新建? |

## 模式一:新建(空目录)

```bash
bash "$(dirname "$SKILL_PATH")/scripts/init-project.sh" <路径> ["项目名"]
```

脚本自动完成:git init(main)/README/AGENTS.md(含合同 TODO 区)/CLAUDE.md 指针/STATUS.md/DECISIONS/ARCHITECTURE/handoff 目录/.githooks 门禁(含 secret 快扫+1500 行红线)/首提交。

**脚本跑完后你(模型)必须做的事**:
1. 引导用户填写 AGENTS.md 的四个合同 TODO(架构边界/验证入口/部署面/费用边界)——逐项问,用户口述你写入;
2. 按需提醒:远端创建(`gh repo create` 或手动)/公开仓需补 LICENSE+SECURITY.md;
3. 输出三行简报:建了什么/合同还缺什么/下一步。

## 模式二:接入(已有项目)

逐项检查,**只补缺失,绝不覆盖已有文件**:

1. **AGENTS.md**:不存在→创建(含全局层指针+合同 TODO);已存在→检查有无全局层指针行,无则**末尾追加**一行,不改已有内容
2. **README.md**:不存在→创建最简骨架;已存在→跳过
3. **CLAUDE.md**:不存在→创建一行指针;已存在→跳过
4. **.githooks/pre-commit**:不存在→从 skill 自带的 scripts/pre-commit.template 复制+启用 `core.hooksPath`;已存在→跳过(提示检查是否含 secret 扫描)
5. **docs/**:不存在→建 DECISIONS.md+ARCHITECTURE.md 骨架;已存在→只补缺失文件
6. **STATUS.md**:不存在→创建含首条初始化记录;已存在→在顶部插入初始化条目

接入完成后同样引导填合同 TODO。

## 不适用场景(refuse to draft)

- **已有完整文档集且已有门禁的项目 → 告知"已齐备",列出现状,不重复装**
- **非 git 目录且用户不想 git init → 只建文档骨架,不装门禁**
- **缺项目名/路径 → 问清楚再动手,不猜**

## 反模式

❌ 差:在一个有 100 个文件的项目上跑新建模式的脚本——脚本会拒绝(空目录守卫),但你手动绕过守卫强行覆盖 = 灾难。
✅ 好:先判定模式 → 接入模式逐项补缺 → 每步确认"已有什么,缺什么"再动。
