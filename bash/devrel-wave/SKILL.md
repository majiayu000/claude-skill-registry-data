# DEVREL_WAVE — мультиканальная лестница к людям из топ-лабов

> **Боль, которую лечит.** Одноканальный X DM = чёрная дыра: у DevRel-людей cold-DM падает в
> папку Requests и часто не читается вовсе. Антон (27.07): мультиканально работает лучше.
> **Единица работы = ОДИН человек**, доведённый по лестнице, а не список из десяти имён.

## Правила волны (вшиты, не вкус)

1. **1 прицельный человек = 1 вендор — и последовательно тоже.** Не два имени в одной
   лаборатории ни параллельно, **ни подряд**. Backup включается только когда первая цель
   **МЕРТВА ПО ОПРЕДЕЛЕНИЮ** — выполнено ОДНО из:
   - пройдены все **доступные** касания лестницы (шаги, заблокированные гейтом [коллега] или
     недоступностью канала, считаются пройденными — их пропуск не должен делать смерть
     недостижимой) **и** прошло ≥30 дней с последнего касания; **или**
   - `status: suppressed` (терминальный отказ, см. п.2a); **или**
   - человек ушёл из лаба / роль исчезла (freshness-чек).
   «Не нашёл анкера», «одно молчание», «DM закрыты» = ⛔ **НЕ смерть**, цель просто ждёт.
   Смену цели внутри вендора — записать в журнал с причиной.
2. **⭐ АНКЕР ОБЯЗАТЕЛЕН — и проверяемый.** Исходящее закрывает ЧЬЮ-ТО живую просьбу.
   Анкер засчитывается, только если выполнены ВСЕ три условия (иначе он декоративный):
   - **свежесть** — анкеру ≤30 дней (пост/issue/дискуссия). Годовой «show me what you're
     building» = ⛔ не анкер;
   - **это просьба, а не высказывание** — человек чего-то ПРОСИТ или на что-то жалуется,
     а не просто говорит на тему;
   - **наш артефакт реально отвечает именно на это** — сформулируй одной фразой «он просил X,
     у нас есть ровно X»; не получается без натяжки → ⛔ анкера нет.
   Записывать в журнал **линк анкера + дату анкера**, а не «анкер есть».
   ⛔ Анкера нет → **НЕ шлём** (`/outbound-gate` шаг 1). Урок 27.07: DM Alex Albert ушёл
   без анкера, по канон-матчу роли — так больше не делаем, даже если человек идеально подходит.
   Замер 26.07: 8 PR → отклик ровно у одного, единственного issue-matched.
2a. **⛔ SUPPRESSION — молчание и мягкий отказ ОСТАНАВЛИВАЮТ лестницу.** Лестница задумана как
   мультиканальность, а не как обход молчаливого отказа. Немедленный полный стоп по человеку
   (и запись `status: suppressed`), если случилось ЛЮБОЕ:
   - мягкий отказ («сейчас не до этого», «не мой профиль», вежливое «спасибо, нет»);
   - явный отказ, раздражение, просьба не писать;
   - он прочитал DM и не ответил **дважды** подряд;
   - заблокировал нас;
   - **закрыл DM или ограничил ответы ПОСЛЕ нашего касания** (изменение = реакция на нас);
     ⚠️ не путать с «DM были закрыты изначально» — у DevRel это обычная настройка, а не отказ;
     такой случай разбирает таблица §Состояния канала (идём другим каналом);
   - публично жалуется на холодные сообщения (⛔ это сигнал «не писать», **не** «читает cold»).
   Возврат к suppressed-человеку возможен только если **ОН** сам к нам обратился.
2b. **⛔ ГЛОБАЛЬНЫЙ ЛИМИТ ВОЛНЫ (закрывает обход «20 запусков по одному человеку»).**
   Единица работы = один человек, но потолок считается по всей кампании:
   **≤2 НОВЫХ людей в неделю** суммарно по всем вендорам и **≤6 активных целей** в лестнице
   одновременно. Считать по ВСЕЙ кампании, а не по хвосту журнала (⛔ `report 50` покажет
   последние записи и «потеряет» старые активные цели — лимит окажется фиктивным):
```bash
python3 - <<'PY'
import json,glob,datetime,collections
rows=[json.loads(l) for p in glob.glob('/Users/<имя>/Obsidian/<vault>/_outreach/ledger/outreach-log-*.jsonl') for l in open(p,encoding='utf-8') if l.strip()]
d=[r for r in rows if 'devrel' in str(r.get('campaign',''))]  # ловит и devrel-*, и evals-devrel
last={}
for r in sorted(d,key=lambda r:r.get('ts','')): last[r.get('person')]=r
active=[p for p,r in last.items() if r.get('status') not in ('suppressed','closed')]
wk=(datetime.date.today()-datetime.timedelta(days=7)).isoformat()
new=[p for p,r in last.items() if min(x.get('ts','') for x in d if x.get('person')==p)[:10]>=wk]
print(f'активных целей: {len(active)}/6 -> {active}')
print(f'новых за 7 дней: {len(new)}/2 -> {new}')
print('МОЖНО брать новую цель' if len(active)<6 and len(new)<2 else '⛔ ПОТОЛОК — цель ждёт')
PY
```
   Потолок исчерпан → цель ждёт следующей недели, «зато по одному» не аргумент.
3. **Freshness-чек роли перед КАЖДЫМ касанием.** Люди меняют роли молча. Alex Albert ушёл из
   Claude Relations в Research между сборкой списка и отправкой. Проверять по свежим постам
   и текущему био, ⛔ не по спискам DevRel из статей.
4. **Кредит вперёд.** Автору анкера — упоминание его issue/поста в самом артефакте, до просьбы.
5. **Долг-чек.** Висит НАШ неотвеченный ответ этому человеку → сперва закрыть долг, потом просить.
5a. **Кредит = польза, а не упоминание имени.** «Вписал его имя в README» ⛔ не кредит.
   Кредит засчитан, когда есть что-то полезное ЕМУ: ссылка на его issue/пост в самом артефакте,
   реальный вклад в его работу, co-author там, где он есть. Нечего дать по существу →
   значит и анкера настоящего не было (см. п.2).
6. **Темп.** Лестница растянута на недели, не дни. Молчание после полной лестницы = стоп по
   этому человеку (не добивать объёмом — менять таргетинг).

**Формальные программы и GitHub дают сигнал сильнее холодного DM.** Прежде чем писать

| **Mistral** | ambassadors + **прямой `devrel@mistral.ai`** | публичный рабочий адрес = не холодная угадайка |
| **любой** | **PR, закрывающий их открытый issue** | reply-rate не измеряется, но сигнал высокий; кейс: OpenAI нанял автора OpenClaw после публичного GitHub-проекта |

⛔ Это отдельная лейна `/local-llm-wave` (PR по репозиториям) — **сначала она, потом эта**.
Холодный DM без публичного вклада за спиной = слабейший из доступных ходов.

### Лестница (замеренная каденция DR: ≤3–4 приватных касания, спейсинг 2–4 дня)

| # | День | Канал | Что делаем | Гейт |
|---|---|---|---|---|
| 0 | **D−7…D−3** | **Публичный warm-up** | ранний тематический реплай (лучше всего в **первые 10–30 мин** под свежим постом) или содержательный GitHub-комментарий. Он видит имя ДО личного касания | ⛔ гейт [коллега] + IP-гейт (хаб) |
| 1 | **D0** | **PR по его issue / заявка в формальную программу** | сильнейший ход; если двери нет — шаг пропускается | GitHub — шипим сами |
| 2 | **D+2…D+4** | **Публичный follow** | второй содержательный публичный контакт | ⛔ гейт [коллега] + IP-гейт |
| 3 | **D+5…D+7** | **Приватное касание #1** (X DM / email) | ⛔ **без ссылок**, ⛔ без job-ask, ⛔ без «Loved your work!», ⛔ без календарной ссылки. Коротко, конкретно, человеческим голосом, soft-ask или no-ask | класс C (сам), журнал |
| 4 | **D+10…D+12** | **Приватное касание #2 — ДРУГОЙ канал** | не повтор: новый факт, другой угол | класс C |
| 5 | **D+14…D+18** | **Финальное касание ИЛИ стоп** | тишина → `closed`, сменить таргетинг | доложить Антону |

⛔ **Потолок: 3–4 приватных касания на цель, никогда больше.**
⛔ **Публичные шаги не блокируют приватные:** нет ОК [коллега] / хаб недоступен → шаг 0 и 2
пропускаются, лестница идёт дальше. Иначе публичный гейт молча заморозил бы всю волну.

### Замеренные reply-rate (ориентир для выбора канала, не обещание)
| Канал | Оценка | Уверенность |
|---|---|---|
| Cold email при персонализации/сигнале | 6–15%+ (база tech 3.4–7.2%) | средняя |
| LinkedIn: accept 28–50% → reply | 10–15% (хорошие 15–25%), InMail 10–18% | средняя |
| **X DM холодный** | **5–12% при гиперперсонализации + Premium, реально часто <5%** | ⚠️ низкая, спор не разрешён |
| GitHub PR по issue | не измеряется | сигнал высокий, качественный |
| Contribution-first письма DevRel-лидерам | ~7.2% позитивных | ⚠️ **единичный источник** (Skyp, Q1-2025, 3k писем) |

⚠️ **X DM — НЕ основной канал.** Большинство холодных DM падает в Message Requests, которую
редко открывают. Именно поэтому мультиканальность (Антон был прав), а не «дожать в X».
Мультиканальные последовательности дают **2–3× lift** к одноканальным.

⛔ **Freshness-чек перед КАЖДЫМ приватным касанием** (не только перед первым): роли двигаются
часто — профиль + свежие посты + careers page, <5 мин. Живой пример в DR: Alex Albert перешёл
с Claude Relations на Research.

⚠️ **Ответ на любом шаге ЗАВЕРШАЕТ сценарий, а не перезапускает его с D0.** Дальше — живой
диалог по Библии, никаких плановых касаний по таблице (канон: «ответил содержательно → счёт
обнуляется» = счёт касаний, не рестарт лестницы). Вернуться к таблице нельзя: диалог начат.

### ⛔ Терминальные состояния — лестница НЕ продолжается ни по одному каналу
| Состояние | Как выглядит | Что делаем |
|---|---|---|
| **Враждебный ответ / «не пишите»** | раздражение, явный отказ, просьба отстать | ⛔ **terminal opt-out**, НЕ «прерывание №1 и живой диалог». Одно короткое «понял, спасибо» — или молчание. `status: suppressed`. Больше ни одного касания ни по одному каналу |
| **Blocked by target** | профиль не виден, DM невозможен, ответы ограничены | ⛔ это **отказ, а не техсбой и не молчание**. `status: suppressed`. ⛔ Не «обходить» через email/LinkedIn/публичное — это и есть преследование |
| **Смена роли / ушёл из лаба** | freshness-чек показал | цель закрыть (`closed`), не дожимать; новый человек = новая цель с нуля |
| **Ответ спустя месяцы после СТОП** | пишет сам, когда уже работает backup | ⛔ приоритет у ОТВЕТИВШЕГО (живой человек > плановая цель). Backup **приостановить** (не удалять) до исхода диалога — иначе нарушим «один вендор = один человек» |

## Шаги исполнения

### 1. Выбор цели + анкер
- Кандидат из §Первая пятёрка (ниже) или по запросу Антона.
- Найти анкер: его свежий пост с вопросом/болью, его issue, его призыв. Записать ЛИНК.
- Анкера нет → цель в бэклог, берём следующую. Не изобретать анкер задним числом.

### 2. Freshness-чек (до текста, ≤5 мин)
Текущее био + 5–10 свежих постов: (а) он ещё в роли? (б) есть ли у него амплификация или тупик.
Роль сменилась → перевыбрать цель, старый список пометить протухшим.

⛔ **Проверка МОМЕНТА (не только роли).** Читая свежие посты, смотрю, не идёт ли у человека
или его компании: увольнения/сокращения · security-инцидент или публичный скандал · утрата,
болезнь, траур · острый конфликт, в который наш заход впишется третьей стороной.
Есть такое → ⛔ **касание откладывается** (минимум на неделю, дальше перепроверить).
Прицельный CTA под постом о сокращениях бьёт по репутации Антона сильнее, чем даёт любой ответ.

⛔ **Жалоба на холодные сообщения = сигнал НЕ ПИСАТЬ.** Не трактовать «меня заваливают DM»
как доказательство, что он их читает и что мы будем исключением.

### 3. Дедуп по журналу — по ВСЕМ идентификаторам, не по одному
⚠️ Одна проверка по одному написанию = ложный CLEAN → дубль живому человеку (грабли 26.07:
журнал латиницей, сессия искала кириллицей). Прогнать `check` по КАЖДОМУ из того, что знаем:
```bash
L=~/Obsidian/<vault>/_outreach/outreach_log.py
for id in "Имя Фамилия" "Фамилия" "Имя" "@handle" "handle" "email@домен" "вендор"; do
  echo "--- $id"; python3 $L check "$id"
done
```
Обязательный минимум идентификаторов: полное имя · только фамилия · display-name из профиля ·
текущий @handle **без @** и с @ · прежние handles (если менял) · email · имя вендора
(поймает «мы уже писали кому-то там»). Хоть одно совпадение → это НЕ новая цель, читать историю.

**⛔ Подтверждение личности цели (не тот человек — реальный риск при распространённом имени):**
до первого касания зафиксировать **устойчивый идентификатор**: URL профиля + @handle + место
работы из живого био. В журнал писать handle, а не только имя. Совпало имя, но не совпал
профиль → это ДРУГОЙ человек, история к нему не относится.
Ошиблись адресатом и он ответил → ⛔ немедленно остановиться, честно извиниться одним
сообщением, `status: suppressed`, ничего не «дожимать».

### 4. Гейт исходящего
Прогнать `/outbound-gate` целиком (прерывание-чек → анкер → долг → кредит → ship → вахта).
Провал любого шага = не шлём.

### 5. Текст (голос Антона)
- Пишет **Opus/Fable**, не Sonnet. Голос Антона, **без ELI5** (ELI5 только Антону, не наружу).
- Только **проверяемые факты**, которые Антон реально мог бы сказать
  (`reglament-konkretnomu-sobesedniku-tolko-proveryaemye-fakty`). Цифры не выдумывать.
- ⛔ **Правда ≠ право сказать.** Факт может быть верным и при этом непубличным: внутренние
  метрики, чужие данные, недоговорённое с партнёром, сырое до анонса. В холодное сообщение идёт
  ТОЛЬКО то, что **уже опубликовано** (живой URL) или что Антон явно разрешил показывать.
  Не уверен, публичное ли число → ⛔ не вставлять (`reglament-ne-utekat-chuzhie-privatnye-dannye-naruzhu`).
- ⛔ **Граница имперсонации.** Пишу ГОЛОСОМ Антона — но не выдаю себя за живого Антона,
  читающего сообщение в реальном времени. Спросили личное («ты сам это делал?», «созвонимся
  сейчас?», «подтверди опыт») → ⛔ не отвечать от первого лица за него: пауза, эскалация Антону.
  Обещания, договорённости, оценки его времени = Tier-2, всегда он.
- Ведём **proof-of-work**, а не титулами: воспроизводимые числа, замороженные логи, верификатор.
  ✅ DR подтвердил: proof-of-work + оффер вклада **бьёт** credentials, похвалу и job-ask.
- ⛔ **Жёсткие стопы первого приватного касания** (замер DR):
  без ссылок · без job-ask · без питча · без «Loved your work!» · без календарной ссылки ·
  без шаблона. Только: коротко, конкретно, человеческим голосом, **soft-ask или no-ask**.
- ⭐ Урок 27.07: **человеческий заход сильнее заготовки** — Антон отправил своё «this is a human
  writing you» вместо моего черновика, и это было правильнее. Черновик = каркас, не догма.
- Каждое сообщение несёт **CTA** (канон Библии: сообщение без CTA — мёртвый контент).
- **Формат сообщения (PLAN.md §Формат, обязателен):**
  - открытие = **искренний интерес**: конкретная отсылка к НАШЕЙ истории с человеком —
    у холодного DevRel это и есть анкер (его пост/issue/доклад), а не «привет, я фанат»
    (`reglament-outreach-genuine-interest-first`);
  - **первая строка — только приветствие**, тело со второй (`outreach-message-format`);
  - CTA обязателен (`insight-every-message-needs-cta`).
- Длина: коротко. Правило §3.3 (≤5–7 слов) относится к непроверенным текстам — здесь текст
  проверяется гейтом, но краткость всё равно выигрывает.
- **Окно отправки: 10:00–20:00 Лиссабона** (PLAN.md — строже библейского 08:00–23:00; ночью
  не шлём, выглядит роботом). Для целей в US/Asia — окно пересекать с их днём, но окно
  Антона главнее: он несёт репутацию отправителя.

### 6. Отправка по каналам — РАЗНЫЕ гейты (не путать!)

| Канал | Гейт | Кто жмёт |
|---|---|---|
| **X DM** | класс C (короткое исходящее 3-му лицу по делу) — решаю сам, журнал + отчёт постфактум | я, с [машина флота] (прецедент 27.07) |
| **⛔ ЛЮБОЕ ПУБЛИЧНОЕ ДЕЙСТВИЕ** | **ГЕЙТ [коллега]** (§3.2) + **IP-гейт** (§7.2 — только с хаба `[машина флота]`) | [коллега] ОК → хаб шлёт |
| **Email** | класс C; link-safety; ⛔ не выдумывать адрес — только подтверждённый | я |
| **LinkedIn** | класс C; ⛔ не создавать аккаунтов, не принимать соглашений | я |

⛔ **«Публичное» = видит кто-то кроме адресата.** Гейт закрывает НЕ ТОЛЬКО reply и пост:
quote-post, repost с комментарием, mention в своём треде, комментарий на любой другой публичной
площадке, публичный «thread про то, как мы к нему шли» — **всё это публичное**. Переименование
действия не выводит его из-под гейта. Сомнение «публичное ли это?» → считать публичным.

⛔ **Один канал = один аккаунт Антона.** Лимит лестницы считается по КАНАЛАМ И ЛИЧНОСТЯМ:
нельзя написать с личного и корпоративного email, с двух LinkedIn, с двух X-аккаунтов —
это тот же самый спрей, просто с разных адресов. Один человек видит нас максимум с одного
адреса на канал.

**Хард-стопы Tier-2 в силе везде:** деньги · обязательства от лица Антона · секреты 3-м лицам ·
масс-рассылка · юридическое. → пауза + `approval.py ask` в 02.

### 7. Журнал + вахта (Connect-правило: «отправил» ≠ «сделано»)

⭐ **ПОРЯДОК ВАЖЕН: сперва `queued`, потом отправка, потом `sent`.** Иначе класс отказа
«DM физически ушёл, а `register` упал» оставляет журнал CLEAN — и следующий запуск шлёт дубль
живому человеку.
```bash
L=~/Obsidian/<vault>/_outreach/outreach_log.py
# (1) ДО отправки — намерение (переживёт падение чего угодно):
python3 $L register --person "<Имя>" --handle <@handle> --channel x-dm \
  --account <аккаунт> --campaign devrel-<вендор> --status queued --note "<анкер-линк + дата анкера>"
# (2) отправка
# (3) ПОСЛЕ отправки — факт:
python3 $L register --person "<Имя>" --handle <@handle> --channel x-dm \
  --account <аккаунт> --campaign devrel-<вендор> --status sent --note "<анкер-линк + суть>"
```
⚠️ `--channel` = канал ФАКТИЧЕСКОГО касания (`x-dm` · `x-reply` · `email` · `linkedin`),
не «x-dm по умолчанию» — иначе история канала врёт и следующий выбор пойдёт по ложным данным.

**Если шаг (3) не выполнился** (упал скрипт, закрылась сессия, неясно — ушло или нет):
⛔ НЕ отправлять повторно. Сначала **проверить факт глазами** — открыть тред и посмотреть,
есть ли наше сообщение. Ушло → дописать `sent`. Не ушло → отправить один раз. Висящий `queued`
без `sent` = «статус неизвестен, проверить руками», а не «можно слать заново».
Вахта ответа = **`/x-inbox-watch`** (X) и `/gmail` (email). Ответ обязан флипнуть статус на
`replied`, иначе ответы «глотаются» ([[outreach-queued-status-swallows-replies]]).
