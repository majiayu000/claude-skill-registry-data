# Raft Codex 配置

由环境维护者按当前请求处理成员配置，交付能被 Codex 加载的最小改动，并说明文件配置与正在运行的 Raft 会话之间的区别。

## 确认对象与范围

- 从当前请求和 Raft 信息确认目标成员、工作目录和计算机。验证目标文件确实可访问；机器显示名不同不等于文件一定不可访问，相同路径也不能证明是同一台机器。
- 检查适用的 AGENTS.md、Codex 版本、目标进程使用的 CODEX_HOME 和配置文件。读取与汇报限定为本次所需字段及来源摘要，完整环境和凭据留在原处。
- 区分“把现有设置拆成个人配置”与“改变参数”。仅要求独立配置时，沿用已核实的有效值；调大窗口但未给目标时，结合所用模型的官方限制澄清目标。
- 对尚未确认的 Codex 参数，核对当前官方文档；环境提供 openai-docs 时可使用该流程。Raft 运行行为以当前启动方式、会话参数和配置读取结果为准。

## 选择配置层

优先用目标工作目录的 `.codex/config.toml` 保存本次需要独立维护的参数，其余继续继承现有配置。仅配置上下文窗口时，将改动限定为相应参数，保留模型、推理强度和服务档位的现有来源。

`CODEX_HOME` 会同时影响配置、认证、会话等状态。只有任务确实需要且已授权该范围的隔离时才选择它；普通配置拆分沿用现有的 HOME、会话和认证位置。

项目配置并不能覆盖所有设置。Codex CLI 参数、宿主通过 app-server 传入的会话参数都可能覆盖文件中的值；Raft 的 model、reasoning 等需要按实际启动方式核实，不能只查看进程命令行。

## 先读取，再修改

用官方 app-server `config/read` 指定目标 `cwd` 和 `includeLayers=true`，检查值、来源以及项目层是否禁用。可运行本 skill 的只读辅助脚本；下列脚本路径相对本 SKILL.md 所在目录解析，调用时展开为实际路径：

```bash
python3 scripts/read_config.py --cwd /absolute/target/workspace
```

`--cwd` 可重复，`--key` 可从脚本白名单中选择；不传 `--key` 时检查常用模型与上下文设置。脚本只调用初始化和配置读取接口，不创建会话或请求模型；只输出选定字段与来源摘要。它不会证明未输出的所有配置都保持不变。

重要判断：

- 文件存在与 TOML 合法后，继续核对值的实际来源；相同数值也可能来自共享用户配置。
- 以 `config/read` 的层状态判断当前项目是否受信任。父目录的 trusted 记录只能作为线索；需要进一步诊断时在本机检查 disabledReason，对外只概括原因。
- 若缺少信任项，确认目标是本次获准配置且可核实归属的工作目录。授权范围涵盖时，仅增加该精确目录的 `projects.<path>.trust_level = "trusted"`；不扩大到父目录或其他仓库。若归属或授权不明，说明具体缺口。
- 多个成员共用用户配置时，只安排一个写入者。修改共享用户配置优先使用带 expectedVersion 的官方配置写入接口；直接编辑文件时，比较原文件版本后做最小原子修改，保留无关改动。

修改只涵盖本次请求的键。上下文相关键为 `model_context_window` 和 `model_auto_compact_token_limit`；后者控制自动压缩阈值，与窗口大小分别设定。具体数值根据该成员的模型与需求选择。

## 验证与交付

1. 修改后重新读取配置；有缓存疑问时用新启动的 app-server 复验。
2. 确认目标值正确、来源指向预期个人文件、项目层已启用。只做配置检查时不需要调用模型。
3. 对纯配置拆分，在内存中比较修改前后的有效配置，确认除预期信任项外没有语义变化；对参数调整，仅允许请求范围内的差异。不要持久化或发送完整有效配置。
4. 区分“文件已写入”“新进程已加载”“现有会话已采用”。磁盘配置读取不能证明正在运行的 Raft 会话已热更新。若确实需要重载，使用当前支持的运行管理方式，并说明生效时间。
5. 向用户简报目标、文件位置、变更值、验证结论和实际生效范围。涉及职责交接时，按当前沟通约定让负责人对齐后续修改安排。

本流程和辅助脚本于 2026-10-31 用 Codex 0.162.1 验证。遇到接口或层结构不匹配时，检查当前版本的 help、schema 和官方说明，不把旧版本观察当成永久限制。
