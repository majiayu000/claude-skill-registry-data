# Case Study Storytelling

Model the project as a narrative system without turning it into fiction. Read `references/narrative-system.md`.

## Workflow

1. Define the intended reader and the action or judgment the case study should enable.
2. Map the protagonist, supporting actors, systems, and decision makers.
3. Define the setting: channel, environment, time, device, organizational context, and constraints.
4. Separate the main plot from supporting subplots.
5. Identify turning points where new evidence or system behavior changed the design.
6. Map branches, alternate states, and unhappy paths.
7. Choose one theme that expresses what the project proves.
8. Convert the narrative into scenes or sections, each with context, tension, choice, evidence, and consequence.
9. Design the presentation for skimming first and depth second.

## AI-agent rule

Keep the human’s goal and agency central. Treat the agent as a supporting actor inside a permissioned system. Show how trust changes through observation, intervention, recovery, and proven outcomes.

## Output

Return a Narrative System Canvas, a section sequence, the main plot and subplots, the trust or emotional arc, and any branches that must remain visible.
