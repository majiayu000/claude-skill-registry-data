# Example

AI の説明が抽象的で分からないとき、人間が打つスキル。直前の回答の分かりにくい箇所を、具体例を複数挙げて言い直す。

`/brief` との違いは効く長さである。`/brief` は打った後の全回答を平易にし続ける。このスキルは**打った1回の回答だけ**に効く。以降の回答まで変えると `/brief` と役割が重なるので、持続させたいときは `/brief` を使う。

## 何を言い直すか

言い直すのは1箇所だけにする。

- 引数が語なら、その語を言い直す
- 引数が番号なら、直前の回答にある番号付きの項目（`/brief` の論点マップなど）のその番号を言い直す。番号付きの並びが2つ以上あれば、先頭の並びの番号とみなす
- 引数が無ければ、直前の回答から最も分かりにくい箇所を1つ選ぶ。分かりにくい箇所とは、それだけでは「実際に何が起きるか」が思い浮かばない記述である。たとえば「変更に強い」「責務が整理された」「この種の失敗を防ぐ」

聞き返さずに書き始める。選んだ対象は回答の冒頭に「〇〇を言い直します」と1行で示す。選び違えても、人間はその1行で気づき、`/example <語>` で打ち直せる。引数が無いときに、ほかにも分かりにくい箇所があれば、末尾にその語を並べる。

## どう言い直すか

1. 対象の説明を1文で言い直す
2. 具体例を3つ前後挙げる。1つずつ「どんな場面で → 何が起きるか」の形で書く
3. 例どうしは、場面を変えて選ぶ

- ❌ 「この設計は変更に強い」の例に、DB を MySQL から PostgreSQL へ替える話と、MySQL から Aurora へ替える話を並べる（どちらも DB の差し替え）
- ✅ DB の差し替え・画面の作り直し・外部 API の乗り換えを1つずつ挙げ、それぞれ直すファイルがいくつで済むかを書く

## 効くのは、この回答だけ

次の回答からは、人間に求められないかぎり、自分から具体例を複数付けたり `/example` の形式を続けたりしない。

## 出す前の自己チェック

> [!IMPORTANT]
> **（AI・必須）** 回答を出す前に次を問い、すべて「はい」になるまで書き直す。
>
> - 言い直した対象は、引数が指す箇所か（引数が無ければ、直前の回答で最も分かりにくい箇所か）
> - 冒頭に、言い直す対象を1行で示したか
> - 具体例は2つ以上あり、それぞれ場面が違うか
> - 各例に「どんな場面で」と「何が起きるか」の両方が書かれているか

## 使用方法

```
/example                    # 直前の回答で最も分かりにくい1箇所を言い直す
/example 冪等性              # 直前の回答の「冪等性」を言い直す
/example 2                  # 直前の回答で2番の項目を言い直す
```
