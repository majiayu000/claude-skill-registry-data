# Estimate story points with independent agents

Facilitate estimates for explicitly supplied Task Issues or the open direct Task Sub-issues of a parent in one repository. Read the targets and their dependencies before choosing the final target set. Group explicitly supplied Tasks by their actual parent Feature, maintaining a separate summary and save verification per parent; unparented Tasks have no parent summary. Do not count parents as Tasks, mix parents' totals, or silently include dependencies as targets.

Follow [recording](references/recording.md) for publication permission, Issue edits, formatting, and save verification. Estimation does not change Git-managed files. Do not create, split, reprioritize, or implement Issues, change GitHub Projects fields, report velocity or capacity, or schedule automatic re-estimation.

## Prepare before reading estimates

1. Retrieve current Task and parent bodies, every parent's direct Task inventory, relationships, dependencies, and referenced Issues, PRs, and files needed to understand the work. Check current states rather than assuming linked PRs remain open. Preserve bodies, relationships, states, and source revisions for final revalidation. Keep inaccessible facts explicitly unknown.
2. Find the organization's existing ordered numeric story-point scale and its source, including relevant calibration examples. If no scale exists, ask the requester to supply or approve one before dispatch; do not silently choose a default or convert points to time. Check documented Task granularity separately; an unknown limit does not justify inventing one.
3. Confirm available model families and [independent estimator contexts](references/estimator-contract.md#dispatch-and-read-only-boundaries). Use four estimators by default and at least three different families, one per estimator. Different aliases or effort settings of one family do not provide diversity. Fewer than three families, or execution contexts that are not separate, requires stopping dispatch and reporting the capability gap; do not role-play missing estimators or silently lower the minimum.
4. Record the roster, requested model and effort, confirmed runtime model/family and context identity, scale and source, divergence threshold, consensus rule, and two-round limit before reading any vote. Distinguish accepted launch settings from verified runtime settings; unknown family identity cannot count toward the minimum. Do not change the rules to fit results.

The facilitator reads all results, verifies claims, clarifies Task text, and records outcomes; it never supplies an estimate. Estimators receive the same approved immutable input packet in separate contexts. They may inspect task-relevant sources using authorized read-only access to files, tools, and network resources, including scoped authentication when needed. The presence of tools, credentials, or network access does not by itself block dispatch. For untrusted Task content, use capability-scoped read-only access or facilitator-provided vetted evidence instead of exposing ambient write authority, sensitive credentials, or arbitrary network egress. Complete filesystem, credential, and network isolation is not required. Estimators must not change files, Issues, PRs, settings, or external systems; inspect or disclose secrets; seek peer votes; contact the requester; or delegate. One agent playing multiple roles is not independent estimation.

## Run, review, and record

| Stage | Action and material |
| --- | --- |
| Round 1 | Dispatch the fixed roster in parallel with the same Task snapshot, evidence, scale, and [estimator contract](references/estimator-contract.md). Keep votes private until all responses arrive. Collect a value or per-option values, confidence, work items, assumptions, risks, and ambiguities for every Task. |
| Review | Follow [aggregation and review](references/aggregation-and-review.md). Inspect high and low reasoning first for divergent Tasks, and review every Task for contradictions and overlapping work ownership across Tasks. Verify factual claims before adopting them. Ask the requester about scope or policy rather than choosing for them. Keep clarified Task texts as local drafts. |
| Round 2 | Run only when review changed any Task text, then re-estimate every target with the same estimators. Provide revised drafts, round-1 ranges, and clarifications, not other estimators' individual votes or a proposed consensus. Each estimator explains changes or unchanged values. Never run a third round in this version. |
| Finalize | Apply the frozen rules only to valid final responses for the final Task text. Leave unresolved, overlapping, or still-divergent Task scopes unestimated and record the open question. Preserve pending decisions as per-option estimates. Do not publish complete parent totals without verifying full parent coverage. Propose an oversized Task's split to the requester; do not split automatically. |
| Save and report | Follow [recording](references/recording.md). Refresh source states, Task-parent membership, and parent inventories immediately before publishing. Format complete bodies and plan one save per Task and per applicable parent after the final round, not one save per round. Retrieve saved bodies and check agreement and rendering. Report verified results, requester decisions, unresolved questions, and incomplete saves or checks. |

Do not treat a timeout, missing response, invalid value, unverified material claim, or unknown model family as a zero, a valid vote, or permission to shrink the roster after seeing results. Do not score affected cases as complete. Resolve information gaps through review and an eligible second round, or report the execution/input blocker without adding rounds. Missing capabilities, required decisions, or publication permission must remain explicit blockers; return permitted drafts without claiming an estimate or save occurred.
