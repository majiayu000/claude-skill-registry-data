# Developer (Full-Cycle)

Сквозной гайд разработки на всех уровнях — от идеи до эксплуатации.

## 1. Требования и анализ
- [ ] Зафиксируй цель и критерии приёмки (Definition of Done)
- [ ] Уточни неоднозначности до написания кода
- [ ] Оцени риски и зависимости

## 2. Проектирование и архитектура
- [ ] Раздели на модули/слои с чёткими границами
- [ ] Определи API и контракты данных до реализации
- [ ] Продумай обработку ошибок и граничные случаи
- [ ] Задокументируй ключевые решения (ADR при необходимости)

## 3. Реализация
- [ ] Следуй стилю и конвенциям проекта
- [ ] Пиши сфокусированные, хорошо названные функции
- [ ] Не хардкодь — выноси в конфигурацию
- [ ] Обрабатывай ошибки явно, не «глотай» исключения
- [ ] Коммить осмысленно (conventional commits)

## 4. Тестирование
- [ ] Unit-тесты на новую логику
- [ ] Интеграционные тесты на контракты
- [ ] Тесты осмысленны, а не ради покрытия
- [ ] Запускай тесты после каждого изменения

## 5. Ревью кода
- [ ] Проверены корректность, безопасность, качество, производительность
- [ ] См. навык `code-review` для полного чек-листа

## 6. Сборка и деплой
- [ ] Сборка и CI проходят зелёным
- [ ] См. навык `deployment` для pre/post-deploy и отката

## 7. Сопровождение
- [ ] Наблюдай за метриками и ошибками после релиза
- [ ] Обновляй документацию и changelog
- [ ] Фиксируй технический долг в бэклоге

## Уровни стека

| Слой | Ключевые практики |
|------|-------------------|
| **Frontend** | Компонентный подход, типизация пропсов, доступность, отзывчивость |
| **Backend** | Валидация входа, параметризованные запросы, идемпотентность, rate-limit |
| **Данные (БД)** | Схема версионируется, миграции обратимы, индексы под запросы |
| **Инфра/DevOps** | Инфраструктура как код, секреты в хранилище, логирование и мониторинг |

## Правила работы
1. Начинай с минимально рабочего решения, затем улучшай (MVP → итерации).
2. Перед деструктивными операциями спрашивай подтверждение.
3. Проверяй изменения тестами перед передачей дальше.
4. Оставляй код лучше, чем нашёл (boy-scout rule).

## Финальная проверка
- [ ] Критерии приёмки выполнены
- [ ] Тесты проходят
- [ ] Документация обновлена
- [ ] Изменения закоммичены с понятным описанием
