# Perfetto 性能追踪与事件分析平台 技能卡

## 基本信息

- **中文名称**：Perfetto 性能追踪与事件分析平台
- **来源仓库**：[google/perfetto](https://github.com/google/perfetto)
- **上游参考分支**：`main`
- **参考提交（需核对）**：`9aa4e2e09b82a0b82537ad19ea3ce4653fbf9d5d`
- **许可证线索**：Apache-2.0、BSD-3-Clause、blessing 等组合（以 LICENSE/third_party 为准）；文件：`源码\LICENSE; 源码\third_party`

## 原说明列出的能力（需核对）

1. 记录线程、调度、CPU/GPU、内存、事件和自定义 trace
2. 以 protobuf/trace 文件保存跨组件时间线
3. 通过 SQL/UI 分析延迟、阻塞、竞态和性能回归

## 不能替代的边界

- 不定位业务函数、不读取/修改内存、不提供网络回执或动作执行；trace 缺失事件不能推断未发生。

## 输入与输出合同

```text
输入：trace 配置、数据源、进程/线程过滤、缓冲区、采样时长和自定义事件。
输出：trace 文件、时间线、SQL 查询结果、计数器和性能报告。
失败：权限不足、缓冲区丢失、时间源不一致或 trace 损坏时标记证据不完整。
后置：输出必须绑定项目、目标版本、平台/ABI（如适用）、时间戳和证据路径。
```

## 接入原则

1. 核对实际源码版本和参考提交，先做最小、可撤销、可回放的接入。
2. 任何地址、线程、设备、模型、资源或协议输入都必须记录来源、版本和后置状态。
3. 工具输出是候选或观测，必须与项目专项规则、状态机和真实成功证据交叉验证。
4. 失败时保留原始错误和现场证据，不把命令退出码、识别命中或 Hook 安装当作业务成功。
5. 可与 Breakpad、Mumu、Hook/线程调度实现组成证据层；性能改善不等于功能成功。

## 与 Codex 项目路由的边界

- `l-gameassist`：负责游戏目标、进程/设备连接和现场任务编排；本技能只提供本卡标注的工具能力，不能扩展为未登记的内存、Hook、协议或输入能力。
- `l-reverse`：负责逆向/静态或运行时证据路由；本技能的输出必须按目标版本、模块、ABI 和现场回读复核，不能把候选分析直接当作成功结论。
- `build-release`：负责构建、依赖、配置、部署、回滚和服务维护；本技能不替代发布门禁，未完成依赖、许可证、异常恢复和回滚检查时不得发布。

## 接入前专项检查

- 核对 trace 数据源、权限、过滤、缓冲区、时钟和 trace_processor/API 版本，记录丢失事件。
- 分析既有 trace 和发起新采集分别选择；时间线与 SQL 结果关联原始工件，性能变化与功能成功分开验证。
