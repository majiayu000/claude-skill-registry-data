# Breakpad 崩溃转储与符号化 技能卡

## 基本信息

- **中文名称**：Breakpad 崩溃转储与符号化
- **来源仓库**：[google/breakpad](https://github.com/google/breakpad)
- **上游参考分支**：`main`
- **参考提交（需核对）**：`418aacd617897c19d960ec3e649f42ea95a6363a`
- **许可证线索**：BSD 风格（以源码 LICENSE 为准）；文件：`源码\LICENSE`

## 原说明列出的能力（需核对）

1. 在 native 崩溃时生成 minidump/崩溃上下文
2. 配合符号文件解析堆栈、模块和线程信息
3. 支持 Android 与桌面平台的崩溃采集接入

## 不能替代的边界

- 只记录崩溃，不修复崩溃、不重启应用、不判断对局状态，也不提供内存读写、Hook 或网络协议能力。

## 输入与输出合同

```text
输入：进程崩溃回调、符号文件/模块版本、minidump 输出目录、平台和 ABI 信息。
输出：minidump 文件、崩溃时间、线程/模块信息和符号化堆栈报告。
失败：无法写入转储、符号不匹配或转储损坏时标记证据不可用，不得据此推断根因。
后置：输出必须绑定项目、目标版本、平台/ABI（如适用）、时间戳和证据路径。
```

## 接入原则

1. 核对实际源码版本和参考提交，先做最小、可撤销、可回放的接入。
2. 任何地址、线程、设备、模型、资源或协议输入都必须记录来源、版本和后置状态。
3. 工具输出是候选或观测，必须与项目专项规则、状态机和真实成功证据交叉验证。
4. 失败时保留原始错误和现场证据，不把命令退出码、识别命中或 Hook 安装当作业务成功。
5. 可接入全生命周期守护和 Perfetto 做故障证据层；恢复动作由项目守护程序执行，Breakpad 本身不负责重开。

- `l-gameassist`：负责游戏目标、进程/设备连接和现场任务编排；本技能只提供本卡标注的工具能力，不能扩展为未登记的内存、Hook、协议或输入能力。

## 接入前专项检查

- 匹配 minidump、平台/ABI、模块与符号构建，记录损坏、不可写出或符号不匹配。
