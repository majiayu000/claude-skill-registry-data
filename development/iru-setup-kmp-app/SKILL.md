# Setup KMP App

Generate a complete, buildable Kotlin Multiplatform (KMP) app for Android and iOS — a Gradle Kotlin-DSL build with a
`shared/` KMP module, an `androidApp/` application module and an `iosApp/` SwiftUI host app generated by XcodeGen —
from the templates in this skill's `reference/` files. Every template was rendered into throwaway projects (both
`ui` values) and proven against the real toolchain on 2026-10-15 (Gradle 9.8.1, AGP 9.4.1, Kotlin 2.4.21, Compose
Multiplatform 1.12.2, Xcode 27.0, XcodeGen 2.46.0) — see **Known quirks / verification notes**.

The layout is the **scaffold contract** the KMP coding and gate skills (`iru-kmp-code-one-task`, `iru-kmp-test`,
`iru-kmp-coverage`, `iru-kmp-code-quality`, `iru-kmp-dokka`, `iru-kmp-bump-version`) and
`iru-setup-kmp-github-workflows` detect and call — Step 8's contract table lists the confirmed task names and
report paths. It mirrors `iru-setup-android-app` (Gradle KTS, version catalog, env-driven signing, Update/Keep/
Replace) and `iru-setup-apple-app` (XcodeGen manifest, the generated `.xcodeproj` never committed, SwiftLint,
XCTest). Like `iru-setup-android-app`, it writes no publishing block — this is an *app*; a KMP library published to
Maven Central is out of scope.

## Reference files — read only what this run needs

| Read | When |
|---|---|
| `reference/gradle-templates.md` | **Always.** Wrapper properties, `settings.gradle.kts`, `gradle.properties`, `gradle/libs.versions.toml`, root `build.gradle.kts` (Kover aggregation + `sonar {}`), `detekt.yml`, `.editorconfig`. |
| `reference/shared-templates.md` | **Always.** `shared/build.gradle.kts` and every `shared/src/*` file (+ the `ui: compose` `App.kt`/`MainViewController.kt`). |
| `reference/android-templates.md` | **Always.** `androidApp/build.gradle.kts`, manifest, resources, `MainActivity.kt` (per `ui`), the Robolectric test. |
| `reference/ios-templates.md` | **Always.** `iosApp/project.yml`, `Config.xcconfig`, `Info.plist`, the Swift sources and tests (per `ui`), `.swiftlint.yml`. |

**Conditional-marker convention used in every reference file**: a line `// >>> <condition>` (or `# >>> <condition>`)
opens a block that is written only when the condition holds, and the matching `// <<< <condition>` closes it; the
marker lines themselves are never written. Conditions are `ui: compose`, `ui: native` and `sonar` (= `sonar` is not
`none`). A file heading suffixed `(ui: compose)`/`(ui: native)` exists only in that variant. `<placeholder>` values
come from Step 5's table; `<package-path>` is `<namespace>` with dots turned into `/`.

## Step 0 — Resolve inputs

Invoked stand-alone (`/iru-setup-kmp-app`) or by `iru-setup-kmp-repository` / the `iru-setup-repository` front door,
which pass resolved answers as `key: value` lines, e.g.:

```
ui: compose
app-name: My App
application-id: com.example.myapp
bundle-id: com.example.myapp
namespace: com.example.myapp
min-sdk: 26
ios-deployment-target: 18.5
license: MIT License
developer-name: Jane Doe
developer-email: jane@example.com
organization-url: https://github.com/example-org
open-source: yes
visibility: public
ci: yes
sonar: cloud
sonar-organization: example-org-github
sonar-project-key: example-org_my-app
sonar-host-url: https://sonarcloud.io
distribution: store
accessibility: enforce
mode: new
on-existing: ask
```

Recognized keys: `ui` (`compose`/`native`), `app-name`, `application-id`, `bundle-id` (default `application-id`),
`namespace` (default `application-id` — shared Kotlin package `<namespace>`, Android app package/namespace
`<namespace>.android`, shared Android namespace `<namespace>.shared`), `project-name` (`rootProject.name`, default
the repository name), `min-sdk` (default `26`), `compile-sdk`/`target-sdk` (default Step 4's lookup),
`ios-deployment-target` (default Step 4's lookup), `version-name` (default `1.0.0-SNAPSHOT` — the gitflow
integration-branch value; pass `1.0.0` for a main-only repository), `version-code` (default `1`), `team-id` (Apple
Developer Team ID, default empty — set later in `Config.xcconfig` or supplied by CI), `license`, `developer-name`,
`developer-email`, `organization-url`, `open-source` (`yes`/`no`), `visibility` (`public`/`private`/`internal` —
only keys the `sonar` recommendation), `ci` (`yes`/`no` — only keys the `sonar` recommendation), `sonar`
(`cloud`/`self-hosted`/`none`) plus `sonar-organization`/`sonar-project-key`/`sonar-host-url`, `distribution`
(`none`/`internal`/`store` — recorded for the report; the store/TestFlight uploads live in
`iru-setup-kmp-github-workflows`' `release.yml`, so the build files are identical for every value), `accessibility`
(`enforce`/`report`/`off`/`none`, default `enforce` — the automated accessibility level of the UI tests, written to
`.ui-quality.yml`; never asked stand-alone, just defaulted), `mode`
(`new`/`existing`), `on-existing` (`ask`/`keep`/`update`/`replace`, default `ask`). Every key found is resolved —
skip its question in Step 2. Unknown keys from a full shared-args set (`publish`, `ci-tests`, `pages`, …) are
ignored and named in the report.

`mode: existing` never means "gap-fill silently": Step 1 still warns about, and asks about, every pre-existing file
group. Only `on-existing` skips that question (`keep` = create only missing files; `update`/`replace` applied to
every existing group; the warning is still printed). Orchestrators forward `on-existing` only when their own `args`
received it.

**Accessibility level `none` and assistive-technology templates.** `accessibility` takes `enforce`, `report`, `off` or
`none` (UI contract §8; the stand-alone question gains a fourth option, **None — opt out entirely**, e.g. a mandated
non-compliant design). With `none`: write `accessibility: none` to `.ui-quality.yml`, do not install or configure the
accessibility test tooling (the Android Accessibility Test Framework audit and the iOS accessibility audit), and omit the accessibility-specific attributes from the generated templates.
With `enforce`, `report` or `off`: include the assistive-technology attributes from the contract's §8 platform
subsections in every generated template — `contentDescription`/`Modifier.semantics` on Android, `accessibilityLabel` on iOS, scalable font sizes, reduced-motion guards — and, for `enforce`/`report` only, the automated checks. In
`mode: existing`, a prior `.ui-quality.yml` follows this skill's existing Update / Keep / Replace prompt and its
`accessibility` value is never silently flipped (**Update** sets it only when `args` supplied it).

  **`gradle.properties`**, **the Gradle wrapper**, **`shared/build.gradle.kts`**, **`androidApp/build.gradle.kts`**,

    For the source skeleton,

  - **Keep as is (Recommended for the source skeleton and `Config.xcconfig`)** — "Leave the file(s) untouched.

    is lost (recoverable only from git history)." Never the default. Even on Replace, never overwrite a Kotlin/Swift

  Ask about groups whose expected content depends on Step 2 answers (`ui`, `sonar`) after Step 2 when `args` didn't
  already resolve them. When updating, read the current `applicationId`, namespace, bundle id
  (`Config.xcconfig`'s `BUNDLE_ID` or `project.yml`'s `PRODUCT_BUNDLE_IDENTIFIER`), app name and versions first and

- **A foreign KMP layout** — `composeApp/build.gradle.kts` (the JetBrains wizard's single module), or a `shared/`

## Step 2 — Collect the required inputs

For anything Step 0 didn't resolve, ask directly (plain conversation, pre-filled from Step 1 when updating):

- **app-name** — launcher label on both platforms (`strings.xml` `app_name`, `Config.xcconfig` `APP_NAME` →
  `CFBundleDisplayName`).
- **application-id** — Android `applicationId`, reverse-DNS.
- **bundle-id** — iOS `PRODUCT_BUNDLE_IDENTIFIER`; offer `application-id` as the default.
- **namespace** — Kotlin base package; offer `application-id` as the default.
- **min-sdk** (`26`), **compile-sdk**/**target-sdk** and **ios-deployment-target** — offer Step 4's looked-up values.
- **Developer name/email, organizationUrl** — recorded in the report (and seen by `iru-setup-readme`).

Then the **license** via `AskUserQuestion` (unless resolved): MIT License (recommended for an app) / Apache License
2.0 / No license (proprietary) / Other (ask name + URL). If one is chosen, remind the user in Step 8 to add a root
`LICENSE` (`iru-check-license` can backfill headers).

Then **ui** (unless resolved), `AskUserQuestion`:

- **Compose Multiplatform (Recommended)** (`compose`) — one Compose UI in `shared/commonMain` (`App()`), hosted by
  `MainActivity.setContent { App() }` on Android and `ComposeUIViewController { App() }` on iOS.
- **Native UI** (`native`) — `shared/` holds logic and state only (`Greeting`, `GreetingUiState`); Android UI is
  Jetpack Compose (Compose BOM) in `androidApp/`; iOS UI is SwiftUI in `iosApp/` over a small `GreetingModel`
  `ObservableObject` wrapping the shared state.

Then `open-source`, `sonar`, `distribution` (skip any resolved). Stand-alone with none resolved, ask `open-source`
first and derive the `sonar` recommendation from it:

- **open-source** — Yes / No.
- **sonar** — SonarQube/SonarCloud via the `org.sonarqube` Gradle plugin (`./gradlew sonar`, normally run by
  `iru-setup-kmp-github-workflows`' CI). Recommend **`cloud`** only when open source **and** `visibility` is public
  (or unset); otherwise state SonarCloud is free only for public/open-source projects (private needs a paid plan),
  recommend **`none`**, offer **`self-hosted`** (Community Build free, you run the server). With `ci: no`, say no CI
  would send reports (only a manual `./gradlew sonar` with a token) and recommend `none`; if still chosen, write the
  block and note it in Step 8. `cloud` → ask `sonar.organization` (suggest `<owner>-github`), default
  `sonar.projectKey` `<owner>_<repo>` and host `https://sonarcloud.io`, confirming both; `self-hosted` → ask host,
  key, and organization only if that server uses organizations; `none` → no plugin, no block.
- **distribution** — `none`/`internal`/`store`. Informational for this skill (see Step 0); default `store` when open
  source, otherwise recommend `internal`. Say plainly that the release signing config is always written (it only
  activates when the four `SIGNING_*` env vars exist) and that the Play/Firebase/TestFlight steps are generated by
  `iru-setup-kmp-github-workflows`.

### Known quirks / verification notes

- **Verified for real on 2026-10-15** in `$TMPDIR/iru-verify/kmp/iru-setup-kmp-app/compose` and `.../native`
  (outside this repository), both with `sonar: cloud` (dummy coordinates — the `sonar` task itself was never run):
  `./gradlew build`, `koverXmlReport koverVerify detekt ktlintCheck :androidApp:lint :shared:lint
  :shared:dokkaGenerate :androidApp:assembleDebug :androidApp:assembleRelease` (unsigned — no `SIGNING_*` vars),
  `:shared:allTests`, `:shared:linkDebugFrameworkIosSimulatorArm64`, `xcodegen generate` (2.46.0, downloaded to a
  temp directory — not installed), `swiftlint lint --strict` (0.65.1, same), and `xcodebuild test` on an iPhone 18
  Pro (iOS 27.0) simulator: 2 XCTest cases passed per variant. Root Kover line coverage 100% for both variants
  (compose: 27/27 lines, 7 classes incl. `AppKt` executed through the Robolectric `MainActivity` test). Before the
  exclusions were repeated in `shared`'s own `kover {}` block, `:shared:koverPrintCoverage` alone reported 44% for
  `ui: compose` (the composables are only executed by the app's Robolectric test) — keep the module-level filters. The
  `native` variant was run on JDK 17, `compose` on JDK 21.
- **compileSdk must be ≥ 37** with this Compose Multiplatform/BOM generation: at 36, `checkDebugAarMetadata` and
  `:shared:checkAndroidMainAarMetadata` fail ("Dependency 'androidx.compose.animation:animation-core-android:1.12.1'
  requires … version 37 or later"). Resolve compileSdk from the AAR metadata, not from habit.
- **Robolectric 4.17 + SDK 36 fails on JDK 21** (`Failed to interact with raw FileDescriptor internals`) — the test
  is pinned to `sdk=35` in `robolectric.properties`, independent of compileSdk/targetSdk.
- **`org.jetbrains.compose.ui.tooling.preview.Preview` no longer exists** in CMP 1.12 — the common `@Preview` is
  `androidx.compose.ui.tooling.preview.Preview` (from `org.jetbrains.compose.ui:ui-tooling-preview`).
- **detekt `MatchingDeclarationName`** fails on the wizard's `Platform.android.kt`/`Platform.ios.kt` naming — the
  actuals live in `AndroidPlatform.kt`/`IOSPlatform.kt` instead.
- **ktlint `chain-method-continuation`** (ktlint_official) flags `libs.versions.android.compileSdk.get().toInt()` in
  build scripts — `.editorconfig` disables that one rule for `*.gradle.kts` only.
- **AGP 9 lint DSL**: `lint { xmlReport/sarifReport }` are deprecated no-ops (reports are always written) — omitted.
- **The AGP KMP library plugin registers no `lint` task**; `com.android.lint` applied to `shared` adds `:shared:lint`.
- **`kotlin { android { withHostTest {} } }`** is the verified form (the coding agent also confirmed the
  `withHostTestBuilder {}` spelling); `androidHostTest` is the source set either way. A Compose UI test
  (`runComposeUiTest`) in `commonTest` NPEs on the Android host test without Robolectric — which is why `ui: compose`
  runs its host tests under Robolectric through the `UiTest` base class (see the UI contract wiring note below).
- **Kotlin default arguments are invisible from Swift** — `Greeting` has an explicit no-arg constructor and
  `GreetingUiState.Companion` an `initial()` overload, so Swift calls `Greeting()` / `GreetingUiState.companion.initial()`.
- **XcodeGen/TEST_HOST**: renaming the app's `PRODUCT_NAME` (e.g. to `$(APP_NAME)`) breaks `iosAppTests`
  ("Could not find test host … iosApp.app/iosApp"); the product stays `iosApp.app` and the launcher label comes from
  `CFBundleDisplayName`. `ENABLE_USER_SCRIPT_SANDBOXING = NO` is required for the Gradle pre-build phase. The test
  target only gets `FRAMEWORK_SEARCH_PATHS` (no `-framework Shared`) — the static framework is already linked into the
  host app.
- **iOS deployment target 18.0 produced `ld: warning: … built for newer 'iOS-simulator' version (18.5)`** from the
  Compose/Skia objects — 18.5 links clean.
- **`xcodebuild -destination 'platform=iOS Simulator,name=iPhone 16 Pro'` failed** although that device exists —
  only on the iOS 18.5 runtime; without `OS=` the newest runtime is assumed. Pick the device from the newest runtime.
- **`xcodebuild build -destination 'generic/platform=iOS Simulator'` fails** in the Gradle pre-build phase with
  "Xcode Requested Architecture Not Configured in Gradle … ios_x64" — a generic simulator build asks for x86_64 too.
  Add `ARCHS=arm64` (verified), use a concrete simulator destination, or add an `iosX64()` target for Intel Macs.
- **SwiftLint**: `unused_import` belongs under `analyzer_rules`; `sorted_imports` sorts `@testable import iosApp`
  first.
- **UI contract wiring verified on 2026-10-16** in `$TMPDIR/iru-verify/kmp/ui-contract/scaffold-{compose,native}`
  (Robolectric 4.17, `androidx.compose.ui:ui-test-manifest` 1.12.1, Xcode 27.0, iPhone 18 Pro on iOS 27.0): `ui:
  compose` — `GreetingScreenTest` in `commonTest` (`androidx.compose.ui.test.v2.runComposeUiTest`, extending the

  PNGs; `./gradlew build koverVerify detekt ktlintCheck :shared:dokkaGenerate` stayed green and Kover stayed at 100%
  (27/27 lines). `ui: native` — the Robolectric `GreetingScreenTest` wrote 12 `--android` PNGs, `xcodebuild test` ran
  the `ImageRenderer` test and wrote 12 `--ios` PNGs (to `TEST_RUNNER_UI_SCREENSHOTS_DIR`, and to `<repo>/.ui-screenshots`
  through `#filePath` without it), `swiftlint lint --strict` clean, Kover 100%. Findings baked into the templates:
  `runComposeUiTest` without Robolectric NPEs on the Android host; `setContent` may be called only once per test on
  Android (the matrix drives a `mutableStateOf`); the simulator only sees `SIMCTL_CHILD_`-prefixed variables;
