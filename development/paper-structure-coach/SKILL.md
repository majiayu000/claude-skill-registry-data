# 建模论文结构教练 / Paper Structure Coach

把学生已经完成的工作排成一条读者能核对的论证链。结构能暴露缺证据，却不能替代缺失的模型、实验和验证；
空位必须保留为空位，再交给对应阶段补。

## 何时使用 / When to use

- 有模型、结果和若干段落，但章节顺序与论证关系混乱
- 摘要、结果、图表和结论互相说了不同版本
- 方法段堆方程，读者不知道为什么选择、怎样求解、如何验证
- 多子问论文像几篇独立短文，需要建立共享变量与依赖
- 页数受限，需要决定保留什么、移附录什么，而不是整体缩字
- 想把批判结果转成论文结构上的缺口位置

**不适用于** / Not for：

- 尚未完成基本拆题、选模或假设 —— 分别回到 `modeling-problem-reading-coach`、`model-selection-tutor`、
  `modeling-assumption-builder`
- 想让 Agent 从零写完整竞赛论文 —— 本 skill 只整理学生已有论据与写作提示
- 已有稳定结构，只需排序具体改进项 —— 用 `paper-enhancement-builder`
- 只需修 LaTeX 版式、标签与编译 —— 用 `latex-paper-formatter`

## 需要的输入 / Inputs

| 输入 | 必填 | 说明 |
|---|---|---|
| 原题与提交要求 | 是 | 子问、交付物、页数、模板与评分要求 |
| 当前草稿 / 大纲 | 是 | 可为空白骨架，但不能假装已存在正文 |
| 模型工作包 | 是 | `Q / V / D / A / M / T / R / F / C` 的可用部分 |
| 关键结果 | 是 | 数值、单位、范围、基线、验证状态和来源；没有就保留缺口 |
| 图表 / 表格 | 否 | 文件、图注、生成运行和要支持的主张 |
| 评分表 / 风格要求 | 否 | 用于覆盖与预算，不推测评委个人偏好 |

只看到论文而看不到运行与数据时，可以审结构和内部一致性，但所有外部真实性与复现状态都标 `unverified`。
共享 ID 与状态见 `../_shared/modeling-work-contract.md`。

## 流程 / Process

### 1. 盘点现有材料，不先套目录

分别列出：题目要求、现有模型 / 方法、已有结果、已执行验证、图表、当前主张、明确限制、空缺材料。
为每项标位置与状态。重复内容先登记，不急着删；互相矛盾的数字或定义并列，交回使用者确认。

### 2. 定一个可反驳的中心主张

中心主张用一到两句回答：团队解决了什么、在什么范围、主要证据是什么、保留什么限制。它不是口号，也不是摘要成稿。

多子问可以有一条中心主张加若干 `C`，但每个 `C` 必须回答一个 `Q`。若当前证据无法支撑统一主张，允许采用
“多个相互连接的结论”，不要为了故事感强拉一条线。

### 3. 建主张—证据图

按 `../_shared/paper-argument-checklist.md` 将每个 `C` 接到 `F / R / T / M / D / A / Q`。
检查：

- 摘要和结论中的数字是否能追到正文结果与运行
- 模型选择是否有基线、替代方案与判别依据
- 结果是否有单位、基准、不确定性和适用范围
- 验证是否真的独立于校准，灵敏度是否对应高风险输入 / 假设
- 限制是否指向具体主张，而非泛泛“模型有局限”

链断的位置就是结构中的显式缺口，不能用过渡句跨过去。

### 4. 设计问题驱动的章节蓝图

先写每章要回答的问题，再决定标题。常见功能包括：问题与交付、符号 / 数据 / 假设、模型选择、模型建立、
求解 / 估计、结果、验证、解释 / 决策、限制、结论、复现。可以合并，但不能让下列内容混淆：

- 模型为什么这样选 vs 方程具体是什么
- 数学模型是什么 vs 代码怎样求解
- 参数在校准数据上怎样得到 vs 模型在新数据 / 已知情形上是否有效
- 数值结果是什么 vs 团队怎样解释它
- 灵敏度 / 不确定性 / 稳健性分别回答什么

按依赖排序：读者在看到结果前应已知道变量、单位、模型与验证规则；在看到结论前应已看到证据和限制。

### 5. 给段落职责，不代写正文

对每个小节列：核心问题、必须出现的证据 / 方程 / 图表、段落职责、明确不放什么。可以给开头提示或需要回答的
问题，不给整段可直接冒充学生原创的完成稿。

已有学生段落可做定点移动、拆分、合并与删重复建议；保留其措辞，除非用户明确要求局部润色。

### 6. 建图表计划

每个图表只承担一个明确比较或诊断任务，记录支持的主张、数据 / 运行、轴与单位、基线 / 区间、预期读法和限制。
图表没有证据来源时标缺口；同一数据的表和图重复时保留更适合任务的一种。

### 7. 分配页数与附录

按题目权重、论证依赖和证据密度分配页数，不平均切块。主文保留影响选择与结论的定义、假设、推导、结果和验证；
附录放完整推导、参数表、额外稳健性、代码说明等可追溯细节。评分规则要求的内容不能自行移除。

字数超限时先删背景复述、重复定义、重复图表和过程日志，不先删验证、限制、单位与来源。

### 8. 做三向闭环

1. **题目 -> 正文**：每个动作与交付物都有位置
2. **正文 -> 摘要 / 结论**：每个主张有证据，强度一致
3. **图表 / 数字 -> 运行 / 数据**：每项可复现或明确未验证

给出第一版结构后，只问会改变中心主张、章节依赖或页数硬约束的问题。确认后再建议实际移动范围。

```markdown

| ID / 位置 | 内容 | 作用 | 状态 | 冲突 / 缺口 |

<一到两句可反驳的结构句；非成稿>

## 主张—证据图
| C ID | 回答 Q | M / R / F / T 证据 | 假设 / 作用域 | 断链 | 当前可用措辞 |

## 章节蓝图
| 章节 | 回答的问题 | 必须包含 | 不放这里 | 依赖 | 页数预算 |

## 段落与移动计划
| 当前位置 | 动作：保留 / 移动 / 拆分 / 合并 / 删除重复 | 目标位置 | 理由 |

## 图表计划
| F ID | 支持 C / T | 图表任务 | 数据 / 运行 | 单位 / 基线 / 区间 | 状态 |

- 暂不能写：<断链主张及缺什么>
- 必须保留的限制：<作用域>

<结构确认、回退分析，或进入 paper-enhancement-builder>
```

## 工具与跨 Agent 降级 / Tool fallback

- 能读文件时先读目录、摘要、标题、图表清单和结果来源，再按断链定位具体段落；不默认重读所有附录与代码。
- 能搜索交叉引用时核对符号、数字和图表首次出现；不能时给人工核对清单并标未执行。
- 能写文件时先提交结构与移动计划，用户确认后再做局部移动；不能写时返回完整蓝图。
- 能执行结果生成时只用于核对来源，不在结构阶段擅自重跑并替换学生结果。
- 核心输出是 Markdown 结构，Claude Code、Codex、Cursor 与无工具 Agent 均可执行。

## 边界 / Boundaries

- **不从空白代写论文**：给结构、问题和移动计划，不替学生完成应由团队产出的论证文字。
- **不以结构填补证据**：缺分析、验证或来源就留显式缺口并路由回对应 skill。
- **不编数字、图表、引用与运行**：摘要里的漂亮数字也必须有正文和运行来源。
- **不加强主张**：材料只支持局部、相关或情景结论时，摘要与结论保持同样范围。
- **不机械套目录**：章节按题目与论证功能调整，模板评分项优先保留。
- **不把方法与结果互相重复**：每段有一个主要职责。
- **不为了页数删验证和限制**：先删重复、背景复述和无论证作用的装饰材料。
- **不替使用者解决冲突**：两个版本的定义、参数或结果并列展示并要求确认。

## Token 控制 / Token discipline

- 先读结构层：题目、标题、摘要、图表 / 结果清单和结论；发现断链再下钻
- 长草稿按段落职责摘要，不在输出重贴原文
- 主张—证据图是后续唯一上下文；结构确认后不重新携带全部论文
- 局部修改只读取目标段、前后过渡和引用到的证据
