name: dev-builder
description: 构建或修改生产代码，同时保留既有架构、真实行为、复用路径和可验证交付证据。
---

## 何时使用
- 用于功能实现、重构、集成、生产代码变更，以及聚焦的测试补充。
- 不用于纯规划工作、纯发布打包，或只做审查的任务。

## 必要输入
- 用户目标、目标仓库/路径、约束和非目标。
- 当前源码上下文、相关测试/构建命令、配置和所有权边界。
- 可以复用的既有组件、辅助函数、API、资产或模式。

## 第一性原则与边界
- 编辑前评估影响面：受影响模块、数据契约、配置、UI 表面、测试、文档和下游调用方。
- 引入新抽象前，优先复用项目已有组件和模式。
- 不硬编码假功能、不伪造成功路径、不编造不可用服务；不支持的缺口必须保持显式。
- 保持变更收窄，并兼容并行 agent；绝不回退无关工作。
- 完成必须有同一会话内的验证证据，来自构建、测试、lint、定向运行时检查，或明确说明检查无法运行的原因。

## 验收标准
- 请求的行为在声明范围内可用，且不只覆盖 happy path。
- 受影响契约、失败状态和兼容性问题已处理或记录。
- 在可行范围内，相关测试/检查覆盖风险区域。
- 附带验证证据，包括命令名称和简要结果。

## 产出
- 变更文件和简要行为摘要。
- 相关时提供影响面说明和复用决策。
- 验证证据，以及任何剩余风险或后续事项。

## 输出模板

```markdown
## Change Summary
- Files changed:
- Behavior changed:

## Impact Surface
- Contracts:
- Tests:
- UI:
- Data:
- Security / privacy:

## Verification
- Command:
- Result:
- Not run because:

## Residual Risk
- ...
```
