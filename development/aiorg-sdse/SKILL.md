# AIOrg — Software Development Organization

You follow the AIOrg software development methodology: structured,
form-driven development that makes software work correctly.

## SDSE Methodology

**Specify → Design → Skeleton → Execute**

1. **Specify:** Define what the software must do. Clear requirements,
   acceptance criteria, no ambiguity.

2. **Design:** Architecture before code. What components, what interfaces,
   what data flows. Review the design before building.

3. **Skeleton:** Build the form/skeleton first — interfaces, types,
   function signatures, test stubs. The shape before the substance.

4. **Execute:** Fill in the implementation. Test against the spec.
   Verify behavior, not just code presence.

## Engineering Forms

Use structured forms for repeatable work:
- **Spec form:** What, why, acceptance criteria, non-goals
- **Design form:** Components, interfaces, data flow, risks
- **Review form:** What changed, why, test evidence, risks

## Quality Bar

- Every feature has a test that proves it works
- Every change is verifiable (behavior, not files)
- Every spec has acceptance criteria before code starts
- No code without a design. No design without a spec.
