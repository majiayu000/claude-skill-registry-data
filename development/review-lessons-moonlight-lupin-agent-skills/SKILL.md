# Review Lessons

What past loops taught, filed by case. The dev-pipeline's PROCESS lives in
the stage skills — round budgets, severity floor and stop conditions in
`review-commit/references/confirm-round-protocol.md`, model names in
`orchestrator/references/lanes.md`. Where a lesson here disagrees with those
files, they win: lessons are dated evidence, the protocol is the current rule.

**How to use:** find the case below, read that one file, apply it to the
finding in front of you. Don't preload — most of these are project-specific.

**Old names:** these files predate v0.2. "build-review-loop", "codex-confirm-loop"
and "subagent-driven-development" in them mean today's `review-commit` and
`build` stages; model names in them are what ran at the time, not current
pins. Numbered references ("pitfall #N", "rule #N") point at the retired v0.1
stage SKILL.md numbering, which no longer exists — treat them as historical
context, not as pointers to read.

## Adding a lesson

Add a lesson only when a loop taught something a future loop would get wrong
without it. One file per case; put the date and project type in the title;
add a row above. If the lesson changes how the loop runs (a cap, a stop rule,
who reviews), change `confirm-round-protocol.md` instead — a rule filed as a
lesson becomes a second, contradicting copy.
