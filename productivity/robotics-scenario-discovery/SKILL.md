# 机器人场景发现

## Purpose

从真实作业流程中找到高价值、可重复、可验证的机器人任务，并在形态和技术方案确定前暴露环境、安全、集成和经济性约束。

## Input

用户可提供一个行业/地点、当前人工流程、客户抱怨、视频或文字观察、候选机器人形态。输入不完整时先做最佳判断，并列出需要现场验证的假设。

示例：`使用 robotics-scenario-discovery，评估商场夜间巡检是否适合轮式机器人。`

## Key Concepts

- **作业而非口号**：把“做巡检”拆成到达、观察、识别、记录、上报和异常处置。
- **触点**：识别人、物、设备、门、电梯、充电桩和业务系统之间的交接。
- **ODD**：机器人获准工作的环境边界，而不是“通常环境”。
- **自动化边界**：明确机器人独立完成、请求确认、人工接管和禁止执行的情况。
- **可替代单位**：用一条任务链、一个班次或一个成功任务比较价值，不用抽象“替代一个人”。

## Application

### 1. 还原当前流程

按时间顺序记录触发、参与者、工具、输入、输出、等待、返工、异常和完成定义。区分观察事实、用户陈述和推测。

### 2. 拆成机器人任务闭环

对每一步回答：

1. 机器人需要感知什么？
2. 如何判断当前状态和目标？
3. 要移动、操作或沟通什么？
4. 如何确认成功？
5. 失败时怎样安全恢复或交给人？

### 3. 定义ODD和变化源

至少覆盖空间尺寸、地面/台阶、坡度、光照、天气、温度、粉尘/液体、人员密度、移动障碍物、网络、定位设施和工作时间。把“偶尔发生但代价高”的情况单列。

### 4. 量化基线与价值

收集任务量、周期、等待、人工投入、错误、事故、停机、培训和峰值。价值指标优先采用任务成功率、人工干预率、吞吐、响应时间、安全事件和单位成功任务成本。

### 5. 比较形态与自动化程度

至少比较：流程改造/固定自动化、轮式底盘、轮式机械臂、足式、足式机械臂、人形以及人工增强方案。若更简单方案覆盖主要任务，不默认选择更复杂形态。

### 6. 评分并选择验证探针

使用 [场景评分卡](references/scenario-scorecard.md)。先验证最可能否定项目的假设，例如地面通过性、抓取对象变化、人员混行安全、接口权限或客户经济性。

### 7. 输出场景简报

交付：流程图、ODD、任务清单、自动化边界、人工接管点、基线指标、形态比较、最高风险假设、验证计划和结论（继续/条件继续/暂停）。

## Examples

### 仓储周转箱转运

不要把场景写成“机器人运送物料”。应拆成接收任务、确认载具、装载确认、路线通行、路口避让、到站交接、空载返回、低电补能和异常处置，并验证高峰吞吐与调度接口。

### 工厂阀门操作

先确认阀门位置、姿态、阻力、操作频率和安全隔离。如果大多数阀门可改造成远程执行器，机器人可能只适合少数遗留设备，场景规模需要重新计算。

## Common Pitfalls

- **只访谈不观察**：描述与实际流程不一致。修正：现场跟班并记录异常样本。
- **平均值陷阱**：平均环境可行，峰值和长尾失败。修正：单列P90/P95负载和高代价异常。
- **把人完全移出流程**：忽略授权、补给和救援。修正：设计清晰的人机协作与接管。
- **用演示替代价值**：能完成一次不等于值得部署。修正：同时验证任务闭环、可靠性和单位经济性。
