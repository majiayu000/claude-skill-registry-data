# App Primer Zero Stinger

## Purpose

Prepare any new or partial repository for a later build: organize private Knowledge, establish actual current state, draft the foundation PRD/contracts/schema, qualify reuse boundaries and deliver a wave-plan handoff. This is a direct-use composition skill, not a new specialist Drone or an implementation launcher.

## When to use

- "Run app-primer-zero", "prime this app", or "prepare this repo before the build".
- "Set up the Library, sort the docs, and give me the state of the union".
- "Create the contracts/seams/schema foundation and a bounded wave handoff".

## When not to use

A bounded feature/bug fix belongs to Pest Controller and its specialist; execution of an approved feature PRD belongs to Smoke It. Existing current-state narration alone belongs to Knowledge. Do not turn preparation into unsolicited implementation, provider setup or deployment.

1. Read [the workflow map](README.md) and [intake/authority](guides/00-intake-and-authority.md). Record current scope, actual baseline, dirty owners, decisions, CI preference and supplied versus qualified harness capabilities.
2. Resolve [core dependencies](references/core-dependencies.md). Load Pest Controller before routing; use Get Started, Knowledge, Library and Contract Writing for their owned phases. Do not duplicate their rules or claim a native role exists without the capability.
3. Follow [inventory/Library](guides/01-inventory-and-library.md). Organize source docs only within authorized scope; preserve historical bodies and links; produce truthful current-state evidence.
4. Follow [contracts/schema](guides/02-contracts-and-schema.md). Draft the foundation PRD using the repo's number/lifecycle, full source-field ledger and native schema reference. Keep exact contract terms Draft until owner acceptance; selected providers are a separate decision.
5. Follow [reuse/waves](guides/03-reuse-and-waves.md). Pin specific donor modules, adapt scope/provider/runtime assumptions, and create contract-first waves with one integrator and exclusive paths. Count every overlapping worker and coordinator overhead within the effective ceiling; use explicit serial preparation when threading is unavailable.
6. Follow [verification](guides/04-verification-and-delivery.md). Validate structural artifacts and report actual evidence; run applicable ordered reviews, then deliver a coordinator starter and bounded worker brief. A valid planning artifact is not runtime or approval proof.
7. Stop at the preparation handoff unless the user separately authorized execution. Preserve current approvals within their exact scope. Follow the actual deadline/retry rules and return the six-field report.
