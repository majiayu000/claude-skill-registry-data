# 项目记忆优先（遇事不决 ki-search）

## 概述

**目的**：让 AI 在处理任何任务前优先检索项目记忆，把"已沉淀的项目知识"作为第一信息源，避免重复排查、遗漏踩坑经验。

**功能**：前置 ki_search 检索项目记忆；命中则带着记忆求解；未命中降级到 expert-solution-workflow 复用路径；改代码时查询强关联关系。

**使用场景**：
- 任何任务或问题开始处理前（自动触发，必做）
- 已定位到要修改的代码、或代码已修改时（查询强关联关系）
- 用户说"查记忆"、"先看看记忆里有什么"时

## 规则

AI 在遇到任何任务或问题、开始处理前，**务必先使用 ki-search 查询项目记忆**，作为第一优先级动作，先看记忆里有没有相关内容：

| 时机 | 动作 | 说明 |
|------|------|------|
| 任何任务/问题开始前 | `ki_search` 查询项目记忆 | **必做**，不跳过。口诀：**遇事不决 ki-search** |
| **已定位到要修改的代码 / 已修改代码时** | `ki_search` 查询被改模块的**强关联关系** | **必做**，见下方「修改代码时查询关联关系」小节 |
| ki 记忆有相关内容 | 带着记忆结果求解 | 交叉参照后再动手 |
| ki 记忆无结果/不充分 | 再走专家团 + 解决方案路径 | 详见 expert-solution-workflow |

**核心原则**：

- **ki-search 永远最先**：项目记忆是最高效、最贴近本项目的资产，先检索它，通常能直接命中答案或定位到关键代码位置。
- **记忆未命中再降级**：只有记忆无结果、或结果不足以支撑求解时，才进入 `expert-lookup`（业务模块专家团）/ `solution-lookup`（具体技术问题解决方案）复用链路。
- **沉淀闭环**：解决问题后，有价值的结论仍需按 expert-solution-workflow 沉淀到项目记忆，保证下次"遇事不决 ki-search"能命中。
- **改代码先查关联**：一旦已定位到要修改的代码（或已修改），必须查询被改模块的**强关联关系**，确认"改了这里牵动了哪些其他模块"，避免遗漏跨模块契约/消费端造成连带破坏。

## 执行

### 查找流程（遇到任何任务/问题时）

```
1. 一律先 ki_search 查询项目记忆（必做，不分问题类型）
   ├─ 命中？→ 记下命中的记忆内容（关键代码位置 / 结论 / 踩坑）
   │        → 带着记忆去定位源码 / 直接求解
   └─ 未命中或结果不足以求解？
        → 进入 expert-solution-workflow 复用路径（use_skill("expert-solution-workflow")：
          判断类型 → 查专家/方案 → 查代码库）
2. 求解过程中如新产生关键知识，随时可再 ki_search 核对或补充检索
3. 解决后，按 expert-solution-workflow 沉淀流程把有价值结论写入项目记忆
```

**检索要点**：

- 查询词用**自然语言描述问题本质**（如"订单超时怎么处理"、"登录模块在哪定义"），不要只搜单个单词。
- 记忆结果与源码不一致时，**以源码为准**（项目记忆可能过期），但记忆仍是定位起点。
- 命中结果不足以完全求解时，不要停在半路，继续走专家团/解决方案或查代码。

### 修改代码时查询关联关系

**触发条件**：当已经**知道要修改的代码**，或**代码已修改**时（含 code review、排错定位、重构、接口/数据结构变更等），**必做**此查询，不跳过。

**动作**：调用 `use_skill("ki-memory-lookup")`，检索被改模块的**强关联关系**（跨模块契约耦合 + 业务耦合），识别"改了这里牵动了哪些其他模块"。

**为什么必做**：强关联揭示"改数据源必须连带改消费端"这类不对称契约，代码中不直观、需浏览完整代码才能发现。提前查询可避免遗漏跨模块消费方/契约方，造成连带破坏（运行时错误）。

**使用要点**：
- 改**源端**（生产方/数据源）→ 必须检查目标端（消费端/契约方）是否需连带修改
- 改**目标端**（消费端）→ 通常源端不用改，不必误报
- 查询失败 / 无可用记录 → 忽略继续，不阻塞主流程
- 与 `ki-memory-lookup` 保持 SSOT，细节以该 skill 为准，本 skill 不重复

### 与 expert-solution-workflow 的关系

本 skill 是 expert-solution-workflow 的**前置步骤**，优先级更高：本 skill 负责「先 ki-search、记忆优先」，后续专家团/解决方案的查找与沉淀逻辑仍按 expert-solution-workflow 执行。两者职责互补，不冲突。

## 例外

以下情况可跳过 ki-search：
- 用户明确说"不用查记忆"、"直接读代码"
- 纯闲聊、寒暄、与任务无关的对话
- 极平凡的一次性动作（如改一个单词/标点），且显然与项目记忆无关
